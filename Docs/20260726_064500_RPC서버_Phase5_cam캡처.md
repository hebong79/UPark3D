## 1. 요약

Phase 1~4까지 등록만 되고 -32000이던 **cam.captureJPG / cam.capturePNG** 를 실동작으로 전환.
- catalog **79 불변**(이미 등록된 method의 동작만 실구현화). **미구현 12 → 10**.
- 카메라 렌더타깃 → JPEG/PNG 인코딩 → **base64 문자열** 반환(파일 저장 안 함, 레퍼런스 준수).

## 2. 기능 매핑

| method | params | 응답 | 상태 |
|---|---|---|---|
| `cam.captureJPG` | `camId`?(생략=선택), `quality`?=85 | `{img_bytes, width, height, format:"jpg", camId}` | ✅ |
| `cam.capturePNG` | `camId`?(생략=선택) | `{img_bytes, width, height, format:"png", camId}` | ✅ |

- `img_bytes` = base64 문자열. `camId` 지정 시 해당 카메라로 **선택 전환 후** 캡처.

## 3. 백엔드 (기존 자산 재사용, 신규 액터 0)

- `APTZCameraActor::Capture`(SceneCapture2D, `SCS_FinalColorLDR`) → `RenderTarget`(`RTF_RGBA8`, 1280×720).
- `CaptureOnce()`로 프레시 프레임, `ACameraControlManager::SelectCamera`로 선택 전환.
- 신규 엔진 의존: **ImageWrapper**(JPEG 품질 인코딩, PNG도 동일 경로).

### 신규 유틸 `Rpc/RpcImageUtil` (RHI 비의존 순수 인코딩)
```cpp
RpcImage::EncodeColors(Pixels(BGRA), W, H, bPng, Quality, OutBytes); // ImageWrapper
RpcImage::ToBase64(Bytes);                                           // FBase64
```
> 인코딩을 모듈에서 분리한 이유: `ReadPixels`는 GPU 필요라 헤드리스 `-nullrhi`에서 검증 불가. **인코딩 순수함수는 합성 픽셀로 유닛테스트**, 실 캡처는 실RHI 스모크로 분리 검증.

## 4. 처리 흐름 (핸들러)

```
captureJPG/PNG:
  camId 있으면 → 선택 전환(SelectCamera) 후 GetCamById, 없으면 SelectedIndex+1
  Cam->CaptureOnce()  → RenderTarget->GameThread_GetRenderTargetResource()
  리소스 없음(-nullrhi) → -32000 / ReadPixels → 비면 -32000
  RpcImage::EncodeColors(BGRA, W, H, bPng, quality) → ToBase64
  → {img_bytes, width, height, format, camId}
```

## 5. 검증 — 전부 통과

- **빌드**: UBT 정식 빌드 성공(경고 0).
- **자동화(EXIT 0)**: `Park3D.Rpc.*` **9개** 전부 Success.
  - 신규 **ImageUtil**: 합성 픽셀 → PNG 시그니처(89 50 4E 47)/JPEG SOI(FF D8)/base64 왕복(디코드 길이 일치)/픽셀 부족 실패.
  - **CamModule**: 헤드리스(-nullrhi) captureJPG → -32000(크래시 없음) 확인.
- **실RHI HTTP 스모크**(`-game` windowed):
  - `cam.captureJPG` → **format=jpg, 1280×720, 45,044 bytes, SOI=0xFFD8**(유효 JPEG)
  - `cam.capturePNG` → **format=png, 1280×720, 952,828 bytes, sig=0x89504E47**(유효 PNG)
  - 잘못된 camId=99 → -32000, catalog=79.
- 상세: `_workspace/rpc_phase5_impact_post.md`, `_workspace/rpc_phase5_luna_behavior_impact_report.md`.

## 6. 사용 예

```powershell
$b = @{ jsonrpc="2.0"; id=1; method="cam.captureJPG"; params=@{ camId=1; quality=85 } } | ConvertTo-Json -Depth 6
$r = Invoke-RestMethod -Uri "http://localhost:13110/rpc" -Method Post -Body $b -ContentType "application/json"
[IO.File]::WriteAllBytes("D:\shot.jpg", [Convert]::FromBase64String($r.result.img_bytes))  # 파일로 저장
```

## 7. 알려진 제약

- base64 페이로드 큼(PNG 1280×720 ≈ 950KB, JPEG ≈ 45KB). 대량/고빈도 시 응답 크기·메모리 유의(`quality`↓로 JPEG 축소).
- 색공간: 톤매핑된 LDR(`SCS_FinalColorLDR`). `SetLinearToGamma(false)`로 이중 감마 방지.
- `-nullrhi` 순수 헤드리스에서는 실 캡처 불가(-32000). 실 픽셀은 GPU 환경 필요.
- MJPEG `/stream`은 범위 외(별도 과제).
