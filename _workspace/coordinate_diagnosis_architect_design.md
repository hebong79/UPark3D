# Unity JSON 좌우 위치 불일치 원인 조사 설계

- 조사일: 2026-07-20 15:51:42
- 범위: `001_Preset_Seo_1.json` 및 차량 위치 JSON을 Unity/Unreal에 각각 로드했을 때의 월드 위치 불일치
- 변경 여부: 없음(원인 분석만 수행)

## 1. 조사 질문

1. JSON 원본의 `x/y/z` 값이 손상되었는가?
2. Unity와 Unreal이 같은 축 의미로 값을 해석하는가?
3. 프리셋과 차량에 공통으로 적용되는 변환 경계가 있는가?
4. 현재 자동화 테스트가 실제 공간 방향 보존을 검증하는가?

## 2. 판정 기준

Unity의 의미 축은 `(X=오른쪽, Y=위, Z=전방)`이고, Park3D Unreal의 의미 축은 `(X=전방, Y=오른쪽, Z=위)`이다. 같은 물리 방향을 보존하려면 다음 변환이어야 한다.

```
Unity (x, y, z) m -> Unreal (z, x, y) cm
```

- Unity 오른쪽 `+X` -> Unreal 오른쪽 `+Y`
- Unity 전방 `+Z` -> Unreal 전방 `+X`
- Unity 위 `+Y` -> Unreal 위 `+Z`

단위 변환은 모든 성분에 `x100`을 적용한다.

## 3. 확인 방법

- Unity 프리셋/차량 코드가 JSON의 벡터를 그대로 월드 위치에 적용하는지 확인한다.
- Unreal 프리셋 DTO 매핑과 차량 `UnityPosToUE`의 실제 수식을 비교한다.
- 예제 JSON 첫 프리셋 및 연결 차량의 좌표를 현재식/의미 보존식으로 계산한다.
- 회전 값이 위치축 변환과 같은 기준을 쓰는지 확인한다.

## 4. 검증 포인트

- `001_Preset_Seo_1.json`의 첫 프리셋 `offsetPos=(-7.367, 0, 19.176)`
- 연결 차량 파일 `CarPos_1Preset_7Num.json`의 첫 차량 `pos=(-7.29164743, -0.000145494938, 18.6345425)`
- Unity `+X` 단위 벡터가 Unreal 화면의 수평 오른쪽 축(`+Y`, 기본 Yaw=0 시)에 도달하는지
- Unity `rotY`를 그대로 UE Yaw로 사용할 수 있는지
