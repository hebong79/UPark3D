## 1. 결론

JSON 파일의 위치값이 잘못 저장된 것이 아니라, **Unreal 로더가 Unity 바닥 평면의 축 의미를 잘못 변환하는 것이 근본 원인**이다.

현재 코드는 Unity 위치를 다음처럼 처리한다.

```text
현재: Unity(x, y, z) -> Unreal(x, z, y)
```

그러나 Unity의 `X=오른쪽, Z=전방`과 Unreal의 `Y=오른쪽, X=전방`을 같은 실제 방향으로 대응하려면 다음이어야 한다.

```text
필요: Unity(x, y, z) -> Unreal(z, x, y)
```

즉 현재 구현은 Unity의 오른쪽(X)을 Unreal의 전방(X)으로, Unity의 전방(Z)을 Unreal의 오른쪽(Y)으로 잘못 보낸다. 이 오류가 프리셋과 차량 모두에 공통 적용되므로 둘 다 같은 방식으로 좌우/방향이 달라진다.

## 2. 코드 근거

- 프리셋: `PresetMakerWidget.cpp:920`이 `FVector(offsetPos.x, offsetPos.z, offsetPos.y)`를 사용한다.
- 차량: `CarPlacementLibrary.cpp:14`가 `FVector(pos.x, pos.z, pos.y)`를 반환하고, `CarActor.cpp:49`가 그 값을 액터 위치로 적용한다.
- 카메라: `CameraControlLibrary.cpp:13`도 같은 변환식을 사용한다.

Unity 쪽은 프리셋/차량 JSON의 `offsetPos`/`pos`를 Unity Transform 위치에 그대로 적용한다. 그러므로 원본 JSON이 아니라 Unreal 공통 변환 경계가 문제다.

## 3. 예제 파일의 수치

`001_Preset_Seo_1.json`의 첫 프리셋 위치는 `(-7.367, 0, 19.176)m`이다.

| 변환 | Unreal 위치(cm) |
|---|---:|
| 현재 `(x,z,y)` | `(-736.7, 1917.6, 0)` |
| 의미 보존 `(z,x,y)` | `(1917.6, -736.7, 0)` |

같은 프리셋의 차량 파일 `CarPos_1Preset_7Num.json`도 현재식으로 변환되므로, 차량 역시 같은 축 뒤바뀜을 보인다.

## 4. 왜 자동화 테스트가 통과했는가

기존 테스트는 현재식으로 변환한 뒤 같은 역변환식으로 되돌리는 라운드트립만 확인한다. 따라서 `(x,z,y)`와 그 역함수는 서로 되돌아가므로 통과하지만, Unity의 오른쪽/전방이 Unreal의 오른쪽/전방으로 실제 보존되는지는 검증하지 못한다.

## 5. 화면 비교에 겹치는 추가 요인

예제 프리셋 JSON에는 `camPos`, `camRot`, `fov`가 있지만, Unreal의 프리셋 DTO는 `camIdx`만 보관하고 이 세 필드를 읽지 않는다. 따라서 현재 Unreal은 별도의 기본 카메라 시점으로 화면을 출력한다.

이것은 "화면의 왼쪽/오른쪽"이 다르게 느껴지는 부가 요인이지만, 프리셋과 차량 월드 위치가 함께 틀어지는 1차 원인은 위의 평면 축 변환식이다.

## 6. 수정 시 주의사항

프리셋만 고치면 차량이 슬롯에서 벗어나고, 차량만 고치면 주차면과 어긋난다. 프리셋ㆍ차량ㆍ카메라의 좌표 변환을 하나의 공통 규약으로 함께 교정하고, 0°/90°/사선 회전까지 검증해야 한다.

현재는 코드 수정, 빌드, PIE 실행을 하지 않았다. 분석은 JSON 원본과 Unity/Unreal 변환 코드를 정적으로 대조해 확인했다.
