# 선택 카메라 중복 캡처 경고(major inefficiency) 제거 — 뷰어가 보일 때만 갱신

- 일시: 2026-10-01
- 브랜치: `fix/viewer-gated-capture`

## 1. 증상

정본(13510) 로그의 경고 대부분이 한 줄이었다.

```
Blueprint: Warning: CaptureScene: Scene capture with bCaptureEveryFrame enabled was told to update - major inefficiency.
```

- 재기동 후 약 10분에 6,396건이 쌓였다. 바로 앞 로그(9/30 17:01부터 약 18시간)에는 677,507건이 있었다. 이번 RPC 작업(#1098~#1102) 이전부터 있던 문제다.
- 10초 실측: 경고 67건(6.7건/초)이었고, 같은 시점 시청 중인 카메라 1·2 스트림 fps는 6.6이었다. 선택 카메라 한 대의 스트림 프레임마다 정확히 한 건씩 났다.

## 2. 원인

같은 카메라를 두 경로가 따로 렌더하고 있었다.

1. `ACameraControlManager::SelectCamera` → `APTZCameraActor::SetCaptureEnabled(true)` 가 **선택 카메라에 `bCaptureEveryFrame=true`** 를 켰다. 화면 안 카메라 뷰어(WBP_CameraViewer)에 띄우기 위해서였다.
2. 카메라 스트림(`UCamStreamSubsystem::ProduceJpeg`), `cam.captureJPG`, `/stream`, 시나리오가 `CaptureOnce()`(=`CaptureScene()`)를 **따로** 부른다.

매 프레임 자동 캡처 중인 컴포넌트에 수동 캡처가 들어오면 엔진이 매번 이 경고를 내고, 장면을 한 번 더 렌더한다. 게다가 선택 카메라는 뷰어를 숨겨도 매 프레임 렌더했다.

## 3. 수정(방안 A)

- `bCaptureEveryFrame` 은 이제 **어떤 카메라에서도 켜지 않는다.** `SetCaptureEnabled` 는 "뷰어 대상" 표시(`IsViewerTarget`)만 남긴다.
- `APTZCameraActor::CaptureOnce` 는 찍은 프레임(`GFrameCounter`)을 기억한다. `CaptureForViewer` 는 **이번 프레임에 아직 안 찍혔을 때만** 찍는다.
- `ACameraControlManager::RequestViewerFrame` — 선택 카메라에 `CaptureForViewer` 를 부른다.
- `UCameraViewerWidget::NativeTick` 이 이미지가 보일 때 `RequestViewerFrame` 을 부른다. Slate 는 화면에 그려지는 위젯만 틱하므로, 뷰어를 숨기면(Ctrl+Space) 호출이 끊기고 렌더도 0이 된다.
- 컨트롤 패널의 선택적 `Img_Viewer` 도 보이면 같은 요청을 한다(독립 뷰어를 숨겨도 패널 화면이 멈추지 않게).
- 순서: 스트림은 월드 틱 안에서 먼저 찍고 Slate 틱(뷰어)은 그 뒤다. 그래서 스트림이 찍은 프레임에는 뷰어가 다시 찍지 않는다(중복 0).
- 테스트 `PTZCameraCaptureStateTest`: "선택 시 bCaptureEveryFrame=true" 기대를 "뷰어 대상 + 늘 false" 로 바꿨다.

## 4. 검증

- 에디터 빌드, Automation **152/152**, 게임 빌드 모두 통과했다.
- 작업본 13540(offscreen)에서 같은 조건(메인 뷰 + 카메라 1·2 MJPEG 시청자, 카메라 1 선택, 20초, `_workspace/viewer_capture_bench.py`)으로 비교했다.

| | 경고/초 | 게임 fps | 스트림 fps(각) |
|---|---|---|---|
| 수정 전(main) | 0.9 | 0.87 | 0.85~0.9 |
| 수정 후 | **0.0** | 1.07 | 1.14 |

  작업본은 정본과 GPU를 같이 써서(측정 중 GPU 100%, 메모리 7.3/8 GB) 절대값이 낮다. 각 1회 측정이므로 fps 차이는 참고값이다.
- 화면 안 뷰어 갱신: 작업본을 창 모드로 띄워 카메라 1 pan +60° 전후를 PrintWindow 로 찍었다(`_workspace/viewer_live_check.py`, `_workspace/viewer_shots/after_a·b.png`). 뷰어 구역만 바뀌고(오른쪽 아래 평균 변화 102) 메인 화면은 그대로였다(0.18). 스트림을 붙이지 않은 상태라 갱신은 뷰어 요청만으로 일어났다. 로그 경고 0건.
- 미검증: 정본 반영, Ctrl+Space 로 뷰어를 숨겼을 때 렌더가 실제로 0이 되는지(fps 비교).
