# 차량 번호판이 2개 붙어 보이는 문제 — 근본 원인과 수정 (2026-10-08)

## 1. 증상
SettingManager 인식 시험 화면(시뮬 192.168.0.125, 서신 기본맵)에서 봉고 탑차 뒤에 번호판이 두 장 보였다.
위쪽 `71다 6648`(흰 판, 2자리 표기)과 그 아래 `681소7481`(KOR 띠). 인식 결과에도
`5 mismatch(71다6648 → 681소7481)` 같은 "다른 차 번호를 읽음" 이 여러 면에서 나왔다.

## 2. 원인 — 번호판이 아니라 "같은 자리에 차 두 대"
- 차량 메시 23종은 전부 `Car_no_plate` 임포트이고, `ACarActor` 는 앞·뒤 판 컴포넌트를 하나씩만 만든다. 차 한 대에 판이 두 장 붙는 코드는 없다.
- .125 의 `car.list` 43대를 좌표로 대조하니 **20쌍이 정확히 같은 좌표(0.00 m)** 에 있었다(주차면은 23면).
  스크린샷의 쌍은 `4-00.17.32`(봉고 탑차, 71다 6648) + `7-00.17.59`(현대 포터).
- 작은 차가 큰 차 안에 묻히면 차체는 가려지지만, 뒤 번호판(차체 바운즈 + 1 cm)이 **탑차 적재함 아래 빈 공간**으로 드러난다.
  작업본(Work13540)에서 봉고 탑차와 SM7 을 같은 좌표에 두자 스크린샷과 같은 화면이 재현됐다
  (`Docs/shots/20261008_car_overlap/01_before_two_plates.jpg`).
- 시뮬레이터는 이런 겹침을 전혀 막지 않았다.
  - `car.create`·`car.createMany`·`car.setAll` 목록 안 중복·`car.placeAtWorld`·`random.slotPlace` 는 이미 선 차가 있어도 그냥 추가했다.
  - `car.placeAtSlot` 도 `replace` 기본값이 false 였다(2026-09-05 "중복 배치는 막지 않는다" 결정).
  - `car.delete` 는 없는 id 도 `ok:true` 를 돌려줬다 → 호출자는 지웠다고 믿고 그 자리에 새 차를 얹는다.
    (이 작업 중에도 Windows 줄끝 `\r` 이 붙은 id 로 삭제가 조용히 실패했다.)
  - 겹친 장면은 `CarPos_before_campaign_20261008.json`(43대)으로 저장돼, 불러올 때마다 다시 나타난다.
- 어느 클라이언트 호출이 00:17:30~00:18:02 에 두 벌을 넣었는지는 확인하지 못했다(.125 로그 접근 불가, SettingManager 소스는 이 PC 에 없음).

참고: 처음 `car.list` 가 23대, `system.stats.carCount` 가 43대로 달라 "매니저 밖 유령 차량" 을 의심했으나,
그 사이 SettingManager 가 장면을 다시 불러온 것이었다. 다시 조회하니 둘 다 43대였다.

## 3. 수정 (마스터 결정: 자리 차 교체 + 없는 id 삭제는 not_found)
| 대상 | 변경 |
|---|---|
| `ACarPlacementManager::RemoveCarsOccupying(WorldLoc)` 신설 | 같은 주차면(`FindParkingSlotAt` 이 같은 면 중심을 집음)이거나 수평 중심 거리 1 m 미만(`OccupyRadiusCm=100`, 숨긴 차 포함)인 차를 지운다. id 가 아니라 배열 원소로 지운다(id 는 겹칠 수 있다). |
| `ACarPlacementManager::MakeUniqueCarId(Avoid)` 신설 | 살아 있는 차와도, 방금 지운 차와도 겹치지 않는 `{순번}-{HH.mm.ss}`. 첫 테스트 실행에서 교체된 차의 id 가 같은 초 안에 새 차에 그대로 재사용되는 것이 드러나 넣었다. |
| `car.create` · `car.placeAtWorld` | 놓기 전에 자리 비움, 응답 `replaced[]`. `allowOverlap:true` 면 예전처럼 겹친다. placeAtWorld 는 스냅된 실제 자리 기준. |
| `car.createMany` · `car.setAll` | 항목마다 자리 비움(같은 호출의 앞 항목도 대상 — 뒤가 이긴다). `cars[]` 는 살아남은 차만, `replaced[]` 추가. |
| `random.slotPlace` | 면에 선 차를 지우고 바꾼다, `replaced[]`, `allowOverlap`. |
| `car.placeAtSlot` | `replace` 기본값 false → **true**. `replace:false` 또는 `allowOverlap:true` 면 쌓는다. 지운 id 재사용 방지. |
| `car.delete` | 없는 id → `-32000` `not_found`. |
| `RpcDto::StringArray` 신설 | `replaced[]` 직렬화. |
| `Rpc/RpcHelpTable.cpp` | 위 7개 메서드의 params·returns·notes 갱신. |
| `Tests/CarPlateRpcExtTest.cpp` | `Park3D.Rpc.CarModuleExt.NoOverlap` 신설. 면 밖 1 m 이내 교체, 2 m 옆은 별개, allowOverlap 은 겹침, 같은 면 다른 점 교체, placeAtSlot 기본 교체, 없는 id 삭제 거부를 검사한다. |

손대지 않은 것
- 패널 Ctrl+클릭은 2026-09-05 결정대로 겹침을 허용한다(`SnapCarPosToSlot` 주석 그대로).
- `scenario.*`·`state.restore`·`car.update`(위치 이동)·주행 시뮬은 바꾸지 않았다.

## 5. 남은 일 · 주의
- **.125 의 현재 장면과 파일 `CarPos_before_campaign_20261008.json` 에는 여전히 20쌍이 겹쳐 있다.** 새 exe 로 바꿔도 `car.load` 는 파일을 그대로 올리므로 겹침이 다시 나온다. 파일을 다시 만들거나 겹친 쪽을 지워야 한다(그 PC·SettingManager 쪽 작업이라 손대지 않음).
