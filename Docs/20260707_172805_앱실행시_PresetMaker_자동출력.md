# 앱 실행 시 PresetMakerWidget 자동 출력 — 구현·검증 보고서

- 작성일: 2026-07-07
- 실행: `parking-cpp-loop`(C++ 전용 자율 루프, 컴파일만 수동 게이트)
- 결과: **반복 1회차에서 성공** (컴파일 1회 수동, 나머지 MCP 자동)

## 1. 요구사항
- 앱(PIE) 실행 시 PresetMakerWidget 대화상자 자동 출력.

## 2. 현재 흐름(변경 전)
- `Park3DGameMode::ShowMenu()`가 BeginPlay에서 MainMenu 생성·`AddToViewport(100)`.
- `MainMenuWidget::NativeConstruct()`는 버튼 바인딩만 → PresetMaker는 사용자가 버튼 클릭 시에만 오픈.

## 3. 변경 내용 (최소·외과적, 1줄)
`MainMenuWidget.cpp :: NativeConstruct` 말미(버튼 바인딩 후):
```cpp
// 앱 실행 시 기본으로 PresetMaker 패널을 연다(요구사항: 시작 시 PresetMaker 출력).
// 구성 시점엔 열린 패널이 없어 배타 토글이 정확히 PresetMaker만 표시한다.
TogglePanel(PresetMakerWidgetClass);
```
- 메뉴가 뷰포트에 뜨는 시점(=앱 실행)에 PresetMaker가 자동으로 열린다.
- 구성 시점엔 열린 패널이 없어 배타 토글이 PresetMaker만 표시(직전 배타 토글 작업과 정합).

## 4. 대안 비교
- 대안 A: `Park3DGameMode::ShowMenu`에서 `UMainMenuWidget` 캐스팅 후 오픈 호출 → 캐스팅·의존 추가.
- **대안 B(채택): NativeConstruct 자체 오픈** → 자기완결적, 1줄, GameMode 무변경.

## 6. 검증 근거
- PIE 재기동 후 뷰포트 스냅샷에 "Preset Maker" 타이틀 + 프리셋 리스트·Preset Idx·Face Count·저장/열기/생성 등 전체 필드 존재.
- 동시 출력 패널은 PresetMaker 단독(Car Install/카메라 리스트 없음).
- `LogTemp`에 `[MainMenu] 패널 클래스 미지정` 경고 없음 → PresetMakerWidgetClass 정상 지정.

## 7. 영향도
- 변경은 `NativeConstruct` 함수 본문 1줄. 헤더·시그니처 불변 → Live Coding 안전(실측 반영).
- `NativeConstruct`는 메뉴가 뷰포트에 추가될 때마다 실행 → 메뉴 재토글(ToggleMenu off→on) 시 PresetMaker 재오픈. **요구("실행 시 출력")는 충족**. 재토글 시 재오픈이 원치 않으면 1회성 가드(멤버 플래그) 추가를 후속으로 검토.
- 기존 배타 토글·카메라 미리보기 정리 로직과 충돌 없음.
