### 1.2 축 매핑 (버그 유발 1순위)

```
UI "가로 (X)" = Unity X → UE X      (Scale.X)

1 m = 100 uu
```

> **정방형(160×160)만 테스트하면 축 뒤바뀜 버그가 절대 드러나지 않는다.** 그래서 **비정방형**을 유닛테스트(300×100, 120×200)와 PIE(120×200 → 스케일 `(120,200,1)` 실측) 양쪽에 필수로 넣었다.

### 1.3 `MaxSizeM` = **500 m** — 이 값은 실측이 강제한 값이다

바닥은 `NoCollision` 이므로 커서 피킹의 실질적 지지대는 **Landscape** 다. `trace_world` 실측 결과:

| 지점 | Landscape Z 실측 |
|---|---|
| **250m 맵**(반경 125m) 모서리 4곳 + 변 중앙 4곳 | **전부 정확히 0** |
| **500m 맵**(반경 250m)까지 | **정확히 0** |
| ±280m | 최대 **12 cm** 솟음 |
| ±300m 모서리 4곳 | **23.4 / 35.2 / 35.9 / 10.1 cm** 솟음 |

지면이 12~36cm 솟으면 **바닥(Z=2cm)을 뚫는다.** 그 지점을 클릭해 차량을 배치하면 `Hit.ImpactPoint.Z ≠ 0` → 차량 JSON의 **`pos.y` 가 0이 아닌 값으로 오염**된다.
→ **상한 500m 로 오염 가능 영역을 입력 단계에서 배제했다. 이 값을 올리려면 Landscape 를 먼저 평탄화해야 한다.**

> ⚠️ [선행 문서]의 최초 버전에 적힌 **`MaxSizeM = 1000` 은 틀린 값이다.** 실제 코드는 `MapFloorLibrary.h:26` = `static constexpr float MaxSizeM = 500.f;` 이며, 유닛테스트가 이 상수를 직접 고정 검증한다.

### 1.4 빌드 에러 2건 — 재발 방지

| 에러 | 원인 | 해결 |
|------|------|------|
| **C1083** (파일을 열 수 없음) | 서브폴더 **내부**에서 `#include "Map/X.h"` 를 썼다. 이 모듈은 `Public/Private` 구조가 아니라 **모듈 루트가 include 검색 경로에 없다.** | **폴더 내부는 형제 include**(`#include "MapFloorLibrary.h"`), **폴더 밖에서만** `Map/` 접두어 |
| **C4459** (외부 선언을 가림, 에러 승격) | `MapFloorActor.cpp` 익명 네임스페이스의 상수 `PlaneBaseUU` 가 **유니티 빌드**에서 같은 번역 단위로 묶인 다른 파일의 **동명 파라미터·지역변수**를 가렸다. | 중복 상수를 **제거**하고, `MapFloorLibrary.h` 의 **기본 인자를 단일 진실 소스**로 삼았다 |

> **교훈:** 언리얼은 여러 `.cpp` 를 하나로 합쳐 컴파일한다(유니티 빌드). **`.cpp` 의 익명 네임스페이스 상수라도 이름이 프로젝트 전역에서 유일해야 안전하다.** 같은 값을 두 곳에 두지 말고 헤더의 기본 인자 하나로 모을 것.

## 2. ★ 아스팔트가 안 보이던 문제 — 근본 원인은 **자동 노출**이었다

이 절이 이번 세션에서 **가장 중요한 기록**이다. 결론부터: **머티리얼도 텍스처도 C++도 문제가 아니었다.**

### 2.1 최종 결론

| 항목 | 내용 |
|------|------|
| **증상** | **PIE 에서만** 아스팔트 바닥이 **베이지색**으로 보인다. **에디터 뷰포트에서는 같은 액터가 정상**으로 보인다. |
| **근본 원인** | **PIE 렌더의 히스토그램 자동 노출(Eye Adaptation).** 160×160m 어두운 아스팔트가 화면을 채우자 노출이 약 **+0.7 EV(×1.64)** 올라가 **아스팔트가 베이지 중간톤으로 떠버렸다.** |
| **왜 방치돼 있었나** | 레벨에 **PostProcessVolume 이 하나도 없어** 엔진 기본 자동 노출이 그대로 걸려 있었다. |
| **왜 에디터에선 정상인가** | **에디터 뷰포트는 고정 노출**로 동작한다. 이 **에디터↔PIE 비대칭**이 오진의 결정적 원인이다. |
| **수정** | 레벨 `PresetMaker1` 에 PostProcessVolume **`PP_FixedExposure` 1개 추가.** **C++·머티리얼·텍스처 전부 무수정.** |

### 2.2 오진 경위 — 숨기지 않고 남긴다

1. **1차 진단(틀림): "머티리얼 컴파일 실패(Fab 텍스처 결손)".**
   로그에 `Failed to compile Material for platform PCD3D_SM6, Default Material will be used in game` 가 실제로 찍혔고, 파일시스템 실측으로 **`Content/Fab/`(4.3GB, 에셋 2,119개)가 부재**함을 확인했다. `M_아스팔트`·`M_콘크리트` 가 실제로 깨져 있었던 것은 **사실이다.**
2. **사용자가 Fab 폴더를 복원** → 이 문제는 해소됐다. (**코드 변경 없음. `M_아스팔트.uasset` 원본 손상 없음.**)
3. **그런데 증상이 남았다.** 복원 후에도 **PIE 에서만** 바닥이 베이지색이었다.
4. 그제서야 **렌더 파이프라인(노출)** 을 의심했고, 아래 §2.3 의 결정적 증거로 확정했다.

> **교훈 1 — 그럴듯한 로그가 진범이라는 보장은 없다.**
> `Failed to compile Material` 은 **사실이었고 실제 결손도 있었다.** 그래서 거기서 조사를 멈췄다. 하지만 **그것을 고쳐도 증상이 남았다.**
> → **"원인으로 보이는 것을 고친 뒤, 증상이 실제로 사라졌는지 반드시 재확인한다"** 는 절차가 빠져 있었다. 정황 증거와 근본 원인을 동일시하지 말 것.

> **교훈 2 — 에디터에서 정상인데 PIE 에서만 이상하면, 에셋이 아니라 렌더 파이프라인을 의심하라.**
> 에디터 뷰포트는 **고정 노출**, PIE 는 **자동 노출**이다. 이 비대칭 자체가 강력한 힌트였는데 초기에 신호로 읽지 못했다.

### 2.3 결정적 증거 (이것 하나로 확정됐다)

> PIE 에서 **바닥만 숨겼더니, 아무것도 바뀌지 않은 Landscape 의 밝기까지 변했다.**
>
> | 대상 | 바닥 표시 | 바닥 숨김 |
> |---|---|---|
> | **Landscape** 평균 RGB | `(201, 188, 180)` | `(192, 176, 160)` |
>
> **내가 건드리지 않은 물체의 픽셀 값이 변했다면, 그건 그 물체의 머티리얼 문제일 수 없다.**
> 화면 전체에 걸린 **균일 게인 = 노출**이라는 뜻이다.

> **교훈 3 — "내가 안 건드린 물체의 픽셀까지 변한다"** 는 관측은 문제를 **개별 에셋 → 화면 전역 효과**로 즉시 승격시키는 강력한 판별식이다. 앞으로 렌더 이상을 만나면 이 테스트를 먼저 해볼 것.

### 2.4 실측으로 반증한 가설 (전부 부정)

| 가설 | 반증 근거 |
|------|----------|
| 한글 경로(`M_아스팔트`) 인코딩 문제 | `OverrideMaterials[0] = /Game/M/M_아스팔트` **정상 할당.** `[MapFloor]` 경고 **0건** → `ConstructorHelpers` 가 한글 경로를 정상 해석 |
| 텍스처 스트리밍 미로드 | `neverStream = true` 로 강제해도 **증상 동일** |
| 렌더 스테이트 캐시 | 무관 |
| 머티리얼 usage flag | 무관 |
| Z-fighting | 무관 |

### 2.5 수정 내용 — 레벨 `PresetMaker1` + PostProcessVolume 1개

| 프로퍼티 | 값 | 의미 |
|---|---|---|
| 액터명 | `PP_FixedExposure` | — |
| `bUnbound` | `true` | **레벨 전역 적용**(볼륨 경계와 무관) |
| `AutoExposureMethod` | `AEM_Histogram` | — |
| `AutoExposureMinBrightness` | `0.0` | **Min == Max → 노출 고정** |
| `AutoExposureMaxBrightness` | `0.0` | 위와 동일값 |
| `AutoExposureBias` | `1.0` | 고정 노출 기준 보정 |

**핵심은 `Min == Max`** 다. 자동 노출의 상·하한을 같은 값으로 묶으면 적응 범위가 0이 되어 **노출이 사실상 고정**된다.

### 2.6 검증

| 항목 | 수정 전 | 수정 후 |
|------|--------|--------|
| **바닥 평균 RGB** | `(176, 155, 135)` (베이지) | **`(56, 43, 34)`** (어두운 아스팔트) |
| 하늘·모래 | — | **밝게 유지됨** (전체가 어두워진 것이 아니다) |

### 2.7 트레이드오프 (명시)

`bUnbound = true` 볼륨이므로 **레벨 전체의 노출이 고정된다.**

- **잃는 것:** 카메라를 어두운 곳/밝은 곳으로 돌려도 **밝기가 자동으로 적응하지 않는다.**
- **얻는 것:** 카메라를 돌려도 **밝기가 출렁이지 않는다.** 색을 눈으로 비교·판단해야 하는 **주차장 저작 툴**에서는 노출이 제멋대로 흔들리는 쪽이 오히려 결함이다.
- → **저작 툴 성격에 비추어 고정 노출이 적합하다고 판단해 채택했다.** 만약 이 프로젝트가 게임플레이 중심으로 바뀌면 재검토 대상이다.

## 3. UI 전면 밝은 테마 재스타일 (완료)

### 3.1 요구와 설계

사용자가 **참조 스크린샷(밝은 회색 패널 + 검은 글씨)** 을 제시하고 **"모든 패널 밝은 테마 전면 재스타일"** 을 지시했다.
설계서 `_workspace/uitheme_architect_design.md` 에서 **팔레트**와 **위젯 클래스별 프로퍼티 매핑**을 먼저 확정한 뒤 적용했다(CLAUDE.md 0번 규칙).

> ⚠️ **팔레트 값은 `FLinearColor` 기준 — 즉 선형(linear) 값이다.**
> **sRGB 값을 그대로 집어넣으면 화면에서 밝게 뜬다.** 색이 의도보다 밝게 나오면 이 변환을 먼저 의심할 것.

### 3.2 적용 범위 — 7개 WBP, **229개 위젯** + CDO 3

| WBP | 변경 위젯 수 |
|-----|-------------|
| `WBP_CameraControl` | 77 |
| `WBP_PresetMaker` | 64 |
| `WBP_CarPlacement` | 51 |
| `WBP_MainMenu` | 18 |
| `WBP_MapSize` | 17 |
| `WBP_CarListItem` | 2 |
| `WBP_CameraViewer` | 0 |
| **합계** | **229** (+ CDO 3) |

**전 WBP 컴파일 에러·경고 0** → **BindWidget 계약 무결**(위젯 이름·구조를 건드리지 않았음이 컴파일로 증명된다).

### 3.3 C++ 하드코딩 색상 4곳 교체 (**로직 무변경**)

| 파일 | 내용 |
|------|------|
| `CameraControlWidget.cpp` | 피킹 버튼 **순빨강 → Danger 색** |
| `PresetMakerWidget.cpp` | 동적 생성 프리셋 행 색, `Txt_OffsetPick` |
| `CarPlacementWidget.cpp` | 토글 색 |

C++ 에서 **런타임에 색을 덮어쓰는 지점**은 WBP 만 고쳐서는 절대 바뀌지 않는다. 그래서 코드 쪽 4곳을 함께 바꿨다. **바꾼 것은 색 상수뿐이고 로직은 손대지 않았다.**
→ **사용자가 컴파일·확인 완료.**

### 3.4 정리한 잠복 지뢰 (최종 스캔 결과 **잔존 0건**)

밝은 테마로 바꾸자 그동안 어두운 배경에 가려 **보이지 않던** 기본값들이 드러났다.

| 잠복 문제 | 조치 |
|---|---|
| 전 버튼 Foreground 가 **시안 `(0,1,1)`** | 팔레트 색으로 교체 |
| `EditableTextBox` 의 `foregroundColor` / `selectedBackgroundColor` 가 **마젠타 `(1,0,1)`** | 교체 |
| 체크박스 **13개**의 `undeterminedForeground` 가 **마젠타** | 교체 |

### 3.5 함정 기록 (다음 UMG 작업자를 위한 실측 지식)

| # | 함정 |
|---|------|
| 1 | **`UBorder` 는 `drawAs = RoundedBox` 일 때만 아웃라인이 렌더된다.** 다른 모드에선 아웃라인 값을 넣어도 그려지지 않는다. |
| 2 | **버튼 최종색 = `widgetStyle.<state>.tintColor` × `backgroundColor` 곱연산.** 한쪽만 바꾸면 의도한 색이 안 나온다. |
| 3 | **모든 버튼의 `disabled.drawAs = NoDrawType`** 이었다 → 밝은 테마에선 **비활성 버튼이 배경에 묻혀 아예 사라진다.** → `RoundedBox` 로 교체했다. |
| 4 | **`WBP_CameraViewer.Img_View` 는 렌더타깃이다 → tint 금지.** 색을 입히면 카메라 영상이 물든다. (그래서 이 WBP 의 변경 위젯 수가 0이다.) |

### 3.6 제약 (스타일만 변경)

**위젯 이름 · 구조 · 레이아웃 · 폰트 · 이벤트는 전부 무변경.** 오직 **스타일 값**만 바꿨다.
→ BindWidget 계약이 깨지지 않았고, 전 WBP 컴파일 경고 0 이 이를 뒷받침한다.

## 7. 이번 세션의 교훈 (요약)

1. **정황 증거 ≠ 근본 원인.** `Failed to compile Material` 은 사실이었지만 **최종 원인이 아니었다.** 고친 뒤 **증상이 실제로 사라졌는지 반드시 재확인**하라.
2. **에디터 정상 / PIE 이상 → 렌더 파이프라인(노출)을 의심하라.** 에디터는 고정 노출, PIE 는 자동 노출이다.
3. **안 건드린 물체의 픽셀까지 변하면, 그건 화면 전역 효과(노출)다.** 개별 에셋 조사를 즉시 중단하고 레벨로 시야를 넓혀라.
4. **유니티 빌드에서는 `.cpp` 익명 네임스페이스 상수의 이름도 전역에서 유일해야 한다** (C4459).
5. **서브폴더 내부는 형제 include, 폴더 밖에서만 경로 접두어** (C1083).
6. **정방형만 테스트하면 축 뒤바뀜은 절대 안 드러난다.** 비정방형을 반드시 넣어라.
7. **밝은 테마 전환은 "그동안 안 보이던 기본값"(시안·마젠타 Foreground)을 드러낸다.** 어두운 배경이 가려주던 지뢰다.
