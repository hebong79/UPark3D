## 2. 민소매

재질 `M_AgentOutfit` 만 다시 만들었다. 새 파라미터는 없다(HLSL 변경 + C++ 의 민소매 `SleeveT` 0.04 → 0).

- 원인: 어깨 둥근 부분이 팔 판정 반경(9 cm)과 `T > 0` 밖이라 윗옷 색으로 남았다.
- 수정: `SleeveT < 0.01` 이면 진동 둘레 선 바깥을 맨살로 칠한다.

```
ax > ShoulderPos.x - 4.5 + 0.2 * (ShoulderPos.z + 6.0 - P.z)
```

- 어깨 위에서 겨드랑이 쪽으로 바깥으로 내려오는 사선이다. 어깨 좌표는 메시별 값이라 Manny·Quinn 에 따로 맞는다.
- 아래로 갈수록 경계가 바깥으로 벌어져 허리·허벅지에는 걸리지 않는다.
- 재생성: `python Tools/agent_outfit/run_build_material.py`

## 3. 자전거 발

- 페달 좌표를 모형을 만드는 코드에서 바로 저장한다(`PedalLeftCm`·`PedalRightCm`). 별도 표가 없어 모형과 어긋날 수 없다.
- `ApplyPedalPose`: 다리를 2관절 IK 로 풀어 발볼(`ball` 뼈)을 페달 윗면 위에 둔다. 무릎은 앞쪽·약간 바깥, 발끝은 10° 내린다.
- 왼발 = 액터 -Y 페달. 자전거 모형의 왼쪽 페달은 앞·아래(크랭크 35°), 오른쪽은 뒤·위다. simple 은 양쪽 같은 높이의 막대다.
- 오토바이는 페달이 없어 예전 고정 다리 그대로다. 페달 회전은 범위 밖이라 발은 고정이다.

### 3.1 계약(추가만)

`agent.list` 의 자전거 탑승자 항목에 `pedalGapCm{left, right}`. 오토바이 탑승자에는 없다.

### 3.2 발볼~페달 거리

| 모형 | Manny 좌·우 cm | Quinn 좌·우 cm |
|---|---|---|
| city | 0.75, 0.75 | 1.17, 1.17 |
| sport | 0.75, 0.75 | 1.17, 1.17 |
| simple | 0.75, 0.75 | 1.17, 1.17 |

- 정지·1.0 m/s 이동 중·멈춘 뒤가 모두 같다(`pedal_table.json`).
- `gripGapCm` 과 달리 **월드에 있는 뼈와 페달로 잰다.** 메시 내림·좌석 붙임·좌우가 틀리면 값이 커진다.
- 값 자체는 발볼 뼈의 바닥 높이다(Manny 0.75, Quinn 1.17). 기대값과 일치하므로 IK 가 끝까지 닿았다는 뜻이다.
- 그래도 재는 페달 좌표는 IK 목표와 같은 변수다. **발이 페달 위에 보이는지는 캡처로 판정한다.**
- `Park3D.Agent.Grip` 에 7모델 × Manny·Quinn 검사를 더했다(자전거만 값 있음, 8 cm 미만).

## 5. 남은 문제

1. **발이 페달을 따라 돌지 않는다.** 이동 중에도 크랭크와 발이 고정이다(범위 밖).
2. **몸집에 비해 자전거가 작아 무릎이 많이 굽는다.** 뒤쪽 페달 다리는 허벅지가 거의 수평에 가깝다. 안장 높이는 손잡이 자세와 묶여 있어 바꾸지 않았다.
3. **민소매 경계는 x·z 만 보는 평면이다.** 앞뒤로 같은 선이고, 진짜 진동 둘레처럼 곡선으로 파이지는 않는다. 근접 앞·뒤에서 어깨와 윗옷 사이가 직선에 가깝게 보인다.
4. **무릎·프레임 겹침은 눈으로만 봤다.** 계산은 없다.
