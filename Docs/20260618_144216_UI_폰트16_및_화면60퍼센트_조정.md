## 3. 폰트 16 적용 (타입별 경로가 다름)

UMG 위젯은 종류마다 폰트 속성 경로가 달라 타입별로 처리했다.

| 위젯 종류 | 폰트 속성 경로 | 대상 |
|-----------|----------------|------|
| `TextBlock` | `Font.Size` | 제목/모든 라벨/버튼 텍스트(Txt_*) 약 28개 |
| `EditableTextBox` | `WidgetStyle.TextStyle.Font.Size` | 모든 입력필드(Field_*) 11개 |
| `ComboBoxString` | `Font.Size` | Combo_DirType |
| 동적 리스트 항목(`TextBlock`) | C++에서 `SetFont` | RebuildPresetList 생성 항목 |

- **주의(함정)**: `EditableTextBox`는 `bIsFontDeprecationDone=false` 상태로, 실제 표시 폰트는 deprecated `Font`나 `WidgetStyle.Font`가 아니라 **`WidgetStyle.TextStyle.Font`**(기존 24)에 있었다. 올바른 중첩 경로로 설정해야 24→16이 반영된다.
- `set_widget_properties`는 중첩 구조체를 **부분 병합(merge)**한다(다른 폰트 속성 FontObject/Typeface/색상 보존, Size만 교체). 한 위젯으로 사전 검증 후 일괄 적용.

### 3.1 동적 리스트 항목 (C++)
`RebuildPresetList()`에서 매 항목마다 `ConstructWidget<UTextBlock>`로 생성하는 라벨은 기본 폰트(24)였다. 런타임 생성이라 디자이너에서 못 바꾸므로 C++에서 처리:
```cpp
FSlateFontInfo EntryFont = Label->GetFont();
EntryFont.Size = 16;
Label->SetFont(EntryFont);
```

## 4. 패널 크기 = 화면 높이의 60% (앵커 기반)

기존 `RootBorder`(CanvasPanelSlot)는 중심점 앵커(0.5,0.5)에 고정 오프셋(드래그로 흐트러진 값)이었다.
→ **stretch 앵커**로 교체해 화면 비율로 채우도록 변경:

| 항목 | 값 | 의미 |
|------|-----|------|
| Anchors.Minimum | (0.30, 0.20) | 좌측 30%, 상단 20% 지점 |
| Anchors.Maximum | (0.70, 0.80) | 우측 70%, 하단 80% 지점 |
| Offsets | 0, 0, 0, 0 | 앵커 영역을 그대로 채움 |

→ 세로 0.20~0.80 = **화면 높이의 60%**, 가로 0.30~0.70 = 화면 너비의 40%, 중앙 정렬. 해상도가 바뀌어도 비율 유지.

### 4.1 빈 공간 없이 채워지는 이유
핵심 슬롯들이 모두 `Fill`로 설정돼 있어, 패널이 커지면 내용이 자연스럽게 늘어난다.
- `Content_HBox`(VerticalBoxSlot) = Fill → 본문이 세로로 확장, 하단 버튼을 맨 아래로 밀어냄
- `PresetList_Border`(VerticalBoxSlot) = Fill → 프리셋 리스트 영역이 남는 세로 공간을 흡수(스크롤)

## 6. 영향도 분석

- **에셋 변경**: `/Game/UI/WBP_PresetMaker`의 텍스트 위젯 폰트 Size(40개)와 RootBorder 슬롯 앵커만 변경. 위젯 구조/바인딩/색상은 불변 → C++ `BindWidget` 영향 없음.
- **소스 변경**: `PresetMakerWidget.cpp`의 `RebuildPresetList()`에 폰트 3줄 추가. 헤더/시그니처 불변 → **C++ 재빌드 1회 필요**(완료). `Park3DGameMode` 등 다른 코드 영향 없음.
- **해상도 호환**: 앵커 기반이라 모든 해상도에서 화면 높이 60% 비율 유지(고정 픽셀 아님).
- **되돌리기**: 폰트는 각 위젯 Size를 원복, 크기는 RootBorder 앵커를 (0.5,0.5) 점 앵커 + 고정 오프셋으로 되돌리면 된다.
