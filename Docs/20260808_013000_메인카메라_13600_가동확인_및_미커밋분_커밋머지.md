## 1. 13600 가동 확인

직전 문서(롤백)의 "서비스 정지" 상태는 이미 해소되어 있었다. 사용자가 신규 빌드를 재배포하고 기동한 상태였다.

| 리슨 포트 | 13510(RPC), **13600(메인 뷰)**, 13601(cam1) — 전부 PID 24388 |

### 첫 확인에서 13600 이 안 보였던 이유 — 타이밍

프로세스는 00:06:29 에 떴지만 메인 뷰 채널은 **00:17:38** 에 열렸다. `TickMainChannel` 은 월드 틱에서
서버를 기동하므로 맵 로드 전에는 포트가 없다. 즉 "포트 없음"은 미구현이 아니라 관측 시점 문제였다.

> ⚠ 로그 시각은 **UTC** 로 찍힌다. `[2026.08.07-15.17.38]` = 로컬 2026-08-08 00:17:38 (UTC+9).
> 로컬 시각과 11분 차이로 오해하지 말 것.

```
LogCamStream:    [CamStream] 연속 스트림 서버 시작 :13600 (fps=5)
LogCamStreamSub: [CamStream] 메인 뷰 채널 기동: http://<IP>:13600/
```

### HTTP 실측 (8초 수신)

```
HTTP/1.1 200 OK
Content-Type: multipart/x-mixed-replace; boundary=park3dframe

경과      : 8.19 s
수신 바이트: 2,096,463 B  (250 KB/s)
JPEG 프레임: 37  (4.52 fps)   ← 목표 5fps
```

> 검증 시 함정: `Invoke-WebRequest` 로 MJPEG 엔드포인트를 치면 스트림이 끝나지 않아 **영원히 블록된다.**
> 원시 `TcpClient` 로 붙어 일정 시간만 읽고 끊어야 한다(스크립트는 스크래치패드에만 두었다).
> 프레임 수는 JPEG SOI(`FF D8`) 개수로 세되 버퍼 경계에 걸친 마커를 처리해야 정확하다.

### 성능에 대한 사실 기록

가드 ON 기준 캡처 1회 **148.70ms**. 목표 5fps 로 환산하면 초당 약 743ms, 즉 누군가 보고 있는 동안
**게임 스레드의 약 74%** 를 캡처가 점유한다. 가드 OFF 비교군(A/B)은 `bMainGuardEnabled=False` 로
재기동해야 얻을 수 있는데, 13601 에 클라이언트 1명이 접속 중이라 임의로 종료하지 않았다. **미측정.**

## 4. 남은 일

1. 가드 A/B 실측 — `bMainGuardEnabled=False` 재기동 필요. 접속 중 클라이언트가 끊긴다.
2. 패키지에서 `DefaultGame.ini` 튜닝이 먹는지 여전히 **미검증**. 패키지 config 는 pak 안에 쿠킹되며,
   pak 바이트를 ASCII 로 훑어 `bMainViewEnabled` 를 찾으면 나오지 않지만 **구버전 키(`MinHoldSeconds`)도
   똑같이 안 나오므로 이 검사는 무효다**(압축 추정). 확인하려면 `Saved/Config/Windows/Game.ini`
   레이어로 값을 바꾼 뒤 `cam.streamStatus` 에 반영되는지 보는 방법뿐이다.
3. 148.70ms 라는 캡처 비용 자체의 재검토 — 가드 비교보다 `MainWidth/Height` 와 `MainFps` 조합이
   더 큰 손잡이일 수 있다.
