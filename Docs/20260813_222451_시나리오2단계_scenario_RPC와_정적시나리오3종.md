## 공용 헬퍼 추출

`cam.aimSlot` 의 겨냥 계산을 `scenario.load` 가 그대로 써야 해서 `RpcModuleSupport` 로 뽑았다.
두 곳에 같은 삼각함수를 복붙하면 한쪽만 고쳐지는 사고가 난다.

```cpp
namespace RpcAim
{
    FVector SlotCenterWorld(const FParkingPreset& P, int32 Slot, float MetersToUU);
    bool    AimPTZ(const FVector& CamLocCm, const FVector& TargetCm, float TargetWidthCm,
                   float MaxZoom, float DefaultHFov,
                   float& OutPan, float& OutTilt, float& OutZoom, float& OutHFovDeg, float& OutDistCm);
}
```

`cam.aimSlot` 은 이 둘을 부르는 형태로 바뀌었다(동작 동일 — 값이 1단계와 같음을 재확인).

## `scenario.*` (4)

| method | 동작 |
|---|---|
| `scenario.list` | `Save/3D/Scenario/*.json` 목록 + desc/actorCount/hasRuns |
| `scenario.get` | 정의 원문 반환 |
| `scenario.load` | 장면 복원 — 주차면 → 차량 → 조명 → actors → 카메라 |
| `scenario.save` | 현재 월드를 시나리오로 덤프(차량·조명은 동반 파일로 저장) |

### 복원 순서가 중요하다

`주차면 → 차량 → 조명 → actors → 카메라` 순서를 지킨다.
`actors` 는 주차면 기하가 있어야 슬롯 좌표를 알고, 카메라 `aim` 도 주차면이 먼저 들어와 있어야 푼다.
카메라는 `pos` 를 먼저 옮긴 뒤 `aim` 을 계산한다 — 각은 카메라 위치 기준이라 순서가 뒤집히면 틀린다.

### 대상을 `carNameId` 로 가리키지 않는다

차량 id 는 `{idx}-{HH.mm.ss}` 시각 기반이라 재현할 때마다 달라진다.
시나리오는 `role` + `at.{presetIdx, slot}`(또는 `at.world`)로 적고, 실행 시점에 생성된 실제 id 를
`scenario.load` 응답의 `actors[]` 로 돌려준다. 외부 스크립트는 그 표를 보고 대상을 잡는다.

## 검증 (전부 실행 확인, 작업본 13520)

빌드 `Result: Succeeded`. `scenario.list` 가 3건을 desc 와 함께 반환.

**시나리오 1** — `scenario.load {name:"occ1_side_carnival"}`

```
presetCount 6, baseCarCount 0, lightFile Sangmyung.json, carCount 2
actors: target 현대_캐스퍼 (-19.371, 13.559) / occluder 기아_카니발 (-19.371, 11.059)
camera: pan 58.0635  tilt 22.8716  zoom 4.9769  distM 34.734
```

캡처: **마젠타로 도색된 대상차와 그 앞을 가로막은 회색 카니발**이 슬롯 3칸 폭 화면에 잡혔다.
색상 A/B 측정에 그대로 쓸 수 있는 구도다.

**시나리오 2** — 카메라 높이 3 m 가 파일에서 적용됨(`tilt 5.3553`, 1번의 22.87 과 대비).
캡처: **탑차가 화면을 거의 채우고** 대상은 운전석 창 너머로 마젠타 조각만 남았다(육안 90%+).
목표 구간 80~100% 와 부합.

**시나리오 5** — `pan 50.2895  tilt 6.4596  zoom 5.0945  distM 35.555`.
캡처: 스타렉스와 카니발이 나란히 서고 **그 사이의 빈 면 바닥이 차체에 덮여 거의 안 보인다**.
빈 면을 점유로 오판하기 쉬운 구도가 만들어졌다.

## 잡은 버그 — 카탈로그 주입 누락

첫 `scenario.load` 가 `카탈로그에 없는 차종: 현대_캐스퍼` 로 실패했다.
이름은 맞았고(`car_catalog.json` 21번), 원인은 `RpcServerSubsystem` 이
`SetCatalog` 를 **CarModule·RandomModule 에만** 호출하고 있었던 것이다.
새 모듈은 `Catalog` 가 빈 배열이라 `prefabName → prefabId` 해석이 전부 실패했다.
`ScenarioModule->SetCatalog(Catalog)` 를 추가해 해결.

→ **앞으로 카탈로그를 쓰는 모듈을 추가하면 이 세 줄을 같이 손봐야 한다.**

## 알려진 한계

- **`scenario.save` 는 `actors` 를 채우지 못한다.** 월드에 "이 차가 가리개였다"는 정보가 없다.
  차량·조명은 동반 파일(`CarPos_<name>.json`, `Light_<name>.json`)로 저장하고 시나리오는 그것을 참조하지만,
  `actors` 는 빈 배열로 나오고 응답의 `note` 에 그 사실을 적어 돌려준다. 설계서에서 예고한 한계다.
- **`scenario.save` 의 `presetFile` 은 인자로 받는다.** 매니저가 "어느 파일에서 왔는지"를 기억하지 않는다.
- `runs`/`shots` 는 아직 실행되지 않는다(3~5단계). 파일에 적혀 있어도 무시된다.
- `color` 는 이름 3종(`magenta`/`cyan`/`green`)만 해석한다. RGB 직접 지정은 필요해지면 추가.
- 가림률 판정은 여전히 RPC 밖이다 — 이번 검증의 "90%+"는 **육안 판단**이고 측정값이 아니다.
