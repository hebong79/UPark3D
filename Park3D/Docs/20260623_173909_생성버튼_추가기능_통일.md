# 생성 버튼을 추가 버튼과 동일 기능으로 변경

작성일: 2026-06-23
대상: `PresetMakerWidget::HandleCreate` (WBP_PresetMaker)
작업 유형: UI 동작 변경 (사소 변경 — 설계 게이트 경량 처리)

---

## 1. 요구사항
- UI의 **생성(Create) 버튼** 클릭 시 **추가(Add) 버튼과 동일한 기능** 수행.

## 2. 설계 생략 사유 (CLAUDE.md 0번 규칙)
- 핸들러 본문을 기존 추가 로직 호출로 교체하는 사소 변경(자료구조/인터페이스 불변)이므로
  전체 설계서를 생략하고 본 문서에 결정 근거만 기록함.

## 3. 변경 내용
파일: [PresetMakerWidget.cpp](../Source/Park3D/PresetMakerWidget.cpp)

**변경 전**
```cpp
void UPresetMakerWidget::HandleCreate()
{
    RecalcParkingNumbers();
    OnCreatePreset(GatherFromFields());
    Notify(TEXT("생성 호출"));
}
```

**변경 후**
```cpp
void UPresetMakerWidget::HandleCreate()
{
    // 생성 버튼은 추가 버튼과 동일하게 현재 입력 폼을 새 프리셋으로 추가한다.
    AddCurrentPreset();
}
```

- 추가 버튼 핸들러 `HandleAdd()` 가 `AddCurrentPreset()` 만 호출하므로, 생성도 동일하게 맞춤.
- `AddCurrentPreset()`: 빈 PresetIdx 탐색 → 현재 입력 폼 값으로 새 프리셋 추가 → 선택/리스트 갱신.

## 4. 검증 (CLAUDE.md 1·2번 규칙)
- **컴파일**: Live Coding 성공 — `Park3D.log`: `08:25:45 Live coding succeeded`.
- **반영**: Build.cs 변경이 없어 Live Coding으로 **실행 중인 에디터에 즉시 패치됨**.
  → 현재 세션에서 생성 버튼 클릭 시 추가와 동일하게 프리셋이 리스트에 추가됨.
- **동작 확인(권장)**: WBP_PresetMaker UI에서 생성 버튼 클릭 → 리스트에 새 항목 추가되는지 시각 확인.
- 단위 테스트: UI 버튼 핸들러 동작이라 시각 확인으로 대체.

## 5. 영향도 분석 (CLAUDE.md 4번 규칙)
- **범위**: `PresetMakerWidget.cpp` `HandleCreate` 단일 함수 본문 교체. 헤더/시그니처 불변.
- **동작 변화**: 생성 버튼이 더 이상 `RecalcParkingNumbers()` 와 BP 훅 `OnCreatePreset` 을
  호출하지 않는다. 이제 추가와 동일하게 프리셋만 추가한다.
- **데드 코드 처리(주의)**: 이 변경으로 C++에서 호출되지 않게 된
  - `RecalcParkingNumbers()` — `UFUNCTION(BlueprintCallable)` **공개 API**
  - `OnCreatePreset()` — `BlueprintImplementableEvent` **공개 훅**
  두 함수는 **블루프린트에서 호출/구현될 수 있는 공개 인터페이스**이므로 삭제하지 않고 보존함
  (CLAUDE.md 3번: 요청받지 않은 데드 코드 삭제 금지). BP에서 이 훅에 의존하던 로직이 있었다면
  생성 버튼 경로로는 더 이상 트리거되지 않으니 확인 필요.
- **회귀 위험**: 낮음. 단, 기존 "생성=3D 생성/번호 재계산" 의미를 의도적으로 사용 중이었다면
  동작이 달라짐(요청에 따른 변경).

## 6. 참고
- 만약 "추가 기능 + 기존 생성 기능"을 **둘 다** 원하셨다면(통합이 아니라 추가),
  `HandleCreate` 에 `AddCurrentPreset();` 호출만 덧붙이고 기존 `RecalcParkingNumbers()`/
  `OnCreatePreset()` 를 유지하도록 조정 가능. 현재는 요청 문구("추가 버튼과 같은 기능")에 따라
  추가 동작으로 **통일**함.
