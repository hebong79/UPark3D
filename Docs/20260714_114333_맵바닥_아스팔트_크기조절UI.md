- 레벨 에셋(`.umap`) 수정 — 바닥 액터는 **런타임 C++ 스폰만** 사용. <br>  ※ **[정정] 이 Non-Goal 은 이후 BUG-1(자동 노출) 수정 과정에서 부득이하게 깨졌다.** 레벨 `PresetMaker1` 에 `PP_FixedExposure` PostProcessVolume 1개를 추가했다(§8.3). **바닥 액터 자체는 여전히 런타임 스폰이며 레벨에 배치되지 않는다.**

- 바닥 경계 밖 차량 배치 차단 — 현행 동작 유지(바닥을 줄여도 그 밖에서는 Landscape가 히트되어 배치 가능).

## 2. 설계 결정과 근거

이 절이 이 문서의 핵심이다. **왜 그렇게 했는가**를 남긴다.

### 2.1 신규 폴더 `Park3D/Source/Park3D/Map/` — Build.cs 수정 불필요

UBT는 모듈 디렉터리(`Source/Park3D/`) 하위를 **재귀 수집**한다. 기존 `Tests/` 폴더가 별도 등록 없이 컴파일되는 것이 증거다. 신규 의존 모듈도 없다(Engine/UMG/Slate 모두 이미 `PublicDependencyModuleNames`).
→ **`Park3D.Build.cs` 는 한 줄도 건드리지 않았다.**

### 2.2 ⚠️ include 규칙 — 폴더 내부는 형제 include (빌드 에러로 학습)

이 모듈은 `Public/Private` 구조가 **아니라** 평면 레이아웃이며, **모듈 루트가 include 검색 경로에 없다.**

| 위치 | 올바른 include | 잘못된 예 |
|------|---------------|-----------|
| `Map/` **내부** 파일끼리 | `#include "MapFloorLibrary.h"` (형제) | ~~`#include "Map/MapFloorLibrary.h"`~~ → **C1083** |
| `Map/` **밖** (`Park3DGameMode.cpp`) | `#include "Map/MapFloorActor.h"` | — |
| `Tests/` → `Map/` | `#include "../Map/MapFloorLibrary.h"` (기존 Tests 상대경로 관례) | — |
| `.generated.h` | `#include "MapFloorActor.generated.h"` (폴더 무관, 파일명 기준) | — |

> 설계서 §2.3의 "`Map/` 접두 형태로 통일 권장"은 **틀린 조언이었고, 실제로 이를 따라 C1083 빌드 에러가 났다.** 위 표가 확정 규약이다. (상세: §6)

### 2.3 Manager 계층 의도적 생략 — 3계층 관례를 "형태"가 아니라 "의도"로 따름

| | 채택: Actor 단독 | 기각: `AMapFloorManager` 추가 |

| 구성 | `UMapSizeWidget` → `AMapFloorActor`(뷰+상태) → `UMapFloorLibrary`(계산) | 위 + Manager 1개 경유 |
| 단점 | 3계층 관례와 형태가 다름 | **Manager가 `Floor->SetFloorSize()` 만 호출하는 순수 패스스루** |

`ACarPlacementManager` 가 존재하는 이유는 **N개 차량의 생성/제거/선택/캐시**를 관리하기 때문이다. 바닥은 **단일 액터·단일 메시**이므로 Manager를 두면 상태도 컬렉션도 없는 위임층이 되어 **CLAUDE.md #2(단순함 우선)을 위반**한다.

### 2.5 ★ NoCollision — 이 한 줄이 회귀를 통째로 제거한다

프로젝트의 커서 피킹은 **6곳 전부 `ECC_Visibility`** 채널을 쓴다.

| 위치 | 코드 |
|------|------|
| `CameraControlManager.cpp:166` | `TraceFloor` — `GetHitResultUnderCursorByChannel(ECC_Visibility, ...)` |
| `CameraControlManager.cpp:186` | `TracePole` |
| `CarPlacementManager.cpp:193` | `TraceFloor` → `OutWorld = Hit.ImpactPoint` |
| `CarPlacementManager.cpp:208` | `TraceCar` |
| `CarPlacementWidget.cpp:114` | `GetHitResultUnderCursor(ECC_Visibility, ...)` |
| `PresetMakerWidget.cpp:183` | `GetHitResultUnderCursor(ECC_Visibility, ...)` |

**실패 시나리오(콜리전을 켰다면):** 바닥(Z=+2cm)이 Landscape(Z=0)보다 위에 있으므로 트레이스가 바닥을 먼저 히트 → `Hit.ImpactPoint.Z` 가 `0.0` → `2.0` → `AddCarAtWorld()` → `UEToUnityPos()` 의 `unity.y = UE.Z / 100` → **차량 JSON의 `pos.y` 가 `0.0` → `0.02` 로 조용히 드리프트.** 저장/재로드 반복 시 누적 오염된다.

**결정: 바닥은 순수 시각 요소이므로 콜리전을 끈다.**
```cpp
FloorMesh->SetCollisionEnabled(ECollisionEnabled::NoCollision);
```
→ 트레이스는 계속 Landscape(Z=0)를 히트 → 피킹·차량 JSON·프리셋 Z 규약이 **전부 무변경**. 데칼은 콜리전과 무관(렌더 전용)하므로 바닥 위에 정상 투영된다.

### 2.6 Z = +2cm — 안전 구간은 개구간 `0 < Z < 4`

```
Z = 5cm  ┬─ 주차면 디버그 라인 (FaceHeightZ = 5)            [기존]
         ├─ 데칼 중심 (DecalCenterZ = 5), 투영 박스 [-20,+30] [기존]
Z = 4cm  ├─ 선택 채움면 (FaceHeightZ + SelectFillZBias = 4)  [기존]
Z = 2cm  ├─ ★ 아스팔트 바닥 (FloorZ = 2)                     [신규]
Z = 0cm  └─ Landscape 지표면 (MCP trace_world 3지점 실측)     [기존, 그대로]
```

- **Z = 0 이면** Landscape와 완전 동일 평면 → 160m 전면 Z-fighting 확정.
- **Z ≥ 4 면** 선택 채움면이 묻히고, **Z ≥ 5 면 주차면 라인·데칼이 바닥 아래로 사라진다.**
- → **2cm** 는 Z-fighting 여유와 데칼 여유(2cm)를 모두 확보하는 값.
- `FloorZ` 는 `UPROPERTY(EditAnywhere)` 로 노출 → 문제가 생기면 재빌드 없이 조정 가능.

### 2.7 축 매핑 — 가로(X)→UE X, 세로(**Z**)→**UE Y**

UI 라벨의 `X`/`Z` 는 **Unity 축 표기**다. 프로젝트 규약(`CarPlacementLibrary.cpp:14`)은:
```cpp
// UnityPosToUE
return FVector(UnityMeters.x * MetersToUU, UnityMeters.z * MetersToUU, UnityMeters.y * MetersToUU);
//              UE.X = unity.x            UE.Y = unity.z            UE.Z = unity.y
```
→ **Unity z(깊이) = UE Y.** 따라서 UI "세로 (Z)" 입력은 **UE Y 스케일**에 매핑된다.

| UI 라벨 | Unity 축 | UE 축 | 스케일 성분 |
|---|---|---|---|
| `가로 (X)` | Unity X | **UE X** | `Scale.X` |
| `세로 (Z)` | Unity Z | **UE Y** | `Scale.Y` |
| (없음 — 평면) | Unity Y(상) | UE Z | `Scale.Z = 1` 고정 |

> ⚠️ **정방형(160×160)만 테스트하면 축 뒤바뀜 버그가 절대 드러나지 않는다.** 구현자가 "세로(Z)"를 UE Z에 연결하면 바닥이 위로 늘어나고, X/Y를 뒤바꾸면 비정방형에서만 틀린다.
> → **비정방형 테스트를 유닛테스트(300×100, 120×200)와 PIE(120×200) 양쪽에 필수로 넣었다.**

### 2.8 텍스처 늘어남 방지 — 추가 코드 **0줄**

`M_아스팔트` 의 머티리얼 그래프를 MCP `MaterialTools.get_expressions` 로 직독한 결과: `WorldAlignedTexture` + `WorldAlignedNormal` MaterialFunctionCall + TextureObject×3 + Constant(=200). **TexCoord/UV 노드가 없다** → **월드 얼라인드(트라이플래너)** 확정.

→ 텍스처 UV가 절대 월드 좌표로 생성되므로 **평면을 160배 스케일해도 텍스처가 늘어나지 않는다**(타일 주기 200uu = 2m 고정). MID 타일링 파라미터도, 메시 UV 스케일도 **전부 불필요**했다. 정찰 단계의 우려("160배 스케일 시 늘어남")는 로컬 UV 가정 하에서만 성립했다.

> | 250m 맵 모서리 4곳 + 변 중앙 4곳 | **전부 정확히 0** |
> | ±280m | 최대 **12 cm** 솟음 |
> | ±300m 모서리 4곳 | **23.4 / 35.2 / 35.9 / 10.1 cm** 솟음 |
>
> 지면이 12~36cm 솟으면 **바닥(Z=2cm)을 뚫는다.** 그 지점을 클릭해 차량을 배치하면 `Hit.ImpactPoint.Z ≠ 0` → `UEToUnityPos()` 를 거쳐 **차량 JSON의 `pos.y` 가 0이 아닌 값으로 오염된다.** §2.5에서 NoCollision으로 막았던 바로 그 드리프트가, 맵을 크게 만들면 지형 쪽에서 되살아나는 것이다.
> → **상한을 500m로 두어 오염 가능 영역을 아예 입력 단계에서 배제했다.** 이 값을 올리려면 **먼저 Landscape를 평탄화해야 한다.**

- `NaN` / `±Inf` → **`DefaultSizeM`(160) 폴백.** `FMath::Clamp(NaN)` 은 NaN을 반환할 수 있어 클램프만으로는 못 잡는다.
- **`FCString::Atof("abc")` 는 `0.f` 를 반환**하므로 Atof 단독으로는 실패를 감지할 수 없다 → `FString::IsNumeric()` 선검사를 병행한다. 파싱 실패 시 **바닥을 건드리지 않고** 통지 후 필드를 실제값으로 되돌린다(무음 실패 금지).

### 3.3 `UMapFloorLibrary` — 순수 계산 (월드/UMG 의존 없음)

`UCarPlacementLibrary` 와 동일한 `UBlueprintFunctionLibrary` 관례. 계산 로직을 전량 여기로 분리했기에 **PIE 없이 유닛테스트 5종으로 검증 가능**하다.

```cpp
static constexpr float DefaultSizeM = 160.f;
static constexpr float MinSizeM     = 10.f;
static constexpr float MaxSizeM     = 500.f;   // ← 정정(1000 아님). Landscape 평탄 구간 실측 한계 — §2.9

/** 텍스트 → 미터. 숫자로 해석 불가하면 false + OutMeters 미변경. */
static bool ParseSizeMeters(const FString& Text, float& OutMeters);

/** [Min, Max] 클램프. NaN/Inf 는 DefaultSizeM 폴백. */
static float ClampSizeMeters(float Meters);

/** 맵 크기(m) → 평면 로컬 스케일. 가로→X, 세로→Y, Z는 항상 1. */
static FVector MapSizeToPlaneScale(float WidthM, float DepthM,
                                   float MetersToUU = 100.f, float PlaneBaseUU = 100.f);
```

핵심 구현:
```cpp
bool UMapFloorLibrary::ParseSizeMeters(const FString& Text, float& OutMeters)
{
    const FString Trimmed = Text.TrimStartAndEnd();
    if (!Trimmed.IsNumeric())
    {
        return false; // 빈 문자열 / "abc" / "12abc" → 실패. OutMeters 미변경.
    }
    OutMeters = FCString::Atof(*Trimmed);
    return true;
}

float UMapFloorLibrary::ClampSizeMeters(float Meters)
{
    if (!FMath::IsFinite(Meters))
    {
        return DefaultSizeM; // NaN/Inf 는 클램프로 걸러지지 않는다.
    }
    return FMath::Clamp(Meters, MinSizeM, MaxSizeM);
}
```

`MapSizeToPlaneScale` 은 **축 매핑의 유일한 변환점**이다:
```cpp
// 가로(X) → UE X, 세로(Z) → UE Y. 평면이므로 Z 스케일은 1 고정.
return FVector((WidthM * MetersToUU) / PlaneBaseUU,
               (DepthM * MetersToUU) / PlaneBaseUU,
               1.f);
```
단위 사슬: `Scale = (160 × 100) / 100 = 160` → 실제 폭 `160 × 100uu = 16000uu = 160m`.

### 3.4 `AMapFloorActor` — 바닥 액터(뷰 + 크기 SSOT)

- 생성자: 메시/머티리얼 로드 → `NoCollision` → `SetCastShadow(false)`(VSM 페이지 절약, 그림자 *받는* 것은 유지) → `SetRelativeLocation(0,0,FloorZ)` → 초기 스케일.

- `SetFloorSize()` 말미에 향후 벽 확장 훅 주석만 남겼다(코드는 없다).

## 8. BUG-1 — 아스팔트가 안 보이던 문제 (**해결 완료 / 원인 설명 전면 정정**)

> ⚠️ **이 절은 2026-07-14 17:40 에 전면 재작성됐다.** 최초 작성 시점의 원인 설명("Fab 텍스처 결손으로 머티리얼 컴파일 실패 → Default Material 체커보드")은 **최종 원인이 아니었다.** 상세 조사 경위는 후속 문서 §2 를 볼 것.

### 8.1 무엇이 실제로 일어났나 (2단계 문제였다)

### 8.2 진짜 원인 — 자동 노출 (Eye Adaptation)

160×160m 짜리 **어두운 아스팔트가 화면을 가득 채우자**, 히스토그램 자동 노출이 "장면이 어둡다"고 판단해 노출을 약 **+0.7 EV(×1.64)** 끌어올렸다. 그 결과 **어두운 아스팔트가 베이지 중간톤으로 떠버렸다.** 즉 **머티리얼은 처음부터 옳았고, 화면에 그려지는 밝기가 틀렸던 것이다.**

- 레벨에 **PostProcessVolume이 하나도 없어** 엔진 기본 자동 노출이 그대로 걸려 있었다.
- **에디터 뷰포트는 고정 노출**로 동작한다 → **똑같은 액터가 에디터에서는 정상으로 보였다.** 이 비대칭이 오진을 오래 끌게 한 결정적 요인이다.

**결정적 증거 (이것 하나로 확정됐다):**
> PIE에서 **바닥만 숨겼더니, 아무것도 바뀌지 않은 Landscape의 밝기까지 변했다** — `(201,188,180)` → `(192,176,160)`.
>
> 바닥을 숨긴 것이 **다른 물체의 픽셀 값까지 바꿨다**면, 그건 그 물체의 머티리얼 문제일 수 없다. **화면 전체에 걸린 균일 게인 = 노출**이라는 뜻이다.

**실측으로 반증한 가설들** (전부 부정됨):

| 가설 | 반증 |
|---|---|
| 한글 경로(`M_아스팔트`) 인코딩 문제 | `OverrideMaterials[0]` 정상 할당. `[MapFloor]` 경고 0건 |
| 텍스처 스트리밍 미로드 | `neverStream=true` 로 강제해도 **증상 동일** |
| 렌더 스테이트 캐시 / usage flag | 무관 |
| Z-fighting | 무관 |

### 8.3 수정 — C++·머티리얼·텍스처 **전부 무수정**

레벨 `PresetMaker1` 에 **PostProcessVolume `PP_FixedExposure` 1개**를 추가한 것이 변경의 전부다.

| 프로퍼티 | 값 | 의미 |
|---|---|---|
| `bUnbound` | `true` | 레벨 전역 적용(볼륨 경계 무관) |
| `AutoExposureMethod` | `AEM_Histogram` | — |
| `AutoExposureMinBrightness` | `0.0` | **Min == Max → 노출 고정** |
| `AutoExposureMaxBrightness` | `0.0` | 위와 동일값 |
| `AutoExposureBias` | `1.0` | 고정 노출 기준 보정 |

**검증:** 바닥 평균 RGB **(176,155,135) → (56,43,34)**. 하늘·모래는 밝게 유지된다.

**트레이드오프(명시):** unbound 볼륨이므로 **레벨 전체 노출이 고정된다.** 카메라를 돌려도 밝기가 출렁이지 않는다 — 주차장 **저작 툴**에는 오히려 적합하다고 판단해 채택했다.

### 8.4 교훈 (재발 방지)

1. **그럴듯한 로그가 진범이라는 보장은 없다.** `Failed to compile Material` 은 사실이었고 실제 결손도 있었으나, **그것을 고쳐도 증상이 남았다.** "원인으로 보이는 것을 고친 뒤 증상이 사라졌는지 반드시 재확인"하는 절차가 빠졌다.
2. **에디터에서 정상인데 PIE에서만 이상하면, 에셋이 아니라 렌더 파이프라인(노출·포스트프로세스)을 의심하라.** 에디터 뷰포트는 고정 노출, PIE는 자동 노출이라는 비대칭이 존재한다.
3. **"내가 안 건드린 물체의 픽셀까지 변한다"** 는 관측은 문제를 개별 에셋에서 **화면 전역 효과**로 즉시 승격시키는 강력한 판별식이다.
4. (기존 교훈 유지) 사전 영향분석의 `get_dependencies` 는 **에셋 레지스트리의 참조 기록**일 뿐 **실제 파일의 존재를 보장하지 않는다.**
