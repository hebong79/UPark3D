# 주차장 선택 콤보(오른쪽 위) + 객리단길 레벨 전환

- 날짜: 2026-09-04
- 요청: ① 화면 오른쪽에 주차장을 고르는 메뉴(서신지구대 / 객리단길 콤보) ② 객리단길을 고르면 객사길 맵(레벨)을 찾아 로딩
- 결과: 구현·빌드·실기 검증 완료(`UnrealEditor -game`). **객사길 레벨은 이름으로는 존재하지 않고, `LV_Park_03` 이 그 레벨이라고 판정했다(근거 §1).** 패키지 재쿡은 하지 않았다(§5).

## 1. "객사길" 레벨은 어디 있나 — 이름으로는 없다, LV_Park_03 이다

`Park3D/Content/**/*.umap` 전수(20개)와 `_UnusedContent/`, 다른 작업본(`D:\Work\UnrealWork\Parking`, `D:\Work\Unreal\...`)까지
파일 이름에 객사/객리/Gaeksa 가 들어간 레벨은 **없다.** 주차장 레벨은 `Levels/LV_Park_01·03·04·05·06·07A·07B·08·09` + `LV_Main` 뿐이고
전부 번호 이름이다(`LV_Park_02` 는 어느 작업본에도 없다).

레벨 ↔ 주차장 이름의 대응은 레거시 BP UI 의 **`Content/Widgets/Panels/WBP_HomePanel.uasset`** 안에 있었다(UTF-16LE 문자열이라
ASCII grep 으로는 안 잡힌다 — 바이트 스캔으로 찾았다). 그 위젯의 "주차장 선택" 콤보 항목 10개:

> 서신지구대 · **객사길 한옥마을** · 동대문 지하주차장 · 속초 수산시장 (평행) · 평택 도로변주차장 · 오산휴게소 · 전주혁신도시 · 수서역 공영주차장 · 속초 수산시장 (사선) · 익산시청 지하주차장

레벨 배열 `LevelNames` 는 `[LV_Park_01, "", LV_Park_03, 04, 05, 06, 07A, 07B, 08, 09]` — **두 번째 칸이 빈 문자열**(레벨 하나가
빠져 있다). 항목 순서와 배열 순서가 일치한다고 보면 객사길 = 빈 칸이 되지만, 그 가정은 다른 항목에서 깨진다(동대문 지하주차장 → `LV_Park_03`
은 야외 노변 주차장이라 성립하지 않음). 그래서 BP 대신 **데이터로 판정**했다.

`UnrealEditor-Cmd -run=pythonscript -NullRHI` 로 레벨 10개를 열어 `BP_ParkingSlot` 액터(그룹)와 면 수(ISM Plane 인스턴스)를 셌다:

| 레벨 | 슬롯 그룹 | 면 수 | 대응 데이터 파일 | 판정 |
|---|---:|---:|---|---|
| LV_Park_01 | 6 | 6+4+6+4+1+2 = **23** | `001_Preset_23Face_Seoshin`(23) | 서신지구대 ✓(정확) |
| **LV_Park_03** | **3** | **5+5+4 = 14** | `001_Preset_13Face.객리단`(5+4+4 = 13), `CarPos_13Num.객리단`, `CamPos_13Face.객리단` | **객리단길(객사길)** — 3그룹 노변 주차, 면 수 1 차이 |
| LV_Park_07A | 3 | 6+37+12 = 55 | `001_Preset_55Face_사선`(55) | 속초 수산시장(사선) ✓(정확) |
| LV_Park_09 | 30 | 83 | `001_Preset_83Face익산`(83) | 익산시청 지하 ✓(정확) |
| LV_Park_04 | 15 | 91 | — | 도심 상가(`Jeonju_Mash` 건물 팩) |
| LV_Park_05 | 15 | 65 | — | 지하(PointLight 32) |
| LV_Park_06 | 40 | 400+ | — | 대형 |
| LV_Park_07B | 5 | 50 | — | 07A 와 같은 좌판 시장 |
| LV_Park_08 | 6 | 56 | — | — |

3그룹짜리는 `LV_Park_03` 과 `LV_Park_07A` 뿐이고 07A 는 55면 사선(속초)과 정확히 맞으므로 객리단(13면·3그룹)의 자리는 `LV_Park_03`
뿐이다. **실기 확인:** `LV_Park_03` 을 열자 담장 벽화가 `Love Jeonju`(전주) — 객리단길은 전주 객사길이다. `40Face_동대문` 만 어느 레벨과도
안 맞는데, 그것이 `LevelNames` 의 빈 칸(사라진 `LV_Park_02`)과 짝이라고 보면 전부 맞아떨어진다.

**한계:** 면 수가 13 vs 14 로 1 차이 나고, 레거시 BP 그래프를 끝까지 해석하지는 않았다. 틀렸다면 `config_pmaker.json` 의
`levels[1].level` 한 줄만 바꾸면 된다(코드 무수정).

## 2. 무엇을 만들었나

### 2.1 설정 — `Save/Config/config_pmaker.json` `levels[]`

```json
"levels": [
  { "name": "서신지구대", "level": "Levels/LV_Park_01" },
  { "name": "객리단길", "level": "Levels/LV_Park_03", "preset_file": "", "carpos_file": "CarPos_13Num.객리단.json", "camerapos_file": "CamPos_13Face.객리단.json" }
]
```

- `name` 이 콤보에 뜨고, 고르면 `level` 로 이동한다. 표기는 기존 `level` 키와 같은 세 가지(`LV_Park_01`·`Levels/LV_Park_01`·`/Game/Levels/LV_Park_01`)를 받는다.
- `preset_file`/`carpos_file`/`camerapos_file` 은 **키가 있을 때만** 최상위 `*_file` 을 덮는다(`TOptional`). 빈 문자열은 "이 주차장은 그 파일을 안 쓴다".
  주차장마다 차량·카메라 파일이 다른데, 안 덮으면 서신 차량 23대가 객리단길 위에 그대로 얹힌다.
- 하드코딩 대신 config 에 둔 이유: 레벨 지정이 이미 `config_pmaker.json` 의 `level` 로 되어 있고(2026-08-17), 판정이 틀렸을 때 코드 없이 고칠 수 있어야 한다.

### 2.2 `FPark3DAppConfig` (`Source/Park3D/Config/Park3DAppConfig.*`)

- `FPark3DLevelOption { Name, Level, TOptional PresetFile/CarPosFile/CameraPosFile }` + `TArray<FPark3DLevelOption> Levels`. `name`·`level` 이 빠진 항목은 경고 후 버린다.
- `NormalizeLevelPath()` — `TravelToConfigLevel` 안에 있던 표기 정규화를 꺼내 콤보와 공유한다(한쪽만 고쳐지는 일이 없게).
- `GetCurrentLevelPath(UWorld)` — PIE 접두어를 뗀 현재 패키지 이름.
- `ApplyLevelOverrides(Config, CurrentLevelPath)` — 현재 레벨과 같은 항목의 파일로 덮고 그 항목을 돌려준다(순수 함수, 테스트 가능).

### 2.3 `ULevelSelectWidget` (`Source/Park3D/LevelSelectWidget.*`, 신규)

**WBP 가 아니라 C++ 위젯 트리**로 만들었다(조명 패널·시뮬 HUD 선례). 이유: `Content/` 는 git 밖이라 WBP 는 커밋에 안 남고, 이 세션엔 에디터 MCP 가
연결되지 않았다. 새 클래스라 쿠킹된 WBP 의 베이스가 아니므로 `UPROPERTY` 를 두어도 `Bad export index` 함정과 무관하다.

- 오른쪽 위 고정(앵커 (1,0), −20/+20px), 250×96, 시뮬 HUD 와 같은 배경색·검은 글자. 제목 "주차장 선택" + `UComboBoxString` + 안내 한 줄.
- 콤보는 카메라 패널과 같은 흰 드롭다운·검은 항목 글자(`OnGenerateWidgetEvent`).
- `Populate()` 가 항목을 채우고 **현재 레벨 항목을 선택 상태**로 둔다. 코드 선택(`ESelectInfo::Direct`)은 이동을 일으키지 않고, 사용자가 고른 것만 `UGameplayStatics::OpenLevel`.
  현재 레벨과 같은 항목을 다시 고르면 이동하지 않는다.

### 2.4 `APark3DGameMode`

- `ShowLevelSelect()` — `BeginPlay` 에서 뷰어 다음, `ApplyStartupConfig` 앞에 호출. `levels` 가 비면 띄우지 않는다(로그 1줄). ZOrder 15.
- `ApplyStartupConfig()` 첫 단계에서 `ApplyLevelOverrides` 를 적용하고 로그 `[Config] 주차장 '…' 의 데이터 파일 적용: …` 을 남긴다.
- `TravelToConfigLevel()` 은 정규화·현재 레벨 판정만 라이브러리 호출로 바꿨다(동작 동일).

### 2.5 `Config/DefaultGame.ini`

`+MapsToCook=(FilePath="/Game/Levels/LV_Park_03")` 추가. **패키지에서 콤보가 동작하려면 재쿡이 필요하다** — 지금 배포본 pak 에는 LV_Park_01 만 있다.

## 3. 레벨 전환이 기존 매니저·RPC 를 깨뜨리는가 — 확인 결과 "안 깨진다"

| 대상 | 종류 | 전환 후 |
|---|---|---|
| `URpcServerSubsystem` | GameInstanceSubsystem | 살아남는다. 모듈은 `WorldGetter` 람다로 월드를 호출 시점에 푼다 → 새 월드를 본다. 실측: 전환 뒤 `system.health`·`car.list`(13대)·`cam.list`(2대) 정상 |
| `UCamStreamSubsystem` | TickableWorldSubsystem | 월드와 함께 내려가고 새 월드에서 다시 뜬다(같은 포트 재바인드). 검증은 `-NoCamStream` 으로 껐다 — 정본(13600/13611+)과 포트가 겹쳐서. **재바인드는 미검증** |
| 카메라·차량·프리셋·조명 매니저 | 액터 | 새 월드의 `GameMode::BeginPlay` 가 다시 만든다(원래 그렇게 설계됨) |
| `TravelToConfigLevel` 의 `static bAttempted` | 프로세스 1회 | 콤보로 옮긴 뒤 새 GameMode 가 config `level`(LV_Park_01)로 되돌리지 않는다 — 이 플래그 덕분. 의도된 동작이지만 의존하고 있다는 점을 적어 둔다 |
| `hide_actors` | config 전역 | 레벨별 이름이라 다른 레벨에서는 `0/2 못 찾음` 경고(기존 동작) |

전환 직후 RPC 호출 2건이 8초 타임아웃으로 실패했다가 30초 타임아웃으로 재시도하니 정상이었다 — 레거시 BP(`BP_PlayerController`) 컴파일 경고 35건이
로드마다 찍히며 몇 초를 먹는다(2026-08-17 과 같은 잔재). 전환 자체의 문제는 아니다.

## 5. 남은 것 / 위험

1. **객리단 데이터 파일이 `LV_Park_03` 지오메트리와 안 맞는다.** `CarPos_13Num.객리단.json`(Unity 좌표)의 차량 13대는 노변 주차면이 아니라 옆 공터에
   일렬로 놓인다(부감 캡처로 확인). 서신 파일이 LV_Park_01 에 우연히 맞았던 것과 달리 이 파일은 그 레벨용으로 만든 적이 없다. 차량 배치 패널에서 옮겨 같은
   이름으로 저장하면 된다(코드 무수정). 카메라 2대(`CamPos_13Face.객리단`)는 주차면 근처에 놓이지만 pan/tilt 는 미조정.
2. **패키지 재쿡 전에는 배포본에서 객리단길 선택이 실패한다**(pak 에 LV_Park_03 없음 → "맵 없음"). `BuildPackage.bat` 재실행 필요. 레벨 하나가 늘어 쿡 시간·용량이 는다.
3. `LV_Park_03` 판정은 §1 의 데이터 대조 + 벽화이지 문서 근거는 아니다. 사용자 확인 권장. 틀리면 config 한 줄.
4. `levels[]` 의 이름이 중복이면 첫 항목이 이긴다(콤보가 문자열 기반).
5. 팀 보드(baro_memo)는 이 머신에 `~/.config/baro-memo/env`(토큰)가 없어 검색·기록을 못 했다.
6. 테스트 실행 중 `Park3D.exe`(정본, 13510)는 건드리지 않았다. 검증용 `-game` 인스턴스는 종료했다.
