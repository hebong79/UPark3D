## 2. 도면 → 좌표 (가정을 명시한다)

도면 치수: 1~5 면 폭 5.85(선 0.15, 외측 6.15, 피치 6.0) · 7~14 면 폭 6.45(외측 6.75, 피치 6.6) · 깊이 2.40 = 면 2.25 + 선 0.15 · 5번 끝→카메라 폴 3.6 · 카메라 폴→7번 시작 4.0 · 10번 끝→다음 폴 구역 0.71.

레벨에는 폴대(`BP_Pole_C_1` 1번, `BP_Pole_C_3` 3번)가 이미 서 있고 카메라 8대가 거기 달려 있다. **폴대는 못 옮기므로 폴대를 기준으로 면을 놓았다.**

- 도로축: 기존 면 yaw 72.09°, 원점 = 옛 1번 면 중심 `(-1738.89, -6148.66)cm`. 축 좌표 s(m) 로 적으면 폴 1 = 28.01, 폴 3 = 63.20(간격 35.19 — 도면 환산 35.0 과 일치, 이것이 폴 기준을 택한 근거).
- 1~5: 5번 끝 = 28.01 − 3.6 → 중심 −2.59, 3.41, 9.41, 15.41, 21.41
- 7~10: 7번 시작 = 28.01 + 4.0 → 중심 35.31, 41.91, 48.51, 55.11 (10번 끝 58.41, 폴 3 까지 4.79 = 도면의 0.71 + 폴 구역)
- 11~14: 11번 시작 = 63.20 + **1.2**(도면 픽셀 비율로 추정한 카메라 폴 중심→11번 선) → 중심 67.7, 74.3, 80.9, 87.5
- 가로 방향: 연석(담장) 쪽 모서리를 고정(옛 t=−1.32)하고 깊이를 2.64→2.40 으로 줄였다 → 중심 t = −0.12. 도로(벽돌 포장)는 +t 쪽, 담장 `Love Jeonju`·인도는 −t 쪽(캡처로 확인).
- 판 크기는 bay 모듈의 외측 규약 `(폭+선, 길이+선)` = 2.40×6.00 / 2.40×6.60 — 피치와 같아 인접 판이 겹치지 않고 맞닿는다(옛 레벨은 6.14 판을 6.0 피치로 놓아 14cm 겹쳤다). `bay.list` 의 type 역판정(`BayClosestType`)이 585cm/645cm 로 돌아온다.

**도면과 어긋나는 곳(알고 둔 것)**: 1번 면 시작이 입구 차단봉(`BP_Barrier_Poles_1`, s=−7.43)에서 1.8m — 도면은 4.1m. 폴 간격과 입구 거리를 동시에 만족하는 배치는 레벨 폴 위치로는 없다(도면이 2.7m 더 길다). 14번 끝(90.8)이 스쿠터 소품(`SM_Scooter`, s=91.0)과 0.7m 겹친다. 둘 다 `bay.update` 로 즉시 조정 가능하다.

## 4. RPC 계약

```
bay.list                                       → level:… 항목 type 이 normal_585cm / normal_645cm
bay.update {name:"level:BP_ParkingSlot_C_3#3", pos?|delta? yaw? type? size?{x:폭,y:길이}}  → bay DTO
bay.delete {name|names|group}                 → deleted[] 에 level:… 도 들어간다. ⚠ 같은 액터 뒤 인스턴스 이름이 한 칸 앞으로
bay.create {group:"BP_ParkingSlot_C_3", pos, yaw?, type?}  → 그 액터의 ISM_Slot 에 추가(레벨 면). group 이 레벨 액터가 아니면 종전대로 프롭
bay.saveLevel {fullPath?|fileName?=LevelSlots} → {ok,path,fileName,count,level}   (Save/3D/Bay)
bay.loadLevel {fullPath?|fileName?}            → {ok,count,missingActors[],fileName,level}
```
- yaw 는 bay 규약(폭 방향 각). LV_Park_03 은 판 로컬 X 가 길이라 인스턴스 yaw 72.09 = bay yaw 162.09. 쓸 때는 그 액터의 기존 축 규약(bXLong)을 유지한다.
- 숨긴(`bay.hide`) 레벨 면은 update 를 거부한다(먼저 `hidden:false`).
- `levelSkipped[]` 는 호환용으로 남았고 항상 빈 배열이다.
- 파일 형식: `{"kind":"levelSlots","level":"/Game/Levels/LV_Park_03","actors":[{"name":"BP_ParkingSlot_C_1","slots":[{"pos":{x,y,z}(m),"yaw":72.09,"scale":{x,y,z}}]}]}` — scale 은 인스턴스 스케일 그대로(Plane 100cm 라 m).

## 6. 함정·메모

- `scene.load` 는 `name`(콤보 이름) 또는 `level` 이 아니라 **`name` 필수** — `{"level":"LV_Park_03"}` 은 `-32000 필수 파라미터 누락: name`.
- `bay.delete` 로 인스턴스를 지우면 ISM 이 뒤 번호를 당긴다 → 여러 개를 지울 땐 한 호출(`names[]`)로. 모듈은 액터별 내림차순으로 지운다.
- ISM 인스턴스 편집(`UpdateInstanceTransform`/`RemoveInstance`/`AddInstance`)은 BP 의 Static 모빌리티 컴포넌트에서도 -game 에서 그대로 먹었다(bay.hide 선례와 같다).
- 정본 `Package/Windows` 미교체. 반영 절차: exe 교체 + `Save/Config/config_pmaker.json`·`Save/3D/Bay/`·`Save/3D/CarPos/CarPos_13Num.객리단.json`·`Save/3D/CameraPos/CamPos_13Face.객리단.json` 복사. 패키지 재쿡은 불필요(Content 무변경).
