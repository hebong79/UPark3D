## 1. 작업 개요와 최종 구성

외부 PC의 "툴 + 에이전트"가 리얼카메라와 Park3D 시뮬레이터를 함께 제어할 수 있도록, **루프백에 묶여 있던 Park3D JSON-RPC 서버를 외부에 개방하고 그 앞에 토큰 인증 게이트를 세웠다.**

### 1.1 호출 경로 2개 — 둘 다 외부에서 닿는다

```
[외부 PC : 툴 + 에이전트]
    │
    ├─(A) REST 직접 호출 ────────────────────────► Park3D PC :13510  POST /rpc
    │      (대부분의 조작. JSON-RPC 2.0, 79개)        URpcServerSubsystem
    │                                                  ↑ X-Park3D-Token
    │
    └─(B) LLM 채팅 ─► MCP 클라이언트 ──HTTP──► Park3D PC :13520  /mcp
           (상황에 따라)                           park3d-rpc-mcp/server.py
                                                        │ ↑ X-Park3D-Token (MCP 토큰)
                                                        │ loopback
                                                        └──► :13510 POST /rpc
                                                             ↑ X-Park3D-Token (RPC 토큰, 별개 값)
```

**2홉 인증이다.** MCP 경계를 통과했다고 REST 경계가 자동 통과되지 않는다. 브리지는 자기 몫의 RPC 토큰을 따로 들고 있어야 하며, http 모드에서 `PARK3D_RPC_TOKEN`이 비면 브리지가 **기동을 거부**한다.

### 1.2 포트 변경

| 용도 | 변경 전 | 변경 후 |
|---|---|---|
| REST (JSON-RPC) | 13120 | **13510** |
| MCP (streamable-http) | (없음) | **13520 신규** |

`Docs/` 아래 13120을 언급하는 과거 11개 문서는 **역사 기록이므로 수정하지 않았다.** 포트 변경 사실은 이 문서로 연결된다.

### 1.3 범위 밖(명시적 비목표)

TLS/HTTPS 종단(평문 유지 — 근거는 8.2절) / 사용자별 계정·역할 분리(단일 공유 시크릿) / 메서드 단위 인가(79개 전부 동일 권한) / 감사 로그 영속화 / 레이트 리밋 / **기존 79개 메서드의 동작 변경**(인증 게이트만 앞단에 추가).

#### `server.py` 주요 변경

- **의존성**: `mcp>=1.2` → `mcp>=1.10,<2` + `uvicorn` + `starlette`. `mcp` 2.0.0에서 `mcp.server.fastmcp`가 **삭제**되어 기존 핀은 깨끗한 환경에서 import 에러로 즉사한다. 실측 해석 버전 `mcp 1.29.0` / `uvicorn 0.52.1` / `starlette 1.3.1`
- **전송 이중화**: `PARK3D_MCP_TRANSPORT`로 선택, **기본 `stdio`**(로컬 개발이 env 하나 없이 그대로 돌아야 함). 알 수 없는 값은 조용히 stdio로 떨어지지 않고 `SystemExit`으로 거부
- **MCP 인증**: `streamable_http_app()` + `BaseHTTPMiddleware`. `mcp.run(transport=...)`은 미들웨어를 끼울 수 없어 쓰지 않았다. 면제 경로는 `/health` 하나
- **예외 처리 버그 수정**: `urllib.error.HTTPError`는 `URLError`의 서브클래스다. 기존 코드는 `URLError`를 먼저 잡아 **401에 "서버 연결 실패. Park3D가 실행 중인지 확인하라"** 는 정반대 진단을 냈다. `HTTPError`를 **먼저** 분기하도록 두 툴 모두 수정
- **토큰 첨부 2경로**: `park3d_catalog`는 `_post_rpc`를 경유하지 않고 자기 `Request`를 직접 만든다. 한 곳만 고치면 **LLM이 가장 먼저 호출하는 툴**이 즉시 깨진다

## 3. 인증 설계 요약

### 3.1 판정 순서 — Origin 거부 → 토큰 → 루프백

게이트는 `HandleRpc`·`HandleCatalog`의 **각 함수 첫 줄 1행**(`PassAuthOrRespond`)으로만 존재한다. 롤백 시 이 2줄만 지우면 원복된다.

```
① Origin 헤더가 있는가?              → 있으면 무조건 401 (DeniedBrowserOrigin)
                                         토큰이 유효해도 거부한다. 예외 없음
② 토큰이 설정돼 있는가?
     ├ 예 → 헤더 토큰과 일치하는가?   → 불일치/누락이면 401 (DeniedBadToken)
     │                                   로컬(루프백)이어도 검사한다
     └ 아니오(무토큰) → peer가 루프백인가? → 아니면 401 (DeniedNotLoopback)
③ 통과 → 기존 79개 메서드 디스패치 (코드 불변)
```

**① Origin 거부가 왜 필요한가.** 저장소 기본 상태는 무토큰이다(토큰을 커밋하지 않기로 확정). 그때 게이트는 "peer가 루프백인가" 하나뿐인데, **개발자 PC에서 열린 임의 웹페이지는 루프백 주체로 통과한다.** 서버가 `Content-Type`을 검사하지 않으므로 `text/plain`으로 보내면 CORS simple request가 되어 preflight도 커스텀 헤더도 없이 `preset.deleteAll` 같은 파괴적 호출이 실행되고, `Allow-Origin: *` 때문에 `cam.captureJPG`의 화면 이미지까지 읽힌다.
비브라우저 클라이언트(curl, 브리지의 `urllib`, 외부 툴, Automation)는 `Origin`을 보내지 않으므로 **전부 무영향**이다. 1줄로 브라우저만 정확히 잘라낸다.

### 3.2 무토큰 시 — 루프백 전용 폴백

| 안 | 로컬 개발 | 외부 호스트 차단 | 판정 |
|---|---|---|---|
| ① 전부 허용 | 무해 | **위험.** ini에 한 줄 빠지면 79개가 LAN에 무인증 노출 | 기각 |
| ② **루프백 전용 허용** | 무해 | 안전 | **채택** |
| ③ 기동 거부 | **깨짐.** 에디터/PIE/Automation/패키지 로컬 실행 전부 토큰 필요 | 가장 안전 | 기각 |

②는 기존 로컬 워크플로를 한 줄도 건드리지 않으면서 같은 상태에서 외부 접근만 차단한다. 판정 근거가 "설정"이 아니라 "실제 peer 주소"라는 점이 중요하다 — 바인드는 `DefaultEngine.ini`, 토큰은 `DefaultGame.ini`로 서로 다른 파일이라 어긋나기 쉬운데, ②는 요청마다 실제 peer를 보므로 두 설정이 어긋나도 판정이 정확하다.

> ⚠ **②가 막는 범위는 "외부 호스트"까지다.** 이를 "fail-closed"라고 부르는 것은 과장이다. 인증되지 않은 **로컬 주체**(브라우저)는 ②가 막지 못하며 그 몫은 3.1의 Origin 거부가 담당한다.

### 3.3 루프백 판정은 문자열이 아니라 `GetRawIp()` **원시 바이트**

```
IPv4  (4바이트) : RawIp[0] == 127                                → 127.0.0.0/8 전체
IPv6 (16바이트) : [0..14] 전부 0 && [15] == 1                     → ::1
                  또는 [0..9]==0 && [10]==0xFF && [11]==0xFF && [12]==127
                                                                  → ::ffff:127.x.x.x
그 외 / 빈 배열 : false (fail-closed)
```

**왜 문자열 비교를 버렸나.** 바인드를 `any`로 열면 `SetAnyAddress()`가 호출되고, 플랫폼에 따라 듀얼스택 IPv6 소켓이 되어 로컬 peer 표기가 `127.0.0.1`에서 `::1`이나 `::ffff:127.0.0.1`로 바뀔 수 있다. 즉 **바인드를 여는 행위 자체가 로컬 판정을 깨뜨릴 수 있고, 예상 밖 표기 하나에 로컬이 통째로 401**이 된다.

엔진의 `FInternetAddr::IsLoopbackAddress()`를 쓰자는 제안이 있었으나 **UE 5.8에 그런 API는 없다.** `IsLoopbackAddress()`는 `Networking` 모듈의 `FIPv4Address`에만 있고, 채택했다면 (a) 모듈 의존이 추가로 필요하고 (b) **IPv4 전용이라 정작 문제의 IPv6 케이스를 못 잡는다.** `Sockets`에 실재하는 `GetRawIp()`가 두 문제를 동시에 해결하며, 덤으로 `TArray<uint8>` 하나만 받는 **완전한 순수 함수**가 되어 소켓 없이 테스트할 수 있다.

**로그에는 여전히 `ToString(false)` 문자열을 남긴다.** 판정은 바이트로, 진단은 문자열로 — 역할을 분리했다.

> 실측 결과 이 PC에서는 바인드를 `any`로 열어도 로컬 peer가 **IPv4 `127.0.0.1`(4바이트)** 로 도착했다. 문자열 방식도 우연히 동작했겠지만, 바이트 판정은 표기가 무엇으로 오든 안전하므로 채택은 유효하다(위험 감소이지 낭비가 아니다).

### 3.4 라우트별 정책 · 401 응답

| 라우트 | Origin 검사 | 토큰 검사 |
|---|---|---|
| `POST /rpc` | 필요 | 필요 |
| `GET /rpc/catalog` | 필요 | 필요 (메서드 목록 = 공격면 정찰 정보) |
| `GET /health` | 불필요 | 불필요 (방화벽/모니터링용. 본문 `{"ok":true}` 외 어떤 정보도 추가하지 않음) |
| `OPTIONS /rpc` | 불필요 | 불필요 (여기서 401을 주면 브라우저가 본요청조차 못 보냄) |

```http
HTTP/1.1 401 Unauthorized
Content-Type: application/json
Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: GET, POST, OPTIONS
Access-Control-Allow-Headers: Content-Type, X-Park3D-Token

{"jsonrpc":"2.0","id":null,"error":{"code":-32001,"message":"인증 실패: X-Park3D-Token 헤더가 없거나 일치하지 않습니다","data":null}}
```

- **본문은 기존 JSON-RPC 에러 스키마 그대로.** 401에서만 다른 스키마를 주면 클라이언트 파서가 갈라진다.
- **`id`는 항상 null.** 게이트는 본문을 파싱하기 **전에** 동작한다. 요청 id를 알려고 본문을 파싱하면 미인증 입력을 파서에 먹이게 된다.
- **세 실패 사유(토큰 불일치 / 비루프백 / Origin 존재)를 응답에서 구분하지 않는다.** 동일 문구. 사유는 서버 로그에만 남긴다.
- **401에도 CORS 헤더를 붙인다.** 안 붙이면 클라이언트가 본문을 읽지 못해 원인 불명 네트워크 에러로 보인다.
- 구현 메모: UE 5.8에 `EHttpServerResponseCodes::Unauthorized`라는 이름은 **없다.** 401의 이름은 `Denied`다(`HttpServerConstants.h:47`). 나가는 상태코드는 설계대로 401.

### 3.5 부수 결정 — `-RpcPort=0`은 이제 "서버 미기동"

기존에는 `CmdPort > 0` 가드에 걸려 **조용히 무시**됐다. 바인드를 개방한 뒤에는 자동화의 `-RpcPort=0`이 LAN에 리스닝 소켓을 여는 사고가 되므로, 스위치의 **존재 여부와 값을 분리**해 0이면 `StartServer`가 라우터 획득 **이전에** return한다 — 리스닝 소켓 자체를 만들지 않는다.

## 5. ⚠ 운영 필독 — 함정 4가지

**이 절이 이 문서의 핵심이다.** 아래 4개는 전부 "제대로 했는데 안 된다"로 나타나며, 그중 둘은 원인 추적이 사실상 불가능하다.

### 5.1 토큰 문자셋은 `[A-Za-z0-9_-]` 뿐이다 — 위반하면 **영구 401이고 추적 불가**

콤마·괄호·공백·탭·CR·LF를 쓰면 **경로마다 다르게 잘린다.** 토큰이 `ab,cd`일 때:

| 토큰 출처 | 파서 | 결과 |
|---|---|---|
| `-RpcToken=ab,cd` | `FParse::Value` (종료문자 `,) \r\n\t`) | `"ab"` **잘림** |
| `[RpcServer] Token=ab,cd` (ini) | `GConfig->GetString` (FParse 아님) | **`"ab,cd"` 원문 보존** |
| 헤더 `X-Park3D-Token: ab,cd` | 엔진이 헤더 값을 콤마 분할 → 첫 값 | `"ab"` **잘림** |

→ **ini로 토큰을 준 경우** Configured=`ab,cd` vs Presented=`ab` → **영구 401**. 그리고 서버는 토큰 값을 어떤 로그 레벨에서도 출력하지 않으므로(타당한 결정) **운영자는 원인을 영원히 알 수 없다.**

**완화 장치**: 기동 시 금지 문자를 검출하면 `Error` 로그 1줄이 뜬다 — **값은 출력하지 않고 "위반 사실"만** 알린다. 401이 계속되면 **가장 먼저 기동 로그의 `[RPC]` 라인을 볼 것.**

```
# 안전
PARK3D_TEST_TOKEN_A1    Abc-123_XY    a_b-c_D9
# 금지 — 조용히 잘린다
ab,cd    a b    a(b    a)b    "따옴표"    한글토큰
```

### 5.2 `-RpcToken=` 커맨드라인은 **엔진이 로그에 평문으로 에코한다**

QA가 실측으로 잡아낸 항목이다(B-1).

```
UnrealEditor.exe Park3D.uproject -game -RpcToken=PARK3D_TEST_TOKEN_A1 -log -abslog=<경로>
→ 생성된 로그에서 토큰 문자열 검색 시 2건 적중
  LogInit: Command Line: ... -RpcToken=PARK3D_TEST_TOKEN_A1 -unattended ...
  LogCsvProfiler: Display: Metadata set : commandline="" ... -RpcToken=PARK3D_TEST_TOKEN_A1 ...
```

**이것은 RPC 코드의 결함이 아니다.** `RpcAuth`/`RpcServerSubsystem`의 자체 로깅은 결백하며, 값이 새는 곳은 **엔진의 커맨드라인 에코 경로**(`LogInit`, `LogCsvProfiler`)다. 설계가 이 경로를 고려하지 않았다.

| 토큰 주입 경로 | 로그 노출 |
|---|---|
| `-RpcToken=<값>` | **노출됨** |
| `[RpcServer] Token=<값>` (ini) | **노출 안 됨** (GConfig 읽기는 에코되지 않는다) |

> ### 운영 지침 (확정)
> **토큰은 ini(`[RpcServer] Token=`)로 주입한다. `-RpcToken=`은 로그에 남으므로 일회성 테스트에만 쓴다.**

`.gitignore`의 `*.log`로 로그 자체는 커밋되지 않지만, **이 프로젝트는 `_workspace/`·`Docs/`에 로그를 첨부·인용하는 관행이 있어 사람이 옮기는 경로로 유출될 수 있다.** 실제로 구현자가 남긴 스모크 로그에 토큰이 2건 그대로 들어 있었다.

### 5.3 토큰을 켜는 **순간** 로컬 브리지 2개가 401이 된다

`.mcp.json`(Claude)과 `.codex/config.toml`(Codex) 어디에도 `PARK3D_RPC_TOKEN`이 **아직 없다.**

```
.mcp.json         env = { "PARK3D_RPC_URL": "http://localhost:13510" }   ← 토큰 없음
.codex/config.toml env = { PARK3D_RPC_URL = "http://localhost:13510" }   ← 토큰 없음
```

토큰이 설정되면 루프백 폴백이 꺼지고 **로컬이어도 토큰을 검사**하므로, 운영자가 `Token=`을 채우는 바로 그 순간 양쪽 stdio 브리지가 전부 죽는다. **이 phase의 목적 자체가 토큰 모드 활성화이므로 발생은 사실상 확정이다.**

주변 동작 점검에서 실서버로 재현했다:

```
(1) 토큰 미배선 — 현재 저장소 상태 그대로
    park3d_catalog → {"ok": false,
                      "error": "RPC 인증 실패(401): PARK3D_RPC_TOKEN 이 서버 토큰과 다르거나 없습니다."}
(2) PARK3D_RPC_TOKEN 배선
    park3d_catalog → {"ok": true, "methods": [ ... 79개 ... ]}
```

**다행히 실패가 조용하지 않다.** 브리지가 "서버 연결 실패"로 오진하지 않고 원인 변수명까지 정확히 짚는다(`HTTPError` 선행 처리 수정의 부수 이득).

> ### 토큰 활성화 절차에 **반드시** 이 배선을 포함시킬 것
> 토큰 설정과 브리지 배선은 **같은 작업 단위**다. 따로 하면 반드시 401을 밟는다.
>
> - 프로세스 환경변수로 `PARK3D_RPC_TOKEN`을 주면 `server.py`가 정확히 집어 헤더에 붙인다는 것은 **실측 확인됨**.
> - **[미검증]** `.mcp.json`의 `env` 블록이 `"PARK3D_RPC_TOKEN": "${PARK3D_RPC_TOKEN}"` 형태의 변수 전개를 지원하는지는 Claude Code 재기동이 필요해 확인하지 못했다. 전개가 안 되면 셸 환경변수 상속 여부를 확인하고, 그것도 안 되면 **"토큰 사용 시 `.mcp.json`을 로컬 전용으로 수정하고 커밋하지 않는다"** 를 절차로 채택한다(토큰은 저장소에 커밋하지 않는다는 원칙 유지).

### 5.4 헤더 키는 엔진이 **소문자로 정규화**한다

```cpp
// Engine/Source/Runtime/Online/HTTPServer/Private/HttpConnectionRequestReadContext.cpp:355
const auto& HeaderKey = HeaderLine.Mid(0, SplitIndex).TrimStartAndEnd().ToLower();
Request->Headers.Emplace(HeaderKey, MoveTemp(HeaderValues));
```

따라서 `Request.Headers.Find(TEXT("X-Park3D-Token"))`은 **항상 nullptr**이다. 서버는 반드시 `TEXT("x-park3d-token")`으로 조회해야 한다(`Origin`도 `TEXT("origin")`).

**클라이언트는 대소문자를 신경 쓸 필요가 없다.** `X-Park3D-Token` / `x-park3d-token` / `X-PARK3D-TOKEN` 세 표기 모두 200임이 실측으로 확인됐다.

이 한 줄이 "토큰을 제대로 보냈는데 계속 401"의 유일한 원인이 될 수 있어, 유닛 테스트 `Park3D.Rpc.Auth.HeaderKey`로 **가장 먼저** 못 박았다.

## 6. 미완료 · 미검증 항목 (은폐하지 않는다)

### 6.1 방화벽 인바운드 규칙 — **미적용**

관리자 권한이 필요해 적용하지 못했다. 현재 상태 실측:

- `13510`/`13520` 전용 인바운드 허용 규칙 **없음**
- `UnrealEditor.exe` 대상 인바운드 규칙은 존재하나 **전부 `Profile=Public`**
- 방화벽 프로파일 Domain/Private/Public **전부 Enabled**, `DefaultInboundAction=NotConfigured`

**Park3D PC에서 관리자 PowerShell로 실행할 것:**

```powershell
# REST (JSON-RPC)
New-NetFirewallRule -DisplayName "Park3D RPC 13510" `
  -Direction Inbound -Protocol TCP -LocalPort 13510 `
  -RemoteAddress 192.168.0.50 -Action Allow -Profile Private,Domain

# MCP (streamable-http)
New-NetFirewallRule -DisplayName "Park3D MCP 13520" `
  -Direction Inbound -Protocol TCP -LocalPort 13520 `
  -RemoteAddress 192.168.0.50 -Action Allow -Profile Private,Domain
```

> ### ⚠ `-RemoteAddress` **생략 금지**
> `-RemoteAddress`는 외부 툴 PC의 IP다. 여러 대면 쉼표로 나열하거나 `192.168.0.0/24`. **이것을 빼면 LAN 전체에 포트가 열린다.**
> 토큰은 평문 HTTP로 흐르므로 동일 네트워크 도청에 노출된다. 토큰 인증은 "포트 스캔·우연한 접속·다른 사내 서비스의 오인 호출"을 막는 층이지 **네트워크 도청을 막는 층이 아니다.** 출발지 IP 한정은 선택이 아니라 필수 방어층이다.
> `-Profile Private,Domain` — Public 프로파일에는 열지 않는다.

```powershell
# 확인
Get-NetFirewallRule -DisplayName "Park3D*" | Format-Table DisplayName,Enabled,Direction,Action
# 제거
Remove-NetFirewallRule -DisplayName "Park3D RPC 13510"
```

REST 직접 호출을 쓰지 않는 배치라면 13510 규칙을 생략하는 것이 최소 권한이다.

### 6.2 외부 PC 실접속 — **미검증**

| ID | 항목 | 상태 |
|---|---|---|
| T-M12 | 외부 PC에서 정토큰 `POST /rpc` → 200 | **미검증** |
| T-M13 | 외부 PC에서 무토큰 → 401 | **미검증** |
| T-M14 | 방화벽 `-RemoteAddress` 밖 IP에서 접속 차단 | **미검증**(규칙 자체가 없음) |

> ### 자기 LAN IP 자기접속은 대체재가 아니다
> 검증에서 성공한 `192.168.0.125` 접속은 **동일 호스트 트래픽**이라 방화벽 통과를 보장하지 않는다. 비루프백 peer 판정 경로를 실증하는 데는 유효하지만, "외부 PC에서 닿는가"의 답은 되지 못한다. 사내망 프로파일이 Private/Domain이면 **외부 PC는 6.1의 규칙을 추가하기 전까지 연결되지 않을 가능성이 높다.**

### 6.3 패키지 exe — **미갱신**

| 산출물 | 시각 |
|---|---|
| `Package/Windows/Park3D/Binaries/Win64/Park3D.exe` | **2026-07-29 18:38** |
| `Package/Windows/Park3D.exe`(런처) | 2026-07-30 16:55 |
| 인증 코드가 들어간 개발 DLL `UnrealEditor-Park3D.dll` | **2026-08-04 10:51** |

**현행 배포본은 포트 13120 + 인증 코드 없음 + 루프백 바인드다.** 재패키징이 필요하다.

- 커맨드라인 우회(`-RpcPort=13510`, `-ini:...BindAddress=any`)를 줘도 **인증은 존재하지 않는다.** 그 우회는 "포트/바인드 조정"용이지 "인증 획득"용이 아니다. 인증 게이트는 바이너리 안에 있다.
- 재패키징 후 검증 순서(추측 금지):
  1. **산출물 타임스탬프가 갱신됐는지 먼저 확인** (`RunUAT` exit 0을 신뢰하지 말 것 — 로그로 판정)
  2. exe 문자열 테이블에서 `DeniedBadToken`·`DeniedNotLoopback`·`DeniedBrowserOrigin`·`x-park3d-token` 검출. `TEXT()` 리터럴은 UTF-16이라 ASCII grep에 안 잡히므로 `strings -el` 사용
  3. **결정적 검증 — 비루프백 주소에서 토큰 없이 `POST /rpc` → 401이어야 한다.** 200이 오면 게이트 없는 바이너리가 개방된 것이므로 **즉시 중단**
  4. `Package/Windows/Save` 아래 기존 프리셋·차량 JSON 유실 여부 확인(**미검증** — 재패키징 미수행)

### 6.4 위험 P-1 — 콘텐츠-only 재쿠킹 시 "인증 없는 exe + bind=any ini"

**이 phase의 최대 위험이다.**

패키지의 Config는 pak/utoc에 쿠킹되고 평문 ini가 없다. **ini만 고치고 콘텐츠만 재쿠킹하면 쿠킹된 ini는 `Port=13510` + `BindAddress=any`를 싣는데 바이너리에는 게이트가 없다** → `0.0.0.0:13510`에 79개 메서드가 **인증 없이 LAN 개방**된다.

프로젝트 메모리 `packaged-vs-editor-divergences`가 "콘텐츠만 재쿠킹하면 exe가 낡은 채 남는다"를 **이미 겪은 사고**로 기록하고 있으며, 그 사고 패턴과 이번 변경(ini는 개방, 방어는 바이너리에)이 정확히 겹친다.

> **바이너리를 포함한 전체 재패키징만 허용한다. 콘텐츠-only 쿡 금지.**
> 재패키징 전까지는 `Package/` 산출물을 원격 개방 용도로 사용하지 않는다.

### 6.5 위험 P-3 — `/health`·OPTIONS는 무인증 + CORS `*` → LAN 존재 오라클

설계가 이 둘을 인증에서 면제한 판단 자체는 옳다(liveness가 필요하고, preflight를 막으면 브라우저가 본요청조차 못 보낸다). **그러나 그 판단은 "포트가 루프백에 묶여 있다"는 전제 아래 내려졌고, 이 phase가 그 전제를 없앴다.**

주변 동작 점검에서 LAN 인터페이스로 직접 확인했다:

| 요청 (LAN `192.168.0.125` 경유) | 응답 |
|---|---|
| `GET /health` 무인증 | **200** |
| `OPTIONS /rpc` 무인증 | **204** |
| `POST /rpc` 무토큰 | **401** `code:-32001` |
| `GET /rpc/catalog` 무토큰 | **401** |

→ 79개 메서드는 정확히 막혀 있고, 새는 것은 **"이 PC에서 Park3D가 돌고 있다" + "RPC 엔드포인트가 존재한다"** 두 가지 정보다. 둘을 합치면 완전한 존재 오라클이다. 인증 **이전 단계**인 엔진 HTTP 헤더 파서가 LAN에 노출된다는 점도 함께 남는다.

**`/health`에 인증을 붙이지 말 것**(요구사항 위반). **방화벽이 올바른 계층이다**(6.1).

## 7. 방화벽 / 전환 절차 / 롤백

### 7.1 권장 전환 순서

```
1. Build.cs + 코드/설정 변경 + 전체 빌드 + 유닛 테스트 통과   ← 이 시점까지 외부 개방 없음
2. Token 미설정 상태로 로컬 기동 → 무토큰 루프백 200 확인      ← 기존 흐름 무해 증명 (되돌릴 지점)
3. 참조처 동기화(.mcp.json / .codex/config.toml / AGENTS.md / SKILL.md)
4. 토큰 설정 후 로컬 인증 매트릭스 확인 + 브리지 토큰 배선(5.3)
5. DefaultEngine.ini 바인드 개방 → netstat / 기동 로그 bind= 확인   ← ★ 실제 노출 시점
6. 방화벽 규칙 추가(6.1) → 외부 PC에서 200/401 실증
7. MCP http 모드 기동 → 2홉 왕복 확인
8. 패키지 전체 재빌드 → 6.3의 3단 검증
```

**2단계에서 멈추면 아무것도 외부에 열리지 않은 채 되돌릴 수 있다. 5단계가 실제 노출 시점이므로 4단계를 반드시 먼저 끝낸다.**

> ⚠ **현재 저장소는 5단계가 이미 반영된 상태다.** `DefaultEngine.ini`에 `+ListenerOverrides`가 들어가 있으므로, **다음번에 Park3D(PIE/`-game`/패키지)를 실행하는 순간부터** `0.0.0.0:13510`이 열린다(상시 개방은 아니다). 다만 `Token=`이 비어 있는 한 무토큰 폴백이 외부를 401로 차단하므로, 실제로 열린 것은 6.5의 존재 오라클뿐이다.
> **이 안전 마진은 `Token=`이 비어 있다는 사실 하나에 전적으로 의존한다.** 누군가 토큰을 설정하면 폴백이 꺼지고 토큰 강도가 유일한 방어선이 된다 — 그래서 **토큰 설정과 방화벽 적용은 같은 작업 단위로 묶어야 한다.**

### 7.2 롤백

**바인드만 되돌리기 — `DefaultEngine.ini`의 `+ListenerOverrides` 한 줄 삭제 후 재기동.**

```ini
[HTTPServer.Listeners]
+ListenerOverrides=(Port=13510,BindAddress=any)   ← 이 줄만 삭제
```

3가지 단서:

1. **스테일 config 오염 없음이 실측으로 확인됐다.** UE는 런타임 config 변경을 `Saved/Config/**`에 기록해 Default*.ini에서 지워도 되살아나는 함정이 있는데, `Park3D/Saved/Config/WindowsEditor/*.ini`에 `[HTTPServer.Listeners]`/`ListenerOverrides`는 **0건**이다. 한 줄 삭제로 깨끗하게 되돌아간다.
2. **"즉시"가 아니라 "재기동 시"다.** 바인드는 리스너 생성 시점에 결정되므로 실행 중인 인스턴스는 그대로 열려 있다. 롤백 후 **반드시 재기동**하고 기동 로그의 `bind=` 값으로 확인한다 — 이 로그를 넣어 둔 목적이 정확히 이것이다.
3. **패키지 exe에는 적용되지 않는다.** 쿠킹된 ini가 pak/utoc 안에 있으므로 재쿡 전까지 산출물에 영향을 주지 않는다.

**전체 되돌리기** — 게이트 2줄(`HandleRpc`/`HandleCatalog`의 `PassAuthOrRespond`) 제거로 원복된다. 게이트를 각 함수 **첫 줄 1행**으로 유지한 부가 이유다. `Build.cs`의 `Sockets`는 남겨도 무해하다.

### 8.2 보안 적대적 검토 — 우회 경로 없음

| 공격 시도 | 결과 | 근거 |
|---|---|---|
| 브라우저 `fetch` + `text/plain` simple request | **401** | 브라우저는 cross-origin POST에 `Origin`을 반드시 붙인다 → 무조건 거부 |
| 브라우저 `<form>` cross-origin POST | **401** | 현대 브라우저는 POST 내비게이션에도 `Origin`을 붙인다 |
| `<script src=".../rpc/catalog">` | 요청은 통과하나 **읽기 불가** | JSON 본문은 유효한 JS가 아니다. `fetch`로 읽으려면 Origin이 붙어 401 |
| `<img>`/내비게이션으로 `GET /rpc` | **404/405** | `/rpc`는 POST·OPTIONS만 바인드 |
| `X-Forwarded-For` 등 헤더로 루프백 위장 | **불가** | peer는 소켓 `getpeername()` 유래. 헤더 미사용 |
| 원격에서 소스 IP `127.0.0.1` 스푸핑 | **불가(사실상)** | TCP 3-way 핸드셰이크 성립 불가 + OS martian 필터 |
| `IsLoopbackRawIp` 오탐 유도 | **불가** | 길이 불명/빈 배열은 **fail-closed** |
| 토큰 헤더 누락/빈 값 | **401** | 어느 한쪽이라도 Trim 후 비면 false |
| 헤더 키를 대문자로 위장해 게이트 우회 | **불가** | 게이트가 소문자 키로 조회, 엔진이 수신 키를 소문자로 정규화 → 표기 무관 |
| 경로 변형(`/rpc/`, `//rpc`) | **우회 없음** | `FHttpPath` 정확 매칭. 매칭되면 게이트 적용, 아니면 404 |
| 배치 배열로 게이트 뒤 진입 | **불가** | 게이트가 `BodyToString` **이전** |
| 공백만 있는 토큰으로 우회 | **불가** | 무토큰 폴백 = 루프백 전용으로 수렴. 외부는 여전히 `DeniedNotLoopback` |

**`/rpc`·`/rpc/catalog`에 대한 인증 우회 경로를 찾지 못했다.** 무토큰 폴백은 루프백 한정으로 정확히 좁혀져 있고, Origin 거부가 로컬 CSRF를 실제로 막는다.

### 8.3 위젯 · 에셋 · JSON 스키마 — 영향 없음

- 변경 파일 목록에 위젯·매니저·에셋이 없다. 위젯은 RPC를 경유하지 않는다.
- `Park3DRpcTypes.h`는 상수 **추가**만 하므로 이 헤더를 include하는 곳의 재컴파일은 발생하나 **의미 변화는 없다.**

### 8.5 하네스 동등성

`.claude/skills/`는 9개, `.agents/skills/`는 8개로 `park3d-auto-approve`의 Codex 대응 스킬이 없다. **이는 Codex 동등성 위반이 아니다** — 해당 스킬은 `.claude/settings.json`의 permissions 규칙을 편집·유지보수하는 것으로 내용 전체가 Claude Code **권한 문법**이며, 동등성 계약이 *"모델명·협업 도구·권한 문법은 각 플랫폼의 유효한 형식을 사용한다"*로 명시적으로 예외를 둔 범주다. 역할·게이트·산출물·실패 복귀 중 어느 것도 이 스킬 부재로 달라지지 않는다. **본 phase 소산도 아니므로 별건으로 둔다.**
