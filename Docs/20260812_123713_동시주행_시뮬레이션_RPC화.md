# 입·출차 시뮬레이션 동시 주행 + RPC 대칭화

- 날짜: 2026-08-12
- 브랜치: `feat/sim-dir-rpc`
- 요청: "입차처럼 출차 관련 RPC화를 해줘" → 확인 결과 `sim.exit` 는 이미 있었고, 실제 요구는
  **"여러 대가 동시에 돌 수 있게"** 였다(작업 중 추가 지시).

---

## 1. 무엇이 문제였나

`sim.exit` 는 2026-08-11 에 이미 결선돼 있었다. 입차와 다른 점은 두 가지뿐이었다.

| | 변경 전 입차 | 변경 전 출차 |
|---|---|---|
| 주행만 | `sim.start` | 없음 (`sim.exit {replay:false}` 로 대체) |
| 주행+리플레이 | `sim.scenario` | `sim.exit {replay:true}` |
| 방향 지정 | — | — (`AParkingSimManager::ParseDir()` 이 구현돼 있는데 **호출부가 하나도 없었다**) |

그리고 더 큰 제약이 있었다. **매니저가 월드에 1개, 주행도 항상 1건**이라
입차가 도는 중에 출차를 부르면 진행 중이던 주행이 통째로 버려지고 그 차량도 사라졌다.
차량 여러 대가 동시에 움직이는 시나리오는 불가능했다.

---

## 2. 설계 — 액터 1개 = 주행 1건

주행 상태(경로·위치·속도·기록·리플레이)가 전부 `AParkingSimManager` 의 멤버이고
`Tick()` 이 그 상태를 돌린다. 그래서 **주행 로직(약 700줄)은 한 줄도 고치지 않고
액터를 여러 개 스폰**하는 것으로 병렬 주행이 된다.

> 대안이었던 "주행 상태를 `FParkSimRun` 구조체로 빼서 한 액터가 배열로 관리"는
> `StartSim`/`TickDrive`/`TickReplay`/`FinishRun` 전부를 고쳐야 해서 이득 없이 위험만 크다.

각 주행은 `RunId`(1부터) 로 식별한다. 완료된 주행도 기록 조회를 위해 액터로 남고,
`KeepFinishedRuns`(20건) 를 넘으면 오래된 것부터 파괴된다. 동시 주행 상한은 `MaxConcurrentRuns` = 16.

### 동시 실행 때문에 새로 막은 것

| 문제 | 원인 | 대응 |
|------|------|------|
| 두 대가 같은 주차면에 겹침 | 대상 면을 무작위로 뽑는데 다른 주행의 면을 몰랐다 | `CollectOccupiedSlots()` — 도는 주행 + 주차 완료 상태 주행의 `(presetId, slotIndex)` 를 후보에서 제외 |
| 차량 id 충돌 | id 가 `{인덱스}-{HH.mm.ss}` 라 같은 초에 두 대가 생기면 겹친다 | `FindByNameId` 로 빌 때까지 인덱스를 민다(주행 스폰·리플레이 스폰 양쪽) |
| 로그 파일 덮어쓰기 | 파일명이 타임스탬프뿐이라 같은 초에 두 주행이 끝나면 하나가 사라진다 | `<타임스탬프>_r<RunId>_sim.log/.json` |
| 콘솔 로그가 뒤섞임 | `[Sim]` 접두사가 모두 같다 | `[Sim #<RunId>]` |

### 하지 않은 것

**차량 간 충돌 회피는 없다.** 경로가 겹치면 두 차가 서로 통과한다. 요청 범위 밖이라 넣지 않았다.

## 4. RPC 사양

### 시작 계열 — 부를 때마다 새 주행이 하나 생긴다

```jsonc
// 입차(기본). dir 을 붙이면 출차도 같은 메서드로.
{"method": "sim.start", "params": {
  "dir": "enter",       // "enter"(기본) | "exit"  — "입차"/"출차"/"out" 도 인식
  "presetId": 0,        // 0=무작위
  "slotIndex": 0,       // 0=무작위(1-based)
  "seed": 0,            // 0=비결정
  "parkMode": "random"  // 생략 시 방향별 기본값: 입차=random, 출차=rear
}}

// 주행 + 완료 후 자동 리플레이까지 예약
{"method": "sim.scenario", "params": {
  "dir": "exit", "replay": true, "replayDelaySec": 1.5, "replaySpeed": 1.0
}}

// 출차 별칭(기존 호출 호환). dir 을 무시하고 항상 출차, replay 기본 false
{"method": "sim.exit", "params": {"parkMode": "front"}}
```

응답에 `runId` 가 들어 있고, 이후 조회·제어는 이 값으로 한다.

### 조회·제어 계열 — `runId` 를 생략하면 가장 최근 주행

```jsonc
{"method": "sim.list",   "params": {"busyOnly": false}}   // 주행 목록 + busyCount + maxConcurrent
{"method": "sim.status", "params": {"runId": 5, "events": 20}}
{"method": "sim.replay", "params": {"runId": 5, "speed": 3.0}}
{"method": "sim.stop",   "params": {"all": true, "removeCar": true}}  // all=true 면 도는 주행 전부
{"method": "sim.entrance"}                                            // 입구=출구 좌표(주행 없으면 조회용 1건 생성)
```

`sim.list` 한 줄: `runId, state, phase, simMode, busy, presetId, slotIndex, parkMode, carId, elapsedSec, distanceM, result`

### HUD·단축키

- **F9 입차 / F8 출차** — 누를 때마다 주행이 하나씩 **추가**된다(기존 주행을 끊지 않는다).
- **정지 버튼** — 도는 주행을 전부 세운다(개별 정지는 `sim.stop {runId}`).
- **F10 리플레이** — 가장 최근 주행.
- 상태줄: `주행 3건   #4 주행   경과 2.1s   이동 1.9m   출차 5-11면`

## 6. 알아 둘 성질

- **면을 다 쓰면 시작이 막힌다.** 주차 완료 상태의 주행도 면을 점유로 잡으므로,
  주차면 수보다 많이 입차시키면 "쓸 수 있는 주차면이 없습니다" 가 난다. 정상 동작이다.
- **끝난 주행은 20건까지만 남는다.** 그 이상 지나면 `sim.status {runId}` 가 "주행이 없습니다" 를 낸다.
  기록 자체는 `Save/3D/Sim/` 에 파일로 남는다.
- **`sim.entrance` 는 주행이 하나도 없으면 조회용 주행 액터를 하나 만든다**(대기 상태라 상한에 안 걸린다).
  그래서 첫 `sim.start` 의 `runId` 가 2 부터 시작할 수 있다.
- 주행마다 로그 2개(`.log`/`.json`)가 쌓인다. 자동 정리는 없다.
