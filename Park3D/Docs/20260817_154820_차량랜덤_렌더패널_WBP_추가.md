# 차량 랜덤 패널(WBP_RenderPanel) 추가 — 이전 BP UI 의 렌더 패널 복원

- 날짜: 2026-08-17
- 브랜치: `feat/unified-hud-ui`
- 요청: "이전 블루프린트로 만들어진 UI를 최대한 참조하고, 현재 UI의 내용을 모두 사용할 수 있게 변경해줘."
  이후 시안을 보고 결정 — ① 탭이 아니라 **독립 패널**로 띄운다 ② **렌더 패널을 만든다** ③ **WBP 로 만든다**
- 결과: **동작 확인 완료.** 메뉴 → "차량 랜덤" → 랜덤 적용으로 차량 23대의 차종·색상이 바뀌는 것을 화면으로 확인했다.

## 1. 이전 UI 에서 가져온 것

블루프린트 세트(`/Game/Widgets`)는 공용 컴포넌트를 갖춘 디자인 시스템이었다.

| 이전 컴포넌트 | 이번 패널에서 |
|---|---|
| `WBP_BlurPanel` | 어두운 반투명 `Border` 바탕(A=0.96) |
| `WBP_TitlePanel` | 제목 + 드래그(루트 보더 렌더 이동) |
| `WBP_Section` | "랜덤" / "표시" 흐린 구획 라벨 |
| `WBP_ComboBox` | 범위 선택(드롭다운 흰 배경 + 검은 글자) |
| `WBP_RenderPanel` | **이 패널 자체** — 그 자리를 대신한다 |

이전 `WBP_RenderPanel` 은 전체 차량 색/차종 랜덤·차량 선택·표시 토글을 갖고 있었고,
현재 코드에서는 그 기능이 `random.*`·`car.*` RPC 로만 열려 있어 화면에서 쓸 수 없었다.

## 2. 만든 것

### 2.1 `URenderPanelWidget` (C++ 베이스)

BindWidget 12개. 동작은 전부 `ACarPlacementManager` 가 소유하고 위젯은 그것만 부른다
(`UCarPlacementWidget` 의 "리셋랜덤" 선례와 같은 규율 — 위젯은 상태를 갖지 않는다).

| 구획 | 컨트롤 | 백엔드 |
|---|---|---|
| 랜덤 | 범위 콤보 · 대수 · 시드 · 랜덤 적용 | `ResetRandomPlacement(Mode, Catalog, Count, Seed)` |
| 랜덤 | 도색 원복 | 차량 순회 `ColorComp->ResetColor()` |
| 표시 | 가릴 대수 · 무작위 숨김 | `HideRandomCars(Count, Seed)` |
| 표시 | 표시 반전 | `ToggleRandomCars(Count, Seed)` |
| 표시 | 전부 표시 · 전체 숨김 | `SetAllCarsHidden(bool)` / `AreAllCarsHidden()` |

랜덤은 **UI 와 RPC 가 공유하는 진입점 `ResetRandomPlacement` 하나로 모았다** — 두 경로가
갈라지면 한쪽만 고쳐지는 전례가 있었다. 콤보 항목 순서는 `ERandomResetMode` 값 순서와 1:1 이다.

전체 숨김 체크 상태는 위젯이 들지 않고 **열릴 때마다 월드에서 읽는다**(`AreAllCarsHidden`).
RPC(`car.hideAll`)로 바꾼 뒤 패널을 열면 위젯이 들고 있던 값과 어긋나기 때문이다(차량 배치 패널 선례).

### 2.2 `WBP_RenderPanel` (`/Game/UI`)

`UMGToolSet` MCP 로 생성·구성·컴파일·저장했다. 트리:

```
RootCanvas (CanvasPanel)
└ RootBorder (Border)            ← CanvasPanelSlot: 좌상단 16,16 / 364×284
  └ VBox_Root (VerticalBox)
    ├ Txt_Title "차량 랜덤"
    ├ Lbl_SecRandom "랜덤"
    ├ Row_Mode      : Lbl_Mode + Combo_Mode
    ├ Row_Num       : Lbl_Count + Field_Count + Lbl_Seed + Field_Seed
    ├ Row_RandomBtns: Btn_Randomize + Btn_ResetColor
    ├ Lbl_SecShow "표시"
    ├ Row_Hide      : Lbl_HideCount + Field_HideCount
    ├ Row_HideBtns  : Btn_HideRandom + Btn_ToggleRandom + Btn_ShowAll
    ├ Row_HideAll   : Check_HideAll + Lbl_HideAll
    └ Txt_Status
```

### 2.3 메뉴 진입

`UMainMenuWidget::InjectRenderButton()` 으로 Exit 앞에 "차량 랜덤" 버튼을 런타임 삽입한다
(조명·시뮬 버튼과 같은 방식 — `WBP_MainMenu` 자산을 건드리지 않는다).
패널 클래스는 BP 기본값(`RenderPanelWidgetClass`)이 비어 있으면 `/Game/UI/WBP_RenderPanel.WBP_RenderPanel_C`
를 직접 로드한다. 조명 패널처럼 C++ 클래스로 폴백하지 않는 이유는 이 패널은 위젯 트리가 WBP 에 있어
C++ 클래스만으로는 화면이 비기 때문이다.

## 3. WBP 를 스크립트로 만들 수 있게 된 경위

이 프로젝트는 2026-08-05 에 "UE5.8 파이썬에 `WidgetTree` 미노출 → WBP 제작 불가" 로 판단하고
조명 패널을 C++ 위젯 트리로 우회했다. 이번에 다시 확인한 결과는 이렇다.

| 경로 | 상태 |
|---|---|
| 파이썬 `WidgetBlueprint.WidgetTree` | 여전히 protected — 불가 |
| 스킬에 적힌 MCP `add_widget` 계열 | **사라짐.** 커밋 `2fa59d0`(`AllToolsets`→개별 툴셋)으로 등록이 끊겼다 |
| 엔진 `UMGToolSet` 플러그인 | **여기 있었다.** `Experimental/Toolsets/UMGToolSet` — "AI assistant tools for creating and manipulating UMG widgets via reflection" |

`UMGToolSet` 만 개별로 켜서 해결했다(`EditorOnly: true`, `TargetAllowList: ["Editor"]` 라
쿡·런타임에 영향 없음). **`AllToolsets` 로 한꺼번에 켜면 안 된다** — `GameFeatures` 가 딸려 와
쿡이 깨진다(`2fa59d0` 이 고쳤던 바로 그 문제).

이 세션은 시작 시 에디터가 꺼져 있어 MCP 툴이 붙지 않았으므로, `Tools/wbp/umcp.py` 로
HTTP 프로토콜을 직접 말해 우회했다(initialize → `Mcp-Session-Id` 헤더 → `notifications/initialized`).

### 함정

- **툴 호출은 `call_tool` 을 거친다.** `tools/list` 에는 세 개(`call_tool`·`describe_toolset`·
  `list_toolsets`)만 보이고 실제 툴은 툴셋 안에 있다.
- **자산 참조는 오브젝트 전체 경로**(`/Game/UI/WBP_X.WBP_X`). 패키지 경로만 주면 거절된다.
- **루트를 Border 로 두면 화면 전체를 덮는다.** 1차 산출물이 그랬다 — 패널은 떴지만 씬이 가려졌다.
  루트는 `CanvasPanel`, 배경 Border 는 자식으로 두고 슬롯에 앵커·오프셋을 준다(`LayoutData` 로 감쌀 것).
- **컴파일 성공이 곧 BindWidget 검증이다.**

## 4. 검증

`-game` 으로 띄워 창을 캡처했다(카메라 스트림에는 UMG 가 실리지 않는다 — 3D 씬만 나간다).

| 항목 | 결과 |
|---|---|
| 메뉴에 "차량 랜덤" 버튼 | 조명·시뮬 아래, Exit 위에 삽입됨 |
| 패널 열기 | 좌상단에 열리고 프리셋 메이커는 배타 토글로 닫힘 |
| 패널 크기 | 씬을 가리지 않음(1차의 전체 덮기 수정 확인) |
| 랜덤 적용 | 차량 23대의 차종·색상 변경, 상태에 `차종 + 색상 적용 — 차량 23대` |
| C++ 컴파일 | 성공 |
| WBP 컴파일 | 성공(= BindWidget 12개 충족) |

## 5. 한계 / 남은 것

- **WBP 자산은 커밋에 없다**(`Content/` 는 gitignore). 다른 작업본에서는 `Tools/wbp/` 의
  스크립트로 재생성해야 한다. README 에 순서와 전제를 적었다.
- **시나리오 촬영은 넣지 않았다.** 시안에는 그렸지만, 실행 로직이 `FScenarioRpcModule` 안에 있어
  위젯에서 부르려면 공용 함수로 빼는 리팩터링이 필요하다. 범위가 커서 별도 작업으로 남긴다.
- 시안의 "거리·각도·줌 범위" 슬라이더도 같은 이유로 보류했다 — 대응하는 매니저 API 가 없다.
- 나머지 패널(카메라·차량·주차면)의 디자인 통일은 하지 않았다. 사용자가 "패널로 띄운다"를
  선택했고 기존 패널은 이미 동작하므로, 건드리면 회귀 위험만 커진다.
