- 날짜: 2026-08-06
- 브랜치: `fix/stream-indirect-light` (워크트리 `D:\Work\UnrealWork\Parking_wt_stream-light`)
- 입력: `Park3D/Docs/Bug/20260806_163723_Park3D_스트림영상_간접광누락_진단.md`
- 결과: **수정 완료·검증 통과**

## 1. 신고 내용

카메라별 MJPEG 스트림(`http://<IP>:13600+camId/`)으로 받은 화면이 `cam.captureJPG` 로 받은
화면보다 어둡고 색이 다르다. 진단서는 "간접광(스카이라이트/GI) 기여가 빠졌다"까지를 측정으로
확정하고, 원인은 시뮬 코드를 봐야 한다고 남겼다.

## 2. 원인

두 경로의 픽셀 파이프라인은 **완전히 동일하다.** 둘 다 같은 `APTZCameraActor::Capture`
(`USceneCaptureComponent2D`, `SCS_FinalColorLDR`)의 같은 렌더타깃을
`CaptureOnce()` → `ReadPixels(RCM_UNorm, LinearToGamma=false)` → JPEG 인코딩으로 처리한다.

다른 것은 **캡처 시점의 컴포넌트 상태 한 가지**뿐이었다.

| 경로 | 캡처 직전 | `bCaptureEveryFrame` |
|---|---|---|
| `cam.captureJPG` | `ResolveCaptureCam` 이 `SelectCamera` 호출 (`CamRpcModule.cpp:91`) | true |
| `/stream` | 선택 상태를 건드리지 않음(의도된 규율) | false |

언리얼 `USceneCaptureComponent::GetViewState()` 는 `bCaptureEveryFrame` 도
`bAlwaysPersistRenderingState` 도 false 이면 **`FSceneViewState` 를 파괴한다.**
뷰 스테이트는 프레임 간 누적이 필요한 렌더 기능의 저장소이므로, 없으면
**Lumen GI · 리플렉션 · TSR · 아이 어댑테이션이 전부 죽는다.**

`bAlwaysPersistRenderingState` 는 `PTZCameraActor` 어디에도 설정된 적이 없었다(기본 false).
따라서 **비선택 카메라의 캡처만** 매번 뷰 스테이트 없이 렌더되어 간접광이 빠졌다.

이는 진단서의 측정과 정확히 일치한다 — 방향광이 지배하는 하늘·차 지붕은 그대로이고,
하늘빛 채움광에 의존하는 그늘·확산면만 어두워지며 남은 햇빛의 따뜻한 색만 남아 갈색이 된다.

### 중요: 증상은 카메라가 아니라 "선택 상태"에 붙어 있었다

진단서 §10 이 남긴 "camId 2 한 대만 측정했다" 는 위험은 이로써 해소된다.
**선택 중인 카메라의 스트림은 정상, 비선택 카메라의 스트림만 어둡다.** 같은 camId 라도
선택을 바꾸면 증상이 나타났다 사라진다.

## 3. 수정 내용

`Park3D/Source/Park3D/PTZCameraActor.cpp` 생성자 — 1줄(+주석 3줄).

```cpp
Capture->CaptureSource = ESceneCaptureSource::SCS_FinalColorLDR;  // 톤매핑된 색(UI 프리뷰용)
// 비선택 카메라도 FSceneViewState 를 유지한다. 이게 없으면 bCaptureEveryFrame=false 인 캡처마다
// 엔진(USceneCaptureComponent::GetViewState)이 뷰 스테이트를 파괴해 Lumen GI/리플렉션/TSR
// 히스토리가 사라진다 — /stream 만 간접광이 빠져 어둡고 갈색으로 보이던 원인.
Capture->bAlwaysPersistRenderingState = true;
```

### 검토한 대안

| 안 | 판정 |
|---|---|
| 슬롯 보유 카메라에 `bCaptureEveryFrame = true` | 기각 — 매 게임 프레임 렌더가 붙어 fps 예산 설계가 무너진다(캡처 1프레임 약 48ms) |
| 스트림이 캡처 전 `SelectCamera` 호출 | 기각 — UI 선택이 스트림에 끌려다니고, 선택은 1대뿐이라 다중 슬롯 스트리밍이 여전히 깨진다 |
| 수신측(SettingManager) 감마·색 보정 | 기각 — 진단서 §7 에서 이미 기각(단일 톤커브로 색이 맞지 않음) |

## 4. 신규 유닛 테스트

`Park3D/Source/Park3D/Tests/PTZCameraCaptureStateTest.cpp`
(`Park3D.CameraControl.CapturePersistRenderState`)

선택 → 해제로 `bCaptureEveryFrame` 를 토글해도 `bAlwaysPersistRenderingState` 가 true 로 남는지,
`CaptureSource` 가 `SCS_FinalColorLDR` 인지 확인한다. 플래그가 되돌아가면 증상이 그대로 재발하므로
이 테스트가 회귀 방어선이다.

## 6. 영향도

| 대상 | 영향 |
|---|---|
| `cam.captureJPG`/`capturePNG`, UI 뷰어 위젯 | 없음 — 이미 뷰 스테이트를 갖고 있던 경로 |
| 카메라별 `/stream` | **수정 대상.** 비선택 카메라도 정상 렌더 |
| 레거시 `/stream`(`MjpegStreamManager`) | 같은 캡처 컴포넌트라 함께 고쳐짐 |
| 슬롯 스케줄링·포트 대역·저장/로드 JSON·RPC 시그니처 | 없음 |
| `Package/Windows/Park3D.exe` | **재패키징 필요.** 원격 배포본에는 아직 반영되지 않았다 |
| SettingManager(수신측) | 코드 변경 불필요 — 보정하지 않기로 한 판단이 그대로 유효 |

## 7. 잔여 위험

- 뷰 스테이트는 카메라별 temporal 히스토리/Lumen 캐시를 잡는다. 캡처된 카메라에만 지연 할당되고
  동시 캡처는 슬롯으로 제한되지만, **카메라 수십 대 환경의 GPU 메모리는 측정하지 않았다.**
- 스트림 첫 프레임은 히스토리가 비어 있어 어두울 수 있다(수 프레임 내 수렴). 검증은 20번째
  프레임으로 했다.
