# Park3D MCP 연결 및 실행 테스트 분석

- 작성 시각: 2026-06-19 18:11:05
- 대상 프로젝트: `D:/Work/Unreal/Project/Parking/Park3D/Park3D.uproject`
- Unreal Engine: UE 5.7.4

## 요약

Park3D 프로젝트를 분석하고 Unreal MCP 연결, 에디터 브리지 응답, 주요 에셋/블루프린트 상태, 빌드 및 헤드리스 커맨드릿 실행을 확인했다.

프로젝트 블루프린트 자체는 정상 컴파일되며, 현재 열린 에디터의 Unreal MCP TCP 브리지는 정상 응답한다. 다만 외부 MCP 설정 경로가 잘못되어 있고, `unrealmcp`/`ue-cli` 명령이 PATH에 없으며, 로컬 DDC/Zen 설정 문제로 헤드리스 실행이 실패 상태로 종료된다.

## 발견한 문제

### 1. MCP 설정의 프로젝트 경로 오류

루트 `.mcp.json`의 `UE_PROJECT`가 현재 프로젝트가 아닌 이전/다른 경로를 가리킨다.

현재 설정:

```json
"UE_PROJECT": "D:/Work/Unreal/Test/Parking/Park3D/Park3D.uproject"
```

정상 경로:

```json
"UE_PROJECT": "D:/Work/Unreal/Project/Parking/Park3D/Park3D.uproject"
```

이 설정 때문에 외부 MCP 클라이언트가 잘못된 프로젝트를 대상으로 실행될 수 있다.

### 2. MCP/CLI 실행 도구가 PATH에 없음

다음 명령이 PATH에서 발견되지 않았다.

- `unrealmcp`
- `ue-cli`

에디터 내부 `UnrealMCPBridge`는 정상 동작하지만, 외부 AI 도구가 MCP 서버를 실행하려면 Python 패키지 또는 CLI 설치/PATH 등록이 필요하다.

### 3. C++ 빌드가 Live Coding 때문에 중단됨

`Build.bat Park3DEditor Win64 Development ...` 실행 결과 UHT까지는 통과했지만, 열린 에디터의 Live Coding 상태 때문에 빌드가 중단되었다.

```text
Unable to build while Live Coding is active.
Exit the editor and game, or press Ctrl+Alt+F11 if iterating on code in the editor or game
```

현재 관찰로는 코드 컴파일 오류라기보다 Live Coding 활성 상태에 따른 빌드 차단이다.

### 4. DDC/Zen 캐시 설정 문제

헤드리스 커맨드릿 실행 중 로컬 Zen/DDC 설정 문제가 확인되었다.

주요 메시지:

```text
Unable to use default cache graph 'InstalledDerivedDataBackendGraph' because there are no writable nodes available.
```

`-DDC-ForceMemoryCache` 옵션으로 블루프린트 컴파일 검사는 진행되었지만, 최종 요약에는 DDC error가 남아 exit code 1로 종료되었다.

관련 경고:

- Zen data path invalid
- Zen server launch failed
- Common DerivedDataCache 경로 쓰기 실패

### 5. 과거 크래시 로그의 Test 경로 흔적

최근/과거 로그와 크래시 컨텍스트에 `D:/Work/Unreal/Test/Parking/...` 경로가 반복적으로 남아 있다.

대표 크래시:

```text
Assertion failed: ++Queue(QueueIndex).RecursionGuard == 1
File: Runtime/Core/Private/Async/TaskGraph.cpp
```

해당 크래시는 MCP `execute_python` 경유로 에디터 작업을 수행하던 중 발생한 흔적으로 보이며, 특히 PIE/에디터 상태 전환 중 맵 생성/로드 같은 작업을 실행할 때 위험할 수 있다.

## 실행 중 수행한 복구

헤드리스 Unreal 프로세스가 종료되면서 `Park3D/Saved/UnrealMCP/port.txt`를 삭제했다. 현재 열린 에디터는 여전히 `55557` 포트에서 살아 있어, MCP Python/CLI가 포트 파일을 찾을 수 있도록 다음 파일을 복구했다.

```text
Park3D/Saved/UnrealMCP/port.txt
```

내용:

```text
55557
```

복구 후 다시 `health_check`를 실행해 정상 응답을 확인했다.

## 권장 조치

1. `.mcp.json`의 `UE_PROJECT`를 현재 프로젝트 경로로 수정한다.
2. `unrealmcp` 또는 `ue-cli`를 설치하고 PATH에서 실행 가능하게 만든다.
3. C++ 정식 빌드 전 에디터를 닫거나 Live Coding을 끈다.
4. `C:/Users/goback/AppData/Local/UnrealEngine/Common/Zen/Data` 및 `DerivedDataCache` 경로를 정리해 writable DDC 노드를 복구한다.
5. MCP `execute_python`으로 맵 생성/로드/PIE 종료 같은 에디터 상태 전환 작업을 할 때는 PIE 종료 후 안정화 시간을 두고 실행한다.

## 결론

Park3D 프로젝트의 핵심 에셋과 블루프린트는 정상이며, 열린 Unreal Editor의 MCP 브리지는 현재 정상 연결된다. 지금 가장 먼저 고쳐야 할 것은 `.mcp.json`의 잘못된 프로젝트 경로와 외부 MCP 실행 도구 설치/PATH 문제다. 그 다음 빌드/자동화 테스트 안정성을 위해 DDC/Zen 캐시 설정을 복구하는 것이 좋다.
