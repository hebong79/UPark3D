# 피킹 Ctrl+좌클릭 — 입력을 PlayerController 와 Slate 양쪽에서 본다

- 작성: 2026-08-18 15:48
- 신고: 카메라 패널 「위치 피킹」이 안 먹는다. 프리셋 메이커의 Ctrl+좌클릭도 같다.
- 결과: 세 패널이 공유하는 입력 헬퍼(`Park3DPickInput.h`)를 넣어 두 경로를 OR 로 묶었다.
- **원인 미확정.** 아래 §3 을 반드시 읽을 것 — 이 변경은 신고된 증상의 원인을 고친 것이 아니다.

## 1. 관측

진단 로그를 심어 조건을 하나씩 찍었다. 신고 시점의 값이다.

```
[진단] ctrl=0 LMB다운=0 LMB눌림=0 패널위=0 pickMode=1 바닥히트=1(-845,-297,10) 커서=1(551,661) 커서표시=1
```

- `pickMode=1`(CamPos), `바닥히트=1`(좌표 정상), `커서=1`, `패널위=0` — **조건 넷 중 셋은 정상**
- `ctrl=0 LMB다운=0 LMB눌림=0` — **PlayerController 가 키·마우스를 하나도 못 본다**

`APlayerController::IsInputKeyDown` / `WasInputKeyJustPressed` 가 계속 false 이면
`bPicking && bCtrl && !bOverPanel && 클릭` 은 영원히 성립하지 않는다. 프리셋 메이커·차량 배치도
같은 코드 패턴이라 함께 죽는다.

## 2. 변경

`Park3DPickInput.h`(신규, 헤더 전용) — 세 패널이 공유한다.

```cpp
bool IsCtrlDown(const APlayerController* PC);        // PC || Slate 수정자
bool IsLeftMouseDown(const APlayerController* PC);   // PC || Slate GetPressedMouseButtons()
struct FLeftClickEdge { bool Poll(const APlayerController* PC); };  // 눌림 상태를 직접 기억해 상승 에지
```

`WasInputKeyJustPressed` 는 Slate 가 입력을 가져가면 쓸 수 없으므로 **에지를 직접 만든다.**
에지 판정은 조건과 무관하게 매 틱 돌려야 한다 — 단축 평가로 건너뛰면 눌림 상태가 낡는다.

적용: 카메라 패널(위치 피킹 + 타겟라인/타겟점), 프리셋 메이커(Offset Pick 이동), 차량 배치(선택/배치).

**이 프로젝트는 같은 함정을 이미 두 번 밟았다** — `ParkFlyPawn` 의 Left Alt, `CarPlacementWidget` 의
Alt·Shift 가 이미 Slate 수정자를 함께 보고 있었다. Ctrl 과 좌클릭만 그 처리가 빠져 있었다.

## 3. 정직한 한계 — 원인은 확정되지 않았다

수정 후 사용자가 "정상 동작"을 확인했지만, **그것이 이 변경 때문이라는 증거는 없다.**

- 다른 PC 는 **이 변경이 들어 있지 않은 마지막 푸시 버전으로 정상 동작**한다. 즉 원래 코드가
  틀린 것이 아니다.
- 정상 동작할 때의 클릭 에지 로그는 이렇다 — PlayerController 도 멀쩡히 본다.

```
[진단] 에지=1 | ctrl pc=1 slate=1 | LMB pc=1 slate=1 | 패널위=0 pickMode=1
[진단] 에지=1 | ctrl pc=0 slate=0 | LMB pc=0 slate=1 | 패널위=0 pickMode=1   ← PC 만 클릭을 놓친 실제 사례
```

- 신고 시점의 `ctrl=0 LMB=0` 상태가 **왜 생겼는지는 재현되지 않았다.** 앱 재기동 후 같은 조작이
  그냥 된다.

그래서 이 변경의 성격은 이렇다.

| | |
|---|---|
| 한 것 | 두 입력 경로를 OR 로 묶어 한쪽이 비어도 동작하게 함 (위 두 번째 로그가 그 근거) |
| 하지 않은 것 | `ctrl=0 LMB=0` 상태를 만든 원인 규명 |

**다시 재발하면 원인 후보로 먼저 볼 곳:** 두 PC 의 갈리는 지점은 `Content/`(WBP 자산)다 — git 제외라
서로 다른 상태이고, 이 PC 는 2026-08-17 에 `Tools/wbp/` 스크립트로 UI 를 재생성했다. 전체 화면을
덮는 위젯의 히트테스트 가시성(`Visible` vs `SelfHitTestInvisible`)이 유력하다. 패널 버튼은 눌리는데
3D 화면 클릭만 안 가는 증상이 정확히 그 모양이다.

## 4. 검증

```
[CameraControl] 카메라 위치 이동: X=-6.95 Z=-0.86 (m)   (4회)
[PresetMaker]  프리셋 이동: (-6.29, -7.32) m            (3회)
```

진단 로그는 커밋 전에 전부 제거했고(잔여 0줄), 제거 후 빌드·배포·재기동까지 마쳤다.

## 5. 정정

앞서 "피킹 버튼 라벨이 안 바뀐다(`SetButtonLabel` 결함)"고 보고했으나 **틀렸다.**
이후 캡처에서 `위치 피킹 중...` 으로 정상 표시됐다. 고칠 것 없다.
