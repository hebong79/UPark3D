# 실행 순서 안내

## 결론: 순서는 상관없다

`python -m unreal_mcp`와 언리얼 에디터의 실행 순서는 상관없습니다.
그리고 대부분의 경우 **`python -m unreal_mcp`를 직접 실행할 필요도 없습니다.**

## 왜 순서가 상관없는가

브리지는 서버 시작 시점에 에디터를 찾지 않습니다. 실제 도구(`editor_status`,
`actor_list` 등)를 **호출하는 그 순간**에 UDP로 에디터를 탐색하고, 연결되면
그 연결을 캐시합니다 (`bridge/remote_exec.py`의 `execute()`). 그래서:

- 서버를 먼저 켜고 나중에 언리얼을 켜도 됨 — 첫 도구 호출 때 에디터가 떠 있으면 그때 연결
- 언리얼을 먼저 켜고 서버를 나중에 켜도 됨
- 연결이 끊겨도 다음 호출 때 자동 재연결

## 실제 권장 사용법

직접 `python -m unreal_mcp`를 띄우지 마세요. 그건 디버깅용 수동 실행이고,
정상 경로는 이렇습니다:

1. **언리얼 에디터를 켠다** (Parking 프로젝트 — 플러그인/Remote Execution 적용을 위해 한 번 재시작 필요)
2. **Claude Code를 켜면** `.mcp.json`을 보고 `python -m unreal_mcp` 서버를 **자동으로** 백그라운드에서 띄웁니다
3. Claude Code에서 `editor_status`를 호출해 `editor_connected: true` 확인

즉, 사람이 신경 쓸 순서는 "언리얼만 켜 두면 된다" 정도이고, 서버 실행은
Claude Code가 알아서 합니다. 굳이 따지자면 도구를 처음 호출하기 전까지만
언리얼이 켜져 있으면 되므로, 실질적으로는 **순서를 신경 쓰지 않아도 됩니다.**
