# 시뮬레이션 차량 간 충돌 회피 + MCP 브리지 포트 지정

- 날짜: 2026-08-12
- 브랜치: `feat/sim-dir-rpc` (동시 주행 커밋 `20c7f90` 을 `main` 에 머지한 뒤 같은 브랜치에서 이어 작업)
- 배경: 동시 주행을 넣자 여러 대가 같은 통로를 쓰면서 **서로 통과**하는 것이 드러났다. 그리고 13510 은
  외부 클라이언트가 쓰고 있어 검증용 인스턴스를 다른 포트로 띄워야 했다.

---

## 1. 차량 간 충돌 회피

### 방식 — 종방향 회피(속도만 조절)

조향은 건드리지 않는다. 경로를 벗어나 옆으로 피하지 않고, **앞이 막히면 속도를 깎아 그 앞에서 선다.**
주차장 통로는 폭이 좁아 회피 조향을 넣으면 주차면·기둥으로 파고들 위험이 크고, 경로 생성(4점 웨이포인트)의
단순함도 깨진다.

`AParkingSimManager::ApplyAvoidance()` 가 매 틱 `TickDrive` 의 목표 속도를 한 번 더 깎는다.

| 단계 | 내용 |
|------|------|
| 탐색 | 다른 **주행 중** 주행(`IsDriving()`)의 차량만 본다. 주차 완료 차량은 통로 밖이라 제외 |
| 통로 판정 | 진행축 기준 앞쪽 `0 < 거리 ≤ AvoidLookAheadM(9m)`, 좌우 `≤ AvoidCorridorHalfM(1.7m)` |
| 감속 | `허용속도 = sqrt(2 · DecelMps2 · max(간격 − AvoidSafeGapM(4.5m), 0))` 로 상한을 건다 |
| 후진 구간 | 진행 방향이 차 방위의 반대이므로 `-Dir2D(Yaw)` 를 기준축으로 쓴다 |

### 교착 해소

마주 보고 선 두 대가 서로를 막으면 둘 다 영원히 서 있게 된다. 그래서
**`AvoidDeadlockSec(4초)` 이상 굳으면 `RunId` 가 작은(먼저 시작한) 쪽이 통과**한다.
"작은 쪽만 통과"는 순서 관계라 사이클이 생길 수 없어 교착이 남지 않는다.
대신 **그 순간 두 차가 겹쳐 지나간다** — 완전한 회피가 아니라 굳음 방지 장치다. 로그에 그대로 남긴다.

### 차선 분리 — 출차 통로를 바깥으로

같은 열에서 입차와 출차가 정면으로 마주치는 일을 줄이려고, **출차의 통로 경유지만**
주차면 바깥쪽으로 `ExitLaneOffsetM(2.5m)` 민다(우측통행 대용). 입차는 통로 중심을 그대로 쓴다.
진입점은 주차면의 진입축 위에 있어야 하므로 옮기지 않는다.

### 파라미터 (전부 `UPROPERTY`, 기본값)

| 이름 | 기본 | 뜻 |
|------|------|-----|
| `bAvoidCollision` | true | 끄면 예전처럼 서로 통과 |
| `AvoidLookAheadM` | 9.0 | 전방 감시 거리 |
| `AvoidCorridorHalfM` | 1.7 | 진행축 기준 좌우 감시 반폭 |
| `AvoidSafeGapM` | 4.5 | 앞차와 유지할 최소 중심간 거리 |
| `AvoidDeadlockSec` | 4.0 | 이만큼 굳으면 우선순위 통과 |
| `ExitLaneOffsetM` | 2.5 | 출차 통로를 바깥으로 미는 양 |

## 2. MCP 브리지 — 호출별 포트 지정

13510 을 외부 클라이언트가 쓰는 중이라 검증용 인스턴스를 13610 에 따로 띄워야 했는데,
브리지는 기동 시 `PARK3D_RPC_URL` 하나로 대상이 고정돼 있었다.

`park3d_rpc` / `park3d_catalog` 에 **선택 인자 `port`** 를 추가했다. 주면 그 포트로, 생략하면 기존 기본값으로 간다.

```jsonc
park3d_rpc(method="sim.list", params={}, port=13610)   // 개발 인스턴스
park3d_rpc(method="cam.list", params={})               // 기본(13510)
```

인스턴스를 여러 개 띄울 때 `.mcp.json` 을 고치고 MCP 서버를 다시 띄우지 않아도 된다.

> **주의(실제로 겪음):** 브리지를 다시 빌드해도 **MCP 서버를 재연결하기 전에는 예전 코드가 돈다.**
> 이때 `port` 는 스키마에 없는 키라 **조용히 무시되고 기본 포트로 호출된다.** 재연결 전에 `port` 를 믿고
> 부르면 엉뚱한 인스턴스를 조작하게 된다 — 실제로 `car.deleteAll` 이 13610 대신 13510 으로 갔다.
> 재연결 여부는 `system.health` 의 `port` 값으로 확인할 것.

## 3. 검증용 두 번째 인스턴스 만드는 법

개발 빌드 exe(`Park3D/Binaries/Win64/Park3D.exe`)를 그대로 실행하면 **Zen 스토리지 서버를 찾다가 실패**한다
(`LogStorageServerPlatformFile: Error: Failed to initialize connection`). 쿠킹된 콘텐츠가 없기 때문이다.
돌아가는 패키지의 exe 는 실행 중이라 덮어쓸 수도 없다. 그래서:

```powershell
robocopy Package\Windows Package\Windows_dev13610 /E /MT:16       # 3.3GB, 229파일
Copy-Item Park3D\Binaries\Win64\Park3D.exe `
          Package\Windows_dev13610\Park3D\Binaries\Win64\Park3D.exe -Force
Start-Process Package\Windows_dev13610\Park3D\Binaries\Win64\Park3D.exe `
  -ArgumentList '-RpcPort=13610','-iniFile=...\Park3D\Config\DefaultGame.ini','-windowed'
```

`Package/` 는 `.gitignore` 대상이라 저장소에는 들어가지 않는다.

## 4. 검증 (실측, 2026-08-12 14:04~14:09, 포트 13610)

빌드 **Succeeded**. 13510(PID 13352)은 건드리지 않고 13610(PID 9248)에서만 시험했다.

| 시나리오 | 결과 |
|----------|------|
| **추종**(같은 열 입차 2건 연속 출발) | 뒤차가 `전방 회피 — #1 이 6.9m 앞에 있어 감속` → 정지 → `전방 정리 — #1 이 비켰습니다` 로 재개. 통로에서 한 번 더 8.9m 앞 감지 |
| **정면**(같은 열 출차 1 + 입차 1) | 출차 통로가 (11.79, 38.64)로 2.5m 밀려 나가고, 입차는 (9.29, 38.64) 그대로. 입차가 1.7초 양보한 뒤 둘 다 완주(각 18.7초) |
| **동시 4건**(같은 열 입차 3 + 출차 1) | 전부 완주 — 입차 3건 주차완료(28.7 / 33.5 / 38.3초), 출차 출차완료(34.1초). 회피 이벤트 3~9건씩 발생 |
| **교착 해소** | 3회 관측: `교착 해소 — 4.0초 대치 후 우선순위(#5 < #8)로 통과합니다(이 구간은 겹칩니다)` (#6<#8, #7<#8 도 동일) |
| 시간 초과 | 없음. 회피로 느려져도 모두 `MaxSimSeconds(180초)` 안에 끝났다 |

### 읽어야 할 결과

동시 4건에서 소요 시간이 단독(18.7초) 대비 **28~38초로 늘었다.** 서로 양보하며 서다 가기를 반복한 결과이고,
이것이 회피가 실제로 개입했다는 증거다.

정면 상황에서 **2.5m 차선 오프셋만으로 완전히 갈라지지는 않는다.** 출차의 `진입점 → 통로` 대각 구간은
입차 통로와 겹치므로, 그 구간에서 마주치면 4초 대치 후 우선순위 통과(겹침)로 풀린다. 위 4건 시험에서
교착 해소가 3회 나온 것이 그 경우다.

## 5. 한계

- **완전한 무충돌이 아니다.** 4초 대치 후 우선순위 통과 구간에서는 두 차가 겹쳐 지나간다.
- **조향 회피 없음.** 옆으로 비켜 가지 않으므로 좁은 통로에서는 서는 것이 유일한 대응이다.
- 회피 대상은 **시뮬레이션 주행 차량뿐**이다. 손으로 배치한 차량(`car.create` 등)은 보지 않는다.
- HUD 화면 표시는 이번에도 눈으로 확인하지 못했다(뷰포트 캡처 수단 없음).
