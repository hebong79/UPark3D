# 질문: 웹에서 통신으로 받아 쓸 때, 백그라운드(오프스크린)와 포그라운드(창) 실행 중 어느 쪽이 더 높은 fps 를 주나?

작성: 2026-09-21 23:30
앞선 문서: `Docs/20260921_231500_질문_창없이_백그라운드_실행_웹_렌더수신_가능여부.md`

## 결론

**단독 실행이면 둘이 같다. 같은 PC 에 다른 창 인스턴스가 함께 있으면 포그라운드 쪽이 압도적으로 높다.**
웹이 받는 fps 는 실행 방식이 아니라 (1) 설정 상한과 (2) GPU 배분으로 정해진다.

## 근거(2026-09-21 실측, Work13540 작업본 + 정본 13510)

1. **캡처 경로가 같다.** 두 방식 모두 창 백버퍼가 아니라 `USceneCaptureComponent2D` 렌더타깃을 읽어 JPEG 로 인코딩한다.
   `captureAvgMs` 2.3~2.5 / `encodeAvgMs` 2.2 로 값이 같았다. 창 모드는 여기에 화면 present 만 더한다 → 단독이면 오프스크린이 같거나 아주 조금 유리.
2. **웹에 가는 fps 의 천장은 설정값이다.** 메인 뷰 `stream_main_fps`(현재 20), 카메라 채널 `stream_total_fps ÷ 실사용 채널 수`.
   정본(창)이 실제로 준 메인 뷰 fps 는 19.7 = 상한 20. 틱이 그보다 높아도 더 못 준다.
3. **같은 GPU 를 나눠 쓰면 전면 창이 이긴다.**

| 작업본 상태 | 작업본 tickFps | 그때 정본 tickFps |
|---|---|---|
| 오프스크린(창 없음) | 3.1~3.5 | 16.5 |
| 창 모드(전면) | 47~48 | 2.5 |

## 정리

| 구성 | 웹이 받는 메인 뷰 fps |
|---|---|
| 창 모드 단독 | 상한 20 (실측 19.7) |
| 오프스크린 단독 | 상한 20 예상, **미측정**(정본을 내리지 않고는 이 PC 에서 못 잰다) |
| 창 + 오프스크린 동거 | 전면 창 쪽 20, 오프스크린 쪽 약 3 |

원인은 Windows GPU 스케줄링(전면 창 우선) 추정이며 확정하지 않았다.

## 권장

- 서버에서는 오프스크린 하나만 띄우고, 웹 fps 는 `config_pmaker.json` 의 `stream_main_fps` / `stream_total_fps` 로 올린다.
- 한 PC 에 창 인스턴스와 같이 둘 계획이면 오프스크린 쪽 fps 는 기대하지 않는다(GPU 분리 필요).
