# 앱 시작 시 설정 파일(config_pmaker.json) 자동 로딩 설계서

- 작성일: 2026-08-05
- 대상: Park3D (UE5)
- 원본 참조: `unity/PresetMaker/CPresetMakerScene.cs` (`LoadInitialData`), `unity/CarObject/CDataMgr.cs`

## 1. 요구사항

`Save/Config/config_pmaker.json` 을 두고, 앱 실행 시 이 파일을 읽어 지정된 JSON 3종을
자동으로 로딩·화면 적용한다. 적용 결과는 **각 UI 패널에서 "열기" 버튼을 눌러 그 파일을 고른 것과
동일한 상태**여야 한다(3D 액터뿐 아니라 위젯 목록·입력 필드·파일명 표시까지).

```json
{
    "rpc_port": 13510,
    "preset_file": "001_Preset_Seo_1.json",
    "carpos_file": "CarPos_Seoshin_2Cam.json",
    "camerapos_file": "CamPos_Seosin.json",
    "max_zoom": 36.0
}
```

> 사용자가 제시한 원본 예시에는 `max_zoom` 뒤에 후행 쉼표가 있었다. UE의 JSON 리더는 후행 쉼표를
> 보장하지 않으므로 실제 파일은 유효 JSON(쉼표 제거)으로 생성한다.

### Unity 원본과의 대응

| Unity | Park3D |
|---|---|
| `DCONFIG_PATH = "Config/config01_preset_maker.json"` | `Save/Config/config_pmaker.json` |
| `LoadPresetFile(DSAVE_PATH_PRESET, preset_file)` | `UPresetMakerWidget::LoadFromJsonFile` |
| `LoadCameraPosFile(DSAVE_PATH_CAMERAPOS, camerapos_file)` | `UCameraControlWidget::LoadFromJsonFile`(신규 추출) |
| `LoadCarPosFile(DSAVE_PATH_CARPOS, carpos_file)` | `UCarPlacementWidget::LoadFromJsonFile` |
| 실패 시 `Debug.LogWarning` 후 계속 | `UE_LOG(Warning)` 후 계속 (동일) |

Unity 원본 저장소에 `CPSimConfig` 구현체가 없어 `rpc_port`·`max_zoom` 의미는 Park3D 기준으로 정의한다.

## 2. 결정 사항

1. **적용 경로 = 위젯 열기 경로.** 매니저/라이브러리를 직접 호출하지 않는다. 매니저만 갱신하면
   위젯 목록이 비어 있는 "UI vs RPC 이원화" 상태가 재현되기 때문이다.
2. **패널은 구성(NativeConstruct)까지 마친 뒤 로드한다.** 사용자가 패널을 열고 "열기"를 누른
   순서와 동일하게 맞춘다. 표시 상태는 바꾸지 않는다(시작 화면은 기존대로 PresetMaker 만 보임).
3. **rpc_port 우선순위**(사용자 확정): `-RpcPort=` > `config_pmaker.json` > `DefaultGame.ini [RpcServer] Port` > 13510.
   `-RpcPort=0`(서버 미기동)의 기존 의미는 유지한다.
4. **max_zoom** = PTZ 카메라의 줌↔FOV 매핑 상한(`APTZCameraActor::MaxZoom`). 매니저가 값을
   보유하고 스폰 시 주입 + 기존 카메라에 일괄 반영한다. 현재 기본값도 36이라 예시 값에서는 무변화다.
5. **실패 처리:** config 없음/파싱 실패 → 아무것도 로드하지 않고 경고 로그(기존 시작 동작 유지).
   개별 파일 없음/파싱 실패 → 해당 항목만 건너뛰고 나머지는 계속(Unity와 동일).
6. **키 누락 허용:** 없는 키는 기본값 유지. 빈 문자열 파일명은 "지정 없음"으로 간주해 건너뛴다.

## 3. 데이터 구조 / 인터페이스

### 3.1 신규 `Source/Park3D/Config/Park3DAppConfig.h/.cpp`

```cpp
USTRUCT()
struct FPark3DAppConfig
{
    int32   RpcPort = 0;            // 0 = 미지정(우선순위 체인에서 스킵)
    FString PresetFile;             // Save/3D/Preset 기준 파일명 또는 절대경로
    FString CarPosFile;             // Save/3D/CarPos
    FString CameraPosFile;          // Save/3D/CameraPos
    float   MaxZoom = 0.f;          // 0 이하 = 미지정
};

class UPark3DAppConfigLibrary : public UBlueprintFunctionLibrary
{
    static FString GetConfigDir();                                  // <SaveRoot>/Config
    static FString GetConfigFilePath();                             // <SaveRoot>/Config/config_pmaker.json
    static bool    FromJson(const FString& Json, FPark3DAppConfig& Out);
    static bool    LoadFromFile(const FString& Path, FPark3DAppConfig& Out);
    static bool    Load(FPark3DAppConfig& Out);                     // 기본 경로 로드
    /** 파일명만 주어지면 Save/3D/<SubDir> 기준으로 해석. 절대/상대경로는 그대로 사용. */
    static FString ResolveDataPath(const FString& SubDir, const FString& FileNameOrPath);
};
```

- 파싱은 `FJsonSerializer` 로 필드 단위 수동 파싱한다. `FJsonObjectConverter` 는 루트 키만 맞으면
  다른 스키마도 조용히 성공시키는 전례가 있어 쓰지 않는다.
- 경로 루트는 `Park3DDataPaths::GetSaveRootDir()` 을 재사용한다(에디터/패키지 양쪽 대응).

### 3.2 변경

| 파일 | 변경 |
|---|---|
| `MainMenuWidget.h/.cpp` | `UUserWidget* EnsurePanelConstructed(TSubclassOf<UUserWidget>)` 추가. 캐시 인스턴스를 만들고, 미표시 상태면 뷰포트 add→remove 로 `NativeConstruct` 를 1회 태운 뒤 원래 표시 상태로 되돌린다. |
| `CameraControlWidget.h/.cpp` | `HandleOpen` 본문을 `bool LoadFromJsonFile(const FString& Path)` 로 추출(다른 두 위젯과 동일한 형태). `HandleOpen` 은 다이얼로그 + 이 함수 호출만 남긴다. |
| `CameraControlManager.h/.cpp` | `float CameraMaxZoom = 36.f` + `void SetCameraMaxZoom(float)` 추가. `AddCamera` 스폰 시 주입. |
| `Park3DGameMode.h/.cpp` | `void ApplyStartupConfig()` 추가. `BeginPlay` 의 카메라 뷰어 표시 뒤에 호출. |
| `Rpc/RpcServerSubsystem.cpp` | 포트 결정 체인에 config 단계 삽입(ini 다음, 커맨드라인 앞). |

## 4. 처리 흐름

### 4.1 RPC 포트 (GameInstance 서브시스템 Initialize — BeginPlay 이전)

```
Port = 13510
 → DefaultGame.ini [RpcServer] Port 있으면 대입
 → config_pmaker.json rpc_port(1~65535) 있으면 대입
 → -RpcPort= 있으면 대입 (0 이면 서버 미기동)
```

### 4.2 데이터 3종 (APark3DGameMode::BeginPlay 말미)

```
ApplyStartupConfig()
 1. UPark3DAppConfigLibrary::Load()            실패 → 경고 후 return
 2. max_zoom  → CameraControlManager::SetCameraMaxZoom (카메라 스폰/자세 반영보다 먼저)
 3. preset_file    → EnsurePanelConstructed(PresetMakerWidgetClass)  → LoadFromJsonFile
 4. camerapos_file → EnsurePanelConstructed(CameraControlWidgetClass)→ LoadFromJsonFile
 5. carpos_file    → EnsurePanelConstructed(CarPlacementWidgetClass) → LoadFromJsonFile
 6. 각 단계 결과를 [Config] 로그로 남긴다(성공/실패/스킵).
```

- 순서는 Unity `LoadInitialData` 와 동일(preset → camerapos → carpos).
- 2번이 3~5번보다 먼저여야 `SyncCamerasToData` 로 새로 스폰되는 카메라가 설정된 상한을 갖는다.
- PresetMaker 패널은 `UMainMenuWidget::NativeConstruct` 가 이미 표시했으므로 add/remove 없이
  그대로 로드된다(표시 상태 불변).

## 5. 대안 비교

| 대안 | 판단 |
|---|---|
| (A) 위젯 열기 경로 재사용 (채택) | UI 목록·필드·파일명까지 사용자가 연 것과 동일. 코드 추가 최소. |
| (B) 매니저/라이브러리 직접 호출 | 3D는 맞지만 패널을 열면 목록이 비어 있고, 이후 저장 시 로드 내용이 사라진다. 기각. |
| (C) 위젯 생성 후 NativeConstruct 없이 로드 | add/remove 왕복은 줄지만, `UCameraControlWidget::NativeConstruct` 가 나중에 `ApplyAllControlsToCamera()` 로 필드값을 카메라에 재적용해 순서 의존이 생긴다. 기각. |
| (D) config를 `Config/`(프로젝트 설정 폴더)에 배치 | UE의 ini 설정 폴더와 혼동. 사용자가 지정한 `Save/Config/` 를 따른다. |

## 6. 좌표/단위 규약

이 기능은 좌표 변환을 수행하지 않는다. 각 위젯의 기존 로드 경로가 Unity↔UE 변환을 그대로 담당한다
(JSON z = UE Z(높이), 거리 단위 m). `max_zoom` 은 배율(무차원), `rpc_port` 는 1~65535 정수.
