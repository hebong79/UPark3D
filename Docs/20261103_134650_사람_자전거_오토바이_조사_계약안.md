## (b) RPC 계약안 — 그룹 `agent.*`

자동차(`car.*`)와 섞지 않는다. 사람·이동수단은 각자 ID 를 갖는 "에이전트" 이고, 탑승은 관계로 잇는다.

| 메서드 | params | 동작 |
|---|---|---|
| `agent.create` | `{kind:"pedestrian"\|"bicycle"\|"motorcycle", pos{x,y,z?}, yaw?, rider?=true(이동수단만), model?, seed?, id?}` | 만든 객체들을 돌려준다. 이동수단 + `rider:true` 는 사람 1 + 이동수단 1 + 관계 1 |
| `agent.move` | `{id, path?:[{x,y}], to?:{x,y}, speed?, avoid?=true}` | `path` 는 그대로 따라가고, `to` 는 보행·통로 격자에서 경로를 찾는다. 탑승 중이면 사람·이동수단 어느 ID 를 줘도 함께 움직인다. 응답에 `moveId`·계획 경로·길이 |
| `agent.stop` | `{id \| ids \| all}` | 그 자리에 선다(`state:"stopped"`) |
| `agent.delete` | `{id \| ids \| all}` | 탑승 중인 이동수단을 지우면 사람은 그 자리에 남는다(관계 종료) |
| `agent.list` | `{kind?, ids?}` | 아래 필드. truth 기록용 |
| `agent.relations` | `{id?}` | `[{relationId, relationType:"riding", fromObjectId(사람), toObjectId(이동수단), validFromMs, validToMs\|null}]` |

- 기본 속도: 사람 1.3 m/s, 자전거 4.0 m/s, 오토바이 3.0 m/s(주차 시뮬 순항 `CruiseSpeedMps` 와 같은 값이고 통로 상한으로 쓴다. 이보다 높게 주면 잘라서 경고).
- `agent.list` 의 한 항목: `{id, objectType:"person"|"bicycle"|"motorcycle", model, pos{x,y,z}, directionDeg, speedMps(실측), motionType:"moving"|"stationary", activityType:"walking"|"standing"|"riding", state:"idle"|"moving"|"waiting"|"arrived"|"stopped"|"blocked", moveId?, remainingM?, ridingWith?, plate?(오토바이)}` + 루트 `timeMs`·`frameId`(기존 캡처·응답과 같은 시계).
- 필드 이름은 설계서 5.5절(`objectType`·`directionDeg`·`speedMps`·`motionType`·`activityType`)을 그대로 따른다.
- 내리기·끌기: 1차 범위 밖이고, 구조상 가능하다(관계만 바꾸고 각 객체를 따로 움직이면 된다). 2차로 `agent.dismount {id}`(관계 `validTo` 종료, 사람은 이동수단 옆에 선다)·`agent.mount`·`relationType:"pushing"`(사람이 걸으며 이동수단을 옆에 끌고 감, 1.3 m/s)를 둘 수 있다.
- `system.help` 표(`Rpc/RpcHelpTable.cpp`)에 한 줄씩 넣는다. 등록과 표가 어긋나면 테스트가 잡는다.
- 정답 캡처: `cam.captureJPG {withTruth}` 의 `truth` 에 `agents[]`(사람·이동수단 상자·가시율, 오토바이 번호판 quad)를 추가하고, 마스크 값을 차량 다음 번호로 이어 쓴다. 이 부분은 2차 제안이다.

## (c) 이동 조건(서신 LV_Park_01)

- **통과 가능 영역**
  - 지금의 통로 그래프(`sim.lanes`)가 쓰는 지면 높이 격자를 재사용한다.
  - 사람: 노면 + 보도(`BP_SidewalkPlane` 10개, 턱 0.2 m 까지 허용) + 횡단보도(`BP_Decal_Zebra` 2개)를 걸을 수 있다.
  - 자전거·오토바이: 통로만 간다(보도 제외, 통로 규칙 one/two/blocked 따름).
  - 벽·건물·펜스(`BP_Barrier_Sidewalk_Fence` 4)·주차된 차는 막힘 칸이다. 서 있는 차는 차체 + 0.3 m 로 막는다.
- **경로**: `to` 를 주면 격자 A*(사람 8방향, 이동수단은 통로 그래프 Dijkstra + 곡률 제한)로 찾는다. `path` 를 직접 주면 막힘 칸을 지나는지 미리 검사해 거절하거나 `note` 를 단다.
- **움직이는 차**
  - 매 틱 주행 중인 차(`sim.*` 주행, `car.drive` 주행)의 앞 2초 위치를 예측한다. 겹칠 것 같으면 에이전트가 감속·정지(`state:"waiting"`)하고, 길이 비면 다시 간다.
  - 오래 막히면 `blocked` 로 끝낸다(주차 시뮬의 `정체중단` 과 같은 규약).
  - 반대로 **차가 사람 앞에서 서는 것**(주차 시뮬 회피 대상에 에이전트를 넣기)도 같이 넣기를 권한다. 그래야 두 쪽 다 피하다 교착되지 않는다.
- **확인이 필요한 위험**
  - 서신 보도는 런타임에 만들어지는 메시(DynamicMesh)다. 정적 질의 격자에 잡히는지 아직 실측하지 않았다.
  - 잡히지 않으면 `BP_SidewalkPlane` 스플라인을 읽어 보도 다각형을 만든다.

## (d) state.snapshot / state.restore

**지금은 되돌리지 않는다.** 범위는 `cars`·`presets`·`cameras`·`view` 넷뿐이다(`Rpc/Modules/StateRpcModule.cpp`).

방안:
1. scope `agents` 를 추가하고 `all` 에 포함한다. 저장 항목은 객체(id·종류·모델·자세·번호판)·관계(riding, validFrom)·이동 상태(경로, 진행 거리, 속도, state)다.
2. restore 는 전부 지우고 같은 ID 로 다시 만든다. 이동 중이던 것은 같은 진행 거리에서 이어 달리고, `restore {paused:true}` 면 그 자리에 정지한다.
3. ID 카운터도 함께 되돌린다. 그래야 복원 뒤 새로 만든 객체가 옛 ID 와 겹치지 않는다.

덤 — 같은 구멍이 차량에도 있다. 주행 중이던 차(`sim.*`·`car.drive`)는 restore 때 `ClearAll` 로 다시 생성되면서 주행이 취소되고, 정지 자세로만 돌아온다. .125 사용 조건이 "움직이는 장면을 되돌리기" 라면 이것도 같이 고쳐야 한다(PM 판단).

## (e) 오토바이 번호판

더미만 쓴다. 기본은 `SM_Plate_Motorcycle` 판 + 고정 더미 문자열(예 `TEST 0000`, 실제 번호 체계에 없는 형식)이다. `agent.list` 의 `plate` 에 그대로 싣는다. 실제 번호 추첨(`PlateKinds`)은 쓰지 않는다. 베트남 판 텍스처는 판 모양 바탕으로만 쓰거나 무늬 없는 판으로 둔다(PM 선택).
