| 시나리오 | 기준 컷 N0 | 가린 컷 N1 | **가림률** | 목표 | 판정 |
|---|---|---|---|---|---|
| 1 옆칸 카니발 | 68,304 px | 43,095 px | **36.9%** | 30~60% | ✅ 구간 내 |
| 2 통로의 탑차 | 58,759 px | 92 px | **99.8%** | 80~100% | ✅ 구간 내 |

기획서가 손계산으로 예측한 구간에 **실측이 그대로 들어왔다.** 차량 메시 실치수를 모른 채 세운
가정(카니발 전장 ~5m 등)이 크게 틀리지 않았다는 뜻이다.

## 설계에서 바꾼 것 — 가림률을 런타임이 계산한다

설계서 §4 는 "가림률 판정은 RPC 밖에 남는다. C++ 에 이미지 분석을 넣지 않는 한
`scenario.shoot` 이 '가림률 45%'를 반환할 수는 없다"고 못 박았다. **이 결정을 뒤집었다.**

이유: 색 마스크 픽셀 계수는 20줄이면 되고, 이것이 없으면 이 단계의 검증 기준
("가림률이 목표 구간에 드는가")을 확인하려고 매번 외부 스크립트를 따로 돌려야 한다.
런타임에 넣으니 `scenario.run` 한 번으로 수치까지 나온다.

여전히 밖에 남는 것: **시나리오 5의 기하 투영 측정**(대상이 차가 아니라 빈 면이라 색을 못 칠한다).

### 마스크 판정 방법

도색된 차체는 명암 때문에 밝기가 크게 흔들린다(캡처를 보면 같은 마젠타가 어두운 옆면부터
하이라이트까지 걸쳐 있다). RGB 근접거리로는 못 잡는다. 대신 채널 비율로 본다.

```cpp
// 켜진 채널(목표색이 >0.5)은 충분히 밝고, 꺼진 채널은 그보다 확실히 어둡다.
OnMin >= 60 && OffMax < OnMin * 0.55
```

magenta = R·B 켜짐/G 꺼짐, cyan = G·B, green = G — 순색 3종에 그대로 일반화된다.

## 추가된 method

| method | 동작 |
|---|---|
| `scenario.shoot {name}` | `shots` 실행. A/B 컷을 `Save/3D/Shot/<name>_<tag>.png` 로 저장하고 가림률 반환 |
| `scenario.run {name}` | `load` + `shoot` 한 번에. 응답에 `load`/`shoot` 를 나눠 담는다 |

`shoot` 은 **`load` 가 먼저 돌아야 한다.** 어떤 차가 어느 role 인지는 월드에 없고
로드 시점에 만든 `role → carNameId` 표에만 있다. 다른 시나리오가 로드된 상태면 거부한다
(`'X' 가 로드되어 있지 않다(현재: 'Y')`).

### shots 스키마

```jsonc
"shots": [
  { "tag":"N0", "camId":1, "format":"png", "hideRoles":["occluder"], "baseline":true },
  { "tag":"N1", "camId":1, "format":"png", "hideRoles":[] }
]
```

`baseline:true` 인 컷의 마스크 픽셀 수가 분모다. 나머지 컷은 `occlusion = 1 - N1/N0` 로 계산된다.
`hideRoles` 로 숨긴 차량은 캡처 직후 **반드시 되돌린다**(캡처 실패 시에도 복원한 뒤 에러를 낸다).

## 검증 (전부 실행 확인, 작업본 13520)

빌드 `Result: Succeeded`. `scenario.run` 3건 실행.

**시나리오 1** — `occlusion 0.369070`. N0 캡처를 눈으로 확인: 대상차만 마젠타로 단독 노출,
가리개 카니발이 사라진 상태. 마스크 계수가 정상 동작함을 확인.

**시나리오 2** — `occlusion 0.998434`. N1 에 마젠타가 92 px 만 남았다(탑차 운전석 창 너머 조각).
저설치 카메라(3 m)가 파일에서 적용돼 tilt 5.36 으로 잡혔다.

**시나리오 5** — `measured:false`, `maskPixels 0`. 대상이 빈 면이라 칠할 것이 없다.
**조용히 0% 로 답하지 않고 `measured:false` 로 사실을 알린다.** N0 는 양옆 차를 모두 숨긴 컷이라
나중에 기하 투영 측정을 붙일 때 기준 컷으로 쓸 수 있다.

## 한계 · 미해결

- **시나리오 5는 여전히 수치가 없다.** 설계서 §5 대로 기하 투영법(슬롯 코너 4점을 화면에 투영)이
  필요하고, 그 전제인 캡처 RT 투영 모델 검증이 아직 안 됐다. 별도 작업으로 남긴다.
- **`runs` 는 실행되지 않는다.** `scenario.run` 이 조용히 넘어가지 않고 응답 `note` 에
  "runs N건은 아직 실행되지 않는다"고 적어 돌려준다. 시나리오 3(주행 가림)이 여기 걸려 있다.
- 마스크 임계값(`OnMin>=60`, 비율 0.55)은 이번 조명(`Sangmyung.json`)에서 맞춘 값이다.
  조명을 크게 바꾸면 재검토가 필요하다 — 그래서 시나리오 정의에 `lightFile` 이 들어 있다.
- 그림자에 잠긴 차체 부분은 마스크에서 빠질 수 있다. N0·N1 이 같은 조명이라 비율에는
  대체로 상쇄되지만, 가리개가 대상에 그림자를 드리우면 가림률이 **과대평가**될 수 있다(미검증).
- PNG 1장이 약 1.4 MB 다. 대량 생산 시 `format:"jpg"` 로 전환할 것(측정은 PNG 권장 — 압축 색번짐).
