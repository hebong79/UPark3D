# 카메라 프리셋 시작 슬롯 → 바닥 번호 재부여

- 날짜: 2026-09-08
- 브랜치: `feat/slot-number-anchors`
- 선행 문서: `Docs/20260907_223000_카메라패널_프리셋별_시작슬롯_지정.md`(기록 전용 시작 슬롯), `Docs/20260907_192400_주차면_바닥_번호_표시_PresetMaker_출력_콤보.md`(바닥 번호)

## 1. 요구

사용자 지시(2026-09-07 밤):

> 1. 바닥에 그려진 번호를 재부여 해야 됨. 이 UI를 만든 핵심임.
> 2. 프리셋의 시작 슬롯부터 다시 바꿀수 있어야하고 뒤쪽의 슬롯 번호는 자동으로 순서대로 재배치 되어야 한다.

09-07 에 승인받은 "번호는 기록만" 결정을 뒤집는 지시다. 시작 슬롯 줄이 있는 이유가 곧 바닥 번호를 현장 번호에 맞추는 것이므로, 기록 전용 필드를 **재부여 기준점**으로 바꿨다.

## 2. 규칙(기준점 모델)

바닥 번호 목록(`AParkingPresetManager::CollectSlotNumbers`)은 이미 순서가 있다 — 프리셋 면(카메라 할당 순) 다음 레벨 `BP_ParkingSlot` ISM 면(액터 이름 번호순 → 인스턴스 순). 이 순서를 **순번(BaseNumber)** 이라 부른다.

카메라 프리셋 하나가 기준점 하나를 낸다: **"이 면(start_face)을 start_slot 번으로 하고, 목록에서 뒤에 오는 면은 +1 씩 잇는다."**

| 상황 | 결과 |
|---|---|
| 기준점 앞의 면 | 순번 그대로 |
| 기준점 면 | `start_slot` |
| 기준점 뒤의 면 | 앞 면 + 1 (다음 기준점을 만날 때까지) |
| 프리셋 면 → 레벨 면 경계 | 이어 매기기를 끊는다(두 묶음은 원래 독립적으로 1부터 센다) |
| 같은 면에 기준점 둘 | 뒤에 넘긴 것(카메라·프리셋 순서상 뒤)이 이긴다 |
| `start_slot` 0 또는 `start_face` 빈 문자열 | 기준점 아님(값만 기록) |

기준점은 **모든 카메라·모든 프리셋**에서 모아 한꺼번에 적용한다. 패널에서 어느 프리셋을 보고 있는지와 무관하게 바닥은 하나의 번호 체계를 보인다. 카메라 4대가 주차장을 나눠 보면 카메라마다 "우리 구역은 여기서 시작"이라고 기준점을 하나씩 찍는 그림이 된다.

번호 중복은 막지 않는다(기준점 두 개를 겹치는 범위로 찍으면 같은 번호가 두 번 나온다). 현장 번호가 곧 사용자의 데이터이고, 막으면 "왜 안 먹는지"를 설명할 길이 없다.

### 왜 순번이 아니라 면 키로 저장하는가

처음 09-07 구현은 클릭한 면의 **번호**만 칸에 넣었다. 재부여를 하려면 "어느 면을" 과 "몇 번으로" 두 값이 필요하다. 어느 면을 순번(정수)으로 적으면 PresetMaker 에서 프리셋 면을 만들거나 지울 때 레벨 면의 순번이 통째로 밀려 엉뚱한 면을 가리킨다(실제로 09-07 정본에서 사용자가 PresetMaker `초기화`를 눌러 프리셋 면 12개가 사라지는 일이 있었다). 그래서 면의 정체를 문자열 키로 적는다:

- 레벨 면: `level:<액터이름>#<ISM 인스턴스>` — 예 `level:BP_ParkingSlot_C_1#0`
- 프리셋 면: `preset:<PresetIdx>#<SlotId>` — 예 `preset:3#3`

`FParkingSlotNumberInfo::FaceKey()` 가 만들고, `preset.numbers` 가 `faceKey` 로 돌려준다.

## 4. 패널 조작 순서

```
① LShift + 바닥 면 클릭  → 안내 문구 "기준 면 #2 → 번호 쓰고 '수정'", 칸에는 그 면의 현재 번호
② 칸에 원하는 번호 입력   → 예 100
③ '수정'                → 프리셋에 (start_face, start_slot) 저장 + 바닥 즉시 재부여
④ '저장'                → JSON 에 "start_slot": 100, "start_face": "level:..." 로 남는다
```

- 칸만 고치고 `수정`을 안 누르면 아무것도 안 바뀐다(09-07 과 같은 2단계 규약).
- 클릭 없이 숫자만 넣고 `수정`하면 기준 면이 없으므로 기록만 된다. 안내 문구가 "LShift+클릭으로 기준 면 지정"으로 남아 그 사실을 알린다.
- 칸을 비우고 `수정`하면 기준 면도 함께 지워져 그 프리셋의 재부여가 풀린다.
- 다른 레벨의 파일을 열면 기준 면을 못 찾아 "기준 면이 이 레벨에 없음"이 뜬다. 값은 보존된다.

기동 시 자동 로딩(`APark3DGameMode::ApplyStartupConfig` → `UCameraControlWidget::LoadFromJsonFile`)도 `SyncNumberAnchors()` 를 지나므로 파일에 적힌 기준점이 곧 기동 직후 바닥 번호다.

## 5. RPC

```jsonc
// 기준점 지정: 순번 5번 면(faceKey 는 preset.numbers 에서) 을 20번으로
cam.savePreset { camId:1, presetId:1, startSlot:20, startFace:"level:BP_ParkingSlot_C_1#0", fileName:"CamPos_X.json" }
// → startSlot/startFace 를 응답에 실어 주고 바닥이 즉시 재부여된다

// 목록 — number 는 재부여 후, baseNumber 는 순번, faceKey 는 기준점에 쓰는 키
preset.numbers → { numbers:[ { number:20, baseNumber:5, faceKey:"level:BP_ParkingSlot_C_1#0", ... } ] }
```

`cam.loadPreset` 은 파일의 기준점으로 바닥을 다시 매기고(패널 `열기`와 같다), `cam.deletePreset` 은 지운 프리셋의 기준점을 뺀다.

**패널 `CamData` 와 RPC `PresetMemory` 는 여전히 별개다**(09-07 항목). 기준점은 "마지막에 넘긴 쪽이 이긴다" — RPC 로 걸어 둔 기준점은 패널에서 `수정`을 누르는 순간 패널 것으로 교체된다(반대도 같다). 실측에서 RPC 로 5번→20 을 건 뒤 패널에서 2번→100 을 `수정`하니 20 계열이 사라지고 100 계열만 남았다. 카메라 액터 상태가 두 경로에서 갈리는 것과 같은 성질이고, 이번에 통합하지 않았다.

## 6. 검증

빌드: `Park3DEditor`·`Park3D` Win64 Development 둘 다 통과. 자동화 테스트 `Park3D.ParkingDecal.SlotNumbers`(TN-1~8), `Park3D.CameraControl.JsonRoundTrip`, `Park3D.CameraControl.JsonFixture` 3/3 성공.

실기(패키지 복제 `Package/Work13520`, exe 만 교체, RPC 13520, 서신 LV_Park_01 레벨 면 23개):

| 단계 | 결과 |
|---|---|
| `cam.savePreset` startFace=순번 5, startSlot=20 | `preset.numbers`: 1,2,3,4,**20,21,…,38**. 화면도 20~25 / 26~29 / 31,32 / 33~37 로 바뀜. 파일에 `"start_slot": 20, "start_face": "level:BP_ParkingSlot_C_1#0"` |
| LShift+클릭 순번 2번 면 | 로그 `기준 면 #2 지정 (레벨 면, 현재 2번)`, 칸 2, 문구 `기준 면 #2 → 번호 쓰고 '수정'` |
| 칸에 100 입력, `수정` | 로그 `번호 기준점 1개 적용` → `프리셋 수정`. 바닥: **1, 100, 101, 102, …, 121**. PTZ 카메라 뷰(우하단)에도 100·101·102 가 그대로 보임 |
| 패널 `저장` → 재기동 | 7절 참조 |

## 7. 재기동 후 자동 적용

패널 `저장`으로 복제본의 `CamPos_Seosin.json` 을 덮어쓴 뒤(파일 시각 00:05:51, `"start_slot": 100, "start_face": "level:BP_ParkingSlot_C_0#1"`) 인스턴스를 껐다 켰다.

```
[ParkingManager] 번호 기준점 1개 적용
[ParkingManager] 주차면 번호 23개 표시(프리셋 0, 레벨 23, 풀 23)
[CameraControl] 열기 2대 ← .../Work13520/Save/3D/CameraPos/CamPos_Seosin.json
[Config] 카메라위치 적용 ← ...
```

기동 직후 `preset.numbers` = `1, 100, 101, …, 121` — 파일만으로 재기동 후에도 같은 번호가 나온다. 검증 뒤 복제본 파일은 정본 것으로 되돌렸다(정본 `CamPos_Seosin.json` 은 손대지 않았다).

## 8. 남은 것·한계

- 번호 중복은 막지 않는다(2절).
- 패널 `CamData` ↔ RPC `PresetMemory` 분리는 그대로다(5절).
- 정본(`Package/Windows`)은 검증 도중 사용자가 앱을 닫아 `Park3D/Binaries/Win64/Park3D.exe` 를 새 빌드로 교체해 두었다. 다음 기동부터 반영된다. 정본 `Save/3D/CameraPos/CamPos_Seosin.json` 에는 아직 기준점이 없다 — 패널에서 찍고 `저장`해야 남는다.
