# MCP로 PIE 메뉴 버튼 클릭 → 대화상자 출력 검증 결과

- 작성일: 2026-07-07
- 대상: PIE(에디터에서 플레이) 실행 중 `WBP_MainMenu`(UMainMenuWidget) 메뉴 버튼 → 패널(대화상자) 토글
- 질문: "MCP를 통해 언리얼을 실행해 메뉴 UI 버튼을 클릭, 대화상자가 정상 출력되는지 확인 가능한가?"

## 1. 결론 (요약)

| 항목 | 가능 여부 | 비고 |
|------|:--------:|------|
| MCP로 실행 중인 PIE 접근 | ✅ 가능 | `SlateInspector`로 창/위젯 트리 접근 |
| 게임 뷰포트 UMG 메뉴 위젯·버튼 식별 | ✅ 가능 | 8개 버튼 정확히 열거 (b52~b59) |
| 화면 스크린샷으로 상태 관찰 | ✅ 가능 | `SlateInspector.Screenshot` |
| **합성 클릭으로 대화상자 실제 열기** | ⚠️ **미동작** | `OnClicked` 미발화 (아래 3항) |

즉, **관찰·식별·스크린샷·상태검증은 100% 자동화**되지만, **"버튼 클릭 → 대화상자 출력"을 합성 클릭으로 트리거하는 것은 현재 불가**하다.

## 2. 수행한 절차

1. `unreal` MCP 서버 승인 (Pending → 승인). 서버는 `localhost:8000/mcp`에서 정상 LISTENING.
2. `SlateInspector.Windows(list)` → 단일 에디터 창(PIE는 뷰포트 임베드 모드).
3. `Observe("", depth=40)` + `Snapshot` → 초기 depth 40에선 게임 UMG 미포착. `WaitFor("프리셋 메이커")=true`로 트리에 존재 확인.
4. `Snapshot(depth=120)` → 게임 UMG 버튼 8개 레퍼런스 확보. 모두 `[src=Button.cpp:67]`(UMG UButton):
   - 프리셋 메이커 `b52`, 차량 배치 `b53`, 카메라 컨트롤 `b54`, 맵 크기 변경 `b55`, 거리.피쳐 체크 `b56`, VLA 학습 데이터 `b57`, VLA 시뮬레이터 `b58`, Exit `b59`
5. `Click(b52)` ×3(홀수), `Hover(b53)+Click(b53)` 시도.
6. 매회 `Snapshot(sp4)` + `GetLogEntries` + 스크린샷으로 검증.

## 3. 관찰 결과 (핵심 근거)

- **클릭 후 Slate 포커스는 대상 버튼으로 이동**(`[focused]` 표기)하나, **패널 위젯이 트리에 추가되지 않음**. 스크린샷에도 메뉴 8버튼만 그대로.
- **로그 무발생**: 프리셋 3회·차량배치 1회 클릭에도 `LogTemp`에 신규 항목 없음.
  - `[PresetMaker] 패널 드래그 시작`(05:51), `[CarPlacement] 메시 프리로드`(05:51)는 **이전 PIE 세션의 실제 사용자 조작 잔재**(프레임번호·타임스탬프로 확인).
  - 실제 마우스 입력에서는 패널이 열렸다는 사실 → 버튼 로직·`*WidgetClass` 바인딩은 정상.
- `[MainMenu] 패널 클래스 미지정` 경고 없음 → `PresetMakerWidgetClass` 등은 정상 지정됨(코드/BP 문제 아님).

## 4. 원인 분석

- **PIE 게임 뷰포트의 UMG 입력 경로**: 게임 UMG 위젯의 마우스 입력은 `FSceneViewport` → `SGameLayerManager`를 통해 라우팅된다.
- **SlateInspector의 입력 방식**: 툴셋 설명대로, 게임 스레드 데드록 회피를 위해 `AutomationDriver` 대신 `FSlateApplication`의 이벤트 API(`ProcessMouseButtonDownEvent/Up`)를 **직접 주입**한다.
- 이 직접 주입은 **에디터 Slate 위젯**에는 포커스·클릭이 정상 전달되지만, **게임 레이어 UMG**의 경우 `SButton`에 포커스는 부여해도 `OnClicked` 델리게이트 실행까지 이어지지 않는다(뷰포트 히트테스트/마우스 캡처 경로 불일치 추정).
- 참고: `IsHovered()` 조건 회피를 위해 `Hover→Click`도 시도했으나 동일하게 미발화.

## 5. 영향도

- 코드 변경 없음(순수 검증). `UMainMenuWidget`/`PresetMakerWidget` 등 기존 로직에 영향 없음.
- 프로젝트 자산·빌드 모듈 무변경.
- 확인된 제약은 **테스트/자동화 전략 선택에만 영향**: 게임 UMG의 클릭-트리거 검증은 SlateInspector 합성 클릭에 의존하면 안 됨.

## 6. 권장 대안

1. **반자동(경로 A)**: 사람이 실제로 버튼을 클릭 → MCP는 `Snapshot`/`Screenshot`/`GetLogEntries`로 대화상자 출력·상태를 **자동 검증**. (관찰 측은 이미 완전 동작)
2. **완전 자동(경로 B, 권장)**: `AutomationTest`(Functional/유닛 테스트)로 게임 월드에서 위젯 생성 → 핸들러(`HandlePresetMaker` 등) 직접 호출 → `AddToViewport`/패널 존재를 assert. 입력 라우팅 이슈를 우회하며 회귀 테스트로 재사용. (CLAUDE.md 1·2번 규칙 부합)

## 7. 재현 명령 요지

```
SlateInspector.Windows(action=list)
SlateInspector.Observe(ref="", maxDepth=40)
SlateInspector.WaitFor(text="프리셋 메이커")        # true
SlateInspector.Snapshot(ref="", maxDepth=120, bIncludeSourceLocations=true)  # b52~b59 확보
SlateInspector.Click(ref="b52")                      # returnValue=true, 그러나 OnClicked 미발화
EditorToolset.LogsToolset.GetLogEntries(category="LogTemp", pattern="...")   # 신규 로그 없음
SlateInspector.Unobserve(identifier="observer_1")
```
