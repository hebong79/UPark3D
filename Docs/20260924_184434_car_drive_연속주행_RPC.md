# car.drive / car.driveStatus — 차량 연속 주행 RPC (보드 #805)

- 날짜: 2026-09-24
- 브랜치: `feat/car-drive-rpc`
- 요청: SettingManager / TourAgent(192.168.0.221) — 통로를 지나가는 차(pass-by traffic)를 20km/h 로 매끄럽게 움직일 RPC. 마스터 지시로 시뮬레이터 쪽을 넘겨받음.

## 1. 배경

`car.setPosition` 을 RPC 로 여러 번 부르면 7.5fps 카메라 스트림에서 순간이동으로 보이고, 속도가 RPC 호출 간격(네트워크 지연)에 묶인다.
주차 시뮬(`AParkingSimManager`)은 면·입구·회피를 전제로 해서 "경로만 주어진 이동"에 쓸 수 없다. 그래서 **매 프레임 DeltaSeconds 로 진행하는 전용 매니저**를 둔다.

이 작업은 다른 세션(VS Code, 18:21~18:25)이 시작해 둔 미커밋 작업을 이어서 완성한 것이다. 18:38 확인 시 13분간 수정이 없어 경합 없음으로 판단.

## 2. 구성

### 동작 규칙
- 첫 구간은 **차량의 현재 위치**에서 출발. 앞 점과 1mm 미만으로 겹치는 점은 버린다(방향 불명).
- 자세는 주차 시뮬과 같은 규약: `rotY = atan2(dy, dx)`(도), `isFront=true`, `ApplyTransformFromData` 가 지면에 앉힌다(z 는 `car.setPosition` 과 같은 지면 스냅).
- 같은 차에 새 `car.drive` → 옛 주행 `cancelled / replaced`.
- 주행 중 `car.delete` → 다음 프레임에 `cancelled / carRemoved`(약한 포인터라 크래시 없음).
- 도착해도 차량은 끝점에 남는다(제거는 호출자 몫).
- 끝난 주행은 조회용으로 64건까지 보관. RunId 는 프로세스 전역 증가값(레벨 전환 후에도 재사용 안 됨). 레벨 전환 뒤 옛 runId 는 FailDomain.

### 이번 세션에서 이어서 바꾼 것
- `car.driveStatus` 필드를 TourAgent 계약에 맞춤: `distanceM`→`distM`, `reason`→`endReason`(비어 있으면 생략), `ok:true` 추가.
- `car.driveStatus` 는 조회라 매니저를 스폰하지 않도록 `ACarDriveManager::Find` 신설.
- 테스트 추가: 길이 0 경로(즉시 arrived/zeroLength), 실제 시험 차선(97.61m·5.56m/s·7.5fps 스텝 → 17.6초, 72.09°).

## 3. RPC 계약

### `car.drive`
params: `{ carNameId, path:[{x,y},...], speedMps?: number = 4 (0 < v ≤ 40), rotY?: "follow" | number(도) }`
response: `{ ok:true, runId, carNameId, totalM, speedMps, etaSec, state }`
errors(-32000 FailDomain): 차량 없음 / path 누락·빈 배열 / path[i] 에 x·y 없음 / speedMps 범위 밖 / rotY 가 "follow"·숫자가 아님. carNameId 누락은 파라미터 오류.

### `car.driveStatus`
params: `{ runId }`
response: `{ ok:true, runId, carNameId, state:"driving"|"arrived"|"cancelled", endReason?: "arrived"|"zeroLength"|"replaced"|"carRemoved", distM, totalM, progress, speedMps, elapsedSec, pos?{x,y,z}, rotY? }` (pos·rotY 는 차량이 남아 있을 때만)
errors: 모르는 runId → -32000.
