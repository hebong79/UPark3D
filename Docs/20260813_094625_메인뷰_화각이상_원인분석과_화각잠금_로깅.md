# 메인 뷰 화각 이상 — 원인 분석과 화각 잠금 로깅 (2026-08-13)

## 1. 신고

"화면 비율이 이상하다. fov 에 문제가 생겼나?" — 주차장이 극단적으로 넓게 보이고
가장자리 물체가 늘어나 보이는 화면 캡처가 함께 제출됨.

## 2. 결론

**FOV 계산 코드의 버그가 아니다.** 메인 뷰의 화각이 런타임에 **138°(수평)로 잠겨** 있었다.
`view.set {fov:0}` 으로 잠금을 해제하자 즉시 정상(72.73°)으로 돌아왔다.

## 3. 근거

| 확인 항목 | 값 |
|---|---|
| 시작 로그 | `[Park3DGameMode] 메인 뷰 화각 고정: 수직 45.00° → 수평 72.73°(16:9)` |
| `view.get` | `fov: 138` |
| `view.set {fov:0}` 직후 `view.get` | `fov: 72.73` |
| 화면 | 정상 비율로 복귀(캡처 확인) |

`APlayerCameraManager::GetFOVAngle()` 은

```cpp
return (LockedFOV > 0.f) ? LockedFOV : GetCameraCacheView().FOV;
```

이므로, 잠금 해제 직후 72.73 이 나왔다는 것은 **`DefaultFOV` 는 정상이었고 `LockedFOV = 138` 이 덮고 있었다**는 뜻이다.
수평 138° 는 대각선이 극단적으로 벌어지는 광각이라 가장자리 왜곡이 "비율이 깨진 것"처럼 보인다.

### 누가 걸었는가

- 코드에서 `PlayerCameraManager::SetFOV` 를 호출하는 곳은 `ViewRpcModule` 의 `view.set {fov}` **한 곳뿐**이다.
- `Content` 전체 `.uasset`/`.umap` 을 훑어 `SetFOV` / `SetFieldOfView` / `LockedFOV` 문자열을 찾았으나 **없음**
  (블루프린트가 건 것도 아니다).
- 카메라 위치도 시작값 `(-15, 0, 15)m` 에서 `(-19.2, 25.4, 19.2)m` 로 옮겨져 있었다 — 시점 조작 흔적과 일치.

즉 **외부에서 `view.set` 으로 건 값**이다. 단, **누가 언제 걸었는지는 특정할 수 없었다**:
RPC 서버는 요청을 로그에 남기지 않고, 연구 프로젝트 정책상 인증 없이 `0.0.0.0:13510` 으로 열려 있다
(`[RPC] ... 누구나 95개 메서드(저장 포함)를 호출할 수 있습니다`).

## 4. 조치

### 4-1. 런타임 복구(파일 변경 없음)

`view.set {fov:0}` → 72.73° 복귀. 사용자 화면 즉시 정상화.

### 4-2. 코드 — 화각 잠금/해제 로깅 (`ViewRpcModule.cpp`)

같은 신고가 다시 오면 또 추적 불가가 되므로, `view.set` 이 화각을 잠그거나 풀 때 **앞뒤 값**을 남긴다.

```cpp
const float PrevFov = PC->PlayerCameraManager->GetFOVAngle();
...
UE_LOG(LogTemp, Log, TEXT("[View] 화각 잠금: %.2f° → %.2f°(수평)"), PrevFov, (float)NewFov);
UE_LOG(LogTemp, Log, TEXT("[View] 화각 잠금 해제: %.2f° → 기본 %.2f°"), PrevFov, PC->PlayerCameraManager->GetFOVAngle());
```

## 5. 검증

1. `Build.bat Park3D Win64 Development` → `Result: Succeeded`.
   `UPROPERTY` 추가가 없으므로 재쿠킹 없이 exe 교체만으로 반영(문서 `20260812_234600` 4절 규칙).
2. 재기동 후 `view.set {fov:100}` → `view.set {fov:0}` 왕복. 로그:

```
[2026.08.13-00.46.05:694][ 18]LogTemp: [View] 화각 잠금: 72.73° → 100.00°(수평)
[2026.08.13-00.46.08:769][ 44]LogTemp: [View] 화각 잠금 해제: 100.00° → 기본 72.73°
```

3. 현재 앱 상태: 카메라 시작 시점 `(-15, 0, 15)m`, 화각 72.73°(잠금 없음).

## 6. 고치지 않고 남긴 것 (사용자 판단으로 보류)

`APark3DGameMode::ApplyMainViewFov` 는 수직 45° 를 **16:9 로 하드코딩**해 수평각으로 환산한다.
UE 는 수평 화각을 유지(MaintainXFOV)하므로 창이 16:9 가 아니면 **의도한 수직 45° 가 어긋난다**
(예: 창 비율 1.59 → 수직 약 49.7°). 주석은 "화면비에 흔들리지 않는 수직각"이라고 말하지만 실제로는 흔들린다.
이번 증상의 원인은 아니어서 이번 변경 범위에서 제외했다. 고치려면 실제 뷰포트 비율로 환산하고
창 리사이즈 때 재적용해야 한다.
