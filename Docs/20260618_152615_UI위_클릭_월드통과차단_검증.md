## 1. 요청 내용

> 마우스가 UI 위에 올라갔을때 맵 바닥이 클릭이 안되게 처리해줘.

확인 결과, **일반 클릭 입력 경로**에 대해서는 별도 코드 추가 없이 이미 차단되도록 구성돼 있었다. 본 문서는 그 구성과 검증을 정리한다.

---

## 2. 결론: 일반 클릭 입력은 이미 차단됨

UI 위 클릭이 월드(맵 바닥)로 통과하지 않게 하는 표준 조건 2가지가 이미 충족돼 있다.

| 조건 | 현재 상태 | 역할 |
|------|-----------|------|
| UI 패널이 hit-test 가능(Visible) | `RootBorder` = **Visible** (60% 패널 전체 덮음) | 패널 위 클릭을 Slate가 소비 |
| 입력 모드 = Game and UI | `Park3DGameMode`가 `FInputModeGameAndUI` 설정 | UI 위는 차단, 패널 밖은 월드 클릭 허용 |

### 2.1 위젯 hit-test 상태(실측)
- `RootBorder` = Visible → **60% 패널 영역 전체가 hit-test 대상** (라벨/박스 사이 빈틈도 뒤의 Border가 잡음)
- 모든 상호작용 위젯(Btn_*, Check_*, Radio_*, Combo_DirType, Field_*) = Visible → 정상 클릭 소비
- 레이아웃 박스(VBox/HBox) = SelfHitTestInvisible → 투명하지만 뒤의 Visible Border가 클릭을 받음
- `RootCanvas` = SelfHitTestInvisible → **패널 바깥 영역은 월드로 통과**(의도대로)

### 2.2 차단 원리(Slate 입력 라우팅)
게임 뷰포트(SViewport) 위에 hit-test 가능한 UMG 위젯이 얹혀 있으면, 그 위치의 마우스-다운은 **위젯 경로에서 처리되고 뷰포트로 내려가지 않는다.** 위젯이 이벤트를 "Handled"로 처리하지 않아도, 적중 위젯이 뷰포트가 아니므로 월드 입력은 해당 클릭을 받지 못한다. 따라서 패널 위 클릭은 월드(맵 바닥)에 도달하지 않는다.

---

## 3. 검증

| 항목 | 방법 | 결과 |
|------|------|------|
| 패널 영역 hit-test = Visible | 위젯 객체 `visibility` 실측 | RootBorder Visible, 전 영역 커버 ✓ |
| 입력 모드 = Game and UI | `Park3DGameMode::BeginPlay` 코드 | `FInputModeGameAndUI` ✓ |
| 실행 시 UI 표시 | Standalone(`-game`) 로그 | `Game class is 'Park3DGameMode'` + UI 표시 로그 ✓ |
| 패널 클릭이 Slate에 소비됨 | 직전 Standalone에서 패널 버튼 클릭 | `[PresetMaker] 추가됨 …` 위젯 핸들러 정상 발화(= Slate가 클릭을 가져감, 월드로 안 샘) ✓ |
| 입력 관련 런타임 오류 | Standalone 로그 | 없음 ✓ |

> 참고: 시각 스크린샷은 standalone D3D 창의 GDI 캡처 제약(+모니터 구성)으로 확보하지 못했으나, 입력 차단 검증은 로그·구성 실측으로 충분하다.

---

## 4. 남은 경우: "커서 아래 월드 트레이스" 픽 (주의)

`OffsetPick`처럼 **매 프레임 마우스 커서 아래 월드를 트레이스**해서 위치를 잡는 방식은, Slate의 클릭 소비와 무관하게 동작하므로 UI 위에서도 바닥이 잡힐 수 있다. 이건 클릭 입력이 아니라 트레이스라 입력 모드로는 못 막는다.

→ 해당 픽 로직(블루프린트 `On Offset Pick` 등) 안에서 **커서가 UI 위면 무시**하도록 가드를 넣으면 된다:
- 위젯 블루프린트에서 `Self → Is Hovered`(UserWidget 내장)가 true면 트레이스/픽을 건너뛴다.
- 현재 `OnOffsetPick`/`OnCreatePreset`는 빈 BlueprintImplementableEvent라 아직 월드 픽 로직이 없으므로, 지금은 새는 경로가 없다.

---

## 5. 영향도 분석

- **변경 없음**: 일반 클릭 차단은 기존 구성(Visible 패널 + Game and UI)으로 이미 충족 → 코드/에셋 변경 없음, 재빌드 없음.
- **월드 픽 추가 시**: 커서-트레이스 방식 픽을 구현하면 `Is Hovered` 가드를 추가해야 UI 위 통과를 막을 수 있음.
- **전체 차단을 원할 경우(대안)**: 패널이 떠 있는 동안 화면 전체에서 월드 클릭을 막고 싶으면 입력 모드를 `FInputModeUIOnly`로 바꾸면 되나, 이 경우 패널 밖 월드 클릭도 모두 막힘(재빌드 필요).
