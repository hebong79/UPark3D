# 패키징 배치에 진행률(%) 표시 추가

- 작성일: 2026-08-06
- 대상: `BuildPackage.bat`, `BuildProgress.ps1`(신규)
- 관련: `Docs/20260805_221200_실행파일_빌드_배치파일.md`

## 1. 요구사항

`BuildPackage.bat` 실행 중 화면에 아무것도 안 나와서 진행 상황을 알 수 없다. 퍼센트로 보이게 한다.

## 2. 원인

기존 배치는 UAT 출력을 **전부 로그 파일로만** 보냈다(`> "%LOG%" 2>&1`). 그래서 배치 스스로
"진행을 보려면 다른 창에서 `Get-Content -Wait` 하라"고 안내하고 있었다.

## 3. 진행률의 근거 — UAT 가 이미 찍는 라인

기존 로그(`_workspace/package_build.log`)에서 확인한 형식이다. 새로 만들어 낸 것이 아니다.

| 단계 | 라인 | 진행률 |
|---|---|---|
| BUILD | `[3/8] Compile [x64] Park3DAppConfig.cpp` | n/m |
| COOK | `LogCook: Display: Cooked packages 400 Packages Remain 260 Total 660` | N/Total |
| 단계 전환 | `********** COOK COMMAND STARTED **********` | BUILD→COOK→STAGE→ARCHIVE |

에픽 런처용 `@progress` 마커는 이 빌드에 0건이라 쓸 수 없어, 위 라인들을 파싱한다.

## 4. 구조

```
UAT stdout ──파이프──> BuildProgress.ps1 ──┬─> 화면: 같은 줄을 덮어쓰며 퍼센트
                                          └─> 파일: 원본 줄 그대로(로그)
```

배치에는 tee 가 없어서 "화면 + 파일 동시 출력" 역할을 이 스크립트가 맡는다.
`[Console]::In.ReadLine()` 로 한 줄씩 스트리밍하고 매 줄 flush 하므로, 종전처럼 다른 창에서
로그를 tail 하는 것도 그대로 된다.

### 출력 예

```
[BUILD] started            elapsed 00:00
[BUILD] done  100%        elapsed 00:00
[COOK] started            elapsed 00:00
[COOK] cook 0/500    0%   elapsed 00:00
[COOK] cook 288/660   44%  elapsed 01:12
[COOK] cook 660/660  100%  elapsed 02:30
```

단계가 바뀔 때만 줄이 남고, 같은 단계 안에서는 한 줄을 갱신한다.

## 5. 설계 판단

| 항목 | 결정 | 사유 |
|---|---|---|
| 표시 방식 | 한 줄 덮어쓰기 | `Write-Progress`(콘솔 상단 고정 바)는 리다이렉트·비대화형 환경에서 사라진다 |
| 화면 문구 | **ASCII 전용** | 처음엔 한글(`쿠킹 400/660`)로 썼다가 콘솔에서 바이트가 깨졌다. 배치는 자신이 어떤 코드페이지에서 실행될지 알 수 없다(`BuildPackage.bat` 헤더의 ASCII ONLY 규칙과 같은 이유). 한글은 주석과 이 문서에만 둔다 |
| 로그 인코딩 | UTF-8(BOM 없음) | 배치의 실패 판정 `findstr` 는 ASCII 마커만 보므로 영향 없음 |
| 실패 판정 | **변경 없음** | 파이프 때문에 `ERRORLEVEL` 이 파이프라인 값이 되지만, 이 배치는 원래부터 exit code 를 믿지 않고 로그 마커(`AutomationTool exiting with ExitCode=0`)와 산출물 존재로 판정한다 |

## 6. 알아둘 것

- **쿠킹 %는 뒤로 갈 수 있다.** `Total` 이 진행 중 커진다(500 → 576 → 660, 의존 에셋 발견).
  최신 `Total` 로 다시 계산하므로 퍼센트가 한 번씩 줄어드는 것은 정상이며 멈춘 것이 아니다.
- **컴파일이 없으면 BUILD 단계는 순식간에 지나간다.** 소스가 그대로면 `[n/m] Compile` 라인 자체가
  나오지 않는다. 체감 진행 구간은 쿠킹이다.

## 7. 검증

| 항목 | 결과 |
|---|---|
| 실제 로그 400줄 재생 → 퍼센트 산출 | **통과** — BUILD 단계 전환, 쿠킹 0%→18%→28%→44%→61%→100% |
| 로그 파일 원본 재현 | **통과** — 400줄 그대로 기록 |
| ASCII 출력(깨짐 없음) | **통과** — 한글 버전에서 깨지던 것을 확인 후 수정 |
| 배치의 실행 중 앱 가드 | **통과** — `[FAILED] Park3D.exe is running.` 후 exit 1 |
| **전체 패키징 1회 실행** | **미검증** — 사용자가 Park3D.exe 를 실행 중이라 배치가 거부했다. 앱 종료 후 1회 실행해 실제 진행률이 흐르는 것을 확인해야 한다 |

## 8. 영향도

- 빌드 산출물·쿠킹 결과에는 영향이 없다. UAT 명령 인자는 그대로이고 출력 경로만 바뀌었다.
- `BuildProgress.ps1` 이 없으면 배치가 시작 시점에 `[FAILED]` 로 멈춘다(가드 추가).
- PowerShell 실행 정책은 `-ExecutionPolicy Bypass` 로 우회하므로 정책 설정과 무관하게 동작한다.
