# 번호판에 번호가 안 보이는 원인 — TextRender 는 Runtime 캐시 폰트를 그리지 않는다

- 작성: 2026-08-17 22:57
- 발단: "차량 번호판에 랜덤으로 차량 번호를 넣어줘"
- 결론 먼저: **기능은 이미 있고 번호도 만들어지고 있다. 글자가 렌더되지 않을 뿐이다.**
  원인은 폰트 에셋의 캐시 종류이며, 이번 커밋으로는 고쳐지지 않는다(§5 선택지).

| 소스 | 결과 |

번호 생성은 살아 있다. 런타임 로그에 차마다 다른 번호가 찍힌다.

```
[CarPlate] Front id=0-16.25.24 number=455가5639 ... text(reg=1 vis=1 hidden=0 text=455 가 5639 ...)
[CarPlate] Front id=1-16.25.35 number=139다3108 ...
```

즉 **"랜덤"은 이미 충족**돼 있다 — 번호는 차량 id(`{idx}-{시각}`) CRC32 해시라 차마다 다르고 실행마다 달라진다.

## 3. 원인

```
Park3D/Content/Actors/Car/Plates/Font/수성돋움체.uasset  →  EFontCacheType::Runtime
```

**`UTextRenderComponent` 는 Offline(텍스처 캐시) 폰트만 그린다.** Runtime 폰트는 Slate/UMG 용이며
TextRender 에 물리면 **경고도 에러도 없이 아무것도 그리지 않는다**. 로그에는 `vis=1 hidden=0` 로 남고
폰트도 정상 로드되므로(FreeType) 로그만 봐서는 정상으로 보인다 — 이 조합이 원인 추적을 어렵게 한다.

`Content` 전체를 훑어 확인했다: **Offline 폰트는 저장소에 하나도 없다.**
2026-08-16 콘텐츠 교체 때 폰트가 Runtime 계열로 바뀐 것이 회귀 지점으로 보인다
(2026-07-20 구현 당시에는 글자가 보였다는 기록이 있다).

## 4. 이번 커밋에 담은 것 — 판/글자 정렬을 메시에서 구한다

원인은 아니었지만 고칠 값이 있었다. 판의 회전과 글자 위치가 **면 법선 = local +Y** 라는 가정으로
코드에 박혀 있었다. 콘텐츠가 바뀌면 그 가정이 깨진다.

- `ACarActor::AlignPlateAndText()` 신설 — 판 메시의 바운즈에서 얇은 축(면 법선)·긴 축(글자 진행)을 구하고,
  판을 차량 바깥으로 돌린 뒤 글자를 면 바깥(`두께 + 0.3cm`)에 놓는다. **바운즈 원점 오프셋도 반영**한다
  (메시가 원점 기준으로 치우쳐 있으면 두께만으로 띄운 글자가 판 속에 박힌다).
- 정렬 결과를 로그로 남긴다 — 다음에 "로그엔 vis=1 인데 화면에 없다"를 만나면 여기서 시작한다.

```
[CarPlate] Front 정렬: 메시축(얇=1 넓=0) 두께=1.51 원점=X=0.000 Y=-0.509 Z=0.000
           → 글자 local=X=4.000 Y=1.300 Z=0.000 world=X=2137.915 Y=524.538 Z=39.117
```

## 5. 남은 선택지 (사용자 결정 대기)

| 방법 | 내용 | 비용 |
|------|------|------|
| A. Offline 폰트 제작 | 에디터에서 TTF 를 Offline 캐시로 임포트(필요 글자: 숫자 10 + 한글 24). TextRender 그대로 | 에디터 작업 + 재쿡. 런타임 비용 0, 코드 거의 불변 |
| **B. 런타임 텍스처** (추천) | 번호를 렌더타깃에 그려 판 재질에 넣는다. 지금 폰트를 그대로 쓰고 에디터 작업이 없다 | 코드 추가(렌더타깃·동적 머티리얼), 차당 1장 |
| C. 3D 위젯 | `UWidgetComponent` + UMG 텍스트 | 코드는 단순하나 차 60대×2 = 위젯 120개로 무겁다 |

엔진 기본 Offline 폰트(`RobotoDistanceField` 등)로는 **한글이 빠진다** — 숫자만 나오고 `가/나/다`가 사라지므로
한국 번호판에는 쓸 수 없다.

## 6. 해결 (2026-08-18) — 3D 위젯으로 그린다

선택지 중 **C(3D 위젯)** 로 갔다. A(Offline 폰트)는 에디터 작업이 필요하고, 사용자가 알려 준
`Content/Widgets/Fonts/Pretendard` 도 확인해 보니 **Runtime 캐시**라 TextRender 문제를 풀지 못했다.
B(런타임 텍스처)는 판 재질의 텍스처 파라미터 이름을 확신할 수 없어(잘못 물리면 노멀맵을 덮는다) 접었다.

- `UCarPlateNumberWidget`(신규): `UScaleBox(ScaleToFit)` + `UTextBlock`. 폰트는 Pretendard Bold, 검정.
  Slate/UMG 는 Runtime 폰트를 그대로 그리므로 한글이 나온다.
- `ACarActor` 에 앞/뒤 `UWidgetComponent` 추가 — 판의 자식이며 면 바깥 0.5cm, 판 폭의 82% 를 차지한다.
  기존 `UTextRenderComponent` 는 블루프린트 호환을 위해 남기되 숨긴 상태 그대로 둔다.
- **ScaleBox 를 쓴 이유**: 상수로 폭을 맞췄더니 `224수0840` 의 마지막 `0` 이 판 밖으로 잘렸다.
  폰트·형식이 바뀔 때마다 상수를 다시 맞추는 대신, 담기는 만큼 자동으로 줄인다.

### 함정 하나 더

`RebuildWidget()` 안에서 `ConstructorHelpers::FObjectFinder` 로 폰트를 찾다가 즉시 크래시했다 —
`FObjectFinders can't be used outside of constructors`. 런타임 경로에서는 `LoadObject` 를 쓴다.
