## 1. 요청

> UI를 출력하지 않고 바닥맵만 출력해서 마우스 컨트롤이 잘 되는지 확인해줘.

평소에는 `APark3DGameMode::BeginPlay()`가 `WBP_PresetMaker` 위젯을 `AddToViewport`로 자동 표시한다.
이번에는 그 UI 없이 **바닥맵 + 마우스 커서**만 띄워 마우스 동작을 확인하는 것이 목표.

---

## 2. 설계(구현 전 선행 — CLAUDE.md 0번)

### 2.1 UI를 띄우는 주체
- `Park3D/Source/Park3D/Park3DGameMode.cpp` 의 `BeginPlay()` 가 `PresetWidgetClass`(기본값 `/Game/UI/WBP_PresetMaker`)로 위젯을 생성·`AddToViewport`.
- 생성자에서 `FClassFinder` 로 클래스를 고정 주입하므로 **CDO만 바꿔서는 UI를 끌 수 없다**(생성자가 매번 재설정). 또한 클래스가 null이면 `BeginPlay`가 조기 반환하여 **커서 설정까지 건너뛴다.**

### 2.2 채택 방식 (재빌드 없음 · 정상 앱 회귀 없음)
| 방식 | 채택 | 사유 |
|------|------|------|
| C++ 수정(위젯 add 제거) | ✕ | 재빌드 필요 |
| 런타임 python으로 위젯 제거 + PIE | ✕ | **PIE를 MCP 브리지 python 안에서 시작하면 에디터가 크래시**(아래 4장) |
| 맵 World Settings GameMode Override | ✕ | PresetEditor는 실제 런타임 맵 → 정상 앱 UI에 영향 |
| **별도 standalone + `?game=` URL override** | **○** | 맵·코드·설정 무변경. 전용 테스트 GameMode를 URL로만 주입 |

### 2.3 테스트 픽스처(임시 자산)
- `/Game/_Test/BP_FloorTestPC` (`PlayerController` 상속): `ShowMouseCursor = true`, 클릭/마우스오버 이벤트 on. **커서를 켜는 역할.**
- `/Game/_Test/BP_FloorTestGM` (`GameModeBase` 상속): `PlayerControllerClass = BP_FloorTestPC`, `DefaultPawnClass = DefaultPawn`.
  - `GameModeBase` 상속이므로 **위젯을 띄우는 로직이 없음 → UI 미표시.**
  - `DefaultPawn` 은 실제 앱과 동일 → PlayerStart 부감 시점으로 **바닥이 그대로 프레이밍**됨.
- 클래스 디폴트만 수정(이벤트 그래프 미사용). 정식 맵/설정은 미변경 → 정상 앱 동작 보존.

## 3. 실행/검증 절차

별도 프로세스로 standalone 게임을 실행(에디터와 독립):

```
UnrealEditor.exe "Park3D.uproject" ^
  "/Game/Maps/PresetEditor?game=/Game/_Test/BP_FloorTestGM.BP_FloorTestGM_C" ^
  -game -windowed -ResX=1280 -ResY=720 -NoVSync -abslog=floor_test.log
```

### 3.1 로그 검증 (PASS)
| 로그 라인 | 의미 |
|-----------|------|
| `LoadMap: /Game/Maps/PresetEditor` | 바닥맵 로드 ✓ |
| `Game class is 'BP_FloorTestGM_C'` | 테스트 GM 적용 = Park3DGameMode 아님 → **UI 미생성** ✓ |
| `Bringing World /Game/Maps/PresetEditor.PresetEditor up for play` | standalone 정상 진입(UEDPIE 아님) ✓ |
| `[Park3DGameMode] Preset Maker UI…` **없음** | 위젯 안 뜸 ✓ |
| `Fatal error / LogWindows: Error` **없음** | 크래시·에러 없이 실행 ✓ |

### 3.2 화면 검증 (스크린샷)
- `_workspace/floor_test_defaultpawn.png`: **바닥 Plane이 부감으로 가득 찬 화면**, 상단에 옅은 하늘. **UI 위젯 전무.**
- 화면 복사본에 커서가 안 잡힘 → 소프트웨어 커서가 아니라 **OS 하드웨어 커서(NoCapture)** 임을 방증(= 프레임과 무관하게 부드러운 커서).
- 참고: `SpectatorPawn` 으로 처음 시도했을 때는 초기 시야가 하늘을 향했음(`floor_test_capture.png`/`floor_test_final.png`). **DefaultPawn 으로 교체하여 실제 앱과 동일한 바닥 프레이밍**을 얻음.

### 3.3 마우스 컨트롤 근거
현재 전역 입력 설정(런타임 실측, 선행 문서의 fix 유지):
- `DefaultViewportMouseCaptureMode = NO_CAPTURE` → OS 하드웨어 커서 사용(프레임 저하와 무관하게 부드러움)
- `DefaultViewportMouseLockMode = DO_NOT_LOCK` → 커서 자유 이동
- `EnableMouseSmoothing = False` → 입력 지연 없음
- 맵이 경량(액터 5개)이라 프레임이 높아 커서 버벅임 요인 자체가 없음.

> **체감 확인은 사용자 몫:** 마우스의 "잘 되는지"는 실시간 상호작용 감각이라 스크린샷으로 단정할 수 없다. 실행 중인 standalone 창(상기)에서 마우스를 움직여 부드러움을 직접 확인하도록 남겨 두었다.

## 4. 사건 기록: PIE를 MCP python 안에서 시작 → 에디터 크래시

- 최초 시도에서 `execute_python` 안에서 `LevelEditorSubsystem.editor_play_simulate()`(PIE 시작)를 호출 → **에디터 즉시 크래시**.
- 크래시 콜스택: `ExecutePythonCode → PythonScriptPlugin → editor_play_simulate → LevelEditor`(게임 스레드에서 월드 재구성과 충돌).
- **교훈:** PIE는 MCP 브리지의 python 컨텍스트에서 시작하면 안 됨. 게임 실행 검증은 **별도 standalone 프로세스**로 수행한다(본 작업도 그렇게 전환). 에디터는 재시작하여 복구함.
