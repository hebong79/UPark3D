# SceneCapture 에 Lumen GI·반사 복구 + 창 화각을 스트림(수직 45°)에 맞춤

- 날짜: 2026-10-29
- 브랜치: `fix/main-view-match-window` (main 9442cab 에서 분기, 미커밋)
- 계기: 마스터 — 「UPark3D 원본(창)과 셋팅매니저 스트리밍 이미지 차이가 너무 난다」, 「근본 원인은 메인뷰와 카메라뷰(렌더타깃뷰)의 퀄리티가 다르다」
- 결정: 화각은 **창을 스트림에 맞춤**, 색은 **메인 뷰 + 카메라 채널 모두** 수정

## 1. 원인

### 1-1. 색 — 엔진이 SceneCapture 의 Lumen 을 기본으로 끈다

UE 5.8 `Renderer/Private/SceneCaptureRendering.cpp:796-804` (상속 PP 가 없을 때):

```cpp
// By default, Lumen is disabled in scene captures, but can be re-enabled with the post process settings in the component.
View->FinalPostProcessSettings.DynamicGlobalIlluminationMethod = EDynamicGlobalIlluminationMethod::None;
View->FinalPostProcessSettings.ReflectionMethod = EReflectionMethod::None;
View->FinalPostProcessSettings.LumenSurfaceCacheResolution = 0.5f;
```

그래서 창(게임 뷰포트)은 Lumen GI·반사로 그리는데 **모든 캡처(메인 뷰 13600, 카메라 채널 1361x, cam.captureJPG)** 는
간접광 없이 그렸다 → 그늘이 거의 검고, 반사면(ARA HAIR 건물 정면)이 하늘색, 흰 차가 청동색.
2026-08-06 「스트림 간접광 누락」 진단의 실제 원인이다. 그때 넣은 `bAlwaysPersistRenderingState` 는 필요조건이지만
Lumen 자체가 꺼져 있어 효과가 없었다. 메인 뷰 가드의 「Lumen 품질 0.5」 도 같은 이유로 지금까지 아무 효과가 없었다.

창과 캡처의 나머지 차이(실측): ShowFlag 는 MotionBlur·SeparateTranslucency·OnScreenDebug 3개뿐,
`LumenSurfaceCacheResolution 0.5→1.0`·`SeparateTranslucency` 를 켜도 수치 변화 없음 → 고치지 않았다.

### 1-2. 화각 — 창은 MaintainYFOV + 4:3

엔진 기본 `AspectRatioAxisConstraint=AspectRatio_MaintainYFOV`(BaseEngine.ini). `CameraStackTypes.cpp:326-333` 은 POV.FOV 를
「POV.AspectRatio 에서의 수평각」 으로 보고 수직각을 구한다. PCM 기본 `DefaultAspectRatio` 가 4:3 이라
`ApplyMainViewFov` 가 넣은 72.73°(= 수직 45° 의 16:9 수평각)가 창에서는 수직 ≈57.8° 가 되었다.
스트림(SceneCapture, FOVAngle = 16:9 수평각)은 수직 45° → 창이 1.36배 넓었다(실측 1.35/1.33, 이론 1.357).

### 6-3. 변경
| 파일 | 내용 |
|---|---|
| `Light/LightControlManager.h/.cpp` | `UCLASS(Config=Game)`, `UPROPERTY(Config) float ExposureBiasTrim`. `ApplyExposureTrim()` — 태그 `Park3D_ExposureTrim` unbound 볼륨(우선순위 1e6)에 `AutoExposureBias = 기준 + trim`. 기준 = 우리 볼륨을 뺀 unbound·활성 볼륨 중 노출 보정을 덮는 최고 우선순위의 값(없으면 `r.DefaultFeature.AutoExposure.Bias`). 0 이면 볼륨 끔. `ApplySettings` 에서 채움광 바로 뒤(UDS 판정 앞)에 호출. `FindExposureVolume` 은 이 볼륨을 건너뛴다 |

### 6-4. 함정 — 볼륨 우선순위는 등록 순간에만 정렬된다
`UWorld::InsertPostProcessVolumeEntry` 가 등록 때의 Priority 로 자리를 정하고 다시 정렬하지 않는다.
첫 배포는 `SpawnActor` 뒤에 `Priority=1e6` 을 넣어 **자리는 0 그대로 → 레벨 볼륨(보정 0)이 이겨 효과 0** 이었다
(로그는 「-0.50 적용」 으로 정상처럼 보였다). `SpawnActorDeferred` 도 소용없었다(`PostRegisterAllComponents` 가 먼저 등록).
→ `RemovePostProcessVolume` + `AddPostProcessVolume` 으로 다시 넣는다. 테스트가 순서를 단언한다.
