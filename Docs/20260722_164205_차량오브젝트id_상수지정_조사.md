# [질문 답변] 차량 오브젝트 id 를 상수로 지정한 곳이 있나?

작성일: 2026-07-22 16:42:05
질문: "차량 오브젝트 id 상수로 지정한 곳이 있나?"

## 1. 결론

**차량 오브젝트 id(`FCarPos::id`, 문자열)를 상수로 박아둔 곳은 프로덕션 코드에 없다.** 항상 `UCarPlacementLibrary::MakeCarId(Index)` 로 생성한다. 리터럴 id 는 유닛 테스트에만 존재한다.

**다만 id 라는 이름이 붙은 다른 필드(`presetId` / `slotId` / `prefabId`)는 상수로 하드코딩된 곳이 여러 군데 있다.** 이 중 `presetId` / `slotId` 는 Unity 원본과 동작이 다르다(§4).

## 2. `id`(문자열) — 상수 없음

### 2.1 유일한 생성 경로

`Park3D/Source/Park3D/CarPlacementLibrary.cpp:111-121`

```cpp
FString UCarPlacementLibrary::MakeCarId(int32 Index)
{
    const FDateTime Now = FDateTime::Now();
    return MakeCarIdFromParts(Index, Now.GetHour(), Now.GetMinute(), Now.GetSecond());
}

FString UCarPlacementLibrary::MakeCarIdFromParts(int32 Index, int32 Hour, int32 Minute, int32 Second)
{
    // Unity 포맷 "{idx}-{HH.mm.ss}" (2자리 영점 채움).
    return FString::Printf(TEXT("%d-%02d.%02d.%02d"), Index, Hour, Minute, Second);
}
```

호출부는 2곳뿐이며 둘 다 `Index` 로 현재 차량 수를 넘긴다.

## 3. 상수로 하드코딩된 "다른 id" 들

### 3.1 배치 시점 하드코딩 (`CarPlacementWidget.cpp`)

```cpp

P.slotId   = -1;                   // ← 상수
P.prefabId = PrefabId;             // Combo_Prefab 기준

// AddCarAtWorld() — 541~545행 (동일 패턴)
P.presetId = 1;                    // ← 상수

```

또한 두 함수 모두 콤보 조회 실패 시 폴백으로 `int32 PrefabId = 1;` 을 상수로 둔다(`CarPlacementWidget.cpp:441, 508`).

### 3.2 구조체 기본값 (`ParkingCarTypes.h:79-81`)

```cpp
int32 presetId = 1;  // 프리셋 그룹 id (1부터)
int32 slotId   = 1;  // 주차면 슬롯 (1부터, -1=슬롯 외)
int32 prefabId = 1;  // 차량 메시 id (1부터, 카탈로그 Idx 와 동일 공간)
```

`slotId` 는 구조체 기본값이 `1` 인데 배치 코드는 `-1` 을 넣는다(§3.1). 값이 서로 다르지만 배치 경로가 항상 명시 대입하므로 실제 충돌은 없다.

### 3.3 폴백 상수 (`CarPlacementManager.cpp:21`)

## 4. Unity 원본과의 차이 (주의 필요)

`presetId` / `slotId` 를 상수 `1` / `-1` 로 박은 것은 **Unity 원본과 다르다.** Unity 는 대화상자 입력 필드에서 읽는다.

`unity/CarObject/CCarPlacementDlg.cs:641-650` (`AddCarObject`)

```csharp
int presetId    = (m_inPresetId.text == "-1" || m_inPresetId.text == "") ? 1 : int.Parse(m_inPresetId.text);
int startSlotId = (m_inFaceIdx.text  == "-1" || m_inFaceIdx.text  == "") ? 1 : int.Parse(m_inFaceIdx.text);
...
kCarPos.presetId = presetId;
kCarPos.slotId   = startSlotId + 1;
```

`unity/CarObject/CCarPlacementDlg.cs:1024-1063` (`OnClicked_AutoCreate`) 도 동일하게 필드에서 읽고, 자동생성은 `slotId = startSlotId + i + 1` 로 **차량마다 1씩 증가**시킨다.

| 항목 | Unity 원본 | UE 현재 |
|------|-----------|---------|
| 배치 시 `presetId` | `Field_PresetId` 입력값 (빈칸/-1 이면 1) | **항상 상수 1** |
| 배치 시 `slotId` | `Field_FaceId` 입력값 + 1 | **항상 상수 -1** |
| 자동생성 `slotId` | `startSlotId + i + 1` (증가) | **전부 상수 -1** |

즉 UE 에서는 상세 필드에 프리셋 id / 면 인덱스를 입력해도 **배치·자동생성 시점에는 무시되고**, 배치 후 [수정] 버튼을 눌러야만 반영된다(`ApplyDetailFields()`). 프리셋 그룹 이동/회전 기능(`Check_PresetGroup`)이 `presetId` 로 대상을 묶기 때문에, 전 차량 `presetId` 가 1 로 고정되면 **그룹 선택이 사실상 "전체 선택"이 된다.**

## 5. 부수 관찰 — id 중복 가능성

`MakeCarId(CarData.datas.Num())` 는 인덱스로 **현재 배열 길이**를 쓴다. 따라서

1. 차량 3대 배치 → id `0-...`, `1-...`, `2-...`
2. 가운데 1대 삭제 → 배열 길이 2
3. 다시 1대 추가 → 인덱스 2 → id `2-HH.mm.ss`

이 때 **같은 초(second) 안에서 벌어지면 기존 `2-...` 와 id 가 완전히 겹친다.** `ACarPlacementManager` 는 id 로 차량을 찾는 경로가 있어(`CarPlacementManager.cpp:153`) 오매칭 가능성이 있다.

Unity 원본도 `iCount = m_ObjCarList.Count` 로 같은 방식이라 **원본 이식 충실도 관점에서는 동일**하다. 즉 UE 에서 새로 생긴 결함은 아니다. 다만 실사용 중 id 충돌이 문제가 되면 "최대 인덱스+1" 또는 GUID 방식으로 바꾸는 것을 검토할 수 있다.

> 본 문서는 조사·답변 문서이며 **코드 변경은 하지 않았다.**
