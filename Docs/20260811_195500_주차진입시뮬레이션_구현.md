# 주차 진입 시뮬레이션 구현 (feat/parking-sim-drive)

작성일: 2026-08-11
브랜치: `feat/parking-sim-drive`

차량 1대가 주차장 입구로 들어와 무작위 주차면까지 주행해 주차하는 시뮬레이션을 추가했다.
주행 상태(이동/정지/주차)와 궤적을 로그로 남기고, 단축키·버튼으로 리플레이할 수 있다.

## 3. 주차면(기하)의 출처 — 이원화 대응

`AParkingPresetManager::StoredPresets` 는 **RPC `preset.load` 경로에서만** 채워진다.
앱 시작 시 `config_pmaker.json` 자동 로딩은 `UPresetMakerWidget` 이 **자기 배열로 렌더러만 호출**하므로
매니저 목록은 비어 있다(기존 알려진 이원화).

그래서 `AParkingSimManager::ResolvePresets()` 는 다음 순서로 목록을 정한다.

1. `AParkingPresetManager::StoredPresets` 가 비어 있지 않으면 그것
2. 비어 있으면 `config_pmaker.json` 의 `preset_file` 을 `UPresetMakerWidget::LoadPresetsFromJson` 으로 직접 읽기 (경로가 바뀌지 않으면 캐시 재사용)

주차면 사각형 자체는 `AParkingPresetManager::ComputeSlotCorners` 를 그대로 쓴다 —
디버그 라인·데칼·`random.slotPlace` 와 같은 기하 위에서 차량이 움직여야 하므로 다시 계산하지 않는다.

면 1개의 주행용 기하:
- **RowDir** = 면이 늘어서는 축(`useBaseWidth=true` 면 xSize 변)
- **DepthDir** = 차량이 드나드는 축(나머지 변)

## 4. 입구

전체 주차면의 코너를 모두 감싼 bbox 를 만든 뒤

```
입구 = ( (Xmin+Xmax)/2 , Ymax + EntranceMarginM(기본 8m) )
```

"가장 우측"은 **메인 뷰(+X 를 바라봄) 기준 화면 오른쪽 = 월드 +Y** 로 해석했다.

`001_Preset_office.json` 실측값:

```
bbox   : X[-21.871, 17.438]  Y[-9.356, 30.644]   (m)
입구   : (-2.217, 38.644)
```

## 5. 경로 생성 (탐색 없음)

목표 면이 정해지면 4점으로 경로를 만든다.

```
입구 ──▶ 통로 ──▶ 진입점 ──▶ 주차면 중심
```

1. **열린 쪽(OpenDir) 판정** — `중심 ± DepthDir*(깊이/2 + 1.5m)` 두 점 중
   *다른 면 사각형 안에 들어가지 않는* 쪽을 고른다(맞은편 열이 있으면 그쪽은 탈락).
   둘 다 뚫려 있으면 bbox 안쪽(= 내부 통로)을 우선한다.
2. **진입점** = `중심 + OpenDir*(깊이/2 + ApproachMarginM(기본 3.5m))`
3. **통로점** = 진입점을 RowDir 로 밀어 입구와 같은 줄에 맞춘 점
   (`t = dot(입구 - 진입점, RowDir)`)
4. 입구 → 통로 → 진입점 → 중심

입구가 bbox 바깥(Ymax+8m)이므로 첫 구간은 항상 주차면이 없는 외곽을 지난다.
통로점→진입점 구간은 열 사이 통로(또는 바깥 둘레)를 따라간다.

실측 예 (프리셋 3 / 5번 면):

```
입구   (-2.22, 38.64)
통로   ( 8.94, 38.64)   ← 프리셋5(X 0.79~5.79)와 프리셋3/4(X 12.44~17.44) 사이 통로
진입점 ( 8.94,  1.93)
주차면 (14.94,  1.93)
```

### 한계 (의도적으로 넣지 않은 것)
- 경로 탐색(A* 등)이 없다. 열이 3줄 이상 겹쳐 통로가 막히는 배치에서는 통로점 구간이
  다른 면 위를 지날 수 있다. 현재 데이터(6프리셋)에서는 발생하지 않는다.
- 차량 간 충돌 회피가 없다(1대 전제).
- 후진 주차가 없다. 항상 전진으로 진입한다.

## 6. 주행 모델

웨이포인트 추종 + 각속도 제한 + 가감속. 파라미터는 전부 `AParkingSimManager` 의 UPROPERTY 다.

| 항목 | 기본값 |
|------|--------|
| 순항 속도 | 3.0 m/s |
| 진입(마지막 구간) 속도 | 1.0 m/s |
| 가속 / 감속 | 2.0 / 3.0 m/s² |
| 최대 각속도 | 70 °/s |
| 제자리 선회 임계각 | 30° |
| 경유지 도달 반경 | 1.0 m |
| 주차 판정 오차 | 0.12 m |
| 샘플 주기 | 0.05 s |
| 시간 제한 | 180 s |

**상태 판정**
- 조향 오차가 임계각(30°)보다 크면 목표 속도를 0 으로 두고 제자리에서 돌린다 → **정지**
- 그 외 주행 중 → **이동**
- 마지막 경유지(면 중심)에 오차 내로 도달 → 위치·각도를 정확히 스냅하고 **주차**

즉 "정지"는 코너에서 방향을 크게 트는 순간 자연스럽게 발생한다(별도 스크립트 없음).

차량 자세는 `ACarActor::ApplyTransformFromData` 를 그대로 쓴다
(`CarData.rotY` = UE yaw, `isFront=true`, `pos` = Unreal 미터).

## 7. 로그

주행이 끝나면(주차완료/중단/시간초과) 두 파일을 남긴다.

```
Save/3D/Sim/<yyyyMMdd_HHmmss>_sim.log    사람이 읽는 로그(UTF-8 BOM)
Save/3D/Sim/<yyyyMMdd_HHmmss>_sim.json   리플레이용 프레임(UTF-8, BOM 없음)
```

`.log` 구성: 머리말(시작시각·차량·입구·목표·결과) → 경로 → 이벤트 → 궤적 샘플.

## 8. 리플레이

- 기록된 프레임을 시간 보간(위치 lerp, 각도 최단호 보간)해 차량 자세를 재생한다.
- 진입점: **F10** / HUD **리플레이** 버튼 / `sim.replay {speed}` (0.1~10배속)
- 메모리에 기록이 없으면 `Save/3D/Sim/` 의 가장 최근 `*_sim.json` 을 읽는다
  (앱을 다시 켜도 직전 주행을 볼 수 있다). 루트 키만 맞아도 역직렬화는 성공하므로
  `frames` 가 비어 있으면 실패로 처리한다.
- 재생이 끝나면 원래 상태(주차)로 되돌린다. 주행 중에는 리플레이를 거부한다.

## 9. 조작 방법

| 방법 | 시작 | 리플레이 | 정지 |
|------|------|---------|------|
| 단축키 | **F9** | **F10** | — |
| HUD 버튼(좌하단 상시) | 시작 (F9) | 리플레이 (F10) | 정지 |
| RPC | `sim.start` | `sim.replay` | `sim.stop` |

HUD 상태줄: `상태: 이동   경과 12.3s   이동 41.2m   목표 3-5면`

### RPC 6종

| method | params | 비고 |
|--------|--------|------|
| `sim.start` | `presetId?`, `slotIndex?`, `seed?`, `parkMode?` | 0/생략 = 랜덤. seed>0 이면 재현 |
| `sim.scenario` | 위 + `replay?`(true), `replayDelaySec?`(1.5), `replaySpeed?`(1.0) | **주행→주차→리플레이를 한 번의 호출로** (§12) |
| `sim.stop` | `removeCar?` | 기본 false(차량 유지). 예약된 자동 리플레이도 취소 |
| `sim.status` | `events?`(기본 20, 0=전부) | 상태·단계·경과·거리·경로·이벤트 tail |
| `sim.replay` | `speed?`(기본 1.0) | |
| `sim.entrance` | — | 입구 좌표 + bbox |

모든 sim.* 응답은 `state`(이동/정지/주차/리플레이)와 `phase`(대기/주행/주차/리플레이대기/리플레이/완료),
그리고 실제로 뽑힌 `parkMode`(전면주차/후면주차)를 함께 돌려준다.

## 12. 시나리오 RPC (`sim.scenario`)

한 번 호출로 **주행 → 주차 → (지연) → 리플레이**까지 이어진다. 차량은 끝나도 주차면에 그대로 남는다.

```json
sim.scenario {
  "seed": 2024,
  "parkMode": "random",
  "replay": true,
  "replayDelaySec": 1.5,
  "replaySpeed": 3.0
}
```

응답은 **즉시** 온다(RPC 핸들러가 게임 스레드라 여기서 기다리면 시뮬레이션 자체가 멈춘다).
진행은 `sim.status` 의 `phase` 로 본다:

```
주행 ──▶ 주차 ──▶ 리플레이대기 ──▶ 리플레이 ──▶ 완료
                 (replayDelaySec)
```

- `replay:false` 면 `sim.start` 와 동일(주차까지만, 이후 phase 는 `주차`).
- 리플레이 자동 시작이 실패하면 재시도하지 않고 `완료`로 넘어가며 경고 로그를 남긴다.
- 주행 중 `sim.stop` 을 부르면 예약된 자동 리플레이도 함께 취소된다.

`.log` 파일은 **주행 기록**이다(주차 완료 시점에 기록). 리플레이는 그 기록의 재생이라
파일에 다시 쓰지 않고, `UE_LOG` 와 `sim.status` 의 phase 로만 확인한다.

## 13. 전면주차 / 후면주차

`parkMode` 파라미터: `front` | `rear` | `random`(기본). 한글 `전면` / `후면` 도 받는다.

| 모드 | 진입 방식 | 차량 방향 | 마지막 구간 |
|------|----------|----------|------------|
| **전면주차** (`front`) | 전진 그대로 진입 | 차 앞이 **주차면 안쪽** | 진입점 → 중심, 전진 1.0 m/s |
| **후면주차** (`rear`) | 진입점에서 통로 쪽으로 돌아선 뒤 **후진** | 차 앞이 **통로 쪽** | 진입점 → 중심, 후진 0.6 m/s |
| **랜덤** (`random`) | 위 둘 중 50:50 | — | — |

- 랜덤은 주차면 추첨과 **같은 난수 스트림**에서 뽑으므로 `seed` 를 주면 면·모드가 함께 재현된다.
  응답·로그의 `parkMode` 에는 요청값이 아니라 **실제로 뽑힌 값**이 들어간다.
- 후진 전 90° 제자리 선회가 들어가므로 후면주차는 전면주차보다 약 4초 더 걸린다(같은 면 기준 19.9s → 23.9s).
- 실차처럼 주차면을 지나쳐 사선으로 꺾어 들어가지는 않는다. 진입점에서 돌아선 뒤 **직선으로 후진**한다
  (전진 진입도 같은 단순화라 두 모드의 궤적이 대칭이다).

`ACarActor` 에는 `rotY` = 실제 차량 전방(코) 방향, `isFront=true` 로 기록한다.
따라서 같은 면에서 두 모드의 `rotY` 는 정확히 180° 차이가 난다(예: 프리셋5/11면 → 전면 -180°, 후면 0°).

검증(2026-08-11, 프리셋 5 / 11번 면 고정):

| 요청 | 실제 | rotY | 소요 | 이동 |
|------|------|------|------|------|
| `front` | 전면주차 | -180° | 19.9s | 37.8m |
| `rear` | 후면주차 | 0° | 23.9s | 37.9m |
| `random` seed 1~12 | 전면 7 / 후면 5 | — | — | — |
| `전면`(한글) | 전면주차 | -180° | 19.9s | 37.8m |

후면주차 로그 발췌:

```
목표: 프리셋 5 / 11번 면 (후면주차)
[  0.00s] 입구 진입 — ... 후면주차(후진 진입 · 차 앞이 통로 쪽)
[  0.00s] 시나리오 예약 — 주차 완료 1.5초 뒤 리플레이 자동 재생(3.00배속)
[ 12.88s] 후면주차 — 진입점에서 돌아서서 후진 시작 (위치 9.27, 17.88)
```
