## 1. 요구사항 (사용자 확정)

기존 디버그라인 방식은 배포판(Shipping/Test)에서 `DrawDebug*`가 `ENABLE_DRAW_DEBUG=0`으로 **컴파일 제거**되어 아예 표시되지 않는다. 따라서 데칼(UDecalComponent, 런타임 렌더 컴포넌트)로 실제 주차면처럼 렌더하고, 선택 표시(fill)까지 데칼이 담당하도록 한다.

## 2. 설계 요약

상세 설계는 `_workspace/parkingdecal_architect_design.md` 참조. 핵심 결정만 정리한다.

### 2.1 소유 구조 — `AParkingPresetManager` 확장
- 신규 액터를 만들지 않고 기존 매니저를 확장. 매니저가 이미 면별 바닥 사각형을 계산하고, 위젯이 이미 매니저 1개를 스폰·`RefreshView`로 라우팅하기 때문.
- **디버그 경로(`RebuildAll`/`DrawPreset`)와 데칼 경로(`RebuildDecals`)를 메서드 단위로 완전 분리** → 상호 무영향(CLAUDE.md 3번 외과적 변경).

### 2.2 순수 기하 함수 추출
- `DrawPreset` 내부에 인라인되어 있던 면별 바닥 사각형 4점 계산을 `static ComputeSlotCorners(...)`로 **추출**하여 디버그·데칼 두 경로가 공유.
- 회전 시퀀스(면회전 `RotateZAround` → 위치이동 → 그룹회전 `RotateZAround`, `FaceHeightZ` 반영)를 **한 글자도 바꾸지 않고** 이동 → 디버그 라인/fill/3D 출력 결과 불변(회귀 방지).

### 2.3 데칼 지오메트리 (핵심)
UDecalComponent는 **로컬 -X 방향으로 투영**한다. 바닥(-Z)으로 투영하려면 로컬 +X를 월드 +Z(Up)로 맞춘다.

- 회전 구성(Euler 계산 회피):
  `Rot = FRotationMatrix::MakeFromXY(FVector::UpVector, dir).Rotator()`
  (로컬 X = Up → 투영 -X = 아래, 로컬 Y = 변 방향 `dir`, 로컬 Z = 수평 두께축)
- 라인 데칼 크기(half-extent):
  `DecalSize = ( DecalProjectionDepth/2, (len + T)/2, T/2 )`
  - X: 투영 깊이(바닥 도달), Y: 변 길이(+코너 보정 T), Z: 스트립 폭(두께 T)
  - **코너 겹침 처리**: 각 변 길이를 두께 T만큼 연장(`len + T`)하여 4모서리 교차부를 완전히 채움.
- 선택 슬롯 fill 데칼: 슬롯 half-extent 전체를 덮는 사각형 1개, 라인보다 아래 정렬(SortOrder), 흰 라인은 위에 유지.

### 2.4 데칼 풀 재사용
- 재빌드 시 데칼을 파괴/재생성하지 않고 **풀(`DecalPool`)에서 재사용**, 잉여는 `Visibility=false`로 숨김 → 누수 없음(QA T6과 일치).

### 2.5 단위 규약
- 두께 10cm = 10 UU → half-extent 5. 슬라이더 2~30cm → half 1~15.
- `DecalCenterZ`(5cm)에서 아래로 `DecalProjectionDepth`(50cm) 투영 → 바닥 메시(z≈0)에 안착.

## 4. 로직 상세

### 4.1 RebuildDecals 알고리즘
```
1. bEnable==false → ClearDecals(); return.
2. LineDecalMaterial null → 경고 로그 후 ClearDecals(); return.
3. cursor = 0
4. for each preset Pi:
5.   for face j in [0, Pi.FaceCount):
6.     ComputeSlotCorners(Pi, j, MetersToUU, FaceHeightZ, Bottom)
7.     if (i==SelectedIndex && SelectFillDecalMaterial):   // fill 먼저(라인 아래)
8.        PlaceFillDecal(Acquire(cursor++), Bottom)
9.     for k in 0..3:                                       // 4변 라인
10.       PlaceLineDecal(Acquire(cursor++), Bottom[k], Bottom[(k+1)%4], ThicknessCm)
11. for idx in [cursor, DecalPool.Num()): DecalPool[idx]->SetVisibility(false)  // 잉여 숨김
```
- 필요 데칼 수 = `Σ(4·FaceCount)` + `(선택 프리셋 FaceCount)`(fill).
- LineMat null이면 전체 스킵, 선택 있음 + FillMat null이면 1회 경고 후 fill만 생략(라인은 정상).

### 4.2 라인 데칼 1개 배치 (좌표/단위)
변 A→B(월드 cm, faceRot·groupRot 이미 반영됨):
```
mid = (A + B) * 0.5
dir = (B - A).GetSafeNormal2D()   // 변 방향(수평)
len = (B - A).Size2D()            // 변 길이(cm)
T   = ThicknessCm                 // 기본 10cm
Rot = FRotationMatrix::MakeFromXY(FVector::UpVector, dir).Rotator()
DecalSize = ( DecalProjectionDepth*0.5, (len + T)*0.5, T*0.5 )
D->SetWorldLocationAndRotation( FVector(mid.X, mid.Y, DecalCenterZ), Rot )
D->SetSortOrder(LineSortOrder); D->SetVisibility(true)
```

### 4.3 라인 두께 UI 연동
- `NativeConstruct`: `Slider_DecalLineThickness` Min=2/Max=30/Step=1/기본 10 설정, `OnValueChanged`를 `HandleDecalThicknessChanged`에, `Check_UseDecal`을 `HandleUseDecalChanged`에 바인딩(기존 R3 슬라이더 패턴 준수).
- `RefreshView` 말미:
  ```cpp
  Mgr->RebuildDecals(Presets, SelForView,
      Slider_DecalLineThickness ? Slider_DecalLineThickness->GetValue() : 10.f,
      Check_UseDecal ? Check_UseDecal->IsChecked() : false);
  ```
- `SelForView`는 기존 HideBar 정책 공유(체크 시 `INDEX_NONE` → fill 없음). 디버그·데칼이 선택표시 정책을 공유.
- 5개 위젯 모두 `BindWidgetOptional` → WBP 미갱신 상태에서도 컴파일·구동 정상. 미배치 시 폴백: 두께 10cm 고정 + 데칼 Off → 데칼 0개(디버그 라인 무영향).
