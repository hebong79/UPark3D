# CLAUDE.md 최소화와 변경 이력 이전 (`docs/claude-md-minimal`)

- 요청: 마스터 이 창 「claude.md를 최소화 해줘. 간단하게 꼭 필요한것만 정리하고 나머지는 제목만 리스트화해서 스킬이나 훅에 적절하게 배치해줘.」, 「최대 200줄이 안넘게 해줘.」, 「간단할수록 좋음 (100줄 이내이면 더욱 좋음)」
- 상태: 마스터 승인(이 창, 선택 「지금 머지·push」)으로 main 머지·push. 코드 변경이 없어 재빌드·교체·재기동은 없다.

## 1. 문제

CLAUDE.md 는 166줄이지만 한 행이 최대 3,592자라 약 204 KB 였다. 세션마다 통째로 읽혔고, 줄 수로는 크기가 드러나지 않았다.

## 2. 바꾼 것

| 항목 | 전 | 후 |
|---|---|---|
| `CLAUDE.md` | 166줄, 약 204 KB | 40줄대, 약 3 KB |
| 변경 이력 138행 | `CLAUDE.md` 표 | `.claude/skills/park3d-history/HISTORY.md`(그대로) |
| 제목 목록 | 없음 | `.claude/skills/park3d-history/SKILL.md`(주제별) |
| 강제 규칙 | 없음 | 훅 `~/.claude/hooks/park3d-guard.mjs` |

- 이력 행은 바꾸지 않았다. 스크립트로 옮긴 뒤 원본 138행과 같은지 비교했다. 제목은 그 행 안의 문자열이라 Grep 으로 찾아진다.
- 주제 분류는 키워드로 했다. 몇 건은 다른 주제로 갔을 수 있다. 전문 검색에는 영향이 없다.
- `park3d-ops-sonnet` 의 SKILL·PROCEDURE 에서 이력 위치를 고쳤다. 문서 전용 배포 기록의 예외 파일에 `.claude/skills/park3d-history/*` 를 더했다. 이력을 옮겼으니 이 파일도 함께 올라가야 한다.

## 3. 내용을 고친 곳

**축 규약 문구.** 옛 문구 `UE (x, z, y_up=Z)` 는 코드와 다르다. `UnityUnrealCoordinateConverter.cpp` 는 `FVector(Unity.Z, Unity.X, Unity.Y)` 다. 2026-10-04 이력에 이미 적혀 있었는데 문구를 안 고친 채였다. 새 문구는 코드를 따른다. `AGENTS.md` 에는 옛 문구가 남아 있다.

**재쿡 승인.** pm-ff 가 전한 마스터 말씀 「재패키징도 pm이 결정할수 있게 해줘. 물론 다른쪽이 쓰는지도 확인해주고.」을 마스터가 이 창에서 확인했다. 재쿡은 다른 쪽 사용을 확인한 뒤 담당 PM 이 명령하고, 머지·푸시만 마스터 승인으로 남겼다.

## 4. 훅

`~/.claude/hooks/park3d-guard.mjs` 를 UPark3D 본 폴더의 `.claude/settings.local.json` 에서 부른다.

- `PreToolUse` Bash·PowerShell: `git add -A`·`--all`·`.`, `--no-verify`, 강제 push 를 거부한다.
- `PostToolUse` Edit·Write: `CLAUDE.md` 가 200줄·한 줄 500자·전체 2만 자를 넘으면 Claude 에게 되돌린다. 옛 문제는 줄 수가 아니라 줄 길이였으므로 함께 본다.

`.claude/settings.json` 에 넣지 않은 이유: 마스터의 미커밋 변경이 있어 건드리면 안 되고, 커밋하면 본 폴더 머지가 그 파일 때문에 거부된다. `settings.local.json` 은 git 제외 파일이다. 그래서 **이 PC 의 본 폴더에서 시작한 세션에만 적용된다.** `.125`·`.8` 은 해당 없다.

위임 규칙(메인이 커밋하지 않기)은 훅으로 만들지 않았다. 서브에이전트와 메인을 가르는 입력값을 확인하지 않았고, 잘못 막으면 운영이 멈춘다.

## 5. 머지할 때

- `fix/agent-grid-spline-wall`, `fix/view-lookat-pitch`, `test/bike-rider-20261106` 은 옛 `CLAUDE.md` 표에 행을 더했다. 이 브랜치와 합치면 **`CLAUDE.md` 가 충돌한다.**
- 해결: `CLAUDE.md` 는 이 브랜치 것을 쓰고, 그 브랜치가 더한 행을 `HISTORY.md` 맨 위로, 제목을 `SKILL.md` 로 옮긴다.
- `.gitattributes` 에 `.claude/skills/park3d-history/*.md merge=union` 을 넣었다. 두 브랜치가 표 맨 위에 동시에 행을 넣어도 충돌하지 않고 둘 다 남는다.
- 지금 다른 작업 트리의 세션이 옛 규칙대로 `CLAUDE.md` 에 행을 쓰면 같은 일이 생긴다. 머지 뒤 PM 이 알려야 한다.

## 6. 검증

- 이력 행 비교 138/138 동일, 제목 138개 모두 해당 행 안의 문자열.
- 훅 파이프 시험 17건 통과(거부 9, 통과 8). 첫 정규식은 `echo git add -A` 를 막아 명령 시작 위치의 `git` 만 보게 고쳤다.
- 훅 실제 발동: `PreToolUse` 는 이 세션의 Bash 호출이 거부됐고, `PostToolUse` 는 538자 줄을 넣은 Edit 에 되돌림이 왔다(그 줄은 되돌림).
- 한계: `&&` 뒤에 오는 글자는 따옴표 안이어도 명령으로 본다. 위 Bash 거부도 시험 문자열 `'cd x && git add -A'` 때문이었다. 그런 명령은 파일로 빼서 돌린다.
- 한계: Bash 로 고친 `CLAUDE.md` 와 Sonnet 의 머지는 `PostToolUse` 검사를 지나지 않는다.
- 빌드·Automation 은 해당 없음(코드 변경 없음).

## 7. 안 고친 것
