- 방침: **C++ 전용(블루프린트 배제).** 루프에서 컴파일만 수동, 나머지는 MCP 자동.
- 산출물: `.claude/skills/parking-cpp-loop/SKILL.md` (신규 스킬), CLAUDE.md 변경이력, 오케스트레이터 위임 노트.

## 1. 왜 이렇게 셋팅했나 (실측 근거)
이 세션에서 MCP 능력을 직접 테스트한 결과:

| 능력 | MCP 자동화 | 근거 |
|------|:---------:|------|
| C++ 코드 수정 | ✅ | Read/Grep/Edit |
| PIE 시작·정지 | ✅ | `EditorAppToolset.StartPIE/StopPIE/IsPIERunning`(실증) |
| UI 상태 검증 | ✅ | SlateInspector Snapshot/WaitFor/Screenshot, LogsToolset, AutomationTestToolset |
| **C++ 컴파일 트리거** | ❌ | `PressKey Ctrl+Alt+F11` PIE on/off 모두 실패, 전용 build 도구 없음 |
| 게임 UMG 합성 클릭 | ❌ | `Click`은 포커스만, `OnClicked` 미발화 |

→ **유일한 병목은 컴파일**. 그래서 컴파일만 사람이 하고 나머지는 자동으로 도는 루프로 설계.

## 2. 셋팅한 것
- **신규 스킬 `parking-cpp-loop`**: C++ 전용 자율 루프 실행기. "수동 컴파일 게이트" 프로토콜을 규약으로 고정.
- **오케스트레이터 연동**: `parking-dev-orchestrator` Phase 0에 "Loop형 요청 → parking-cpp-loop 위임" 추가.
- **CLAUDE.md 변경이력**: 2026-07-07 행 추가.
- **메모리 갱신**: `mcp-pie-start-crash`(네이티브 StartPIE 정상), 신규 `slateinspector-pie-umg-click-limit`.

## 3. 루프 동작 (반복 단위)
```
[1] AUTO  설계/재설계 (실패 시 원인 분석 후 수정 설계)
[2] AUTO  C++ 수정 + (필요 시)Automation 테스트 작성
[3] AUTO  (선택) 외부 UBT로 문법 에러 선검출 → 있으면 사람 안 부르고 [1]로
[4] MANUAL 컴파일 게이트 ← 유일한 사람 개입 (Ctrl+Alt+F11 → "완료")
[5] AUTO  IsPIERunning 확인 → StopPIE→StartPIE 재기동
[6] AUTO  검증 (Automation 테스트 결과 or Snapshot 상태 카운트/로그)
[7] AUTO  성공→[8] / 실패→근거 기록 후 [1] 자동 재개 (동일 실패 3회 시 중단·보고)
[8] AUTO  보고 + Docs 문서화 + 영향도 분석
```
- 컴파일 성공은 사용자 '완료' 후 `LogLiveCoding` 로그로 교차 확인.

## 4. 사용법
사용자가 아래 형식으로 주고 "루프 돌려줘/자동으로 반복해줘"라고 요청하면 `parking-cpp-loop`가 실행된다.
```
Goal: <최종 목표>
Loop:
  * <수정> * <컴파일> * <동작 트리거> * <검증> * <실패 시 재설계> * <성공 시 보고>
Requirements:
  * <검증 가능한 성공 기준들>
```
- 검증 수단은 **C++ Automation 테스트 우선**(클릭·PIE 불필요, 헤드리스), 실 UI 확인이 꼭 필요하면 PIE+Snapshot.
- 매 반복 사람이 하는 일은 **Ctrl+Alt+F11 후 "완료"** 한 번뿐.

## 5. 컴파일까지 완전 무인으로 가려면(참고, 현재 방침 밖)
- 에디터 종료→외부 UBT 빌드→재실행→MCP 재연결: 완전 무인이나 반복당 수분·재연결 리스크.
- Live Coding 끄고 레거시 Hot Reload + 외부 빌드: 에디터 유지·무인이나 레거시라 불안정.
- (블루프린트 이관은 방침상 배제.)
→ 현재는 **"컴파일 1회 수동"이 가장 안정적**이라 이 방식으로 셋팅함.
