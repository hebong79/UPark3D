# git pull 에러 해결 + SDF 번호판 수신 PC 배포 (2026-08-27)

이 PC(`D:\Work2\Unreal2\UPark3D`)에서 `git pull` 이 실패했다. 원인을 잡고, 이어서 들어온
**번호판 SDF 양각 전환**을 이 PC 에 실제로 적용·빌드·실행 검증까지 마쳤다.

---

## 1. git pull 에러

```
error: Your local changes to the following files would be overwritten by merge:
        Park3D/Save/Config/config_pmaker.json
Please commit your changes or stash them before you merge.
Aborting
Updating a8c5d91..9b61b29
```

충돌(conflict)이 아니라 **사전 차단**이다. fast-forward 로 들어올 5커밋 중
`5950439 chore(config): 스트림 총 fps 예산 5.0 → 20.0` 이 `config_pmaker.json` 을 건드리는데,
같은 파일에 커밋 안 된 로컬 수정이 있어 git 이 손대기를 거부했다.

### 판정 — 버릴 것이 있는지부터 본다

로컬 수정과 원격이 가져올 내용이 **바이트 단위로 동일**했다. 둘 다 `stream_total_fps: 5.0 → 20.0`.

```bash
git show origin/main:Park3D/Save/Config/config_pmaker.json > /tmp/cfg_origin.json
git diff --no-index /tmp/cfg_origin.json Park3D/Save/Config/config_pmaker.json   # 차이 0
```

**이 확인 없이 `git checkout --` 을 치면 안 된다.** 같은 값을 나와 원격이 각각 손댄 경우에만
버려도 무해하고, 값이 다르면 stash 하거나 커밋해서 병합 대상으로 올려야 한다.

```bash
git checkout -- Park3D/Save/Config/config_pmaker.json
git pull                                              # a8c5d91..9b61b29, 5커밋
```

결과 config: `stream_slots 30 / stream_hard_max_slots 30 / stream_total_fps 20.0` (로컬 의도 그대로).

## 2. 받은 내용 — 코드만 와서는 화면이 안 바뀐다

5커밋의 핵심은 **번호판 양각을 Text3D 압출 → SDF 텍스처+머티리얼 릴리프로 전환**한 것이다
(`e207a4a`). `Park3D.uproject` 에서 Text3D 플러그인이 빠졌고 `CarActor.*` 가 크게 줄었으며
`Plate/PlateGlyphAtlas.*` 가 신설됐다. 상세는
[20260827_180238_번호판_양각_SDF_머티리얼_전환_구현.md](20260827_180238_번호판_양각_SDF_머티리얼_전환_구현.md).

수신 PC 가 할 일은 `ContentDelivery/README.md` 에 적힌 3단계다.

| 단계 | 명령 | 왜 필요한가 |
|------|------|-------------|
| 1 | `git pull` | 소스 · 아틀라스(`Save/Config/plate_glyph_sdf.png`) · 메트릭 · 툴 |
| 2 | `python ContentDelivery/apply.py --write` | 머티리얼 `M_PlateFront.uasset` — `.gitignore:35` 가 `Park3D/Content/` 를 통째로 제외(SVN 이 정본)해서 **git 으로는 절대 안 온다** |
| 3 | `BuildPackage.bat` | 플러그인 구성이 바뀌어 **exe 교체로는 안 되고** C++ 빌드 + 전체 재쿡이 필요 |

2단계를 빠뜨려도 **깨지지 않고 조용히 옛 평면 위젯으로 폴백**한다. 그래서 화면만 봐서는
"업데이트가 안 왔나?" 로 오해하기 쉽다 — 판정은 로그로 한다(5장).

## 3. 함정 — `make_manifest.py` 의 `**다름**` 은 받는 PC 에서 의미가 뒤집힌다

`ContentDelivery/README.md` 는 이렇게 적고 있다.

> `**다름**` 이 뜨면 이 배달본이 낡은 것이다 — SVN 쪽을 확인하고 다시 담아라.

이 문장은 **배달본을 만든 PC 기준**이다. 그 PC 에서는 로컬 `Park3D/Content` 가 정본이므로
불일치 = 배달본이 낡음이 맞다. 그런데 **받는 PC 에서는 로컬 `Park3D/Content` 가 구본**이라
불일치가 곧 "덮어써야 한다"는 신호다. 문서대로 읽고 적용을 건너뛰면 2단계를 통째로 빼먹는다.

이번에도 `**다름**` 이 떴고, 방향은 해시·크기·시각으로 갈랐다.

```
43a540ae6d769492  37166 B  2026-08-27 23:42  ContentDelivery/.../M_PlateFront.uasset   ← 신규(SDF, Custom HLSL 노드 포함)
25de77b5935904c0  20029 B  2026-08-10 02:34  Park3D/Content/.../M_PlateFront.uasset    ← 구본
```

**판정 기준: 크기와 시각. 배달본이 크고 새것이면 받는 쪽이다.** 적용 후 로컬 해시가

## 5. 실행 검증

기동 로그가 곧 판정이다.

```
[PlateSDF] 아틀라스 1536x2048 글리프=44 셀=256 폰트=166 (.../Save/Config/plate_glyph_metrics.json)
[PlateSDF] '455가 5639' 합성: 글자 8개, 배율 가로0.8396 세로1.1655, 캡 162.5texel(≈6.98cm), 밉 11단
[CarPlate] SDF id=0-16.25.24 number=455가5639 판=52.10x11.00cm rt=있음 front=1 back=1 폴백위젯=0/0
```

**차량 23대 전부 `front=1 back=1` · `폴백위젯=0/0`** — 폴백 0건. 머티리얼이 안 왔다면
`front=0 back=0 폴백위젯=1/1` 이 떴을 것이다.

화면으로도 확인했다. 메인 뷰를 앞 번호판(`world (21.379, 5.245, 0.542) m`)에 붙여 찍으니
`455가 5639` 가 글자 가장자리 모따기 하이라이트 + 접지 그림자와 함께 양각으로 읽힌다.

**캡처 방법 메모** — `cam.captureJPG` 는 인자 없이 부르면 **메인 뷰가 아니라 CCTV 카메라
(camId=1)** 를 찍는다. 내가 맞춘 메인 뷰를 보려면 `view.get` 의 `streamPort`(13600) MJPEG 에서
한 프레임을 떠 오는 편이 낫다 — 인스턴스 상태를 전혀 안 건드린다.

```python
r = urllib.request.urlopen('http://localhost:13600', timeout=10)   # multipart/x-mixed-replace
# 버퍼에서 FFD8 ~ FFD9 한 쌍을 잘라내면 그것이 1프레임
```

`view.*` 좌표는 **미터**다(로그의 plate world 는 cm) — 100 으로 나눠 넣는다. 검증 뒤
`view.set` 으로 원래 값(`pos (-15,0,15) · pitch -45 · fov 72.734`)을 그대로 복원했다.
