## 1. 증상

> 처음 시작 시에는 (마우스가) 부드럽게 움직였다. 마우스 클릭 후부터는 마우스 드래그로 동작하지 않음.

- 버튼을 안 누른 상태: OS 하드웨어 커서(NoCapture)가 부드럽게 이동(이전 fix 정상).
- **빈 바닥을 클릭한 순간부터 드래그가 먹지 않음**(커서가 사라지거나 멈춘 듯 보임).

---

## 2. 원인

- `Park3DGameMode::BeginPlay()`는 `FInputModeGameAndUI`로 입력 모드를 설정한다.
- `FInputModeGameAndUI`의 `bHideCursorDuringCapture` **기본값은 true**.
- GameAndUI 모드에서 **위젯이 없는 영역(바닥)을 클릭-드래그하면** 게임 뷰포트가 마우스를 캡처하고, 이때 커서가 **숨겨진다**. 그 사이 마우스 이동은 폰(DefaultPawn)의 마우스룩으로 전달된다.
- 결과적으로 "클릭 후 드래그가 안 먹는" 것처럼 보였다. (커서 부드러움 문제가 아니라 **캡처 시 커서 숨김** 문제)
- 평소 앱에서는 화면 대부분을 UI 위젯이 덮어 위젯을 클릭하므로 잘 드러나지 않았으나, "Offset Pick 월드 클릭"처럼 바닥을 클릭하는 경로에선 영향이 있었다.

> 참고: 직전 검증에서 쓴 임시 테스트 GameMode는 `GameModeBase`(기본 **GameOnly**)였어서 캡처가 더 강하게 일어났다. 즉 증상의 일부는 테스트 셋업 차이였고, 근본 동작은 위 GameAndUI 캡처 기본값에서 비롯된다.

---

## 3. 수정 내용

요구 동작(사용자 선택): **커서는 유지, 카메라 회전은 허용**. → 최소 1줄 수정.

`Park3D/Source/Park3D/Park3DGameMode.cpp` `BeginPlay()`:

```cpp
FInputModeGameAndUI InputMode;
InputMode.SetWidgetToFocus(PresetWidget->TakeWidget());
InputMode.SetLockMouseToViewportBehavior(EMouseLockMode::DoNotLock);
// 빈 뷰포트(바닥)를 클릭-드래그하는 동안에도 커서를 숨기지 않음.
// (기본값 true면 클릭 후 드래그 시 커서가 사라져 "마우스가 안 먹는" 것처럼 보임)
InputMode.SetHideCursorDuringCapture(false);   // ← 추가
PC->SetInputMode(InputMode);
```

- 효과: 클릭-드래그 중에도 커서가 보이고 동작한다. 카메라 회전(DefaultPawn 마우스룩)은 그대로 허용된다.

## 5. 영향도 분석

- **C++/어셈블리**: `Park3DGameMode.cpp` 1줄 추가. 재빌드 1회(완료, 성공). 다른 모듈 의존성 변화 없음(`UMG`/`Engine` 기존 사용 범위 내).
- **정상 앱 동작**: 입력 모드만 `HideCursorDuringCapture=false`로 바뀜. UI 패널 드래그·버튼·JSON·3D 뷰는 GameAndUI 유지로 그대로 동작. 변경은 **클릭-드래그 시 커서 가시성**에만 영향.
- **카메라**: 사용자가 카메라 회전을 허용했으므로 DefaultPawn 마우스룩은 유지. (만약 카메라 고정을 원하면 후속으로 폰 마우스룩 제거 필요 — 이번 범위 아님.)
- **설정/맵**: `DefaultEngine.ini`, `DefaultInput.ini`, `PresetEditor.umap` 무변경. NoCapture/DoNotLock/NoSmoothing fix 유지.
- **임시 테스트 자산**: `/Game/_Test/`의 `BP_FloorTestGM`(재구성), `WBP_Empty`(신규), `BP_FloorTestPC`(이제 미사용). 어느 맵 World Settings에도 연결되지 않아 정상 실행에 영향 없음. 불필요 시 `/Game/_Test` 폴더 삭제로 정리 가능.

## 6. 결과 요약

- ✅ 원인 규명: GameAndUI의 `bHideCursorDuringCapture=true` 기본값 → 바닥 클릭-드래그 시 커서 숨김.
- ✅ 수정: `SetHideCursorDuringCapture(false)` 1줄 추가, 빌드 성공.
- ✅ 검증: 바닥만 출력되는 standalone에서 수정된 BeginPlay 실행 확인(로그/스크린샷), 에러 없음.
- ⏳ 클릭-드래그 커서 유지의 최종 체감은 실행 중 창에서 사용자가 확인.
