## 2. 구조

| 파일 | 역할 |

| `Sim/ParkManeuverPlanner.*` (신규) | UObject 없는 계획기. 뒷축 기준 자전거 모델, 최종 자세에서 역적분, 기동 가족별 파라미터 탐색 + 경로 전 구간 간격 검사, Dubins(전진 최단). 로컬 프레임(+X 진행, +Y 면 쪽)과 거울상 변환 `FLotFrame` |

### 판정 규칙
- **유형**: 가장 가까운 이웃 면 쪽 = 열 방향. 면 긴 변과의 |cos| ≥ 0.9 → 도로변, ≤ cos75° → 정형, 그 사이 → 사선. `lot_type` 로 강제 가능.
- **통로 쪽**: 면 바로 앞이 다른 면이면 탈락, 맞은편 면 줄이 보이면 가점, 입구 쪽이면 가점.
- **통로 폭**: config `sim_aisle_m` > 맞은편 줄까지 실측 > 기본(정형 6.0, 사선 5.5). 가정 폭일 때만 맞은편 끝을 벽으로 둔다.
- **같은 줄**: 같은 유형·열 방향·통로 쪽 + 열 선 1.5 m 이내(T자로 만나는 줄을 묶지 않는다).
- **진행 방향**: 도로변·정형 = 입구 쪽에서 들어오는 방향, 사선 = 기울기 방향(일방통행). 도로변 자동 게이트는 면이 오른쪽(우측통행).
- **간격 기준**: 0.25 m. 차체 폭은 메시 바운즈 × 0.85(사이드미러 제외 — 캐스퍼 1.87→1.59, SM7 2.25→1.91). 연석은 0.2 m 여유(차체가 연석 위로 넘어가도 된다).
- **방식 대체**: 요청 방식으로 간격을 못 지키면 다른 방식으로 바꾸고 `note` 에 사유. `strictMode:true` 면 대체하지 않고 실패.
- **자동 게이트(정형·사선)**: 입구·출구가 미지정이면 Dubins 로 주차된 차를 가로지르지 않도록 **통로 끝에서 출발/끝**. 지정 게이트에서 오는 연결 구간은 차량 간격(`transitClearanceM`)을 재고 기준 미달이면 `note` 로 경고.

## 3. RPC

| 메서드 | 요약 |
|---|---|
| `sim.start` | `{faceKey? | number? | presetId+slotIndex?, dir?, parkMode?, strictMode?, seed?, prefabId?|prefabName?, withPlan?=true}` → `{runId, lotType, parkMode, maneuver, clearanceM, gearChanges, pathLengthM, faceKey, slotNumber, note, entrance, exit, plan}` |
| `sim.exit` / `sim.scenario` | 같은 면 지정. 출차는 서 있는 차를 먼저 인수 |
| `sim.plan` | 계획만(주행 없음). `debug:true` 면 실패해도 `{ok:false, error, plan(가장 나은 후보)}` |
| `sim.slots` | 면 목록 `{number, faceKey, source, lotType, angleDeg, center, axisYaw, rowYaw, aisleYaw, lengthM, widthM, aisleWidthM, occupied, carNameId}` + 게이트 |
| `sim.gates` / `sim.setGates` | 입구·출구 조회 / 이 레벨에 한해 지정(`reset:true`), 저장 안 함 |
| `sim.status` | `currentSegment·gear·currentLabel` 추가, `withPlan:true` 로 경로 |
| `sim.entrance` | 이제 주행을 만들지 않는다(게이트 계산만), `exit`·`gates` 추가 |

`plan` = `{ok, lotType, maneuver, clearanceM, closest, transitClearanceM, usedGate, gearChanges, lengthM, note, carLengthM, carWidthM, minTurnRadiusM, segments[{index, gear:D|R, kind:arc|straight, steer:left|right|center, lengthM, curvature, radiusM?, angleDeg?, transit, label}], polyline[{x,y,yaw,gear,seg}]}` — polyline 은 차체 중심, 0.5 m 간격, UE 미터.

## 4. 검증
- 빌드: Park3DEditor · Park3D 통과.
- Automation **143/143**(신규 `Park3D.Sim.Planner.{Dubins,Enter,Exit,Frame}`, `Park3D.AppConfig.SimGates`).
- `-game -RenderOffscreen` 13530(에디터 바이너리): 객리단 8번 입·출차, 서신 12(전진)·21(후진) 입차와 출차, 서신 바깥에 만든 사선 시험 면(preset `faceRot:30`) 3(전진)·6(후진) 입차와 출차 — 캡처 5장.
- **미검증**
  - 패키지 빌드(유니티 빌드 충돌 확인): 사용자 에디터가 켜져 있어 Live Coding 이 UBT 를 거부. 새 함수는 전부 접두사를 붙였다.
  - 실제 사선 레벨: config `levels[]` 에 없음. 사선은 서신 바깥 차도 위 시험 면으로만 확인했다. 그 자리에서는 보도 건너편 줄까지를 통로 폭(5.43 m)으로 재서 후진 셋업 때 차가 보도로 넘어갔다. 보도·벽은 레벨 데이터에 없으므로 실제 사선 주차장은 `sim_aisle_m` 을 지정할 것.
  - 서신 입구: 자동(통로 끝 출발). 실제 입구를 config 로 주면 Dubins 연결 구간이 생긴다.

## 5. 가정과 함정
- **객리단 진행 방향**: 차선규제봉(도로 중앙, 면 줄에서 약 8.3 m)과 카메라 폴대(보도) 위치로 도로 쪽을 판정하고, 우측통행(면이 오른쪽)으로 14번 → 1번(−107.91°)을 택했다. 기존 배치 차량은 대부분 72.09° 를 보고 있어 반대일 수 있다 — `sim_entrance/sim_exit` 를 뒤집으면 된다.
- **3번 면(서신, 통로 4.78 m)** 은 대형차(SM7·카니발) 전진·후진 모두 간격 부족 — 물리적으로 맞는 결과. 중형(쏘렌토·K5)은 후진으로 들어간다. 정형 전진은 통로가 좁으면 자주 후진으로 대체된다.
- **엔진 전역 `FPoly`** 와 이름이 겹쳐 계획기 다각형은 `FPoly2D`.
- **오프스크린 시험 인스턴스는 RPC 한 건에 약 2초**(틱당 처리, GPU 타임아웃 경고) — 계획 시간 측정은 단위 테스트(11~300 ms)로 했다.
- `preset.create` 의 `offset.z` 는 면 높이로도 쓰여 `car.placeAtWorld` 스냅 차량이 지하 −20 m 에 놓였다(시험 설정 실수, 코드 무수정).
