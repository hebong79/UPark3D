# RPC 외부 연결 실패 — 포트에 박힌 바인드 override 가 포트 변경으로 빗나갔다

- 작성: 2026-08-17 11:28
- 증상 신고: SettingAgent 장비 설정에서 `연결 실패 · 5000ms · Park3D RPC 통신 실패
  (http://192.168.0.10:13520/rpc cam.getPTZ): The operation was aborted due to timeout`
- 대상: `Park3D/Config/DefaultEngine.ini`, `Park3D/Config/DefaultGame.ini`, `.mcp.json`,
  `Park3D/Save/Config/config_pmaker.json`

## 1. 무엇이 원인이었나

**RPC 만 루프백에 바인드돼 있었다.** 방화벽·인증·앱 미기동 어느 것도 아니다.

| 대상 | 결과 |
|------|------|
| `http://127.0.0.1:13520/rpc` | 200 |
| `http://192.168.0.10:13520/rpc` | 연결 거부 |

listen 상태가 갈라져 있었다 — RPC 는 `127.0.0.1:13520`, 영상은 `0.0.0.0:13600/13611/13612`.
**영상 URL 은 되는데 제어 URL 만 안 되는** 모습이 여기서 나온다(영상은 자체 소켓이라 엔진 HTTP 서버 설정과 무관).

기동 로그 한 줄에 답이 있었다.

```
[RPC] 리슨 포트 결정: 13520
[RPC] JSON-RPC 서버 시작: http://localhost:13520/rpc (bind=localhost, auth=ANONYMOUS(우회), method 116개)
```

`bind=localhost` 인 이유: 외부 바인드 지정이 **포트에 박혀 있었다.**

```ini
[HTTPServer.Listeners]
+ListenerOverrides=(Port=13510,BindAddress=any)
```

그런데 `Save/Config/config_pmaker.json` 의 `rpc_port` 가 **13520** 으로 바뀌면서 이 목록이 빗나갔고,
엔진 기본값(`localhost`)으로 **조용히** 폴백했다. 실패를 알리는 로그도, 에러도 없다.

같은 파일의 주석이 이미 이 사고를 예고하고 있었다 — *"포트와 결합된다: -RpcPort= 로 다른 포트를 쓰면
이 override 가 매칭되지 않아 조용히 localhost 로 폴백한다"*. 경고가 있었어도 포트를 바꾼 쪽
(`config_pmaker.json`)과 바인드를 여는 쪽(`DefaultEngine.ini`)이 **다른 파일**이라 함께 움직이지 않았다.

## 2. 포트 결정 순서

사고 당시에는 ini·config·커맨드라인 셋이 경쟁했다. **지금은 config 한 곳이다**(§4-c):

1. 소스 기본값 — `URpcServerSubsystem::Port = 13510`
2. `Save/Config/config_pmaker.json` 의 `rpc_port` ← **정본**
3. 커맨드라인 `-RpcPort=`(자동화용 일회성. `0` 이면 서버 미기동)

## 3. 조치 (13520 을 정본으로)

| 파일 | 변경 |
|------|------|
| `Park3D/Config/DefaultEngine.ini` | `+ListenerOverrides=(Port=13520,BindAddress=any)` 추가(13510 도 유지) + 사고 경위 주석 |
| `Park3D/Config/DefaultGame.ini` | `[RpcServer] Port` 13510 → 13520 (폴백까지 일치) |
| `.mcp.json` | `PARK3D_RPC_URL` 13510 → 13520 |
| `Park3D/Save/Config/config_pmaker.json` | `rpc_port` 13520 (이미 바뀌어 있던 값을 이제 저장소에 반영) |

전역 `DefaultBindAddress=any` 는 쓰지 않는다 — 이 프로세스의 **모든** HTTP 리스너(현재·미래)가 상속으로
외부에 열리고, 그런 리스너에는 우리 인증 게이트가 없다. 포트별 override 를 유지한다.

## 4. 검증(실측)

```
[RPC] JSON-RPC 서버 시작: http://0.0.0.0:13520/rpc (bind=any, auth=ANONYMOUS(우회), method 116개)
LocalAddress 0.0.0.0  LocalPort 13520
```

신고와 같은 메서드로 확인:

| 대상 | 결과 |
|------|------|
| `POST http://127.0.0.1:13520/rpc cam.getPTZ` | 200 (`pan 19.80 / tilt 8.70`) |
| `POST http://192.168.0.10:13520/rpc cam.getPTZ` | **200** (동일) |

## 4-b. 후속 조치 — 포트를 소스에서 빼고 config 로 옮겼다 (같은 날 오후)

§3 의 조치는 "13520 을 정본으로" 였는데, 실제 운용은 그 반대다 — **정본은 13510 이고 13520 은 한 PC 에서
시뮬레이터를 두 대 띄울 때 쓰는 두 번째 자리**다. 그래서 포트를 소스·ini 에 박는 방식 자체를 걷어냈다.

| 파일 | 지금 |
|------|------|
| `DefaultGame.ini [RpcServer] Port` | **13510** — 정본 기본값. 소스는 이 값만 안다 |
| `Save/Config/config_pmaker.json` | 이 PC 가 실제로 쓰는 값(`rpc_port: 13520`). ini 를 이긴다 |
| `DefaultEngine.ini [HTTPServer.Listeners]` | **포트를 적지 않는다.** 서버가 기동 시 자기 포트로 등록한다 |

핵심은 `URpcServerSubsystem::EnsureListenerBindOverride()` 다. 리스너를 잡기 직전에
"내가 쓸 포트에 대한 override 가 있나?" 를 보고, 없으면 만들어 넣는다.

```cpp
Overrides.Add(FString::Printf(TEXT("(Port=%d,BindAddress=%s)"), Port, *Bind));
GConfig->SetArray(TEXT("HTTPServer.Listeners"), TEXT("ListenerOverrides"), Overrides, GEngineIni);
FCoreDelegates::TSOnConfigSectionsChanged().Broadcast(GEngineIni, { ... });  // 엔진 캐시를 다시 읽게
```

엔진은 이 목록을 캐시하고 "설정 섹션이 바뀌었다"는 신호에만 다시 읽으므로(`HttpServerConfig.cpp`,
`bListenersCacheDirty`) 신호를 직접 준다. ini 에 같은 포트 항목이 이미 있으면 손대지 않는다 — 수동 지정이 이긴다.

바인드 값은 config 의 `"rpc_bind"` 로 바꾼다(기본 `any`, 루프백 전용은 `"localhost"`).

### 함께 넣은 것

- **`main_port`** (config) — 메인 뷰 MJPEG 포트가 ini 전용이라 두 번째 인스턴스가 13600 을 뺏을 수밖에 없었다.
  이제 config 로 덮는다. 카메라 대역(`cam_port_min/max`)은 원래부터 config 우선이었다.
- **두 대 띄우는 규칙**: 제어 포트는 인스턴스마다 **+10**, 영상 포트는 **+100**.
  sim1 = 13510 / 13600 / 13611–13650, sim2 = 13520 / 13700 / 13711–13750.
  두 번째 인스턴스는 **config 파일 하나만** 바꾸면 된다(소스·ini 불변).

### rpc-mcp 브리지도 config 로 (v1.1.0)

- 인스턴스 목록을 `park3d-rpc-mcp/instances.json` 에서 읽는다. 소스에 포트를 두지 않는다.
- `park3d_rpc({sim:"sim2", ...})` 로 대상을 고르고, 응답의 `target` 이 실제로 간 곳을 알려 준다.
- `park3d_instances` 로 목록과 기동 여부(`/health`)를 본다.
- 브리지 자신의 http 리슨 포트 기본값을 **13520 → 13540** 으로 옮겼다 — 시뮬 2 의 제어 포트와 정면 충돌이었다.
- `.mcp.json` 이 가리키던 `D:/Work/UnrealWork/Parking/park3d-rpc-mcp/dist/server.js` 는 **이 PC 에 없다.**
  그동안 이 MCP 서버는 뜨지 못했다 → 저장소 안의 `./park3d-rpc-mcp/dist/server.js` 로 고쳤다.

### 검증(실측)

```
[RPC] 리슨 포트 결정: 13520                                   ← ini 는 13510, config 가 이김
[RPC] 바인드 override 등록: Port=13520 BindAddress=any (출처: 기본값)
[RPC] JSON-RPC 서버 시작: http://0.0.0.0:13520/rpc (bind=any, ...)
[CamStream] 포트 대역 13611~13650 (출처: config_pmaker.json, 최대 40대)
```

`cam.getPTZ` → `127.0.0.1:13520` **200**, `192.168.0.10:13520` **200**.

## 4-c. 포트가 사는 곳을 한 곳으로 (ini 에서 완전히 제거)

§4-b 까지도 포트는 ini(기본값)와 config(실제값) 두 곳에 있었다. 질문이 나왔다 — "둘 중 하나에만 두면 어떤가?"
**답은 config 다.** 취향이 아니라 사실에서 나온다:

```
Package/Windows/Park3D/Config/DefaultGame.ini   ← 없다
Package/Windows/Save/Config/config_pmaker.json  ← 있다(평범한 텍스트 파일)
```

ini 는 빌드 시 바이너리 설정으로 구워져 **패키지에는 파일 자체가 없다.** 거기 적힌 포트는 재패키지 없이는
못 바꾸는데, 화면에는 그 값이 적혀 있으니 "ini 는 13510 인데 왜 13520 으로 뜨지"가 된다 — 이번 사고의 씨앗이
정확히 그 이중화였다. 카메라 대역은 원래부터 config 가 정본이라, 제어 포트만 ini 에 두면 규칙도 둘로 갈라진다.

| 항목 | 어디에 |
|------|--------|
| `rpc_port` · `main_port` · `cam_port_min/max` | **`Save/Config/config_pmaker.json` 한 곳** |
| 소스 기본값(13510 / 13600 / 13601~) | C++ 멤버 초기값. config 가 없을 때만 쓰인다 |
| 일회성 예외 | 커맨드라인 `-RpcPort=` (자동화용, `0` = 서버 미기동) |

- `DefaultGame.ini` 에서 `Port=` · `BasePort=` · `MaxCameras=` · `MainPort=` 를 지우고, 그 자리에
  "포트는 여기 없다 → config_pmaker.json" 을 못 박았다. **ini 를 읽던 코드도 없앴다** — 숨은 세 번째 출처를
  남기지 않기 위해서다.
- 기동 로그가 출처를 함께 찍는다. 포트가 예상과 다를 때 어느 파일을 열지가 이 한 줄로 끝난다:

```
[RPC] 리슨 포트 결정: 13520 (출처: config_pmaker.json rpc_port)
[RPC] 바인드 override 등록: Port=13520 BindAddress=any (출처: 기본값)
[RPC] JSON-RPC 서버 시작: http://0.0.0.0:13520/rpc (bind=any, ...)
[CamStream] 포트 대역 13611~13650 (출처: config_pmaker.json, 최대 40대)
[CamStream] 메인 뷰 채널 기동: http://<IP>:13600/
```

`cam.getPTZ` → `192.168.0.10:13520` **200**.

## 5. 다음에 포트를 바꿀 때

§4-b 이후로는 **`config_pmaker.json` 하나만 고치면 된다** — 바인드는 서버가 따라온다.
그래도 확인은 기동 로그 한 줄로 한다: `[RPC] JSON-RPC 서버 시작: ... (bind=any|localhost ...)`.
`bind=localhost` 면 외부에서는 어떤 방화벽 설정으로도 붙지 않는다.

브리지 쪽은 `park3d-rpc-mcp/instances.json` 의 포트를 같이 맞추고, `park3d_instances` 로 확인한다.

## 6. 별건으로 남기는 관찰

신고 화면의 영상 URL 이 `http://192.168.0.10:13611/stream` 인데, 같은 화면의 안내가
"camId 1 의 영상 포트는 13601 입니다 — 지금 13611 는 다른 카메라를 봅니다" 라고 말한다
(영상 포트 = 13600 + camId). 이번 연결 실패의 원인은 아니지만, 그대로 두면 **다른 카메라 화면**을 보게 된다.
