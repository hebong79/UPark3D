# 레벨별 차량·카메라 데이터 파일을 어디에 적을 것인가

- 일시: 2026-09-05 22:19
- 종류: 질문 답변(코드 변경 없음)
- 질문: 레벨을 바꿀 때 `config_pmaker.json` 의 `carpos_file`·`camerapos_file` 을 그 레벨에 맞게 바꿔야 한다. config 에 JSON 파일들을 레벨 단위로 저장하는 게 맞나, 더 좋은 방법이 있나?

## 결론

**레벨 → 데이터 파일 매핑은 지금처럼 `config_pmaker.json` 의 `levels[]` 에 두는 것이 맞다.** 이 구조는 2026-09-04 주차장 선택 콤보 작업 때 이미 들어갔고(`Park3DAppConfig.cpp:250` `ApplyLevelOverrides`), 실제로 `LV_Park_03` 진입 시 객리단 파일로 바뀐다. 바꿔야 할 것은 구조가 아니라 **최상위 `*_file` 의 역할이 애매한 점** 하나다.

## 지금 상태와 숨은 결합

```jsonc
"level": "Levels/LV_Park_01",
"levels": [
  { "name": "서신지구대", "level": "Levels/LV_Park_01" },                       // ← 파일 없음
  { "name": "객리단길",   "level": "Levels/LV_Park_03", "carpos_file": "...객리단.json", "camerapos_file": "...객리단.json" }
],
"carpos_file":    "CarPos_Seoshin_2Cam.json",   // ← 사실상 서신 파일
"camerapos_file": "CamPos_Seosin.json"
```

동작 규칙(`Park3DGameMode.cpp:455-462`): 현재 레벨이 `levels[]` 에 있고 그 항목에 키가 있으면 최상위를 덮고, 키가 없으면 최상위 값을 그대로 쓴다.

문제는 **서신 항목이 파일을 안 적어 최상위 값에 기대고 있고, 최상위 값이 우연히 서신 파일**이라는 점이다. 이 결합 때문에:

- `levels[]` 에 세 번째 주차장을 파일 없이 추가하면 → 서신 차량 23대가 그 주차장 위에 얹힌다(2026-09-04 항목에서 이미 겪은 증상).
- 최상위 `level` 을 다른 레벨로 바꾸면서 최상위 파일을 안 고치면 → 같은 증상.
- 최상위 `*_file` 이 "기본값"인지 "서신 것"인지 읽는 사람이 알 수 없다.

## 권장: 최상위는 폴백, 주차장마다 명시

```jsonc
"level": "Levels/LV_Park_01",
"levels": [
  { "name": "서신지구대", "level": "Levels/LV_Park_01", "preset_file": "", "carpos_file": "CarPos_Seoshin_2Cam.json", "camerapos_file": "CamPos_Seosin.json" },
  { "name": "객리단길",   "level": "Levels/LV_Park_03", "preset_file": "", "carpos_file": "CarPos_13Num.객리단.json", "camerapos_file": "CamPos_13Face.객리단.json" }
],
"preset_file": "", "carpos_file": "", "camerapos_file": ""   // levels[] 에 없는 레벨용 폴백(비워 두면 자동 로딩 없음)
```

- **코드 변경 0.** `ApplyLevelOverrides` 와 `ApplyToPanel` 의 "빈 문자열은 조용히 건너뜀"(`Park3DGameMode.cpp:498`) 규칙이 그대로 이 의미를 만든다.
- 주차장 하나의 정보가 한 줄에 다 모인다(이름·레벨·데이터 3종). 새 주차장은 줄 하나 추가.
- 최상위가 비어 있으면 "파일 빠뜨림"이 **차량 0대**로 드러난다. 지금은 남의 차량이 얹혀 "배치가 이상하다"로 드러나 원인 찾기가 더 오래 걸린다.
- 데이터 파일 자체는 지금처럼 `Save/3D/CarPos/`·`Save/3D/CameraPos/` 평면 폴더에 두고 이름에 주차장을 넣는 관례(`_서신`·`.객리단`·`(익산)`)만 지키면 된다.

## 검토했지만 권하지 않는 방법

| 방법 | 안 권하는 이유 |
|------|---------------|
| **레벨마다 config 파일**(`config_pmaker.LV_Park_01.json` …) | 포트·스트림 예산·카메라 광학 규격·`hide_actors` 처럼 레벨과 무관한 값이 파일 수만큼 복제돼 어긋난다. RPC 클라이언트·`-RpcPort` 규약이 "config 하나"를 전제한다. 주차장 전환은 `TravelToConfigLevel` 이 config 를 다시 읽는 구조라 파일 이름 스위칭 코드가 새로 필요하다 |
| **폴더 관례**(`Save/3D/<주차장>/CarPos.json`, config 없이 레벨명으로 추론) | 지금 `CarPos/` 30개·`CameraPos/` 28개 대부분이 주차장별 정본이 아니라 실험용(7Num·25Face·Test·MultiCam)이고, 서신만 해도 `CarPos_Seoshin_2Cam` 과 `CarPos_23Num_서신` 두 벌이다 — "주차장당 파일 하나"가 성립하지 않는다. `car.save/load/deleteFile` 의 허용 폴더 검문(`CarFilePaths.h`: `Save/3D/CarPos` 고정)도 손대야 한다 |
| **레벨 안에 기본 파일명 저장**(레벨 BP·월드 세팅) | `Content/` 는 git 밖이고, 바꾸려면 재쿡이 필요하다. config 로 덮는 길을 연 이유(`Park3DAppConfig.h:110`)와 정반대 |
| **파일 안에 대상 레벨 기록**(`CarPos_*.json` 에 `level` 필드) | 검증용 단서로는 좋지만 "어느 파일을 열 것인가"는 못 정한다. 자동 로딩과 별개로 나중에 추가해도 된다(불일치 시 경고) |

## 적용 (2026-09-05 22:2x, 사용자 승인)

권장 형태 그대로 `Park3D/Save/Config/config_pmaker.json` 을 고쳤다.

- 서신 항목에 `preset_file: ""`, `carpos_file: "CarPos_Seoshin_2Cam.json"`, `camerapos_file: "CamPos_Seosin.json"` 명시
- 최상위 `carpos_file`·`camerapos_file` → `""` (폴백, 자동 로딩 없음)
- 정본 인스턴스(13510)가 읽는 `Package/Windows/Save/Config/config_pmaker.json` 은 수정 전 HEAD 와 내용이 같았으므로(줄바꿈만 CRLF) 같은 파일로 덮었다. **실행 중인 정본에는 재기동 전까지 반영되지 않는다.**
- `Package/Work13520` 의 config 는 `levels[]` 자체가 없는 작업본 복사본(포트 13520)이라 손대지 않았다.
- 검증: 파이썬 `json.load` 로 파싱 확인. 자동화 테스트(`Park3D.AppConfig.*`)는 테스트 내장 샘플 JSON 을 쓰므로 이 파일에 영향받지 않는다. **기동 로그 `[Config] 주차장 '서신지구대' 의 데이터 파일 적용: … carpos="CarPos_Seoshin_2Cam.json"` 은 재기동 후 확인해야 한다(미검증).**

## 함께 알아 둘 것

- config 는 **기동·레벨 전환 시 자동 로딩 기본값**일 뿐이다. 실행 중에는 패널 "열기"나 `car.load`/`cam.load` 로 아무 파일이나 바꿔 올릴 수 있으므로, 실험 파일까지 config 에 넣을 필요는 없다.
- 객리단 파일은 `LV_Park_03` 지오메트리와 안 맞아 차량이 공터에 놓인다(2026-09-04 확인, 재배치·재저장 필요). 이건 매핑 방식과 무관한 데이터 문제다.
- `preset_file` 은 두 주차장 다 `""` 라 프리셋 자동 로딩이 안 돌고, 화면의 주차면은 레벨 `BP_ParkingSlot` 이 그린다(2026-09-05 항목). 주차장을 늘릴 때 프리셋 파일을 적을지는 그 주차장이 프리셋 기능(시뮬·`random.slotPlace`)을 쓰는지로 정한다.
