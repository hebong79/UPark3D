# 차량 배치 UI — 랜덤 모드 콤보 + 리셋랜덤 버튼 추가

- 작성: 2026-08-09 23:01:13
- 브랜치: `feature/carplacement-random-reset-ui` (main 에서 분기)
- 요청: 차량배치 UI 에 랜덤 타입(콤보)과 버튼을 추가하고, 이미 존재하는 내부 랜덤 기능에 연결

## 1. 배경 — 기능은 있었고 UI만 없었다

Unity 원본 `CCarPlacementDlg` 에는 드롭다운(`m_cboResetRandomType`) + 버튼(`m_btnResetRandom`) 조합과
`ERandomResetMode { ColorOnly=0, ObjectAndColor=1, CountObjectAndColor=2 }` 가 있었다(`CCarPlacementDlg.cs:23-28, 1066-1157`).

UE 포팅 시점에는 이 중 **RPC 경로만** 넘어와 있었다:
- `car.resetRandom` 이 mode 문자열을 bool 3개로 분기(구 `CarRpcModule.cpp:311-347`)
- 위젯에는 `Check_RandomPlacement`(색상+차종 동시 랜덤, 배치 시 1대에만 적용) 체크박스 하나뿐
- `ERandomResetMode` 에 해당하는 UENUM 은 코드에 없었음

즉 **"내부 기능은 있는데 UI 진입점이 없는" 상태**였고, 모드 분기 로직이 RPC 모듈 안에만 존재해
UI 를 붙이면 같은 로직이 두 벌로 갈라질 위험이 있었다.

## 3. 설계 결정

### 3-1. 모드 분기는 매니저로 승격 — UI/RPC 단일 진입점

`ACarPlacementManager::ResetRandomPlacement(Mode, Catalog, RequestedCount, Seed)` 하나가 UI 버튼과
`car.resetRandom` 양쪽을 처리한다. Unity 원본에서도 `ResetRandomPlacement()` 가 UI·RPC 공유 진입점이었다.

| 모드 | 동작 | 반환(가시 대수) |
|---|---|---|
| `ColorOnly`(0) | 가시 차량 색상만 랜덤. 차종·위치·표시상태 불변 | 전체 |
| `ObjectAndColor`(1) | 위치/회전 유지 + 차종 랜덤 재생성 + 색상 랜덤 | 전체 |
| `CountObjectAndColor`(2) | 위 동작 + 요청 대수만 남기고 랜덤 숨김 | 요청 대수 |

배치 기준은 Unity 의 "프리셋 주차면"이 아니라 이 포트의 기존 계약대로 **현재 차량 위치**다
(`ToCarPosDatas()` 로 현 상태를 원본 삼아 재생성). RPC 계약을 바꾸지 않기 위해 그대로 유지했다.

### 3-2. 콤보 인덱스 == enum 정수 (Unity 규약 승계)

Unity 는 `(ERandomResetMode)m_cboResetRandomType.value` 로 드롭다운 값을 그대로 캐스팅한다.
같은 규약을 쓰되, 값이 밀리면 "색상만"을 골랐는데 차종까지 갈아치우는 조용한 오동작이 되므로
enum 값 0/1/2 를 테스트로 봉인했다(`Park3D.CarPlacement.RandomResetMode`).
기존 `Combo_Type`(index+1 == ECarType)과 같은 인덱스 기반 매핑 관례를 따른다.

### 3-3. 개수 입력은 자동생성 개수 필드(`Field_Count`)를 공유

Unity 원본이 `m_InCreateCarNum` 을 공유한다(`ReadRequestedRandomCarCount()`, `CCarPlacementDlg.cs:1159-1165`).
전용 입력칸을 새로 만들지 않고 같은 규약을 따랐다. 모드 2 에서만 의미가 있다.

## 4. 함께 고친 것 (요청 범위와 직접 연결됨)

### 4-1. 숨길 대수 0 을 그대로 넘기던 버그

구 코드는 `HideRandomCars(FMath::Max(0, GetCarCount() - Count), 0)` 였다.
그런데 `HideRandomCars` 는 `HideCount <= 0` 을 **"자동 랜덤 숨김"** 으로 해석한다(`CarPlacementManager.cpp:342-346`).
따라서 요청 대수가 전체 대수 이상이면 "숨기지 마라"가 "무작위로 숨겨라"로 뒤집혀 차량이 사라졌다.

```cpp
const int32 HideNum = GetCarCount() - RequestedCount;
if (HideNum > 0) { HideRandomCars(HideNum, Seed); }
```

회귀 테스트로 요청 6(=전체) / 99(>전체) / 0 세 경우 모두 전원 표시를 단정한다.

### 4-2. 랜덤 색상을 `CarData.color` 에도 기록

기존에는 머티리얼에만 칠했다. `ToCarPosDatas()` 는 액터의 `CarData` 를 반환하므로
색이 데이터에 없으면 **저장 → 재로드**나 **다음 `RefreshView()`(RebuildAll)** 에서 색이 -1(원본색)로 되돌아간다.
UI 버튼으로 리셋한 결과가 다른 조작 한 번에 지워지므로, 고른 색을 데이터에도 남기도록 했다.

부수 효과: `car.resetRandom`/`car.setRandomColor` 후 `car.save` 하면 이제 색상이 파일에 남는다.

## 5. UI 구성 방식 — WBP 가 아니라 C++ 주입

`WBP_CarPlacement` 는 디자이너 에셋이지만, 이번 작업 시점에 에디터/Unreal MCP 가 기동되지 않아
WBP 위젯 트리를 편집할 수 없었다(헤드리스 WBP 편집 불가 — UE5.8 파이썬에 `WidgetBlueprint.WidgetTree` 미노출).
`MainMenuWidget::InjectLightButton()` 선례를 따라 C++ 로 구성했다.

- 두 위젯을 `BindWidgetOptional` 로 선언 → **나중에 디자이너로 옮겨도 코드 변경 불필요**.
  이미 바인딩되어 있으면 `InjectRandomModeRow()` 는 아무것도 하지 않는다.
- 삽입 시점은 `NativeOnInitialized()`. `NativeConstruct` 는 패널을 재-`AddToViewport` 할 때마다 다시 도는데,
  `NativeOnInitialized` 는 인스턴스당 1회라 중복 삽입이 생기지 않고, Slate 트리 생성 전이라 삽입 위치가 화면에 반영된다.
- 삽입 위치: `VBox_Root` 에서 `Check_RandomPlacement`(랜덤배치)가 들어 있는 줄 바로 다음.
  앵커가 래퍼 안에 있을 수 있어 부모를 거슬러 올라가 직계 자식을 찾는다.
- 스타일은 기존 위젯에서 복사한다 — 콤보는 `Combo_Type` 의 `WidgetStyle`/`ItemStyle`,
  버튼은 `Btn_AutoCreate` 의 스타일과 라벨 폰트, 라벨은 `Lbl_Count` 의 폰트/색. 한글 폰트가 자동으로 따라온다.

구조:

```
VBox_Root
 └ (신규) VerticalBox
     ├ TextBlock "랜덤 모드"        (Lbl_RandomMode)
     └ HorizontalBox
         ├ ComboBoxString  Fill     (Combo_RandomMode)
         └ Button "리셋랜덤"         (Btn_ResetRandom)
```

## 6. 위젯 핸들러가 하는 일

`UCarPlacementWidget::ResetRandomPlacement()`

1. 매니저/차량 없으면 로그만 남기고 종료
2. 콤보 선택 인덱스 → `ERandomResetMode`(선택 없으면 `ObjectAndColor`)
3. `Field_Count` → 요청 대수
4. `Mgr->ResetRandomPlacement(...)` 호출
5. **`CarData = Mgr->ToCarPosDatas()` 로 위젯 데이터를 월드 상태와 동기화**
   — 이게 없으면 다음 `RefreshView()`(RebuildAll)가 옛 `CarData` 로 랜덤 결과를 덮어쓴다
6. 선택 해제 + `RebuildCarList()` + 결과 로그

## 7. 검증

### 7-1. 빌드

```
Build.bat Park3DEditor Win64 Development -Project=...\Park3D.uproject
→ Result: Succeeded (18.06s)
```

### 7-2. 자동화 테스트 (`-nullrhi`, 헤드리스)

- `Park3D.CarPlacement.*` 19건 전부 Success (신규 `RandomResetMode`, `ResetRandomPlacement` 포함)
- `Park3D.Rpc.*` 31건 전부 Success (`CarModule`, `RandomModule` 포함 → RPC 계약 무회귀)
- 월드 의존 테스트가 건너뛰어지지 않았음을 로그에서 확인("에디터 월드 없음" 경고 없음)

신규 테스트가 단정하는 것:
- enum 값 0/1/2 고정, 한글 표시명 3종
- `ParseRandomResetMode` 의 기존 문자열 계약 전부(별칭·대소문자·공백·정수·빈 문자열=기본 모드) + 미허용 값 거부 시 출력 불변
- ColorOnly 가 차종을 바꾸지 않고 색을 `CarData.color` 에 기록
- ObjectAndColor 가 대수·위치를 보존하고 차종은 카탈로그 Idx 범위
- CountObjectAndColor 가 요청 대수만 표시
- 요청 대수 >= 전체 / 0 일 때 아무것도 숨기지 않음(4-1 회귀 방지)

### 7-3. 실제 앱 (`-game`, 1600×900)

메인 메뉴 → 차량 배치 패널에서 "랜덤 모드" 줄이 랜덤배치 아래에 정상 표시됨(스크린샷 확인).
세 모드 모두 실행 로그로 동작 확인(`CarPos_office.json` 65대 기준):

```
[CarPlacement] 랜덤 리셋(색상만 랜덤) — 총 65대 중 65대 표시
[CarPlacement] 랜덤 리셋(객체 + 색상) — 총 65대 중 65대 표시
[CarPlacement] 랜덤 리셋(개수 + 객체 + 색상) — 총 65대 중 5대 표시
```

## 8. 남은 사항 / 주의

- **WBP 는 건드리지 않았다.** 디자이너에서 위치·크기를 조정하고 싶으면 `WBP_CarPlacement` 에
  `Combo_RandomMode` / `Btn_ResetRandom` 이름으로 위젯을 추가하면 되고, 그 순간부터 C++ 주입은 자동으로 비활성화된다.
- 모드 2 의 "숨김"은 차량을 삭제하지 않는다(`SetActorHiddenInGame`). 저장하면 숨겨진 차량도 파일에 남는다 — 기존 계약 그대로.
- 시드는 UI 에서 항상 0(비결정)으로 넘긴다. 재현이 필요하면 RPC `car.resetRandom` 쪽에 seed 파라미터를 붙이는 별도 작업이 필요하다.
