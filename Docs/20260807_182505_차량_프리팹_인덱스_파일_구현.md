# 차량 프리팹 인덱스 파일(car_catalog.json) — 시작 시 로딩

- 작성일: 2026-08-07 18:25:05
- 요청: 차량 오브젝트 목록을 JSON 으로 만들어 앱 시작 시 로딩하고 초기 인덱스(prefabId)로 사용
- 관련: [20260807_180554_차량_오브젝트_목록.md](20260807_180554_차량_오브젝트_목록.md)

---

## 1. 설계 판단 — 왜 "순서만" 담았나

바꾸고 싶은 것은 **prefabId ↔ 차종 매핑(순서)** 뿐이다. 메시 경로와 `ECarType` 까지 JSON 에 복제하면

- 진실원이 둘로 갈라져 DT_CarCatalog 와 어긋날 수 있고,
- 메시 경로에 오타가 나도 런타임에 조용히 빈 차량이 된다(에디터의 참조 무결성 보장을 잃는다).

그래서 **DT_CarCatalog = "어떤 차종이 있고 어떤 메시를 쓰는가"**(단일 진실원), **car_catalog.json = "몇 번이 어느 차종인가"**(순서)로 역할을 나눴다. 파일이 없으면 DataTable 순서를 그대로 쓴다 — 즉 이 기능은 순수한 덮어쓰기 레이어다.

---

## 2. 파일

`Park3D/Save/Config/car_catalog.json` (UTF-8)

```json
{
    "comment": "차량 프리팹 인덱스. 배열 순서가 prefabId(1부터)다. ...",
    "cars": [
        "BMW_1시리즈",
        "기아_EV6",
        ...
        "혼다_ZR-V"
    ]
}
```

**현재 기준 그대로** 23종을 DT_CarCatalog 의 기존 순서(이름순)로 적었다. 따라서 이번 변경으로 동작이 바뀌지 않는다 — 앞으로 순서를 바꿀 수 있는 손잡이가 생긴 것이다.

---

## 3. 신규 코드

### `Config/CarCatalogConfig.h` / `.cpp` — `UCarCatalogConfigLibrary`

| 함수 | 역할 |
|---|---|
| `GetFilePath()` | `Save/Config/car_catalog.json` 절대 경로. 경로 해석은 기존 `UPark3DAppConfigLibrary::GetConfigDir()` 재사용 |
| `ParseOrder(Json, Out)` | JSON → 이름 배열. 공백 정리, 빈 문자열 제거. 실패 시 Out 미변경 |
| `LoadOrder(Out)` | 파일에서 읽기 |
| `ApplyOrder(Order, InOut)` | 카탈로그 재배열 + `Idx` 를 1부터 재부여 |
| `GetCachedOrder()` | 최초 1회 로드 후 캐시 |
| `InvalidateCache()` | 캐시 폐기(파일 수정 후 재적용, 테스트 격리) |

**`ApplyOrder` 규칙** — 데이터가 조용히 사라지지 않게 설계했다.

| 상황 | 처리 |
|---|---|
| 목록에 있고 카탈로그에도 있음 | 목록 순서대로 앞에 배치 |
| 카탈로그에만 있음(목록 누락) | **버리지 않고** 원래 순서로 뒤에 이어 붙임 + 경고 로그 |
| 목록에만 있음(카탈로그에 없는 이름) | 건너뜀 + 경고 로그 |
| 같은 이름 중복 | 첫 번째만 소모 |
| 목록이 비어 있음(파일 없음) | 아무것도 하지 않음(`Idx` 도 안 건드림) |

### 결선 지점

**`ACarPlacementManager::CatalogFromTable()`** 끝에서 한 번만 적용한다.

```cpp
UCarCatalogConfigLibrary::ApplyOrder(UCarCatalogConfigLibrary::GetCachedOrder(), Out);
```

차량배치 UI(`CarPlacementWidget.cpp:215`)와 RPC(`RpcServerSubsystem.cpp:195`)가 **모두 이 함수를 거치므로**, 여기 한 곳에서 적용해야 두 경로의 id 해석이 갈리지 않는다.

**`APark3DGameMode::ApplyStartupConfig()`** 맨 앞에서 캐시를 채우고 로그를 남긴다.

```
[CarCatalog] 차량 프리팹 인덱스 23종 적용: .../Save/Config/car_catalog.json
```

`config_pmaker.json` 조기 반환보다 **앞**에 둔 이유: 설정 파일이 없어 자동 로딩을 건너뛰는 경우에도 인덱스는 적용되어야 하고, 뒤이은 차량배치 자동 로딩이 카탈로그를 쓰기 때문이다.

## 4. 검증

**빌드**: `Build.bat Park3D Win64 Development` → `Result: Succeeded`. `CarCatalogConfig.cpp`·`CarPlacementManager.cpp`·`Park3DGameMode.cpp` 컴파일 + `Park3D.exe` 링크 통과.

**유닛테스트**: `Tests/CarCatalogConfigTest.cpp` 신규 2건.

| 테스트 | 케이스 |
|---|---|
| `Park3D.CarCatalog.Parse` | 정상 / 공백 다듬기 / 빈 문자열 제거 / 손상 JSON / `cars` 키 없음 / 실패 시 Out 미변경 |
| `Park3D.CarCatalog.ApplyOrder` | 순서 뒤집기 / 목록 누락분 뒤에 이어 붙이기 / 없는 이름 건너뛰기 / 중복 / 빈 목록 |

⚠ **테스트를 실행하지 못했다.** 두 테스트 모두 `EditorContext` 라 에디터 빌드가 필요한데, 에디터(PID 9804)가 떠 있어 Live Coding 이 `Park3DEditor` 빌드를 거부한다(exit 6). 에디터를 닫고 `Build.bat Park3DEditor Win64 Development` 후 `Automation RunTests Park3D.CarCatalog` 로 실행해야 한다.

⚠ **런타임 동작도 미검증이다.** 시작 로그와 차량 배치 결과는 확인하지 않았다.

## 5. 남은 사항

- **패키지 사본**: `Package/Windows/Save/Config/` 에는 `config_pmaker.json` 만 있다. 패키지에서도 인덱스를 쓰려면 `car_catalog.json` 을 같이 넣어야 한다(없으면 DataTable 순서로 동작 — 실패는 아니다).
- **Unity 원본 순서는 여전히 미확보**다. 이 파일은 순서를 바꿀 수단을 만든 것이고, **어떤 순서가 옳은지는 아직 모른다.** 원본 프리팹 배열을 확보하면 `cars` 배열만 다시 적으면 된다(재빌드·재쿠킹 불필요).
- **파일 수정 반영 시점**: 캐시는 최초 사용 시 1회만 읽는다. 실행 중 파일을 고쳐도 반영되지 않는다 — 재시작하거나 `InvalidateCache()` 를 호출해야 한다. 필요하면 RPC 메서드로 노출할 수 있다.
