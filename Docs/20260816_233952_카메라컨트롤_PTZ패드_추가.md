# 카메라 컨트롤 패널 — PTZ 방향 패드(누르는 동안 연속 이동) 추가

- 작성: 2026-08-16 23:39
- 대상: `Park3D/Source/Park3D/CameraControlWidget.h` / `CameraControlWidget.cpp`
- 요청: SettingAgent 웹 UI 의 `PTZ 제어` 패드(▲◀중지▶▼ + 줌 + step)와 같은 컨트롤로 pan/tilt/zoom 을 변경.
  줌 버튼은 기호로, 작게.

## 1. 무엇을 만들었나

카메라 컨트롤 패널(`WBP_CameraControl`) 스크롤 본문(`VBox_Root`) 끝에 PTZ 패드를 **C++ 로** 붙였다.

```
PTZ 제어 (누르는 동안 이동)
      [ ▲ ]           [ + ]
[ ◀ ][중지][ ▶ ]      [ − ]
      [ ▼ ]        step [ 2 ]
```

| 컨트롤 | 동작 | 대상 값 |
|--------|------|---------|
| ▲ / ▼ | 누르는 동안 tilt 감소 / 증가 | `ECamCtrl::Tilt` |
| ◀ / ▶ | 누르는 동안 pan 감소 / 증가 | `ECamCtrl::Pan` |
| + / − | 누르는 동안 zoom 증가 / 감소 | `ECamCtrl::Zoom` |
| 중지 | 즉시 정지 | — |
| step | 초당 이동량(pan/tilt 는 도, zoom 은 배율). 비었거나 0 이하면 2 | — |

크기: 방향 버튼 36×24, 줌 버튼 24×18(기호만), step 입력 46×22.

## 2. 값 흐름 — 기존 슬라이더와 같은 경로

패드는 카메라를 직접 건드리지 않는다. 기존 컨트롤 묶음(`FSliderCtrl`)의 **Cur 필드 → 슬라이더 → 카메라** 경로를
그대로 탄다(`StepControl`).

```
TickPtzMove(Δt)
  → StepControl(Kind, step × Δt)
      → Min/Max 클램프 → SetControlCurText → SetControlSlider → ApplyControlToCamera
```

그래서 패드로 움직이면 Pan/Tilt/Zoom 슬라이더와 숫자 필드가 같이 따라 움직이고,
Min/Max 필드로 정한 범위를 넘지 않는다. 프리셋 추가/수정(`CollectDirFromControls`)도 별도 처리 없이 최신 값을 집는다.

## 3. 판단이 필요했던 지점

### 3.1 tilt 부호 — ▲ 는 감소다

`UCameraControlLibrary::PanTiltToRotator` 가 `FRotator(-Tilt, Pan, 0)` 이다. 즉 **tilt 가 커질수록 아래를 본다**
(카메라 프리셋의 `tilt 21.7` 이 내려다보는 각). 따라서 위를 보는 ▲ 는 tilt 를 **빼야** 한다. pan 은 Yaw 그대로라
▶ 가 증가다.

### 3.2 손을 뗀 것을 무엇으로 아는가

`OnReleased` 만 믿지 않는다. 버튼 밖으로 커서를 끌고 나가 떼면 이벤트가 오지 않을 수 있고, 그러면 카메라가
계속 돌아간다. 그래서 매 틱 `UButton::IsPressed()` 로 눌림 상태를 직접 확인해 정지한다(`TickPtzMove`).
`OnReleased` 바인딩은 한 틱 빨리 멈추기 위한 보조이고, 정지의 정본은 폴링이다.
가운데 `중지` 는 같은 정지 핸들러(`HandlePtzStop`)를 누를 때 호출한다.

### 3.3 새 위젯 참조를 UPROPERTY 로 들지 않은 이유

**이미 쿠킹된 WBP 의 C++ 베이스에 `UPROPERTY` 를 추가하면 패키지가 `Bad export index` 로 즉사한다**
(CLAUDE.md 2026-08-12 — 함수만 추가할 때와 달리 exe 교체로 안 되고 콘텐츠 재쿠킹이 필요).
패드가 필요로 하는 참조는 step 입력 1개와 방향 버튼 6개뿐이고, 이들의 GC 소유는 `WidgetTree` 와 부모 패널
슬롯이 이미 하고 있다. 그래서 관찰용으로만 `TWeakObjectPtr` 로 들었다 —
리플렉션 프로퍼티 목록이 바뀌지 않으므로 exe 교체만으로 패키지에 반영된다.

(기존 `Btn_TargetLine` 등이 `UPROPERTY(Transient)` 인 것과 스타일이 다른 것은 이 이유 때문이며,
같은 판단이 필요한 다음 추가분도 여기를 따르는 편이 안전하다.)

### 3.4 버튼 패딩

`UButton` 기본 스타일의 `NormalPadding` 이 커서 `USizeBox` 로 정한 24×18 을 라벨이 밀어낸다.
`NormalPadding`/`PressedPadding` 을 0 으로 낮춰야 "작게" 가 실제로 작아진다.

### 3.5 재구성 중복 방지

`TogglePanel` 이 패널을 캐시한 채 다시 `AddToViewport` 하므로 `NativeConstruct` 가 재실행된다.
`BuildDistanceLauncher`/`BuildGetPtzButton` 이 `Btn_*` 널 검사로 중복 생성을 막는 것과 같은 방식으로,
`BuildPtzPad` 는 `Field_PtzStep.IsValid()` 를 가드로 쓴다.

## 5. 처음에 "적용이 안 된" 이유 — 패널이 고정 높이라 잘렸다

첫 빌드 후 화면에 패드가 없었다. 로그에는 경고가 없어(`VBox_Root` 존재) 패드는 **만들어졌지만 보이지 않는**
상태였다. WBP 구조가 `RootCanvas → RootBorder → Scroll_Root(ScrollBox) → VBox_Root` 이고
**RootBorder 높이가 캔버스에서 고정**이라, 본문 끝에 붙인 패드가 스크롤 아래로 밀린 것이다.

→ `GrowPanelForPtzPad()` 로 패드를 붙일 때 패널 높이를 `GPtzPadHeight(100)` 만큼 키운다.
자동 크기(`AutoSize`)이거나 세로로 늘어나는 앵커면 뷰포트가 높이를 정하므로 건드리지 않는다.

**교훈**: `VBox_Root` 에 뭔가를 덧붙이는 기능은 "붙였다"와 "보인다"가 다르다. 이 패널은 고정 높이 + ScrollBox 라
덧붙이는 쪽이 높이까지 책임져야 한다(기존 동적 버튼 3개는 마침 남은 높이 안에 들어갔던 것뿐이다).

## 6. 레이아웃 2차 수정(실제 화면 확인 후)

| 증상 | 원인 | 수정 |
|------|------|------|
| 줌 `+`/`−` 버튼이 24px 가 아니라 열 너비로 늘어남 | `UVerticalBoxSlot` 기본 정렬이 `Fill` 이라 SizeBox 의 폭 지정을 덮어씀 | 줌 열 슬롯을 `HAlign_Left` 로 |

## 8. P/T/Z 현재값 표시 추가(2026-08-17)

요청: 참조 UI 처럼 패드에서 PTZ 값을 바로 보이게 할 것(위쪽 Pan/Tilt/Zoom 필드까지 눈을 올리지 않도록).

```
PTZ 제어 (누르는 동안 이동)
P [19.80]  T [8.70]  Z [1.62]
      ▲            +
◀  중지  ▶         −
      ▼        step [2]
```

- 값의 **원본은 여전히 위쪽 Cur 필드**다. 표시는 그것을 비추기만 한다(상태를 두 곳에 두지 않는다).
- 갱신 지점은 `SetControlCurText` 하나 — 슬라이더·직접 입력·프리셋 로드·`현재 카메라 PTZ 가져오기`·패드,
  어느 경로로 값이 바뀌든 같은 함수를 지나므로 표시가 어긋날 수 없다.
- 참조 UI 의 `X` 닫기 버튼과 부제는 넣지 않았다 — 저건 독립 창이지만 이건 패널 안의 한 구역이라
  닫기 대상이 아니고, 대상 카메라 표시는 이미 패널 상단(카메라 리스트)에 있다.

### 실측(패키지 재빌드 후)

| 항목 | 필드(Cur) | 패드 표시 |
|------|-----------|-----------|
| Pan (▶ 1.5s 후) | 22.805 | **22.81** |
| Tilt | 8.700 | **8.70** |
| Zoom (+ 1.0s 후) | 3.653 | **3.65** |

## 9. 이번에 드러난 빌드 함정 — 플러그인 세트가 바뀌면 exe 교체가 통하지 않는다

에디터에서 MCP 플러그인을 켜면서 `.uproject` 의 `AllToolsets` 이 개별 툴셋 목록으로 풀렸다
(`MCPClientToolset` 추가, `AllToolsets` 제거). 그 뒤:

1. **exe 만 갈아끼우면 패키지가 부팅하지 못한다** — 새 exe 에는 `CommonConversationRuntime` 이 없는데
   스테이지된 구성은 그 플러그인을 요구한다(`AllToolsets → ConversationToolset → CommonConversation`).
   스테이지 사본의 `.uproject` 에서 그 플러그인을 꺼도 의존 관계로 다시 켜져 소용없었다 → **재쿠킹·재스테이징이 답**.
2. **에디터가 떠 있으면 빌드 자체가 막힌다** — `Unable to build while Live Coding is active`.
3. **쿡이 죽는다** — `Config/DefaultGame.ini` 의 `GameFeatureData` 자산 규칙은 GameFeatures 플러그인이
   켜져 있을 때만 유효한데, 플러그인이 빠지면서 `AssetBaseClass` 를 못 찾아
   `Failed to load class /Script/GameFeatures.GameFeatureData` 로 쿡이 실패했다.
   → 현재 플러그인 구성에 맞춰 해당 줄을 주석 처리했다(플러그인을 다시 켜면 되살릴 것 — 주석에 명시).

**주의**: `Park3D.uproject`(플러그인 변경)와 `DefaultGame.ini`(위 3번)는 **짝이다.** 하나만 되돌리면
둘 중 한쪽 방향으로 쿡이 깨진다.

## 10. Unreal MCP 를 쓰지 못한 이유

요청은 "Unreal MCP 로" 였으나 이번 작업에서는 쓸 수 없었다.

- `.mcp.json` 의 `unreal` 서버는 `http://localhost:8000/mcp` 인데 **8000 에 리스너가 없었다**
  (에디터가 연 포트는 35213 하나이고 HTTP 로 응답하지 않는다).
- MCP 도구는 **세션 시작 시점에 연결**된다. 이 세션 시작 시 서버가 없어 unreal 도구가 로드되지 않았고
  세션 도중에는 붙일 수 없다(`/mcp` 재연결이 필요).
- 더해서 UE5.8 파이썬에는 `WidgetBlueprint.WidgetTree` 가 노출되지 않아 WBP 위젯 트리 편집 자체가 막혀 있다
  (2026-08-05 조명 패널에서 확인된 제약) → 이 패널이 애초에 C++ 로 구성된 이유이며, 이번 표시도 같은 경로로 넣었다.
