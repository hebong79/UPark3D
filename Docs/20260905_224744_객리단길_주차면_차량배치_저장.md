## 절차

1. **면 좌표 확보.** RPC 에는 레벨 `BP_ParkingSlot` 의 ISM 인스턴스를 나열하는 메서드가 없다. 그래서 09-04 의
   `Tools/usd_export/inventory_level.py` 를 커맨드릿(`-NullRHI`, 포트 미사용 → 정본 무간섭)으로 `/Game/Levels/LV_Park_03` 에
   돌려 `ISM_Slot` 인스턴스 14개의 월드 변환을 얻었다(약 1분).
2. `car.clear` 로 옛 `CarPos_13Num.객리단.json` 분 13대(공터에 놓여 있던 것) 제거.
3. 면 중심(cm→m)을 `pos` 로 `car.placeAtWorld` ×14. 차종은 `prefabId` 로 14종 골고루(2,6,7,4,11,13,19,10,1,5,14,9,18,23).
4. `car.save {fullPath}` 두 번(저장소·패키지). `fileName` 만 주면 `Saved/CarData` 로 가므로 `fullPath` 를 썼다.
5. 캡처는 `cam.captureJPG` 응답의 base64 를 파이썬으로 파일에 풀어 확인. 카메라 2 높이·PTZ 는 확인 후 원래 값(7m, pan 32.5/tilt 32.2)으로 되돌렸다.

## LV_Park_03 주차면 실측 (ISM_Slot 인스턴스, cm)

세 그룹 모두 yaw **72.09°**, scale **(6.14, 2.64, 1)** → 면 하나 **614 × 264cm 평행(노변) 주차면**.
간격은 인접 면끼리 (184.47, 570.94) = 600cm 등간격.

| 액터 | 면 | 중심 X | 중심 Y |
|------|----|-------:|-------:|
| BP_ParkingSlot_C_1 | 0~4 | −1738.89 → −1001.00 | −6148.66 → −3864.91 |
| BP_ParkingSlot_C_2 | 0~4 | −706.45 → 31.44 | −2941.20 → −657.45 |
| BP_ParkingSlot_C_3 | 0~3 | 355.80 → 909.21 | 355.24 → 2068.06 |

**LV_Park_01 과 축이 반대다.** LV_Park_01 은 scale (2.64, 5.14) 로 로컬 X=폭·Y=길이였는데(09-05 문서), LV_Park_03 은
**X=길이·Y=폭**이다. `FindLevelSlotAtWorld`(`CarPlacementManager.cpp:340-344`)가 하드코딩이 아니라 `HalfY >= HalfX` 비교로
긴 변을 고르기 때문에 그대로 맞았다 — 응답 `rotY` 가 72.09(= 인스턴스 yaw + 0°)로 나온 것이 그 증거다.

## 전면 방향 — 알아 둘 것

스냅 규약(09-05, 사용자 결정)은 "전면이 **가장 가까운 PTZ 카메라** 쪽". 이 레벨은 카메라 액터 3개가 전부 (2.6, −1.5)m 한 자리에 있어
- 남쪽 10대(그룹 1·2): `rotY 72.09` → 북쪽(카메라 쪽)을 본다
- 북쪽 4대(그룹 3): `rotY 252.09` → 남쪽(카메라 쪽)을 본다

즉 **같은 노변에서 두 무리가 서로 마주 본다.** 한 방향 도로라면 실제와 다를 수 있다. 통일하려면 그룹 3 네 대에
`car.setRotationY 72.09` 를 주고 다시 `car.save` 하면 된다(이번엔 규약대로 두고 사용자 판단에 맡겼다).
