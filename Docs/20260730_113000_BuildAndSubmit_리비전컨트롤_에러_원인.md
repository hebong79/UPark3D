# "Cannot connect to revision control; automated build aborted." 원인과 해결

작성일: 2026-07-30
분류: 질문 답변 (저장소 파일 변경 없음 / 진단만)

---

## 1. 질문

에디터에서 **Build and Submit** 창을 띄우고 빌드했더니 Message Log의 `Build and Submit Errors (1)`에

```
Cannot connect to revision control; automated build aborted.
```

가 떴다. "실행파일(exe)을 위한 빌드"인데 왜 실패하나?

---

## 2. 결론 — 그 창은 실행파일을 만드는 경로가 아니다

**Build and Submit**은 exe 패키징과 **무관한 기능**이다.

| 항목 | Build and Submit | Package Project (exe) |
|---|---|---|
| 하는 일 | 레벨의 **라이팅/내비메시/HLOD 등 맵 빌드** 후 결과 에셋을 **리비전 컨트롤에 자동 커밋(Submit)** | 콘텐츠 **쿠킹 + 게임 타깃 컴파일 + 스테이징** |
| 산출물 | 빌드된 `.umap`/BuiltData 에셋 (소스 관리에 제출됨) | `Park3D.exe` + 쿠킹 콘텐츠 |
| 소스 관리 필요 | **필수** (Perforce/SVN/Git 연결 없으면 즉시 중단) | 불필요 (`-noP4`) |

즉 이 창은 "빌드해서 **팀 저장소에 올려주는**" 자동화 워크플로다. 엔진 코드(`FEditorBuildUtils::EditorAutomatedBuildAndSubmit`)가 **가장 먼저 리비전 컨트롤 프로바이더 연결을 확인**하고, 연결이 없으면 맵 빌드를 시작조차 하지 않고 위 메시지를 남기며 중단한다.

---

## 3. 왜 연결이 안 되나

현재 프로젝트는 리비전 컨트롤 프로바이더가 에디터에 연결되어 있지 않다.

- `d:\Work\UnrealWork\Parking` 및 `Park3D` 하위에 **SVN 작업 복사본(`.svn`)이 없다**.
- `Saved/Config/WindowsEditor/`에 `SourceControlSettings.ini`가 **존재하지 않는다** (= 프로바이더 미설정 상태).
- 현재 버전 관리는 git(`main` 브랜치)으로 하고 있으며, 에디터의 Revision Control 패널에는 연결되어 있지 않다.

따라서 에러는 **버그가 아니라 정상 동작**이다. 제출할 대상(리비전 컨트롤)이 없으므로 자동 빌드가 스스로 중단한 것.

---

## 4. 해결

### 4-1. exe가 목적이라면 (권장)

`Build and Submit` 창을 닫고 아래 중 하나를 쓴다.

**A. 에디터 GUI**
> 상단 **Platforms → Windows → Package Project** → 출력 폴더 선택

**B. 커맨드라인 UAT** (이 프로젝트에서 쓰던 방식)

```bat
"C:/Program Files/Epic Games/UE_5.8/Engine/Build/BatchFiles/RunUAT.bat" BuildCookRun ^
  -project="D:/Work/UnrealWork/Parking/Park3D/Park3D.uproject" ^
  -noP4 -platform=Win64 -clientconfig=Development ^
  -cook -build -stage -pak -archive ^
  -archivedirectory="D:/Work/UnrealWork/Parking/Package"
```

`-noP4`가 있어 리비전 컨트롤을 아예 타지 않는다. 산출물: `Package/Windows/Park3D.exe`
(현재 파일 기준 마지막 패키징: 2026-07-29 18:39)

> 주의: `RunUAT`의 exit 0만으로 성공 판정하지 말 것. 로그와 `Package/Windows/` 산출물 **타임스탬프**로 확인한다.

### 4-2. 맵(라이팅) 빌드만 목적이라면

툴바 **Build → Build All Levels**를 쓴다. 제출 단계가 없으므로 리비전 컨트롤이 필요 없다.

### 4-3. 굳이 Build and Submit을 쓰려면

에디터 우하단 **Revision Control → Connect to Revision Control**에서 프로바이더(Subversion/Perforce/Git)를 연결해야 한다. 프로젝트 루트의 `svn_setup.ps1`이 SVN 공존 설정 스크립트다. 다만 **exe 산출과는 무관**하므로 지금 목적에는 불필요하다.

---

## 5. 영향도

- 저장소 파일 변경 없음(진단·문서만). 코드·설정·에셋 무변경.
- `Build and Submit` 시도는 리비전 컨트롤 확인 단계에서 중단되었으므로 **맵/BuiltData가 수정되지 않았다**. 롤백할 것 없음.
- 기존 패키징 경로(`Package/Windows/Park3D.exe`)와 RPC/MCP 연결 구성에 영향 없음.

## 6. 실제 패키징 실행 결과 (2026-07-30 16:55~16:56)

§4-1 B의 UAT 명령을 그대로 실행. `BUILD SUCCESSFUL`, `AutomationTool exiting with ExitCode=0`, 총 48.43초.

| 단계 | 결과 |
|---|---|
| BUILD | `Target is up to date` / `No build products were made` — 재컴파일 불필요 |
| COOK | 증분 쿠킹, 653 패키지 (UAsset 3.26 GiB) |
| PAK | `LogIoStore: Success`, UnrealPak 10.18초, ExitCode=0 |
| STAGE | UFS 2657 / NonUFS 34 / Debug 6 파일 |
| ARCHIVE | `Package/Windows`로 아카이브 |

### 산출물 타임스탬프 검증

| 파일 | 시각 |
|---|---|
| `Package/Windows/Park3D-Windows.pak` 외 `.ucas`/`.utoc` | **2026-07-30 16:55~16:56** (갱신됨) |
| `Package/Windows/Park3D.exe` (런처 스텁) | 2026-07-30 16:55 (갱신됨) |
| `Package/Windows/Park3D/Binaries/Win64/Park3D.exe` (실제 게임 exe) | 2026-07-29 18:38 (그대로) |

**게임 exe가 갱신되지 않은 것은 정상이다.** 최신 소스가 2026-07-29 18:37이고 빌드 산출물이 18:38이라 UBT가 up-to-date로 판정했다. 스테이징은 원본 타임스탬프를 보존해 복사하므로 시각이 같고, 크기도 `345,019,392`바이트로 원본과 일치한다. 즉 exe에는 최신 C++ 변경이 이미 들어 있다.

> 07-29 문서 §3의 "exe만 stale" 상황과는 다르다. 그때는 exe(07-27)가 소스(07-28~29)보다 **오래됐던** 것이고, 이번엔 exe(07-29 18:38)가 소스(07-29 18:37)보다 **최신**이다.

오늘 14:56에 수정된 `Park3D/Config/DefaultGame.ini`는 `-pak` 스테이징으로 pak(16:55) 안에 들어갔다. (`-pak` 사용 시 Config는 낱개 폴더가 아니라 pak 내부에 존재한다.)

### 참고: 에디터를 켠 채 패키징 가능했던 이유

`UnrealEditor.exe`(PID 13528)가 실행 중이었으나, 디스크의 `UnrealEditor-Park3D.dll`(07-29 18:37)이 이미 최신이라 UBT가 재링크를 시도하지 않았다. DLL 재링크가 필요한 상태였다면 파일 잠금으로 LNK1168 실패가 났을 것이다. **소스를 수정한 뒤 패키징할 때는 에디터를 닫아야 한다.**
