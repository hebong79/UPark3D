### 왜 위젯 바깥이 아니라 안쪽 여백인가

기존에는 위젯이 판 폭의 82% 를 차지하고 **판 중심**에 놓였다. 그래서 번호의 중심이 곧 판의 중심이었고,
왼쪽 파란 KOR 스트립 위까지 글자가 밀려 내려와 스트립에 닿았다.

영역을 오른쪽으로 옮기는 방법은 두 가지였다.

1. 3D 로 위젯 컴포넌트를 `MeshWide` 축만큼 오른쪽으로 미는 방법
2. 위젯을 판에 1:1 로 덮고 **위젯 안쪽 여백**으로 영역을 정하는 방법

**2번을 골랐다.** 1번은 "판 로컬 +X 가 화면의 어느 쪽인가"가 앞판·뒷판에서 각각 뒤집히는지를 축 계산으로
증명해야 하는데(판 회전 → 시선 방향 → UE 좌수계 `Right = Up × Forward`), 이 프로젝트에는 이미
`PlateTextSideShift = 4cm`(TextRender 용) 주석이 "오른쪽"이라고 적혀 있으면서 그 TextRender 자체가
런타임 폰트라 **화면에 안 그려져 검증된 적이 없는** 값으로 남아 있다. 반면 위젯 안쪽 Slate 좌표의
좌/우는 화면에 글자가 뒤집히지 않고 나온다는 사실만으로 확정된다.

### 영역 좌표 (DrawSize 520×110px = 판 52×11cm → 10px = 1cm)

```
판 왼쪽 |--2cm--|--- 파란 스트립 4cm ---|--2cm--|########## 번호 영역 ##########|--2cm--| 판 오른쪽
0px                                    60px    80px                          500px    520px
```

- 왼쪽 여백 `NumberAreaLeft = 80px` — 스트립 끝(60px) + 스트립에서 떨어질 간격 2cm
- 오른쪽 여백 `NumberAreaRight = 20px` — 판 오른쪽에서 2cm(왼쪽과 대칭)
- 위아래 `NumberAreaVertical = 10px` — 이전(판 높이의 82%)과 글자 크기가 같도록

## 2. 검증(실측)

패키지 복제본 `Package/Work13530`(RPC 13530)에 새 exe 만 갈아끼워 기동하고 PTZ 카메라로 촬영했다.
사용자의 실행 중인 인스턴스(`Package/Windows`)는 건드리지 않았다.

픽셀 실측(앞 번호판, 1280×720 캡처):

```
판 테두리 256..1039px (777px = 52cm → 14.94px/cm)
파란 영역  258..338px  (판 왼쪽에서 0 ~ 5.4cm)
번호 잉크  404..996px  (판 왼쪽에서 9.8 ~ 49.4cm)
→ 스트립 끝에서 4.4cm 떨어져 시작, 판 오른쪽 2.6cm 앞에서 끝난다.
```

영역(8~50cm)은 좌우 2cm 로 대칭이고, 잉크가 그보다 안쪽에서 시작·종료하는 차이(왼쪽 1.8cm,
오른쪽 0.6cm)는 글리프의 좌우 side bearing 이다. 글자마다 다르므로 여백으로 보정하지 않았다 —
보정하면 번호가 바뀔 때마다 정렬이 흔들린다.

## 3. 알아 둘 것

- **파란 KOR 영역은 두 겹이다.** `CarActor` 생성자가 붙이는 큐브(`SecurityStrip`, 판 왼쪽 2cm 지점에서
  4cm)와 판 메시(`SM_Plate_F/B`) 재질이 그리는 KOR 필드가 겹쳐 있다. 실측상 파랗게 보이는 폭은
  약 5.4cm 로 큐브보다 넓고 판 왼쪽 끝에 붙어 있다. 여백을 다시 만질 일이 있으면 큐브 값이 아니라
  **캡처의 파란 폭**을 기준으로 잡을 것.
- 글자는 `ScaleBox(ScaleToFit)` 가 영역 폭을 꽉 채우도록 키운다. 즉 8자리 번호에서는 폭이 기준이고
  글자 크기는 번호 조합에 따라 조금씩 달라진다(기존 동작 그대로).
- 위젯이 판을 1:1 로 덮게 바뀌었으므로, 앞으로 여백은 전부 `UCarPlateNumberWidget` 의 상수에서 정한다.
  `ACarActor` 쪽에는 더 이상 "판 폭의 몇 %" 같은 값이 없다.
