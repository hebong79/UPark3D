# 웹 PTZ 요청과 네이티브 프리셋 이동의 결과 불일치 — 원인 분석과 해결 방향

- 작성일: 2026-08-07 15:19:09
- 대상: `CameraControlWidget` / `CamRpcModule` / `CamPos_office.json`
- 상태: **원인 확정. 해결 방향 (b) 채택 — `CamPos_office.json` 을 위치 고정으로 재작성 예정.**

---

## 1. 현상

같은 "Preset 2 로 이동" 요청인데 두 경로의 결과가 다르다.

| | 경로 | 결과 |
|---|---|---|
| 사례 1 | 웹 클라이언트 → 이동 요청 → 이동 후 "현재 카메라 PTZ 가져오기" 로 UI 덮어씀 | Pan/Tilt/Zoom = 57.500 / 21.500 / 7.400, 위치 = X -36.300 / Z -13.600, 프리셋 콤보 = **Preset 1** |
| 사례 2 | Park3D UI 에서 직접 Preset 2 선택 | Pan/Tilt/Zoom = 57.500 / 21.500 / 7.400, 위치 = X **-38.300** / Z **-13.700**, 프리셋 콤보 = Preset 2 |

PTZ 는 완전히 같고 **카메라 위치만 다르다.** 그런데 렌더된 화면은 전혀 다른 장면으로 보인다.

## 2. 원인

### 2-1. 웹 경로에는 카메라를 이동시킬 방법이 없다

`Park3D/Save/3D/CameraPos/CamPos_office.json` 의 실제 값:

| 프리셋 | UI X축(좌우) | UI Z축(앞뒤) | 높이 | pan | tilt | zoom |
|---|---|---|---|---|---|---|
| 1 | -36.3 | -13.6 | 13.5 | 47.1 | 30.4 | 2.4 |
| 2 | -38.3 | -13.7 | 13.5 | 57.5 | 21.5 | 7.4 |

사례 1 의 값을 대조하면 **P/T/Z 는 Preset 2, 위치는 Preset 1** 이다. 즉 웹 요청은 PTZ 만 적용했고 카메라 몸체는 Preset 1 자리에 그대로 있었다.

RPC 에는 프리셋 이동 메서드가 아예 없다 — `Rpc/Modules/CamRpcModule.cpp:320-325` 에서 `cam.savePreset` · `cam.loadPreset` · `cam.applyPreset` 세 개 모두 `NotImplemented(-32000, "per-camera 프리셋 메모리 없음")` 이다. 웹이 쓸 수 있는 것은 `cam.setPTZ`(:188) 뿐이고 이 메서드는 `SetPanTilt` + `SetZoom` 만 호출한다. 위치를 바꾸려면 `cam.setPosition`(:163) 을 따로 불러야 하는데 그 호출은 없었다.

### 2-2. 근본 원인 — 프리셋 정의가 양쪽에서 다르다

| | 프리셋의 내용 |
|---|---|
| 실장비(HNR-2036LA) / 웹 클라이언트 | **P/T/Z 만.** 폴대에 고정된 몸체는 이동 불가 |
| Park3D `FCamDir` | **위치(`pos`) + P/T/Z + ptzmin/ptzmax** |

웹은 장비 규약대로 PTZ 만 보냈고, 네이티브는 Park3D 규약대로 위치까지 옮겼다. 불일치의 본질은 버그가 아니라 **모델 차이**다.

### 2-3. 왜 화면 차이가 그렇게 큰가

위치 차이는 2.0 m 뿐이지만 zoom 7.4 에서 수평 화각은

```
HFOV = 2·atan( tan(56.5°/2) / 7.4 ) ≈ 8.31°
```

30 m 앞 피사체 기준 화면 폭이 약 4.4 m 이므로 **2 m 이동 = 화면 폭의 약 46%** 다. 완전히 다른 장면으로 보이는 것이 정상이다.

### 2-4. "현재 카메라 PTZ 가져오기" 버튼은 정상 동작했다

읽어온 57.500 / 21.500 / 7.400 이 파일의 Preset 2 값과 소수 첫째 자리까지 일치한다. `Rotator ↔ Pan/Tilt`, `FOV ↔ Zoom` 역변환이 왕복으로 맞는다는 뜻이다. 설계대로 위치는 건드리지 않았을 뿐이다.

## 3. 부수적으로 드러난 위험 2건

1. **RPC 로 카메라가 움직여도 UI 는 모른다.** 사례 1 에서 Preset ID 와 콤보가 여전히 `1 / Preset 1` 이었다. 이 상태에서 "수정" 을 누르면 **Preset 1 에 Preset 2 의 PTZ 가 덮어써진다.**
2. **위치 컨트롤은 3개가 묶여 있다.** `ApplyControlToCamera`(CameraControlWidget.cpp:466-474) 는 X·Z·높이 중 하나만 건드려도 3개를 한꺼번에 카메라에 다시 밀어 넣는다. 웹이 위치까지 옮겼더라도 UI 슬라이더를 한 번 만지는 순간 옛 위치로 되돌아간다.

## 4. 해결 방향

| | 내용 | 판정 |
|---|---|---|
| (a) | `cam.applyPreset` 을 구현해 웹의 프리셋 요청이 위치까지 적용 | **기각.** "웹은 위치 정보가 없고 PTZ 만 변경되어야 한다" 는 요구와 정면 충돌 |
| (b) | 프리셋에서 위치를 떼어내고 웹·네이티브 모두 PTZ 만 이동 | **채택** |

### 4-1. (b) 의 규칙

> 프리셋 전환은 P/T/Z 만 바꾼다. 카메라 위치(X·Z·높이)는 프리셋과 무관하게 고정이다.

(b) 를 적용하면 **사례 1 이 정상이고 사례 2(네이티브)가 과잉 동작**이 된다. 웹을 고치는 것이 아니라 Park3D 를 실장비 규약에 맞추는 방향이다.

### 4-2. 위치의 소유자가 프리셋 → 카메라로 옮겨간다

현재 위치를 담는 필드는 `CameraControlTypes.h` 의 `FCamDir.pos` 하나뿐이고, 카메라를 나타내는 `FCameraPos` 에는 위치 필드가 없다. (b) 에서는 **"카메라 1대 = 설치 위치 1개 + 그 자리에서 바라보는 방향 N개"** 가 된다.

### 4-3. 코드 변경 지점

핵심은 `FillControlsFromDir`(CameraControlWidget.cpp) 의 세 줄이다.

```cpp
SetVal(ECamCtrl::X,      Dir.pos.x);   // ← 제거
SetVal(ECamCtrl::Height, Dir.pos.z);   // ← 제거
SetVal(ECamCtrl::Z,      Dir.pos.y);   // ← 제거
SetVal(ECamCtrl::Pan,    Dir.pan);     // 유지
SetVal(ECamCtrl::Tilt,   Dir.tilt);    // 유지
SetVal(ECamCtrl::Zoom,   Dir.zoom);    // 유지
```

이 세 줄을 빼면 프리셋을 바꿔도 위치 필드가 그대로 남고, 뒤이은 `ApplyAllControlsToCamera()` 가 같은 위치를 다시 쓰므로 카메라가 움직이지 않는다. 위치는 슬라이더·"카메라 피킹" 으로만 바뀌며, 그것은 프리셋과 무관한 **설치 작업**이 된다.

### 4-4. JSON 스키마는 유지한다

`pos` 필드를 삭제하면 `CameraControlTypes.h` 첫 줄에 못 박힌 **"Unity SCameraPosList 와 100% 호환"** 규약이 깨진다. 필드는 남기되 의미만 바꾼다.

- 의미: "이 프리셋의 위치" → **"이 카메라의 설치 위치(모든 프리셋에 동일 값)"**
- 저장: 현재 카메라 위치를 전 프리셋의 `pos` 에 같은 값으로 기록
- 로드: 첫 프리셋의 `pos` 를 카메라 위치로 채택

기존 툴에서 파일은 그대로 읽힌다.

## 5. `CamPos_office.json` 현황과 재작성 계획

### 5-1. 현황 — 카메라 1대, 프리셋 5개

전부 `cam_id: 1` 이다. **나눌 카메라가 없다.** 위치가 5개 다 다른 것은 폴대가 5개여서가 아니라, 프리셋을 만들 때마다 카메라를 조금씩 옮겨가며 구도를 잡았고 "추가"/"수정" 이 `CollectDirFromControls` 에서 그 순간의 X·Z·높이까지 함께 저장했기 때문이다. **한 폴대가 5번 움직인 흔적**이다.

| 프리셋 | X축(좌우) | Z축(앞뒤) | 높이 | pan | tilt | zoom |
|---|---|---|---|---|---|---|
| 1 | -36.3 | -13.6 | 13.5 | 47.1 | 30.4 | 2.4 |
| 2 | -38.3 | -13.7 | 13.5 | 57.5 | 21.5 | 7.4 |
| 3 | -39.9 | -13.7 | 13.5 | 21.7 | 18.3 | 3.4 |
| 4 | -39.8 | -13.2 | 14.0 | 36.2 | 17.4 | 4.4 |
| 5 | **-22.6** | -11.0 | 14.0 | 11.1 | 21.7 | 2.9 |

1~4 는 3.6 m 안에 모여 있어 미세 조정 수준이지만, **5번만 X 로 17.3 m 떨어져 있다.** 실장비라면 폴대를 뽑아 옮긴 셈이라 있을 수 없는 값이다.

### 5-2. 할 일은 분리가 아니라 재조준

1. 설치 위치 하나를 확정한다.
2. 5개 프리셋의 P/T/Z 를 그 자리 기준으로 다시 잡는다. 각 프리셋의 pan/tilt/zoom 은 *자기 위치에서* 그 구역을 겨누도록 맞춰진 값이라, 카메라가 한 자리에 고정되면 같은 각도가 다른 곳을 가리킨다.

### 5-3. 재조준 계산법

각 프리셋의 원래 조준점을 주차장 바닥(z=0)으로 투영해 구한 뒤, 새 위치에서 그 점을 겨누는 각도를 역산한다.

```
지면 거리   d0   = 높이 / tan(tilt)            (tilt 는 하향이 양수)
조준점      (ax, ay) = (x + d0·cos(pan), y + d0·sin(pan))
새 각도     pan' = atan2(ay - cy, ax - cx)
            tilt' = atan(새높이 / d')
            zoom' = zoom · d' / d0             (화면상 크기 유지)
```

**원래 조준점**

| 프리셋 | 조준점 (X, 앞뒤) | 거리 |
|---|---|---|
| 1 | (-20.64, 3.26) | 23.0 m |
| 2 | (-19.89, 15.20) | 34.3 m |
| 3 | (-1.97, 1.39) | 40.8 m |
| 4 | (-3.75, 13.18) | 44.7 m |
| 5 | (11.92, -4.23) | 35.2 m |

### 5-4. 설치 위치 후보별 재조준값

**후보 A — 프리셋 1 자리 (-36.3, -13.6, 13.5)**

| 프리셋 | pan | tilt | zoom | 거리 |
|---|---|---|---|---|
| 1 | 47.1 → 47.1 | 30.4 → 30.4 | 2.4 → 2.4 | 23.0 m |

| 5 | 11.1 → 11.0 | 21.7 → **15.4** | 2.9 → **4.0** | 35.2 → 49.1 m |

어느 후보를 골라도 **프리셋 5 는 tilt 6~7° 감소, zoom 1.4배 증가**가 불가피하다. 카메라가 17 m 물러난 셈이라 같은 곳을 보려면 더 눕히고 더 당겨야 한다.

조준점이 바닥에 있다고 가정한 계산이므로, 실제로 차량 상단을 겨눴다면 tilt 가 소폭 달라진다. 재작성 후 PIE 에서 프리셋별 화면을 육안 확인해야 한다.
