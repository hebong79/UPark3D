# MapFloorActor 아스팔트 "미렌더" 버그 — 근본 원인 규명 및 수정

작성일: 2026-07-14
작업: unreal-implementer (MCP 실증 기반)

---

## 0. 결론 요약 (먼저)

**머티리얼은 처음부터 정상이었다. 버그가 아니었다.**
실제 원인은 **게임(PIE) 렌더의 자동 노출(Auto Exposure / Eye Adaptation)** 이다.

> 160×160 m 짜리 **어두운 아스팔트 평면이 화면을 가득 채우자**, 히스토그램 기반 자동 노출이
> "장면이 너무 어둡다"고 판단해 **노출을 약 +0.7 EV(≈1.6배) 올려버렸다.**
> 그 결과 어두운 아스팔트가 톤매핑을 거쳐 **베이지색 중간톤**으로 떠버렸다.
> 레벨에 **PostProcessVolume 이 하나도 없어서** 엔진 기본값(`r.DefaultFeature.AutoExposure=1`)이 그대로 적용되고 있었다.
> 에디터 뷰포트는 **고정 노출**을 쓰기 때문에 같은 액터가 정상(어두운 아스팔트)으로 보였다 — 이것이 "PIE에서만 깨진다"의 정체다.

수정: 레벨에 **Unbound PostProcessVolume 1개**를 추가해 **노출을 고정**(EV100 = 0)했다.
C++ / 머티리얼 / 텍스처는 **한 줄도 건드리지 않았다. 컴파일 불필요.**

### (E1) 결정적 실험 — 에디터 월드에서는 처음부터 정상이었다
생성자만으로 스폰한 `AMapFloorActor`(**프로퍼티 일절 미조작**)를 에디터 월드에 배치하고 캡처:

| 조건 | 바닥 영역 평균 RGB | 판정 |
|------|-------------------|------|
| z=300 (공중에 띄움), 원거리 카메라 | **(75, 60, 50)** | 진짜 아스팔트 |
| z=2 (실제 값), 원거리 카메라 | **(99, 82, 70)** | 진짜 아스팔트 |
| z=2 (실제 값), 근접·그레이징 카메라 | **(109, 88, 70)** | 진짜 아스팔트 (골재 질감 선명) |

→ **생성자 할당만으로 아스팔트가 정상 렌더된다.** (a)(b) 계열 가설은 여기서 모두 사망.
(오케스트레이터의 "생성자 할당만으로 렌더되는 상태를 관찰한 적 없다"는 우려는 해소됨.)

## 2. 근본 원인 확정

### (E2) 동일 액터 · 동일 카메라 A/B — 에디터 vs PIE
레벨에 배치한 **같은** MapFloorActor를, **같은 카메라**(PIE 기본 시점 `Loc=(-1500,0,1500), Pitch=-45`)에서 촬영:

| 렌더 경로 | 원거리 Landscape(상단 밴드) | 바닥(하단) |
|-----------|---------------------------|-----------|
| **에디터 뷰포트** (고정 노출) | (124.0, 104.4, 92.4) | **(107.7, 89.1, 74.5)** ← 아스팔트 |
| **PIE 게임 뷰** (자동 노출) | (201.4, 188.0, 179.9) | **(176.7, 155.1, 135.1)** ← 베이지 |
| 배율 | ×1.62 | ×1.64 |

**바닥만 밝아진 게 아니라 Landscape도 똑같은 배율로 밝아졌다.**
→ 머티리얼 결함이 아니라 **화면 전체에 걸린 균일한 노출 게인**이다.

### (E3) 확정타 — 바닥을 숨기면 "Landscape"가 어두워진다
PIE에서 카메라·Landscape는 그대로 두고 **바닥만 `bVisible=false`**:

| 상태 | 원거리 Landscape 평균 RGB |
|------|--------------------------|
| 바닥 표시 | (201.4, 188.0, 179.8) |
| **바닥 숨김** | **(191.6, 176.0, 159.6)** |

Landscape 자체는 아무것도 안 바뀌었는데 **밝기가 변했다.**
이건 **자동 노출 말고는 설명이 불가능하다.** 어두운 바닥이 히스토그램을 끌어내리자 노출이 올라간 것.

### 왜 "베이지"였나 (관측치가 서로 비슷했던 이유)
- 아스팔트(정상 노출 ≈107) × 1.64 ≈ **176** → 오케스트레이터 실측 **(176,155,135)** 와 일치.
- 바닥을 숨기면 노출이 내려가 모래가 **(181,165,148)** 로 보임.
- **두 값이 우연히 비슷해서** "바닥이 안 그려지는 것 같다"는 착시가 생겼다. 실제로는 둘 다 정상 렌더였다.

### 부수 확인
- 머티리얼 그래프: `WorldAlignedTexture` × 3 (BaseColor / Normal / ORM) + `TextureObject` × 3. 정상.
- BaseColor 텍스처 `T_sfrofg0a_2K_B` 썸네일 평균 = **(39, 35, 31)** → 원본 알베도는 확실히 어둡다.
- 레벨 내 **PostProcessVolume 0개** → 엔진 기본 자동 노출(히스토그램, Bias +1.0)이 그대로 적용 중이었다.

## 3. 수정 내용

### 변경 (에셋 1건뿐)
**`/Game/Maps/PresetMaker1`** 레벨에 PostProcessVolume 액터 **1개 추가**:

| 항목 | 값 |
|------|-----|
| 액터 라벨 | `PP_FixedExposure` |
| `bUnbound` | `true` (Infinite Extent — 레벨 전역) |
| `Priority` | `1.0` |
| `AutoExposureMethod` | `AEM_Histogram` |
| `AutoExposureMinBrightness` | **`0.0`** (EV100) |
| `AutoExposureMaxBrightness` | **`0.0`** (EV100) |
| `AutoExposureBias` | `1.0` (프로젝트 기본값과 동일 — 명시적 고정) |

Min=Max 로 두면 자동 노출이 **한 값에 고정**된다(적응 자체를 없앰).
오버라이드는 위 4개뿐이고 **나머지 포스트프로세스 설정은 전부 상속(미오버라이드)** 이다.

### 건드리지 않은 것
- `MapFloorActor.h/.cpp` — **무수정**
- `M_아스팔트`, 텍스처 3종 — **무수정** (검증용으로 `neverStream`을 잠시 켰다가 **원래 값 `false`로 복구 완료**)
- 프로젝트 ini — 무수정 (`DefaultEngine.ini` 를 고치면 에디터 재시작이 필요해 즉시 검증이 불가능하므로 레벨 볼륨을 택했다)

### 왜 `AEM_Manual` 이 아닌가
`AEM_Manual` 을 먼저 시도했으나 화면이 **완전 검정(0,0,0)** 이 됐다.
Manual 은 카메라 셔터/ISO/조리개 기반 물리 노출인데 이 레벨의 라이트 강도가 물리 단위로 캘리브레이션돼 있지 않기 때문이다.
→ 히스토그램 방식 + Min=Max 고정이 이 프로젝트에 맞는 해법.

## 5. 영향도 / 트레이드오프 (정직하게)

1. **전역 시각 변화**: PostProcessVolume 이 Unbound 이므로 **레벨 전체의 노출이 고정**된다.
   카메라를 어디로 돌리든 밝기가 더 이상 출렁이지 않는다.
   주차장 **저작 툴** 성격상 이게 옳다(WYSIWYG, 에디터 뷰포트와 동일 거동). 다만 "게임처럼 눈부심 적응"을 원했다면 이 값은 조정 대상이다.
2. **EV100 = 0 은 경험적 튜닝값**이다. 더 밝게/어둡게 원하면 `PP_FixedExposure` 의 Min/Max Brightness 를 같은 값으로 함께 바꾸면 된다 (−1.0 하면 2배 밝아짐 ≈ 에디터 뷰포트와 거의 일치).
3. **PTZ 카메라/씬 캡처에도 동일 적용**된다(Unbound). 위 검증에서 인게임 카메라 뷰어도 정상 노출 확인.
4. **텍스처 3종 재저장**: 검증 중 `neverStream` 을 토글했다가 원복했고, 전체 저장 시 동일 내용으로 재직렬화됐을 수 있다. **의미상 변경 없음.**

## 7. 미확인 / 정정 사항

- 오케스트레이터의 "**사실 4**"(PIE 중 동일 머티리얼 재할당 → 즉시 아스팔트)는 **재현되지 않았다.**
  본 조사에서는 재할당 전후 픽셀이 (169.2,148.7,130.3) → (169.2,148.7,130.1) 로 사실상 무변화였다.
  당시 노출 적응 과도기(수 프레임) 화면을 관찰했거나, 다른 영역을 비교한 것으로 추정한다. 이 단서는 근본 원인과 무관하다.
- 따라서 "프로퍼티는 옳은데 렌더 결과만 틀렸다"는 전제 자체가 **부정확했다**: 렌더 결과도 (노출을 감안하면) 옳았다.
