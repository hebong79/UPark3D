# 카메라 뷰어 표시 크기 변경 (400×225 → 480×270)

- 작성일: 2026-07-09 13:12 (13:20 정정)
- 요청: "카메라 뷰어 크기를 이미지에 보이는 크기로 설정" / "처음 기본값의 크기임"
- 대상: `UCameraViewerWidget::DefaultViewSize`

> ## ⚠️ 정정 (13:20)
> 최초에 **렌더타겟 해상도**(`InitRenderTarget` 1280×720→400×225)를 바꿨으나, 이는 **화면에 보이는 뷰어 박스 크기를 바꾸지 않는다**(해상도/선명도만 변경). 사용자가 원한 것은 **화면 표시 박스 크기**였다.
> - **렌더타겟 해상도 변경은 원복**(1280×720). → 확대 시에도 선명 유지.
> - **화면 표시 크기**를 `DefaultViewSize` 400×225 → **480×270**(16:9)로 변경.
>
> 아래 1~3절(렌더타겟 해상도 관련)은 **폐기된 접근**이며 기록용으로 남긴다. 실제 반영 내용은 4절 이후 및 이 배너를 따른다.

---

## 실제 변경 (확정)

| 파일 | 변경 |
|------|------|
| `CameraViewerWidget.h` | `DefaultViewSize` `(400,225)` → **`(480,270)`**, `CurrentViewSize` 기본값도 동일 |
| `PTZCameraActor.h/.cpp` | 렌더타겟 해상도 변경 **원복**(1280×720, 메모리 주석 원복) |

- 표시 크기 결정 경로: `NativeConstruct` → `CurrentViewSize = DefaultViewSize` → `ApplyViewSize()` 가 `Img_View` 의 캔버스 슬롯 크기를 `CurrentViewSize` 로 직접 지정. 즉 **`DefaultViewSize` 가 화면 박스 크기의 실질 결정값**.
- 16:9 비율(480:270) 유지 → 리사이즈 로직·프레임 그리기 영향 없음. `MinViewWidth(160)~MaxViewWidth(1280)` 범위 내.

### ⚠️ 반영 안 될 경우 점검 (WBP 인스턴스 오버라이드)
- `DefaultViewSize` 는 `UPROPERTY(EditAnywhere)` 라 **`WBP_CameraViewer` 에셋에서 값이 오버라이드**되어 있으면 C++ 기본값 변경이 무시된다.
- 컴파일 후에도 크기가 그대로면 → `WBP_CameraViewer` 디자이너의 Details 에서 `Viewer > Default View Size` 를 480×270 으로 지정(또는 오버라이드 해제)해야 한다.

## (폐기) 최초 접근: 렌더타겟 해상도 일치

## 1. 요구사항 해석

- 스크린샷의 우하단 카메라 뷰어는 **초기 기본 표시 크기**(`UCameraViewerWidget::DefaultViewSize = 400×225`, 16:9)로 보이는 상태다.
- 요청은 **렌더타겟(캡처 텍스처) 해상도를 그 표시 크기와 1:1로 맞추는 것**이다.
  - 뷰어 표시 크기(400×225)는 이미 원하는 값 → 변경 불필요.
  - 변경 대상은 **렌더타겟 해상도**: 기존 1280×720 → **400×225**.

## 2. 변경 내용 (외과적, 2곳)

### 2.1 `PTZCameraActor.h`
```cpp
// 변경 전
void InitRenderTarget(int32 W = 1280, int32 H = 720);
// 변경 후
void InitRenderTarget(int32 W = 400, int32 H = 225);   // 뷰어 표시 크기와 1:1
```
- 유일한 호출부 `ACameraControlManager::AddCamera()` 의 `Cam->InitRenderTarget();` 는 **인자 없이 기본값 사용** → 자동으로 400×225 적용.
- 주석도 "기본 1280x720" → "기본 400x225 = 뷰어 표시 크기와 1:1" 로 갱신.

### 2.2 `PTZCameraActor.cpp`
- 렌더타겟 메모리 주석 갱신: RGBA8 기준 `~3.5MB/1대(1280×720)` → `~0.35MB/1대(400×225)`.

## 3. 효과 / 트레이드오프

| 항목 | 변경 전(1280×720) | 변경 후(400×225) |
|------|------------------|------------------|
| 기본 표시(400×225) 선명도 | 다운스케일 표시 | **1:1 네이티브(선명)** |
| RT 메모리(RGBA8, 1대) | ~3.5MB | **~0.35MB** (약 1/10) |
| 뷰어를 크게 리사이즈 시 | 최대 1280폭까지 선명 | **확대되어 흐릿** |

- 뷰어 위젯은 드래그로 최대 `MaxViewWidth=1280`까지 리사이즈 가능. RT가 400폭으로 고정되므로 그 이상 확대하면 업스케일 블러 발생. (요청이 "표시 크기와 일치"이므로 의도된 절충.)
- 표시 크기 자체(400×225)는 변화 없음 — 화면상 뷰어 크기는 동일, 해상도(선명도/메모리)만 바뀜.

## 4. 반영 조건 (중요)

- 헤더 기본 인자 변경이므로 **호출부 `CameraControlManager.cpp` 도 재컴파일**되어야 새 기본값이 반영된다(기본 인자는 호출부에서 치환됨). Live Coding은 헤더 변경 시 의존 TU를 자동 재컴파일하므로 충족.
- 렌더타겟은 **카메라 생성(AddCamera) 시점**에 생성된다. 이미 만들어진 카메라의 RT는 재생성 전까지 기존 1280×720 유지 → **PIE 재시작 또는 카메라 재추가** 후 400×225 적용.

## 5. 영향도 분석

- **직접 영향:** `APTZCameraActor` 만. 캡처 파이프라인/브러시 지정 로직(`CameraViewerWidget::SetRenderTarget`, `CameraControlWidget`)은 `RT->SizeX/SizeY` 를 그대로 읽으므로 코드 수정 불필요 — 브러시 `ImageSize` 가 자동으로 400×225로 세팅됨.
- **종횡비:** 400:225 = 16:9 로 기존과 동일 → 캡처 FOV/왜곡 영향 없음.
- **다른 모듈/에셋:** 없음. 블루프린트에서 `InitRenderTarget` 을 인자 지정해 호출하는 곳이 있다면 그 값이 우선(현재 C++ 호출부는 인자 없음).
- **테스트:** 기존 유닛 테스트(CameraControl*)는 RT 해상도에 의존하지 않음 → 회귀 없음.

## 6. 검증 (대기)

- 컴파일: 에디터에서 Ctrl+Alt+F11(Live Coding) 또는 에디터 종료 후 풀 빌드.
- 동작 확인(PIE): 카메라 추가/선택 → 뷰어가 기본 크기에서 선명 표시되는지, `RenderTarget->SizeX==400 && SizeY==225` 확인.
