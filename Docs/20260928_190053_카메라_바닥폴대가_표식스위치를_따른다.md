# 카메라 바닥 폴대가 표식 스위치를 따른다 (보드 #940)

- 날짜: 2026-09-28
- 브랜치: `fix/cam-pole-follows-marks` (main 머지 안 함)
- 요청: SettingManager(192.168.0.221) — 「카메라 위치 보기」 체크박스가 꺼져 있고 `cam.marks` 가
  `enabled:false` 인데도 카메라 밑에 얇은 1 m 기둥이 서 있다. 켜고 끄면 사라진다.

## 1. 증상과 원인

보드 #940 은 09-23 에 "공은 사라지는데 기둥은 남는다"로 올라왔고, 그 절반은 그날 커밋
`0d974c2`(cam.setMarks 가 `ShowAllPoles` 를 부른다)로 고쳐졌다. 남아 있던 것은 **기본값**이다.

- `APTZCameraActor` 생성자가 `PoleMesh` 를 **보임**으로 만든다(`SetCollisionEnabled(QueryOnly)` 만 하고
  가시성은 엔진 기본값 = 보임).
- `ACameraControlManager::AddCamera` 는 표식/폴대 상태를 새 카메라에 적용하지 않는다.
- 폴대를 끄는 코드는 `cam.setMarks` 하나뿐이었다. 카메라를 만들거나 다시 만드는 모든 경로
  (`cam.create` · `cam.loadPosFile`→`SyncCamerasToData` · `cam.resetCameras` · 기동 시
  `EnsureDefaultCamera`)는 `if (bMarksEnabled) RebuildMarks(Mgr);` 만 했다.

즉 **스위치가 꺼진 채 태어난 카메라는 전부 기둥을 달고 나온다**. 기동 직후가 그 상태이므로
"한 번도 켜 본 적 없으면 기둥이 서 있다"가 된다. 켜고 끄면 `ShowAllPoles(false)` 가 돌아 사라진다.

폴대는 액터가 아니라 카메라 액터의 컴포넌트라 `env.list` 에 안 나온다(#940 의 관찰 3과 일치).

## 2. 수정

폴대 가시성의 단일 기준점을 **매니저**에 두고, 카메라를 만들 때 그것을 적용한다.

| 파일 | 변경 |
|------|------|
| `PTZCameraActor.cpp` | 생성자에서 `PoleMesh` 를 **숨김**으로 시작(콜리전도 `NoCollision` — `SetPoleVisible(false)` 와 같은 규약) |
| `CameraControlManager.h/.cpp` | `bPolesVisible`(Transient, 기본 false) 신설. `ShowAllPoles` 가 값을 저장하고, `AddCamera` 가 새 카메라에 적용. 조회용 `ArePolesVisible()` |
| `CameraControlWidget.cpp` | 패널 「폴대 보기」 버튼이 위젯 플래그가 아니라 **매니저의 현재 값**에서 뒤집는다(그 사이 RPC 가 바꿨을 수 있다 — `car.hideAll` 체크박스 관례) |
| `Rpc/Modules/CamRpcModule.cpp` | `cam.create` · `cam.loadPosFile` · `cam.resetCameras` · `cam.marks` 가 `ShowAllPoles(bMarksEnabled)` 로 재적용. `cam.marks`/`cam.setMarks` 응답에 `polesVisible` 추가 |

### 왜 RPC 쪽에도 재적용을 두는가

`FCamRpcModule`(`bMarksEnabled`)은 GameInstance 서브시스템에 얹혀 **레벨 전환을 살아남고**,
`ACameraControlManager`(`bPolesVisible`)는 레벨 액터라 **새로 만들어진다**. `scene.load` 한 번에
두 값이 갈리므로 표식을 만지는 지점마다 모듈 값을 매니저로 밀어 넣는다(값이 같으면 비용 없음).

### 계약 변화 (웹/외부 호출자)

- `cam.marks` · `cam.setMarks` 응답에 **`polesVisible`**(bool) 이 늘었다. 기존 필드·의미는 그대로.
- `cam.marks` 는 조회지만 **폴대를 스위치에 맞춘다**(멱등). 그 대가로 게임 내 패널
  「폴대 보기」로 기둥만 켜 둔 상태는 다음 `cam.marks` 호출에 덮인다 — 표식 스위치가 사실상
  기둥의 주인이라는 뜻이다. 패널 버튼은 계속 동작하고(누르면 매니저 현재값을 뒤집는다) 라벨도
  어긋나지 않는다.

## 3. 검증

- `Build.bat Park3DEditor Win64 Development` → **Succeeded**
- `Build.bat Park3D Win64 Development` → **Succeeded**
- `Automation RunTests StartsWith:Park3D` (`-nullrhi -RpcPort=13530`, 정본 13510 무간섭)
  → **147/147**, 실패 0. 신규 `Park3D.Rpc.CamModuleExt.MarkPoles` 1건 증가(146 → 147).
- **신규 테스트가 실제로 이 버그를 잡는지 확인**: 생성자 기본값·`AddCamera` 적용·`cam.create`
  재적용 세 줄만 되돌려 빌드하니
  `Expected 'marks off: 보이는 폴대 0' to be 0, but it was 2` 와
  `'끈 뒤 추가한 카메라도 폴대 숨김' to be 0, but it was 1` 로 실패했다. 되돌린 줄을 복구한 뒤
  다시 147/147.

테스트가 검사하는 것: 표식 꺼짐에서 `cam.create` ×2 → 보이는 폴대 0 / `cam.loadPosFile`(3대)
→ 0 / `cam.setMarks true` → 3, 그 뒤 `cam.create` → 4 / `cam.setMarks false` → 0, 그 뒤
`cam.create` → 0 / `cam.resetCameras` → 0. `cam.marks` 의 `enabled`·`polesVisible` 도 대조.

### 미검증

- **실기 화면**: 정본 Park3D.exe(13510)는 이 세션에서 내리지 말라는 제약이 있어 교체·재기동을
  하지 않았다. 사람이 콘솔에서 exe 를 갈아야 화면으로 확인된다.
- **패키지 빌드**: 새 `.cpp` 를 추가하지 않았으므로 돌리지 않았다(유니티 충돌 위험 지점인
  익명 네임스페이스 신규 함수 `VisiblePoleCount`/`FindCameraManager` 는 Source 전체에 같은 이름의
  자유 함수가 없음을 grep 으로 확인).
- **폴대 모양**: #940 의 관찰 5("기둥이 공까지 올라오지 않고 1 m 짜리다")는 손대지 않았다.
  `PoleMesh` 는 실린더 스케일 `(0.1, 0.1, 1.0)` = 100 uu 고정이고 카메라 높이를 따르지 않는다.
  높이를 따라가게 하려면 `UpdatePolePosition` 에서 Z 스케일을 카메라 높이로 잡아야 한다(별건).

## 4. 배포

사람이 콘솔에서:

1. 정본 `Package/Windows` 인스턴스(13510) 종료.
2. `Park3D/Binaries/Win64/Park3D.exe` → `Package/Windows/Park3D/Binaries/Win64/Park3D.exe` 교체
   (옛 exe 는 `.bak_20260928` 로). 재쿡은 필요 없다 — Content·Save 변경 없음.
3. 재기동 후 확인: 기동 직후 카메라 밑에 기둥이 없다 → `cam.setMarks {enabled:true}` 로 공+기둥
   → `{enabled:false}` 로 둘 다 사라짐 → `cam.create` 해도 기둥 없음. `cam.marks` 의
   `polesVisible` 이 `enabled` 와 같은 값이어야 한다.
