# 시작 슬롯 — 수동 모드에서도 갯수를 받아 start slot 부터 강제로 매긴다

작성 2026-09-08 (같은 날 오전 `20260908_104500_시작슬롯_자동재부여_옵션.md` 의 후속)

## 1. 요청

> 1. 수동모드 일때도 갯수 입력이 가능하도록 수정해줘.
> 2. 단 수동모드는 겹치는 슬롯 번호가 생겨도 된다.
> 3. 수동모드는 start slot 부터 강제적으로 번호를 먹인다.

오전 결정("수동이면 기준 면 한 장만, 갯수 칸은 잠근다")을 되돌린다. 첨부 화면(객리단 `Camera 5` /
`Preset 3`, 시작 슬롯 7, 갯수 8, 자동 꺼짐)처럼 **수동에서 갯수를 넣었는데 칸이 회색으로 잠겨 안 먹던**
상태가 신고의 실체다.

## 2. 결정

| 항목 | 결정 | 이유 |
|------|------|------|
| 갯수 N (N>0) | **모드 무관** 기준 면부터 N 장을 `start_slot, +1, +2 …` 로 강제 | 요청 1·3 |
| 번호 중복 | 막지 않는다(수동·자동 모두) | 요청 2. 자동도 원래 안 막았다(09-08 새벽 결정) |
| 갯수 빈칸(0) | **여기서만 모드가 갈린다** — 수동: 기준 면 한 장 / 자동: 묶음 끝까지 | 옛 파일(`start_count` 없음·`auto_renumber` 없음)의 동작을 그대로 지킨다 |
| 갯수 칸 | 항상 사용 가능. 체크박스 콜백(`HandleStartAutoChanged`) 삭제 | 잠글 이유가 사라졌다 |
| 적용 시점 | 체크·타이핑만으로는 안 바뀌고 **'수정'** 이 반영 | 기존 규약 유지 |

### 가정 — 사용자에게 확인받지 않은 것

"자동" 이 무엇을 더 해야 하는지는 요청에 없어 **자동 모드의 동작은 손대지 않았다**. 그 결과 두 모드의
차이는 **갯수를 비웠을 때뿐**이다(수동=한 장, 자동=끝까지). 요청 2 의 "단 수동모드는 겹쳐도 된다" 를
"자동은 겹치지 않게 하라" 로 읽을 여지가 있는데, 그러려면 자동에서 나머지 면을 밀어 번호를 유일하게
만드는 새 규칙이 필요하다 — 요청에 없어 넣지 않았다. 필요하면 별도 지시로.

## 3. 동작 규칙 (`AParkingPresetManager::ApplyNumberAnchors`)

```cpp
Remaining = A->Count > 0 ? A->Count : (A->bAuto ? 무한 : 1);
```

| 자동 | 갯수 | 바뀌는 면 |
|------|------|-----------|
| 꺼짐(기본) | 0 | 기준 면 1장 (변경 없음) |
| 꺼짐 | N | **기준 면 포함 N 장** (신규 — 전에는 1장) |
| 켜짐 | 0 | 기준 면부터 묶음 끝까지 (변경 없음) |
| 켜짐 | N | 기준 면 포함 N 장 (변경 없음) |

묶음 경계(프리셋 면 → 레벨 면)에서 끊기는 규칙, 같은 면에 기준점이 둘이면 뒤가 이기는 규칙은 그대로.

예) 면 1..6, 기준 면 3

- 수동 + 갯수 2 + 시작 1 → `1, 2, 1, 2, 5, 6` (앞의 1·2 와 겹치지만 막지 않는다)
- 수동 + 갯수 0 + 시작 10 → `1, 2, 10, 4, 5, 6`
- 자동 + 갯수 0 + 시작 10 → `1, 2, 10, 11, 12, 13`

파일 형식(`CamPos_*.json`)·RPC 계약은 바뀌지 않았다. 값의 **해석**만 바뀐다 — 오전에 `auto_renumber:false` +
`start_count:N` 으로 저장해 둔 파일은 이제 N 장을 바꾼다.

## 5. 검증

- `Park3DEditor`·`Park3D` 두 타깃 빌드 성공.
- 자동화 테스트 **104/104 성공**(`Park3D.ParkingDecal.SlotNumbers` 포함, 실패 0).
- 실기: 패키지 복제(`Package/Work13520`, exe·pdb 만 12:07 빌드로 교체, RPC 13520) 서신지구대 레벨 면 23개.

**RPC 경로** (`cam.savePreset` → `preset.numbers`, 기준 면 `level:BP_ParkingSlot_C_1#0` = 5번)

| 호출 | 바닥 번호 |
|------|-----------|
| 수동, 시작 100, 갯수 3 | `1,2,3,4,100,101,102,8,9,…,23` |
| 수동, 시작 1, 갯수 2 | `1,2,3,4,**1,2**,7,8,…,23` (중복 허용) |
| 수동, 시작 100, 갯수 0 | `1,2,3,4,100,6,7,…,23` (한 장) |
| 자동, 갯수 0 | `1,2,3,4,100,101,…,118` (끝까지) |
| 자동, 갯수 3 | `1,2,3,4,100,101,102,8,…,23` |
| 시작 0 (해제) | `1,…,23` |

**패널** — 카메라 패널을 열어 `자동` 이 꺼진 상태에서 갯수 칸이 시작 슬롯 칸과 같은 밝은 색이고,
클릭 후 `3` 타이핑 → 편집 중에도 검은 글자로 보이며 Enter 후 `3` 이 남는다. 시작 슬롯 `100` 도 같다.
LShift+클릭으로 기준 면을 찍어 '수정' 까지 누르는 패널 왕복은 이번에 다시 하지 않았다 — 패널이 프리셋에 쓰는
필드(`WriteStartSlotTo`)와 적용 함수(`ApplyNumberAnchors`)는 RPC 와 같은 코드이고 그쪽을 위 표로 확인했다.
