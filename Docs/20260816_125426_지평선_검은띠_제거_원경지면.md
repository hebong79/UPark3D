# 하늘과 지면 사이의 검은 띠 제거 — 원경 지면(BackdropMesh) 추가

- 선행 작업: `20260816_121248_콘텐츠교체후_전체검정화면_복구.md` 의 "남은 것 #1"

## 1. 원인

`AMapFloorActor` 의 바닥은 **유한한 평면**(기본 160×160m)이고,
`ALightControlManager` 가 스폰하는 `ASkyAtmosphere` 는 **지평선 위쪽만** 그린다.
그래서 "바닥의 먼 끝"과 "하늘의 아래 끝" 사이 구간에 그릴 것이 아무것도 없어
그 띠가 검게 남았다.

```
화면 위 →  하늘 (SkyAtmosphere)
           ▓▓▓▓ 검은 띠  ← 바닥 밖 = 빈 공간
           바닥 (160×160m 평면)
화면 아래
```

카메라를 수평 근처로 올릴수록 넓게 보인다. 조명 문제가 아니라 **지면 지오메트리가
지평선까지 닿지 않는 것**이 원인이다.

## 2. 조치 — `BackdropMesh` (원경 지면)

`AMapFloorActor` 에 바닥과 **같은 머티리얼**(`/Game/M/MI_Asphalt`)을 쓰는 큰 평면을
하나 더 두고 바닥보다 조금 아래에 깔았다.

| 항목 | 값 | 이유 |
|---|---|---|
| 머티리얼 | `/Game/M/MI_Ground` | 바닥(`MI_Asphalt`)을 부모로 하고 `Tint` 만 0.8 로 낮춘 인스턴스. §4 참조 |
| 한 변 | 20,000 m | 눈높이 수 m 에서 평면 끝이 지평선과 **0.03° 이내**로 붙는다. 더 키우면 원거리 정점 정밀도만 나빠진다 |
| Z | −2 cm | 바닥(`FloorZ=2`)보다 낮아야 겹치는 구간에서 바닥이 이긴다(Z-fighting 회피) |
| 콜리전 | 없음 | 바닥과 동일. 켜면 커서 피킹(`ECC_Visibility`)이 오염된다 |
| 그림자 | 안 드리움 | 바닥과 동일(VSM 페이지 낭비 제거). 받는 것은 유지 |
| `bAffectDistanceFieldLighting` | false | 아래 참조 |
| `bAffectDynamicIndirectLighting` | false | 아래 참조 |

### 2-1. 루트 컴포넌트를 씬 컴포넌트로 교체

기존에는 `FloorMesh` 자체가 `RootComponent` 였다. 그대로 두고 `BackdropMesh` 를
붙이면 **`SetFloorSize()` 의 스케일이 자식에게도 곱해져** 원경 지면이 맵 크기를 따라
출렁인다. 그래서 빈 `USceneComponent` 를 루트로 두고 두 메시를 형제로 붙였다.

`AParkingPresetManager` 가 데칼 부착을 위해 루트 씬 컴포넌트를 도입한 것과 같은 이유다.
`FloorMesh`/루트를 외부에서 직접 만지는 코드는 없다(`MapSizeWidget`·`MapRpcModule` 모두
`SetFloorSize`/`ResetFloorSize`/`WidthM`/`DepthM` 만 쓴다) — 전수 확인함.

### 2-2. GI·거리필드에서 뺀 이유

20km 평면을 전역 거리필드와 Lumen 에 넣으면 씬 전체의 간접광이 달라져
**지금의 조명·노출이 흔들리고, 픽셀 기반 가림률 측정(`scenario.*`)의 기준선도 같이
움직인다.** 이 평면의 목적은 배경을 메우는 것뿐이므로 GI *기여*에서만 뺐다
(빛을 *받는* 것은 그대로라 바닥과 같은 톤으로 보인다).

같은 이유로 `ExponentialHeightFog` 는 쓰지 않았다 — 지평선은 자연스럽게 메워지지만
안개가 근거리 픽셀까지 바꿔 측정값을 오염시킨다.

## 3. 검증 (PIE 실측)

카메라 1을 틸트 −8°(수평 위)로 올려 `cam.capturePNG` 로 캡처:

- **검은 띠 완전히 사라짐.** 지면이 지평선까지 이어지고 하늘과 맞닿는다
- 지평선 근처에서 지면이 대기 산란(aerial perspective)으로 옅어져 하늘로 자연스럽게 넘어간다
  — 별도 안개 없이도 하드 라인이 생기지 않는다
- 높이 15m·틸트 10° 오버뷰에서도 **바닥(160m)과 원경 지면의 이음매가 보이지 않는다**

기동 로그에 `[MapFloor]` 경고 없음(머티리얼 정상 해석), `[ParkingManager] 데칼 92개 활성` 유지.

캡처 후 카메라 1은 원래 값(pos z=4.5, pan 151.9, tilt 16.5, zoom 1.7)으로 원복했다.

## 4. 원경 전용 머티리얼 `MI_Ground` (13:15 추가)

원경을 바닥과 **완전히 같은** 머티리얼로 두었더니 바닥 경계가 사라져서
**맵 크기 변경 패널의 시각적 피드백이 없어지는** 부수 효과가 생겼다.
(바닥 크기는 순수 시각 요소이고 주차 프리셋·차량 배치와는 무관하므로 기능 영향은 없었지만,
가로/세로를 바꿔도 화면에서 차이를 알 수 없는 건 명백한 퇴행이다.)

그래서 원경만 살짝 어둡게 했다.

- `/Game/M/MI_Ground` — 부모 `/Game/M/MI_Asphalt`, `Tint` 만 `(0.8, 0.8, 0.8, 1)`
- `MapFloorActor.cpp` 의 `BackdropMesh` 머티리얼을 이 인스턴스로 지정.
  `MI_Ground` 를 못 찾으면 바닥 머티리얼로 폴백한다 — 톤 구분보다 **검은 띠를 막는 쪽이 우선**이다.

결과: 주차장 바닥이 주변 지면보다 살짝 밝아 경계가 은은하게 보이고
(새로 포장한 부지처럼 읽힌다), 지평선은 여전히 이어진다. 실측 캡처로 확인함.

## 5. 함정 — PIE 중에는 에셋 생성·저장·삭제가 안 된다

`MI_Ground` 를 PIE 실행 중에 만들려다 헛돌았다. `create` 는 성공한 것처럼
`refPath` 를 돌려주고 `set_vector_parameter`/`get_vector_parameter` 도 정상 동작하는데,
`save_assets` 만 조용히 실패한다:

```
save_assets(["/Game/M/MI_Ground"])  -> Asset does not exist: /Game/M/MI_Ground
save_assets(["/Game/M/MI_Asphalt"]) -> Asset does not exist: /Game/M/MI_Asphalt   ← 디스크에 멀쩡히 있는데도
exists / delete                      -> 전부 false
로그: LogUtils: Error: The Editor is currently in a play mode.
```

즉 "새 에셋이 등록 안 됐다"가 아니라 **PIE 중에는 에셋 경로 해석 자체가 막힌다.**
게다가 이때 PIE 를 멈추면 MCP(8000) 리스너까지 같이 죽어(팀보드 #42) 손을 쓸 수 없게 된다.

**에셋 작업은 PIE 를 켜기 전에 끝낼 것.** 이미 PIE 중이라면 에디터를 재기동하는 편이 빠르다.
(이번엔 종료 신호마저 PIE 에 막혀 강제 종료해야 했다 — 저장 안 된 것은 재생성 3줄짜리
`MI_Ground` 뿐이라 손실은 없었다.)
