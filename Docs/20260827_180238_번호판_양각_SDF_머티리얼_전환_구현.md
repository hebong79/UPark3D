## 2. 왜 지오메트리를 버렸나 (실측)

선행 문서의 진단 그대로다. 요약하면 증상 둘의 **원인이 다르고 둘 다 지오메트리로는 못 고친다.**

- **가까이서 평평하다** — 압출 측벽이 화면에 2.5px 나 나오는데 명암 대비가 0 이었다.
  글자 알베도가 `0.015` 라 디퓨즈가 전부 0 으로 깎여 법선이 어디를 보든 같은 색이 나온다.
  **두께가 아니라 셰이딩 문제**다.
- **오른쪽이 얇아 깨진다** — 원거리에서 획 굵기가 0.7px 이 되면 지오메트리는 **밉이 없어 사라진다.**
  실측: 판 폭 47px 에서 번호 오른쪽 절반 픽셀값이 전부 판 흰색(700대)이었다.

텍스처로 옮기면 밉·이방성 필터가 회색으로 수렴시켜 후자가 없어지고,
머티리얼이 노멀·거칠기·가림을 함께 내므로 전자도 없어진다.

부수로 없어진 것들: 압출 두께 0.1cm 양자화(규격 1.3~1.6mm 를 못 맞추던 문제), 21GB 메모리 사고,
GeometryMask 글로벌 셰이더 의존(= "exe 교체로는 검증 불가" 함정), 차량당 글자 메시 드로우콜.

## 3. 실물을 보고 맞춘 것

사용자 지시로 실제 번호판을 찾아 **치수를 실측해 맞췄다.**
기준: Wikimedia Commons `Republic of Korea euro license plate.jpg` (1474×322, 2019 유럽형 520×110, 파란 KOR 띠).
판 폭을 52.1cm 로 놓고 환산했고, 이미지 종횡비가 4.578 로 실제 4.727 보다 3.3% 세로로 늘어 있어 보정했다.

| 항목 | 실물 | 전(Text3D) | 후(SDF) |
|------|------|-----------|---------|
| 글자 높이 | **7.08 cm** | 5.78 cm (−22%) | 6.98 cm |
| 번호 잉크 좌/우 | 7.14 / 49.84 cm | 8.02 / 50.10 cm | 7.78 / 49.81 cm |
| 숫자 피치 | **5.01 cm 균일** | 비례폭(가변) | 5.01 cm 균일 |
| 글자 세로 중심 | 5.48 cm(판 중앙) | 판 중앙 | 판 중앙 |
| 파란 띠 오른쪽 끝 | 5.62 cm | — | 5.4 cm(메시가 그린다) |

두 가지가 이 실측에서 나왔다.

1. **숫자는 고정폭이다.** 실물 피치가 5.01/4.99/5.02 로 균일했다. 폰트(수성돋움체)는 비례폭이라
   `'0' 114.75 vs '1' 91.75` 로 다르다 → 베이커에서 숫자 어드밴스를 가장 넓은 것으로 통일했다.
   안 하면 `111` 같은 번호가 유독 좁아 보인다.
2. **2019 개정에서 문자 폭·자간이 좁아졌다**(나무위키). 우리가 가진 수성돋움체는 넓은 쪽이라
   높이를 실물에 맞추면 글자가 판을 넘친다 — 실물 `어드밴스합/글자높이 = 6.198`, 우리 `7.272`.
   → **가로만 0.853 배로 압축**한다(`CondenseX`). 그러면 숫자 잉크 폭도 실물과 같은 `0.61 × 글자높이` 가 된다.

폰트는 **수성돋움체**로 바꿨다(전에는 Pretendard Bold). 이 프로젝트가 이미 갖고 있던 실제 번호판
서체인데, 레거시 `TextRender` 가 런타임 폰트를 못 그려서 못 쓰던 것이다 — 오프라인 베이크에서는
그 제약이 없다. 실물과 나란히 놓고 글자꼴이 일치함을 확인했다
([대조 이미지](img/20260827_161319_번호판_노멀맵_양각/11_실물대조_레이아웃.png)).

### 3.1 짚고 넘어갈 사실 — 실물 KOR 띠 번호판은 대개 **평면이다**

조사 중에 나온 사실이라 적어 둔다. 한국 번호판은 두 갈래다.

- **페인트식** — 알루미늄을 압인해 문자가 **양각**이고 그 위에 도색한다.
- **재귀반사식(필름식)** — 재귀반사 필름에 인쇄한다. **파란 KOR 띠와 태극·홀로그램은 이쪽에만 있다.**

즉 우리가 모델링한 "KOR 띠가 있는 유럽형"은 실물에서는 필름식이고, 문자가 양각이 아닐 가능성이 높다
(필름식 제작 공정에서 압인 여부까지는 확인하지 못했다 — **미검증**).
사용자 요구가 양각이므로 양각으로 만들었고, 이 문서는 그 사실만 남긴다.

## 4. 머티리얼 (M_PlateFront)

### 4.1 기존 그래프에 이미 자리가 있었다

열어 보니 번호를 받을 슬롯이 이미 있었다 — 새 머티리얼도, 새 지오메트리도 만들 필요가 없었다.

```
TexCoord0 → ×(U Tiling, V Tiling) → +(U, V) → UV'
UV' → "BaseColor"(T_Normal: 흰 바탕 + 파란 KOR) .RGB → Lerp.A
UV' → "Text"(T_Emissive, 사실상 미사용) .R          → Lerp.Alpha
                          "TextColor"(검정)         → Lerp.B
Lerp → BaseColor        (Normal·Roughness·AO 는 전부 미연결이었다)
```

바꾼 것은 **Lerp.Alpha 하나**(→ SDF coverage)이고, 나머지는 비어 있던 출력에 새로 꽂았다.

### 4.2 UV — 판 앞면은 UV 공간의 **가운데 1/5** 만 쓴다

`TexCoord0` 를 그대로 쓰면 안 된다. 판 앞면의 UV0 는 `u ∈ [0,1]`, **`v ∈ [0.4, 0.6]`** 이다.
모르고 v 를 0~1 로 가정했더니 글자가 세로로 5배 늘어났다.

확정 방법(그래프를 읽어서는 알 수 없다 — 화면으로 재야 한다):
1. 눈금이 있는 프로브 텍스처를 `Text` 파라미터에 넣고 판을 찍는다.
2. 램프(위 절반 u, 아래 절반 v)로 방향을 확정 — **u 는 왼→오, v 는 위→아래**.
3. v 를 64등분한 줄무늬로 폭을 잰다 — 판 높이 238px 안에 13주기 → **v 폭 0.198 ≈ 0.2**.

그래서 Custom 노드가 `T = (u·UScale + UOff, v·VScale + VOff)`, 기본 `(1, 0, 5, −2)` 로 편다.
기존 UV' 체인은 `T_Normal` 아틀라스 전용(V Tiling 4)이라 공유하면 번호가 4번 반복된다.

### 4.3 Custom(HLSL) 노드 하나

노드로 풀면 4탭 샘플·smoothstep·중앙차분·정규화까지 25개쯤 되고, 한 줄 고칠 때마다 연결을 다시 세야 한다.
릴리프 계산은 모따기 폭·AO 폭·양각 높이가 서로 물려 있어 **한 곳에 모여 있어야 튜닝된다.**

```hlsl
float2 T = float2(UV.x*UScale + UOff, UV.y*VScale + VOff);
float S  = sample(T);                       // 0.5 = 외곽선, >0.5 = 글자 안쪽
float Sl,Sr,Su,Sd = sample(T ± 1텍셀);

#define HGT(x) smoothstep(0.5 - Bevel*0.5, 0.5 + Bevel*0.5, (x))   // 외곽선에 **걸친** 모따기
float3 N = normalize(float3(-dhdu*Relief, dhdv*Relief, 1));        // 중앙차분 → 접선공간 노멀

float w = max(0.5*(abs(ddx(S)) + abs(ddy(S))), 1e-4);
Cov = smoothstep(0.5 - w, 0.5 + w, S);                             // 거리 무관 AA

float sh = smoothstep(0.5 - 0.03, 0.5 + 0.03, sample(T + Shadow)); // 접지 그림자(1탭)
float occ = ...;                                                    // 뿌리 AO
AO = saturate(1 - (AOStrength*occ + ShadowStrength*sh) * (1 - Cov));
return N;
```

출력은 `return`(노멀) + 추가 출력 `Cov`, `AO` 세 개다.

### 4.4 결선

```
Cov  → 기존 Lerp.Alpha  → BaseColor(레거시)
Lerp × AO → Substrate Slab .Diffuse Albedo
Lerp(PlateRoughness, GlyphRoughness, Cov) → Slab .Roughness  (+ 레거시 MP_Roughness)
Custom.return → Slab .Normal                                  (+ 레거시 MP_Normal)
Slab → MP_FrontMaterial
```

파라미터 기본값(전부 실측 환산, 렌더타깃 1024×256 = 판 52.10×11.00cm 기준 → 1텍셀 0.51×0.43mm):

| 파라미터 | 값 | 뜻 |
|---|---|---|
| `SdfBevel` | 0.16 | 모따기 폭(SDF 단위) ≈ 2.6텍셀 ≈ 1.1mm |
| `SdfRelief` | 3.5 | 양각 높이(텍셀) ≈ 1.5mm — 노멀 기울기를 정한다 |
| `SdfAOBand` / `SdfAOStrength` | 0.20 / 0.15 | 글자 바깥 뿌리 AO |
| `SdfShadowV` / `SdfShadowStrength` | −3.5/256 / 0.55 | 접지 그림자(위로 한 탭) |
| `SdfUScale/UOff/VScale/VOff` | 1 / 0 / 5 / −2 | 판 UV → 렌더타깃 UV |
| `PlateRoughness` / `GlyphRoughness` | 0.50 / 0.32 | 도료가 판보다 광택 있다 |

## 5. 검증 중 드러난 것들 (전부 실측)

### 5.1 ★ 이 프로젝트는 **Substrate 가 켜져 있다** — 레거시 출력에 새로 연결해도 화면이 안 바뀐다

`DefaultEngine.ini:26` 에 `r.Substrate=True`.

같은 `Constant3Vector` 를 **BaseColor** 에 걸면 판이 즉시 빨개지는데, **Emissive** 에 50(!)을 걸어도
픽셀이 1도 안 변했다. 저장·`PostEditChange`·recompile 을 다 태워도 같았다.
BaseColor 만 듣는 이유는 **원래부터 연결돼 있어 레거시→Substrate 변환에 이미 잡혀 있었기 때문**이다.

→ 새 출력(Normal/Roughness/AO/Emissive)을 쓰려면 `SubstrateSlabBSDF` 를 직접 만들어
`MP_FrontMaterial` 에 꽂아야 한다. 레거시 출력에도 같이 걸어 두면 Substrate 를 끌 때 폴백이 된다.

**이걸 모르면 "머티리얼이 안 먹는다"에서 몇 시간을 태운다.**

### 5.2 ★ 하늘빛만 드는 자리에서는 노멀을 아무리 세게 줘도 판정할 수 없다

시험용 판을 `(0,0,20000)` 에 띄웠는데 **어느 방향으로 돌려도 밝기가 150~160 으로 같았다**(8방향 실측).
균일한 하늘빛 아래에서는 법선이 바뀌어도 들어오는 빛이 같아 아무 차이가 없다.
주차장 지면 높이(z=300)로 내리니 **63~194** 로 갈렸다(yaw 90 정면광, 225~315 그늘).

릴리프 판정은 **빗각 햇빛(yaw≈155)** 에서 한다. `Tools/plate_sdf/lit_shot.py` 가 그 자리를 재현한다.

### 5.3 ★ 양각을 읽히게 하는 것은 대칭 AO 가 아니라 **아래로 지는 접지 그림자**다

대칭 AO 만 넣었을 때는 초점 안 맞은 테두리로 보였다. 판은 수직이고 해는 늘 위에 있으므로
1.5mm 솟은 글자는 **항상 아래쪽에** 그림자를 만든다 — SDF 를 위로 한 탭 옮겨 읽으면 그대로 나온다.
방향 스윕으로 확인: 위로 읽으면 솟아 보이고, 아래로 읽으면 **파여** 보인다
([방향 스윕](img/20260827_161319_번호판_노멀맵_양각/14_그림자방향_스윕.jpg)).

그림자 경계는 **모따기와 무관하게 날카로워야** 한다. `(Ssh-0.5)/Bevel` 로 나눴더니 모따기를 넓힐 때
그림자까지 번져 드롭섀도처럼 뭉갰다 → 고정 폭 `smoothstep(0.47, 0.53, Ssh)`.

### 5.4 ★ 모따기는 외곽선 **안쪽이 아니라 걸치게** 둔다

안쪽으로만 깎으면 경사면이 전부 검은 글자 위(알베도 0.02)에 놓여 디퓨즈가 0 이라 안 보인다 —
지오메트리 양각이 실패한 것과 **정확히 같은 이유**다. 걸쳐 놓으면 경사면의 절반이 흰 판 위에 와서
직사광에서 바로 읽힌다.

### 5.5 ★ 패키지에서만 드러난 것 둘 — 에디터로는 절대 못 잡는다

첫 쿡 결과가 번호 없이 폴백 위젯으로 떨어졌다. 원인이 둘이었고 **둘 다 심어 둔 로그 한 줄이 곧바로 가리켰다.**

**① 아틀라스 텍스처가 쿡에서 통째로 빠졌다.**

```
LogStreaming: Warning: LoadPackage: SkipPackage: /Game/Actors/Car/Plates/Textures/T_PlateGlyphSDF
              - The package to load does not exist on disk or in the loader
LogTemp: Display: [PlateSDF] 아틀라스=없음 글리프=44 셀=256 폰트=166
```

`UPlateGlyphAtlasSubsystem` 이 경로 문자열로 `LoadObject` 하므로 이 텍스처를 가리키는 **에셋 참조가
하나도 없다.** 쿠커는 참조만 따라가니 안 굽는다. **이 프로젝트가 이미 밟은 함정이다** —
2026-08-16 에 `DT_CarCatalog` 를 JSON 으로 대체한 뒤 차량 메시가 같은 이유로 빠졌었다.
→ 그때의 해법을 그대로: `DefaultGame.ini` 에 `+DirectoriesToAlwaysCook=(Path="/Game/Actors/Car/Plates/Textures")`.

**② 판 앞면 머티리얼은 슬롯 0 이 아니라 슬롯 1 이다.**

```
[CarPlate] Front ... plateMat0=.../M_PlateFrame  plateMat1=.../M_PlateFront
[CarPlate] SDF   ... rt=없음 front=0 back=0 폴백위젯=1/1
```

`CreateDynamicMaterialInstance(0)` 은 **테두리** 머티리얼의 MID 를 만들고 `SetTextureParameterValue`
는 없는 파라미터에 대고 **조용히 아무 일도 안 한다**(실패를 돌려주지 않는다).
→ 슬롯 번호를 박지 말고 **`NumberSDF` 파라미터가 있는 슬롯을 찾는다**. 메시 슬롯 순서가 바뀌어도 따라간다.

에디터에서는 둘 다 안 드러난다 — 에디터는 디스크에서 직접 읽고, 머티리얼 확인은 판 메시가 아니라
머티리얼 자산에 대고 했기 때문이다. **판정은 반드시 패키지 실행 로그로 한다.**

### 5.6 ★ 렌더타깃 자동 밉(`bAutoGenerateMips`)이 **밉을 채우지 않는다** → CPU 로 옮겼다

첫 성공 이후 다음 증상이 나왔다 — **줌 24 이상은 번호가 멀쩡한데 줌 16 이하는 통째로 사라지고,
줌 20 에서만 희미하게 비쳤다.** 계단 모양이 밉 전환을 정확히 가리킨다(트라이리니어가 정상 밉0 과
빈 밉1 을 섞는 구간이 딱 줌 20 이다). `Rt->GetNumMips()` 는 11 을 돌려주는데 **내용이 비어 있었다.**
`bCanCreateUAV = true` 를 켜도 같았다.

축소 자체를 의심할 뻔했으나 **오프라인에서 몇 초 만에 갈렸다** — 같은 합성 결과를 박스 필터로 내리니

```
mip0 1024x256  글자안쪽비율 0.2370      mip3  128x 32  0.2424
mip1  512x128            0.2354      mip4   64x 16  0.2461
mip2  256x 64            0.2373      mip5   32x  8  0.2305
```

**밉5(32×8)까지 멀쩡하다.** 그러니 SDF 축소는 무죄이고 원인은 엔진의 밉 생성이다.

→ 8분짜리 재쿡으로 엔진 내부를 추측하는 대신 **GPU 경로를 버리고 CPU 로 합성한다.**
`UTextureRenderTarget2D` + Canvas → **`UTexture2D` + 직접 만든 밉 체인**.
아틀라스도 UE 텍스처 에셋이 아니라 `Save/Config/plate_glyph_sdf.png` 를 `ImageWrapper` 로 디코드한다.

부수로 두 가지가 같이 해결됐다.
- ①의 `DirectoriesToAlwaysCook` 지시가 필요 없어졌다(에셋을 안 쓴다) → 되돌렸다.
- **`Content/` 가 gitignore 라 fresh clone 에서 아틀라스가 사라지던 문제**도 없어졌다 —
  이제 아틀라스·메트릭 둘 다 `Save/Config/` 에 있고 git 이 추적한다.

교훈: **"밉 단수 11"은 밉이 채워졌다는 증거가 아니다.** 판정은 화면으로 한다.

### 5.7 그 밖에

- **에디터 MCP 툴은 `call_tool` 을 거쳐야 한다.** 전체 이름을 `tools/call` 에 그대로 주면
  `Unknown tool` 로 400 이 나는데, **사유가 응답 본문에만 있어** `urlopen` 예외만 보면 알 수 없다.
- **배열 프로퍼티는 한 번에 통째로 못 넣는다.** Custom 노드 입력 8개를 한 번에 주면
  `ArrayAdd: elements changed alongside the size change; insertion points are ambiguous` 로 거부된다 →
  **한 개씩 늘려야** 받는다.
- **Custom 노드의 기본 출력 이름은 `""` 가 아니라 `return`** 이다.
- **텍스처 스트리밍이 물면 저해상 밉이 올라와** SDF 가 흐려지고 임계 0.5 를 먹인 글자 윤곽이
  울렁거린다. 미리보기 텍스처는 `neverStream=true` 로 둔다(런타임 렌더타깃은 스트리밍 대상이 아니다).
- **한낮 야외 장면에서 emissive 1.0 은 안 보인다.** 디버그로 노멀을 emissive 에 꽂았다가
  "출력이 안 먹는다"로 오진할 뻔했다 — 노출이 태양 기준이라 1 nit 은 묻힌다.
- **git-bash 에서 `/Game/...` 인자는 `MSYS_NO_PATHCONV=1` 없이는 `C:/Program Files/Git/Game/...` 으로 바뀐다.**
- `find_actors` 의 인자 이름은 `name`(부분 일치)이고 `tag`·`actor_type`·`root`·`bounds`·
  `collision_channels` 를 모두 줘야 한다. `CaptureViewport` 는 `captureTransform`·`annotations` 에
  기본값이 없다. `CaptureAssetImage` 는 256×256 이라 1.4텍셀 모따기 판정에는 못 쓴다.
- **판 앞면은 로컬 +Y 다.** 뒤에서 찍으면 검은 판만 나온다.

## 7. 한계 / 미검증

- **판 47px(원래 증상과 같은 축척)에서의 1:1 대조는 못 했다.** 실행 인스턴스가 달라 차량 배치가
  다르고 같은 시야를 재현하지 못했다. 판 78px 까지는 8글자 판독을 확인했다.
- 릴리프 파라미터는 **에디터 뷰포트(빗각 햇빛)** 에서 고른 값이다. 실제 CCTV 화각·거리에서
  다시 봐야 한다 — 특히 원거리에서 그림자가 밉에 먹혀 사라지는 지점을 안 쟀다.
- **극단적 사각**(판을 거의 옆에서 볼 때)은 실루엣이 없어 평평해 보인다. Bump Offset(1탭 패럴랙스)로
  메울 수 있으나 CCTV 화각에서 그 각이 실제로 나오는지 확인하지 않아 넣지 않았다.
- 노멀 기울기에 **가로/세로 18% 이방성**이 남아 있다(텍셀이 0.51 vs 0.43mm). 0.6mm 짜리 모따기라
  눈에 안 보인다고 판단해 보정하지 않았다.
- `M_PlateFront` 의 옛 `Text` 텍스처 파라미터(T_Emissive)는 **연결만 끊고 남겨 뒀다.**
  안 쓰이면 컴파일에서 빠지고, 외부에서 세팅해도 아무 일이 없다.
- 실물 치수는 **사진 1장**에서 잰 값이다. 국토부 고시 원문의 수치와 대조하지 않았다.
- 필름식 번호판이 실제로 양각인지는 확인하지 못했다(3.1).
- 원격 GPU 베이크(3090)는 별도 문서로 진행 중이다.
