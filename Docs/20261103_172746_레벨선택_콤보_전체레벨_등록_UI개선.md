## 1. 결과 요약

- 콤보 항목이 3개에서 11개가 됐다. 패키지에 쿡된 주차장 레벨 10개와 기본맵이다.

- 콤보 UI 를 고쳤다.

  - 항목은 이름과 설명(`실내 · 65면 · 데이터 없음`) 두 줄이다.
  - 현재 레벨 항목에 강조색 점·강조색 이름·「현재」 표시를 단다.
  - 목록 높이는 420 으로 묶고, 넘치면 스크롤한다.

## 3. 동대문 = `LV_Park_05` 근거

PM 이 기준으로 준 「40면·13그룹」과 **면 수는 맞지 않는다**. LV_05 는 65면·15그룹이다. 그런데도 등록한 근거는 아래 세 가지다. 근거가 약하다고 보면 이 항목만 빼면 된다(config 한 줄).

1. **소거법**
   - 레거시 `WBP_HomePanel` 이름 10개 중 「지하」는 동대문과 익산 둘뿐이다.
   - 실내 레벨도 LV_05 와 LV_09 둘뿐이다.
   - 익산은 LV_09 로 이미 확정돼 있다(면 수 83 일치). 남는 실내 레벨이 LV_05 하나다.
2. **카메라 배치가 평행이동 하나로 맞는다**
   - `CamPos_40Face_동대문.json` 의 카메라 3대는 UE 축(x = Unity.z, y = Unity.x)으로 (6.5, −0.8), (−10.2, −0.7), (−26.4, −0.8) m 이다.
   - y 를 +52.1 m 옮기면 (6.5, 51.3), (−10.2, 51.4), (−26.4, 51.3) 이 된다.
   - LV_05 의 `BP_Camera` 액터 중 (7.3, 51.3), (−10.3, 51.3), (−26.4, 51.3) 과 오차 0.8 / 0.1 / 0.0 m 로 겹친다. x 는 옮기지 않았다.
   - 카메라 높이 3.5~4.0 m 도 지하 천장 높이다. 실외 레벨 카메라는 6.3~6.5 m 다.
   - 다른 레벨에 회전·거울까지 허용해 같은 정합을 해 보면 최대 오차가 12~23 m 다.
     - 예외는 LV_09 로 0.86 m 다. 다만 거울과 90° 회전이 필요하다.
     - 일직선 3점이라 기둥 줄이 비슷한 지하 레벨에는 잘 맞는다. 이 근거만으로는 약하다.
3. **면 배치**
   - 동대문 프리셋 40면의 중심을 같은 평행이동(−0.3, +49.6 m)으로 옮기면 모두 LV_05 면에서 4.2 m 안에 든다.
   - 그중 20면은 1 m 안이다. 나머지는 대부분 면 한 칸(2.3~2.9 m) 어긋난다.
   - Unity 데이터가 레벨 일부(카메라 7대 중 3대가 보는 범위)만 다룬다고 보면 40 대 65 의 차이가 설명된다. **추정이다.**

## 5. 레벨별 `hide_actors`

### 문제

- 최상위 `hide_actors` 는 `["StaticMeshActor_188", "StaticMeshActor_185"]` 다. 서신(LV_01)의 소나무·참나무를 숨기려고 넣은 것이다.
- 그런데 이 목록은 모든 레벨에 적용된다. 새 레벨에서 같은 이름의 다른 액터가 숨겨졌다. 작업본 로그와 인벤토리로 확인했다.

| 레벨 | 숨겨진 것 |
|---|---|
| LV_05 | 천장 배관 `wdkmabe_tier_21`, 환기 덕트 `SM_Air_Vent_Duct_31` |
| LV_09 | 천장 조명 `Luce_Soffitto…40`, 천장 부재 `vghoacydw…759` |
| LV_04 | 비닐봉지, 건물 소품 |
| LV_06 | 변압기 `SM_Transformer3` |
| LV_08 | 주차금지 표지 `SM_NoParking11` |

### 수정

- `levels[]` 항목에 `hide_actors` 를 받는다(`FPark3DLevelOption::HideActors`, `TOptional<TArray<FString>>`).
  - 키가 없으면 최상위 값을 유지한다.
  - `[]` 면 아무것도 숨기지 않는다.
- `ApplyLevelOverrides` 가 이 값을 덮는다. `APark3DGameMode::ApplyConfigHiddenActors` 는 이제 override 를 거친다.
- 새로 넣은 8개 항목에는 `"hide_actors": []` 를 넣었다. 서신·객리단·기본맵은 키가 없어 지금과 같다.
- 정본 교체 때 `levels[]` 만 바꿔도 이 효과가 같이 들어간다. 최상위 값은 그대로 둔다.

### 함정 — 콤보 항목 위젯에 브러시 위젯을 쓰면 GC 뒤에 죽는다

- 첫 판은 현재 표시 점을 `UBorder`(둥근 상자 브러시)로 그렸다. 쿡된 작업본이 레벨 로드 약 45초 뒤 크래시했다.
  - `EXCEPTION_ACCESS_VIOLATION reading 0xffffffffffffffff`
  - 콜스택 `SButton::OnPaint → … → SBox → SBorder::OnPaint → FSlateDrawElement::MakeBox`
- 원인: `UComboBoxString` 은 `OnGenerateWidgetEvent` 가 준 `UWidget` 에서 Slate 위젯만 가져가고, UObject 는 아무도 붙잡지 않는다.
  - `UBorder`·`UImage` 는 브러시를 UObject 안에 둔다. Slate 는 그 포인터를 그린다.
  - 그래서 GC 가 UObject 를 지우면 해제된 메모리를 그리게 된다.
  - 텍스트 블록은 값을 복사해 가서 괜찮다. 다른 패널 콤보들도 텍스트만 쓴다.
- 수정: 점을 글자 「●」로 바꿨다. GC 가 한 번 돈 뒤(로그 확인) 콤보를 열고 레벨을 바꿔도 크래시가 없었다.

- 정본 `Save\Config\config_pmaker.json` 은 `levels[]` 만 바꾼다. 시작 레벨 `"level": "Levels/LV_Park_01"` 은 유지한다.
- 작업본 config 는 포트를 13540/13700/13711~13750 으로 바꾼 복사본이다. 정본에 그대로 복사하지 않는다.
