## 2. 확정 사항 (선결 Q 해소)

### Q4 — 도색 색 파라미터 = `BaseColorFactor` ✅
차량 도색 슬롯은 **머티리얼 슬롯명 `"carpaint"`**(차종별 슬롯 인덱스 상이, 슬롯명으로 검색). 머티리얼은 glTF `MI_Default_Opaque_DS` 기반 `MaterialInstanceConstant` → 색 벡터 파라미터 **`BaseColorFactor`**. `UCarColorComponent`는 carpaint 슬롯에 동적 MID를 생성해 이 값을 설정/복원한다.

### Q5 — 메시 정면축 보정 = **+180°** ✅ (스크린샷으로 확정, 초기 가정 -90 폐기)
- 임포트 차량 메시는 **길이축이 로컬 Y**, yaw=0일 때 **정면이 -Y**(기준 차량 탑다운 검증).
- Unity rotY=0(=Unity +Z 정면=UE +Y)에 맞추려면 `MeshForwardYawOffset = 180`.
- 검증: 실제 23대를 offset별로 배치 후 탑다운 비교 — **offset=180 → 주차면에 수직으로 나란히 정상 배치**(`_workspace/car_top_offset180.png`), offset=-90 → 줄 따라 앞뒤로 오배치. `CarActor.h` 기본값을 180으로 수정.

`unity/CarObject/CarPos_23Num_서신.json`(23대)을 라이브러리와 동일 수식으로 배치, prefabId 1→기아_모닝 / 2→현대_쏘나타, preset별 색상(빨강/파랑/은색). 탑다운 결과 **3개 그룹이 주차면에 수직으로 나란히 정렬**된 정상 주차장 형태 확인(`_workspace/car_top_offset180.png`). 도색(BaseColorFactor)도 그룹별로 정상 적용. 검증 액터는 전부 정리.

## 6. DT_CarCatalog

- 차량 23종을 행으로 등록: `Idx`(1~23, **이름순 순번**), `Type`(이름 기반 추정), `PrefabName`, `Mesh`(소프트오브젝트).
- CSV 임포트로 생성 — enum/소프트경로 정상 파싱 확인(예: Car_6=기아_모닝, Type=Small, Mesh 정상).
- ⚠ **주의**: 여기서 `Idx`는 이름순 순번이며 **Unity JSON의 `prefabId`와 매핑이 다를 수 있음**. 실제 prefabId↔차종 대응표(Unity 원본 카탈로그)가 확보되면 행 Idx/순서를 재정렬해야 함 → §8 후속.
