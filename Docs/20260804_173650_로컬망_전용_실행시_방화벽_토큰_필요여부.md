## 1. 결론

| 항목 | 필요 여부 | 현재 상태 |
|------|-----------|-----------|
| 인증 토큰 | **필수** — 없으면 LAN의 다른 PC는 100% 401 | ✅ `Token=apark3d` 설정됨 |
| 인바운드 방화벽 허용 | **필수** — 없으면 다른 PC에서 연결 자체가 안 됨 | ✅ 규칙 `Park3D RPC 13510` (TCP 13510, Inbound, Allow, Profile=Any) 존재 |
| 외부 바인드 | 필수 | ✅ `BindAddress=any` → 실측 `0.0.0.0:13510` 리슨 중 |

**즉, 둘 다 필요하고, 둘 다 이미 구성되어 있다.** 추가 작업 없이 LAN에서 접속 가능하다.

## 2. 토큰이 "LAN 전용이어도" 필수인 이유

`Park3DRpcAuth::Authorize` (`RpcAuth.cpp:89-113`)의 판정 순서:

1. `Origin` 헤더가 있으면 → **무조건 거부** (브라우저 fetch/XHR 차단)
2. 서버 토큰이 설정돼 있으면 → **루프백이어도 토큰 검사**
3. 서버 토큰이 비어 있으면 → **루프백(127.x/::1)만 허용**, 그 외 피어는 `DeniedNotLoopback`

3번이 핵심이다. "LAN이니까 토큰 없이 열어두자"는 선택지가 **아예 없다.**
토큰을 비우면 바인드가 `any`여도 다른 PC의 요청은 전부 401이 된다.
기동 로그도 이 경우 Error로 경고한다:

```
[RPC] 외부 바인드(any)인데 토큰 미설정 — 루프백 외 모든 요청이 401 로 거부됩니다.
```

정상 구성일 때의 기동 로그:

```
[RPC] JSON-RPC 서버 시작: http://0.0.0.0:13510/rpc (bind=any, auth=token, method 79개)
```

### 토큰 전달 방법

| 경로 | 전달 방식 |
|------|-----------|
| `/rpc`, `/rpc/catalog` | 헤더 `X-Park3D-Token: apark3d` |
| `/stream` (MJPEG) | 헤더 우선, 없으면 `?token=apark3d` 쿼리 폴백 (`<img>`는 헤더를 못 붙임) |
| `/health` | 인증 불필요 (생존 확인용) |

### 토큰 관련 주의

- 허용 문자셋은 `[A-Za-z0-9_-]` **뿐**이다. 콤마·괄호·공백을 넣으면 커맨드라인(`FParse`)은 절단하고
  ini는 원문을 보존해 서버/클라이언트 토큰이 어긋나 **영구 401**이 된다. 토큰 값은 로그에 찍히지 않아 추적이 어렵다.
- 현재 `apark3d`는 `DefaultGame.ini`에 **커밋되어 있다**(같은 파일 주석은 커밋하지 말라고 명시).
  사설망 한정이면 실질 위험은 낮지만, 값이 공개 이력에 남는다는 점은 인지할 것.
  바꾸려면 ini를 비우고 기동 시 `-RpcToken=<값>`으로 주는 편이 낫다(커맨드라인이 ini보다 우선).

## 3. 방화벽

Windows Defender 방화벽은 인바운드를 기본 차단하므로 규칙이 없으면 LAN에서 TCP 연결 자체가 실패한다
(401이 아니라 **연결 타임아웃/거부**로 나타난다 — 증상으로 토큰 문제와 구분 가능).

실측된 기존 규칙:

| DisplayName | Direction | Action | Protocol/Port | Profile | Enabled |
|-------------|-----------|--------|---------------|---------|---------|
| Park3D RPC 13510 | Inbound | Allow | TCP 13510 | **Any** | True |

포트 기반 규칙이므로 에디터(UnrealEditor.exe)·패키지(Park3D.exe) 어느 쪽으로 기동해도 동작한다.

### 선택적 강화 (LAN 전용이 확정이라면)

`Profile=Any`는 **공용(Public) 네트워크에 붙었을 때도** 13510을 연다.
카페/테더링 등에서 노출을 원치 않으면 Private/Domain으로 좁힐 수 있다(호스트 상태 변경이므로 별도 승인 필요):

```powershell
Set-NetFirewallRule -DisplayName "Park3D RPC 13510" -Profile Private,Domain
```

## 4. 증상별 진단 표

| 증상 | 원인 | 확인 방법 |
|------|------|-----------|
| 연결 타임아웃 / 거부 | 방화벽 차단, 또는 Park3D 미실행 | `Get-NetTCPConnection -State Listen -LocalPort 13510` |
| `/health`는 되는데 `/rpc`가 401 | 토큰 누락/불일치 | 서버 로그 `DeniedBadToken` |
| 루프백은 되는데 외부만 401 | 토큰 미설정 (무토큰 모드) | 서버 로그 `DeniedNotLoopback` |
| 브라우저 JS에서만 401 | `Origin` 헤더 → 무조건 거부 | 서버 로그 `DeniedBrowserOrigin` |
| 외부에서 아예 안 붙음, 로그는 `bind=localhost` | `-RpcPort=`로 포트를 바꿔 `ListenerOverrides`와 불일치 → 조용히 localhost 폴백 | 기동 로그 `bind=` 값 |

## 5. 접속 예시 (다른 PC에서)

```bash
# 생존 확인 (무인증)
curl http://192.168.0.125:13510/health

# JSON-RPC 호출
curl -X POST http://192.168.0.125:13510/rpc \
  -H "Content-Type: application/json" \
  -H "X-Park3D-Token: apark3d" \
  -d '{"jsonrpc":"2.0","id":1,"method":"system.health"}'

# MJPEG 스트림 (<img src=...> 도 동일 URL)
http://192.168.0.125:13510/stream?cam=Cam1&fps=10&token=apark3d
```

> 호스트 IP `192.168.0.125`는 2026-08-04 실측값이다. DHCP로 바뀔 수 있으므로 접속 실패 시 `ipconfig`로 재확인할 것.
