# WASD 이동을 지면(월드 XY) 기준으로 변경

- 날짜: 2026-08-14
- 브랜치: `feat/wasd-ground-move` (워크트리 `.claude/worktrees/wasd-ground-move`)
- 대상: `Park3D/Source/Park3D/ParkFlyPawn.h`, `Park3D/Source/Park3D/ParkFlyPawn.cpp`

## 1. 요구사항

WASD 는 **월드 바닥 기준**으로 화면에 보이는 앞뒤좌우로 이동해야 한다. 이동 방향의 **업(Z) 성분은 0**
이며, 카메라 로컬(피치 포함) 방향이 아니다.

## 2. 기존 동작과 문제

`AParkFlyPawn` 은 `ADefaultPawn` 을 상속하고, 엔진 기본 입력 바인딩을 그대로 쓴다
(`ADefaultPawn::InitializeDefaultPawnInputBindings` — W/S·상하 방향키 → `DefaultPawn_MoveForward`,
A/D → `DefaultPawn_MoveRight`, Q/E → `DefaultPawn_MoveUp`).

엔진 기본 `MoveForward` 는 **컨트롤 회전 전체**(피치 포함)의 X 축으로 이동한다.

```
AddMovementInput(FRotationMatrix(ControlRotation).GetScaledAxis(EAxis::X), Val)
```

따라서 아래를 내려다보는 시점(주차장을 조감하는 이 앱의 기본 시점)에서 W 를 누르면 앞으로 가는 게
아니라 **바닥으로 파고들고**, 올려다보면 떠오른다. 좌우(`MoveRight`)는 롤이 0 인 동안에는 Z 성분이
0 이라 원래도 지면 평면이지만, 요구사항을 코드에 명시적으로 못 박기 위해 함께 오버라이드했다.

## 3. 변경 내용

`AParkFlyPawn` 에서 `MoveForward`/`MoveRight` 를 오버라이드하고, 이동축을 **요(yaw)만 남긴 회전**에서
새로 만든다.

```cpp
FVector AParkFlyPawn::GetGroundMoveAxis(EAxis::Type Axis) const
{
    const FRotator GroundRot(0.0f, Controller ? Controller->GetControlRotation().Yaw : GetActorRotation().Yaw, 0.0f);
    return FRotationMatrix(GroundRot).GetScaledAxis(Axis);
}
```

- 전방(`EAxis::X`) = `(cos yaw, sin yaw, 0)`
- 우측(`EAxis::Y`) = `(-sin yaw, cos yaw, 0)`
- 두 축 모두 **Z 성분 0**.

### 왜 "시선 벡터 투영"이 아닌가

흔한 구현은 시선 벡터의 Z 를 0 으로 만들고 정규화하는 것이다. 이 방식은 **수직으로 내려다볼 때
(피치 −90°) 전방 벡터 길이가 0 이 되어 W/S 가 죽는다.** 이 앱은 위에서 내려다보는 시점을 상시 쓰므로
치명적이다. 요만 남긴 회전에서 축을 만들면 **어떤 피치/롤에서도** 유효한 지면 축이 나온다.

## 4. 유지된 기존 동작

- **RMB 게이트**: 오버라이드한 `MoveForward`/`MoveRight` 도 결국 `AParkFlyPawn::AddMovementInput` 을
  거치므로, "마우스 오른쪽 버튼을 누른 동안에만 이동"이 그대로 유지된다.
- **Left Alt 패닝**: Alt 보유 중 이동 차단도 같은 경로라 유지된다.
- **높이 이동**: Q/E(`MoveUp_World`)는 손대지 않았다 — 수직 이동은 그쪽이 전담한다.
- **휠 줌**: `ZoomAlongView` 는 여전히 **시선 방향**(피치 포함)으로 전/후진한다. 요구사항은 WASD 에
  대한 것이라 줌은 그대로 뒀다.

## 5. 부수 효과

상/하 방향키가 `DefaultPawn_MoveForward` 축에 함께 물려 있어(엔진 기본 매핑) 방향키 전후진도 같이
지면 기준이 된다. Alt 보유 중에는 기존대로 패닝이 전담한다.
