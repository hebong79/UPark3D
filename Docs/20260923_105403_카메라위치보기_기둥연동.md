# 카메라 위치 보기 — 구 아래 기둥도 같이 켜고 끄기

## 요청
SettingManager 「카메라 컨트롤 › 위치(XYZ) › 카메라 위치 보기」 체크박스를 켜고 끌 때 구(표식) 아래의 작은 기둥도 같이 보이거나 숨겨지게 한다.

## 원인
- 체크박스는 RPC `cam.setMarks {enabled}` 를 부른다. 이 RPC 는 카메라 눈 아래 0.8 m 에 놓는 **구 액터(`CamMark` 태그)** 만 만들고 지웠다.
- 바닥의 작은 기둥은 표식이 아니다. `APTZCameraActor::PoleMesh`(엔진 실린더, 0.1×0.1×1 m, 바닥 Z 고정)이고 카메라 액터에 처음부터 붙어 있다. 그래서 체크박스와 상관없이 늘 보였다.

## 변경
`Source/Park3D/Rpc/Modules/CamRpcModule.cpp` — `cam.setMarks` 처리기에서 표식을 다시 만든 뒤 `Mgr->ShowAllPoles(bMarksEnabled)` 를 부른다(이미 있던 `ACameraControlManager::ShowAllPoles` → `APTZCameraActor::SetPoleVisible` 사용).

- 기둥을 숨기면 충돌도 꺼진다(`SetPoleVisible` 의 기존 동작). 따라서 끈 상태에서는 앱 안 카메라 패널의 **폴대 클릭 선택(TracePole)도 되지 않는다.**
- 기동 직후 상태는 바꾸지 않았다. 기둥은 보이고 표식은 꺼진 상태로 시작한다. 기둥은 `cam.setMarks` 를 한 번 부른 뒤부터 체크박스를 따른다. 기동할 때 기둥까지 숨기면 사용자가 아무것도 건드리지 않았는데 앱 안 폴대 피킹이 막히기 때문이다.

## 알려진 한계
- `cam.setMarks false` 뒤에 `cam.loadPosFile` 등으로 카메라가 **새로 생기면**, 새 카메라의 기둥은 기본값(보임)으로 나온다. 체크박스를 한 번 더 토글하면 맞춰진다.
- 앱 안 패널의 `bShowPole` 기본값(false, 버튼 "폴대 보기")과 실제 기둥 기본 상태(보임)는 원래부터 서로 다르다. 이번 범위 밖이라 손대지 않았다.

## 검증
- 게임 타깃 빌드 `Result: Succeeded`.
- 작업본 `Package/Work13540`(RPC 13540, exe 만 교체)에서 LV_Park_01 카메라 1 근처로 메인 뷰를 옮긴 뒤 `cam.setMarks` 를 on → off → on 순서로 부르고 매번 창을 캡처했다. on 에서는 구와 기둥이 모두 보였고, off 에서는 둘 다 사라졌으며, 다시 on 에서는 둘 다 돌아왔다(`Docs/shots/20260923_cam_marks_pole/`).
- 정본(`Package/Windows`, 13510)은 교체하지 않았다. 웹 체크박스를 직접 눌러 보는 확인도 하지 않았다(RPC 경로는 같다).
