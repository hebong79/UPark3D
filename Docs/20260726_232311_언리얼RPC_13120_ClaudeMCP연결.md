# 언리얼 Park3D RPC 서버(13120)를 Claude CLI MCP로 연결

작성일: 2026-07-26
대상: `Park3D/Source/Park3D/Rpc/RpcServerSubsystem.*`, `park3d-rpc-mcp/`, `.mcp.json`

---

## 1. 요구사항

Park3D의 JSON-RPC 서버(기본 13110)를 **13120 포트로 실행**하고, 그 서버를 **Claude CLI가 MCP 툴로 호출**하게 한다.

## 2. 왜 13110 서버에 MCP를 직접 못 붙이나 (핵심)

Park3D 서버는 **JSON-RPC 2.0을 평문 HTTP(`POST /rpc`)로** 노출한다(도메인 메서드 `car.list` 등).
Claude CLI의 MCP(`--transport http`)는 이름만 JSON-RPC로 같을 뿐 **MCP 프로토콜**(`initialize` 핸드셰이크 → `tools/list` → `tools/call`, 세션/SSE)을 요구하는 **다른 규약**이다.

```
❌ claude mcp add --transport http park3d http://localhost:13120/rpc   # MCP 핸드셰이크 실패
```

→ **얇은 MCP 브리지**가 필요하다. Unity 원본도 동일 방식(`unity_rpc` / `unity_rpc_catalog` 툴 2개)이었다.

## 3. 변경 사항

### 3-1. 포트 결정(코드) — Config 파일 + 커맨드라인, 비파괴적

`RpcServerSubsystem::Initialize`에서 포트를 아래 **우선순위**로 결정한다. **코드 기본값 13110은 유지**하고 런타임에만 덮어쓴다. `RegisterSystemMethods`가 `Port`를 캡처(`system.health`)하므로 그 **이전**에 적용.

1. 커맨드라인 `-RpcPort=NNNN` (최우선)
2. **Config 파일** `Config/DefaultGame.ini` → `[RpcServer] Port` (GConfig)
3. 코드 기본값 13110

```cpp
// RpcServerSubsystem.cpp — Initialize() 내, Super::Initialize 직후
int32 ConfigPort = 0;
if (GConfig && GConfig->GetInt(TEXT("RpcServer"), TEXT("Port"), ConfigPort, GGameIni) && ConfigPort > 0 && ConfigPort <= 65535)
{
    Port = ConfigPort;   // Config 파일 값
}
int32 CmdPort = 0;
if (FParse::Value(FCommandLine::Get(), TEXT("RpcPort="), CmdPort) && CmdPort > 0 && CmdPort <= 65535)
{
    Port = CmdPort;      // 커맨드라인이 최우선
}
```

추가 include: `Misc/CommandLine.h`, `Misc/Parse.h`, `Misc/ConfigCacheIni.h`.

**Config 파일** — `Park3D/Config/DefaultGame.ini`:

```ini
; Park3D JSON-RPC 서버 리슨 포트. 커맨드라인 -RpcPort= 가 있으면 그쪽이 우선.
[RpcServer]
Port=13120
```

→ cmdline 없이 `-game`/PIE로 실행해도 **13120**이 적용된다(포트 변경은 이 파일 숫자만 수정, 재빌드 불필요).

### 3-1-b. 부수 수정(빌드 블로커) — 유니티 빌드 심볼 충돌

증분(2회차) 빌드에서 유니티(jumbo) 병합 시 익명 네임스페이스 파일로컬 헬퍼 **이름 중복**으로 C2084 발생:
`GetCamById`(CamRpcModule.cpp + MeasureRpcModule.cpp), `NotImplemented`(CamRpcModule.cpp + RandomRpcModule.cpp). 첫 빌드는 adaptive-unity가 해당 파일을 제외해 우연히 통과했었다. Measure/Random 쪽만 접두어로 유일화(`Measure_GetCamById`, `Random_NotImplemented`)해 해소. **RPC 모듈 신규 작성 시 파일로컬 헬퍼 이름은 모듈 접두어로 유일화할 것.**

### 3-2. MCP 브리지 — `park3d-rpc-mcp/server.py`

Python `FastMCP`(mcp>=1.2, `unreal-mcp`와 동일 스택). PEP723 inline 의존성으로 `uv run` 시 자동 설치. 표준 라이브러리 `urllib`만으로 13120에 HTTP 왕복.

노출 툴 2개(도메인 메서드를 개별 툴로 만들지 않음 → 서버에 메서드 추가돼도 브리지 무수정):

| 툴 | 동작 |
|---|---|
| `park3d_catalog()` | `GET /rpc/catalog` → 등록 메서드 목록 |
| `park3d_rpc(method, params)` | `POST /rpc` → 단건 JSON-RPC 호출, `{ok, result}` 또는 `{ok:false, error}` |

베이스 URL은 `PARK3D_RPC_URL` 환경변수(기본 `http://localhost:13110`)로 지정.


## 5. 사용 방법 (Claude 세션에서)

1. **서버가 실행 중**이어야 한다(위 2번, 13120 리슨). 없으면 브리지 툴이 연결 실패 error 반환.
2. **최초 1회 승인**: project 스코프 MCP는 보안상 승인 대기 상태다. 대화형 `claude` 실행 → `park3d-rpc` 승인.
3. 이후 자연어로 요청하면 Claude가 툴을 호출한다. 예:
   - "park3d 카탈로그 보여줘" → `park3d_catalog()`
   - "1번 프리셋 차량 목록" → `park3d_rpc("car.list", {"presetId":1})`
   - "프리셋 생성" → `park3d_rpc("preset.create", {"offset":{"x":0,"z":5},"faceCount":5,"camIdx":1})`

## 6. 영향도

- **코드 변경 범위**: `RpcServerSubsystem.cpp` 1곳(Initialize)만. 기존 메서드/모듈/기본 포트(13110) 로직 무수정 → 회귀 위험 낮음.
- **신규 파일**: `park3d-rpc-mcp/server.py`(독립), `.mcp.json`에 `park3d-rpc` 항목 추가(기존 `unreal` 항목 유지).
- **좌표 규약**: 브리지는 값을 변환하지 않고 그대로 전달. z=높이 규약은 서버/호출자 책임.
- **주의**: 도메인 메서드(car/preset/cam 등) 대부분은 월드/맵과 매니저 액터가 로드된 상태를 요구한다. `system.*`은 맵 무관.

## 7. 서버 종료

실행한 `UnrealEditor.exe -game` 창을 닫거나 프로세스를 종료하면 서버(13120)도 내려간다.
