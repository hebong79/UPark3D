## 2. 무엇을 바꿨나 (`Tools/usd_export/run_export_env.py` 만, 17줄 +/12줄 −)

1. `building` 을 `CATEGORIES` 에 넣고 `build_items` 의 제외 조건(`("building","skip")`)에서 뺐다. `classify` 의 note 도 "건물(제외)" → 실제 내용으로. `skip`(UDS 하늘·`SM_CameraPyramid`) 은 그대로 제외.
2. **slug 충돌 처리**를 추가했다(§3-1). 충돌한 것만 부모 폴더를 접두사로 붙인다.

`export_env.py`·`inventory_level.py`·차량 도구는 무수정. 인벤토리(`_inventory.json`, 09-04 14:19)는 다시 뽑지 않았다 — 건물 59종은 이미 그 안에 있었고 분류만 바뀌었다.

실행:
```powershell
# 1) export + wrapper + 실측 (pxr 있는 파이썬으로)
uv venv <scratch>\usdvenv --python 3.13 ; uv pip install usd-core --python <scratch>\usdvenv\Scripts\python.exe
<scratch>\usdvenv\Scripts\python.exe Tools/usd_export/run_export_env.py --only building
```
시스템 파이썬(3.13, pxr 없음)으로 돌리면 export·wrapper 까지만 되고 노멀 override·실측이 빠진다(`[measure] pxr(usd-core) 없음`). 이전 세션이 만든 측정용 venv 는 그 세션의 스크래치에 있어 지금은 없다 — 매번 새로 만드는 데 1분이면 된다.

`--only building` 은 출력 루트의 `_job/_report/_summary/_classification.json` 을 **덮어쓴다**. 환경 120종 실행 기록은 돌리기 전에 `_env120_*.json` 으로 복사해 뒀다.

## 3. 함정과 판단

### 3-1. 같은 이름의 에셋이 두 폴더에 있으면 뒤의 것이 앞의 것을 덮는다
첫 실행 결과표에 `sm_a07_3` 이 **두 번** 나왔고 두 행의 실측값이 같았다(8.00×0.30×4.00 m, 86 삼각형). 폴더는 58개.

| 에셋 | 실체 | 배치 |
|---|---|---|
| `Building/Park_01/A07/SM_A07_3` | 2삼각형 평면 4×3 m, `MI_FlutedWall_002` | `BP_Building10` ×13 |
| `Building/Park_01/A11/SM_A07_3` | 유리 프레임 8×0.3×4 m, 86삼각형, `MI_Frame_003/MI_Brick_023/MI_Glass_002` | `BP_Building26` ×6 |

slug 가 에셋 **이름**만으로 만들어져 둘 다 `building/sm_a07_3/` 에 쓰였고, 뒤에 export 된 A11 이 A07 의 usdc 를 덮었다(report 는 둘 다 ok — 파일 실물이 있으니). 환경 120종·차량 23종은 이름이 전부 유일해서 드러나지 않았다. 수정: slug 를 만든 뒤 중복을 찾아 **충돌한 것만** `<부모폴더>_<이름>` 으로(`a07_sm_a07_3`, `a11_sm_a07_3`). 나머지 57종의 slug·폴더는 그대로라 기존 참조가 안 깨진다. 재실행 전 덮인 `sm_a07_3` 폴더는 지웠다.

교훈: **결과표 행 수 = 출력 폴더 수**인지 세어 볼 것. report 의 ok 카운트는 덮어쓰기를 못 잡는다.

### 3-2. 건물 유리(`MI_Glass_002`)는 차량 유리 문제가 없다
차량은 유리 7종이 Thin Translucent 라 베이커가 값을 못 뽑아 전부 0 이었다(#272). 건물 유리는 UE 에서 **불투명 재질**이다 — 베이킹 결과가 BaseColor/Metallic/Roughness 텍스처 3장이고 opacity 입력 자체가 없다. `fix_zero_glass` 는 39개 wrapper 어디서도 발동하지 않았다(`glass_fixed: []`). Omniverse 에서 투명하게 보이지 않을 것이고, 그건 UE 화면과 같은 것이라 손대지 않았다.

### 3-3. 노멀 상수 결함은 그대로 재현
39종 79재질에서 `normal = (0.498,-0.498,1)` 상수(UE 5.8 베이커 결함, #272)가 나와 wrapper 가 `(0,0,1)` 로 덮었다. 2삼각형 평면 20종은 재질이 1개이고 노멀 입력이 텍스처라 해당 없음.

### 3-4. 삼각형 불일치 2종
| slug | UE `get_num_triangles(0)` | USD |
|---|---:|---:|
| `sm_a05_1` | 817 | 4,640 |
| `sm_a09_8` | 304 | 314 |

환경 120종 때의 규칙(불일치 = Nanite 폴백 vs 소스)과 같은 패턴으로 보이지만 인벤토리에 Nanite 플래그가 없어 **추정**이다. 나머지 57종은 정확히 일치.

### 3-5. `SM_None` — 크기 0×0×3 m 의 2삼각형 메시가 824 인스턴스
`Building/Default/Meshs/SM_None`, 재질 `WorldGridMaterial`(엔진 기본). 바운즈가 x·y 0 이라 화면에 안 나오는 자리표시(빈 벽 슬롯)로 보인다. 21개 액터가 쓰므로 뺄 근거가 없어 그대로 뽑았다. Omniverse 에서 824개를 깔 이유는 없으니 **레벨 조립 때 건너뛰면 된다**.

### 3-6. 벽체는 부품이지 건물이 아니다
59종 전부 3~8 m 폭·2.2~4 m 높이의 한 층짜리 벽/창/문 모듈이다. 건물 한 채는 `BP_Building*` 이 ISM 으로 수십~수백 개를 조립한 것이라, Omniverse 에서 건물을 다시 세우려면 `_inventory.json` 의 액터별 인스턴스 변환(월드 위치·회전·스케일)이 필요하다. 이번 범위는 에셋 단위 변환까지이고 조립(레벨 export)은 하지 않았다. 도로 슬래브·보도·데칼과 같은 한계다.

## 5. 미검증 / 남은 것

- **화면 전부 미검증**(Omniverse 렌더 없음): 벽돌·프레임 색, 노멀 override 효과, 유리 불투명 표현.

- `_summary.json` 은 이번 실행(건물 59종)으로 덮였다. 환경 120종 기록은 `_env120_summary.json` 등 4개 백업본.
