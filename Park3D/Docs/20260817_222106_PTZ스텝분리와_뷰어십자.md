# PTZ step 분리 + 카메라 뷰어 중앙 십자

- 날짜: 2026-08-17
- 브랜치: `feat/ptz-step-and-crosshair`
- 요청: ① step 을 Pan/Tilt 용과 Zoom 용 둘로 나눌 것 ② 카메라 뷰 패널 중앙에 십자 표시
- 결과: 둘 다 화면으로 확인 완료.

## 1. step 을 둘로

Pan/Tilt 는 도(°), Zoom 은 배율(1~36)이라 단위가 다르다. 하나로 묶으면 한쪽이 항상 어긋난다 —
Pan 에 맞춘 2/초를 Zoom 에 쓰면 한 번 눌러도 끝까지 튄다.

| 필드 | 대상 | 기본값 |
|---|---|---|
| `Field_PtzStep` | Pan / Tilt | 2 (도/초) |
| `Field_PtzStepZoom` | Zoom | 0.5 (배율/초) |

PTZ 패드는 C++ 이 런타임에 만들므로(WBP 무수정) 입력칸 한 줄을 더 붙이는 것으로 끝난다.
`TickPtzMove` 가 Pan/Tilt 에는 `GetPtzStep()`, Zoom 에는 `GetPtzStepZoom()` 을 쓴다.

## 2. 뷰어 중앙 십자

`NativePaint` 에서 그린다. 이미 외곽 프레임을 같은 방식으로 그리고 있어 붙이기만 하면 됐다.

**위젯을 얹지 않은 이유** — 처음엔 `Img_View` 를 `Overlay` 로 감싸 그 위에 선 이미지를 놓으려 했다.
그러면 `Img_View->Slot` 이 `OverlaySlot` 이 되는데, `ApplyViewSize` 와 드래그·리사이즈가
`Cast<UCanvasPanelSlot>(Img_View->Slot)` 에 의존한다. 크기 조절과 이동이 통째로 깨진다.

### 두 번 헛짚었다

**① `UPROPERTY` 로 색·두께를 노출했다.** 이 파일에는 이미
"쿠킹된 WBP 의 C++ 베이스에 UPROPERTY 를 추가하면 패키지가 Bad export index 로 즉사한다"
(CLAUDE.md 2026-08-12)는 경고가 PTZ 패드 참조에 달려 있었는데 그대로 반복했다.
→ `static constexpr` 상수로 되돌렸다.

**② 안 보이는 원인을 좌표 문제로 의심했다.** 실제로는 색 문제였다.
빨간색으로 바꿔 보니 처음부터 정확한 자리에 그려지고 있었고, 흰색 75% 가 밝은 아스팔트에 묻혔던 것이다.
→ 어두운 테두리(검정 55%, 두께+2)를 깔고 그 위에 밝은 심(흰색 95%)을 얹는 이중선으로 해결.
어느 배경에서도 읽힌다.

**교훈: "안 보인다"는 위치·조건보다 대비를 먼저 의심할 것.** 진단용으로 원색을 한 번 칠해 보면
좌표 문제인지 색 문제인지 즉시 갈린다.

## 3. 검증

`-game` 1900×1000 으로 띄워 창을 캡처했다. 뷰어가 창 밖으로 넘쳐 중앙이 안 보이던 것은
`Saved/CameraViewer/ViewerSize.json` 의 저장 폭이 830 이어서였다 — 크기를 줄여 재확인했다.

## 4. 남은 것

- **카메라 패널 버튼 재배치·그룹 구분선 미완.** PTZ 십자키 오른쪽 빈 공간으로 하단 버튼들을
  옮기면 세로 길이가 줄어 스크롤도 함께 사라진다.
- 카메라 위치를 카메라 단위로 공유하는 동작(직전 커밋)은 여전히 화면 검증이 남아 있다 —
  프리셋 콤보를 실제로 바꿔 봐야 한다.
