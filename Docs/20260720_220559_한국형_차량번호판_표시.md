## 1. 최종 결론

차량 전·후면에 기존 Content 번호판 StaticMesh를 장착하고, Content 글꼴·TextRender로 결정적인 한국형 번호를 표시하는 작업을 완료했다. 사용자 보고 기준으로 Loop 15 Live Coding C++ 컴파일이 성공했고 시각 결과도 완료되었다. PIE 로그에서도 전·후면 번호판이 등록·가시 상태로 기록되었다.

다만 PIE 종료 후 Unreal MCP `localhost:8000` 연결이 두 차례 HTTP transport error를 반환했다. 따라서 최종 10.8cm 글자 크기에 대한 새 Automation 재실행과 새 viewport screenshot은 이 세션에서 검증하지 못했다. 이 제한과 잔여 확인 항목은 숨기지 않고 아래에 기록한다.

## 2. Loop 6~15 변경 흐름

| Loop | 관찰/목표 | 적용한 설계·변경 | 판정 |
|---|---|---|---|
| 6 | 번호판 컴포넌트와 결정적 번호의 최초 구현 | 앞·뒤 기존 번호판 Mesh와 TextRender를 `ACarActor`에 부착하고 `FCarPos.id`(없으면 불변 데이터 seed) CRC32로 번호를 1회 생성. 고정 숫자 슬롯은 런타임 문자열과 겹치지 않게 처리 | C2672로 테스트 컴파일 중단 후 assertion 수정. 이후 시각 실패가 확인되어 재설계 |
| 7 | PIE에서 판과 글자가 전혀 보이지 않음 | 번호판 표면이 local `+Y`임을 기준으로 front local `-Y`/yaw `180°`, back local `+Y`/yaw `0°`로 외측 방향을 수정. TextRender를 표면 외측으로 이동하고 Init 후 실제 transform을 로그에 기록 | 외측 장착 로직 적용 |
| 8 | `FVector`/`FRotator` double과 float tolerance 충돌 | 번호판 관련 `TestEqual` tolerance를 double literal `1e-3`로 통일 | C2666 원인(테스트 타입) 수정 |
| 9 | 일부 expected 값에 float literal 잔존 | mount Z·yaw·text offset/roll expected를 `double`로 통일 | C2666 재발 방지 |

| 11 | 한국 일반 승용차 형식 필요 | `100~699` + 일반용 허용 한글 + 4자리의 canonical 번호 생성. 예: `123다4567`. black frame/blue KOR strip Cube와 MID를 런타임으로 추가 | 형식·결정성 로직 구현 |

| 14 | 6.5cm 글자가 작음 | `WorldSize`만 `6.5→9.0cm`로 확대 | 사용자 시각 피드백 반영 |

## 3. 변경 파일과 핵심 로직

| 파일 | 변경 내용 |
|---|---|
| [`CarActor.h`](../Park3D/Source/Park3D/CarActor.h) | 앞·뒤 plate/text/frame/security-strip 컴포넌트, `PlateNumber`, 결정적 생성·표시 API 선언 |
| [`CarActor.cpp`](../Park3D/Source/Park3D/CarActor.cpp) | Content asset 로드, 외측 mount, canonical 번호 생성, 표시용 공백 삽입, TextRender 배치, 진단 로그, 임시 합성물 hidden 처리 |
| [`CarActorTest.cpp`](../Park3D/Source/Park3D/Tests/CarActorTest.cpp) | 번호 형식·허용 문자·결정성·전후 동일성·재초기화 불변·material 경로·hidden 상태·text layout·10.8cm 기대값 검증 |

관련 좌표/JSON 공통 변경 파일은 [구현 변경 기록](../_workspace/json_coordinate_flag_implementer_changes.md)에 정리되어 있다. 번호판 작업은 JSON DTO나 좌표 변환을 추가로 변경하지 않았다.

### 번호 생성 및 표시

- seed: `id` 우선, 빈 id이면 type/preset/slot/prefab/pos/rotY/isFront를 조합한 불변 문자열.
- `CRC32(seed)`에서 prefix `100 + hash % 600`, 허용 일반용 한글 pool 인덱스, serial `(hash / 997) % 10000`을 결정한다.
- canonical 저장/도메인 값: `123다4567` 형태(3자리 + 1글자 + 4자리).
- TextRender 표시 값: `123 다 4567`(시각적 가독성을 위한 공백만 추가).
- 같은 JSON을 새 Actor로 로드해도 같은 번호이며, 같은 Actor의 재초기화·재표시·Tick으로 번호가 바뀌지 않는다.

### 장착·렌더링

- Content `/Game/Cars/번호판/일반차_번호판_F`(front), `/Game/Cars/번호판/일반차_번호판`(back)을 차량 Mesh local bounds의 양 끝과 하단에 부착한다.
- front plate는 local `-Y`, yaw `180°`; back plate는 local `+Y`, yaw `0°`로 표면 법선이 차량 외측을 향한다.
- TextRender는 Content `수성돋움체_Font`와 `DefaultTextMaterialTranslucent1`을 사용하며 local location `(X=4cm, Y=1.55cm, Z=0)`, yaw `90°`, roll `0°`, black color, XScale `.80`, 최종 `WorldSize=10.8cm`이다.
- 원래 추가했던 black frame/blue strip Cube와 MID는 컴포넌트·Blueprint 호환성을 위해 삭제하지 않았지만 `UpdatePlatePresentation`에서 항상 hidden으로 둔다. 실제 화면은 Content의 원본 white/bezel/blue KOR 배경만 사용한다.
- 번호판·텍스트·보조 Cube는 collision/overlap/shadow를 끄고 차량 선택·도색 수명주기와 분리한다.

Loop 10에서는 `M_Plate`가 parameter 없는 검정 Constant material이라 그대로는 흰 판을 만들 수 없음을 확인했다. 엔진 `BasicShapeMaterial`의 `Color=White` MID를 두 slot에 적용하는 보정으로 흰 판을 먼저 확보하고, TextRender의 local basis를 다시 맞춰 90도 세로 표시를 수평으로 교정했다. Loop 13에서 실제 Content 원본이 이미 white body·bezel·blue KOR를 제공한다는 근거가 확보되어 white MID override는 제거하고 `M_Plate`/`M_Num`을 최종 표시 경로로 복구했다. 즉 임시 흰색·검정/파랑 Cube 합성물은 최종 화면에 남지 않고 hidden 상태다.

## 4. Content asset 및 JSON 영향도

### Content 재사용 및 비변경

Asset registry/thumbnail 조사에서 일반차 번호판은 약 `52×2~3×11cm`이며 material slot은 `M_Plate`, `M_Num`이다. `M_Num`의 기존 `번호판` Texture2D가 white body, inset/rounded bezel, 좌측 blue KOR/security field를 이미 제공하므로 Loop 13에서 per-component white MID override를 제거하고 원본 material pair를 복구했다. Content asset 파일·material graph·texture는 수정하지 않았다.

`M_Text`/`RT_Text`는 runtime 문자열을 그리는 기존 pipeline이 없어 사용하지 않고, 검증된 Content Font + TextRender 경로를 유지한다.

### JSON 좌표 범위 보존

이번 번호판 표시 변경은 `isUnreal` 플래그, legacy Unity 위치 변환, UE 미터→월드 cm 경계, 차량 위치·회전·자동배치 로직을 변경하지 않았다. 기존 규약의 좌표 변환 및 저장 스키마 영향은 [좌표 플래그 설계](../_workspace/json_coordinate_flag_goal_loop_design.md)와 [영향도 보고서](../_workspace/json_coordinate_flag_impact_report.md)를 따른다. 번호 문자열은 JSON DTO에 새 필드로 저장하지 않는다.

## 5. 검증 결과

### 컴파일 실패와 수정

| 오류 | 발생 지점/원인 | 수정 |
|---|---|---|
| C2672 | `GetStaticMesh()`의 `TObjectPtr<UStaticMesh>`를 `TestNotNull` raw pointer 템플릿으로 추론하지 못함 | 해당 두 검사를 `TestTrue(GetStaticMesh() != nullptr)`로 변경 |
| C2666 | UE 5.8 `FVector`/`FRotator` double actual과 float tolerance/expected literal 혼용 | tolerance 및 mount/rotation expected를 모두 double literal로 통일 |
| C4310 | 테스트의 `TCHAR('하'/'허'/'호')` multi-byte character literal | `FString UsageChar = Expected.Mid(3,1)`와 UTF-16 `TEXT("하")` 등으로 비교 |

이 오류들은 번호판 production logic이 아니라 Automation assertion의 타입·문자 리터럴 표현 문제였다.

### 최종 실행 근거

- 사용자 보고: Loop 15 수동 Live Coding C++ 컴파일 성공, 시각 작업 완료.
- [`Park3D.log`](../Park3D/Saved/Logs/Park3D.log)에서 2026-07-20 13:02:08~13:02:13의 `[CarPlate]` 기록 확인.
- 로그 샘플: `372소8085`, `252어4923`, `431두1892`, `685수7158`, `314다6440` 등. 모두 `100~699 + 허용 일반 한글 + 4자리`이고 rental `하/허/호`가 없다.
- 각 샘플의 front/back에서 `plate(reg=1 vis=1 hidden=0)`, front yaw `180°`, back yaw `0°`, effective material `M_Plate`/`M_Num`, text `123 소 8085`와 같은 공백 표시, Content font/material이 로그에 남았다.

### 미검증 및 제약

- PIE 종료 후 Editor MCP endpoint `localhost:8000/mcp`가 두 차례 HTTP transport error를 반환했다.
- 그 결과 최종 10.8cm에 대한 새 `Park3D.CarPlacement.PlateNumber` Automation 실행 결과와 새 viewport screenshot은 확보하지 못했다.
- 소스 및 테스트 기대값에는 `WorldSize=10.8`이 반영되어 있고 사용자 시각 완료 보고·runtime log는 확보했지만, text field overflow/blue field overlap의 마지막 screenshot 판정은 MCP 재기동 후 보완해야 한다.
