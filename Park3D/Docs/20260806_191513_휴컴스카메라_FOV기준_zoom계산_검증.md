- 결론(요약): **문서로는 확인 불가 — 그 PDF에는 FOV(화각) 규격이 한 줄도 없다.** Park3D가 쓰는 58°/36배는 휴컴스 문서가 아니라 Unity 원본 코드 상수에서 그대로 상속한 값이다. 게다가 **줌↔FOV 변환 모델이 Unity 최신 경로(탄젠트)와 다르다(Park3D는 선형 나눗셈)** — 고배율에서 화각이 약 8~9% 좁게 나온다.

---

## 1. 참조 문서(HTTP_API_Hucoms_V1.22.pdf)가 실제로 규정하는 것

83페이지 전문을 텍스트 추출해 `fov / 화각 / angle / lens / optical / magnif / 58 / 36x` 로 전수 검색했다.

| 항목 | 문서 내용 | 위치 |
|---|---|---|
| FOV·화각·초점거리 | **전혀 없음** (검색 0건) | — |
| 광학 배율(36x 등) | **전혀 없음** | — |
| zoom 위치 | `zoompos=<int> 0~65535` — 단위·의미 설명 없음(렌즈 raw 위치) | §8.1 p.54 |
| zoom 이동 | `zoom=in|out|stop`, `zoomspeed=1~100` (방향+속도 제어만) | §8.3 p.57 |
| pan | `panpos=<int> 0~35999` = (0~359.99°)×100 | §8.1 p.54 |
| tilt | `tiltpos=<int> -2000~9000` = (-20~90°)×100 | §8.1 p.54 |
| 지원 여부 조회 | `ZoomSupported = Yes/No` 만 | Annex Capabilities |

즉 이 문서는 **CGI 프로토콜 명세**이지 렌즈 사양서가 아니다. pan/tilt는 각도 단위가 명시되어 있지만 **zoom만 각도 대응이 없다**(0~65535 raw). 따라서 "휴컴스 카메라의 FOV"라는 값 자체를 이 PDF에서는 얻을 수 없고, 58°가 맞는지 틀린지 **판정할 근거가 문서에 존재하지 않는다**.

부수적으로: 실장비 zoom 단위(0~65535 위치)와 Park3D의 zoom 단위(1~36 배율)는 **차원이 다르다**. 실카메라 PTZ 상태를 받아 시뮬 카메라에 반영하려면 별도의 `zoompos → 배율` 매핑이 필요한데(실렌즈는 위치↔배율이 비선형), 저장소에 휴컴스 HTTP 클라이언트나 그 매핑 코드는 **없다**(`zoompos`/`cgi-bin`/`hucoms` 전수 검색 결과 코드 0건, 문서 언급 1건).

## 2. Park3D 가 실제로 쓰는 값과 공식

- 기준 화각: `DefaultHFov = 58.f` (수평) — [PTZCameraActor.h:55](Park3D/Source/Park3D/PTZCameraActor.h#L55)
- 최대 배율: `MaxZoom = 36.f` — [PTZCameraActor.h:51](Park3D/Source/Park3D/PTZCameraActor.h#L51), 설정 파일 `max_zoom`(현재 `36.0`)로 덮어쓰기 가능
- 변환: `HFov = 58 / clamp(zoom, 1, 36)`, 역변환 `zoom = clamp(58 / HFov, 1, 36)` — [CameraControlLibrary.cpp:47-64](Park3D/Source/Park3D/CameraControlLibrary.cpp#L47-L64)
- 적용: `Capture->FOVAngle = ZoomToHFov(...)` — [PTZCameraActor.cpp:85-97](Park3D/Source/Park3D/PTZCameraActor.cpp#L85-L97)

**58°의 출처는 휴컴스 문서가 아니라 Unity 원본 상수다.**

```csharp
// unity/CameraControl/CameraObj/CObjCamera.cs:27-29
public const float DEFAULT_FOV = 58.0f;              // 수평 58°
public const float DEFAULT_VERT_FOV = 34.6348f;      // 수평 58°일 때 수직(16:9)
public float DMAX_ZOOM = 36.0f;                      // 최대 줌 배율 (휴컴스 카메라 기준 36배줌)
```

- `36`에는 "휴컴스 카메라 기준"이라는 주석이 붙어 있으나 **출처 문서·모델명은 없다.**
- `58`에는 근거 주석조차 없다(주석에 폐기값 `89.195f`, `53.13f` 흔적만 남아 있음).

### 수평/수직 처리는 Unity와 일치(문제 없음)

Unity는 `Camera.fieldOfView`가 수직이라 `HorizontalToVerticalFieldOfView`로 변환해 넣고, UE `USceneCaptureComponent2D::FOVAngle`은 수평이라 변환 없이 그대로 넣는다. 렌더타겟이 16:9(기본 1280×720)이므로 zoom=1에서 수직 화각은 `2·atan(tan(29°)·9/16) = 34.635°` — Unity `DEFAULT_VERT_FOV = 34.6348`과 **일치**한다. 이 부분은 정확히 이식되었다.

## 3. 발견된 실제 불일치 — 선형 모델 vs 탄젠트 광학 모델

같은 `unity/` 트리 안에서 두 가지 공식이 공존한다.

| 경로 | 공식 | zoom=36일 때 수평 화각 |
|---|---|---|
| `unity/CameraControl/CameraObj/CObjCamera.cs` (구버전 사본) | `hFov = 58 / zoom` (선형) | 1.611° |
| `unity/_MoveTmp/CPtzSpaceVehiclePlacer.cs:509` 이 호출하는 `CObjCamera.ZoomToHFov` | `hFov = 2·atan(tan(29°)/zoom)` (탄젠트) | 1.764° |
| `unity/20260724_224837_RPC_전체_API_레퍼런스.md:424` | "탄젠트 광학 모델(1=58°, 36=약 1.76°)" | 1.76° |

**Park3D는 선형 쪽을 이식했다.** 실제 광학 줌은 초점거리 배율이므로 `tan(θ/2)`가 배율에 반비례하는 **탄젠트 모델이 물리적으로 옳다**. 두 모델의 차이:

| zoom | 선형(Park3D 현재) | 탄젠트(실광학) | 차이 |
|---|---|---|---|
| 1 | 58.000° | 58.000° | 0% |
| 2 | 29.000° | 30.976° | −6.4% (더 좁음) |
| 4 | 14.500° | 15.785° | −8.1% |
| 8 | 7.250° | 7.928° | −8.6% |
| 16 | 3.625° | 3.969° | −8.7% |
| 36 | 1.611° | 1.764° | −8.7% |

즉 Park3D는 zoom≥4 구간에서 **실제보다 약 8~9% 더 확대된(좁은) 화면**을 만든다. 번호판 겉보기 크기·검출기 학습 데이터 스케일에 직접 영향을 주는 크기의 오차다.

주의: 저장소의 `unity/CameraControl/CameraObj/CObjCamera.cs` 에는 `_MoveTmp` 가 호출하는 `static ZoomToHFov` 가 **존재하지 않는다**. 이 사본이 실제 게임 프로젝트보다 **낡았을 가능성**이 크므로, 어느 쪽이 현행 원본인지 확인이 필요하다.

## 5. 권고(구현하지 않음 — 판단 요청)

1. **58°·36배의 출처 확정**: 휴컴스 실제 모델명 → 렌즈 사양(예: "f=4.3~129mm, 수평 화각 58.0°~1.8°")을 확보해야 한다. HTTP API 문서로는 영원히 확인되지 않는다.
2. **탄젠트 모델로 통일할지 결정**: 물리적으로 옳고 Unity 최신 경로와도 맞지만, 기존 저장된 프리셋/카메라 위치 파일의 zoom 값이 **같은 숫자로 다른 화각**을 의미하게 되므로 회귀 영향이 있다. 별도 설계·영향도 분석 대상.
3. **`DefaultHFov` 설정화**: 현재 `max_zoom` 만 `config_pmaker.json` 으로 조정 가능하고 58°는 코드 상수다. 카메라 모델이 바뀌면 재빌드가 필요하다.
