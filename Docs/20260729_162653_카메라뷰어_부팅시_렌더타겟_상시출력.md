# 카메라 뷰어 — 앱 시작 직후 렌더타겟 뷰 정상 출력

작성일: 2026-07-29 16:26:53
대상: `ACameraControlManager`, `APark3DGameMode`, `UCameraViewerWidget`

---

## 1. 요구사항

- 현상: 카메라 컨트롤 UI를 열면 우하단 카메라 뷰어에 렌더타겟 카메라 출력이 보이지만,
  UI를 열기 **전까지는 흰색 사각박스**만 보인다.
- 요구: 앱이 처음 시작하자마자 렌더타겟용 카메라 뷰가 정상 출력되어야 한다.

---

## 2. 원인 분석 (2중 결함)

### 2-1. 매니저·카메라·렌더타겟이 아예 없다

`ACameraControlManager`는 오직 `UCameraControlWidget::GetCameraManager()`(CameraControlWidget.cpp:345)에서만
lazy 스폰된다.

```cpp
ACameraControlManager* Mgr = Cast<ACameraControlManager>(
    UGameplayStatics::GetActorOfClass(World, ACameraControlManager::StaticClass()));
if (!Mgr) { Mgr = World->SpawnActor<ACameraControlManager>(); }   // ← 패널을 열어야만 실행
```

즉 컨트롤 패널을 한 번도 열지 않으면
**매니저 없음 → 카메라 액터(APTZCameraActor) 없음 → 렌더타겟(RT) 없음** 이다.

`APark3DGameMode::BeginPlay`는 `ShowCameraViewer()`로 뷰어 위젯만 올렸을 뿐, 그릴 대상(RT)을 만드는 주체가 없었다.

### 2-2. 뷰어가 "RT 없음" 상태를 처리하지 못한다

`UCameraViewerWidget::NativeTick`은 RT가 바뀔 때만 브러시를 갱신한다.

```cpp
UTextureRenderTarget2D* RT = Mgr ? Mgr->GetSelectedRenderTarget() : nullptr;
if (RT != AppliedRT.Get())   // nullptr != nullptr → false
{
    SetRenderTarget(RT);     // ← 한 번도 호출되지 않는다
}
```

매니저가 없으면 `RT`도 `AppliedRT`도 `nullptr`이라 조건이 **거짓**이 되어,
"RT 없으면 이미지를 접는다"는 `SetRenderTarget(nullptr)` 처리가 실행되지 않았다.
한편 `NativeConstruct`는 `Img_View`를 무조건 `Visible`로 켜두었으므로,
**브러시가 지정되지 않은 UImage의 기본 흰색 사각형**이 그대로 화면에 남았다. → 이것이 "흰색 사각박스"다.

## 3. 설계

소유 규약을 지킨다: **뷰어는 매니저를 스폰하지 않는다**(소유 역전 방지, CameraViewerWidget.h:83 주석).
따라서 `AMapFloorActor::GetOrSpawn`이 이미 쓰는 "GameMode가 부팅 시 월드 액터를 보장" 패턴을 그대로 따른다.

| 항목 | 결정 | 근거 |
|------|------|------|
| 매니저 확보 주체 | `APark3DGameMode::BeginPlay` | `AMapFloorActor::GetOrSpawn(GetWorld())` 선례와 동일 위치 |
| 확보 방법 | `ACameraControlManager::GetOrSpawn(UWorld*)` 정적 함수 | 위젯의 "있으면 재사용, 없으면 스폰"을 static으로 승격 → 중복 스폰 없음 |
| 기본 카메라 | `EnsureDefaultCamera()` — 0대면 1대 생성 + 자세 반영 + 재선택 | 선택이 곧 캡처 on + 즉시 1회 캡처(`SelectCamera`)이므로 이 호출 뒤 RT가 유효 |
| 초기 자세 | 높이 5m / X·Z 0 / pan·tilt 0 / zoom 1 | `UCameraControlWidget`의 `GCtrlDefaults`와 **같은 값** → 패널을 나중에 열어도 화면이 바뀌지 않음 |
| 호출 순서 | 매니저 보장 → `ShowCameraViewer()` | 뷰어의 첫 `NativeTick`에서 곧바로 RT가 잡히게 |
| 뷰어 초기 가시성 | `Collapsed`로 시작 | RT가 없을 때 흰 사각형이 남지 않게 하는 2차 안전망 |

### 대안 비교

| 대안 | 채택 | 사유 |
|------|------|------|
| **A. GameMode가 매니저·기본 카메라 보장** | ✅ | 기존 `MapFloorActor` 부팅 보장 패턴과 동일. 소유 규약 유지 |
| B. 뷰어(`NativeTick`)가 매니저를 스폰 | ❌ | "뷰어가 매니저를 스폰하지 않는다"는 기존 소유 규약 위반 |
| C. 뷰어에 흰 박스 대신 플레이스홀더 텍스트 | ❌ | 요구사항(카메라 뷰 정상 출력) 미달. 증상만 가림 |
| D. 매니저를 레벨에 액터로 배치 | ❌ | 레벨 에셋 의존 발생. 코드로 보장하는 기존 관례와 불일치 |

## 4. 구현

### 4-1. `CameraControlManager.h` — 인터페이스 추가

```cpp
/** 부팅 시 자동 생성되는 카메라 1대의 초기 자세(Unreal 미터/도). */
UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Camera")
FCamDir DefaultCameraDir;

/** 월드의 매니저를 재사용하고 없으면 스폰한다(멱등). */
static ACameraControlManager* GetOrSpawn(UWorld* World);

/** 카메라가 0대면 1대 생성 + DefaultCameraDir 반영. 이후 항상 현재 인덱스를 재선택한다. */
UFUNCTION(BlueprintCallable, Category = "Camera")
void EnsureDefaultCamera();
```

### 4-2. `CameraControlManager.cpp` — 구현

```cpp
ACameraControlManager::ACameraControlManager()
{
    ...
    // 높이만 기본값과 다르다(FCamDir 기본이 pan=0/tilt=0/zoom=1). pos는 Unreal 미터: (x, z, 높이).
    DefaultCameraDir.pos.z = 5.f;
}

ACameraControlManager* ACameraControlManager::GetOrSpawn(UWorld* World)
{
    if (!World) { return nullptr; }
    if (ACameraControlManager* Existing = Cast<ACameraControlManager>(
        UGameplayStatics::GetActorOfClass(World, ACameraControlManager::StaticClass())))
    {
        return Existing;
    }
    return World->SpawnActor<ACameraControlManager>();
}

void ACameraControlManager::EnsureDefaultCamera()
{
    if (Cameras.Num() == 0)
    {
        if (!AddCamera(TEXT("Camera 1"))) { return; }
        ApplyDir(0, DefaultCameraDir);
    }
    // 이미 카메라가 있어도 재선택한다 — 캡처 on + 즉시 1회 캡처로 RT를 살리는 것이 이 함수의 계약이다.
    SelectCamera(FMath::Clamp(SelectedIndex, 0, Cameras.Num() - 1));
}
```

### 4-3. `Park3DGameMode.cpp` — 부팅 시 보장

```cpp
// 카메라 매니저/기본 카메라 보장 — 패널을 열지 않으면 매니저가 스폰되지 않아 렌더타겟이 아예 없었고,
// 뷰어는 브러시 없는 빈 이미지(흰 사각형)만 그렸다. 뷰어보다 먼저 만들어 첫 틱에 RT가 잡히게 한다.
if (ACameraControlManager* CamMgr = ACameraControlManager::GetOrSpawn(GetWorld()))
{
    CamMgr->EnsureDefaultCamera();
}

ShowCameraViewer();
```

### 4-4. `CameraViewerWidget.cpp` — 흰 박스 잔상 제거

```cpp
// 이미지는 접힌 상태로 시작한다. RT가 없을 때 NativeTick은 (nullptr == AppliedRT)라 SetRenderTarget을
// 호출하지 않으므로, 여기서 Visible로 켜두면 브러시 없는 기본 흰 사각형이 그대로 남는다.
// 첫 틱에 선택 카메라의 RT가 잡히면 SetRenderTarget이 Visible로 되돌린다.
if (Img_View)
{
    Img_View->SetVisibility(ESlateVisibility::Collapsed);
}
```

## 7. 영향도 분석

### 7-1. 회귀 없음 확인

| 대상 | 분석 |
|------|------|
| `UCameraControlWidget::NativeConstruct` | `GetCameraManager()`가 `GetActorOfClass`로 GameMode가 만든 매니저를 찾는다 → 중복 스폰 없음. `GetCameraCount()==0` 분기가 스킵되어 카메라가 2대로 늘지 않는다 |
| `EnsureCamDataSlots()` | 매니저 카메라 수(1)에 맞춰 `CamData.datas`를 1개로 채운다. 기존과 동일 |
| 패널 오픈 시 화면 | `ApplyAllControlsToCamera()`가 슬라이더 기본값(= 부팅 시 적용값과 동일)을 다시 쓴다 → 화면 변화 없음 |
| `UCameraViewerWidget::SetRenderTarget` | 변경 없음. `Collapsed` 초기값은 RT가 잡히면 `Visible`로 복원된다 |
| 유닛 테스트 | 기존 11건 + 신규 1건 전부 통과 |

### 7-2. 의도된 부수효과 (2건)

1. **폴대(실린더) 조기 노출** — 시작 직후 원점에 카메라 폴대가 보인다.
   기존에도 패널을 열면 보이던 것과 동일한 상태이나 노출 시점이 앞당겨졌다.
   숨기려면 `EnsureDefaultCamera()` 뒤에 `ShowAllPoles(false)` 한 줄이면 된다.
2. **씬 캡처 상시 1대** — 카메라 1대가 `bCaptureEveryFrame=true`로 매 프레임 캡처한다.
   기존에도 패널을 열면 동일했고 대수도 1대로 같다. GPU 비용은 RT 256급 1장 수준.

### 7-3. 파생 이득

RPC `cam.*` 메서드가 부팅 직후부터 동작한다(기존에는 패널을 열기 전까지 카메라 0대).

### 7-4. 범위 밖 관찰 (미수정)

- `NativeTick`은 RT가 유효했다가 카메라가 전량 파괴되면
  `RT(nullptr) == AppliedRT.Get()(weak → nullptr)`이 되어 `SetRenderTarget(nullptr)`을 놓친다.
  이번 수정으로 부팅 경로는 해소됐으나 "카메라 전량 삭제" 경로에는 같은 구조가 남아 있다.
  마지막 카메라 1대는 `cam.delete`가 거부되므로 실제 재현은 어렵다.
- `NativePaint`의 외곽 프레임이 첫 프레임에 이미지 사각형과 어긋나 보이는 경우가 있다
  (`camview_boot_window.png` 우하단). 기존부터 있던 현상으로 이번 변경과 무관하다.
