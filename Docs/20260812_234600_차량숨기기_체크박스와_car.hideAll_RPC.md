# 차량 숨기기 체크박스 + car.hideAll RPC (2026-08-12)

## 1. 요구사항

차량 배치(Car Install) 패널에 "차량 숨기기" 체크박스를 추가하고, 같은 기능을 RPC로도 노출한다.

**확인한 것**: 숨김 대상은 **전체 차량**이다(선택 차량이 아니라). 사용자 확인 완료.

## 2. 설계

숨김의 실제 동작은 **매니저(`ACarPlacementManager`)가 소유**하고, 체크박스와 RPC는 그 하나의 진입점을 부른다.
`car.resetRandom` ↔ "리셋랜덤" 버튼이 `ResetRandomPlacement`를 공유하는 기존 규약과 같다 —
여기서 각자 구현하면 두 경로가 갈라진다.

```
[체크박스] ─┐
            ├─→ ACarPlacementManager::SetAllCarsHidden(bool)
[car.hideAll] ─┘         └ SetActorHiddenInGame + SetActorEnableCollision
```

### 왜 충돌까지 끄는가
숨긴 차량이 클릭 픽·시뮬레이션 회피에 계속 걸리면 "숨겼다"가 거짓말이 된다.
기존 `HideRandomCars`/`ToggleRandomCars`도 표시와 충돌을 같은 짝으로 다룬다.

### 체크 상태를 저장하지 않는 이유
체크박스에 상태를 들고 있으면 RPC로 숨긴 뒤 패널을 열었을 때 화면과 어긋난다
(메모리 `preset-list-ui-vs-rpc-split`의 UI/RPC 이원화 재발). 그래서 패널이 열릴 때
`AreAllCarsHidden()`으로 **월드에서 읽어** 체크 상태를 맞춘다.
`UCheckBox::SetIsChecked`는 `OnCheckStateChanged`를 쏘지 않으므로 재귀가 생기지 않는다.

## 3. 변경 내용

### 3-1. `CarPlacementManager.h` / `.cpp`

| 함수 | 동작 |
|------|------|
| `int32 SetAllCarsHidden(bool bInHidden)` | 전체 차량 표시/숨김. 실제로 상태가 바뀐 대수 반환. |
| `bool AreAllCarsHidden() const` | 차량이 1대 이상이고 전원이 숨김이면 true. |

- 데이터(`FCarPosDatas`)는 건드리지 않는다 — 표시만 바뀌므로 **저장 파일에 영향 없음**.
- 인자명이 `bInHidden`인 이유: `bHidden`은 `AActor` 멤버라 **UHT가 섀도잉으로 컴파일을 막는다**
  (`Function parameter: 'bHidden' cannot be defined ... as it is already defined in scope 'AActor'`).

### 3-2. `CarPlacementWidget.h` / `.cpp`

- `Check_HideCars`(`BindWidgetOptional`) 추가.
- `InjectHideCarsRow()` — WBP에 위젯이 없으면 C++로 만들어 `VBox_Root`의 **세로배치 줄 다음**에 삽입한다.
  기존 `InjectRandomModeRow()`와 같은 규약이며, 스타일은 `Check_Vertical`·`Lbl_Vertical`에서 복사해 톤을 맞춘다.
  (에디터 없이 WBP를 수정할 수 없어 런타임 삽입을 쓴다 — 메모리 `umg-panel-without-wbp`)
- `SetAllCarsHidden(bool)` — 매니저 호출 + 체크박스 동기화 + 상태 메시지.
- `NativeConstruct`에서 `AreAllCarsHidden()`으로 체크 상태 초기화.
- `RefreshView()` — `RebuildAll`은 액터를 **새로 스폰**하므로 표시 상태가 초기화된다.
  체크가 켜져 있으면 재스폰 직후 다시 접는다(안 그러면 체크는 켜졌는데 차가 보인다).

### 3-3. `CarRpcModule.cpp` — `car.hideAll`

```
요청:  {"method":"car.hideAll","params":{"hidden":true}}
응답:  {"ok":true,"hidden":true,"changedCount":65,"carCount":65}
```

- `hidden`은 필수(`RequireBool`).
- `changedCount`는 **이번 호출로 실제 바뀐 대수**다(이미 그 상태였던 차량은 세지 않는다).
- car.* 핸들러 21 → 22개.

## 4. 패키지 크래시와 재패키징 (중요)

exe만 갈아끼우는 기존 절차로 띄웠더니 **시작 즉시 크래시**했다.

```
ObjectSerializationError: /Game/UI/WBP_CarPlacement ... Default__WBP_CarPlacement_C:
Bad export index 16908287/154.
```

원인은 코드 버그가 아니라 **직렬화 스키마 불일치**다. 쿠킹된 패키지는 언버전드(unversioned) 속성
직렬화를 쓰므로, 블루프린트의 **C++ 베이스 클래스에 `UPROPERTY`를 추가하면** 이미 쿠킹된
`WBP_CarPlacement`의 CDO를 읽을 수 없다.

- **함수(UFUNCTION)만 추가**할 때는 exe 교체로 충분하다(같은 세션의 앞선 작업이 그랬다).
- **`UPROPERTY` 추가·삭제·순서 변경**은 반드시 **콘텐츠 재쿠킹**이 필요하다.

해소: `RunUAT BuildCookRun -build -cook -stage -pak -archive` 전체 재패키징(`BUILD SUCCESSFUL`,
`ExitCode=0`). 재패키징은 `Package/Windows/Save/`를 덮어쓰지 않으므로 사용자 데이터는 보존되지만,
안전을 위해 `_workspace/pkg_save_backup_20260812/`에 백업해 두었다.

## 6. 알려진 한계

- RPC로 표시 상태를 바꿔도 **이미 열려 있는 패널의 체크박스는 즉시 갱신되지 않는다**(패널을 다시 열면 맞는다).
  실시간 동기화는 위젯 틱 폴링이나 매니저 델리게이트가 필요해 이번 범위에서 제외했다.
- 부분 숨김(랜덤 숨김 등) 상태에서는 `AreAllCarsHidden()`이 false이므로 체크가 해제되어 열린다(의도).
