## 2. 구현 — 무엇을 어디에

### #1099 계약 정직성

- **안 읽은 키 경고(1단계 롤아웃)** — `RpcParam::FReadTracker`(RpcParamUtil). 디스패처가 핸들러 호출 동안 스택에 두고, `RpcParam::Get*/Require*/Has` 가 params **최상위** 키를 읽을 때 기록한다. 헬퍼를 거치지 않는 직접 접근 약 20곳에는 `RpcParam::MarkRead` 를 넣었다. 핸들러가 끝난 뒤 한 번도 안 읽힌 키를 응답 최상위 `warnings:[{kind:"unknownParam", key}]` 로 낸다(result 가 배열인 method 가 있어 result 옆). 서버 로그에도 `[RPC] <method> 이 읽지 않은 params 키: …` 한 줄.
  - **방식을 고른 이유**: 193개 method 의 허용 키 표를 손으로 만들면 #1103 과 같은 일이고 빠지는 곳이 생긴다. "실제로 읽혔는가" 는 핸들러 코드 자체가 정답이다. 조건부로 읽는 키(예 `bay.update` 의 `all`)는 그 경로를 안 타면 경고된다 — 실제로 무시된 것이므로 맞는 경고다.
  - **실패 응답에는 붙이지 않는다** — 필수 키 누락으로 일찍 끝나면 뒤에서 읽혔을 정상 키까지 '안 읽음' 이 된다.
  - **2단계(기본 오류 -32602)는 하지 않았다** — 추적은 실행 **뒤에** 알 수 있어 변경이 이미 일어난 다음이다. 실행 전에 거부하려면 method 별 스키마(#1103)가 필요하다.
  - 조건 단락으로 정상 키가 경고되던 4곳(`overwrite` — `bExisted && GetBool(overwrite)`)은 조건 밖에서 읽게 고쳤다(bay.exportPresets·cam.importPosFile·cam.savePosFile·preset.importFile).
- **오류 `error.data.kind`** — `bad_params | not_found | busy | unsupported | internal`. `FRpcError::Kind` 를 지정하면 그 값, 아니면 `Park3DRpc::ClassifyErrorKind` 가 코드·메시지로 정한다(메시지 문구는 서버가 소유하므로 분류도 서버 한 곳). `Require*` 실패는 명시적으로 bad_params. 예전엔 `data:null`.
- **동작 안 하는 method** — 보드가 꼽은 10개를 작업본에서 실제로 불러 봤다: **9개는 이미 구현돼 있었다**(2026-08-11 결선 — `cam.savePreset` 등은 파라미터 누락, `random.*` 는 프리셋 없는 레벨에서 "프리셋 없음" 으로 정상 거부). 진짜 미구현은 `random.placeInView` 하나 → `-32004`, `kind:unsupported`(`FRpcError::FailNotImplemented`).
- **변경 후 상태 + changed** — `preset.update/rotate/setSize/setDirType`(DTO + `changed` 0|1, DTO 직렬화 전후 비교로 일반화), `preset.move`(+changed), `preset.groupMove/groupRotate`(+`changed`·`presets[]`·`notFound[]` — 옛 `moved/rotated` 는 "찾은 수" 로 유지), `preset.delete`(`existed`·`changed`·`remaining`), `preset.clear`(`cleared`), `car.setColor`·`car.show`(CarDto+changed), `cam.setPTZ`(pan/tilt/zoom+changed).
- **조용한 오동작 1건 추가 발견·수정** — `cam.setPTZ {camId, zoom}` 은 주지 않은 pan·tilt 를 **0 으로 덮었다**(기본값 0/0/1). 이제 현재 값을 유지한다.

### #1100 일괄·되돌리기 — `StateRpcModule`(신규)

- `state.snapshot {scope?: cars|presets|cameras|view|all|[...]}` → `{token}`; `state.restore {token}`; `state.drop`; `state.list`. 메모리 보관 최근 20개. 차량은 FCarPos+숨김+번호판(번호·종류)+도색, 프리셋은 `StoredPresets`+번호 기준점, 카메라는 위치+PTZ, 뷰는 위치·회전. 없는 토큰은 `not_found`.
- `car.createMany` / `car.setAll {cars:[{prefabId|prefabName, pos{x,y,z?}, rotY?, isFront?, presetId?, faceSlot?, visible?, plate?, plateKind?}]}` — **전부 먼저 검사**하고 하나라도 틀리면 아무것도 안 바꾼다. `pos` 는 `{x,y,z}` 그대로(car.create 의 x,z 필수 규약을 따르지 않는다).
- `car.setVisible {carNameIds[] | all, visible}`, `preset.setAll {presets:[preset.create params]}`(항목 실패 시 원래 목록 복원, 항목 안 모르는 키는 `unknownParams`).
- `system.batch {calls:[{method,params}], atomic?}` — 한 HTTP 요청·한 게임 스레드 콜백 안에서 차례로 실행 → **중간 상태가 스트림 프레임에 안 그려진다**(언리얼은 "한 번만 다시 그리기" 가 구조적으로 성립). `atomic:true` 면 시작 전 `state.snapshot(all)` 을 떠 두고 실패 시 되돌린다(`rolledBack`). env/light 는 되돌리지 않는다. 중첩 금지.
- **revision** — 성공한 mutating 호출마다 도메인 카운터 증가. `system.stats.revision{cars,presets,cameras,view,env,total}`, mutating 응답 최상위 `revision`. 값이 안 바뀐 호출도 올린다(보수적).
- **requestId** — mutating 호출의 `params.requestId`(문자열/숫자)가 60초 안에 같은 method 로 다시 오면 실행하지 않고 첫 응답을 `duplicate:true` 로 돌려준다(성공 응답만 기억).
- **preset idx 질문의 답** — `preset.delete {idx:3}` 은 4번을 3번으로 당기지 **않는다**. idx 는 `AddPreset` 이 `max+1` 로 주는 안정 id 다(배열 위치가 아님). 그래서 `uid` 는 만들지 않았다.
- `bay.clear` 응답에 `keptLevelBays`·`cleared`·`changed`.

### #1101 새 프레임

- **frameId = 장면 순번** — `Park3DRpc::SceneSeq()`(프로세스 전역, 성공한 mutating RPC 마다 +1). mutating 응답 최상위 `frameId`, `cam.captureJPG/PNG` 결과 `frameId`, MJPEG 파트 헤더 `X-Frame-Id`(메인 뷰는 CaptureScene 을 건 순간의 값을 리드백 슬롯에 실어 나른다, 카메라 채널은 동기 렌더 직전 값).
  - **엔진 프레임 번호(GFrameCounter)를 쓰지 않은 이유**: 같은 프레임 안에서 RPC 변경이 캡처 앞·뒤 어디에 들어갔는지를 프레임 번호로는 가를 수 없다. 장면 순번이면 "그림의 frameId ≥ 변경의 frameId ⇒ 변경이 들어 있다" 가 정확히 성립한다.
  - 한계: 패널 조작·시뮬 주행 같은 RPC 밖 변화는 세지 않는다.
- `cam.captureJPG/PNG {afterFrame}` — 언리얼 캡처는 **항상 그 자리에서 동기 렌더**하므로 기다릴 일이 없다. 아직 오지 않은 순번을 달라고 하면 `bad_params`(조용히 옛 그림을 주지 않게).
- `view.waitFrame {after, camId?=0, timeoutMs?=3000}` — 단건 요청이면 HTTP 응답을 미루고 `FTSTicker` 로 틱마다 그 채널이 공개한 프레임 순번을 본다(게임 스레드를 막지 않음). 보는 사람이 없는 채널은 그리지 않으므로 즉시 `reason:"noClients"`. `system.batch` 안에서는 즉시 답.
- `preset.getView` 신설(setView 의 짝). 나머지 set/get 짝은 이미 있음(car.getSelectionMark·plate.getDefault·light.get·view.get 등). 새 덧그림은 `view.getLabels`/`preview.list`.
- **.10 이 2.6 fps 인 원인(⑥)** — 원격 PC 라 이 세션에서 조사하지 못했다. 참고: 이 PC 작업본(13540, `-RenderOffscreen`)도 `system.stats` fps 1.9 였다.

### #1102 가리키기·미리보기

- `view.pick` — `{u,v}`(0~1) 추가. 응답에 `target{type: car|camera|face|prop|ground|none, id, carNameId?, camId?, faceKey?, faceNumber?, presetIdx?, slotId?}`, `source: trace|groundPlane|none`, `pos`. **트레이스가 빗나가면(#1093 — 바닥 콜리전 없음) 지면 평면 z=`groundZ`(기본 0 m) 교점**으로 대신한다. face 는 바닥 번호와 같은 목록(`FindSlotNumberAtWorld`). **`hit` 은 bool 그대로 둔다**(SettingManager 가 이미 `hit:false` 로 분기 중) — 요청서의 `hit:{type…}` 대신 `target` 키.
- `view.lookAt {target: car|face|preset|camera, id, distance?}` — distance 를 생략하면 대상 크기에 맞춰(최소 8 m) 물러난다. face 의 id 는 faceKey 또는 바닥 번호.
- `view.topDown {target?, id?, bounds?{min,max}, height?}` — 생략 시 바닥 번호가 있는 면 전체를 담는 높이.
- `ARpcOverlayActor`(신규) — 자기 `ULineBatchComponent` 와 TextRender 풀에 그린다(월드 영구 디버그 라인은 프리셋 매니저가 RefreshView 때 지운다). 0.1초마다 다시 그려 움직이는 차를 따라간다.
  - `car.highlight {carNameIds|carNameId, on?, color?, clear?}`, `preset.highlight {idxs|idx, …}` — 윤곽선, 객체 불변.
  - `view.setLabels {cars?, presets?, cameras?}` / `view.getLabels` — 라벨 carNameId · `P<idx>` · `C<camId>`. 글자는 메인 뷰 화면과 평행.
  - `preview.show {id, faces?[{x,y,z?,rot,xSize,zSize}], boxes?[{x,y,z?,rot,size}], color?}` / `preview.clear {id?}` / `preview.list` — 반투명 고스트, car/preset 목록·저장에 안 들어간다.
  - 전부 **global**(월드 한 벌 — 모든 시청자에게 보인다). 응답에 `global:true`.
- `car.list`(CarDto) 에 `color`(저장값, -1=미지정)·`colorName`(지금 칠해진 색: 10색 이름 | custom | original)·`rgb`. `plateKind` 는 이미 있었다.
- 번호 글자 방향(⑦)은 같은 날 앞 작업 `numberRot`(#1086)으로 이미 완료.
- 언리얼 쪽 신설 method 는 `system.describe.extensions[]` 에 추가했다.

## 4. 계약 변화(클라이언트가 알아야 할 것)

- 응답 최상위에 새 키: `warnings`(성공 시 안 읽은 키), `revision`·`frameId`(mutating 성공 시), `duplicate`(requestId 중복). JSON-RPC 클라이언트가 모르는 최상위 키를 무시하면 영향 없음.
- `error.data` 가 `null` → `{kind}`.
- `system.describe` 의 `mutating` 기본값이 "비영속이면 true" → 이름 동사 판정(list·get*·catalog·numbers·capture… = false). 메타가 있는 method 는 메타 그대로.
- `cam.setPTZ` 가 생략 축을 현재 값으로 유지(전에는 0). 응답이 `{ok}` → `{ok, camId, pan, tilt, zoom, changed}`.
- `car.setColor`·`car.show` 응답이 `{ok}` → CarDto + `ok`·`changed`.
- `preset.update/rotate/setSize/setDirType` 응답에 `changed`, `preset.clear` 가 `{ok, cleared, changed}`.
