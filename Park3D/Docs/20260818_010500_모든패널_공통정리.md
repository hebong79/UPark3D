# 모든 패널에 같은 정리 적용 — 구분선 · 높이 자동맞춤 공용화

- 날짜: 2026-08-18
- 브랜치: `feat/panel-common-cleanup`
- 요청: 카메라 패널에 넣은 정리를 **모든 패널**에 같게 적용

## 0. 먼저 확인한 것 — "이전 UI가 푸시됐다"는 사실이 아니었다

사용자가 옛 UI 화면을 보고 다른 컴퓨터가 이전 UI를 푸시했다고 판단했다. 확인 결과:

- `origin/main` 에 우리 UI 코드가 **그대로 있다** — `RelocateActionButtons`, `InsertGroupDividers`,
  `SideColumnMinWidth`, `DockIconSize`, `GPtzPadScale = 1.0f`, 실측 여백 코드까지.
- 다른 컴퓨터의 11개 커밋은 번호판 위젯 · Env RPC · 저장 데이터 갱신이고 UI 를 되돌린 것이 없다.
- 로컬과 `origin/main` 의 `Source`·`Tools` 차이는 0.

**진짜 원인은 실행 중이던 exe 가 낡은 것이었다** — `Package/Windows/.../Park3D.exe` 가 08-17 23:23 빌드
(중간 버전: 네 버튼 줄까지 옆 칸에 넣어 "카메라 피킹 시…"가 잘리던 상태)였다.
Content(WBP)는 git 제외(SVN 관리)라 git 으로는 UI 자산이 오갈 수 없다는 점도 함께 확인했다.

> 교훈: "옛 UI가 보인다"는 신고는 **소스 → 빌드 → 배포 exe** 세 단계 중 어디가 낡았는지부터 가른다.
> 이번엔 소스·빌드는 최신이고 배포본만 낡았다.

## 1. 공용화한 것 (`Park3DPanelStyle.h`)

| 함수 | 하는 일 |
|---|---|
| `MakeGroupDivider` | 1px 가로선(흰색 35%) — 어두운 카드에서 보이는 색 |
| `FindContentColumn` | 카드 안에서 줄이 쌓이는 `UVerticalBox` 를 **구조로** 찾는다(자식 최다). 패널마다 이름이 달라 이름으로 못 찾는다 |
| `FindRowIn` | 어떤 위젯이 속한 "줄"(열의 직계 자식)을 되돌린다 |
| `InsertGroupDividers` | 기준 위젯들이 속한 줄 앞에 선을 넣는다. 줄 앞이 라벨이면 라벨 위에. 뒤에서부터 삽입해 인덱스가 안 밀린다 |
| `FitPanelHeight` | 카드 높이를 본문에 맞춘다. 여백은 `카드 높이 − 스크롤 영역 높이` 로 실측하고 매 틱 재보정 |

카메라 패널이 갖고 있던 구현을 그대로 올려서 네 패널이 같은 코드를 쓴다.

## 2. 패널별 적용

| 패널 | 구분선 기준 | 높이 자동맞춤 |
|---|---|---|
| 카메라 컨트롤 | 프리셋 / 위치 슬라이더 / PTZ 패드 / 하단 버튼 (4개) | 기존대로 |
| 차량 배치 | 자동생성 / 차량 리스트 / 선택 속성 / 하단 버튼 (3개 삽입) | 추가 |
| 주차면 프리셋 | Offset / Dir Type / 데칼 (1개 삽입) | 추가 |
| 차량 랜덤(렌더) | 숨김 개수 / 전체 숨기기 | 스타일 적용도 함께 추가 |

삽입 개수는 런타임 로그로 확인했다(`구분선 N개 — 기준 열 …`). 기준 위젯이 열의 0번이면
그 앞에는 선을 넣지 않으므로 패널에 따라 개수가 다르다.

## 3. 검증

- 주차면 프리셋 패널: 화면 확인 — 구분선 보이고, 카드가 내용에 맞게 줄어 빈 공간·잘림 없음.
- 카메라·차량 배치: 삽입 로그로 확인(각 4개·3개). 카메라 패널 배치는 직전 커밋에서 화면 확인 완료.
- 렌더 패널: 코드 경로만 확인(패널을 열지 못함).

**검증 방법 메모**: 패널 열기는 독 아이콘 클릭뿐이라 자동화가 취약하다.
좌표 클릭은 창을 앞으로 올린 뒤에만 먹고(첫 클릭은 활성화에 먹힌다), `PostMessage` 로 보낸
마우스 메시지는 Slate 가 무시한다. 캡처는 `PrintWindow(PW_RENDERFULLCONTENT)` 로 가려져도 된다.

## 4. 남은 것

- 주차면 프리셋 패널의 왼쪽 열(리스트·버튼)에는 선이 들어가지 않는다 —
  `FindContentColumn` 이 열 하나만 고르기 때문. 필요하면 열을 둘 다 받도록 넓히면 된다.
- 렌더 패널 화면 확인.
