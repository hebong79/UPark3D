## 2. "이 나무"를 액터로 특정한 방법 — 프로젝션 오버레이

직전 건은 사용자가 스크린샷에 빨간 원을 그려 줬지만 이번엔 표시가 없어, 화면의 나무 전부를
액터에 대응시켜 놓고 골랐다. **`view.pick` 으로 한 점씩 찔러 보는 것보다 이 방향이 낫다** —
pick 은 나뭇잎을 통과해 뒤 지면을 맞히지만, 프로젝션은 나무 전체를 한 화면에 이름표로 깔아 준다.

절차:

1. `view.get` 으로 현재 시점(pos·pitch·yaw·fov)을 받는다.
2. `env.list` 로 나무 액터를 모은다(라벨 `^SM_(Oak|Pine)`).
3. 각 액터의 캐노피 중심(`pos.z + 높이/2`)을 `view.pick` **과 같은 투영식**으로 화면 좌표로 옮긴다.
4. 캡처 이미지에 원+이름표로 겹쳐 그려 눈으로 확정한다.

투영식은 `ViewRpcModule.cpp` 의 `view.pick` 과 같아야 한다(다르면 조용히 어긋난다).

```
X(정면) = (cos p·cos y, cos p·sin y, sin p)
Y(우)   = (-sin y, cos y, 0)
Z(상)   = (-sin p·cos y, -sin p·sin y, cos p)
tanH = tan(fov/2),  tanV = tanH × (540/960)      ← 수직은 렌더타깃 화면비로 파생
ndcX = (d·Y / d·X) / tanH,  ndcY = (d·Z / d·X) / tanV
```

### 함정 둘

- **캡처 PNG 좌표 ≠ 렌더타깃 좌표.** 창 캡처에는 제목줄·테두리가 들어 있다. 눈대중하지 말고
  `GetClientRect` + `ClientToScreen` 으로 오프셋을 실측한다(이번 창: 오프셋 `(8,31)`, 클라이언트
  `1464×824`, 화면비 1.7767 ≒ 렌더타깃 960×540 의 1.7778).
- **PowerShell 에서 `,` 는 `*` 보다 우선순위가 높다.** `@($cp*$cy, $cp*$sy, $sp)` 는
  `$cp * ($cy,$cp) * ($sy,$sp)` 로 파싱돼 `op_Multiply` 에러가 난다. 각 원소를 괄호로 묶거나
  스칼라 변수로 풀어 쓸 것.

내려다보는 각(pitch −66.8°)에서는 **높이 오차가 화면 위치를 크게 흔든다** — 같은 XY 인
`SM_Oak_7`(캐노피 중심 4.4m)과 그 화단판(0.2m)이 화면에서 200px 떨어져 찍혔다. 캐노피 중심을
쓰면 나무에, 지면 z 를 쓰면 화단판에 맞는다.

   주차면과 흰 차량이 그대로 드러났다(같은 영역 확대 비교).
2. config 반영 후 앱 재시작(런타임 숨김이 아니라 시작 시 적용임을 가르기 위해).

## 4. 주의
