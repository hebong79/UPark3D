## 스태틱/PTZ 구분 방식

`FCamDir` 에는 카메라 종류 필드가 없다. 코드를 바꾸지 않고 파일만으로 구분하기 위해:

- **스태틱** — `sname: "Static 1"`, 프리셋 1개, **`ptzmin == ptzmax == (pan, tilt, zoom)`**. 카메라 패널은 Pan/Tilt/Zoom 슬라이더 범위를 `ptzmin/ptzmax` 로 세팅하고 값을 그 범위로 클램프하므로(`CameraControlWidget.cpp:796-856`) 슬라이더·PTZ 패드로 움직일 수 없다. `ValueToSlider` 는 Min==Max 를 0 나눗셈 없이 처리한다(`CameraControlLibrary.cpp:106`).
- **PTZ** — `sname: "Preset N"`, 프리셋 3개, `ptzmin (-180,-90,1)` / `ptzmax (180,90,36)`.

한계: RPC `cam.setPTZ` 는 `ptzmin/ptzmax` 를 보지 않으므로 원격에서는 스태틱 카메라도 움직인다. 종류를 코드 수준에서 강제하려면 `FCamDir` 에 필드를 추가해야 한다(이번 범위 밖).

## 판단이 갈릴 수 있는 곳

- **2·3·4번의 폴대 배정**은 이미지의 도로 화살표 방향(교통은 SW→NE)과 보이는 면 유무로 골랐다. 2번(3번 폴대 SW)과 4번(4번 폴대 NE)은 다른 배정도 가능하다(4번을 2번 폴대 NE 로, 3번을 4번 폴대 SW 로). 확정하려면 현장 폴대별 채널표가 필요하다.
- 6번 EV3 의 목표면(06)은 안내판 위치로 추정한 것. 실제로는 07 일 수도 있다.
- 레벨 디자이너가 BP_Camera `Body` 에 넣어 둔 회전(3-2 → SW, 3-3 → NE, 4 → SW, 1-3 → SW)은 참고만 했고 따르지 않았다 — 1-1·1-2·2번은 기본값(-9.94/76.81)이라 조준 의도가 없었다.
