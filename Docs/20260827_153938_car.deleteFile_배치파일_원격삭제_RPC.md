# `car.deleteFile` — 저장한 배치 파일을 원격에서 지우는 RPC

작성 2026-08-27 15:39 · 브랜치 `feat/car-delete-file` · 기준 커밋 `52747ea`
요청자: SettingManager/TourAgent(192.168.0.221:13040) 마스터 지시 —
*"지울 수 있는 RPC를 만들어줘"*

---

## 1. 왜 만들었나 — 만들 수만 있고 못 지우는 비대칭

TourAgent 의 **연출 레시피**는 저장할 때마다 시뮬레이터에 `car.save` 를 보내
그 기계 디스크에 배치 파일을 하나씩 남긴다.

```
POST /rpc {"method":"car.save","params":{"fileName":"touragent-scene-20260826-213748"}}
→ {"ok":true,"path":"../../../Park3D/Saved/CarData/touragent-scene-20260826-213748.json"}
```

그런데 **지울 길이 없었다.** `file.list`·`file.delete` 는 이 서버에 없고(실측 `-32601`),
`car.*` 의 삭제는 전부 **월드의 차량**을 지우는 것이지 파일을 지우는 것이 아니다
(`car.delete`·`car.deleteAll`·`car.clear`).

그래서 사람이 레시피를 지워도 저쪽 파일은 남았고, 화면이 이렇게 말할 수밖에 없었다:

> ⚠ 시뮬레이터 디스크의 배치 파일 「touragent-scene-20260826-213748」 은 **남습니다** —
> 지울 RPC 가 없어 그 기계에서 사람이 지워야 합니다.

레시피를 만들 때마다 파일이 하나씩 쌓이는데 청소는 원격으로 못 하는 구조였다.
**`car.save` 의 짝을 만드는 것**이 이 변경이다.

---

## 2. 신설 메서드

### `car.deleteFile`

| 항목 | 값 |
|---|---|
| 파라미터 | `fullPath` **또는** `path`(폴더) + `fileName` — **`car.save`·`car.load` 와 같은 해석**(`ResolveCarPath`) |
| 기본 폴더 | `path` 생략 시 `Saved/CarData` (= `car.save` 의 기본 자리) |
| 확장자 | `fileName` 에 `.json` 이 없으면 붙인다 |
| 월드 | **필요 없다** — 파일 조작뿐이라 맵이 안 올라온 상태에서도 동작한다 |

응답:

```json
{ "ok": true, "path": "…/Saved/CarData/touragent-scene-20260826-213748.json",
  "fileName": "touragent-scene-20260826-213748.json",
  "existed": true, "deleted": true }
```

**없는 파일은 실패가 아니다**(멱등). 그때는 `existed:false, deleted:false` 로 `ok` 를 돌려준다 —
청소는 여러 번 불려도 같은 결과여야 하고, 이미 지워진 파일 때문에 부른 쪽의 삭제 흐름이
실패로 끝나면 안 된다. 「없었다」와 「지웠다」는 두 칸으로 구분해 사실대로 말한다.

실패는 두 가지뿐이며 둘 다 `-32000` 이다.

| 사유 | 메시지 |
|---|---|
| 허용 폴더 밖 | `배치 파일 폴더 밖입니다: <경로> (허용: <폴더들>)` |
| `.json` 이 아님 | `배치 파일이 아닙니다(.json 만 지울 수 있습니다): <경로>` |
| OS 삭제 실패 | `배치 파일 삭제 실패: <경로>` |

---

## 3. 왜 자리를 가두는가 — 삭제는 저장과 대칭이 아니다

`car.save`·`car.load` 는 `fullPath` 를 주면 그대로 쓴다. 삭제만은 그러면 안 된다:
이 RPC 서버는 **`AllowAnonymous`** 다(`Docs/20260804_185500_RPC_익명접속_허용_플래그.md`).
경로를 그대로 믿으면 네트워크에 닿는 누구나 `Config`·`Content`·`Saved` 아래 아무 파일이나
지울 수 있는 통로가 된다. 쓰기는 덮어써도 원본이 남지만 **삭제는 되돌릴 수 없다.**

그래서 삭제만 **폴더와 확장자로 가둔다** — `Park3D/Source/Park3D/Rpc/Modules/CarFilePaths.h`.

허용 폴더:

| 폴더 | 무엇이 있나 |
|---|---|
| `Saved/CarData` | `car.save` 가 `fileName` 만 받았을 때 쓰는 기본 자리 — TourAgent 의 `touragent-scene-*.json` |
| `Save/3D/CarPos` | 시뮬 UI 가 저장하는 배치(SettingMain 이 사본을 갖고 있다) |

규칙 세 줄:

1. 경로를 **먼저 접는다** — 슬래시 통일 → 절대 경로 → `..` 접기 → 중복 슬래시 제거.
   접기를 비교 뒤로 미루면 `…/CarData/../../Config/x.json` 이 「CarData 로 시작하는 문자열」이라
   그냥 통과한다. **이것이 이 파일에서 제일 중요한 한 줄이다.**
2. 폴더 비교는 `Root + "/"` 로 한다 — `CarData` 와 `CarDataBackup` 은 다른 폴더다.
3. 대소문자는 무시한다 — 윈도우 파일시스템이 그렇게 다루고, 이 서버는 거기서 돈다.

규칙을 헤더의 **순수 함수**로 뺀 이유는 자동화 테스트가 실제 폴더 없이(가짜 루트를 주입해)
이 판정을 시험할 수 있어야 하기 때문이다.

## 5. 테스트

### 자동화 테스트(신규 2개)

- **`Park3D.CarFile.DeleteGuard`** — 허용 폴더 안의 `.json` 만 통과한다.
  통과 1건 + 거절 6건: `..` 탈출 · 폴더 밖 · `.json` 아님 · 접두사 겹치는 이웃 폴더
  (`CarDataBackup`) · 폴더 경로 자체, 그리고 역슬래시·대소문자 표기 차이는 **같은 파일**로 본다.
- **`Park3D.CarFile.DeleteRoundTrip`** — 실제 파일을 만들고 → 검문 통과 → 지우고 →
  없어졌는지 확인 → 두 번째 호출도 실패가 아님(멱등).

### ⚠ 미검증 — 빌드·실기

이 변경은 **리눅스 쪽 세션(192.168.0.221)에서 작성**했다. 그 기계에는 언리얼 툴체인이 없어
**컴파일도 자동화 테스트 실행도 하지 못했다.** 실기 확인은 다음 두 걸음이 남아 있다.

1. 윈도우(`D:/Work2/Unreal2/UPark3D`)에서 빌드 + 자동화 테스트 2건 실행.
2. 패키지 배포 뒤 실기 왕복 — 아래 순서 그대로.

```bash
# 1) 배치 저장 → 파일이 생긴다
curl -s -XPOST http://192.168.0.10:13510/rpc -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"car.save","params":{"fileName":"delete-rpc-probe"}}'

# 2) 지운다 → existed:true, deleted:true
curl -s -XPOST http://192.168.0.10:13510/rpc -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":2,"method":"car.deleteFile","params":{"fileName":"delete-rpc-probe"}}'

# 3) 다시 지운다 → existed:false, deleted:false (실패가 아니다)
# 4) car.load 로 확인 → "로드 실패: …/delete-rpc-probe.json"
# 5) 폴더 밖은 거절되는지 → fullPath 로 Config 아래를 겨냥하면 -32000 「배치 파일 폴더 밖입니다」
```

## 6. 영향도

- **기존 메서드 변경 없음.** `car.save`·`car.load` 는 한 글자도 안 건드렸다. 새 메서드 하나가
  디스패처에 더해질 뿐이라, 옛 클라이언트는 아무 영향을 받지 않는다.
- **`system.catalog` 가 한 줄 늘어난다**(car.* 22 → 23). 카탈로그 개수를 못 박은 테스트는 없다.
- **부르는 쪽**: SettingManager/TourAgent 가 레시피 삭제에서 이 메서드를 부른다. 아직 이 빌드가
  안 올라간 시뮬레이터는 `-32601` 을 주고, 그쪽 화면은 그것을 「이 시뮬레이터는 아직 삭제 RPC 가
  없습니다」로 그대로 표시한다 — 배포 순서에 의존하지 않는다.
- **문서**: `Docs/20260807_173431_Park3D_RPC_메서드_목록.md` 은 그 시점(커밋 `135f296`)의
  스냅샷이라 고치지 않았다. 이 문서가 그 뒤의 추가분 기록이다.
