## 2. 옷

### 2.1 방법

옷 에셋이 저장소·1030 엔진·`_UnusedContent`·Omniverse·Blender·Vault 캐시 어디에도 없다. 그래서 PM 이 승인한 안 C 로, 형상을 바꾸지 않고 새 재질로 칠한다.

- 재질: `/Game/Characters/Mannequins/Outfit/M_AgentOutfit` (생성 스크립트 `Tools/agent_outfit/build_outfit_material.py`).
- 뼈대 기준 자세의 정점 좌표(Pre-Skinned Local Position)로 부위를 가른다. 애니메이션·탑승 자세에서도 옷이 몸을 따라간다.
- 이 노드는 정점 셰이더 전용이라 Vertex Interpolator 로 넘긴다.
- 부위 경계(어깨·팔꿈치·손목·목·허리·무릎·발목)는 런타임에 그 메시의 기준 자세 뼈에서 읽는다. Manny·Quinn 체형이 달라서다.
- 파이썬 `AnimPose` 는 스켈레톤 기준 자세를 돌려줘 Manny·Quinn 값이 같게 나온다. C++ 은 메시의 `GetRefSkeleton()` 을 쓴다.

### 2.2 계약(추가만)

```
agent.create {outfit?, outfitSeed?, riderOutfit?, riderOutfitSeed?}
agent.list → 사람 항목에 outfit{seed, sleeve, bottom, pattern, top, topAlt, bottomColor, shoes, skin, hair, applied}
             탑승자 항목에 gripGapCm{left, right}
```

| 필드 | 값 |
|---|---|
| `sleeve` | long, short, none |
| `bottom` | long, shorts |
| `pattern` | plain, stripe, check |
| `top`, `topAlt` | white, black, gray, navy, blue, skyblue, red, pink, green, yellow, beige, brown |
| `bottomColor` | jeans, black, navy, gray, khaki, beige |
| `shoes` | white, black, gray, brown |
| `skin` | light, medium, tan, dark |
| `hair` | black, darkbrown, brown, gray |

- seed 를 생략하면(또는 0 이하) 새로 뽑아 `outfit.seed` 로 돌려준다.
- 같은 seed 면 id 와 무관하게 같은 옷이다(`person-114`, `person-115` 로 확인).
- `outfit` 은 일부 필드만 줘도 되고 나머지는 seed 로 뽑는다. `agent.list` 의 `outfit` 을 그대로 돌려줘도 같은 옷이 된다.
- 없는 이름·키는 -32000 `bad_params` 로 거절하고 아무것도 만들지 않는다.
- 걷는 사람에 `riderOutfitSeed`, 이동수단에 `outfitSeed` 를 주면 `warnings[{kind:unknownParam}]` 로 알린다.
- 탑승자 없는 이동수단(`rider:false`)에는 `outfit` 이 없다.

## 3. 손잡이

### 3.1 방법

- 2관절 IK 로 팔꿈치를 계산하고, 손 방향은 앞·약간 아래·안쪽, 손바닥은 아래로 둔다.
- 손가락 4개를 마디별 누적 55·105·140° 로 만다. 엄지는 굽히지 않았다.
- 상체는 두 팔이 팔 길이의 92 % 안에 닿는 가장 작은 각으로 숙인다(최소 8°). 고개는 그 30 % 만 숙인다.
- 자세는 탑승 때 한 번 정하고 이동·정지 내내 유지한다. 옷은 재질뿐이라 자세에 영향을 주지 않는다.
- 상수 `GripPalmUpCm = 3` 은 손바닥을 손잡이 중심 위 3 cm 에 얹으려는 값이다.

### 3.2 손잡이 좌표와 측정값

| 모델 | 손잡이 중심 (x, ±y, z) cm | 출처 | 숙임 Manny / Quinn | gripGapCm 좌·우 (Manny, Quinn 동일) |
|---|---|---|---|---|
| city | 24.0, 28.0, 101.0 | 모형 생성 좌표 | 8° / 8° | 3.00, 3.00 |
| sport | 40.0, 26.0, 97.0 | 모형 생성 좌표 | 27° / 28° | 3.00, 3.00 |
| simple | 38.0, 24.0, 98.0 | 모형 생성 좌표(막대 ±28 의 끝 쪽) | 23° / 24° | 3.00, 3.00 |
| scooter1 | 18.2, 31.5, 101.7 | 메시 정점 | 8° / 8° | 3.00, 3.00 |
| evscooter2 | 36.5, 30.0, 96.1 | 메시 정점 | 18° / 21° | 3.00, 3.00 |
| hondawave | 21.3, 29.0, 97.4 | 메시 정점 | 8° / 8° | 3.00, 3.00 |
| scooter3 | 22.1, 28.0, 104.2 | 메시 정점 | 8° / 8° | 3.00, 3.00 |

- simple 에도 핸들 막대가 있어 같은 방식으로 잡는다. 고무 손잡이는 없고 막대 끝 쪽을 쥔다.
- 오토바이는 메시마다 손잡이 위치가 다르다(앞뒤 약 18 cm, 높이 약 8 cm 차이).

### 3.3 이 수치의 한계

- **`gripGapCm` 은 IK 를 푼 좌표와 재는 좌표가 같다.** `middle_01` 뼈와 손잡이 표 좌표의 거리이므로, 표가 틀려도 3.00 이 나온다.
- 이 값이 증명하는 것은 「팔이 닿았다(IK 가 목표까지 풀렸다)」뿐이다. 「실제 손잡이 위에 있다」는 캡처로만 판정한다.
- `Park3D.Agent.Grip` 테스트도 같은 이유로 표의 정확성을 검증하지 못한다.
- 오토바이 값은 `Tools/agent_outfit/grip_stats.py` 가 뽑은 정점 중심이며, y 는 손잡이 길이의 가운데로 잡았다.

### 3.4 오토바이 7종의 실제 상태

- 폴더의 메시는 7개지만 고를 수 있는 모델은 4개이고, PM 결정으로 그대로 뒀다(이번 범위 밖).
- `SM_Motrocycle` 과 `SM_Scooter_1` 은 정점 47,429개 좌표가 모두 같다(`numpy.allclose`). 재질 슬롯 이름만 일부 다르다.
- 고르지 못하는 3개: `SM_Motrocycle`, `SM_EV_Scooter_1`, `SM_Scooter_2`. 실제로 다른 형상은 두 개다.

## 5. 눈에 띄는 문제

**옷 경계**
1. (뒤이어 수정 — `20261104_191700_민소매_자전거_발_수정.md`) **민소매가 어깨 덮개처럼 보인다.** 어깨 바깥쪽이 팔 판정 반경(9 cm) 밖이라 윗옷 색으로 남는다. Manny·Quinn 공통. 반경을 키우면 가슴 옆이 피부색이 될 위험이 있어 그대로 뒀다.
2. **무늬가 기준 자세 좌표를 따른다.** 팔을 내린 기준 자세 기준이라 팔의 줄무늬·체크가 비스듬하고, 탑승 자세에서 더 기운다.
3. **허리선이 수평 직선이다.** 옷 주름·벨트는 없다.

**재질로 못 고치는 것**
4. **마네킹 몸의 굴곡이 그대로 드러난다.** 가슴판·복부 모양이 옷 아래 비쳐 갑옷이나 쫄쫄이처럼 보인다. 옷 두께·치마 같은 실루엣 변화도 없다. 안 C 의 한계다.
5. **얼굴에 이목구비가 없다.** 머리카락은 머리에 칠한 색이라 모자나 복면처럼 보인다.

**이번 범위 밖**
6. (뒤이어 수정 — `20261104_191700_민소매_자전거_발_수정.md`) **자전거 발이 페달에 놓이지 않는다.** 다리는 예전 고정 각도라 발이 페달 앞쪽 허공에 있다. 오토바이는 발판 근처라 덜 어색하다.
7. **엄지는 굽히지 않아** 근접하면 손잡이를 완전히 감싸지 않는다.
8. **옷과 차체의 겹침:** 옆 캡처에서 크게 겹치는 곳은 못 봤다. 다만 충돌을 계산하지 않았고, 눈으로만 봤다.

**에디터 한정**
9. 에디터 `-game` 에서 재질을 처음 쓰면 셰이더 비동기 컴파일 동안 원래 마네킹으로 보인다. 첫 캡처가 그렇게 찍혀 「안 칠해진다」로 오인할 뻔했고, 약 45 초 뒤 다시 찍으니 정상이었다. 쿡된 패키지에서는 안 생길 것으로 보지만 확인하지 못했다.

## 6. 함정과 수정

- **첫 게임 빌드 실패:** `ModelNames` 의 오토바이 반복 변수가 옛 타입(`FApMesh`)이었다. `FApMoto` 로 고쳐 재빌드했다(이번 diff 안, PM 사전 승인 범위).
- **재질의 팔 판정:** 기준 자세의 팔은 팔꿈치에서 꺾여 있어 어깨~손목 직선과 약 9 cm 벌어진다. 두 토막으로 나눴고, 손끝은 손목 너머로 이어야 손이 바지색이 되지 않는다.
- `build_outfit_material.py` 는 NullRHI 라 셰이더 오류가 드러나지 않는다. 판정은 실제 캡처로 한다.
- 로그의 `Failed to compile Material`(도로 신호등 재질 11건)은 이번 변경과 무관하다. 어제 로그 `game_agents.log` 에도 같은 11건이 있다.

## 7. 배포 때 확인할 것

이번 작업은 머지·재쿡·정본 교체를 하지 않았다.

1. **재쿡 필요.** exe 만 바꾸면 크래시는 없지만 회색 마네킹으로 남는다(13540 시험으로 확인, `옷 재질이 없어…` 경고가 사람마다 1줄).
2. **쿡 결과에 재질이 들어가는지 미확인.** `DefaultGame.ini` 에 `DirectoriesToAlwaysCook=/Game/Characters/Mannequins/Outfit` 을 넣었다.
   - 쿡 뒤 `Manifest_UFSFiles_Win64.txt` 에 `M_AgentOutfit` 이 있는지 본다.
   - 실행해 `outfit.applied:true` 와 옷 캡처를 본다. 에디터 `-game` 검증은 이것을 대신하지 않는다.
3. **Content 는 git 밖이다.** `.125` 등 다른 작업 트리에서 쿡하려면 아래 파일이 필요하다. `python Tools/agent_outfit/run_build_material.py` 로 다시 만들 수도 있다.
   - `Park3D/Content/Characters/Mannequins/Outfit/M_AgentOutfit.uasset`
4. **작업본 상태:** `Package\LvCombo20261103\Windows\Park3D\Binaries\Win64\Park3D.exe` 는 새 exe 다. 옛 exe 는 같은 폴더 `Park3D.exe.bak_20261104_outfit`. 13530·13540 은 내렸다.
