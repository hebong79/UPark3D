## 2. 인벤토리와 분류

### 2.1 어떻게 뽑았나
`Tools/usd_export/inventory_level.py` 를 pythonscript commandlet 으로 돌려(`EditorLoadingAndSavingUtils.load_map` → `EditorActorSubsystem.get_all_level_actors`) 액터마다 StaticMesh/ISM/HISM/SplineMesh/Decal 컴포넌트의 메시·재질·텍스처·월드 변환을 `Env/_inventory.json` 에 덤프했다. `.umap` 문자열 훑기(ASCII 249개 경로)는 블루프린트 안의 메시(카메라 부품, 가로등 부품, 주차면 스토퍼 등)를 못 본다 — 인벤토리는 로드된 월드에서 뽑아야 한다. Park3D 인스턴스(13510/13520)는 둘 다 꺼져 있어 `env.list` 는 쓰지 못했다.

**LV_Park_01 은 World Partition 이 아니다** — `__ExternalActors__` 에는 `Maps/PresetMaker1` 만 있고 LV_Park_01 의 액터 325개는 `.umap`(3.3 MB) 안에 있다. CLAUDE.md 의 "부팅맵 World Partition" 은 PresetMaker1 시절 얘기다.

## 3. 만든 파일 / 실행

| 경로 | 역할 |
|---|---|
| `Tools/usd_export/inventory_level.py` | commandlet 안. 레벨을 열어 액터·컴포넌트·메시·재질·텍스처·변환을 JSON 으로 |
| `Tools/usd_export/export_env.py` | commandlet 안. job 의 `items`(메시→USD)·`textures`(텍스처→PNG, `AssetExportTask` 가 확장자로 exporter 선택). ASCII 전용 |
| `Tools/usd_export/run_export_env.py` | 호스트. 인벤토리 → 분류 → job JSON(ensure_ascii) → commandlet → wrapper → 유리·노멀 override → pxr 실측 → `_summary.json`. `run_export.py` 의 `measure`/`flatten_constant_normals`/상수를 import 해 쓴다(차량 파일 무수정) |
| `Env/_inventory.json`, `_classification.json`, `_job.json`, `_report.json`, `_summary.json`, `_ue.log` | 실행 기록(출력 폴더, 미커밋) |

```powershell
python Tools\usd_export\run_export_env.py                # 인벤토리(없으면) → 120건 export → wrapper·측정
python Tools\usd_export\run_export_env.py --inventory    # 레벨 인벤토리만 다시
python Tools\usd_export\run_export_env.py --only camera pole arm topper
python Tools\usd_export\run_export_env.py --skip-export  # wrapper·override·측정만 (pxr 있는 파이썬으로)
```
commandlet 인자는 차량과 동일(`-run=pythonscript -AllowCommandletRendering -EnablePlugins=PythonScriptPlugin,USDImporter -DisablePlugins=EasyFileDialog -NoTextureStreaming -unattended -nop4`), `.uproject` 무수정. 측정용 pxr 은 `uv venv` + `uv pip install usd-core`(26.8).

## 5. 밟은 함정 / 새로 안 것

1. **wrapper 의 `def Xform` 이 지오메트리를 지운다.** LOD 가 하나뿐인 메시(120 중 90)는 UE 가 루트 prim 자체를 `Mesh` 로 내보내는데(LOD 여러 개면 `Xform` + `LOD0` 자식), 차량 wrapper 를 그대로 베낀 `def Xform "slug" (references …)` 는 타입 opinion 이 참조를 이겨 루트가 `Xform` 이 되고 **메시가 통째로 사라진다**. `measure()` 가 `meshes=0` 으로 잡아냈다(120 중 119 — 유일한 예외가 LOD 4개짜리 오토바이). 해법은 **타입 없는 `def "slug"`** — 참조된 쪽 타입이 올라오고 Mesh/Xform 둘 다 Xformable 이라 0.01 스케일은 그대로 먹는다. 차량 wrapper(`run_export.write_wrapper`)는 루트가 항상 Xform 이라 무사하지만 단일 LOD 메시에 쓰면 같은 일이 난다.
2. **`o.Get() or 1.0` 은 찾으려는 0.0 을 1.0 으로 바꾼다.** 유리 zero 판정에 그 관용구를 썼다가 `materials_zero_opacity=['MI_Glass']` 인데 `glass_fixed=[]` 로 나와 들켰다. None 만 따로 걸러야 한다.
3. **베이커 상수 노멀 결함 `(0.498,-0.498,1)` 은 환경 메시에서도 그대로 나온다** — 24종 48재질(노멀 텍스처가 없는 재질 전부: 카메라·폴대·암·토퍼·콘·사이렌 등). wrapper 에서 `(0,0,1)` 로 덮었다(차량과 같은 함수). 노멀 텍스처가 베이킹된 재질(나무·소품 대부분)은 해당 없음.
4. **카메라 렌즈 `MI_Glass` 와 오토바이 유리 3종은 베이킹 값이 전부 0**(#272 "값 없음") → wrapper 에서 차량 `glass_fix.py` 의 표(`clearglass/redglass/orangeglass`)와 같은 값을, 표에 없는 `MI_Glass` 는 clearglass 값(0.8 회색, opacity 0.30, IOR 1.45)을 override. **선택값이며 화면 미검증**.
5. **Nanite 메시는 UE 의 `get_num_triangles(0)` 과 USD 삼각형 수가 크게 다르다.** 51종이 Nanite 이고 그중 44종이 불일치 — `SM_UtilityPole` 2,048 → 61,386, `SM_Oak_1` 13,623 → 33,987, `street_light_Bottom_01` 1,953 → 52,480. `get_num_triangles` 는 Nanite 폴백(렌더 LOD0)을, USD exporter 는 소스 메시 디스크립션(Nanite 원본)을 쓴다. 나머지 76종(비-Nanite 69 + Nanite 7)은 정확히 일치. Omniverse 에는 원본 해상도가 간다 — 가볍게 쓰려면 소비자 쪽에서 줄여야 한다.
6. **텍스처 크기는 UE 가 말한 값을 믿으면 안 된다** — commandlet 에서 `Texture2D.blueprint_get_size_x()` 가 34장 전부 32 를 돌려줬다(스트리밍 꺼진 상태의 상주 밉 추정, 미확인). 판정은 PNG 헤더(IHDR)로 했다: 표식 2048², 간판 1080², 화살표 128×256.
7. **주차면 표식은 메시가 아니다.** `BP_ParkingSlot.uasset` 문자열에 `T_DisabledOnly`·`T_ElectricOnly`·… 가 박혀 있고 인벤토리에서 `ISM_Slot` 의 재질이 `MID_M_ParkingSlot_0`(텍스처 파라미터)로 확인됐다. 면 윤곽선은 머티리얼 함수(`MF_Rectangle*`)가 그리는 절차 재질이라 텍스처로도 안 나온다 — 슬롯 선 자체가 필요하면 `Plane` 에 `M_ParkingSlot` 을 베이킹하거나(512² 로는 선이 뭉개진다) Omniverse 쪽에서 다시 그려야 한다.
8. **바닥 재질은 에셋 기본값이 나간다.** 도로 슬래브 에셋의 재질은 `MI_Asphalt_MAIN` 인데 레벨은 컴포넌트 재질 override 로 `MI_Asphalt_no_Markings`(3곳)·`MI_Asphalt_Double_Center_Line_Yellow_`(대부분)를 쓴다. 에셋 export 는 override 를 모른다 → USD 슬래브의 차선 표시는 레벨 화면과 다를 수 있다(무엇이 다른지는 미검증). #272 가 지적한 "스플라인 팬 UV" 는 `SplineMeshComponent`(BP_Road_Creator7/13/14 의 13개) 얘기고 ISM 슬래브 33개는 평면 UV 다.
9. **`get_mesh_description` 은 UE 5.8 파이썬 `StaticMesh` 에 없다** — 소스 삼각형 수는 USD 쪽에서 세는 수밖에 없었다(5번의 근거는 Nanite 플래그 + USD 실측).
10. 첫 항목 39.6초(베이킹 셰이더 콜드 컴파일), 이후 항목당 0.1~1.4초 — 차량(첫 1대 119초)보다 짧은 것은 차량 배치가 DDC 를 이미 채워 둔 덕이다. 텍스처 34장은 합계 1.7초.
11. **대기 방식**: 백그라운드 알림을 기다리며 턴을 끝내면 이 환경에서 두 번 연속 멈췄다 — 완료 조건 until 루프를 **포그라운드 Bash(timeout 600000)** 로 붙잡는 편이 확실했다.

## 6. 검증된 것 / 안 된 것

**검증(수치·파일):** 120 메시 출력 실물, wrapper 120개 전부 pxr 로 열림·`meshes>=1`·bbox 가 상식과 일치(4장), LOD variantSet 30종, 텍스처 상대경로·누락 0, `materials_zero_opacity` 120종 전부 빈 목록(override 후), 노멀 override 48건, PNG 34장 헤더 크기, Nanite 44종 불일치의 원인 귀속(전부 Nanite).

**미검증:** Omniverse/Isaac 렌더가 이 PC 에 없다 → **모든 항목의 화면(색·노멀 override 효과·유리 값·베이킹 텍스처 품질·트리 카드 투명도(Opacity 채널 베이킹 여부)·도로 슬래브의 차선 표시)** 은 보지 못했다. 나무 재질 `MI_Oak/MI_Pine` 은 마스크드(잎 카드)일 가능성이 큰데 opacity 가 텍스처로 남았는지 값으로 축약됐는지는 파일에서만 확인 가능하고(텍스처 2장 존재) 렌더 결과는 모른다. 주차면 표식 PNG 의 알파가 Omniverse 데칼로 쓰기에 맞는지도 미확인.

## 8. 남은 선택지

- 레벨 통째(Landscape·보도·데칼·배치 포함)가 필요하면 #153 의 `LevelExporterUSD` 경로가 따로 있다 — 이 산출물은 에셋 라이브러리이고 배치는 `_inventory.json` 으로 조립해야 한다(ISM 인스턴스별 변환은 `inventory_level.py` 에 `get_instance_transform` 을 더하면 된다).
- 유리 값·노멀 override 는 wrapper 레이어에만 있어 원본 `.usdc` 무수정 — 렌더를 보며 `run_export_env.py` 의 `GLASS_FALLBACK` 만 고치고 `--skip-export` 로 재적용.
- 출력은 커밋하지 않는다(191 MB). 전달은 #272 처럼 zip + sha256.
