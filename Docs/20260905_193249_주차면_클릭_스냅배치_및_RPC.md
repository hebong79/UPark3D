# 주차면 클릭 스냅 배치 + `car.placeAtWorld` RPC

작성일: 2026-09-05
대상: `ParkingPresetManager` / `CarPlacementManager` / `CarPlacementWidget` / `CarRpcModule` / `ParkingDecalTest`

## 1. 요청

> 마우스로 클릭하여 차량배치 할 때 (첨부 화면처럼) 주차면 중앙에 자동으로 배치시켜 줘. RPC화도 해줘.

차량 배치 패널의 **배치 시작 → Ctrl+좌클릭** 경로는 지금까지 히트 지점을 그대로 썼다
(`CarPlacementWidget.cpp:543` → `AddCarAtWorld`). 그래서 `rotY=0`, `slotId=-1` 로
주차면과 무관하게 놓였고, 사선 주차면에서는 차가 면을 가로질러 섰다.

## 2. 결정 사항(사용자 확인)

| 항목 | 결정 | 비고 |
|------|------|------|
| 스냅 조건 | **주차면 사각형 안쪽을 클릭했을 때만** 스냅 | 밖이면 기존대로 클릭 지점에 그대로 배치 |
| 회전 | 면 길이축 정렬 + 차량 전면이 **그 프리셋의 감시카메라**(`CameraIdx`)를 향하는 쪽 | `random.slotPlace` 와 같은 규약 |
| 이미 찬 면 | 판정 없이 **그대로 겹쳐 배치** | `random.slotPlace` 와 같은 규약(중복을 막지 않는다) |

## 3. 변경 내용

### 3.1 `AParkingPresetManager::FindSlotAtWorld` (신규, 정적 순수 함수)

```cpp
static const FParkingPreset* FindSlotAtWorld(
    const TArray<FParkingPreset>& Presets, const FVector& WorldLoc, float MetersToUU,
    int32& OutSlotId, FVector& OutCenterWorld, float& OutAxisYaw);
```

- **"점 → 면" 역판정.** 기존 `ComputeSlotCorners`(면 → 사각형 4점)의 역방향이며,
  같은 함수가 만든 바로 그 사각형 위에서 판정한다. 라인·데칼·시뮬·랜덤배치와 기하가 갈라지지 않는다.
- XY 로만 판정한다(클릭은 바닥을 맞히므로 Z 는 무시). 사각형은 볼록하므로
  네 변의 외적 부호가 모두 같으면 내부이고, 변 위(외적 0)는 안쪽으로 친다.
- `OutAxisYaw` 는 긴 변 방향(전/후면 판정 **전** 값)이다. Unity yaw = `atan2(UE.Y, UE.X)`.
- 사각형이 겹치면 먼저 만난 것을 돌려준다(프리셋 배열 순 → 면 순).

### 3.2 `AParkingPresetManager::ResolvePresets` (신규)

`StoredPresets` 가 비면 `config_pmaker.json` 의 `preset_file` 을 읽어 캐시한다.

> ⚠ **프리셋 목록 이원화** — 시작 시 자동 로딩분은 `UPresetMakerWidget` 이 들고 있고
> `AParkingPresetManager::StoredPresets` 에는 **없다**(RPC `preset.load`/`scenario.load` 경로만 그걸 채운다).
> 이 폴백이 없으면 실행 중인 화면에서 스냅이 **한 번도 걸리지 않는다** — 값이 아니라
> 목록의 출처가 원인이라 코드만 봐서는 안 드러난다. `AParkingSimManager::ResolvePresets`
> 가 같은 이유로 같은 규약을 쓴다(그쪽은 매니저 액터가 아예 없는 경우까지 스스로 처리하므로 그대로 뒀다).

### 3.3 레벨의 `BP_ParkingSlot` 면 — **실제로 걸리는 쪽은 이것이다**

> ⚠ **프리셋만으로는 이 기능이 한 번도 동작하지 않는다.** `Save/Config/config_pmaker.json` 의
> `preset_file` 이 서신·객리단 **둘 다 `""`** 이고, 시작 자동 로딩은 빈 값을 조용히 건너뛴다
> (`Park3DGameMode.cpp:498`). 실행 중인 인스턴스(13510)에 `preset.list` 를 던지니 실제로 `[]` 였다.
> 게다가 `001_Preset_13Face.객리단.json` 의 그룹 오프셋은 LV_Park_03 의 `BP_ParkingSlot` 배치와
> 맞지 않는다(파일 UE 환산 (X,Y)cm = (5744,410)/(2571,417)/(-6,419) vs 레벨 액터 (356,355)/(-706,-2941)/(-1739,-6149)).

화면에 칠해져 있는 주차면의 진짜 출처는 **레벨의 `BP_ParkingSlot` 액터**다. 이 블루프린트는
면마다 ISM 인스턴스를 하나씩 둔다(레벨 인벤토리 `_inventory.json` 실측):

```
BP_ParkingSlot_C_6 / ISM_Slot (InstancedStaticMeshComponent, /Engine/BasicShapes/Plane)
  instances: 6
  [0] loc (1549.05, 2472.55, 10.1)  rot yaw 180  scale (2.64, 5.14, 1.0)
  [1] loc (1299.05, 2472.55, 10.1)  ...
```

플레인 로컬 바운즈가 ±50 이므로 **인스턴스 하나 = 264cm × 514cm 주차면 사각형**이고,
로컬 **X=폭 · Y=길이**라 차량 길이축 yaw = `인스턴스 yaw + 90°` 다.
같은 액터의 `ISM_Stopper`(스토퍼)·`ISM_Space`(통로 줄무늬)는 이름으로 거른다.
대상 액터는 클래스 이름 `BP_ParkingSlot*` 로 고른다 — 이 블루프린트는 C++ 타입이 없어 `Cast` 가 안 된다
(`APark3DGameMode::HideParkingSlotIcons` 와 같은 규약).

### 3.4 `ACarPlacementManager` — 단일 스냅 창구

```cpp
bool SnapCarPosToSlot(const FVector& WorldLoc, FCarPos& InOutPos) const;          // 값을 쓴다(C++ 전용)
UFUNCTION(BlueprintCallable)
bool FindParkingSlotAt(const FVector& WorldLoc, FVector& OutCenterWorld, float& OutYaw,
                       int32& OutPresetId, int32& OutSlotId) const;               // 조회만 한다
```

클릭 배치와 RPC 가 **같은 함수**를 부른다(복붙하면 한쪽만 고쳐진다).

- 면 출처 순서: **① 프리셋 면**(로드돼 있으면 `presetId`/`slotId` 까지 채워 sim·scenario 와 같은 공간)
  → **② 레벨 `BP_ParkingSlot` 면**(번호가 없으므로 `presetId`/`slotId` 는 건드리지 않는다 = `slotId` -1 유지).
- 면 밖이면 **아무것도 바꾸지 않고** `false` → 호출부는 클릭 지점을 그대로 쓴다.
- `isFront` 는 건드리지 않는다. 후면주차 지정은 호출부 몫이며 `ACarActor` 가 +180 을 붙인다.
- 높이는 클릭 지점이 아니라 **면 자신의 평면**을 따른다 — 같은 면에 클릭으로 놓든 RPC 로 놓든
  차가 같은 높이에 서게 하기 위해서다(프리셋 면은 `random.slotPlace` 와 같은 값).
- 전면 방향 기준 카메라: 프리셋 면은 그 프리셋의 `CameraIdx`, 레벨 면은 번호가 없으므로 **가장 가까운** PTZ 카메라.

> ⚠ **함정 — `UPARAM(ref)` 를 붙이면 블루프린트/파이썬에서 결과를 못 읽는다.** 처음엔
> `SnapCarPosToSlot` 을 `UFUNCTION(BlueprintCallable)` + `UPARAM(ref) FCarPos&` 로 노출했는데,
> `UPARAM(ref)` 는 그 파라미터를 **입력 전용**으로 만들어 파이썬이 넘긴 구조체 복사본만 바뀌었다
> (검증 스크립트가 `snapped:true` 인데 `pos` 가 전부 0 인 것으로 잡아냈다). 값 쓰기는 C++ 전용으로 두고
> **조회를 `FindParkingSlotAt` 으로 분리**해 노출했다. 참고로 UE 파이썬은 `bool` 반환 + out 파라미터 함수를
> 성공 시 out 튜플, 실패 시 `None` 으로 돌려준다(반환 bool 은 튜플에 없다).

### 3.5 위젯 (`UCarPlacementWidget::AddCarAtWorld`)

`FCarPos` 를 만든 뒤 `CarData.datas.Add` **전에** 스냅을 건다. 알림 문구도 갈린다:

- 스냅됨: `배치 +1 — 1번 프리셋 6번 면 (총 24대)`
- 면 밖: `배치 +1 (총 24대)` (기존과 동일)

### 3.6 RPC `car.placeAtWorld` (신규)

| 파라미터 | 기본값 | 설명 |
|---|---|---|
| `pos` (필수) | — | UE 미터. **`x`·`y` 가 지면, `z` 가 높이** |
| `snap` | `true` | false 면 스냅 없이 지점 그대로 |
| `prefabId` / `prefabName` | 1 | `prefabId` 우선, 없으면 이름으로 카탈로그 조회 |
| `type` | 1(Small) | `ECarType` 정수 |
| `presetId` | 1 | 스냅되면 실제 프리셋 번호로 덮인다 |
| `rotY` | 0 | 스냅되면 면 축 값으로 덮인다 |
| `isFront` | true | 스냅이 건드리지 않는다 |
| `color` | -1 | -1 = 미도색 |

응답: `{ok, carNameId, snapped, presetId, slotId, rotY, pos}`.

> ⚠ **`pos` 해석이 `car.create` 와 다르다.** `car.create` 가 쓰는 `RpcParam::RequirePosXZ` 는
> `x`,`z` 를 필수로 받고 **지면 y 를 0 으로 채운다**(Unity 시절 x,z 가 지면이던 잔재).
> 그 규약을 그대로 쓰면 스냅 판정이 y=0 인 엉뚱한 자리를 보게 되므로,
> 이 메서드는 `pos` 키만 필수로 확인하고 `{x,y,z}` 를 그대로 읽는다.

### 3.7 테스트

`Park3D.ParkingDecal.FindSlotAtWorld` 신설(5 케이스): 면 안 적중·2번 면·면 밖 두 방향·
면회전 90°의 길이축·프리셋이 여럿일 때 품는 쪽 선택.

## 5. 남은 한계

- **화면 판정 미검증.** 이 프로젝트에서 "값이 들어갔는데 화면이 다르다"가 여러 번 나왔으므로
  실제 클릭 배치는 실행 인스턴스에서 캡처로 확인해야 한다. 정본(13510)은 이전 빌드라
  exe 를 갈아끼우고 재기동해야 반영된다(`Save/` JSON 은 따라오지 않는다 — 2026-08-18 항목).
- 전면이 카메라를 향하게 뒤집는 분기는 커맨드릿 월드에 카메라가 없어 실행되지 않았다.
- 면이 겹치면 "먼저 만난 면"이 이긴다 — 클릭으로는 뒤쪽 면을 고를 수 없다.
- 레벨 면으로 스냅한 차량은 `slotId` 가 `-1`(슬롯 외) 그대로다. `random.slotJitter` 처럼
  `presetId`+`slotId` 로 대상을 고르는 기능은 이 차량들을 잡지 못한다.
