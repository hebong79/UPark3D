# 차량배치 대화상자 — 차량 오브젝트 콤보박스 기준 prefabId 강제 설정

작성일: 2026-07-22 14:01:42

## 1. 요구사항

차량배치 대화상자(`WBP_CarPlacement` / `UCarPlacementWidget`)에서 **차량 오브젝트 콤보박스(`Combo_Prefab`) 선택값을 기준으로 ID를 강제로 설정**한다.

사용자 확정 사항:

| 항목 | 확정 내용 |
|------|-----------|
| 강제 설정 대상 ID | `FCarPos::prefabId` (차량 타입 `type`, id 문자열 `Field_Idx` 는 대상 아님) |
| 적용 시점 | **수정 버튼(`Btn_Modify`) 클릭 시** (콤보 변경 즉시 반영·역방향 동기화는 범위 밖) |

## 2. 변경 전 문제점

`ApplyDetailFields()` 는 `presetId` / `slotId` / `rotY` / `isFront` 만 반영하고 `prefabId` 는 **전혀 건드리지 않았다.**

Unity 원본은 반영한다 — `unity/CarObject/CCarPlacementDlg.cs:774-782`:

```csharp
private void ToSaveData(SCarPos kCarPos)
{
    kCarPos.rotY     = float.Parse(m_inRotateY.text);
    kCarPos.slotId   = int.Parse(m_inFaceIdx.text);
    kCarPos.presetId = int.Parse(m_inPresetId.text);
    kCarPos.isFront  = m_toFrontFace.isOn;
    kCarPos.type     = m_cboCarType.value + 1;
    kCarPos.prefabId = m_cboCarPrefabs.value + 1;   // ← UE 포팅 시 누락됨
}
```

결과적으로 UE 버전에서는 콤보박스로 다른 차량 프리팹을 골라도 **이미 배치된 차량에는 적용할 방법이 없었다**(신규 추가·자동생성 시에만 반영).

## 3. 설계

### 3.1 prefabId 산출 규약 (회귀 주의)

Unity 원본은 `m_cboCarPrefabs.value + 1` 로 계산하지만, **UE 포팅에서는 이 식을 쓰지 않는다.**

- 근거: Unity `CCarPlacementDlg.cs:193-196` 주석 — "m_PrefabList 인덱스 순서와 SCarData.m_Idx 값은 일치하지 않을 수 있다"(누락/중복으로 `nPos+1 == m_Idx` 가정이 깨짐). Unity 자체도 `OnValueChanged_CarPrefabs()` 에서는 이름 매칭으로 `m_iCurPrefabId = kCarData.m_Idx` 를 쓴다.
- UE 는 `Combo_Prefab` 항목을 카탈로그(`DT_CarCatalog`) 순서 그대로 채우므로 **`Catalog[ComboIndex].Idx` 가 곧 `prefabId`** 다.
- `prefabId` 와 카탈로그 `Idx` 는 둘 다 **1-based 동일 공간**이다(기존 `Park3D.CarPlacement.CatalogLookup` 테스트가 이 규약을 고정하고 있음. 과거 0-based 로 오인해 전 차량이 한 칸 밀리는 회귀 있었음).

이는 기존 `AutoCreate()` / `AddCarAtWorld()` 의 산출 방식과 완전히 동일하다.

### 3.2 인터페이스 (신규)

순수 함수로 분리해 유닛 테스트가 가능하도록 했다(기존 `BuildShiftSelection`, `FindEntryByPrefabId` 와 동일한 패턴).

```cpp
// CarPlacementLibrary.h
UFUNCTION(BlueprintCallable, BlueprintPure, Category = "Car|Data")
static int32 PrefabIdFromComboIndex(const TArray<FCarPresetEntry>& Catalog,
                                    int32 ComboIndex, int32 FallbackId = 1);
```

| 입력 | 반환 |
|------|------|
| `ComboIndex` 가 `Catalog` 유효 범위 | `Catalog[ComboIndex].Idx` |
| `INDEX_NONE`(미선택) / 범위 초과 / 빈 카탈로그 | `FallbackId` |

### 3.3 처리 흐름

```
[사용자] 리스트/월드에서 차량 선택
   → 차량 오브젝트 콤보(Combo_Prefab)에서 원하는 프리팹 선택
   → [수정] 버튼 클릭
       ↓
ModifySelected()
   → ApplyDetailFields(CarData.datas[PrimaryIndex])
        presetId / slotId / rotY / isFront  (기존)
        prefabId = PrefabIdFromComboIndex(GetCatalog(), Combo_Prefab->GetSelectedIndex(), 기존값)  ← 신규
   → RebuildCarList()
   → RefreshView() → Mgr->RebuildAll(CarData, Catalog, Sel)
        ↓ prefabId 로 카탈로그 메시를 다시 찾아 스폰 → 월드 차량 메시가 즉시 교체됨
```

`prefabId` 변경이 화면에 반영되는 것은 `ModifySelected()` 가 이미 `RefreshView()` 를 호출하고, `ACarPlacementManager::RebuildAll()` 이 `FindEntryByPrefabId()` 로 메시를 재해석하기 때문이다. **추가 변경 없이 메시 교체가 동작한다.**

### 3.4 대안 비교

| 대안 | 내용 | 채택 여부 |
|------|------|----------|
| A. `ApplyDetailFields()` 에서 반영 | 수정 버튼 경로에만 개입. Unity `ToSaveData()` 와 1:1 대응 | **채택** (사용자 확정 시점과 일치, 변경 최소) |
| B. `Combo_Prefab->OnSelectionChanged` 즉시 반영 | 콤보를 건드리는 순간 선택 차량이 바뀜 | 미채택 — 실수로 콤보를 스크롤해도 데이터가 변해 위험 |
| C. 위젯 내 인라인 계산(라이브러리 함수 없이) | 코드 3줄 더 짧음 | 미채택 — 유닛 테스트 불가(코딩 규칙 1번 위배) |
| D. 콤보 인덱스 `+1` 사용 (Unity 식 그대로) | 원본과 동일 | **미채택 — 회귀 위험**. §3.1 참조 |

### 3.5 의도적으로 하지 않은 것 (범위 밖)

- `type`(차량 타입) 강제 반영 — 사용자가 `prefabId` 만 선택. `Combo_Type` 값은 수정 시 여전히 무시된다.
- 차량 선택 시 콤보박스 역방향 채움(Unity `FromSaveData()` 의 `m_cboCarPrefabs.value = kCarPos.prefabId - 1`) — 미구현.
- 다중 선택 차량 일괄 적용 — 기존과 동일하게 `PrimaryIndex` 1대에만 적용.

## 6. 영향도 분석

### 6.1 직접 영향

| 대상 | 영향 |
|------|------|
| `Btn_Modify` (수정) 동작 | **동작 변경**. 이제 선택 차량의 `prefabId`(=차량 메시)가 콤보박스 값으로 덮어써진다. 수정 버튼을 rotY/presetId 조정용으로만 쓰던 사용 습관에서는 **의도치 않게 차량 종류가 바뀔 수 있다.** → §6.4 권고 참조 |
| 월드 메시 | `RefreshView()` → `RebuildAll()` 경로로 자동 교체. 별도 처리 불필요 |
| JSON 저장/로드 | 스키마 무변경. `prefabId` 필드는 원래 존재. 호환성 영향 없음 |

### 6.2 회귀 없음 확인 대상

- `AutoCreate()` / `AddCarAtWorld()` — 미수정. 기존 인라인 계산식 그대로이며, 신규 함수와 산출 결과가 동일하다.
- `ACarPlacementManager::FindEntryByPrefabId()` — 미수정. `Park3D.CarPlacement.CatalogLookup` 테스트가 계속 규약을 보호한다.
- `UPresetMakerWidget` 등 타 위젯 — `CarPlacementLibrary` 신규 함수는 추가만 했으므로 기존 심볼 영향 없음.

### 6.3 빌드 의존성

- 새 심볼은 `PARK3D_API UCarPlacementLibrary` 의 정적 함수 1개 추가뿐 — 모듈/`Build.cs` 변경 없음.
- 헤더 변경(`CarPlacementLibrary.h`)이 있어 이 헤더를 include 하는 파일들의 재컴파일 필요(`CarPlacementWidget.cpp`, `CarPlacementManager.cpp`, 테스트 2종). UHT 재실행 필요(`UFUNCTION` 추가).

### 6.4 운영 권고 (미해결 사항)

차량 선택 시 콤보박스가 그 차량의 `prefabId` 로 되돌아 채워지지 않으므로(§3.5), **차량 A(프리팹 3)를 선택한 뒤 콤보가 여전히 프리팹 1 을 가리키는 상태에서 수정 버튼을 누르면 A 가 프리팹 1 로 바뀐다.** Unity 원본은 `FromSaveData()` 에서 콤보를 되채워 이 문제가 없다. 후속으로 역방향 동기화(§3.5 2번 항목) 구현을 권장한다.

2. 리스트에서 그 차량 선택 → 차량 오브젝트 콤보에서 **다른 프리팹** 선택 → **수정** 클릭
