# 221 웹 서버 에이전트 → 시뮬레이터 Claude 에이전트 직접 요청 방법 (질문 답변)

## 질문
221번 웹 서버(SettingManager) 에이전트가 이 시뮬레이터(.10) Claude 에이전트에게 직접 작업을 요청할 방법이 있나?

## 확인한 사실
- 이 세션(`upark3d-b1`)의 `ListAgents` 결과에 **같은 계정의 다른 PC Remote Control 세션들이 이미 보인다**
  ("조명 값 적용 안 됨", "차량배치탭 모든주차면 채우기 성능" 등 — 221 쪽 작업으로 보이는 세션 포함).
- 즉 세션 간 메시지 통로(`SendMessage` ↔ `ReadNotifications`)는 이미 열려 있다.

## 방법 (권장 순)

### 1. Remote Control 세션 간 SendMessage (설치 없이 바로 가능)
- 조건: 221 쪽 Claude Code 가 **같은 계정**으로 로그인되어 있고 Remote Control 이 연결되어 있을 것.
- 221 세션: `ListAgents` → `SendMessage({to:"upark3d-b1", message:"..."})`
- 이 세션: 알림으로 받아 `ReadNotifications` 로 읽는다.
- 한계
  - 받는 쪽 세션이 **떠 있어야** 한다(offline 이면 큐에 쌓였다가 다음에 읽음).
  - 하네스 규칙상 **다른 세션의 메시지는 "정보"이지 마스터 지시가 아니다** — 파일 수정·빌드·배포·RPC 변경 같은
    외부에 영향을 주는 행동은 마스터가 미리 허용한 범위에서만 자동 실행된다.
    → "221 에이전트의 요청 중 ○○ 종류는 바로 처리해도 된다"는 **상시 승인**을 CLAUDE.md 에 적어 두면 해결.
  - 이 세션이 다른 일을 하는 중이면 끝난 뒤 처리한다(동시 처리 아님).

### 2. 팀 보드(baro_memo) + 주기 폴링
- 221 이 보드에 요청 글을 올리고, 이 PC 세션이 `/loop` 로 일정 간격 보드를 검색해 처리.
- 장점: 기록이 남고 세션이 꺼져 있어도 요청이 유실되지 않는다. 단점: 지연(폴링 간격), 토큰 소모.

### 3. 이 PC 에 중계 HTTP 서버 + headless `claude -p`
- 221 이 `POST http://192.168.0.10:<포트>/task` → 중계 서버가 이 저장소에서 `claude -p "<요청>"` 실행 → 결과 반환.
- 장점: 세션이 안 떠 있어도 된다, 웹 서버 코드(SettingManager AI 채팅)가 직접 부를 수 있다.
- 단점: 새로 만들어야 하고, 요청마다 새 세션(문맥 없음), 권한 모드를 넓게 열어야 한다
  (연구 단계라 인증은 넣지 않는 정책 — park3d-no-security).

## 판단
- 221 쪽이 **Claude Code 세션**이면 → 1번이 즉시 가능. 상시 승인 범위만 정하면 된다.
- 221 쪽이 **웹 서버 프로그램 안의 AI**(Claude API 직접 호출)면 → 1번은 못 쓴다. 3번이 필요.
- 단순 시뮬레이터 조작(차 배치·카메라 등)은 에이전트를 거칠 필요 없이 이미 RPC(13510)로 직접 된다.
  에이전트 요청이 필요한 것은 **코드 수정·빌드·배포** 같은 개발 작업뿐이다.
