# 시작 슬롯 수동 지정이 '수정'할 때마다 되돌아가는 문제 — 번호 지정을 프리셋 밖의 목록으로

- 날짜: 2026-09-08
- 신고: "아직도 자동이 아닌데 자동처럼 슬롯시작 ~ 개수 만큼 외의 값들이 자동으로 변경된다. 근본적인 방법으로 수정해줘."
- 대상 인스턴스: 정본 `Package/Windows`(RPC 13510) — **손대지 않음**. 수정 exe 는 작업본 `Package/Work13520`(RPC 13520) 에 넣어 기동해 두었다.
- 변경 파일: `Park3D/Source/Park3D/CameraControlTypes.h`, `CameraControlLibrary.h/.cpp`, `CameraControlWidget.h/.cpp`, `ParkingPresetManager.h`(주석), `Rpc/Modules/CamRpcModule.h/.cpp`, `Tests/CameraControlLibraryTest.cpp`, `Tests/RpcServerTest.cpp`
- 파일 형식 변경 있음(3절). RPC 계약 변경 있음(4절).

## 2. 원인 — 기준점이 "카메라 프리셋마다 하나"였다

09-07/09-08 의 설계는 시작 슬롯을 `FCamDir`(카메라 프리셋 1개)의 필드 4개(`start_slot`/`start_face`/`start_count`/`auto_renumber`)로 들고 있었다. 즉 **프리셋 하나가 기준 면 하나만 기억한다.** 같은 프리셋에서 다른 면을 지정하면 덮어쓰기이고, 덮인 면은 원복된다.

그런데 바닥 번호는 카메라·프리셋과 무관하게 **주차장에 한 벌**뿐이다. 실제 적용도 모든 카메라·프리셋의 기준점을 **한꺼번에 모아** 한 번에 적용하고 있었으므로(`CollectNumberAnchors` → `SetNumberAnchors`), "프리셋별"이라는 것은 저장 위치의 이야기일 뿐 화면상 의미가 없었다. 프리셋을 넘겨도 바닥 번호는 안 바뀐다. 그 저장 위치가 만든 함정이 넷이다.

1. 같은 프리셋에서 두 번째 면을 지정하면 첫 지정이 사라진다(이번 신고).
2. 프리셋 '추가'가 줄의 값을 새 프리셋에 복사해 같은 기준점이 둘 생긴다.
3. 프리셋·카메라를 지우면 그 안의 기준점이 소리 없이 함께 빠진다.
4. 같은 면을 두 프리셋에서 지정하면 뒤에 오는 쪽이 이겨 어느 쪽이 살아 있는지 화면으로는 모른다.

여러 열을 각각 다시 매기려면 프리셋을 그 수만큼 만들어 하나씩 넣어야 했는데, 아무도 그렇게 생각하지 않는다.

## 3. 수정 — 번호 지정을 **파일 전체의 목록**으로 옮겼다

### 데이터

`FCamDir` 의 필드 4개를 없애고, 카메라 파일 루트(`FCameraPosList`)에 목록을 하나 둔다.

```json
{
  "isUnreal": true,
  "datas": [ ...카메라/프리셋 그대로... ],
  "slot_numbers": [
    { "face": "level:BP_ParkingSlot_C_2#0", "slot": 31, "count": 2, "auto_renumber": false },
    { "face": "level:BP_ParkingSlot_C_0#1", "slot": 51, "count": 2, "auto_renumber": false }
  ]
}
```

- 항목 하나 = "이 면(face)을 slot 번으로". 수동이면 count 장(0=한 장)만, `auto_renumber` 면 묶음 끝까지(count 무시). 규칙은 종전과 같고 매니저(`ApplyNumberAnchors`)는 손대지 않았다 — 원래부터 목록을 받고 있었다.
- 같은 face 를 다시 지정하면 **그 항목만** 바뀐다. slot 0 은 그 face 의 지정을 지운다. 다른 face 는 건드리지 않는다(`UCameraControlLibrary::SetSlotNumber` 한 곳 — 패널과 RPC 가 같은 함수를 쓴다).
- 호환: `slot_numbers` 가 없는 옛 파일·Unity 파일은 빈 목록으로 읽힌다. Unity 파서는 모르는 키를 무시한다. **09-07~09-08 사이에 `start_slot` 을 넣어 저장한 파일은 그 값을 읽지 않는다** — 정본·저장소에 그런 파일은 없었다(값이 든 것은 작업본에서 어제 검증용으로 만든 객리단 파일 하나뿐). 필요하면 다시 지정해 저장한다.

### 패널("시작 슬롯" 줄)

배치는 그대로(시작 슬롯 · 갯수 · ☐ 자동 · 안내 문구). 동작만 바뀐다.

- LShift+클릭으로 면을 찍고 번호·갯수를 쓰고 **'수정'** → 그 면의 항목이 목록에 들어간다. **앞서 지정한 다른 면은 그대로 남는다.**
- 이미 지정된 면을 찍으면 그 항목의 번호·갯수·자동이 칸에 올라오고 문구가 `기준 면 #11(지정됨) → '수정'` 이 된다. 번호 칸을 **비우고 '수정'** 하면 그 면의 지정만 풀린다.
- 문구 끝에 `· 지정 N곳` 이 붙는다 — 목록이 몇 개인지 볼 곳이 여기뿐이다.
- 프리셋·카메라를 바꿔도 줄은 바뀌지 않는다(목록은 프리셋 것이 아니다). '열기'·'초기화'는 줄을 비운다. **'초기화'는 목록도 통째로 비운다**(카메라 1대로 줄이는 그 버튼).
- 프리셋 '추가'·'삭제', 카메라 '삭제'는 목록과 무관해졌다.
- '수정'마다 로그 한 줄: `[CameraControl] 번호 지정 '수정': 면 <키>(#순번) 번호 N 갯수 C 자동 A → 반영|변경 없음(지정 K곳)`. "안 먹는다"가 오면 이 줄부터 본다.

### RPC

- `cam.savePreset` 의 `startSlot`/`startFace`/`startCount`/`autoRenumber` 파라미터와 프리셋 응답의 같은 이름 4개를 **제거**했다(어제 열린 것, 보드에 사용처 없음).
- **`cam.setSlotNumber`** `{face, slot, count?, auto?, save?, fileName?}` 신설 — 목록에 넣거나(같은 face 는 덮음) `slot:0` 으로 지운다. 바닥에 즉시 반영. `save:true` 면 파일에 쓰되 **메모리에 카메라가 없으면(`cam.loadPreset` 전) 거부**한다 — 카메라 0대짜리 파일로 덮어쓰지 않기 위해. 응답 `{ok, changed, slotNumbers:[…], fileName?}`.
- **`cam.slotNumbers`** `{}` → `{count, slotNumbers:[{face, slot, count, auto}]}`.
- `cam.loadPreset` 은 파일의 목록을 그대로 바닥에 적용한다(종전과 같음). `cam.savePreset`/`cam.deletePreset` 은 더 이상 번호를 건드리지 않는다.
- 패널 `CamData` 와 RPC `PresetMemory` 가 별개인 점은 그대로다 — 마지막에 넘긴 쪽이 이긴다(09-08 문서와 같은 한계).

## 6. 함정 — 자동화 쪽(다음 세션용)

- **입력 자동화 키가 사용자 창으로 새어 들어갔다.** 작업본 창을 `SetForegroundWindow` 로 못 올린 채 키를 보냈더니 사용자가 쓰던 창에 "31" 이 찍혔다. 이후 `panel_auto.py` 는 매 입력 전에 `GetForegroundWindow()==작업본` 을 확인하고 아니면 아무 입력도 없이 중단한다. 사용자가 자리에 있을 때는 이 가드 없이 합성 입력을 보내지 말 것.
- **칸을 비우려고 보낸 Delete 스캔코드 0x53 은 숫자패드 Del/'.' 이다.** NumLock 이 켜져 있으면 '.' 이 찍혀 칸이 `.31` 이 되고 `Atoi` 가 0 을 돌려준다 — 화면엔 "31" 처럼 보여 한참 헤맸다(로그에 raw 값을 찍고서야 갈렸다). Backspace(0x0E) 를 쓸 것.
- **마우스 down/up 80ms 는 프레임이 느릴 때 한 틱에 묻혀 클릭 에지가 안 잡힌다.** 350ms 로 늘리니 LShift+클릭이 매번 잡혔다.
