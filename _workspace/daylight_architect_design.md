# [daylight] 설계서 — 레벨 조명 한낮 상향

작성: architect 역할 / phase = `daylight`
대상 맵: `/Game/Maps/PresetMaker1` (World Partition + OFPA)

## 1. 요구사항

사용자 요청: "화면이 너무 어둡다. 좀더 밝게 조정해줘."
사용자 결정 사항(질의 확인 완료):
- 방식 = **레벨 조명 자체를 밝게** (노출 보정·런타임 조절 기능 추가는 배제)
- 목표 = **한낮 (밝고 또렷)**

| ID | 요구사항 | 검증 기준 (측정 가능) |
|----|---------|----------------------|
| R1 | 한낮 수준 밝기 | Camera-1 캡처의 지면·차량 영역(하단 65%) 평균 루마 **110~150** |
| R2 | 주차선·차량 색이 또렷 | 뭉갬(루마 ≤16) **≤ 5%**, 클리핑(≥254) **≤ 1%**, 지면 중앙값 **≥ 90** |
| R3 | 노출 고정 설계 유지 | `PP_FixedExposure` 프로퍼티 **변경 0건** |
| R4 | 최소 변경 | 라이트 프로퍼티 외 에셋·코드 변경 0건 |
| R5 | 카메라 뷰어에도 반영 | Camera-2 캡처도 R1 범위 충족 |

### 현재 상태 실측 (변경 전 기준선)

`cam.captureJPG(camId=1, 1280x720)` → 측정:

| 지표 | 현재 값 | 목표 |
|------|--------|------|
| ground_mean_luma | **16.6** | 110~150 |
| ground_median_luma | **5.5** | ≥ 90 |
| ground_p95_luma | 56.4 | - |
| sky_mean_luma | 79.2 | - |
| crushed(≤16) | **71.19%** | ≤ 5% |
| clipped(≥254) | 0.00% | ≤ 1% |

지면 픽셀의 71%가 완전 검정으로 뭉개져 있다. 이는 "어둡다"가 주관적 인상이 아니라 **정보가 실제로 소실된 상태**임을 뜻한다.

## 2. 원인 분석

레벨의 조명 리그 실측값 (헤드리스 파이썬 조사, `_workspace/daylight_lightscan_before.log`):

| 액터 | 프로퍼티 | 값 |
|------|---------|-----|
| `DirectionalLight` | Intensity | **6.0 lux** (UE5 기본 태양광 10.0 미만) |
| | Rotation | pitch **−16.29**, yaw 43.73, roll 112.36 |
| | AtmosphereSunLight | True (index 0) |
| `SkyLight` | Intensity | 1.0 |
| | SourceType / RealTimeCapture | SLS_CAPTURED_SCENE / **True** |
| `PP_FixedExposure` (unbound, prio 1) | AutoExposureMethod | HISTOGRAM (override) |
| | Bias | 1.0 (override) |
| | Min/MaxBrightness | **0.0 / 0.0** (override) → EV100 고정 |
| `SkyAtmosphere` / `VolumetricCloud` / `ExponentialHeightFog` | - | 기본값 |

**원인 두 가지가 겹쳐 있다.**

1. **태양 고도가 16.29°** — 일몰 직전 각도. 수평 지면에 대한 입사 코사인이 sin(16.29°) = **0.28**로, 들어오는 빛의 72%가 각도 때문에 손실된다. 더해서 저각도는 대기 통과 경로가 길어 `SkyAtmosphere` 투과율까지 떨어뜨린다(캡처 이미지에서 지평선이 붉게 뜬 이유).
2. **노출이 고정** — `Min/MaxBrightness = 0.0/0.0`이라 자동 노출이 사실상 잠겨 있다. 일반적인 씬이라면 어두운 조명을 노출계가 보정해 주지만, 여기서는 보정이 없어 조명 부족이 화면에 그대로 나온다.

`PP_FixedExposure`라는 명명과 min=max 고정은 **CCTV 화면 밝기를 프레임마다 일정하게 유지하려는 의도된 설계**로 판단한다(카메라가 차량을 비출 때 자동 노출이 출렁이면 감시 영상으로 못 쓴다). 따라서 노출은 건드리지 않고 **조명만** 올린다 — 사용자 선택과도 일치한다.

## 3. 변경 설계 (안 A — 채택)

코드 변경 없음. 레벨 액터 프로퍼티 2건만 변경한다.

| 대상 | 프로퍼티 | 현재 | 변경 후 | 근거 |
|------|---------|------|--------|------|
| `DirectionalLight` | Rotation.Pitch | −16.29 | **−55.0** | 태양 고도 16.29° → 55°. 입사 코사인 0.28 → 0.82 (**2.9배**) + 대기 투과율 상승. 90°(정오 수직)로 하지 않는 이유는 그림자가 완전히 사라져 차량 형상 구분이 나빠지기 때문 — R2("또렷")를 위해 그림자를 남긴다 |
| `DirectionalLightComponent` | Intensity | 6.0 | **10.0** | UE5 DirectionalLight 기본 태양광 값. 기본 미만이던 것을 표준으로 복귀 (**1.67배**) |
| `SkyLight` | Intensity | 1.0 | **유지(1차)** | `RealTimeCapture=True`이므로 하늘이 밝아지면 앰비언트가 **자동으로** 따라 오른다. 먼저 변경 없이 측정하고, 그늘 뭉갬(R2)이 남을 때만 2차로 조정 |

- **Yaw 43.73 / Roll 112.36 유지**: yaw를 유지해 그림자 방향을 보존한다(기존 주차장 배치의 시각적 인상 변화 최소화). Roll은 디렉셔널 라이트의 진행 방향(액터 +X)을 바꾸지 않으므로 무관하며, 불필요한 변경을 피하기 위해 그대로 둔다.
- 예상 배율: 2.9(각도) × 1.67(광량) × 대기 투과율 상승분 ≈ **7배 이상**. 기준선 16.6 → 목표 110~150 구간에 들어갈 것으로 추정하나, 톤매퍼가 비선형이므로 **추정에 의존하지 않고 측정으로 수렴시킨다**(6절).

## 4. 대안 비교

| 안 | 내용 | 채택 여부 | 사유 |
|----|------|----------|------|
| **A** | 태양 고도·광량 상향 | **채택** | 실제로 빛이 늘어 그늘 속 정보가 복원된다. 그림자·반사가 자연스럽고 카메라 뷰어와 메인 화면이 함께 밝아진다 |
| B | `PP_FixedExposure`의 Bias를 1.0 → 4.0 | 기각 | 값 하나로 즉효지만, 조명은 그대로라 **이미 검정으로 뭉개진 71%에는 복원할 정보가 없다**. 노이즈만 증폭되고 하늘이 먼저 클리핑된다. R3(노출 고정 유지)과도 충돌하며 사용자가 "조명 자체" 방식을 선택해 배제 |
| C | `SkyLight` Intensity만 크게 상향 | 기각 | 앰비언트만 오르면 그림자가 사라져 평평해진다. "밝고 또렷"의 또렷함과 정면 배치 |
| D | C++로 런타임 조명 제어 추가 | 기각 | 사용자가 방식 질의에서 선택하지 않음. R4(최소 변경) 위배 |

## 5. 처리 흐름

에디터·Unreal MCP(8000)가 모두 미기동이므로 GUI 경로를 쓸 수 없다. 동작이 확인된 **`UnrealEditor-Cmd.exe -run=pythonscript` 헤드리스 경로**로 수행한다.

```
1. 헤드리스 파이썬: 맵 로드 → DirectionalLight/SkyLight 획득 → 프로퍼티 설정 → save_dirty_packages
   (WP+OFPA이므로 .umap이 아니라 __ExternalActors__ 하위 .uasset이 저장된다)
     ↓ 검증: 재조사 스크립트로 프로퍼티 영속 확인 (T1)
2. UnrealEditor.exe -game 을 별도 RPC 포트로 기동 (실행 중인 패키지 13510과 병존)
     ↓
3. cam.captureJPG → measure.py 로 R1/R2 판정 (T2, T3)
     ↓ 미달 시
4. 값 조정 후 1~3 반복 (최대 3회, 초과 시 사용자에게 보고하고 중단)
     ↓ 통과 시
5. 재패키징 — 실행 중인 Park3D.exe(PID 14284/21508) 종료가 필요하므로 **사용자 확인 후** 수행
```

## 7. 미해결 리스크

- **R-1**: 예상 배율 7배가 톤매퍼 특성상 목표 구간을 넘어 하늘이 클리핑될 수 있다 → 6절 수렴 루프의 measure.py `clipped_px`로 감지, 초과 시 Intensity를 낮춰 재수렴.
- **R-2**: 태양 고도 변경으로 `VolumetricCloud`·`ExponentialHeightFog` 외관이 함께 바뀐다(일몰 붉은빛 → 주간 흰빛). 이는 "한낮" 요구의 필연적 귀결이라 허용하되, 사후 영향도에 명시한다.
- **R-3**: 라이트맵을 쓰는 스태틱 라이팅 에셋이 있다면 리빌드가 필요할 수 있다 → 사전 영향도에서 라이팅 모빌리티 확인.
