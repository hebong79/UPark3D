# 카메라 스트림 포트 대역을 config_pmaker.json 으로 이관 — 설계서

- 작성일: 2026-08-05
- 선행: `Docs/20260805_223740_시작시_설정파일_자동로딩_설계서.md`, `Docs/20260805_180808_카메라별_전용포트_MJPEG_스트리밍_설계서.md`

## 1. 요구사항

1. `config_pmaker.json` 에 카메라 스트림 포트 대역 `min=13601`, `max=13610` 을 둔다.
2. 포트 부여는 지금과 동일하게 쓴다(cam1=13601, cam2=13602 …).
3. 카메라 대수가 대역을 넘으면 **config 를 수정해서** 쓴다.
4. 대수 확인 시점은 **카메라위치 파일 로딩 시**와 **파일 저장 시**. 초과면 config 도 함께 수정한다.

## 2. 현재 구조와 차이

| | 현재 | 변경 후 |
|---|---|---|
| 대역 설정 | `DefaultGame.ini` `[/Script/Park3D.CamStreamSubsystem] BasePort=13600`, `MaxCameras=10` | `config_pmaker.json` `cam_port_min`/`cam_port_max` 우선, 없으면 ini |
| 포트 계산 | `ResolvePort(BasePort, CamId, MaxCameras) = BasePort + CamId` | **그대로** |
| 대수 초과 | 채널을 못 받음(조용히 스트림 없음) | 대역을 늘리고 config 에 기록 |

`BasePort = cam_port_min - 1`, `MaxCameras = cam_port_max - cam_port_min + 1` 로 환산해서 넣는다.
이러면 포트 계산 함수와 기존 유닛테스트(`Park3D.Rpc.CamStream.ResolvePort`)를 건드리지 않는다.
`min=13601, max=13610` → `BasePort=13600, MaxCameras=10` = 지금과 완전히 같은 동작이다.

## 3. 인터페이스

### 3.1 `FPark3DAppConfig` (확장)

```cpp
int32 CamPortMin = 0;   // 0 = 미지정
int32 CamPortMax = 0;   // 0 = 미지정
```

JSON 키: `cam_port_min`, `cam_port_max`. **둘 다 있어야** 적용한다(하나만 있으면 미지정 취급).

유효 조건: `2 <= min <= max <= 65535`.
`min=1` 을 막는 이유 — `BasePort = min-1 = 0` 이 되는데 `ResolvePort` 는 `BasePort <= 0` 을 거부한다.

### 3.2 `UPark3DAppConfigLibrary` (추가)

```cpp
/** config 파일의 cam_port_max 만 바꿔 다시 쓴다. 나머지 키는 원본 그대로 보존한다. */
static bool UpdateCamPortMax(const FString& Path, int32 NewMax);
```

구조체를 통째로 직렬화하지 않고 **원본 JSON 오브젝트를 읽어 해당 필드만 교체**한다. 그래야 이 구조체가
모르는 키(나중에 사람이 손으로 넣은 항목)가 자동 수정 과정에서 사라지지 않는다.

### 3.3 `Park3DCamStream` (순수함수 추가)

```cpp
/** [min,max] → (BasePort, MaxCameras). 범위가 유효하지 않으면 false 이고 Out 을 건드리지 않는다. */
bool PortRangeToBase(int32 MinPort, int32 MaxPort, int32& OutBasePort, int32& OutMaxCameras);

/** 카메라 CamCount 대를 담는 데 필요한 max 포트. min+Count-1, 65535 초과면 65535 로 클램프. */
int32 ExtendedMaxPort(int32 MinPort, int32 CamCount);
```

### 3.4 `UCamStreamSubsystem` (추가)

```cpp
/**
 * 카메라 CamCount 대를 담도록 포트 대역을 보장한다. 모자라면 대역 상한을 늘리고,
 * config 파일이 있으면 cam_port_max 를 함께 기록한다. 늘렸으면 true.
 */
bool EnsurePortRangeForCameras(int32 CamCount);
```

## 4. 처리 흐름

### 4.1 기동 (`Initialize`)

```
BasePort=13600, MaxCameras=10          (ini 값 = UPROPERTY(config))
 → config_pmaker.json 로드
 → cam_port_min/max 둘 다 유효하면 PortRangeToBase 로 환산해 덮어쓴다
 → 로그: [CamStream] 포트 대역 13601~13610 (출처: config|ini)
```

우선순위는 `config_pmaker.json > DefaultGame.ini > 코드 기본값`. rpc_port 에서 정한 규약과 같다
(카메라 포트에는 커맨드라인 스위치가 없다).

### 4.2 대수 확인 (요구사항 4)

```
UCameraControlWidget::LoadFromJsonFile   ← 파일 열기 + 시작 시 자동 로딩(같은 경로)
    SyncCamerasToData(...) 직후 → EnsurePortRangeForCameras(Mgr->GetCameraCount())

UCameraControlWidget::HandleSave         ← 카메라위치 파일 저장
    저장 성공 직후 → EnsurePortRangeForCameras(Mgr->GetCameraCount())
```

`EnsurePortRangeForCameras(N)`:

```
N <= MaxCameras                    → false (변경 없음)
NewMax = ExtendedMaxPort(min, N)   → 65535 클램프
MaxCameras = NewMax - min + 1      (메모리 즉시 반영 → 다음 Tick 의 SyncChannels 가 채널 개설)
config 파일이 있으면 UpdateCamPortMax 기록, 없으면 메모리만 확장하고 그 사실을 로그로 남긴다
```

채널 개설 자체는 기존대로 `Tick → SyncChannels` 가 한다. 이 함수는 **상한만** 올린다.

### 4.3 축소는 하지 않는다

카메라가 줄어도 `cam_port_max` 를 되돌리지 않는다. 되돌리면 사용자가 의도해서 넓혀둔 대역을 앱이
말없이 좁히게 된다. 채널 자체는 `SyncChannels` 가 카메라 수에 맞춰 닫으므로 포트는 실제로 점유되지 않는다.

## 5. 대안 비교

| 대안 | 판단 |
|---|---|
| (A) min/max → BasePort/MaxCameras 환산 (채택) | 포트 계산 함수·기존 테스트 무수정. 설정 표현만 바뀐다. |
| (B) `ResolvePort` 시그니처를 (Min,Max,CamId) 로 변경 | 포트↔카메라 매칭 함수(어긋나면 다른 카메라 영상이 나가는 조용한 실패)를 건드려야 한다. 이득 없이 위험만 늘어 기각. |
| (C) 초과 시 config 대신 ini 수정 | ini 는 빌드 설정 성격이고 패키지에서 쓰기 대상이 아니다. 사용자 요구도 config. 기각. |
| (D) 매 Tick 마다 대수 확인·config 기록 | 파일 쓰기를 틱에 넣게 된다. 로딩/저장 시점만 확인하는 요구사항이 더 안전하고 저렴하다. 채택하지 않음. |

## 6. 영향 예상

- `min=13601,max=13610` 인 기본 config 에서는 **동작이 지금과 100% 동일**하다(BasePort=13600, MaxCameras=10).
- config 에 키가 없으면 ini 값이 그대로 살아 기존 동작 유지.
- 카메라 11대짜리 파일을 열면 `cam_port_max` 가 13611 로 바뀌고 cam11 이 13611 에서 스트리밍된다.
- 포트 확장은 위쪽으로만 가므로 13510(RPC)/13520(MCP 브리지)과 새로 충돌하지 않는다.

## 7. 검증 계획

1. 유닛테스트
   - `Park3D.AppConfig`: `cam_port_min/max` 파싱, 한쪽만 있으면 미지정, 범위 밖 거부,
     `UpdateCamPortMax` 왕복 + **다른 키 보존** 확인
   - `Park3D.Rpc.CamStream`: `PortRangeToBase` 정상/역전/범위밖, `ExtendedMaxPort` 클램프
2. 실행 검증
   - 기본 config(2대 파일) 기동 → `cam.list` 의 `streamPort` 가 13601/13602 인지
   - 카메라 11대 파일 로딩 → config 의 `cam_port_max` 가 13611 로 갱신되고 cam11 채널이 열리는지
   - 로딩 전후로 config 의 다른 키(rpc_port, preset_file …)가 그대로인지
3. 회귀: config 에서 두 키를 지운 상태로 기동 → 기존 ini 동작(13601~13610) 유지
