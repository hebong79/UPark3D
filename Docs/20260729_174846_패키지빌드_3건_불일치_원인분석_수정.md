      `UCarPlacementWidget`, `UCameraControlWidget`, `UPresetMakerWidget`

## 1. 신고 내용

빌드된 실행파일(`Package/Windows/Park3D.exe`) 기준, 에디터에서는 정상인데 패키지에서만 발생:

1. 처음 시작 시 카메라뷰가 안 보이고, 카메라 컨트롤 UI를 열어야 보인다.
2. 카메라뷰 영역 표시 프레임 사각형의 위치가 많이 벗어난다.
3. 차량배치 UI에서 "열기"로 불러오면 차량이 1개만 나온다.

| 수단 | 용도 |
|------|------|
| 산출물 타임스탬프 비교 | exe/pak/소스의 시점 불일치 확인 |

| **패키지 앱 로그** | 3번의 결정적 증거 |

## 3. 1번 — 시작 시 카메라뷰 안 보임

### 원인: 바이너리/콘텐츠 시점 불일치 (stale 패키지)

| 산출물 | 시각 |
|--------|------|
| `Package/Windows/Park3D/Binaries/Win64/Park3D.exe` | **2026-07-27 00:04** |
| `Package/Windows/Park3D/Content/Paks/*.pak/.ucas/.utoc` | **2026-07-28 17:01** |
| 카메라 뷰어 상시표시 소스(`CameraViewerWidget`·`Park3DGameMode`) | 2026-07-28 ~ 07-29 |

콘텐츠만 재쿠킹되고 **exe는 재빌드되지 않아**, 카메라 뷰어 상시표시 기능이 실행파일에 아예 들어있지 않았다.
그래서 패키지에서는 "컨트롤 패널을 열어야 뷰어가 생기는" 예전 동작이 그대로 나왔다.

### 조치

코드 변경 없음. `-build`를 포함한 전체 `BuildCookRun`으로 재패키징.

> **재발 방지**: 콘텐츠만 재쿠킹하면 C++ 변경이 반영되지 않는다.
> 패키징은 항상 `-build -cook -stage -pak`을 함께 돌려 exe와 pak의 시점을 맞춘다.

## 4. 2번 — 프레임 사각형 위치가 벗어남

### 원인: tick(desktop) 공간 지오메트리를 그리기(window 공간)에 사용

`UCameraViewerWidget::NativePaint`가 외곽 프레임을 그릴 때 이미지의 지오메트리를 이렇게 얻고 있었다.

```cpp
const FGeometry ImgGeo = Img_View->GetCachedGeometry();   // ← tick 공간 = 데스크톱 좌표
FSlateDrawElement::MakeLines(OutDrawElements, Layer + 1, ImgGeo.ToPaintGeometry(), Pts, ...);
```

UMG의 세 지오메트리 접근자는 좌표 공간이 다르다(UE 5.8 `Widget.h`).

| 접근자 | 공간 |
|--------|------|
| `GetCachedGeometry()` | tick 공간 = **데스크톱** 좌표 |
| `GetTickSpaceGeometry()` | 동일(데스크톱) |
| `GetPaintSpaceGeometry()` | paint 공간 = **윈도우** 좌표 |

`FSlateDrawElement` 그리기는 **윈도우 좌표**에서 이뤄지므로, 데스크톱 좌표를 그대로 넘기면
창 위치와 DPI 배율만큼 어긋난다. 에디터 PIE는 두 공간이 거의 일치해 드러나지 않고,
독립 실행/패키지에서만 크게 밀린다.

### 실측 (패키지, 1280×720 창)

| 항목 | 값 |
|------|-----|
| 이미지 좌상단(창 좌표) | 약 (742, 438) |
| 프레임이 그려진 좌상단 | 약 (1025, 595) |
| 어긋남 | 약 **(283, 157)** — 창 밖으로 잘려 우하단 모서리만 보임 |

### 수정

```cpp
// 반드시 paint 공간 지오메트리를 쓴다. GetCachedGeometry()는 tick 공간(=데스크톱 좌표)이라
// 그리기(윈도우 좌표)와 공간이 다르고, 창 위치·DPI 배율만큼 프레임이 어긋난다.
// 에디터 PIE 에서는 두 공간이 거의 일치해 드러나지 않고, 독립 실행/패키지에서만 크게 밀린다.
const FGeometry ImgGeo = Img_View->GetPaintSpaceGeometry();
```

> 같은 파일의 `NativeOnMouseButtonDown`·`NativeOnCursorQuery`는 `GetCachedGeometry()`를 계속 쓴다.
> 이들은 `MouseEvent.GetScreenSpacePosition()`(= 데스크톱 좌표)과 비교하므로 공간이 일치해 올바르다.
> **잘못된 곳은 `NativePaint` 한 곳뿐이다.**

## 5. 3번 — 차량이 1개만 나옴

### 5-1. 결정적 증거 — 패키지 앱 로그

`Package/Windows/Park3D/Saved/Logs/Park3D-backup-2026.07.29-04.36.48.log`

```
[04.32.30] [CarPlacement] 로드 5개 ← ../../../Save/3D/Preset/001_Preset_Seo_1.json (Unity→UE 정규화)
[04.32.30] [CarPlacement] 열기 5대 ← ../../../Save/3D/Preset/001_Preset_Seo_1.json
[04.33.35] [CarPlacement] 로드 1개 ← ../../../Save/3D/Preset/001_Preset_Cam1.json (Unity→UE 정규화)
[04.33.35] [CarPlacement] 열기 1대 ← ../../../Save/3D/Preset/001_Preset_Cam1.json
```

연 파일은 `Save/3D/**Preset**/` 아래의 **주차면 프리셋 파일**이었다. 차량 파일이 아니다.

| 파일 | `datas[0]` 키 | 원소 수 |
|------|---------------|---------|
| `001_Preset_Cam1.json` (프리셋) | idx, faceCount, offsetPos, faceRot, xSize, zSize, dirType, useBaseWidth, camIdx, camPos, camRot, fov | **1** |
| `001_Preset_Seo_1.json` (프리셋) | 위 + presetName, groupRot | 5 |
| `CarPos_7Num.json` (차량) | id, presetId, slotId, prefabId, pos, rotY, isFront | 7 |

### 5-2. 원인 A — 스키마 검증 부재 (직접 원인)

`UCarPlacementLibrary::LoadCarDatasFromJson`은 역직렬화 성공 여부만 확인했다.

```cpp
if (!FJsonObjectConverter::JsonObjectStringToUStruct(Json, &OutData, 0, 0)) { ... return false; }
```

프리셋 파일도 **루트 키가 똑같이 `datas` 배열**이라 `FJsonObjectConverter`는 조용히 **성공**하고,
원소 수만큼 전 필드 기본값짜리 `FCarPos`를 만든다.
→ 프리셋 1개짜리 파일 = "차량 1대 로드 성공" + 원점에 정체불명 차량 1대.
(프리셋 5개짜리 파일은 "차량 5대"로 잡혔다 — 로그가 그대로 보여준다.)

### 5-3. 원인 B — 패키지에서 기본 경로가 존재하지 않음 (유발 원인)

```cpp
// 수정 전
return FPaths::Combine(FPaths::ProjectDir(), TEXT("Save"), TEXT("3D"), TEXT("CarPos"), TEXT("CarPos_SNum.json"));
```

| 실행 형태 | `ProjectDir()` | `ProjectDir()/Save` 존재 | 실제 데이터 위치 |
|-----------|----------------|--------------------------|------------------|
| 에디터 | `Park3D/` | **있음** | `Park3D/Save/3D/...` |
| 패키지 | `<Stage>/Park3D/` | **없음** | `<Stage>/Save/3D/...` (스테이지 루트) |

패키지에서는 `Save/`가 `ProjectDir()` **바깥**(한 단계 위)에 스테이징된다.
그래서 열기 대화상자의 시작 폴더가 **존재하지 않는 경로**가 되고, 사용자가 직접 탐색하다
`Save/3D/Preset/`에서 프리셋 파일을 고르게 됐다. 에디터는 경로가 실제로 있어 정상 동작했다.
→ **"에디터는 되는데 패키지만 다름"의 정체.**

### 5-4. 수정

**A. 스키마 판별** (`CarPlacementLibrary.cpp`) — 역직렬화 **전에** 종류를 확인한다.

```cpp
static const TCHAR* CarOnlyKeys[] = { TEXT("prefabId"), TEXT("prefabName"), TEXT("rotY"), TEXT("isFront") };
// datas[0] 이 위 키를 하나도 갖지 않으면 차량 파일이 아니다(프리셋 원소에는 없다).
```

```cpp
FString Reason;
if (!LooksLikeCarDatas(Json, Reason))
{
    UE_LOG(LogTemp, Warning, TEXT("[CarPlacement] 차량 배치 파일이 아님(%s): %s"), *Reason, *FilePath);
    return false;
}
```

빈 `datas`(전체 삭제 저장본)는 유효로 통과시킨다.

**B. 데이터 경로 해석** (신규 `Park3DDataPaths.h`) — 실행 형태와 무관하게 `Save/` 실제 위치를 찾는다.

```cpp
inline FString GetSaveRootDir()
{
    // 1) ProjectDir()/Save (에디터·정상 스테이징)
    // 2) 없으면 ProjectDir()/../Save (패키지 스테이지 루트)
    // 둘 다 없으면 1)을 반환해 기존 쓰기 동작 유지
}
inline FString GetDataFilePath(const TCHAR* SubDir, const TCHAR* FileName);
```

적용 지점 3곳(같은 결함을 공유하고 있었다):

| 파일 | 변경 |
|------|------|
| `CarPlacementWidget::GetDefaultCarFilePath` | `Park3DDataPaths::GetDataFilePath(TEXT("CarPos"), TEXT("CarPos_SNum.json"))` |
| `CameraControlWidget::GetDefaultCameraFilePath` | `... (TEXT("CameraPos"), TEXT("CamPos_SNum.json"))` |
| `PresetMakerWidget::GetDefaultPresetFilePath` | `... (TEXT("Preset"), TEXT("preset.json"))` |

## 8. 영향도 분석

### 8-1. 회귀 위험

| 대상 | 분석 |
|------|------|
| `LoadCarDatasFromJson` 호출부 | 위젯 `LoadFromJsonFile`, `RebuildFromFile`, RPC `car.load` 3곳. 정상 차량 파일은 그대로 통과(테스트 2·기존 `JsonRoundTrip`·`UnitySample` 통과) |
| 기존 차량 파일 호환 | 참조 데이터 `CarPos_*.json`은 모두 `prefabId`/`pos`/`rotY`/`isFront`를 가진다. 재패키징 후 `CarPos_7Num.json` 7대 로드 확인 |
| `GetDefaultCarFilePath` 등 3곳 | 에디터에서는 `ProjectDir()/Save`가 존재하므로 1)번 분기 → **경로 값 동일**(동작 불변) |
| `NativePaint` 변경 | 프레임 그리기 전용. 입력/커서 경로는 그대로 `GetCachedGeometry()` 사용 |
| 자동화 테스트 | 47/47 통과 |

### 8-2. 동작 변화 (의도됨)

1. **차량 열기에서 다른 종류의 JSON을 고르면 실패한다.** 이전에는 "성공"으로 보고되고 정체불명 차량이 생겼다.
   실패 사유는 로그(`[CarPlacement] 차량 배치 파일이 아님(...)`)로 남는다.
2. 패키지에서 저장/열기 기본 폴더가 **실제 데이터 위치**(`<Stage>/Save/3D/...`)를 가리킨다.
   이전에는 존재하지 않는 경로였다.

### 8-3. 범위 밖 관찰 (미수정)

- **차량 배치 패널이 1280×720 창에서 좌측 화면 밖으로 벗어난다**(`_workspace/pkgfix_carpanel2.png`
  좌측 가장자리에 패널 조각만 보임). 이번 신고 대상이 아니고 사용자 환경(더 큰 창)에서는
  재현되지 않을 수 있어 손대지 않았다. 별도 확인이 필요하다.
- 프리셋/카메라 파일 열기에도 같은 종류의 스키마 검증이 없다. 차량과 동일한 혼동이 가능하다.
  이번에는 신고된 차량 경로만 막았다.
