## 2. 구현 중 실제로 걸린 함정 3건 (기록)

| # | 증상 | 원인 | 조치 |
|---|------|------|------|
| 1 | `ManagerApply` 테스트가 값이 전부 기본값이라며 실패 | 테스트가 라이트를 **따로 스폰**했는데, 매니저는 "월드의 첫 DirectionalLight"를 찾는다. 에디터 월드에는 이미 `EditorStartupMap=PresetMaker1` 의 라이트가 로드돼 있어 그쪽이 대상이 됐고, 스폰한 사본은 손대지 않은 채 남았다 | 테스트를 월드의 실제 조명 대상으로 바꾸고, 원래 값을 스냅샷 → 검증 → **복원**하도록 재작성 |
| 2 | 방위 200 을 넣었는데 액터가 −160 을 돌려줌 | `FRotator` 가 yaw 를 [−180,180] 으로 정규화. 같은 방향이다 | 단언을 0~360 환산 비교로 수정. `CaptureCurrent` 왕복은 `ClampSettings` 의 래핑 덕에 이미 정상이었다 |
| 3 | 메뉴에 넣은 "조명 설정" 버튼이 Exit **아래**에 붙음 | `ShiftChild` 는 UMG 슬롯 배열만 바꾸고 **이미 만들어진 Slate 트리는 재배치하지 않는다**. `NativeConstruct` 는 Slate 빌드 이후 시점 | 버튼 삽입을 `NativeOnInitialized`(Slate 빌드 전)로 이동 → 순서 정상 |

추가로 `Btn_Exit` 가 `VBox_Menu` 의 직계 자식이 아니어서 `GetChildIndex` 가 INDEX_NONE 을 반환했다 → 부모를 거슬러 올라가 직계 자식을 찾도록 보완.

## 4. 미해결 트레이드오프 (은폐 없이 명시)

**하나의 노출값으로 원경과 근경을 동시에 맞출 수 없다.**

원인은 `ExponentialHeightFog` 밀도 **0.0436**(UE 기본 0.02의 2배 이상) + `SkyAtmosphere.height_fog_contribution=1.0` 의 원거리 인스캐터다. 원경 지면이 근경보다 훨씬 밝게 떠서, 노출로 원경을 맞추면 근경(CCTV 카메라 뷰)이 어두워진다.

- EV 0 에서 메인 뷰포트가 192 로 측정된 것은 **톤매퍼 상단에서 포화**된 상태였기 때문이며, 카메라 경로는 EV 에 정확히 선형으로 반응한다(110 → 38.8 = 1.5스톱).
- 채택한 EV 2.5 에서 **카메라 뷰 지면 뭉갬이 5.8% → 70.5%** 로 악화된다. 차량 식별은 여전히 가능하나 노면은 어둡다.

근본 해결은 안개 밀도를 낮추는 것이지만, 사용자가 선택한 6항목에 안개가 없어 이번 범위 밖이다. **7번째 항목(안개 농도) 추가는 소규모 변경**이며, 최종 보고에서 제안한다.

## 5. 미검증 항목

| 항목 | 사유 |
|------|------|
| 저장/열기 **네이티브 파일 대화상자** 실제 조작 | 대화상자가 뜨는 것까지는 코드 경로가 기존 패널(카메라/차량/프리셋)과 동일하나, 대화상자 안에서 파일명을 입력·선택하는 실조작은 수행하지 않았다. 저장·로드 로직 자체는 T5·T6 로 검증됨 |
| 슬라이더 드래그 조작 | Slate 슬라이더는 클릭만으로 값이 바뀌지 않고 드래그가 필요해 자동 조작으로 검증하지 못했다. 값 반영 경로는 수치입력 + 적용 및 T7 로 검증됨 |
| 패널 드래그 이동 | 기존 패널과 동일한 코드(선례 복사) |
