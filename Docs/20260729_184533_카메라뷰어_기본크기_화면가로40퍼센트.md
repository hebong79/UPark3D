# 카메라 뷰어 기본 표시 크기를 화면 가로의 40%로 설정

작성일: 2026-07-29 18:45:33
대상: `UCameraViewerWidget`

---

## 1. 요구사항

카메라 뷰 크기를 **화면 가로의 약 40%**로 설정한다. 최초 로딩 시의 기본값이다.

기존 기본값은 고정 `480×270`이었고, 화면 크기와 무관했다.

---

## 2. 설계

- 저장/복원 동작(`ViewerSize.json`)은 **그대로 둔다**. 사용자가 리사이즈한 값이 있으면 그것이 우선이고,
  저장값이 없을 때의 기본값만 바꾼다.
- 비율은 `DefaultViewWidthRatio`(기본 0.4)로 노출해 조정 가능하게 한다.
- 높이는 기존 규약대로 16:9로 파생, `MinViewWidth`/`MaxViewWidth`로 클램프.

### 핵심 난점 — 슬롯 폭과 화면 폭의 변환 계수를 알 수 없다

`ApplyViewSize()`는 캔버스 슬롯 크기를 **로컬(슬레이트) 단위**로 지정하는데,
요구사항은 **화면 픽셀 비율**이다. 그 사이 변환 계수를 계산으로 구하려는 시도가 두 번 다 빗나갔다.

| 시도 | 계산 | 실제 화면 비율 |
|------|------|----------------|
| 1. `GetViewportSize`(픽셀) ÷ `GetViewportScale` | 40% 의도 | **26%** (실측 317px / 1280) |
| 2. 루트 위젯 로컬 폭 × 0.4 | 40% 의도 | **49%** (실측 629px / 1280) |

원인: 루트 위젯과 캔버스 슬롯 사이에 추가 스케일이 있어 두 값 모두 계수가 아니었다.
(참고 실측: 저장값 로컬폭 807.33 → 화면 535px, 계수 0.663. `GetViewportScale`이 주는 값과 다르다.)

### 채택안 — 가정 대신 실측하고 보정

렌더 폭은 슬롯 폭에 **선형**이다. 따라서 현재 화면 비율을 실제로 재고, 목표 비율과의 비를 곱하면 된다.

```
새 폭 = 현재 폭 × (목표 비율 / 현재 화면 비율)
현재 화면 비율 = Img_View 절대폭 / 루트 절대폭   (둘 다 tick 공간 → 계수 동일)
```

| 대안 | 채택 | 사유 |
|------|------|------|
| **실측 후 보정** | ✅ | 변환 계수를 몰라도 정확하다. WBP 레이아웃이 바뀌어도 유효 |
| 계수를 상수로 하드코딩(예: ratio 0.3256) | ❌ | 이 창 크기에서만 맞는 매직넘버. 해상도가 바뀌면 깨진다 |
| WBP 루트 캔버스 구조 수정 | ❌ | 요청 범위 밖. 다른 위젯 레이아웃에 파급 |

### 1회 보정이 아니라 수렴 반복인 이유

첫 틱의 지오메트리는 아직 정착 전이라 화면비가 잘못 측정된다.
실측 로그: 폭 480에서 화면비를 **0.167**로 읽었지만 실제는 약 0.205였고,
그 값으로 1회 보정했더니 최종 49%가 나왔다.

→ 목표 비율에 **수렴할 때까지 매 틱 재보정**한다(오차 0.005 이내면 확정, 상한 30틱).
실제로는 **2회**만에 확정된다. 사용자가 뷰어를 잡아끌기 시작하면 즉시 보정을 중단한다.

## 3. 구현

### 3-1. `CameraViewerWidget.h`

```cpp
/** 최초 실행(저장값 없음) 시 기본 표시 폭 = 화면 가로의 이 비율. 높이는 16:9로 파생. */
UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Viewer")
float DefaultViewWidthRatio = 0.4f;

/** 화면 대비 목표 비율이 되도록 현재 표시 폭을 보정한다(순수함수, 테스트 대상). */
static float ComputeCorrectedViewWidth(float CurrentWidth, float CurrentRenderedRatio,
    float TargetRatio, float MinWidth, float MaxWidth);

bool  bPendingDefaultSize = false;   // 저장값 없어 기본 크기 확정 전
int32 DefaultSizeAttempts = 0;       // 무한 보정 방지 상한
static constexpr float DefaultSizeTolerance   = 0.005f;
static constexpr int32 DefaultSizeMaxAttempts = 30;
```

`DefaultViewSize`(480×270)는 보정 시작값 겸 최종 폴백으로 남긴다.

### 3-2. `NativeConstruct` — 저장값이 없으면 보정 예약

```cpp
else
{
    // NativeConstruct 시점에는 루트 지오메트리가 아직 0이므로 첫 틱으로 미룬다.
    CurrentViewSize = DefaultViewSize;
    bPendingDefaultSize = true;
}
```

### 3-3. `NativeTick` — 수렴할 때까지 보정

```cpp
if (bPendingDefaultSize && (bMovingViewer || bResizingViewer))
{
    bPendingDefaultSize = false;   // 사용자가 잡아끌면 즉시 손을 뗀다
}
if (bPendingDefaultSize && Img_View)
{
    const float ImgW  = Img_View->GetCachedGeometry().GetAbsoluteSize().X;
    const float RootW = MyGeometry.GetAbsoluteSize().X;
    if (ImgW > 0.f && RootW > 0.f)
    {
        const float Ratio = ImgW / RootW;
        if (FMath::IsNearlyEqual(Ratio, DefaultViewWidthRatio, DefaultSizeTolerance)
            || ++DefaultSizeAttempts > DefaultSizeMaxAttempts)
        {
            bPendingDefaultSize = false;
            UE_LOG(...);   // 확정 로그
        }
        else
        {
            const float W = ComputeCorrectedViewWidth(
                CurrentViewSize.X, Ratio, DefaultViewWidthRatio, MinViewWidth, MaxViewWidth);
            CurrentViewSize = FVector2D(W, W * 9.f / 16.f);
            ApplyViewSize();
        }
    }
}
```

### 3-4. 순수함수

```cpp
float UCameraViewerWidget::ComputeCorrectedViewWidth(float CurrentWidth, float CurrentRenderedRatio,
    float TargetRatio, float MinWidth, float MaxWidth)
{
    if (CurrentWidth <= 0.f || CurrentRenderedRatio <= 0.f || TargetRatio <= 0.f)
    {
        return CurrentWidth;   // 아직 측정 불가 → 다음 틱 재시도
    }
    return FMath::Clamp(CurrentWidth * (TargetRatio / CurrentRenderedRatio), MinWidth, MaxWidth);
}
```

## 6. 영향도 분석

| 대상 | 분석 |
|------|------|
| 저장/복원(`ViewerSize.json`) | 변경 없음. **저장값이 있으면 그대로 우선** 적용되고 보정 자체가 실행되지 않는다 |
| 리사이즈/이동 | 변경 없음. 드래그 시작이 감지되면 보정 플래그를 즉시 해제해 사용자 조작과 충돌하지 않는다 |
| 리사이즈 저장 | 변경 없음. 보정 결과는 저장하지 않으므로 다음 실행에서 창 크기에 맞춰 다시 계산된다 |
| `RenderTargetVisibility`/`SizeRoundTrip` 테스트 | 통과 |
| 전체 자동화 | 48/48 통과 |

### 부수 효과 (의도됨)

- 기존에 저장된 `ViewerSize.json`이 있으면 새 기본값이 보이지 않는다.
  **확인을 위해 프로젝트/패키지의 `Saved/CameraViewer/ViewerSize.json` 2개를 삭제했다**
  (각각 폭 814.21 / 807.33). 이전 크기가 필요하면 한 번 리사이즈하면 다시 저장된다.
- 창 크기를 바꿔 재실행하면(저장값이 없는 한) 그 창 기준 40%로 다시 잡힌다.

### 범위 밖 관찰 (미수정)

- 실행 중 창 크기를 바꿀 때는 재보정하지 않는다. 요구사항이 "처음 로딩시 디폴트값"이라 최초 1회만 수렴시킨다.
- 패키징 중 ZenServer(`[::1]:8558`) 연결 거부로 `BUILD FAILED`가 1회 발생했다(쿠킹은 0 에러, 스테이징에서 실패).
  재실행으로 정상 완료. ZenServer가 죽어 있으면 재실행이 필요하다.
