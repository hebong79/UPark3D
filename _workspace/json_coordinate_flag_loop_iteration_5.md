# Goal/Loop 5 — 차량 전면주차 시각 방향 보정

## 사용자 확인

Loop 4 PIE에서 차량 위치와 주차선 장축 정렬은 정상이다. 다만 Unity에서 전면주차였던 차량이 UE에서 모두 후면으로 보인다. 사용자는 차량을 180° 더 돌리도록 명시했다.

## 설계/수정

좌표 `(z,x,y)`, `rotY` same-sign 변환, JSON flag, 자동배치는 그대로 둔다. 시각 메시 경계인 `MeshForwardYawOffset`만 `+90°`에서 `+270°(=-90°)`로 바꿨다.

`isFront=false`의 추가 `+180°`는 유지한다. Automation은 동일 `rotY`의 front/back 쌍에 대해 액터 yaw 정규화 차=180°와 메시 local `-Y` 월드 방향의 정확한 반대를 검사한다. 따라서 전면 시각 보정이 바뀌어도 전후면 관계는 깨지지 않는다.

## 영향/검증 게이트

legacy Unity 및 `isUnreal:true` JSON 변환 경로와 자동배치 코드는 수정하지 않았다. C++ 기본값 변경이므로 수동 컴파일 뒤 기존 JSON/자동배치/차량 방향/카메라 Automation 및 PIE를 다시 실행해야 한다.

## 반복 기록

시각 축 보정은 Loop 3(프리셋), Loop 4(차량 90°), Loop 5(차량 전후면)로 세 번 발생했다. 그러나 원인은 각각 별도 코드 경계이므로 동일 원인 3회 연속 실패 중단 규칙에는 해당하지 않는다.
