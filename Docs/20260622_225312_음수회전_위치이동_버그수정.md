# 버그 수정 — 음수 회전 각도에서 주차면 위치가 이동하는 문제

- 작성일: 2026-06-22 22:53:12
- 작업 유형: 버그 수정(3D 배치/회전 로직). C++ 재빌드 필요.
- 대상: `Park3D/Source/Park3D/ParkingPresetManager.cpp` `DrawPreset()`
- 분석 노트: `.claude/skills/parking-dev-orchestrator/_workspace/negrot_shift_architect_analysis.md`

## 1. 증상
FaceRotate(면 회전)가 **음수**가 되면 주차면 그룹이 제자리에서 회전하지 않고 **반대편으로 평행이동**한다. (양수에서는 정상)

## 2. 근본 원인
`DrawPreset`의 면 누적 배치량 `Disp = Step * j * Sign`에서 `Sign` 계산이 0~360 정규화 각도 기반:
```cpp
float Norm = FMath::Fmod(FaceRot, 360.f);
if (Norm < 0.f) Norm += 360.f;          // 예) -30° → 330°
const float Sign = (Norm > 180.f) ? -1.f : 1.f;   // 330 > 180 → Sign = -1
```
- 음수 각도는 `360 - θ`로 정규화되어 항상 `>180` → `Sign = -1` → 면 배치 방향이 +축에서 −축으로 반전.
- `Step`은 `Xs / |cos θ|`로 부호 대칭이라 간격은 같고 **방향만** 뒤집혀, 그룹 전체가 Origin 반대편으로 이동.
- Default·Dir 모드 모두 `Disp`에 `Sign`이 곱해져 동일 영향.

### 수치 검증 (Xs=2.5m, FaceCount=4, Origin=0)
| 각도 | 면 X 위치 | 비고 |
|------|-----------|------|
| +30° | 0, 289, 577, 866 | 정상 |
| −30° (수정 전) | 0, −289, −577, −866 | **반대편 이동(버그)** |
| −30° (수정 후) | 0, 289, 577, 866 | 제자리·대칭(틸트만 반대) |

## 3. 수정 (최소·외과적)
면 배치 진행 방향은 회전 부호와 무관해야 한다(회전은 제자리). `Sign` 반전 제거:
```cpp
// 제거: Norm/Sign 계산
const float Disp = Step * j;   // 이전: Step * j * Sign
```
- 양수(<180) 케이스는 원래 `Sign=+1` → **영향 없음(회귀 없음)**.
- 음수/>180 케이스만 +방향으로 교정 → 양수와 대칭 제자리 회전.
- 사용되지 않게 된 `Norm`/`Sign` 변수 제거(CLAUDE.md 3번). `FaceRot`은 CosF·면회전·Dir 분기에서 계속 사용.

## 4. 영향도
- `ParkingPresetManager::DrawPreset` 시각화 로직만 변경. **저장 데이터/JSON 스키마 불변**.
- GroupFaceRotate·BoxSize·Offset 등 다른 파라미터 처리 불변.
- 위젯/카메라/입력 무관.

## 5. 검증 상태 (정직 보고 — 미완료)
1. **재빌드 미수행**: 에디터 실행 중 + 선행 단계 변경으로 전체 재빌드 필요. 현재 미컴파일.
   - (본 변경 자체는 함수 본문만이라 선행 변경 빌드 후엔 Live Coding 가능하나, 현재는 함께 재빌드 권장)
2. **자동 유닛테스트**: DrawPreset은 디버그 라인 렌더라 순수 유닛테스트 부적합 → 수동 검증.
3. **수동 검증(재빌드 후)**:
   - 프리셋 회전을 +값/−값 동일 크기로 줬을 때 그룹 위치가 같은지(틸트만 반대) 확인.
   - 0°에서 변화 없음.
   - 첨부 스크린샷처럼 음수에서 그룹이 옆으로 튀지 않는지 확인.

## 6. 비고
- 회전 |각도|가 180°를 넘는 비정상 입력에서는 더 이상 방향 반전이 일어나지 않음(제자리 회전 일관). 기존 Unity의 eulerAngles>180 반전 모사를 의도적으로 제거함.
