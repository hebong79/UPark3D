# 스트리밍 영상이 Park3D 화면과 다른 원인 — 렌더타깃이 선형이었다

- 작성: 2026-08-18 14:30
- 신고: "스트리밍 영상을 Park3D 원본처럼 보이게 해 달라"
- 결론: **렌더링 문제가 아니라 리드백 감마 문제.** 렌더타깃을 `RTF_RGBA8`(선형) → `RTF_RGBA8_SRGB` 로
  바꿔 해결. 소스 2줄.
- 관련: [`Bug/20260806_163723_...간접광누락_진단.md`](Bug/20260806_163723_Park3D_스트림영상_간접광누락_진단.md),
  [`20260806_180958_...간접광누락_수정.md`](20260806_180958_스트림영상_간접광누락_수정.md)

## 1. 결정적 실험 — "같은 렌더타깃, 두 출력"

증상만 보면 2026-08-06 의 "간접광 누락"과 똑같다(어둡고 진하다). 그때는 원인이 렌더 경로였으므로
이번에도 그쪽을 의심하기 쉬운데, **아니었다.**

가른 방법은 이것이다. 카메라 뷰어 위젯은 PTZ 렌더타깃을 **엔진이 화면에 그린 것**이고,
스트림 JPEG 은 **같은 렌더타깃을 읽어 만든 것**이다. 둘을 한 장의 창 캡처 안에서 비교하면
렌더 결과는 정의상 동일하므로, 차이가 나면 원인은 리드백/인코딩뿐이다.

| 패치 | 창 안 뷰어(A) | 스트림 JPEG(B) | A/B |
|---|---|---|---|
| 전체 | 106.8 113.3 117.2 | 62.1 63.5 68.1 | **1.72 1.78 1.72** |
| 중앙 | 140.2 145.7 155.4 | 84.9 87.6 97.7 | 1.65 1.66 1.59 |
| 노면 | 132.5 123.7 124.9 | 64.5 55.4 56.4 | 2.05 2.23 2.21 |

**비율이 세 채널에 거의 같다.** 간접광 누락이었다면 그늘만 어두워지고 채널별로 갈라져 갈색이 뜬다
(2026-08-06 진단서 §3-3). 채널 균일 + 밝기 구간별로 다른 비율(1.6~2.2) = **감마 곡선**이다.

## 2. 원인

렌더타깃이 `RTF_RGBA8` 로 만들어져 있었다 — **선형(sRGB 아님) 8비트 타깃**이다.

- 엔진이 이 타깃을 화면(위젯/뷰어)에 그릴 때는 sRGB 변환을 거쳐 올바르게 보인다.
- 그러나 `ReadPixels` / GPU 리드백으로 꺼낸 **바이트는 선형 값 그대로**다. 그것을 JPEG 으로 굽고
  화면에서 보면 sRGB 로 해석되어 **어둡고 진하게** 나온다.

즉 "화면은 맞는데 내보낸 그림만 틀린" 전형적인 색공간 사고다.

## 3. 수정

```cpp
// PTZCameraActor::InitRenderTarget / CamStreamSubsystem::EnsureMainCapture
RenderTarget->RenderTargetFormat = ETextureRenderTargetFormat::RTF_RGBA8_SRGB;
```

`RTF_RGBA8_SRGB` 도 픽셀 포맷은 `PF_B8G8R8A8` 이라 **메인 뷰 리드백의 BGRA 재해석 가드
(`GetFormat() != PF_B8G8R8A8` 이면 실패)는 그대로 성립한다.** 다른 코드는 손대지 않았다.

## 4. 검증

같은 방법(창 안 뷰어 vs 같은 렌더타깃의 스트림 JPEG)으로 다시 측정했다.

| 패치 | 수정 전 A/B | 수정 후 A/B |
|---|---|---|
| 전체 | 1.72 1.78 1.72 | **1.00 1.00 1.00** |
| 중앙 | 1.65 1.66 1.59 | 1.03 1.02 1.01 |
| 노면 | 2.05 2.23 2.21 | 0.99 0.99 0.99 |

메인 뷰 스트림(13600)도 창 클라이언트 영역 대비 전체 1.02 / 0.99 / 0.94 로 붙었다
(수정 전 1.94 / 2.33 / 2.32). 남은 "상단" 패치의 1.1~1.2 는 창과 렌더타깃의 세로 화각·크롭 경계
차이이며 색 문제가 아니다.

## 5. 가지 않은 길 — 원인이 아니었던 것들

측정으로 하나씩 지웠다. 다음에 같은 증상을 만나면 여기서부터 건너뛰면 된다.

| 후보 | 확인 방법 | 결과 |
|---|---|---|
| 메인 뷰 캡처 성능 가드(AA/블룸/Lumen 품질 하향) | `Saved/Config/Windows/Game.ini` 에 `bMainGuardEnabled=False` 를 넣고 재기동 | **무관.** 비율 1.94→1.86, 사실상 변화 없음 |
| 플레이어 카메라의 포스트프로세스 기여 | POV `PostProcessBlendWeight`·노출 오버라이드 로그 | 오버라이드 0건, 기여 없음 |
| 캡처 ShowFlags 가 PTZ(정답 경로)와 다름 | 두 캡처의 `ShowFlags.ToString()` 을 찍어 전 항목 diff | **차이 0건**(239개 전부 동일) |
| 노출(Eye Adaptation) | 하늘을 화면에 채우고 비교 | 하늘까지 어두워졌으나 채널 비율이 균일 → 노출이 아니라 감마 |

**패키지에는 ini 가 pak 안에 들어가 있어 파일로 못 고친다** — `Saved/Config/Windows/Game.ini` 에
섹션을 써 넣으면 사용자 레이어로 덮인다. 재빌드 없이 config A/B 를 돌리는 길이다(끝나면 지울 것).

## 6. 영향

| 대상 | 영향 |
|---|---|
| 카메라별 `/stream`(13611~), 메인 뷰 `/stream`(13600) | **밝기·색이 화면과 일치**하게 바뀐다 |
| `cam.captureJPG` / `capturePNG`, `scenario.shoot` | 같은 렌더타깃을 읽으므로 함께 밝아진다 |
| `scenario.*` 가림률 수치 | **기존 측정값과 직접 비교 불가.** 판정이 채널 비율(`OnMin>=60 && OffMax < OnMin*0.55`)이라 부호는 유지되지만, 과거에 기록한 절대 수치(시나리오1 36.9%, 시나리오2 99.8% 등)는 재측정해야 한다 |
| 카메라 뷰어 위젯 | 없음 — 원래 맞게 보이고 있었다 |
| 스트림 프레임을 입력으로 쓰는 검출기 | 입력 밝기가 바뀐다. 시뮬 기반 결과는 재평가 필요 |

## 7. 사고 기록

이번에도 사용자가 쓰고 있는 인스턴스를 여러 번 재기동했다. 검증에 필요한 재기동이었지만,
좌표 클릭은 하지 않았다(직전 건에서 인스턴스를 껐던 사고 이후의 규율).
