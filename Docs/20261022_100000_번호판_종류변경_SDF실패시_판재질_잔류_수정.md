# 번호판 종류 변경 시 SDF 합성이 실패하면 판 재질이 직전 종류로 남던 결함 수정

- 날짜: 2026-10-22
- 브랜치: `fix/plate-kind-material-on-sdf-fail`
- 관련: 보드 #1718 작업 중 덤으로 발견(2026-10-21 CLAUDE.md 변경 이력 "CarActor.cpp:330 추정")

## 1. 증상

2026-10-21 정본에서 차량 `5-16.25.43` 은 기록상 `commercial` 인데 화면은 흰 판이었다.
`car.setPlate` 로 종류를 바꾸면 `applied:false` 가 나오고 글자가 겹쳤다.

## 2. 원인(정본 로그 `Park3D-backup-2026.10.21-12.46.20.log`)

```
[PlateSDF] 아틀라스에 없는 글자 '자' — 종류 합성을 건너뛴다(kind=commercial 경남57자1087)
[CarPlate] SDF id=5-16.25.43 number=457가1087 판=52.00x11.00cm rt=없음 front=0 back=0 폴백위젯=1/1
```

1. `commercial` 은 용도 글자로 '자' 를 쓰는데 글리프 아틀라스(65자)에 '자' 가 없어 SDF 합성이 실패한다.
2. `ApplyPlateNumberSdf` 의 `Bind` 는 `PlateNumberSdf == nullptr` 이면 **재질을 갈기 전에** 돌아갔다.
   - 스폰 때: 슬롯에 메시 기본 `M_PlateFront`(흰 판)가 남았다 → "기록 commercial·화면 흰 판".
   - 종류 변경 때: `SetPlate` 는 `FrontPlateMid/BackPlateMid` 포인터만 비우고, 슬롯에는 **직전 종류의 MID(옛 번호 SDF 가 물린 채)** 가 그대로 남았다. 폴백 위젯도 켜져 새 번호를 그리니 옛 번호와 겹쳤다.
3. 처음 추정한 `CarActor.cpp:330`(`SetPlate` 의 분기)은 정상이었다 — 종류 변경 시 다시 정렬하는 길은 탔고, 막힌 곳은 그 안의 `Bind` 였다.

## 3. 수정

`Park3D/Source/Park3D/CarActor.cpp` `ApplyPlateNumberSdf` 의 `Bind`:

- 판 앞면 슬롯(`NumberSDF` 파라미터를 가진 슬롯)의 재질을 **SDF 성공 여부와 무관하게** 이번 종류의 것으로 맞춘다.
  종류별 판이 아니면(`KindMaterial == nullptr`) `SetMaterial(Slot, nullptr)` 로 오버라이드를 풀어 메시 기본 `M_PlateFront` 로 돌린다.
- MID 는 SDF 가 있을 때만 만든다. SDF 가 없으면 MID 없이 재질만 바뀐다.
  두 베이스 재질(`M_PlateFront`, `M_PlateKind`)의 `NumberSDF` 기본값은 검정 텍스처라(`Tools/plate_sdf/build_material.py`, `Tools/plate_kinds/build_plate_assets.py`) 판에는 글자가 안 그려지고 번호는 폴백 위젯만 보인다 → 겹침 없음.

## 4. 테스트

`Park3D/Source/Park3D/Tests/CarActorTest.cpp` 에 `Park3D.CarPlacement.PlateKindSwap` 신설.
K5 메시 차량(id `5-16.25.43`)의 번호 `457가1087` 을 `normal_paint8 → commercial → ev → commercial → normal_film` 순으로 바꾸며 매번:

- 앞·뒤 판 슬롯 1 의 재질(MID 면 부모) == `MI_Plate_<kind>`
- MID 유무 == SDF 유무
- 앞 폴백 위젯 표시 == SDF 실패

아틀라스에 따라 실패 여부가 달라도 성립하는 불변식만 본다.

## 6. 남은 것

- 아틀라스에 '자' 가 없어 `commercial`(그리고 같은 로그에서 `old_business` 도) 번호는 여전히 판 텍스처로 못 그리고 폴백 위젯으로 나온다. 고치려면 `Tools/plate_sdf/bake_glyph_sdf.py` 로 글리프를 추가해 아틀라스를 다시 구워야 한다(별건).
- SDF 실패 상태에서 번호만 바꾸면(`RefreshPlateNumberSdf`) MID 가 없어 새 SDF 가 성공해도 판에 물리지 않는다. 실패 원인이 용도 글자라 번호만 바꿔서는 성공하지 않으므로 이번 범위에서 손대지 않았다.
