# 레벨이 출력되지 않던 문제 — `preset.save` 가 만든 빈 `Save/` 폴더가 데이터 루트를 가로챔

- 날짜: 2026-09-16
- 신고: 정본(13510) 화면에 주차장 레벨이 안 나오고 빈 하늘·노면만 보인다(Preset Maker 패널은 정상).
- 변경 파일: `Park3D/Source/Park3D/Rpc/Modules/PresetRpcModule.cpp`
- 배포: `Package/Windows/Park3D/Binaries/Win64/Park3D.exe` 교체(09-16 10:44 빌드), 잘못 생긴 `Package/Windows/Park3D/Save/` 폴더 제거

## 1. 증상과 로그

기동 로그(`Package/Windows/Park3D/Saved/Logs/Park3D.log`, 09-16 09:58 기동분):

```
LogLoad: LoadMap: /Game/Maps/PresetMaker1?Name=Player
[LevelSelect] config 에 levels 가 없어 주차장 선택 패널을 띄우지 않습니다.
[Config] 시작 설정 파일 없음/읽기 실패 — 자동 로딩 건너뜀: ../../../Park3D/Save/Config/config_pmaker.json
[ParkingManager] 주차면 번호 0개 표시(프리셋 0, 레벨 0, 풀 0)
[Light] 레벨에 태양이 없어 DirectionalLight 를 생성했습니다.   ← 빈 부팅맵의 징후
```

`config_pmaker.json` 을 못 읽어 `TravelToConfigLevel()` 이 이동하지 않고 **빈 부팅맵 `PresetMaker1`** 에 머문 것이다.
config 자체는 `Package/Windows/Save/Config/config_pmaker.json` 에 멀쩡히 있었다(`level: "Levels/LV_Park_01"`).

## 2. 원인

`Park3DDataPaths::GetSaveRootDir()` 의 규칙:

1. `ProjectDir()/Save` 폴더가 **존재하면** 그것(에디터용)
2. 없으면 `ProjectDir()/../Save` (패키지 스테이지 루트 — 실제 데이터가 있는 곳)

패키지에서 `ProjectDir()` 은 `Package/Windows/Park3D/` 이고 원래 `Park3D/Save` 는 없다. 그런데
**`Package/Windows/Park3D/Save/3D/Preset/preset.json`(38바이트, `{"isUnreal":true,"datas":[]}`)** 이
09-15 18:50:32 에 생겨 있었다. 폴더가 존재하게 된 순간부터 규칙 1 이 이기고, 다음 기동(09-16 09:58)부터
config·카메라·차량·프리셋 파일을 전부 그 빈 폴더에서 찾아 아무것도 못 읽었다.

누가 만들었나 — 로그에 09-08 부터 RPC 호출이 한 줄씩 남아 있어 바로 특정됐다:

```
[2026.09.15-09.50.32:731][111]LogTemp: [RPC] 192.168.0.221 preset.save {}
```

(UTC 09:50:32 = KST 18:50:32, 파일 시각과 일치.) `preset.save` 의 기본 경로가
`PresetRpcModule.cpp:23` 에서 **`FPaths::ProjectDir()/Save/3D/Preset`** 을 직접 조합하고 있었다 —
다른 모든 저장/로드(패널·cam.*·car.*·light·scenario)는 `Park3DDataPaths::GetDataFilePath` 를 쓰는데 이 한 곳만 예외였다.
에디터에서는 두 경로가 같아 드러나지 않고, 패키지에서 외부 클라이언트가 파라미터 없이 한 번 호출하면
"다음 기동부터 레벨이 안 뜨는" 지연 폭탄이 된다.

09-08 항목("config 는 정상인데 프리셋 면이 그려진다")과 같은 발신지 패턴(외부 `preset.*` 호출)이다.

## 3. 수정

`ResolvePresetPath()` 의 기본 경로를 `Park3DDataPaths::GetDataFilePath(TEXT("Preset"), *FileName)` 으로 —
패널(`PresetMakerWidget.cpp:955`)이 쓰는 것과 같은 함수. `fullPath`·`path` 를 준 경우의 동작은 그대로.

```cpp
if (Dir.IsEmpty())
{
    return Park3DDataPaths::GetDataFilePath(TEXT("Preset"), *FileName);
}
return FPaths::Combine(Dir, FileName);
```

같은 패턴(`ProjectDir(), TEXT("Save")`)이 다른 곳에 없는지 grep — `Park3DDataPaths.h` 자체 외에는 없음.

## 5. 남은 것(선택)

`GetSaveRootDir()` 규칙 1 은 "폴더 존재" 만 보므로 어떤 코드든 `ProjectDir()/Save` 아래에 파일 하나만 쓰면
같은 사고가 재발한다. 이번엔 쓰는 쪽 한 곳을 고쳤고 루트 선택 규칙은 손대지 않았다.
재발 방지를 더 원하면 규칙 1 을 "`Config/config_pmaker.json` 이 있는 폴더" 로 좁히는 안이 있다(에디터 `Park3D/Save/Config` 에는 있음).

## 6. 같은 증상을 다시 보면

- 로그에 `[Config] 시작 설정 파일 없음/읽기 실패 — ../../../Park3D/Save/...` 가 있으면 config 가 아니라 **`Package/Windows/Park3D/Save` 폴더 존재 여부**를 먼저 본다.
- 만든 주체는 `[RPC] <IP> <메서드>` 줄을 파일 시각(KST = 로그 UTC + 9h)으로 대조.
