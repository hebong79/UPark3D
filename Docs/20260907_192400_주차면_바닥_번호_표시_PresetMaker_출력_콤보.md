## 1. 무엇을 번호 매기는가

화면에 칠해진 면은 두 종류가 있고, 둘 다 번호를 붙인다.

| 대상 | 번호 규칙 | 근거 |
|---|---|---|
| 프리셋 면(`FParkingPreset` × FaceCount) | PresetMaker 리스트의 `[시작~끝]` 과 같은 값 — `UParkingGeometryLibrary::CalculateParkingSpaceAssignments`(카메라 idx → 프리셋 idx 순 연속) + 면 순서 | 패널이 이미 그 번호를 쓰고 있다. 다른 번호를 바닥에 쓰면 리스트와 어긋난다 |
| 레벨 `BP_ParkingSlot` 의 `ISM_Slot` 인스턴스 | 액터 이름 끝 숫자 순(`BP_ParkingSlot_C_1, _2, _3…`, 숫자 비교라 `_10` 이 `_2` 뒤) → 인스턴스 순으로 1부터 | 인스턴스에는 번호가 없다. `Park3D/Saved/Inventory/inventory_LV_Park_03.json` 으로 확인하니 이 순서가 SW 끝 (-17.39,-61.49)m 부터 NE 로 이어지고, 카메라 문서(`Docs/20260906_174500_*`)의 "SW 끝부터 01…14" 와 같다 |

서신·객리단 config 는 `preset_file` 이 `""` 라 실제로 보이는 것은 레벨 면 번호다(객리단 14개). 프리셋과 레벨 면이 같은 자리에 겹쳐 있으면 번호도 겹친다(현재 두 주차장 모두 프리셋이 비어 있어 해당 없음).

## 2. 어떻게 그리는가 — `UTextRenderComponent` 를 바닥에 눕힘

- `AParkingPresetManager::RebuildSlotNumbers(Presets)` 가 데칼 풀과 같은 cursor 규약으로 `UTextRenderComponent` 풀(`NumberPool`)을 재사용한다. 잉여는 숨김, 파괴하지 않는다.
- **폰트는 엔진 기본(`RobotoDistanceField`, Offline 캐시)을 그대로 쓴다.** 팀 보드 #63 / `CarPlateNumberWidget.h` 의 함정 — 프로젝트 한글 폰트(Runtime 캐시)를 TextRender 에 걸면 아무것도 안 그려진다. 여기는 숫자만 쓰므로 기본 폰트로 충분하다.
- 자세: TextRender 메시는 로컬 YZ 평면(법선 +X, 읽는 방향 −Y, 위 +Z, 엔진 `TextRenderComponent.cpp:1119-1126`). `FRotationMatrix::MakeFromXZ(UpVector, 글자위쪽)` 으로 법선을 월드 위로 눕힌다.
- **글자 위쪽 방향**: 면의 두 축(길이·폭) 중 **가장 가까운 카메라 방향과 더 나란한 축**을 골라 카메라 **반대쪽**으로 둔다 → 도로(카메라) 쪽에서 보면 글자가 똑바로 서고 번호는 도로를 따라 읽힌다. 처음엔 길이축으로 고정했는데, 객리단길은 **평행주차**(면 scale (6.14, 2.64) 의 긴 변이 도로 방향)라 글자가 도로에서 보면 옆으로 누웠다(캡처로 확인 후 수정). 카메라가 없으면 길이축.
- 크기: 기본 120cm, **면 폭의 45% 상한**(두 자리 숫자 폭 ≈ 높이×1.1 이라 좁은 면에서 라인을 넘지 않게). 객리단 폭 264cm → 118.8cm, 프리셋 기본 폭 250cm → 112.5cm.
- 색: 노랑 `(255,200,0)` — 흰 라인·베이지 노면과 갈린다(2026-08-17 십자선 교훈: 안 보이면 위치보다 대비를 먼저 의심). 높이 6cm(라인 5cm 위), 그림자 없음.
- 라인/데칼 모드와 **독립** — 두 모드 어디서나 같은 번호. 위젯 `RefreshView` 와 매니저 `RefreshView`(RPC 경로) 끝에서 모두 호출한다.

## 3. 토글 — PresetMaker 패널 "주차면 번호" 콤보

- 상태의 주인은 매니저 `bShowSlotNumbers`(기본 true). 콤보는 그 값을 바꾸고 `RefreshView` 를 부를 뿐이다(`bUseDecalView` 와 같은 구조). 패널을 다시 열 때마다 매니저 값으로 콤보를 맞춘다(`SetSelectedIndex` → `ESelectInfo::Direct` → 핸들러 무시).
- 항목: `출력`(기본) / `숨김`.
- **WBP 를 고치지 않고 C++ 로 행을 끼웠다** — `Content/` 는 git 밖이고 에디터 MCP 도 이 세션엔 연결되지 않았다. 또 쿠킹된 WBP 의 C++ 베이스에 `UPROPERTY` 를 더하면 패키지가 `Bad export index` 로 죽으므로(2026-08-12) 콤보 포인터는 **비-UPROPERTY** 로 둔다(위젯 트리가 자식으로 붙들어 GC 안전). 핸들러 `UFUNCTION` 추가는 함수라 exe 교체로 반영된다.
- 위치: `Park3DPanelStyle::FindContentColumn` 이 찾은 본문 세로상자에서 `Check_UseDecal` 이 속한 줄 **바로 다음**. WBP 에서 그 줄이 "데칼 표시 … 속도" 블록 하나라 실제로는 "속도" 줄 아래, "주차면 폭" 줄 위에 들어간다(캡처 참조). 한 번만 삽입(`bSlotNumberRowInserted`).
- 드롭다운 스타일은 주차장 선택 콤보의 `ApplyWhiteDropdown` 을 복사(흰 배경 + 검은 글자, `HandleSlotNumberItem`).

## 4. 시작 시 표시

`APark3DGameMode::BeginPlay` 가 `ApplyStartupConfig()` 뒤에 `AParkingPresetManager::GetOrSpawn` → `RebuildSlotNumbers(ResolvePresets())` 를 한 번 부른다. 매니저는 원래 패널을 열어야 생겼기 때문에, 이 호출이 없으면 프리셋 파일이 빈 주차장(서신·객리단)에서는 패널을 열기 전까지 번호가 안 보인다. 카메라 매니저(파일 적용) **뒤**여야 글자 방향이 카메라를 본다. 레벨 전환은 새 GameMode 가 다시 그린다.

## 6. 재검증(글자 방향 수정 후)

글자 방향 규칙은 두 번 틀렸다(둘 다 캡처로 반증).

| 시도 | 규칙 | 결과 |
|---|---|---|
| 1 | 글자 위 = 길이축(카메라 반대) | 객리단은 평행주차라 길이축이 도로 방향 → 글자가 도로에서 보면 옆으로 누움 |
| 2 | 길이·폭 중 가장 가까운 카메라 벡터와 더 나란한 축 | 카메라가 폴대 끝(도로 쪽 2~4m)이라 면 중심→카메라 벡터의 열 방향 성분이 더 큼(예: 면 (-5.2,-23.7)m → 카메라3 (-4.1,-14.6)m) → 1 과 같은 결과 |
| 3(확정) | 길이·폭 중 **열 방향(가장 가까운 이웃 면 쪽)에 수직인 축**, 부호는 카메라 반대 | 도로(동쪽)에서 똑바로 서고 번호가 도로를 따라 읽힘 |

최종 exe(19:52)로 복제본 재기동 → 로그 `주차면 번호 14개 표시(프리셋 0, 레벨 14, 풀 14)`, 캡처(`car.hideAll` 후, 45m 상공 yaw −107)에서 SW→NE 로 3,4,(5 는 폴대·카메라 아이콘 아래),6,7,8,9 가 노란 글자로 보이고 글자 위쪽이 서쪽(도로 반대)이다. 자동화 테스트 `Park3D.ParkingDecal.*` 5/5.

### 8.1 실행본이 낡았다(신고의 직접 원인)

정본이 띄운 `Package/Windows/Park3D/Binaries/Win64/Park3D.exe` 가 **9월 5일 22:04** 자였다. 오늘 11시에 패키지 빌드가 돌았지만 그건 이 작업(19:20~) 이전이라 옛 코드다. 패키지 루트의 `Park3D.exe`(171KB 부트스트랩)와 `.ucas` 만 오늘 날짜라 겉보기엔 최신처럼 보인다 — **판정은 항상 `Park3D/Binaries/Win64/Park3D.exe` 의 시각으로 한다**(2026-08-18 의 "실행본이 읽는 파일을 보라" 와 같은 함정).

### 8.2 글자 높이를 절대값으로 박아 면 판 밑에 깔렸다

`SlotNumberZ=6cm` 를 월드 절대 Z 로 썼다. LV_Park_03 은 `ISM_Slot` 인스턴스가 z=1.1cm 라 우연히 보였지만, **LV_Park_01 은 면 판이 z=10cm** 라 글자가 판 아래로 들어가 위에서 전혀 안 보였다(로그는 "23개 표시" 라고 정상 출력 — 값과 화면이 또 갈렸다). 수정: `Center.Z + SlotNumberZ`(면 기준 상대). 이제 LV_Park_01 에서 1~23 이 모두 보인다.

### 8.3 카메라 화면에서 숫자가 거꾸로 나왔다

`MakeFromXZ(Up, Axis)` 의 로컬 +Z 를 "글자 위쪽" 으로 보고 카메라 **반대쪽**을 향하게 했더니 카메라 캡처에서 5·6·7·8·9·10 이 전부 180° 뒤집혀 나왔다. 엔진 정점이 `Z = −Top`(TextRenderComponent.cpp:1119) 이라 로컬 +Z 는 글자 **아래쪽**이다. 수정: 축이 **카메라를 향하게** 둔다. 감시 카메라 화면이 이 앱의 판정 화면이므로 그쪽 기준으로 맞췄다(`cam.captureJPG` 로 확인).

### 8.4 유니티 빌드 이름 충돌(빌드 실패)

`PresetMakerWidget.cpp` 의 익명 네임스페이스 `ApplyWhiteDropdown` 이 `LevelSelectWidget.cpp` 의 같은 이름과 **C2084 재정의 에러**를 냈다. 익명 네임스페이스라도 Adaptive Unity 가 두 .cpp 를 한 TU 로 묶으면 충돌한다. 처음 빌드가 통과한 것은 그때 이 파일이 유니티에서 제외돼 있었기 때문이다(수정 이력에 따라 바뀐다). → `ApplyPresetWhiteDropdown` 으로 개명.

## 7. 한계·메모

- 번호는 **화면 표시 전용**이다. `FCarPos.slotId`·`sim.*`·`scenario.*` 의 slotId 공간은 건드리지 않았다(레벨 면은 여전히 번호가 없다).
- RPC 는 열지 않았다(요청 범위 밖). 필요하면 `preset.setView` 옆에 `bShowSlotNumbers` 를 여는 것이 자연스럽다.
- 정본 인스턴스(13510)는 exe 를 갈아끼우고 재기동해야 반영된다. `Package/Windows` 는 건드리지 않았다.
