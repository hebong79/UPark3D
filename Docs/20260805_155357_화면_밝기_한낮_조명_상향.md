## 2. 원인 분석

### 2-1. 증상 실측

실행 중인 인스턴스의 Camera-1을 캡처해 루마를 측정했다(지면·차량 영역 = 프레임 하단 65%).

| 지표 | 값 |
|------|-----|
| 평균 루마 | 16.6 / 255 |
| 중앙값 루마 | 5.5 |
| 뭉갬(루마 ≤16) | **71.19%** |

지면 픽셀의 71%가 완전 검정으로 뭉개져 있었다. "어둡다"는 주관적 인상이 아니라 **정보가 실제로 소실된 상태**였다. 차량이 없는 순수 아스팔트만 떼어 보면 뭉갬이 **97.6%**로, 지면은 사실상 검은 화면이었다.

### 2-2. 조명 리그 실측

프로젝트 소스(`Park3D/Source/`)에 조명 관련 C++ 코드가 **전혀 없어**, 밝기는 전적으로 레벨 액터가 결정한다. 에디터와 Unreal MCP(8000)가 모두 꺼져 있었으므로 `UnrealEditor-Cmd.exe -run=pythonscript` **헤드리스 경로**로 조사했다.

| 액터 | 프로퍼티 | 값 |
|------|---------|-----|
| `DirectionalLight` | Intensity | **6.0 lux** (UE5 기본 태양광 10.0 미만) |
| | Rotation | pitch **−16.29**, yaw 43.73, roll 112.36 |
| | AtmosphereSunLight | True (index 0) |
| `SkyLight` | Intensity / SourceType / RealTimeCapture | 1.0 / CapturedScene / **True** |
| `PP_FixedExposure` (unbound, prio 1) | Method / Bias / Min / Max | HISTOGRAM / 1.0 / **0.0** / **0.0** |
| `SkyAtmosphere`·`VolumetricCloud`·`ExponentialHeightFog` | - | 기본값 |

### 2-3. 원인 — 두 가지가 겹쳐 있었다

1. **태양 고도가 16.29°** — 일몰 직전 각도다. 수평 지면 입사 코사인이 sin(16.29°) = **0.28**로 빛의 72%가 각도 때문에 손실되고, 저각도는 대기 통과 경로가 길어 `SkyAtmosphere` 투과율까지 떨어뜨린다(캡처에서 지평선이 붉게 뜬 이유).
2. **노출이 고정** — `Min/MaxBrightness = 0.0/0.0`이라 자동 노출이 잠겨 있다. 보통은 노출계가 어두운 조명을 보정하지만, 여기서는 보정이 없어 조명 부족이 화면에 그대로 드러난다.

`PP_FixedExposure`라는 명명과 min=max 고정은 **CCTV 화면 밝기를 프레임마다 일정하게 유지하려는 의도된 설계**로 판단했다(카메라가 차량을 비출 때 자동 노출이 출렁이면 감시 영상으로 쓸 수 없다). 따라서 노출은 건드리지 않고 조명만 올렸다 — 사용자 선택과도 일치한다.

## 3. 변경 내용

**코드 변경 없음. 레벨 액터 프로퍼티 3건만 변경했다.**

| 대상 | 프로퍼티 | 변경 전 | 변경 후 | 근거 |
|------|---------|--------|--------|------|
| `DirectionalLight` | Rotation.Pitch | −16.285559 | **−55.0** | 태양 고도 16.29°→55°. 입사 코사인 0.28→0.82(2.9배) + 대기 투과율 상승 |
| `DirectionalLightComponent` | Intensity | 6.0 | **20.0** | 목표 밝기까지 실측으로 수렴시킨 값(4절) |
| `SkyLightComponent` | Intensity | 1.0 | **1.5** | 그늘 뭉갬 완화 |

- **yaw 43.73 / roll 112.36은 유지**했다. yaw를 보존해 그림자 방향을 그대로 두어 기존 주차장 배치의 시각적 인상 변화를 최소화했다. roll은 디렉셔널 라이트의 진행 방향(액터 +X축)을 바꾸지 않으므로 무관하다.
- 태양 고도를 90°(정오 수직)로 하지 않은 이유는 그림자가 완전히 사라져 차량 형상 구분이 나빠지기 때문이다. "또렷"을 위해 그림자를 남겼다.

### 검토했으나 채택하지 않은 대안

| 안 | 내용 | 기각 사유 |
|----|------|----------|
| B | `PP_FixedExposure`의 Bias를 1.0→4.0 | 값 하나로 즉효지만 조명은 그대로라 **이미 검정으로 뭉개진 71%에는 복원할 정보가 없다**. 노이즈만 증폭되고 하늘이 먼저 클리핑된다 |
| C | `SkyLight`만 크게 상향 | 앰비언트만 오르면 그림자가 사라져 평평해진다. "또렷"과 정면 배치 |
| D | C++로 런타임 조명 제어 추가 | 사용자가 선택하지 않음. 최소 변경 원칙 위배 |

## 4. 값 수렴 과정 (측정 기반)

추정에 의존하지 않고 실측으로 수렴시켰다. 사전 영향도 경고에 따라 **실행 중인 패키지가 아니라** `-game`으로 새로 띄운 인스턴스(RPC 13511)에서 검증했고, 실행 중 패키지(13510)의 차량 23대 배치와 카메라 자세(pos·pan·tilt·zoom)를 RPC로 복제해 **동일 구도**로 비교했다.

| 후보 | 태양 pitch / Intensity | 하늘 | Cam1 평균 루마 | 뭉갬 | 클리핑 |
|------|----------------------|------|--------------|------|--------|
| 기준선 | −16.29 / 6.0 | 1.0 | 16.6 | 71.19% | 0.00% |
| A | −55 / 10.0 | 1.0 | 56.2 | 17.26% | 0.04% |
| B | −55 / 16.0 | 1.5 | 92.3 | 7.88% | 0.06% |
| **C (채택)** | **−55 / 20.0** | **1.5** | **106.2** | 5.92% | 0.07% |

> **중간에 내린 판단 하나를 정정했다.** 후보 A 단계에서 "아스팔트 반사율상 평균 110~150은 화면을 태워야만 나온다"고 판단했으나, 광량을 올려 실측하니 **클리핑 없이 도달 가능**했다. 광량을 2배로 올리는 동안 클리핑은 0.04%→0.07%로 사실상 변하지 않았다. 노출 고정 + 필믹 톤매퍼에 하이라이트 여유가 충분했기 때문이다.

## 6. 영향도

### 6-1. 변경된 파일

```
Park3D/Content/__ExternalActors__/Maps/PresetMaker1/**  (DirectionalLight, SkyLight 액터 패키지)
```

`.umap`·`Config/`·`Source/` 변경 **0건**. 빌드·모듈 의존성에 영향 없음.

> **`Park3D/Content/`는 `.gitignore:27`로 git 추적 대상이 아니다.** 따라서 이 변경은 커밋되지 않으며 버전 관리 밖에서 관리된다. 되돌리려면 원본 값(pitch −16.285559 / Sun Intensity 6.0 / SkyLight 1.0)을 다시 적용해야 한다.

### 6-2. 라이팅 리빌드 불필요

두 라이트 모두 **Movable**이고 프로젝트가 스태틱 라이팅을 껐다(`r.AllowStaticLighting=0`). `DefaultEngine.ini`의 `r.DynamicGlobalIlluminationMethod=1`(Lumen)과도 일관된다. 조명이 전부 동적으로 계산되므로 **라이트맵 리빌드가 필요 없다.**

### 6-3. 의도된 부수 변화

태양 고도가 바뀌었으므로 대기 산란 결과가 함께 바뀐다.

| 요소 | 변경 전 | 변경 후 |
|------|--------|--------|
| 하늘 색 | 일몰 붉은 기 (루마 66.6~79.2) | 주간 밝은 회백색 (201.7~202.4) |
| `ExponentialHeightFog` | 저각도 산란으로 지평선이 붉음 | 흰 헤이즈 |
| `VolumetricCloud` | 어둡게 깔림 | 밝게 표현 |
| 그림자 방향 | yaw 43.73 | **동일** |

"한낮"이라는 요구의 필연적 귀결이다.

### 6-4. 카메라 뷰어 연동

`PTZCameraActor`의 SceneCapture는 `CaptureSource = SCS_FinalColorLDR`(톤매핑 후 색)이라 씬 조명을 그대로 받는다. 따라서 **코드 변경 없이** 카메라 뷰어와 MJPEG 스트림이 함께 밝아진다.

### 7-1. 런타임 배치 소실과 복원

재패키징을 위해 실행 중인 인스턴스를 종료하면서, **저장되지 않은 런타임 배치(차량 23대·카메라 2대)가 소실**됐다. 이는 재패키징 확인 시 사전 고지한 위험이었다.

복원 경로를 찾아 되살렸다.

| 항목 | 복원 방법 | 결과 |
|------|----------|------|
| 차량 23대 | `Package/Windows/Save/3D/CarPos/CarPos_SNum.json`의 첫 차량 id `0-16.25.24`가 소실된 배치와 **정확히 일치** → `car.load {fullPath}`로 로드 | 23대 복원. 좌표는 소실 전 대비 0.04~0.12 단위 차이(런타임에 미세 지터가 적용돼 있었음) |
| 차량 방향 | 파일값 `rotY=5.24` vs 소실 전 `rotY=180` → `car.groupRotate {presetId:1, deltaRotY:174.755}` | 13대 회전, `rotY=180` 일치 |
| 카메라 2대 | 작업 중 기록해 둔 자세값으로 `cam.setPosition`/`cam.setPTZ` 재설정 | Cam1 (−7.1, −9.5, 5) pan 19.8 / tilt 8.7 / zoom 1.6214, Cam2 (20.7, −10.7, 5) pan 113.8 / tilt 6.0 / zoom 2.9 — 소실 전 값과 일치 |

> **주의 — 완전 복원은 아니다.** 차량 좌표에 소실 전과 0.04~0.12 단위의 미세 차이가 있고, 이는 런타임에만 있던 지터라 되살릴 수 없다. 또한 이 복원 상태 역시 **저장되지 않은 런타임 상태**이므로, 유지하려면 UI 또는 `car.save`로 저장해야 한다.

## 9. 작업 방법 기록 (재사용)

에디터·Unreal MCP 없이 레벨 에셋을 수정·검증한 경로다.

1. **조사·수정**: `UnrealEditor-Cmd.exe <uproject> -run=pythonscript -script=<py> -unattended -nosplash -nullrhi`
   - WP+OFPA 맵은 `save_dirty_packages(True, True)`로 저장해야 외부 액터 패키지가 기록된다.
   - 저장 후 맵을 언로드/재로드해 **디스크 값으로 영속을 재확인**할 것.
   - `unreal.log()` 출력은 커맨드라인 stdout이 아니라 `Park3D/Saved/Logs/Park3D.log`에 남는다.
   - `unreal.Rotator` 생성자 인자 순서는 (roll, pitch, yaw)라 혼동하기 쉽다 — `set_editor_property`로 이름 지정할 것.
2. **검증 기동**: `UnrealEditor.exe <uproject> -game -RpcPort=13511 -RpcAllowAnonymous -windowed`
   - 실행 중인 패키지(13510)와 **포트를 달리해 병존** 가능. 실행 중 인스턴스는 쿠킹 콘텐츠라 맵 수정이 반영되지 않으므로 반드시 새 인스턴스로 검증한다.
3. **측정**: `cam.captureJPG` → base64 디코드 → 루마 통계(`_workspace/measure.py`).
   - MCP 도구로 캡처를 직접 받으면 base64가 컨텍스트를 채우므로, curl로 파일에 저장한 뒤 디코드할 것.
