## 4. 단계 3에서 드러난 구조적 사실 — 스테이지에 `DefaultGame.ini` 가 없다

지시는 "새 exe 와 DefaultGame.ini 를 Package/Windows 에 복사"였으나, **복사할 대상 경로가 존재하지 않았다.**

```
Package\Windows\ 전체를 재귀 검색 → DefaultGame.ini 0건
Package\Windows\Park3D\Content\Paks\Park3D-Windows.pak (11.5 MB) 내부에 쿠킹되어 있음
```

패키지 빌드에서 프로젝트 config 는 pak 안으로 쿠킹되므로 **파일 복사로는 바꿀 수 없다.**
따라서 동일한 목적(재빌드 없이 값 튜닝)을 달성하는 UE 표준 경로인 사용자 config 레이어를 사용했다.

```
Package\Windows\Park3D\Saved\Config\Windows\Game.ini
```

이 파일은 원래 없었고(그래서 롤백 시 삭제 대상), `DefaultGame.ini` 위에 덮이는 레이어다.
단계 5의 A/B(`bMainGuardEnabled` False→True)가 성립하려면 이 경로가 반드시 필요했다.

> 이 방식이 실제로 먹는지는 **검증되지 않았다.** 검증 계획은 "guard=False 로 띄운 뒤
> `cam.streamStatus` 의 `main.guard.enabled` 가 false 로 보이면 override 성공(C++ 기본값은 true)"
> 이었으나, 앱이 기동되지 않아 실행하지 못했다.

배포 자체는 수행되었다(새 exe 복사 후 UTF-16 리터럴 4종 FOUND 로 확인). 이후 롤백했다.

## 5. 단계 4 실패 — 근본 원인은 Session 0 격리

### 증상

재기동 시도가 전부 실패했다. 로그 tail:

```
LogD3D12RHI: Error: hr failed at WindowsD3D12Viewport.cpp:162
             with error DXGI_ERROR_NOT_CURRENTLY_AVAILABLE
Fatal error: [D3D12Util.cpp] [Line: 1062]
[Callstack] FD3D12Viewport::Init()
[Callstack] FSlateRHIRenderer::CreateViewport()
[Callstack] SWindow::ShowWindow()
[Callstack] UGameEngine::CreateGameWindow()
[Callstack] FPreLoadScreenManager::Initialize()
[Callstack] FEngineLoop::PreInitPreStartupScreen()
```

종료 코드 3.

### 원인

```
이 셸의 SessionId   : 0        (services, UserInteractive = False)
사용자 데스크톱     : Session 1 (console, goback, Active)
```

**Session 0 프로세스는 대화형 데스크톱/윈도우 스테이션이 없어 D3D12 스왑체인을 만들 수 없다.**
그래서 게임 윈도우 생성 단계에서 `DXGI_ERROR_NOT_CURRENTLY_AVAILABLE` 로 죽는다.
원래 인스턴스(PID 19212)는 사용자가 Session 1 에서 띄운 것이었다.

### 이 실패가 이번 코드 변경과 무관하다는 근거

1. 크래시 지점이 `FEngineLoop::PreInitPreStartupScreen()` — **엔진 기동 중, 게임 코드 진입 전**이다.
   `UCamStreamSubsystem` 은 월드 생성 이후에야 만들어지므로 이 시점에 존재하지도 않는다.
2. 콜스택 전체가 D3D12/Slate/윈도우 생성 경로이며 Park3D 심볼이 하나도 없다.
3. 실패 원인이 세션 격리이므로 **어떤 빌드를 띄워도 동일하게 실패한다.**

다만 이는 "새 빌드가 정상 동작한다"는 증명이 **아니다.** 새 빌드는 컴파일·링크·리터럴 반영까지만
확인되었고, **런타임 동작은 여전히 미검증**이다.

### 부수적으로 확인된 것 (내 환경 한정 함정)

`run_park3d.bat` 을 그대로 돌렸을 때 첫 실패는 다른 이유였다.

```
'Park3D.exe'은(는) 내부 또는 외부 명령... 이 아닙니다.
```

내 셸에 `NoDefaultCurrentDirectoryInExePath=1` 이 설정되어 있어 cmd 가 현재 디렉터리에서
실행 파일을 찾지 않기 때문이다. **사용자 환경에는 이 변수가 없으므로 bat 은 정상이다.**
`run_park3d.bat` 은 수정하지 않았다.

### 7-B. 새 빌드로 배포하고 실측까지 진행

1. 앱이 떠 있다면 종료.
2. 재배포(2개):

```powershell
Copy-Item 'D:\Work\UnrealWork\Parking\Park3D\Binaries\Win64\Park3D.exe' `
          'D:\Work\UnrealWork\Parking\Package\Windows\Park3D\Binaries\Win64\Park3D.exe' -Force
```

`Game.ini.deployed` 는 `bMainGuardEnabled=False`(A/B 1회차용)로 들어 있다.

3. **데스크톱에서** `run_park3d.bat` 실행.
4. 그 뒤 검증·실측은 HTTP/RPC 로 하므로 내가 이어서 할 수 있다. 알려주면 진행한다.
   - 13510/13600 LISTEN 확인, 13600 MJPEG 수신 바이트 확인, 13510 회귀 확인
   - `main.guard.enabled == false` 로 Game.ini override 가 실제로 먹는지 검증
   - 30초 관측 → `captureAvgMs` / `captureMaxMs` 기록
   - `bMainGuardEnabled=True` 로 바꾸고 재기동(다시 사용자 손 필요) → 같은 측정 → 비교표

## 8. 배운 것 (재발 방지)

1. **Session 0 셸에서는 GUI/D3D 애플리케이션을 기동할 수 없다.** 종료는 되지만 기동은 안 된다 —
   이 비대칭이 위험하다. "종료 후 재기동" 류 작업은 착수 **전에** 세션을 확인해야 한다.
   `[Environment]::UserInteractive` 와 `(Get-Process -Id $PID).SessionId` 로 1초면 확인된다.
2. 이번 작업에서 그 확인을 기동 실패 **후에** 했다. 순서가 반대였다. "재기동 방법 확보"는
   커맨드라인을 아는 것만으로 부족하고, **그 방법을 이 컨텍스트에서 실제로 실행할 수 있는지**까지
   포함해야 한다.
3. 패키지 빌드의 config 는 pak 내부에 있다. 스테이지에 `DefaultGame.ini` 가 보이지 않는 것이 정상이며,
   런타임 튜닝은 `Saved/Config/<Platform>/Game.ini` 레이어로 한다.
