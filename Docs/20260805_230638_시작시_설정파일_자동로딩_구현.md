# 앱 시작 시 설정 파일(config_pmaker.json) 자동 로딩 — 구현·검증

- 작성일: 2026-08-05
- 설계서: `Docs/20260805_223740_시작시_설정파일_자동로딩_설계서.md`
- 원본 참조: `unity/PresetMaker/CPresetMakerScene.cs` (`LoadInitialData`)

## 1. 무엇을 만들었나

`Park3D/Save/Config/config_pmaker.json` 을 앱 시작 시 읽어, 지정된 프리셋·카메라위치·차량배치 JSON 을
자동으로 로딩·화면 적용한다. **각 패널의 "열기" 버튼 경로를 그대로 호출**하므로, 3D 액터뿐 아니라
위젯 목록·입력 필드·파일명 표시까지 사용자가 직접 파일을 연 것과 같은 상태가 된다.

```json
{
    "rpc_port": 13510,
    "preset_file": "001_Preset_Seo_1.json",
    "carpos_file": "CarPos_Seoshin_2Cam.json",
    "camerapos_file": "CamPos_Seosin.json",
    "max_zoom": 36.0
}
```

> 사용자가 제시한 예시의 후행 쉼표(`36.0,`)는 유효 JSON 이 아니므로 실제 파일에서는 제거했다.
> 파일명만 적으면 `Save/3D/{Preset|CameraPos|CarPos}` 아래에서 찾고, 경로를 적으면 그 경로를 쓴다.
> 키를 빼면 그 항목만 건너뛴다.

| 파일 | 내용 |

| **`Source/Park3D/Tests/Park3DAppConfigTest.cpp`** (신규) | 유닛테스트 8건. |

| `Source/Park3D/Rpc/RpcServerSubsystem.cpp` | 포트 결정 체인에 config 단계 삽입. |

### 2.1 파싱 (`UPark3DAppConfigLibrary`)

`FJsonSerializer` 로 **필드 단위 수동 파싱**한다. `FJsonObjectConverter` 는 루트 키만 맞으면 다른
스키마도 조용히 성공시키는 전례가 있어 쓰지 않았다. 파싱 실패 시 출력 구조체를 건드리지 않는다.
`rpc_port` 가 1~65535 밖이면 "미지정"(0)으로 떨어뜨려, 이상한 포트를 조용히 잡는 일이 없게 했다.

### 2.2 적용 순서 (`APark3DGameMode::ApplyStartupConfig`)

```
1. max_zoom      → ACameraControlManager::SetCameraMaxZoom
                    (아래 카메라위치 로딩이 카메라를 새로 스폰하므로 반드시 먼저)
2. preset_file   → UPresetMakerWidget::LoadFromJsonFile
3. camerapos_file→ UCameraControlWidget::LoadFromJsonFile
4. carpos_file   → UCarPlacementWidget::LoadFromJsonFile
```

2~4의 순서는 Unity `LoadInitialData` 와 같다. 각 패널은 `EnsurePanelConstructed` 로 **표시 없이
구성만** 마친 뒤 로드하므로, 시작 화면은 기존과 동일하게 PresetMaker 패널만 보인다.

### 2.3 RPC 포트 우선순위 (사용자 확정)

```
-RpcPort=NNNN  >  config_pmaker.json rpc_port  >  DefaultGame.ini [RpcServer] Port  >  13510
```

`-RpcPort=0`(서버 미기동)의 기존 의미는 그대로다. MCP 브리지·자동화가 `-RpcPort=` 로 포트를 바꿔
띄우던 동작이 설정 파일에 덮이지 않는다.

## 4. 영향도 분석

### 4-1. 빌드/모듈

새 의존 모듈 없음(Json/JsonUtilities 는 이미 사용 중). `Park3DEditor Win64 Development` 풀 빌드
성공(링크 포함). 신규 폴더 `Source/Park3D/Config/` 는 모듈 소스 루트 아래라 `Build.cs` 수정 불필요.

### 4-2. 기존 기능

| 대상 | 영향 |
|---|---|
| `UCameraControlWidget::HandleOpen` | 본문을 `LoadFromJsonFile` 로 옮긴 순수 추출. 다이얼로그 취소 시 동작 동일, 실패 시 `Notify("열기 실패")` 동일. |
| `ACameraControlManager::AddCamera` | 스폰 카메라에 `MaxZoom` 을 주입하는 1줄 추가. 기본값이 액터 기본값과 같은 36 이라 설정을 안 쓰면 무변화. |
| `UMainMenuWidget` | 메서드 추가만. `TogglePanel` 로직 불변. |
| `URpcServerSubsystem` | 포트 체인에 1단계 추가. 설정 파일이 없거나 `rpc_port` 가 없으면 기존과 완전히 동일. |
| `APark3DGameMode::BeginPlay` | 마지막에 호출 1줄 추가. 설정 파일이 없으면 조기 반환. |
| 저장(Save) 경로 | 변경 없음. 자동 로딩된 상태에서 "저장"을 누르면 평소처럼 다이얼로그가 뜬다. |

### 4-3. 남는 경계 / 알아둘 것

- **패널 zoom Max 필드 vs config `max_zoom`**: 위젯의 `Camera Zoom Max` 는 카메라위치 JSON 이
  주는 값이고, `max_zoom` 은 액터의 줌↔FOV 매핑 상한이다. 둘을 일부러 연결하지 않았다(파일 저장 시
  서로 덮어쓰는 것을 피하려는 것). 다른 값을 쓰면 슬라이더 상한과 실제 클램프가 어긋날 수 있다.
- **`preset.list` RPC 는 여전히 빈 목록**을 돌려준다. 위젯 목록과 RPC 프리셋 매니저 목록이 원래
  분리되어 있기 때문이며(기존 제약), 이번 변경이 만든 문제가 아니다. 화면·데칼은 정상이다.
- **패키지 빌드**: 설정 경로는 `Park3DDataPaths::GetSaveRootDir()` 를 쓰므로 스테이지 루트의
  `Save/Config/` 를 본다. 패키지에 반영하려면 재패키징(또는 스테이지의 `Save/Config/` 에 파일 배치)이
  필요하다. 이번 작업에서는 재패키징을 수행하지 않았다.
