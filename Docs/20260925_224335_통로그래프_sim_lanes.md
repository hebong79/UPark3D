## 1. 문제

`ParkSimLot::PlanEnter/PlanExit` 은 게이트와 목표 면 줄을 **Dubins 한 번**(`MinRadius×1.3`)으로 이었다.
그 연결은 주차된 차만 `note` 로 검사하고 다른 면 줄·빈 면·벽·일방통행은 모른다. 통로 진행 방향도
"입구가 어느 쪽이냐"(`Along >= 0 ? RowDir : -RowDir`)로만 정했다. 객리단길(한 줄)은 괜찮지만 서신지구대(LV_Park_01,
가운데 섬 1–4/11–14, 반시계 일방, 입구·출구 나란히)에서는 역주행하고 출차 연결이 18–23번 면을 가로지른다.

## 2. 한 일

### 2.1 통로 그래프 자동 생성 (`Sim/ParkLaneGraph.*`, 신규)

1. **주행 가능 격자** — 주차면 바운딩 박스 + 12 m, 0.2 m 격자(120만 칸 넘으면 칸을 키움). 칸마다 **차 지붕 높이(지면+2.5 m)에서
   아래로** 정적 오브젝트 질의(`AllStaticObjects`, 복합 충돌)를 쏜다. 맞은 높이가 지면 ±5 cm 면 주행 가능.
   - 지면 기준 = 면 중심 아래 높이의 중앙값으로 거른 최소제곱 평면(경사 10% 넘으면 믿지 않고 중앙값).
   - 무시하는 액터: 차량(`ACarActor`), 폰, `BP_ParkingSlot*`(LV_Park_01 면 판은 z=10 cm 콜리전이 있다).
   - 2.5 m 위에서 쏘므로 나뭇잎·카메라 팔·가로등 머리는 통로를 막지 않는다. 연석·볼라드·장비·벽·차단봉은 막는다.
   - **Visibility 채널을 쓰지 않는다** — LV_Park_01 노면(`BP_SplineMeshPlane`)은 Visibility 를 무시한다(CarActor 접지 주석과 같은 이유).
2. 주차면 칸을 뺀다(격자 값 2).
3. 거리 변환(Felzenszwalb) → **차 반폭 1.0 m 로 깎은 공간** → Zhang-Suen 세선화 → 골격.
4. 이웃 수로 노드 칸(끝점·교차)을 묶어 노드, 그 사이 골격을 에지로. 정리 반복: 폭 2.4 m 미만 에지 제거,
   0.6 m 안의 노드 병합, 끝이 막힌 2 m 미만 가지 제거, 차수 2 노드 합치기, 총 5 m 미만 조각 제거.
5. id: 노드는 0.1 m 반올림 좌표 순, 에지는 (작은 노드, 큰 노드, 길이) 순 → `N1…`, `E1…`. 같은 레벨·같은 면 구성이면 같은 id
   (레벨 다시 불러와도 같음을 실측).
6. 캐시: 레벨 경로별, 면 구성 서명(개수·중심·치수)이 바뀌거나 `rebuild` 면 다시 만든다. 서신 122~290 ms.

### 2.2 규칙

- 에지마다 `one`(From→To, `reverse` 면 반대) / `two` / `blocked`.
- 적용 순서: 에지 개별(runtime > config) > loop(runtime > config) > 기본 `two`.
- `loop: ccw|cw` — 주차면 무리 중심 둘레의 정규화 순환 `Σ(p−c)×Δp / Σ|p−c||Δp|` 의 부호로 에지 방향을 정한다.
  **ccw = UE 탑뷰(X 위·Y 오른쪽)에서 반시계 = 외적 < 0** (#982 의 정의와 같다). |값| < 0.3 인 방사 에지와
  게이트 5 m 안의 8 m 미만 연결 에지(`by: connector`)는 `two`.
- `suggestedLoop` — 입구 방향을 오른쪽(yaw+90°)으로 꺾었을 때 도는 방향. 서신(TourAgent 게이트) = **ccw**(도색과 일치).
- 저장: runtime 은 프로세스 전역·레벨별(`sim.setGates` 와 같은 성질, 재기동하면 사라짐). config 는 `levels[].sim_lane_rules`(같은 스키마).

### 2.3 경로 → 실차 궤적

1. **경로 찾기** — 방향 에지 상태 (에지, 방향) 위 Dijkstra. 같은 에지를 되짚는 U턴 금지(고리 에지를 같은 방향으로 한 바퀴는 허용),
   노드에서 **135° 넘게 꺾는 연결 금지**(에지 끝 5 m 현 방향으로 잰다 — 1~2 m 로 재면 골격 교차의 V 자 때문에 실제 90° 꺾기도 U턴으로 보였다).
2. **진행 방향** — 면 앞 통로 에지를 찾고(면 통로 쪽 가장자리에서 통로 폭 절반, 열 방향과 |cos|≥0.6, 6 m 안), 규칙이 허락하는
   ±열 방향을 게이트까지 그래프 길이 순으로 **차례로 해 본다**(가까운 쪽이 모서리를 못 돌면 반대쪽, note 에 남김). 사선·도로변 출차는 방향 고정.
3. **목표선** — 그래프 경로(양방향 에지는 우측통행 오프셋 = min(폭/4, 폭/2−차반폭−0.25))를 게이트·기동 이음점과 잇고,
   **지름길**(25 m 안에서 여유 ≥ 차반폭+0.35 m 인 직선으로 사이 점을 버림 — 골격 교차의 V 자 우회 제거) →
   **모서리 둥글리기**(반경 1.15×최소회전반경 접원호, 변이 짧으면 줄임).
4. **추종** — 순수 추종(곡률 ≤ 1/(1.05 R), 0.005 1/m 로 양자화한 호, 0.2 m 스텝, 전진만). 입차는 **기동 시작 자세에서 거꾸로**
   추종해 뒤집으므로 기동과의 이음매 오차가 0(테스트 3e-13 m). 출차는 기동 끝에서 앞으로.
5. **판정** — 차체 12점을 0.25 m 마다 격자에 대 본다. 벽·장애물(격자 0)에 닿으면 실패, 면 가장자리(2)면 note.
   게이트 4 m 안은 보지 않는다(차단봉은 열린다). 격자 밖은 잰 적이 없으니 막힘으로 보지 않는다.
   우측통행 오프셋으로 실패하면 가운데 선으로 한 번 더. 서 있는 차와의 간격은 예전처럼 `transitClearanceM` + note.
6. 기동 앞·뒤 통로 직진은 2 m 로 줄였다(그래프 경로가 통로를 달린다).
7. 그래프를 안 쓰는 경우: 레벨에 면이 없어 그래프가 비었을 때, 입구·출구가 `auto` 인 정형·사선(예전대로 통로 끝 출발/도착),
   면 앞 통로 에지를 못 찾았을 때(예전 Dubins + **경고 note**). 규칙상 길이 없으면 **실패**(대체하지 않는다).

## 3. RPC 계약

```
sim.lanes {rebuild?, withGrid?, groundTolM?(rebuild 때만, 0.05), halfWidthM?(rebuild 때만, 1.0)}
  -> {nodes[{id,x,y}], edges[{id, from, to, pts[{x,y}], lengthM, minWidthM, rule:one|two|blocked, reverse, by:default|loop|connector|config|runtime}],
      rulesSource: runtime|config|default, loop, suggestedLoop, loopCenter{x,y}, entrance, exit,
      build{boundsMin, boundsMax, cellM, groundZ, drivableCells, freeCells, buildMs, note},
      grid?{origin{x,y}, cellM, w, h, data(base64, 칸당 1바이트 0 막힘/1 주행/2 주차면, index = iy*w + ix, 칸 중심 = origin + (ix,iy)*cellM)}}
sim.setLaneRules {loop?:"ccw"|"cw"|"none", edges?:[{id, rule, reverse?}], reset?}   -> sim.lanes 와 같은 응답
  (없는 id 는 거부. reset 은 먼저 runtime 규칙을 지운다. edges 는 id 별로 덮어쓴다)
sim.start / sim.exit / sim.plan  -> plan.laneRoute {used, edges[], lengthM(그래프 중심선), rulesSource, pts[{x,y}](추종 목표선)}
  plan.polyline 에 그래프 구간이 들어 있다(구간 label "통로를 따라 주행(통로 그래프)" / "통로를 따라 출구로(통로 그래프)", transit=true).
config levels[].sim_lane_rules = {loop?, edges?:[{id, rule, reverse?}]}
```

좌표는 UE 월드 미터. #981 제안에서 바꾼 것: 없음(이름 그대로). 더한 것: `reverse`/`by` 필드, `withGrid`, `laneRoute.pts`, 규칙 없음 시 `loop:"none"`.

## 5. 함정·결정

- **엔진 전역 `FEdge`** 와 이름이 겹쳐 `using namespace ParkLane` 한 테스트가 깨졌다 → `FLaneEdge/FLaneNode/FLaneGraph/FLaneGrid`.
  도우미는 `ParkLane` 안 익명 네임스페이스에 둔다(유니티 빌드 C2084 예방).
- 골격 교차점은 모서리 쪽으로 밀려 경로가 V 자로 우회한다 → 순수 추종이 모서리에서 벽을 긁었다. 해법은 세 겹:
  135° 판정을 5 m 현으로, 격자 여유 기반 지름길(25 m), 접원호 둥글리기. 지름길 범위 10 m 는 DP 로 성긴 점 사이를 못 넘어 실패했다.
- 추종 실패 판정을 "경로에서 3 m" 로 했다가 실제로 안 부딪치는 경우까지 떨어뜨렸다 → 차체를 격자에 대 보는 것이 진짜 판정, 4.5 m 는 안전장치만.
- 우측통행 오프셋은 모서리에서 차를 바깥 벽으로 민다(서신 좌상단 (11.7, 4.0)) → 오프셋으로 안 되면 가운데 선.
- 게이트 자리의 `SM_ParkingEntrance`(차단봉 구조물, 6.8×7 m·높이 2 m)는 격자에서 막힘이다 → 게이트 4 m 안은 충돌 판정 제외.
  그 때문에 서신의 바깥 도로 쪽 그래프(E1–E5, E12)는 주차장 그래프와 떨어져 있다(TourAgent 가 막을 에지).
- `sim.setLaneRules` 는 저장하지 않는다(요청대로 TourAgent 가 매 주행 전에 건다). config 기본값은 `levels[].sim_lane_rules`.
