# 차량배치 대화상자 다중 선택 방식 변경 (연속 범위 → 개별 토글)

관련 phase: `carmultisel`
관련 산출물: `_workspace/carmultisel_architect_design.md`, `_workspace/carmultisel_impact_post.md`, `_workspace/carmultisel_luna_behavior_impact_report.md`

## 1. 요청 사항

> 차량배치 대화상자에서 차량을 클릭하여 선택하는데 LShift+마우스 클릭이면 여러 개의 차량을 선택할 수 있다.
> 현재는 프리셋 기준으로만 선택된다. 프리셋과 관계없이 여러 개가 선택될 수 있도록 수정해줘.
> (추가) 리스트 뷰에서도 아이템 선택이 똑같이 가능하게.
> (추가) 선택은 된다. 프리셋의 주차면이 4개이면 4개까지만 된다.

---

## 2. 원인 분석

기존 Shift+클릭은 **앵커(AnchorIndex) ~ 대상(Index) 사이의 연속 범위**를 통째로 선택하는 방식이었다.

```cpp
// 변경 전 — CarPlacementWidget.cpp
if (bShiftDown && CarData.datas.IsValidIndex(AnchorIndex))
{
    SelectedIndices = UCarPlacementLibrary::BuildShiftSelection(
        CarData.datas.Num(), AnchorIndex, Index);   // 앵커~대상 연속 범위
}
```

CarPos JSON의 차량 배열은 **프리셋 단위로 연속 저장**되어 있다.
(예: `presetId=1` 차량이 index 0~3, `presetId=2` 차량이 index 4~10)

따라서 사용자가 한 프리셋 안에서 Shift+클릭을 반복하면 선택 결과가 항상 그 프리셋의 연속 구간에 갇히고,
**"주차면이 4개인 프리셋은 4개까지만 선택된다"** 는 증상으로 나타났다.
서로 떨어진 차량(다른 프리셋 소속)만 골라 담는 것은 구조적으로 불가능했다.

> 참고: 선택 개수를 제한하는 상수나 클램프는 코드 어디에도 없었다. 순수하게 "연속 범위" 알고리즘의 결과였다.

## 3. 변경 내용

### 3.1 `UCarPlacementLibrary` — 선택 계산 함수 교체

**제거**: `BuildShiftSelection(ItemCount, AnchorIndex, TargetIndex)` — 연속 범위 생성
**신규**: `ToggleSelection(Current, ItemCount, Index)` — 개별 토글

```cpp
// CarPlacementLibrary.h
/**
 * Shift 토글 다중 선택. Current 에 Index 가 있으면 제거, 없으면 추가한다.
 * 프리셋·리스트 연속성과 무관하게 임의의 차량을 골라 담을 수 있다.
 * 결과는 항상 오름차순이며 [0, ItemCount-1] 범위 밖 인덱스는 모두 걸러낸다.
 */
UFUNCTION(BlueprintCallable, BlueprintPure, Category = "Car|Selection")
static TArray<int32> ToggleSelection(const TArray<int32>& Current, int32 ItemCount, int32 Index);
```

```cpp
// CarPlacementLibrary.cpp
TArray<int32> UCarPlacementLibrary::ToggleSelection(const TArray<int32>& Current, int32 ItemCount, int32 Index)
{
    // 유효 범위 밖 항목은 결과에서 제외한다(데이터 삭제 후 남은 인덱스 정리 겸용).
    TArray<int32> Out = Current.FilterByPredicate([ItemCount](int32 Value)
    {
        return FMath::IsWithinInclusive(Value, 0, ItemCount - 1);
    });

    if (FMath::IsWithinInclusive(Index, 0, ItemCount - 1) && Out.Remove(Index) == 0)
    {
        Out.Add(Index);
    }
    Out.Sort();
    return Out;
}
```

### 3.2 `UCarPlacementWidget::SelectCarWithModifiers` — 토글 반영

```cpp
if (bShiftDown)
{
    // 프리셋/리스트 연속성과 무관하게 클릭한 차량만 추가·해제한다.
    SelectedIndices = UCarPlacementLibrary::ToggleSelection(SelectedIndices, CarData.datas.Num(), Index);
    // 방금 클릭한 항목이 남아 있으면 그것이, 해제됐으면 남은 마지막 항목이 상세 표시 기준.
    PrimaryIndex = SelectedIndices.Contains(Index)
        ? Index
        : (SelectedIndices.Num() > 0 ? SelectedIndices.Last() : INDEX_NONE);
}
else
{
    SelectedIndices.Reset();
    SelectedIndices.Add(Index);
    PrimaryIndex = Index;
}

if (CarData.datas.IsValidIndex(PrimaryIndex))
{
    FillDetailFields(CarData.datas[PrimaryIndex]);
}
SyncSelectionVisuals();
```

### 3.3 `AnchorIndex` 상태 제거

토글 방식에는 앵커 개념이 없으므로 `CarPlacementWidget.h`의 `AnchorIndex` UPROPERTY와
`AutoCreate` / `AddCarAtWorld` / `DeleteSelected` / `InitAll` / `LoadFromJsonFile` 의 대입 5곳을 제거했다.
(`Park3D/Content` 전체 `.uasset` 검색 결과 Blueprint 참조 0건 확인 후 제거)

### 3.4 리스트 뷰

**코드 변경 없음.** 리스트 항목 클릭은 이미 월드 클릭과 같은 함수로 수렴한다.

```
[월드 좌클릭]  NativeTick ──────────────────────────┐
                                                    ├─→ SelectCarWithModifiers(Index, bShift)
[리스트 클릭]  UCarListItemWidget::HandleClicked ──┘
               → OnClicked(Index, bShiftDown)
               → HandleListItemClicked
```

따라서 §3.2 수정 하나로 **월드 뷰와 리스트 뷰가 동일하게 토글 다중 선택**을 지원한다.

### 이번 범위에서 제외한 것

`Check_PresetGroup`(프리셋 그룹) 체크박스는 **선택**이 아니라 **이동/회전 대상 확장** 기능이다.
체크 시 선택 차량들과 같은 `presetId` 전원이 이동/회전 대상이 된다. 사용자 확인 결과 이번 요구사항과 무관하여 그대로 두었다.
다중 선택 후 이 체크박스를 켜면 확장 대상도 그만큼 넓어진다.

## 7. 알려진 동작

- 선택된 차량 전부를 Shift+클릭으로 해제하면 `PrimaryIndex`가 `INDEX_NONE`이 되고 상세 필드는 마지막 값이 남는다(기존 `DeleteSelected` 관례와 동일).
- Shift+방향키는 여전히 "월드축 이동"이다. Shift+마우스 클릭(선택)과 입력 종류가 달라 충돌하지 않는다.
