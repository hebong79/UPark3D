# 차량 "선택 표시" 체크박스 + 저장 대화상자 파일명 유지

- 작성: 2026-08-18 13:49
- 요청 ① 차량을 선택하면 나오는 표시의 출력 여부를 체크박스로(기능 포함)
- 요청 ② 열기할 때 쓴 파일 이름을 저장할 때 그대로 쓰게

## 1. 선택 표시 On/Off

### 무엇이 표시였나

`ACarActor::SetSelected` 가 메시에 오버레이 머티리얼(`/Game/UI/M_CarSelect`, 반투명 청록 림 발광)을
덧입히고 `SetRenderCustomDepth` 를 켠다. 도색(carpaint)과 겹치지 않게 오버레이로 얹는 방식이다.

### 설계 — 선택 상태와 표시를 분리한다

**표시를 끈다고 선택을 풀면 안 된다.** 표시가 꺼져 있어도 이동·회전·수정·삭제 대상은 그대로
선택된 차량이어야 하기 때문이다. 그래서 `bSelected` 는 건드리지 않고 화면만 가른다.

```cpp
// ACarActor
void ACarActor::ApplySelectionVisual()
{
    const bool bShowMark = bSelected && bSelectionMarkVisible;   // 둘 다 참일 때만 오버레이
    MeshComp->SetOverlayMaterial(bShowMark ? SelectionOverlayMaterial : nullptr);
    MeshComp->SetRenderCustomDepth(bShowMark);
}
```

`IsSelected()` 가 그대로 진실을 말하므로 그것을 보는 쪽(`CarPlacementManagerTest`, RPC)은
표시 설정과 무관하게 동작한다 — 게이트를 `bSelected` 쪽에 걸었다면 테스트가 깨졌을 것이다.

권위는 매니저에 둔다(`차량 숨기기`/`리셋랜덤` 선례 — 동작은 매니저가 소유하고 체크박스는 그것만 부른다).
**설정을 밀어 넣는 자리는 `SetSelectedIndices` 하나다.** 모든 차량의 선택 표시가 이 함수를 지나므로,
배치 중 새로 스폰된 차량도 별도 처리 없이 현재 설정을 받는다.

```cpp
void ACarPlacementManager::SetSelectedIndices(const TArray<int32>& Sel)
{
    for (int32 i = 0; i < Cars.Num(); ++i)
    {
        Cars[i]->SetSelectionMarkVisible(bSelectionMarkVisible);
        Cars[i]->SetSelected(Sel.Contains(i));
    }
}
```

### UI — WBP 를 건드리지 않고 체크박스를 넣는다

`InjectHideCarsRow` 와 같은 방식으로 C++ 위젯 트리에 한 줄(`[체크박스] 선택 표시`)을 만들어
차량 숨기기 줄 바로 다음에 끼운다. 스타일은 기존 체크박스(`Check_Vertical`)와 라벨(`Lbl_Vertical`)에서
복사한다. 삽입은 `NativeOnInitialized`(위젯 인스턴스당 1회)에서 한다 — `NativeConstruct` 는
패널을 다시 열 때마다 돌아 중복 삽입이 된다.

**함정: 이 체크박스만 `UPROPERTY(BindWidget)` 이 아니다.**
쿠킹된 WBP 의 C++ 베이스에 `UPROPERTY` 를 추가하면 패키지가 `Bad export index` 로 즉사하고,
**exe 교체로는 반영되지 않아 콘텐츠 재쿡(직전 기록 58분)이 필요해진다**(2026-08-12 기록).
함수 추가는 안전하다. 그래서 포인터는 `TWeakObjectPtr<UCheckBox> Check_SelMark`(비-UPROPERTY)로 들고,
위젯은 이름으로 만든다 — 위젯 자체는 `WidgetTree` 가 참조하므로 GC 로 사라지지 않고,
`WidgetTree->FindWidget<UCheckBox>(TEXT("Check_SelMark"))` 로 먼저 찾으므로 나중에 디자이너가
같은 이름으로 만들어 넣으면 그것이 집힌다(`BindWidgetOptional` 과 같은 효과).

체크 상태는 위젯에 저장하지 않고 **패널을 열 때마다 매니저에서 읽는다**(`IsSelectionMarkVisible`).
위젯에 들고 있으면 다른 경로로 바꾼 뒤 패널을 열었을 때 화면과 어긋난다(차량 숨기기 선례).

## 2. 저장 대화상자가 열었던 파일명을 그대로 쓴다

네 패널(카메라 프리셋·주차 프리셋·차량 배치·조명 설정) 모두 저장 대화상자의 기본값이
**고정 기본명**이었다 — `CamPos_SNum.json`, `preset.json`, `CarPos_SNum.json`, `LightSettings.json`.
열어서 고친 파일을 저장하려면 매번 목록에서 다시 골라야 했다.

각 위젯에 `FString CurFilePath`(마지막으로 열거나 저장한 **전체 경로**)를 두고, 성공한 열기·저장
지점에서 채운 뒤 저장 대화상자의 기본값으로 쓴다.

```cpp
const FString BasePath = CurFilePath.IsEmpty() ? GetDefault...FilePath() : CurFilePath;
const FString DefaultDir  = FPaths::GetPath(BasePath);
const FString DefaultFile = FPaths::GetCleanFilename(BasePath);
```

- **파일명만이 아니라 폴더까지 기억한다.** 카메라·차량 패널에는 이미 `CurFileName`(파일명만)이
  있지만 그것만으로는 `Save/` 밖에서 연 파일이 엉뚱한 폴더에 저장된다.
- 아직 한 번도 열거나 저장하지 않았을 때만 기존 고정 기본명으로 떨어진다 — 기존 동작이 사라지지 않는다.
- 열기 대화상자는 손대지 않았다(요청 범위 밖).

차량 배치 패널은 시작할 때 `config` 의 `carpos_file` 을 로드하므로, 기동 직후에도 저장 대화상자에
`CarPos_Seoshin_2Cam.json` 이 이미 채워져 있다.

## 3. 검증

- 빌드: `Build.bat Park3D Win64 Development` — 두 번 모두 `Result: Succeeded`.
- 패키지(`Package/Windows`)에 exe 만 교체하고 재기동 — `Bad export index` 없이 정상 기동.
  패널 구성 경고(`VBox_Root 를 찾지 못해…`) 없음.
- 사용자가 "선택 표시" 체크박스 동작을 화면에서 확인("정상동작").
- **저장 대화상자 기본값은 런타임에서 직접 확인하지 않았다** — 파일 대화상자를 띄우려면
  좌표 클릭이 필요한데, 이 세션에서 좌표 클릭이 실행 중 인스턴스를 끄는 사고를 냈다(§4).
  열기 → 저장 순으로 눌러 보면 바로 드러난다.

## 4. 사고 기록 — 좌표 클릭으로 남의 인스턴스를 껐다

패널을 열려고 독 아이콘(차량, 창 좌표 585,772)을 `SendInput` 으로 클릭했는데, 직후 로그가
`LogExit: Preparing to exit` 로 **정상 종료**를 찍었다(크래시 아님). 캡처로 좌표를 확인하고
`SetForegroundWindow` 로 최상단을 보장한 뒤 클릭했는데도 그랬다.

CLAUDE.md 에 이미 같은 경고가 있다("좌표 클릭은 창 크기·최상단 여부를 검사하지 않으면 남의 창이나
`종료` 를 누른다 — 실제로 눌러 인스턴스가 꺼졌다"). **사용자가 쓰고 있는 인스턴스에는 좌표 클릭
자동화를 하지 않는다.** 확인이 필요하면 패키지를 복제해 다른 포트로 띄우거나, 사용자에게 부탁한다.
