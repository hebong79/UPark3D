# RPC `/help` 엔드포인트 — 보드 #1156

## 1. 요청

보드 #1156(SettingManager 세션): 시뮬레이터 `GET /help` 를 SettingManager(`http://192.168.0.221:13090/help`)와 같은 모양으로.
지금은 `/help` 가 404 이고 `system.catalog` 는 이름 215개뿐이라 클라이언트(simCatalog.ts·TourAgent·AI 채팅)가 파라미터·실패 메서드를
각자 손으로 적어 두고 있었다.

요청 항목과 대응:

| # | 요청 | 결과 |
|---|---|---|
| 1 | `GET /help` markdown(영어, 짧게, 엔드포인트·오류 코드·"이 인스턴스 지금") | 구현 |
| 2 | `GET /help?format=json` 기계 색인 — method·title·params[{name,type,required,default,unit}]·returns·mutating·movesCamera·destructive·implemented·notes·example. **system.catalog 와 같은 레지스트리에서** | 구현. method 목록·mutating 은 레지스트리, 설명은 표 |
| 3 | `GET /help/rpc/<method>` — 그대로 도는 curl(실제 값) | 구현. `<carNameId>` 등 자리표시자를 요청 때 실제 값으로 채운다 |
| 4 | 등록됐지만 실패하는 메서드 `implemented:false + reason` | `random.placeInView` 1개(-32004). 2026-08-07 목록의 10개 중 9개는 08-11 에 이미 결선됨 |
| 5 | 단위·축 한 번에 | `GET /help/units` |
| 선택 | `system.catalog` 가 같은 객체를 | `system.catalog {detail:true}`(인자 없으면 기존 이름 목록 그대로) |

OmiPark3D(13700)는 이 저장소가 아니라 범위 밖이다.

## 2. 구조

```
GET /help ──────────────┐
GET /help?format=json   │   URpcServerSubsystem::HandleHelp  (라우트 "/help" 하나 — 엔진 라우터가 경로를 뒤에서부터
GET /help/rpc[?group,q] ├─▶   잘라 가며 찾으므로 /help/rpc/<m>·/help/units 도 여기로 온다)
GET /help/rpc/<method>  │        │ BuildHelpContext(Host 헤더) — 레벨·포트·대수·자리표시자 실제 값
GET /help/units ────────┘        ▼
RPC system.help {method?}   Park3DRpcHelp (RpcHelp.cpp)
RPC system.catalog {detail} ── method 목록·mutating ← URpcDispatcher(레지스트리)
                               설명·params·예시   ← RpcHelpTable.cpp (216줄)
```

- **표와 레지스트리가 어긋나면 테스트가 실패한다** — `Park3D.Rpc.Help.TableMatchesRegistry`(Tests/RpcHelpTest.cpp)가 모듈 17개를 등록한
  디스패처로 ① 표에 없는 method ② 등록 안 된 표 줄 ③ JSON 파싱·중복을 본다. **새 method 를 등록하면 `RpcHelpTable.cpp` 에 한 줄 넣을 것.**
  런타임에도 표에 없는 method 는 `documented:false`·`undocumented[]` 로 드러난다(빠졌다고 숨지 않는다).
- `mutating` 은 표에 두지 않고 `URpcDispatcher::IsMutating` 을 그대로 낸다 — requestId 중복 제거·revision 이 따르는 값과 같아야 한다.
  `destructive` 는 표 OR 기존 `SetMethodMeta`. 기존 한국어 `SetMethodMeta` 설명은 `docKo` 로 함께 낸다.
- 예시 자리표시자: `<carNameId>`(보이는 첫 차), `<camId>`(1), `<presetId>`(매니저 첫 프리셋), `<faceKey>`(`preset.numbers` 첫 면),
  `<levelName>`. 못 채운 것(`<runId>`, 프리셋 0개 레벨의 `<presetId>`)은 `fill[]` 에 남는다.
  **매니저를 스폰하지 않는다** — 액터를 직접 세고, `preset.numbers` 는 프리셋 매니저가 있을 때만 부른다.
- curl 은 비ASCII 를 `\uXXXX` 로 낸다(Windows 셸에서 한글 인자가 깨지는 문제 — 09-22 변경 이력의 함정).
- 인증은 걸지 않았다(문서다, `park3d-no-security`). 토큰 모드면 curl 에 `X-Park3D-Token: <token>` 이 붙는다.
- `version` = `park3d-help/1 · exe <실행 파일 수정 시각 UTC> · <method 수>`. 엔진 `FApp::GetBuildDate()` 는 엔진 빌드 날짜라 쓰지 않았다.

## 3. 표 작성

215개 핸들러를 모듈별로 서브에이전트 5개가 **코드만 읽어**(RPC 호출 없음) JSON 으로 뽑고, 일회성 스크립트로 `RpcHelpTable.cpp` 를 만들었다.
이후로는 `.cpp` 가 원본이다(생성기를 저장소에 두지 않았다 — 한 단계가 늘면 빠뜨린다).

## 4. 레지스트리 수정 — mutating 오판 7건

표 작성 중 에이전트 판단과 `IsMutating` 이 11건 달랐다. 핸들러를 직접 확인해 **계산만 하고 돌려주는** 7건을 조회로 고쳤다
(`RpcDispatcher.cpp` ReadActions 에 `angles·renumber·camXZ·pickCount·entrance·random·bake`):
`measure.angles`, `preset.renumber`, `random.camXZ`, `random.pickCount`, `sim.entrance`, `plate.random`, `plate.bake`.
→ 이제 이 호출들은 revision·frameId 를 올리지 않는다.

그대로 둔 4건: `cam.marks`(조회지만 폴대·표식을 다시 맞춘다 — 09-28 결정), `preset.importFile`(파일만 쓰고 장면 불변),
`env.reloadAssets`(에셋 캐시 재스캔·프롭 정리), `random.placeInView`(미구현).

## 5. 단위 조사에서 드러난 사실

- **CLAUDE.md 의 축 규약 문구와 코드가 다르다.** 규약은 "Unity `(x, y_up, z)` → UE `(x, z, y_up)`" 인데 코드
  (`UnityUnrealCoordinateConverter.cpp:5-8`)는 **UE = (Unity.z, Unity.x, Unity.y)** — 지면 두 축이 바뀐다. `/help/units` 는 코드를 따랐다.
  규약 문구 수정 여부는 마스터 판단(이번에 손대지 않음).
- PTZ `tilt` 양수 = 아래, `view.*` `pitch` 양수 = 위(반대 부호). zoom 은 배율 1..36, raw 단위 없음.
- `env.list`/`env.hide` 만 cm, 나머지는 m.
- 저장 파일은 `isUnreal:true` 면 UE m, 없으면 Unity Y-up 으로 읽어 변환한다. 저장은 항상 `true`.

## 6. 에이전트가 찾은 버그(이번에 고치지 않음 — 각 method 의 notes 에 적어 둠)

- `RequirePosXZ` 계열(`car.create/setPosition/update/createLine`, `cam.setPosition/setPreset`, `preset.create`, `bay.create`, `env.create`,
  `measure.setTargetPoint`)이 **x·z 필수, y 생략 시 0** — UE 에선 높이가 필수고 지면 y 가 조용히 0 이 된다.
- `car.createLine {vertical}` 무효, `car.delete`·`car.resetColor` 없는 id 에도 ok, `scenario.delete` 이름 생략 시 `scenario.json` 삭제,
  `random.frontBack` 이 `slotIndex` 무시, `measure.targetLine` 이 `camId` 무시, `light.*` 가 `requestId` 도 -32602 로 거절,
  `map.get` 이 바닥이 없으면 바닥을 만든다, `car.createMany/setAll` 부분 실패 시 되돌리지 않음.
