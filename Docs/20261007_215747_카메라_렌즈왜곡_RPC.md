# 카메라별 렌즈 방사 왜곡 RPC `cam.setDistortion` / `cam.getDistortion` (보드 #1297)

- 브랜치: `feat/cam-distortion-1297`
- 요청: 보드 #1297 (SettingManager, `claude/cam-plan-under-idis`). 이 요청은 실제 지하 설치(IDIS DC-S6261XT PTZ, 천장 2~2.5 m)를 시뮬에서 재현하려는 것이다. 중심 화각은 SettingManager 가 줌 환산으로 이미 맞추고 있어서, 빠진 것은 렌즈가 **휘는 것**뿐이었다.
- 계약: OmiPark3D(`feat/cam-distortion`)와 같다.

## 1. 계약

| method | params | 응답 |
|---|---|---|
| `cam.setDistortion` | `camId`(필수), `k1`(필수), `k2`(생략 = 0) | `{camId, k1, k2}` |
| `cam.getDistortion` | `camId` | `{camId, k1, k2}` |

- 모델은 OpenCV 핀홀 방사 왜곡이다(탄젠트 좌표).
  - `x = X/Z`, `y = Y/Z`, `r² = x² + y²`
  - `x_d = x·(1 + k1 r² + k2 r⁴)`, y 도 같다.
  - `u = f·x_d + cx`, `f = (W/2)/tan(hfov/2)` — hfov 는 **현재 줌이 반영된** 수평 화각이다.
  - k 는 줌과 무관하다. 줌을 당기면 화면 안의 r 이 줄어 휨이 저절로 약해진다.
- 다음 경우는 `-32602`(`data.kind = bad_params`)로 거절한다.
  - `|k| > 1`
  - zoom 1(그 카메라의 `DefaultHFov`, 렌더타깃 비율 기준)의 화면 모서리에 닿기 전에 그림이 접히는 k. 판정식은 `1 + 3k1 r² + 5k2 r⁴ ≤ 0` 이다.
  - 사유 문장에 접히는 반경을 적는다.
- `k1 = k2 = 0` 이 핀홀이고, 기존 렌더 경로를 그대로 쓴다(추가 비용 0).
- 이 값은 **저장하지 않는다**. 카메라를 새로 만들면(`cam.create`·`cam.loadPosFile`·`cam.resetCameras` 등) 0 으로 돌아간다.
  - SettingManager 는 cam.create/setPosition/setHeight/setPTZ 뒤에 k ≠ 0 일 때만 다시 보낸다(요청서). 그 흐름과 맞는다.
- mutating 여부는 레지스트리 규칙(`get*` = 조회)을 따른다. `system.describe`·`/help` 에 둘 다 나온다.

## 2. 구현

### 2.1 모델 — `Source/Park3D/CamLensDistortion.{h,cpp}`(신규, `CamLens` 네임스페이스)

- `DistortRadius`/`DistortSlope`/`MonotonicLimit`/`Validate`/`CornerTan`/`UndistortRadius`/`DistortTan`/`UndistortTan`
- 역변환은 단조 구간(`DistortSlope > 0`) 안에서 이분법으로 푼다.
  - 기울기의 근을 식으로 푸는 대신 훑기 + 이분법을 썼다. k2=0·허근·두 근으로 경우를 나눌 필요가 없다.
- `cam.setFOV` 로 화각을 넓혀 모서리가 접힘 영역에 들면 단조 구간 끝에서 자른다(가장자리가 늘어난다). 이 경우 검사는 하지 않는다.

### 2.2 렌더 — `APTZCameraActor::CaptureInto`

PTZ 캡처는 전부 `CaptureOnce`(뷰어·MJPEG·`cam.captureJPG/PNG` 같은 크기·scenario)와 `CaptureAtSize`(다른 크기 `cam.captureJPG`)를 지난다. 두 함수가 이제 `CaptureInto(타깃)` 를 부르고, 왜곡이 켜져 있으면 다음 순서로 그린다.

1. 출력 타깃을 48×27 격자로 나눈다. 각 꼭짓점을 왜곡 후 탄젠트 좌표로 보고 역변환해서, 그 픽셀이 보는 방향을 얻는다.
2. 그 방향을 모두 담는 반각 탄젠트 `TW`(1% 여유, 85° 상한)를 정한다. 그 화각으로 **중간 타깃 `WideCaptureTarget`** 에 찍는다.
   - 중간 타깃 크기 = 출력 × `TW/tan(hfov/2)`(상한 4096)이다. 그래서 중심의 픽셀 배율이 핀홀과 같다.
   - `Capture->FOVAngle` 은 `CaptureScene` 직후 원래 값으로 되돌린다. `GetZoom`·화면 투영은 원래 화각을 본다(`TextureTarget` 을 바꿨다 되돌리는 기존 규약과 같다).
3. `FCanvasTriangleItem`(Opaque)으로 격자 삼각형을 출력 타깃에 그린다. 각 꼭짓점의 UV 는 그 방향이다.
   - 머티리얼 에셋이 필요 없다. `Content/` 는 git 밖이고 에디터 MCP 도 미연결이라 이 방식을 골랐다.
4. 최종 타깃에 왜곡된 그림이 들어간다. 그래서 뷰어·스트림·캡처가 모두 같은 그림을 본다.

**함정 2개**
- `FCanvasUVTri` 의 꼭짓점 색 기본값은 `(0,0,0,0)` 이다. 이 색이 텍스처에 곱해지므로, 흰색을 넣지 않으면 그림이 **통째로 검다**. 첫 실기 확인에서 평균 밝기 0.0 이 나왔다.
- 캔버스는 타깃의 표시 감마(기본 2.2)로 한 번 더 인코딩한다(`BatchedElements` 의 `GammaMain`). sRGB 타깃은 하드웨어가 인코딩하므로, 출력 타깃의 `TargetGamma = 1` 로 둔다.
  - `TargetGamma` 는 캔버스 그리기에만 쓰인다. SceneCapture 경로는 이 값을 보지 않는다.

### 2.3 3D ↔ 픽셀

- `scenario.shoot` 의 `slotPolygon`(`ScenarioRpcModule`)이 슬롯 모서리 4점을 화면에 투영할 때 같은 `DistortTan` 을 쓴다.
  - 단, 모서리 4점만 휘게 하고 변은 직선으로 잇는다. 휜 변까지 따라가지는 않는다.
- `cam.aimSlot` 은 면 중심을 화면 중심에 두는 계산이다. 왜곡이 중심을 바꾸지 않으므로 고치지 않았다.
- `view.pick` 은 메인 뷰라 대상이 아니다.

## 3. 검증

- 빌드: 게임·에디터 타깃 둘 다 Succeeded(Sonnet 서브에이전트가 실행). 흰색 수정 뒤 게임 타깃을 다시 빌드했다.
- Automation **161/161**(`Park3D` 전체). 신규 `Park3D.CameraControl.LensDistortion`(모서리 탄젠트, 허용/거절 경계, 단조 구간 끝, 왕복, 중심 불변)과 `Park3D.Rpc.Help.TableMatchesRegistry` 가 포함된다.
  - 이 테스트는 흰색 수정 **전** 소스로 돌렸다. 수정은 렌더 코드 한 곳이라 테스트 대상이 아니다.
- 실기: 작업본 `Package/Work13540`(13540, 정본 무관), 카메라 1(pan 180, tilt 27, zoom 1). 스크립트는 `_workspace/distortion_check.py`·`distortion_stream_check.py` 이다.
  - `cam.getDistortion` 초기값 0,0. `k1=-0.5` → -32602 `folds the image at r=0.8165 … reaches only 0.5443`, `k2=1.5` → -32602.
  - `k1=-0.3` → `{camId:1,k1:-0.3,k2:0}`, `cam.getDistortion` 이 같은 값을 돌려준다. `cam.getPTZ` 줌 1 불변.
  - 1280×720 캡처의 픽셀 차 평균(흑백):

    | 비교 | 중심 40×40 | 왼쪽 1/8 띠 |
    |---|---|---|
    | k0 vs k0(잡음) | 1.94 | 1.10 |
    | k0 vs k1=-0.3 | 3.44 | **15.70** |

    중심 픽셀은 (202,199,190) → (205,202,193), 평균 밝기는 114.3 → 116.9 였다. 중심은 잡음 수준이고 가장자리만 바뀌었다.
  - 화면으로도 확인했다(`Docs/shots/20261007_cam_distortion/dist_k0.jpg`·`dist_k1m03.jpg`). 오른쪽 위 창틀 직선이 안쪽으로 휘고, 모서리에 원래 화각 밖의 물체(왼쪽 아래 벽돌, 오른쪽 아래 분홍 간판)가 들어온다. 검은 테두리는 없다.
  - 1920×1080 `cam.captureJPG {width,height}` 도 같은 경로로 찍힌다(`dist_k1m03_1080.jpg`).
  - MJPEG `13961/stream` 프레임: k0 캡처와의 가장자리 차는 15.56, k1=-0.3 캡처와의 차는 **1.61** 이다. 스트림도 왜곡 그림이다.

## 4. 미검증·한계

- **비용 미측정**: 왜곡이 켜진 카메라는 k1=-0.3·56.5° 기준으로 약 1.3배 큰 타깃(약 1.7배 픽셀)을 렌더한다. 스트림 fps 영향은 재지 않았다(작업본이 정본과 GPU 를 공유한다).
- 화면 안 뷰어 위젯 캡처, 패키지 빌드(새 .cpp 2개 — 유니티 빌드 충돌 확인용), 정본 배포는 하지 않았다.
- TSR·Lumen 히스토리: 왜곡을 켜고 끄면 캡처 타깃 크기가 바뀌므로 그 순간 히스토리가 한 번 리셋될 수 있다(크기가 다른 `CaptureAtSize` 와 같은 성질).
- k 는 패널 UI·카메라 파일에 없다(요청 범위 밖).
