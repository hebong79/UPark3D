# 마우스 휠 줌 + Left Alt + 방향키 화면기준 이동

- 작성: 2026-08-12 18:04:49
- 대상: `Park3D/Source/Park3D/ParkFlyPawn.{h,cpp}`, `CarPlacementWidget.cpp`, `PresetMakerWidget.cpp`
- 빌드: `Build.bat Park3D Win64 Development` → **Succeeded** (컴파일·링크 통과)

## 1. 요구사항

1. 마우스 스크롤로 줌인/줌아웃.
2. **Left Alt + 방향키**를 누르면 화면에 보이는 그대로 좌우·상하 이동.
   - 최초 요청은 Ctrl 이었으나 대화 중 Left Alt 로 변경됨.

## 2. 변경 요약

### 2.1 `AParkFlyPawn` — 줌

- `SetupPlayerInputComponent` 에 `EKeys::MouseScrollUp` / `MouseScrollDown` 을 `IE_Pressed` 로 바인딩.
  휠은 축이 아니라 한 칸마다 Pressed 로 들어오므로 이 방식이면 한 칸 = 한 번 호출이 된다.
- `ZoomAlongView(Amount)` 이 시선 방향(`GetViewRotation().Vector()`)으로 `AddActorWorldOffset` 한다.
  기본 `ZoomStep = 300.0f` (cm, 3m/칸).
- **MovementComponent 를 거치지 않는다.** 가속·감속이 붙으면 휠 한 칸의 이동량이 프레임마다 달라져
  예측이 안 된다. 줌은 "한 칸에 정확히 N cm" 가 맞다.
- RMB 게이트와 무관하게 항상 동작한다(요구사항: "스크롤만 하면 된다").

### 2.2 `AParkFlyPawn` — Left Alt + 방향키 패닝

- `PrimaryActorTick` 을 켜고 `Tick()` 에서 방향키를 폴링한다(누르고 있는 동안 연속 이동).
- 이동 축은 **월드축이 아니라 시점 축**이다.
  - 좌/우 → `FRotationMatrix(GetViewRotation()).GetScaledAxis(EAxis::Y)` (화면 오른쪽)
  - 상/하 → 같은 행렬의 `EAxis::Z` (화면 위쪽)
  - 시점을 아래로 내려다보는 상태에서 "위" 키는 화면 위쪽 = 지면에서 멀어지는 방향으로 간다.
    이것이 "화면상에 보이는 그대로" 의 정의다. 월드 +X/+Y 로 가는 기존 차량 이동과 다르다.
- 기본 `PanSpeed = 1500.0f` (cm/s, 15m/s). 둘 다 `UPROPERTY(EditAnywhere)` 로 노출.

### 2.3 방향키 중복 동작 차단 (3곳)

방향키는 이미 세 군데가 쓰고 있어, 아무 처리 없이 패닝을 붙이면 한 번 눌러 두 가지가 동시에 움직인다.

| 위치 | 기존 동작 | 처리 |
|------|----------|------|
| `ADefaultPawn` 축 `DefaultPawn_MoveForward` (Up/Down 방향키) | RMB 보유 시 전/후진 | `AParkFlyPawn::AddMovementInput` 이 Left Alt 보유 중이면 **전부 무시** |
| `UCarPlacementWidget::NativeTick` | 배치 모드에서 선택 차량 이동 | Left Alt 보유 중이면 이동 블록 진입 안 함(기존 RMB 양보와 같은 자리) |
| `UPresetMakerWidget::NativeOnKeyDown` | 오프셋 제어 모드에서 프리셋 이동/회전 | Left Alt 눌린 키 이벤트는 소비하지 않고 `Super` 로 넘겨 폰에 양보 |

### 2.4 Alt 감지 이중화

코드베이스에 이미 `Alt 는 에디터 PIE가 가로채 게임 입력에 안 잡힘` 이라는 기록이 있다
(`CarPlacementWidget.cpp` 의 Shift 사용 사유 주석).
그래서 Alt 판정을 한 경로에만 의존하지 않는다.

```cpp
bool AParkFlyPawn::IsLeftAltHeld() const
{
    const APlayerController* PC = Cast<APlayerController>(GetController());
    if (PC && PC->IsInputKeyDown(EKeys::LeftAlt)) return true;
    // PIE 등에서 Alt 가 게임 입력으로 안 들어오는 경우 대비.
    return FSlateApplication::IsInitialized()
        && FSlateApplication::Get().GetModifierKeys().IsLeftAltDown();
}
```

`FModifierKeysState::IsLeftAltDown()` 은 좌/우 Alt 를 구분하므로 요구대로 **Left Alt 만** 잡는다.
`CarPlacementWidget` 의 양보 판정도 같은 이중화를 쓴다(`Slate` 는 이미 모듈 의존에 있고
해당 파일은 `SlateApplication.h` 를 이미 포함하고 있었다).

## 3. 검증 상태

- **컴파일/링크**: `Build.bat Park3D Win64 Development` → `Result: Succeeded`.
  산출물 `Park3D/Binaries/Win64/Park3D.exe` 갱신됨.
- **실동작(휠 줌, Alt+방향키 이동)**: 미검증. 키·휠 입력은 사람이 직접 눌러야 확인된다.
  현재 13510 에서 도는 인스턴스는 이번 빌드 이전 산출물이므로, 확인하려면 새 빌드로 재기동해야 한다.
- PIE 에서 Alt 가 여전히 안 잡히면 Slate 폴백이 받아주는지가 실측 대상이다.
  둘 다 실패하면 수정자 키를 Shift 로 바꾸는 것이 대안(기존 차량 이동이 이미 Shift 를 그 이유로 쓴다).

## 4. 튜닝 지점

| 값 | 기본 | 의미 |
|----|------|------|
| `ZoomStep` | 300 cm | 휠 한 칸 이동 거리. 주차장 규모(수십 m)에서 3m/칸 |
| `PanSpeed` | 1500 cm/s | Alt+방향키 이동 속도 |
