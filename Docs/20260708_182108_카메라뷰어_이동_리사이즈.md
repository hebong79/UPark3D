# 카메라 뷰어 이동 + 리사이즈(16:9) — 구현·검증 보고서

- 작성일: 2026-07-08
- 실행: `parking-cpp-loop` (C++ 전용, 컴파일만 수동 게이트)
- 결과: **3회차 반복 끝에 성공** (검증 실패 → 재분석·재설계 루프 2회)
- 대상: `CameraViewerWidget.h/.cpp` (UCameraViewerWidget)

## 1. 요구사항
- 렌더타겟 카메라뷰(우하단 뷰어)의 크기 조절 + 이동 가능.
- (R1) 드래그 시 앱 화면제어(카메라 회전 등) 영향 없음.
- (R2) 리사이즈 시 16:9 유지.
- 조작(확정): 본체 드래그=이동, 변/코너 드래그=리사이즈. 코너/변에 리사이즈 커서 표시.

## 2. 반복 기록 (Loop)
| 회차 | 증상 | 원인 | 조치 |
|------|------|------|------|
| 1 | 아무데나 드래그하면 뷰어 이동, 리사이즈 안 됨 | 뷰어 WBP 루트가 **전체화면 캔버스**라 화면 전체가 히트테스트 | 루트=SelfHitTestInvisible, 이미지만 Visible → 이미지에서만 드래그. 코너 판정을 이미지 기준으로 |
| 2 | 이동 정상, **리사이즈 무동작**(커서는 우하단만) | Img_View가 **CanvasPanelSlot**에 있어 `SetDesiredSizeOverride` 무시(캔버스는 슬롯 크기 사용) | 이동·리사이즈를 **캔버스 슬롯 SetPosition/SetSize**로 통일. 커서·리사이즈를 **전 변/코너**로 확장 |
| 3 | 모두 정상 | — | 완료 |

## 3. 최종 구현
### 헤더(멤버·오버라이드)
- `DefaultViewSize(400,225)`, `MinViewWidth/MaxViewWidth`, `ResizeCornerZone` (UPROPERTY).
- 오버라이드: `NativeConstruct`, `NativeOnMouseButtonDown/Move/Up`, `NativeOnCursorQuery`.
- 런타임 상태: `CurrentViewSize`, `DragStartLocal/Size/SlotPos`, `bEdgeL/R/T/B`, `bMoving/bResizing`.

### 핵심 로직
- `NativeConstruct`: 루트 `SelfHitTestInvisible` + 이미지 `Visible`(이미지에서만 입력 수신 → 3D 클릭 보존). `ApplyViewSize()`.
- `ApplyViewSize`: `UCanvasPanelSlot::SetSize(CurrentViewSize)`(없으면 `SetDesiredSizeOverride` 폴백).
- `ButtonDown`: 이미지 영역 안일 때만 시작. 변 근접(`ComputeViewerEdges`)이면 리사이즈, 아니면 이동. `CaptureMouse`+`Handled`(R1).
- `Move`: 이동=`CanvasSlot->SetPosition(start+delta)`; 리사이즈=잡은 변 기준 `DeltaW`로 폭 산출→`(W, W*9/16)`(R2)→`ApplyViewSize`.
- `CursorQuery`: 코너=Resize↘/↙, 변=↔/↕, 본체=이동(CardinalCross). 이미지 밖=Unhandled(통과).

## 4. 요구사항 충족
- ✅ 이동·리사이즈 동작. 리사이즈 커서 **전 변/코너**.
- ✅ (R1) 드래그 중 화면 회전 등 없음 — CaptureMouse+Handled로 입력 소비. 이미지 밖 클릭은 3D로 통과(캔버스 히트 제거).
- ✅ (R2) 리사이즈 항상 16:9(높이=폭×9/16).

## 5. 검증
- 실PIE 사용자 실조작: 본체 드래그 이동, 전 변/코너 커서 확인, 드래그 리사이즈 + 16:9 유지, 이미지 밖 드래그 시 화면 영향 없음 — **모두 정상 확인**.
- 컴파일: 3회 수동 게이트(헤더 변경 → PIE 정지 후) 모두 succeeded.

## 6. 영향도
- `UCameraViewerWidget`만 변경. 다른 위젯/매니저 무관.
