## 1. 증상과 최초 관측

사용자 화면에는 쿡 진행률이 `83/579 14%` 에서 고정돼 있었다. 프로세스는 살아 있었다.

| 커밋 차지 | **68.4GB / 69.5GB (98%)** |

| 로그 갱신 | 계속 갱신됨 (22:19:12 → 22:22:23 → 22:27:02) |

즉 **행(hang)이 아니라 진행이 매우 느린 상태**였다.

- 쿡 스레드가 차량 메시 **34개 배치의 완료를 기다리며 블로킹**돼 있었다. 배치가 끝나기 전에는 `Cooked packages` 카운터가 올라가지 않으므로 진행률이 굳어 보인다.
- 메시 1개당 요구 메모리가 **1.0~4.5GB**. 34개 동시 = 약 70GB 요구.
- 호스트 커밋 한도는 **69.5GB**(RAM 63.8GB + 페이지파일 4GB). 여유가 1GB 남짓이라 OOM 직전이었다.
- DDC 미스가 겹쳤다. 로그에 `FULL COOK: Incremental Cooks are disabled ... recooking all packages` 와 `Missing cached shadermap ...` 이 함께 찍혀 메시·셰이더를 처음부터 굽고 있었다.

핵심은 **진행률 숫자가 멈춰 있는 것과 실제 정지는 다르다**는 점이다. 판정은 CPU 델타·로그 갱신 시각·커밋 차지 세 가지로 했다.

## 3. 조치

사용자 지시로 22:27 에 빌드를 중지했다(UnrealEditor-Cmd, AutomationTool(dotnet), cmd 래퍼 2개 강제 종료). 커밋 차지 68GB → 18.9GB 로 회수.

이후 동시성 상한을 설정에 넣었다.

`Park3D/Config/DefaultEngine.ini`

```ini
[ConsoleVariables]
Editor.AsyncAssetCompilationMaxConcurrency=4
```

### cvar 유효성 확인

이름을 추측하지 않고 엔진 소스에서 확인했다.

- `Engine/Source/Runtime/Engine/Private/AsyncCompilationHelpers.cpp:366`
  `FString::Printf(TEXT("Editor.Async%sCompilation"), AssetType)` — `FAsyncCompilationStandardCVars(TEXT("Asset"), ...)` 가 `Editor.AsyncAssetCompilation*` 계열을 동적으로 등록한다. 그래서 소스를 `Editor.AsyncAsset...` 리터럴로 grep 하면 안 잡힌다.
- 같은 파일 `BindThreadPoolToCVar` 가 값을 `FQueuedThreadPoolWrapper::SetMaxConcurrency` 로 스레드풀에 직접 건다.
- 커맨드라인 대안도 있다: `-asyncassetcompilationmaxconcurrency=N` (`AsyncCompilationHelpers.cpp:306`).

### 채택하지 않은 대안

`AssetCompilingManager.cpp:67` 의 `Editor.AsyncAssetCompilationMaxMemoryUsage` (GB 하드 리밋, 기본 0 = 시스템 가용 메모리 기준 자동 튜닝). 이번 실패는 그 자동 튜닝이 이미 동작 중인데도 한계에 부딪힌 경우라, 예측 가능한 동시성 상한을 택했다. 노브는 하나만 넣었다.

페이지파일 확장(4GB → 32GB)도 후보였으나 호스트 설정 변경이라 적용하지 않았다.

## 5. 알아둘 것

- **메시 빌드 구간은 일회성이다.** 중단된 첫 실행에서 완료된 메시의 DDC 캐시가 살아남아, 재실행 때는 34개가 아니라 **15개만** 다시 빌드했다. 33개가 모두 캐시된 지금은 다음 빌드에서 이 벽을 건너뛴다.
- **꼬리 구간이 느리다.** 남은 메시 3개(`기아_봉고` 4.5GB, `기아_봉고_탑차` 3.75GB 등)를 처리할 때 CPU 가 11코어 → 1코어로 떨어졌다. Nanite 빌드의 일부 단계가 단일 스레드다. 쿡 카운터가 0/503 에서 44분간 정지한 것처럼 보인 구간이 이것이다.
- **동시성 4는 지금 하드웨어에 보수적이다.** 실측 피크가 43GB(여유 32GB)였으므로 8 정도로 올릴 여지가 있다. 다만 메시 DDC 가 이미 채워져 다음 빌드에서는 이 구간 자체가 없으므로, 값을 올릴 실익은 콘텐츠를 새로 추가할 때 생긴다.
- 롤백은 `[ConsoleVariables]` 두 줄을 지우면 된다(엔진 기본값 -1 = 무제한).

## 6. 진행이 멈춘 것처럼 보일 때 판정 절차

```
1. 로그 LastWriteTime  → 갱신되면 살아 있음 (진행률 숫자와 별개)
2. 프로세스 CPU 델타    → 30초 샘플. 0 에 가까우면 진짜 정지 의심
3. 커밋 차지 / 한도     → 95% 초과면 OOM 위험 구간
4. Memory\Pages Input/sec → 수백 이상이면 스래싱
5. 로그 tail            → "Waiting for ... to be ready N/M" 이면 배치 대기지 정지 아님
```
