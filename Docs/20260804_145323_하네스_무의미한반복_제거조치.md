# 하네스 무의미한 반복 제거 조치 (2026-08-04)

## 요청
"무의미한 반복이 없게 조치해줘."

## 설계 (구현 전 — CLAUDE.md 0번)

### 문제 정의
앞선 분석에서 특정한 중첩 반복 원인 4건 + 1건을 제거한다. 프롬프트/역할 정의 파일만 수정하며 Park3D 소스는 건드리지 않는다.

### 원인 → 조치 매핑

| # | 원인 | 증상 | 조치 |
|---|---|---|---|
| A | 구현 단계 내부 자기 재시도가 반복 카운트에 안 잡힘 | 3회 중단이 실제보다 훨씬 늦게 걸린다. 반복이 두 배가 아니라 **숨는다** | 내부 시도를 카운트에 합산 + `내부 시도: N회` 기록 의무화 |
| B | "1회 재시도"가 오케스트레이터·implementer·qa 3중 중첩 | 같은 실패에 실제 시도 2~3배 | **재시도 소유권**을 실행 주체 1곳으로 고정. 상위 역할은 재시도 금지 |
| C | qa-verifier 자체 반려 루프 ↔ cpp-loop의 architect 복귀가 이중 | 같은 수정이 두 경로로 중복 반복 | Goal/Loop 중 qa-verifier는 **판정만 반환**, 복귀는 `[7]` 단일 경로 |
| D | 확정 사실 참조 메모리 4건이 dangling | 세션이 바뀌면 "MCP로 컴파일 자동화" 같은 **불가능한 시도를 처음부터 재반복** | 메모리 4건 승격 + 스킬 링크 정정 |
| + | "동일 원인" 판정 기준 부재 | 원인 라벨을 새로 붙이면 카운터가 초기화됨 → 15회까지 진행 | 판정 기준 정의(대상 Requirement + 실패 증상 동일이면 동일 원인) |

### 대안 비교
- **대안 1 — 총 반복 상한(예: 8회) 신설**: 숫자가 자의적이고, 정당한 장기 루프까지 끊는다. 채택하지 않음.
- **대안 2 — 동일 원인 판정 기준을 조인다(채택)**: 15회 같은 사례는 "원인 라벨이 매번 달라서" 통과했다. 기준을 조이면 자연히 걸린다. 새 임계값을 만들지 않아 단순하다(CLAUDE.md 2번).

### 근거 데이터
저장소 루트 `_workspace/`의 완료된 루프 기록 26건 — `json_coordinate_flag` 15회, `camera_distance_goal_loop` 9회, `car_multiselect` 2회. 26개 중 14개가 "컴파일"을 언급(수동 게이트가 운용 축임). **각 파일이 내부 시도 횟수를 기록하지 않아 실제 시도 총량을 사후에 확인할 수 없었다** — 이것이 A의 직접 증거다.
