# [lightport] 주변 동작 사후점검 보고서

CLAUDE.md 5번 규칙. 변경 지점(조명 액터 6개 + `FLightSettings` 기본값 + 조명 프리셋)의
**인접 호출·UI/입력·저장/로드·렌더/액터 상태**를 기존 테스트·실행 로그·캡처와 교차 점검한다.

판정: 통과 / 실패 / **미검증**(확인하지 않은 것을 통과로 적지 않는다)

## 1. 인접 호출

| 항목 | 판정 | 근거 |
|---|---|---|
| `Park3DGameMode::BeginPlay` → `ApplySettings` 경로 | 통과 | 기동 로그 `[Light] 시작 조명 적용 — 저장된 기본값 파일 (노출 -1.02, 태양 5.0 lux, 고도 44.5°)` — 저장소·패키지 양쪽 |
| `ULightControlLibrary::LoadDefaultSettings` 포인터 해석 | 통과 | `_default.txt` = `Sangmyung.json` 이 실제로 로드됨(위 로그 수치가 프리셋과 일치) |
| `ClampSettings` 조용한 절단 | 통과 | EV -1.02 는 하한 -5 에서 멀다. 파일 기록값과 기동 로그 수치 일치 확인 |
| `ALightControlManager::FindSun/FindSky/FindExposureVolume` | 통과 | 셋 다 "찾지 못해 …건너뜁니다" 경고가 로그에 없음 |
| `CaptureCurrent` 기본값 폴백 경로 | 미검증 | 레벨에 액터가 모두 있어 폴백이 타지 않는다. 액터 없는 상황을 만들어 시험하지 않았다 |

## 2. UI / 입력

| 항목 | 판정 | 근거 |
|---|---|---|
| 메인 메뉴 렌더 (조명 설정 항목 포함) | 통과 | `shots/final_vp_1.png` 에 "조명 설정" 버튼 정상 표시 |
| Preset Maker 패널 렌더·값 표시 | 통과 | 〃 — 프리셋 목록 5건, Offset/BoxSize/데칼 두께 등 정상 |
| 조명 설정 패널을 열어 6항목 조절 | **미검증** | 패널을 실제로 열어 슬라이더/입력을 조작하지 않았다. 합성 클릭이 UMG OnClicked 를 쏘지 못하는 기존 제약 때문 |
| 조명 저장/열기 다이얼로그 | **미검증** | 파일 다이얼로그를 띄우지 않았다 |

## 3. 저장 / 로드

| 항목 | 판정 | 근거 |
|---|---|---|
| 기존 `Daylight.json` 보존 | 통과 | md5 `28a7d4c3…` — 백업본과 동일 |
| `FileRoundTrip` 테스트가 `_default.txt` 를 복원 | 통과 | 테스트 88개 실행 후에도 `_default.txt` = `Sangmyung.json` 유지 |
| 조명 JSON 스키마 호환 | 통과 | `Park3D.Light.JsonRoundTrip` / `BadJson` / `FileRoundTrip` 통과 |
| 프리셋·차량·카메라 저장 데이터 | 통과(무영향) | 조명 변경은 이들 파일을 건드리지 않는다. `Park3D.Rpc.PresetModule`/`CarModule`/`CamModule` 통과 |
| 맵 파일(`PresetMaker1.umap`) | 통과 | 백업과 바이너리 동일 — 의도치 않은 맵 저장 없음 |
| 대상 외 외부 액터 133개 | 통과 | 전부 백업과 동일 |

## 5. 실패 / 고위험

**없음.** 다만 사후 영향도 §5 에 적은 대로 뭉갬·클리핑 판정 기준 2건이 초과했고,
그 원인(태양 방위 261° 회전)은 노출로 상쇄 불가능한 종류다. 구현 결함이 아니라
**설계 판정 기준이 방위 변경을 전제하지 않았던 문제**이므로 구현/QA 로 되돌리지 않고 사용자 판단 사항으로 올린다.
