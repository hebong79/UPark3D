# 운영 단계를 Sonnet 5.5 에 위임하는 스킬

## 요청

마스터(2026-10-05): "스킬로 항상 담당을 sonnet5.5 로 할 수 있게 설정해 줘(커밋, 머지, 푸시, 재빌드, 재기동)."

## 방식

Claude Code 에는 "이 명령은 이 모델이 실행" 같은 설정이 없다. 그래서 다음처럼 구현했다.

- 메인 세션이 위 단계를 **직접 실행하지 않는다**.
- 대신 **Agent 도구로 Sonnet 서브에이전트를 띄워 맡긴다**.
  - 호출 값: `model: "sonnet"`, `subagent_type: "general-purpose"`, 포그라운드.
  - `sonnet` 별칭은 최신 Sonnet, 곧 Sonnet 5.5 를 가리킨다.

## 파일

| 파일 | 내용 |
|---|---|
| `.claude/skills/park3d-ops-sonnet/SKILL.md` | 메인 세션용. 발동 조건(커밋·머지·푸시·빌드·재기동·배포 요청), 승인 확인, 위임 호출법, prompt 틀, 실패 시 대신 실행 금지. |
| `.claude/skills/park3d-ops-sonnet/PROCEDURE.md` | Sonnet 서브에이전트용 실제 절차. 커밋(지정 파일만·Sonnet 서명), 빌드(`_workspace/build_target.cmd`), 머지(`--no-ff`·충돌 시 abort), 푸시(`origin main` 만), 정본 교체·재기동, 금지 사항, 보고 형식. |
| `CLAUDE.md` "운영 단계 담당" 절 | 스킬은 설명이 맞을 때만 발동한다. 그래서 매 세션 읽히는 지침에도 규칙을 적었다. |

## 정본 재기동 절차의 근거 (실측)

`Win32_Process` 로 현재 정본을 확인했다.

- 정본은 `Package\Windows\Park3D.exe`(부트스트랩)를 **인자 없이** 띄운 것이다.
- 그 결과 프로세스가 둘 뜬다. 부트스트랩, 그리고 본체 `Package\Windows\Park3D\Binaries\Win64\Park3D.exe Park3D` 다.
- 종료할 때는 경로가 `Package\Windows\` 인 것만 끈다. 작업본 `Package\Work13540` 은 건드리지 않는다.
- 백업 이름 규칙 `Park3D.exe.bak_yyyyMMdd[b,c…]` 는 기존 파일들에서 따왔다.

## 안전장치

- 머지·푸시·정본 교체·재기동은 `git-flow` 대로 **마스터 승인**이 있을 때만 한다.
  - 메인 세션이 prompt 에 `예/아니오` 로 적는다.
  - 서브에이전트는 `아니오` 단계를 실행하지 않는다.
- 서브에이전트가 하지 않는 것: 코드 수정, `--no-verify`, `--force`, `reset --hard`, `git add .`.
- 빌드가 Live Coding 때문에 거부되면 프로세스를 죽이지 않고 보고한다.
- 재쿡이 필요한 변경에서는 exe 교체를 멈추고 보고한다. 해당 변경은 쿠킹된 WBP 베이스의 `UPROPERTY` 추가, 셰이더 플러그인 추가다.
- 서브에이전트가 실패하면 메인 세션이 대신 실행하지 않는다. 마스터에게 묻는다.

## 한계

- 이 규칙은 **지침**이다. 메인 세션이 Bash 로 `git commit` 을 치는 것을 기술적으로 막는 훅은 아니다.
  강제가 필요하면 PreToolUse 훅으로 막을 수 있다. 다만 그 훅은 서브에이전트의 같은 명령도 막을 수 있어 넣지 않았다.
- Docs 문서·변경 이력은 맥락을 아는 메인 세션이 쓴다. 그 커밋은 다시 위임한다.

## 검증

- 이 문서와 스킬 파일을 커밋하는 일 자체를 스킬대로 Sonnet 서브에이전트에 위임했다. 결과는 대화 응답에 적었다.
