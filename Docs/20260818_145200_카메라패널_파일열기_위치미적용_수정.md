# 카메라 컨트롤 패널 — 파일열기(JSON) 시 카메라 위치가 첫 프리셋 값으로 설정되지 않던 문제

- 날짜: 2026-08-18
- 브랜치: `fix/camera-open-position`
- 커밋: `9df4a79`
- 대상 파일: `Park3D/Source/Park3D/CameraControlWidget.cpp`, `Park3D/Source/Park3D/CameraControlWidget.h`

## 1. 증상

카메라 컨트롤 패널의 **파일열기**로 카메라 프리셋 JSON을 불러와도 카메라가 파일에 적힌
위치로 돌아가지 않는다. Pan/Tilt/Zoom 은 정상 적용된다.

실측(패키지 실행, `CamPos_Seosin.json` 로드 직후 `cam.list`):

| | Camera-1 (선택 중) | Camera-2 (비선택) |
|---|---|---|
| 파일 첫 프리셋 | (-7.029, -1.227, 4.5) | (21.917, 4.113, 4.5) |
| 수정 전 실제 | **(-7.029, 0, 5)** | (21.917, 4.113, 4.5) |
| 수정 후 실제 | (-7.029, -1.227, 4.5) | (21.917, 4.113, 4.5) |

즉 **선택된 카메라만**, 그중에서도 **X 만 파일값이고 높이·Z 는 패널의 직전 값**(위 표에서는
기동 직후라 기본값 높이 5, Z 0)으로 남았다.

## 2. 원인

### 2-1. 잘못된 전제 — `USlider::SetValue` 는 브로드캐스트한다

`CameraControlWidget.cpp` 의 `SetControlSlider` 에는 이런 주석이 달려 있었다.

```cpp
// 프로그램적 SetValue는 OnValueChanged 미브로드캐스트(사용자 조작만 발생) → 재진입 없음.
C->Slider->SetValue(...);
```

UE 5.8 엔진 실물은 그렇지 않다 —
`Engine/Source/Runtime/UMG/Private/Components/Slider.cpp:41`

```cpp
void USlider::SetValue(float InValue)
{
    if (MySlider.IsValid()) { MySlider->SetValue(InValue); }
    if (Value != InValue) { Value = InValue; HandleOnValueChanged(InValue); }  // ← OnValueChanged.Broadcast
}
```

값이 달라지면 프로그램적 세팅도 `OnValueChanged` 를 쏜다. 따라서 `SetControlSlider` 는
`HandleSliderX/H/Z` → `OnSliderChanged` → `ApplyControlToCamera` 로 **되돌아온다**.

참고로 같은 파일이 함께 전제하던 `UEditableTextBox::SetText` 는 실제로 `OnTextCommitted` 를
쏘지 않는다(`EditableTextBox.cpp:163`). 텍스트 쪽 전제는 맞고 슬라이더 쪽만 틀렸다.

### 2-2. 되돌이 + 참조 별칭이 겹쳐 값이 무너진다

`FillControlsFromDir(const FCamDir& Dir)` 은 여섯 컨트롤을 **순서대로** 채운다.

```
SetVal(X, Dir.pos.x)  →  SetVal(높이, Dir.pos.z)  →  SetVal(Z, Dir.pos.y)  →  Pan/Tilt/Zoom
```

첫 `SetVal(X)` 의 슬라이더 세팅이 되돌아와 `ApplyControlToCamera(X)` 를 부르고, 이것이
`SyncCameraPosAcrossPresets(bFromControls=true)` 를 호출한다. 이 함수는 **컨트롤의 현재 값**을
`CamData` 의 해당 카메라 **모든 프리셋에 써 넣는다**. 그런데 그 시점의 컨트롤은
`X = 파일값`, `높이·Z = 직전 값` 인 혼합 상태다.

결정타는 `Dir` 이 값이 아니라 **참조**라는 점이다. 호출자는 `FillControlsFromDir(CP.datas[0])`
처럼 `CamData` 안의 원소를 그대로 넘긴다. 위에서 덮어쓴 대상이 바로 그 원소여서,
이어지는 `SetVal(높이, Dir.pos.z)` · `SetVal(Z, Dir.pos.y)` 는 **파일값이 아니라 방금 덮인
직전 값**을 읽는다.

### 2-3. 왜 이렇게만 증상이 났나

- **비선택 카메라는 멀쩡** — `LoadFromJsonFile` 이 먼저 부르는 `SyncCamerasToData` 가
  각 카메라에 `datas[0]` 를 직접 적용하고, `ApplyControlToCamera` 는 `GetCamera(CurCamIndex)`
  하나만 건드리기 때문.
- **Pan/Tilt/Zoom 은 멀쩡** — 해당 `ApplyControlToCamera` 분기는 `SyncCameraPosAcrossPresets`
  를 부르지 않아 `CamData` 를 건드리지 않는다.
- **X 는 멀쩡** — 덮어쓰기가 일어나기 전에 이미 `Dir.pos.x` 를 읽었다.

같은 함수를 쓰는 카메라 콤보 전환 · 카메라/프리셋 삭제 경로도 동일한 결함을 갖고 있었다.

## 3. 수정

`FillControlsFromDir` 하나에 두 가지를 넣었다.

```cpp
void UCameraControlWidget::FillControlsFromDir(const FCamDir& InDir)
{
    const FCamDir Dir = InDir;                              // (1) 별칭 차단 — 값 복사
    TGuardValue<bool> FillGuard(bFillingControls, true);    // (2) 되돌이 차단
    ...
    ApplyAllControlsToCamera();   // 여섯 개를 다 채운 뒤 한 번에 반영(기존 그대로)
}
```

```cpp
void UCameraControlWidget::OnSliderChanged(ECamCtrl Kind, float Slider01)
{
    if (bFillingControls) { return; }   // 채우는 중에는 카메라에 반영하지 않는다
    ...
}
```

`bFillingControls` 는 기존 `bComboRefreshing` 과 같은 자리에 둔 **일반 bool** 이다 —
쿠킹된 WBP 의 C++ 베이스에 `UPROPERTY` 를 추가하면 패키지가 `Bad export index` 로 즉사하므로
(CLAUDE.md 2026-08-12) 반드시 비-UPROPERTY 여야 한다.

`ApplyAllControlsToCamera` 는 `ApplyControlToCamera` 를 직접 부르므로 가드의 영향을 받지 않는다.
따라서 카메라 반영·프리셋 동기화는 종전대로 함수 끝에서 한 번 일어난다.

## 4. 검증

1. `Build.bat Park3DEditor Win64 Development` · `Build.bat Park3D Win64 Development` — 둘 다 성공.
2. `Package/Windows` → `Package/Work13520` 로 `robocopy /MIR` 복제(포트 config 만 유지),
   `Park3D/Binaries/Win64/Park3D.exe` 만 갈아끼워 실행.
   - 개발 exe 단독 실행은 Zen 스토어 문제로 죽으므로 이 절차를 쓴다(CLAUDE.md 2026-08-12).
3. 기동 시 `config_pmaker.json` 의 `camerapos_file` 자동 로딩은 파일열기와 **같은**
   `LoadFromJsonFile` 을 타므로, 기동 직후 `cam.list` 로 A/B 를 잰다.
4. 수정 전 exe / 수정 후 exe 를 번갈아 넣어 §1 의 표를 얻었다.

## 5. 남긴 것(이번 범위 밖)

- **높이/X/Z 의 min/max 는 파일에서 오지 않는다.** Pan/Tilt/Zoom 은 프리셋의 `ptzmin/ptzmax`
  로 갱신되지만 위치 3종은 패널의 현재 범위를 그대로 쓰고, 값은 그 범위로 클램프된다.
  범위 밖 위치를 담은 파일을 열면 조용히 잘린다. 이번 증상의 원인은 아니라 손대지 않았다.
- 피킹(Ctrl+좌클릭) 경로도 컨트롤을 순서대로 세팅하므로 중간에 혼합값이 한 번 카메라에
  실린다. 최종값은 지역 변수에서 오므로 결과는 정확하고, 눈에 띄는 증상이 없어 두었다.
