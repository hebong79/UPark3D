# `car.assignPreset` — 카메라 프리셋 기준 차량 presetId 재배정

- 날짜: 2026-08-13
- 대상: `Park3D/Source/Park3D/Rpc/Modules/CarRpcModule.cpp`
- 데이터: `Save/3D/CarPos/CarPos_office_20.json` (20대)

## 배경

`CarPos_office_20.json` 의 차량 20대가 **전부 `presetId: 1`** 이었다.
차량을 "어느 카메라 뷰에 속하는지"로 묶을 수단이 없어 가림 연출·학습 데이터 작업에서
카메라 단위 그룹핑이 불가능했다.

기존 RPC 중 차량의 `presetId` 를 바꾸는 것이 없었다(`car.create` 로 만들 때만 지정 가능).
그래서 전용 메서드를 새로 만들었다.

## "프리셋"이 두 종류라는 점부터

| | 파일 | 개수 | 식별자 |
|---|---|---|---|
| 주차면 프리셋 | `Save/3D/Preset/001_Preset_office.json` | 6개 | idx 1,2,3,4,5,7 |
| **카메라 PTZ 프리셋** | `Save/3D/CameraPos/CamPos_office.json` | **5개** | preset_id 1~5 |

이번에 차량에 넣기로 한 것은 **카메라 PTZ 프리셋 번호(1~5)** 다(사용자 결정).
두 번호 체계는 1:1이 아니다 — 카메라 프리셋 5개가 주차면 3개 열을 근/원으로 나눠 본다.

각 카메라 프리셋이 실제로 겨냥하는 지면 점(계산값):

| 카메라 프리셋 | pan / tilt / zoom | 지면 조준점 (x, y) | 겨냥하는 열 |
|---|---|---|---|
| 1 | 46.9 / 29.4 / 2.7 | (-19.9, 3.9) | 주차면 idx1 근거리 |
| 2 | 57.8 / 23.5 / 6.0 | (-19.7, 12.7) | 주차면 idx1 원거리 |
| 3 | 23.2 / 19.8 / 3.1 | (-1.8, 1.2) | 주차면 idx2 근거리 |
| 4 | 36.8 / 17.4 / 4.4 | (-1.8, 12.2) | 주차면 idx2 원거리 |
| 5 | 11.6 / 15.7 / 4.0 | (10.8, -3.9) | 주차면 idx3 |

## 판정 규칙 — 조준점 최근접

각 프리셋의 **지면 조준점**을 구하고, 차량 중심(XY, m)에서 가장 가까운 조준점의 `preset_id` 를 쓴다.

```
지면까지 수평거리 = 카메라높이 / tan(tilt)      // tilt 양수 = 하향 (PanTiltToRotator: Pitch = -Tilt)
조준점 = (camX + 거리·cos(pan), camY + 거리·sin(pan))   // pan = UE Yaw, 0°=+X, +방향=+Y
```

**화각 포함 판정을 쓰지 않은 이유**: 프리셋 줌이 커서 화각이 매우 좁다.
`zoom 6` 이면 `hfov = 2·atan(tan(56.5°/2)/6) ≈ 10.2°` 이고, 31 m 거리에서 화면 폭이 약 5.5 m —
주차면 2칸 남짓이다. 화각 포함으로 판정하면 20대 중 대부분이 어느 프리셋에도 안 들어가 미배정이 된다.

`tilt <= 0` 인 프리셋은 지면과 만나지 않으므로 후보에서 제외한다(수평·상향 시선).

## 구현

`car.assignPreset` 를 `CarRpcModule` 에 추가했다.

| 파라미터 | 기본값 | 설명 |
|---|---|---|
| `camFile` | `CamPos_office` | 카메라 프리셋 파일명(`.json` 자동 부착) |
| `camFullPath` | — | 절대경로. 주면 `camFile` 무시 |

반환: `{ok, camFile, camPresetCount, carCount, changed, cars:[{carNameId, prevPresetId, presetId, presetName, distM}]}`

**카메라 프리셋은 파일에서 직접 읽는다.** `CamRpcModule` 의 인메모리 목록(`PresetMemory`)은
`cam.savePreset`/`cam.loadPreset` 을 부르기 전까지 비어 있어 기동 직후에는 쓸 수 없기 때문이다.
경로 해석은 `Park3DDataPaths::GetDataFilePath` 에 맡긴다 — 패키지에서는 `Save/` 가 `ProjectDir()` 밖이다.

## 결과 (실행 확인)

`car.load` → `car.assignPreset {camFile:"CamPos_office"}` → `car.save`.

`carCount: 20`, `camPresetCount: 5`, `changed: 17`(3대는 이미 1이었다).

| presetId | 대수 | 위치 |
|---|---|---|
| 1 | 3대 | x=-19.3 열, y 1.1~6.0 |
| 2 | 3대 | x=-19.3 열, y 8.6~13.6 |
| 3 | 5대 | x=-2.3 열, y -3.8~6.1 |
| 4 | 4대 | x=-2.3 열, y 8.6~16.0 |
| 5 | 5대 | x=+14.8 열 전체 |

조준점까지 거리(`distM`)는 최소 0.55 m, 최대 6.86 m 였다.
최대값은 x=14.8 열의 차량인데, 카메라 프리셋 5의 조준점 x가 10.8 로 열에서 4 m 떨어져 있어서다
(그래도 다른 프리셋보다는 압도적으로 가깝다).

저장 파일은 UTF-8(BOM 없음, 첫 바이트 `7B`)로 기록됐고 한글 `prefabName` 도 그대로다.
원본은 `CarPos_office_20.bak_20260813.json` 으로 백업했다.

## 알려진 한계 · 주의

- **`slotId` 는 건드리지 않았다.** 원래 `presetId`+`slotId` 는 "(주차면 그룹, 그 안의 슬롯)" 한 쌍인데,
  `presetId` 가 카메라 프리셋 번호가 되면서 이 쌍의 의미가 깨졌다. `slotId` 를 함께 바꾸면
  어느 기준의 슬롯인지 더 모호해지므로 요청 범위(`presetId`)만 바꿨다.
  현재 파일의 `slotId` 값은 과거 배치의 잔재이며 신뢰할 수 없다(일부는 -1).
- **주차면 프리셋 번호가 필요한 곳과 섞이면 안 된다.** `sim.start {presetId}` 등 `preset.*` 계열의
  `presetId` 는 여전히 **주차면 프리셋 idx(1,2,3,4,5,7)** 다. 차량 데이터의 `presetId` 와 다른 공간이다.
- `car.list {presetId:N}` 필터는 이제 "카메라 프리셋 N 이 겨냥하는 차량"을 뜻한다.
- 배치를 바꾸면 다시 불러야 한다(자동 갱신 없음). 결과는 `car.save` 전까지 런타임에만 있다.
- 주차면 idx 4·5·7 열에는 현재 차량이 없다. 그 열에 차를 놓으면 조준점 최근접 규칙상
  가장 가까운 카메라 프리셋으로 배정되지만 실제로는 어느 프리셋도 그 열을 겨냥하지 않는다.
  거리 임계값은 두지 않았다(`distM` 을 보고 사람이 판단).
