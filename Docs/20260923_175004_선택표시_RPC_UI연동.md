# 선택 표시 RPC 가 패널 체크박스와 함께 바뀌게 — UI 가 없으면 거부

## 요청
"선택표시 플래그를 rpc화 해주고 UI도 같이 변경하게 해줘. (만약 UI가 없으면 실행안되게 처리)"

## 이전 상태
- `car.setSelectionMark {visible}` 는 오전(11:13) 작업으로 이미 있었다. 다만 **매니저(`ACarPlacementManager::SetSelectionMarkVisible`)만 바꿨다.**
- 차량 배치 패널의 "선택 표시" 체크박스는 패널을 열 때(`NativeConstruct`)만 월드 값을 읽는다.
  → 패널이 열려 있는 동안 RPC 로 끄면 화면의 체크박스는 체크된 채로 남았다.

### "UI 가 없다"의 정의
- 차량 배치 패널 인스턴스가 그 월드에 없거나, 있어도 "선택 표시" 체크박스 주입이 실패한 경우(`VBox_Root` 못 찾음 등).
- **패널이 닫혀 있어도 인스턴스가 살아 있으면 "있음"** 이다. 닫힌 패널의 체크박스도 갱신되고, 다시 열면 `NativeConstruct` 가 월드 값을 다시 읽는다.
- 패널 인스턴스는 기동 시 config `carpos_file` 이 지정돼 있으면 `EnsurePanelConstructed` 로 만들어진다(서신·객리단 둘 다 지정). 지정이 없는 레벨에서는 사용자가 패널을 한 번 열기 전까지 `car.setSelectionMark` 가 거부된다.
- 레벨 전환(`scene.load`) 뒤에는 새 GameMode 가 새 패널을 만든다 — 옛 패널은 옛 월드 소속이라 월드 비교로 걸러진다.

## 검증
- 빌드: `Park3DEditor`·`Park3D` Win64 Development 둘 다 Succeeded.
- Automation `StartsWith:Park3D` **134/134** 통과(수정 전 1차). 테스트 보강 후 `Park3D.Rpc.CarModuleExt` 5/5 통과.
  - 에디터 월드에는 로컬 플레이어가 없어 `UUserWidget::Initialize` 가 `NativeOnInitialized`(체크박스 주입)를 부르지 않는다 → 테스트는 "패널은 있으나 체크박스 없음 = 거부" 까지만 확인하고, 체크박스 연동은 실기에서 봤다.
- 실기: 작업본 `Package/Work13540`(RPC 13540, exe 만 교체, 정본 13510 무간섭)
  - 기동 직후 `car.getSelectionMark` → `{visible:true, ui:true}`
  - `car.select` 1대 → `car.setSelectionMark false` → `{ok, visible:false, changedCount:1}` → get `{visible:false, ui:true}` → `true` 로 복귀 `changedCount:1`
  - 로그에 **패널 함수의 알림** `[CarPlacement] 선택 표시 끄기 — 1대 갱신` / `켜기 — 1대 갱신` 이 RPC 줄과 함께 찍힘 → RPC 가 패널 경로(체크박스 `SetIsChecked` 포함)를 탔다.
- **미검증**: 열린 패널의 체크박스가 화면에서 바뀌는 모습은 캡처하지 않았다(패널 열기 자동화 스크립트가 이 PC 에 없음). 실기에서 "UI 없음" 거부는 재현하지 않았다(두 레벨 모두 기동 시 패널이 생김) — 자동화 테스트로만 확인.
- 정본(`Package/Windows`, 13510) exe 는 교체하지 않았다.

## 호출자 영향
- 웹(SettingManager 「선택 표시」 체크박스)은 `car.setSelectionMark` 가 -32000 으로 실패할 수 있음을 처리해야 한다. `car.getSelectionMark.ui` 로 미리 알 수 있다.
