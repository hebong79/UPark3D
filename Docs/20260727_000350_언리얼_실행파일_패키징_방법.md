# 언리얼(UE5)에서 독립 실행 exe 만드는 방법 — Park3D 기준

작성일: 2026-07-27
대상: `Park3D/Park3D.uproject` (UE 5.8)

---

## 0. 먼저: "빌드"와 "패키징"은 다르다

| 구분 | 산출물 | 용도 | 이 프로젝트에서 |
|---|---|---|---|
| **모듈 빌드**(Editor 타깃) | `UnrealEditor-Park3D.dll` | 에디터/PIE·`-game`에서 C++ 코드 로드 | UBT `Build.bat`로 매번 함. **독립 exe 아님** |
| **패키징**(Cook + Stage) | `Park3D.exe` + 쿠킹된 콘텐츠 | 에디터 없이 배포·실행 | UAT `BuildCookRun`으로 이번에 생성 |

- 모듈 빌드는 **엔진 공용 `UnrealEditor.exe`가 우리 DLL을 로드**하는 구조라 프로젝트 전용 exe가 안 생긴다.
- 독립 exe는 **콘텐츠를 쿠킹(cook)** 해서 `.pak`으로 묶고, 게임 타깃(`Park3D`)을 빌드해 **`Park3D.exe`** 를 만드는 별도 과정이 필요하다.

---

## 1. 방법 A — 에디터 GUI (간단, 권장 입문)

1. 에디터 상단 **Platforms**(플랫폼) 드롭다운 → **Windows** → **Package Project** 클릭.
   - (구버전 메뉴: `File → Package Project → Windows`)
2. 출력 폴더 선택 → 쿠킹·빌드·스테이징이 진행된다(하단 진행바).
3. 완료 시 선택 폴더에 `Windows/` 하위로 실행 파일이 생성된다.

**사전 설정**(Project Settings):
- **Project Settings → Maps & Modes → Game Default Map**: 패키지가 부팅 시 로드할 맵. Park3D는 `/Game/Maps/PresetMaker1`로 설정되어 있음.
- **Project Settings → Packaging → Build Configuration**: `Development`(로그·콘솔 있음, 디버깅 편함) / `Shipping`(최적화·로그 최소, 배포용).
- **Packaging → List of maps to include**: 비우면 참조된 맵만 쿠킹. 특정 맵을 강제 포함하려면 추가.

---

## 2. 방법 B — 커맨드라인 UAT (자동화·CI 권장, 이번에 사용)

`RunUAT.bat BuildCookRun` 한 방으로 빌드+쿠킹+스테이징+아카이브까지 수행.

```bat
"C:/Program Files/Epic Games/UE_5.8/Engine/Build/BatchFiles/RunUAT.bat" BuildCookRun ^
  -project="D:/Work/UnrealWork/Parking/Park3D/Park3D.uproject" ^
  -noP4 -platform=Win64 -clientconfig=Development ^
  -cook -build -stage -pak -archive ^
  -archivedirectory="D:/Work/UnrealWork/Parking/Package"
```

### 주요 옵션

| 옵션 | 의미 |
|---|---|
| `-project=` | .uproject 경로 |
| `-platform=Win64` | 대상 플랫폼 |
| `-clientconfig=Development` | 빌드 구성. `Development`(디버깅) 또는 `Shipping`(배포) |
| `-cook` | 콘텐츠를 대상 플랫폼용으로 쿠킹 |
| `-build` | 게임 타깃(`Park3D`) C++ 컴파일 |
| `-stage` | 실행에 필요한 파일을 스테이징 폴더로 복사 |
| `-pak` | 에셋을 `.pak` 하나로 묶음(생략 시 낱개 파일) |
| `-archive` `-archivedirectory=` | 최종 산출물을 지정 폴더로 아카이브 |
| `-noP4` | Perforce 미사용 |
| (선택) `-nocompileeditor` | 에디터 재컴파일 생략(속도↑) |
| (선택) `-compressed` | pak 압축 |

> 쿠킹은 참조된 모든 에셋을 변환하므로 **오래 걸린다**(Park3D는 Fab 에셋이 많아 수십 분+). 처음 1회가 가장 길고, 이후 증분 쿠킹은 빨라진다.

## 3. 결과물 위치·구조

`-archivedirectory` 기준으로:

```
D:/Work/UnrealWork/Parking/Package/
└─ Windows/
   └─ Park3D/
      ├─ Park3D.exe            ← 독립 실행 파일(더블클릭)
      ├─ Park3D/               ← 프로젝트 데이터(Content pak, Config 등)
      └─ Engine/               ← 엔진 런타임 파일
```

- 배포는 `Windows/` 폴더 **통째로** 복사한다(exe 단독으로는 못 돈다 — 옆의 데이터/엔진 파일 필요).

## 4. 실행 및 Park3D RPC 서버 확인

패키지 exe도 `GameInstanceSubsystem`(`URpcServerSubsystem`)이 부팅 시 자동 기동하므로 **RPC 서버가 그대로 뜬다**.

```
Package/Windows/Park3D/Park3D.exe -windowed -resx=1280 -resy=720
```

- 포트는 `Config/DefaultGame.ini`의 `[RpcServer] Port`를 읽는다(패키지에 Config 포함됨) → 기본 **13120**.
- 다른 포트로 띄우려면 `Park3D.exe -RpcPort=13130` (커맨드라인이 config보다 우선).
- 헬스체크: `curl http://localhost:13120/health` → `{"ok":true}`.

---

## 5. 주의사항

- **시작 맵 필수**: `Game Default Map`이 비어 있으면 빈 레벨로 부팅한다. RPC 서버(subsystem)는 맵 무관하게 뜨지만, 도메인 메서드(car/preset/cam 등)는 매니저 액터가 있는 맵이 로드돼야 동작한다.
- **Development vs Shipping**: 콘솔·로그·`-RpcPort` 같은 커맨드라인 옵션은 Development에서 편하다. Shipping은 일부 콘솔/로그가 제한될 수 있다.
- **Config 포함 확인**: `Config/*.ini`는 스테이징에 포함된다. 포트를 config로 바꾸는 전략이 패키지에서도 유효.
- **에디터 종료 후 빌드**: Live Coding이 켜져 있으면 모듈 DLL 링크가 막힌다. 패키징 전 에디터를 닫는다.
- **첫 쿠킹은 길다**: 실패 시 로그 마지막의 `BUILD FAILED`/`AutomationTool exiting with ExitCode` 를 확인.
