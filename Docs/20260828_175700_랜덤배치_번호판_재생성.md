# 랜덤 배치 시 표시되는 대수만큼 번호판 번호 재생성

작성: 2026-08-28 17:57 · 대상: `ACarActor`, `ACarPlacementManager`

## 1. 질문 1 — "주차면 갯수만큼 미리 생성했다가 랜덤 갯수만큼만 보여주고 나머지는 숨기는가?"

**그렇다.** 다만 "주차면 갯수"가 아니라 **현재 차량 목록(배치 데이터) 전부**가 기준이다.

`ACarPlacementManager::ResetRandomPlacement`(UI "리셋 랜덤" 버튼 · 차량 랜덤 패널 · RPC `car.resetRandom` 공용 진입점)의
`CountObjectAndColor` 모드 흐름:

1. `ToCarPosDatas()` — 현재 월드의 차량 상태(위치/회전/메타)를 원본으로 뜬다.
2. `RebuildAllRandomMesh()` — **전부 지우고 전부 다시 스폰**한다(차종만 랜덤 교체, 위치·id 유지). 이 시점에는 전원이 보인다.
3. `HideRandomCars(전체 − 요청 대수)` — 요청 대수만 남기고 나머지를 **숨긴다**(`SetActorHiddenInGame` + 충돌 해제).
   액터를 지우지 않으므로 다음 호출에서 다시 늘릴 수 있다.
4. `SetRandomColorOfCarList()` — 보이는 차량만 랜덤 도색.

즉 "미리 다 만들어 두고 초과분을 숨긴다"가 맞다. 슬롯 기반으로 **새로 스폰**하는 경로는 별개다(`random.slotPlace`).

## 2. 질문 2 — 번호판 번호 랜덤 재생성

### 왜 지금까지 안 바뀌었나 (원인)

번호는 `ACarActor::MakeDeterministicPlateNumber(FCarPos)` 가 **`FCarPos.id` 의 CRC32** 로 만든다.
`RebuildAllRandomMesh` 는 위치·메타와 함께 **id 를 그대로 옮기므로**, 차량을 몇 번 재생성해도 같은 자리의 차는
항상 같은 번호가 나온다. 차종·색·대수만 달라지고 번호판은 고정이었다.
→ 재생성 경로에 손대는 것으로는 절대 안 바뀐다. 번호를 **명시적으로 갈아 끼우는 창구**가 필요했다.

### 변경 내용

| 파일 | 추가 |
|------|------|
| `CarActor.h/.cpp` | `MakeRandomPlateNumber(FRandomStream&)`, `SetPlateNumber(FString)`, `RefreshPlateNumberSdf()`, `PlateSdfAspect` |
| `CarPlacementManager.h/.cpp` | `RandomizeVisiblePlateNumbers(int32 Seed)` + `ResetRandomPlacement` 재생성 경로에서 호출 |
| `Rpc/Modules/CarRpcModule.cpp` | `car.randomizePlates` 신설 |
| `Rpc/RpcModuleSupport.cpp` | 차량 DTO 에 `plate` 필드(= `car.list`/`car.get`/`car.update` 응답) |
| `Tests/CarPlacementManagerTest.cpp` | 회귀 테스트 2건 |

- 번호 생성 규약을 `PlateNumberFromHash(uint32)` 한 곳으로 모았다. 결정적 번호는 id 해시를, 랜덤 번호는
  `FRandomStream::GetUnsignedInt()` 을 넣는다 — **형식(100~699 + 일반용 한글 + 4자리)이 갈라지면 랜덤 번호만
  SDF 아틀라스에 없는 글자를 요구할 수 있다.**
- `SetPlateNumber` 는 ① `PlateNumber` ② 레거시 TextRender ③ **폴백 위젯**(SDF 실패 차량이 화면에 쓰는 것)
  ④ SDF 텍스처를 모두 갱신한다.
- `RefreshPlateNumberSdf` 는 `UpdatePlatePresentation`(정렬) 전체를 다시 돌리지 않는다. 판 자세는 그대로이고
  바뀐 것은 글자뿐이라, 처음 구울 때 저장해 둔 **판 종횡비(`PlateSdfAspect`)** 로 텍스처만 다시 구워 기존 MID 에 물린다.
  아직 한 번도 굽지 않았으면(정렬 전) 아무것도 하지 않는다 — 어차피 다음 정렬이 새 번호로 굽는다.
  굽기에 실패하면 **파라미터에 null 을 넣지 않고 옛 텍스처를 유지**한다(번호가 통째로 사라지는 것보다 낫다).

### 적용 범위(의도적 선택)

- **재생성 두 모드에서만** 번호를 새로 뽑는다 — `ObjectAndColor`, `CountObjectAndColor`.
  `ColorOnly`("색상만")는 이름대로 색만 바꾸므로 건드리지 않는다.
- **보이는 차량만** 바꾼다. 숨긴 차는 이번 장면에 없고, 다시 표시했을 때 id 기준 번호로 남아 있는 편이 추적하기 쉽다.
- 같은 장면에 같은 번호가 두 대 나오지 않도록 **숨긴 차 번호까지 포함해** 중복을 피해 뽑는다(최대 16회 재시도).
- 시드 규약은 기존과 같다: `seed != 0` 재현, `seed == 0` 비결정. UI/RPC 는 0 을 넘기므로 누를 때마다 새 번호다.
- 번호는 JSON 저장 대상이 아니다(기존과 동일) — 저장/열기로 왕복하면 id 기준 번호로 되돌아간다.

### RPC 표면

`car.resetRandom` 안에서만 도는 상태로 두면 ① 차종·색을 바꾸지 않고 번호만 바꿀 방법이 없고
② 번호를 **읽을 방법이 로그 grep 뿐**이라 계약이 성립하지 않는다. 둘 다 열었다.

| 메서드 | 인자 | 응답 | 비고 |
|--------|------|------|------|
| `car.randomizePlates` | `seed?`(0=비결정, >0=재현) | `changedCount`, `carCount`, `plates[{carNameId, plate}]`, `seedHonored` | 가시 차량 번호만 교체. **차종·색·표시상태 불변** |
| `car.list` / `car.get` | (기존) | 차량 항목에 `plate` 추가 | canonical `123다4567`. 런타임 값이라 저장 파일에는 없다 |

동작은 매니저(`RandomizeVisiblePlateNumbers`)가 소유하고 RPC 는 그것만 부른다 — `car.hideAll`/`car.resetRandom` 선례와 같은 규약이라
UI 경로와 RPC 경로가 갈라지지 않는다.

## 3. 검증

### 자동화 테스트 (`UnrealEditor-Cmd -ExecCmds="Automation RunTests Park3D.CarPlacement"`)

20건 중 19건 성공. 신규/확장 2건 모두 성공:

- `Park3D.CarPlacement.ResetRandomPlacement` — 6대 중 2대 표시 시 **가시 2대만 번호가 새로 뽑히고
  숨긴 4대는 id 기준 번호 유지**, 장면 안 6개 번호가 서로 다름.
- `Park3D.CarPlacement.RandomizeVisiblePlateNumbers`(신규) — 같은 시드 → 같은 번호(재현), 시드 0 → 새 번호.

**실패 1건은 이 변경과 무관한 기존 실패**다:
`Park3D.CarPlacement.PlateNumber` 의 표시 문자열 기대값이 `"553 어 8818"` 인데 실제는 `"553어 8818"` —
2026-08-21 에 표기를 `672 우 3269` → `672우 3269` 로 바꾸면서 테스트를 같이 고치지 않은 것이다(CarActorTest.cpp:191,195).
이번 작업 범위가 아니라 손대지 않았다.

### 런타임 (패키지 복제 `Package/Work13540`, RPC 13540 · 스트림 13800 대역)

원본 실행창(13510)은 건드리지 않았다. exe 만 새로 빌드한 것으로 교체.

| 시점 | 차량 `0-16.25.24` 번호판 | 근거 |
|------|--------------------------|------|
| 기동 직후 | `455가5639` | 로그 `[CarPlate] SDF …` + 화면 캡처에 `455가 5639` |
| `car.resetRandom {mode:countObjectAndColor, count:23}` 후 | `647어1797` | 로그 `[CarPlate] 번호 교체 …` + **화면 캡처에 `647어 17…`** |

- 값만 바뀌고 화면은 그대로인 함정(이 프로젝트에서 여러 번 있었다)을 피하려고 **화면 캡처로 확인**했다.
- `count:23`(전원 표시) → 번호 교체 로그 **23건**, `count:5` → **5건**이고,
  교체된 5개 id 가 `car.list` 의 `visible:true` 5대와 **정확히 일치**했다.

### RPC 실측 (같은 복제 인스턴스, exe 재교체 후)

`car.hideRandom {count:18}` 로 23대 중 5대만 남긴 뒤 `car.randomizePlates {seed:0}`:

| 확인 | 결과 |
|------|------|
| `changedCount` / `plates` 길이 | 5 / 5 (가시 대수와 일치) |
| 가시 5대 번호 변경 | 5건 (예: `139다3108` → `174마7134`) |
| **숨긴 18대 번호 변경** | **0건** |
| 응답 `plates` vs `car.list` 의 `plate` | 전부 일치 |
| 장면 안 번호 유일성 | 23 / 23 |
| `seed:777` 두 번 호출 | 결과 동일(재현) |
| 가시 대수 | 호출 전후 5 유지(표시상태 불변) |

## 4. 남은 것 / 한계

- 숨긴 차량을 나중에 "전체 표시"로 되살리면 그 차들은 id 기준 번호를 그대로 쓴다(의도).
- 특정 차량에 **원하는 번호를 지정**하는 RPC 는 열지 않았다(`ACarActor::SetPlateNumber` 는 이미 있으므로 필요해지면 결선만 하면 된다).
- `car.resetRandom` 은 여전히 시드를 0 으로 박아 부른다(기존 동작) — 재현이 필요하면 `car.randomizePlates` 의 시드를 쓴다.
