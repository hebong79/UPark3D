# 환경 레벨 복원 및 부팅맵 교체 — 렌더링을 도심 주차장 씬으로 되돌림

- 날짜: 2026-08-17
- 브랜치: `feat/restore-environment-level`
- 신고: "스트리밍(웹)과 언리얼 원본의 렌더링 차이가 크다. 둘 다 참조 이미지(도심 주차장)처럼 나오게 해 달라."
- 결과: **렌더링 목표 달성.** 부팅맵을 `LV_Park_01` 로 교체하고 코드 3곳을 고쳐 검증 완료. 패키지 재빌드는 별도.

## 1. 신고의 전제가 틀렸다 — 셰이더 문제가 아니었다

참조 이미지에는 건물·가로수·볼라드·노면 마킹·아스팔트가 있고, 신고된 두 화면에는 회색 평면과 차량뿐이었다.
이 차이는 셰이더·후처리로 만들 수 있는 것이 아니라 **씬에 환경 콘텐츠가 없는 것**이었다.

전날 커밋 `17485c0`(미사용 콘텐츠 5,322개 분리)이 원인이다. 의존성 BFS 의 루트가
`/Game/Maps/PresetMaker1` 이었는데, 그 부팅맵은 이미 액터가 비어 있었으므로 **환경 전체가
"미사용"으로 판정**되어 `_UnusedContent/` 로 빠졌다.

| 빠진 것 | 규모 | 참조 이미지에서의 역할 |
|---|---|---|
| `Environment/` | 3,428개 / 4,243MB | 건물·가로수·볼라드·표지판·맨홀 |
| `Road_Creator_Pro/` | 818개 / 860MB | 아스팔트 노면·차선·화살표·"출구" 마킹 |
| `UltraDynamicSky/` | 813개 / 597MB | 하늘·태양·대기 |
| `Levels/LV_Park_01~09`, `LV_Main` | 10개 맵 | **주차장 씬 배치 자체** |

`PresetMaker1` 의 `__ExternalActors__` 는 복원 후에도 파일 1개뿐이다. 그 맵의 환경은
이번 분리 이전(CLAUDE.md 2026-08-16 "콘텐츠 교체" 항목)에 이미 소실됐다 — 되살릴 대상이 아니다.

## 2. 대상 레벨 판별 — 자동 스크린샷은 실패했고, 메시 이름으로 좁혔다

`LV_Park_01~09` 중 어느 것인지 가리려고 에디터 파이썬으로 `SceneCapture2D` 부감 이미지를 뽑았다.
**다섯 번 시도했고 모두 씬을 알아볼 수 없었다.** 원인은 넷이었고 앞의 셋은 고쳤다.

| 증상 | 원인 |
|---|---|
| 이미지 10장이 전부 동일 | 전체 액터 바운즈로 중심을 잡아 UDS 의 187km 스카이돔이 지배 → 카메라가 105km 밖 |
| 확장자는 png 인데 못 읽음 | RT 기본 포맷이 float → `export_render_target` 이 EXR 로 씀(매직 `76 2f 31 01`). `RTF_RGBA8` 지정으로 해결 |
| 화면이 기울고 하늘을 봄 | `spawn_actor_from_class` 의 rotation 인자가 먹지 않음 → 스폰 후 `set_actor_location_and_rotation` 로 명시 |
| **텍스처가 체커보드, 구조물이 검정** | SceneCapture 는 텍스처 스트리밍에 뷰를 등록하지 않아 밉이 로드되지 않고, UDS 조명도 초기화되지 않는다. `r.TextureStreaming 0` 로도 해결 실패 |

렌더 판별을 접고 **배치된 스태틱메시 이름**으로 대조했다(렌더 불필요).

- `LV_Park_07A/07B` 는 사과·배·양파·대파 좌판 200여 개 = 재래시장 → 해당 없음
- `LV_Park_04` 는 건물소품 129·간판 145·가로수 161 = 도심 상가
- `LV_Park_01` 은 실패한 캡처에도 **청록색 주차면**이 찍혀 있었다 → 참조 이미지의 전기차 청록 주차면과 일치

사용자가 `LV_Park_01`/`LV_Park_03` 로 범위를 좁혔고, 위 청록 주차면 근거로 `LV_Park_01` 을 택했다.
부팅맵은 ini 한 줄이라 판별이 틀렸으면 즉시 바꿀 수 있다.

## 3. 변경 내용

### 3.1 부팅맵 (`Config/DefaultEngine.ini`)

```ini
GameDefaultMap=/Game/Levels/LV_Park_01     ; was /Game/Maps/PresetMaker1
EditorStartupMap=/Game/Levels/LV_Park_01
```

### 3.2 단색 바닥 억제 — `map_floor` 설정 신설

`APark3DGameMode::BeginPlay` 가 `AMapFloorActor::GetOrSpawn` 으로 160×160m 평면을 **무조건** 깔았다.
빈 부트 맵에는 맞는 동작이지만, 레벨이 자기 아스팔트를 가진 지금은 그 위를 덮어 버린다.

- `FPark3DAppConfig::bMapFloor`(기본 `true` = 기존 동작) 추가, JSON 키 `map_floor`
- `Save/Config/config_pmaker.json` 에 `"map_floor": false`
- 설정을 `BeginPlay` 에서 한 번 더 읽는다 — `ApplyStartupConfig` 는 메뉴 표시 뒤에 돌아
  그때는 이미 바닥이 스폰된 뒤다. JSON 파일 하나 파싱이라 비용은 무시할 수준

### 3.3 조명: 통합 하늘 시스템이 있으면 손대지 않는다 (`LightControlManager`)

**이 절은 세 번 뒤집힌 끝의 결론이다.** 중간 판단을 그대로 남긴다 — 같은 함정을 다시 밟지 않기 위해서다.

`LV_Park_01` 의 조명은 전부 `Ultra_Dynamic_Sky`(UDS) 한 액터가 소유한다.

```
Ultra_Dynamic_Sky_C
  Sun / Moon            (DirectionalLightComponent 2개)
  Captured Scene Sky Light / Cubemap Sky Light  (SkyLightComponent 2개)
  SkyAtmosphere, VolumetricCloud, HeightFog, Sky_Sphere
  PostProcessComponent 2개
  Time of Day = 960, Day Length 30분 / Night Length 15분  ← 시간이 실제로 흐른다
```

| 시도 | 결과 |
|---|---|
| ① `FindSun`/`FindSky` 를 액터→컴포넌트 기준으로 확장 | 이중 조명(두 번째 태양 스폰)은 막았으나, **컴포넌트 배열에서 `Moon` 이 `Sun` 보다 앞서** 달을 집었다. `light.get` 은 우리 값을 돌려주는데 화면은 야간 — "적용된 것처럼 보이는" 상태 |
| ② `IsUsedAsAtmosphereSunLight()` 로 태양 확정 | 태양은 맞게 잡았지만 여전히 어두웠다. 하늘·구름·하늘빛 캡처는 라이트가 아니라 **Time of Day** 가 지배하기 때문 |
| ③ 레벨의 UDS 를 `Animate Time of Day=false`, `Time of Day=1300` 으로 고정 | 그래도 어두웠다. 우리 unbound `PostProcessVolume` 이 UDS 자체 포스트프로세스를 덮고 있었다 |
| ④ **UDS 가 있으면 조명을 아예 건드리지 않는다** | 밝은 한낮. 목표 달성 |

최종 구현은 `HasExternalSkySystem()` — 태양이 `ADirectionalLight` 액터가 아니라 BP 액터가 품은
컴포넌트면 통합 하늘 시스템으로 보고, `ApplySettings` 와 `EnsureLightingActors` 가 모두 즉시 빠진다.
우리가 스폰하는 태양은 항상 `ADirectionalLight` 이라 빈 부트 맵 동작은 그대로 살아 있다.

**교훈: `light.get` 이 방금 넣은 값을 돌려주는 것은 적용의 증거가 아니다.** 값이 유지되는 것과
화면이 그렇게 그려지는 것은 별개이며, 이 프로젝트에서는 두 번 그 차이에 속았다. 조명 검증은
반드시 캡처 이미지로 한다.

**이 레벨에서 잃는 것:** 조명 패널과 `light.*` RPC 가 무력해진다. `scenario.*` 의 가림률 측정은
조명 조건을 시나리오 정의(`lightFile`)로 통제하는 설계였는데, 이 레벨에서는 그 통제가 서지 않는다.
밝기를 바꾸려면 레벨에서 UDS 의 `Time of Day` 를 조정해야 한다.

### 3.3.1 (참고) 조명 탐지를 액터 → 컴포넌트 기준으로

`FindSun`/`FindSky` 가 `ADirectionalLight`/`ASkyLight` **액터만** 찾았다. `LV_Park_01` 의 조명은
전부 `Ultra_Dynamic_Sky_C` **BP 액터가 품은 컴포넌트**라 "조명 없음"으로 오판되어,
`EnsureLightingActors` 가 두 번째 태양·하늘·하늘빛을 스폰했다 — 이중 조명.

반환형을 `UDirectionalLightComponent*`/`USkyLightComponent*` 로 바꾸고, 액터 검색 실패 시
`FindComponentByClass` 로 BP 액터 내부까지 훑는다. `SkyAtmosphere` 존재 판정도 컴포넌트 기준으로 바꿨다.

`ADirectionalLight` 는 조명 컴포넌트가 곧 루트라, 컴포넌트에 `SetWorldRotation` 을 걸면 액터 회전도
함께 움직인다 — 기존 테스트(`Park3D.Light.ManagerApply`, 액터 회전을 검증)가 그대로 통과한다.

### 3.4 시작 조명 적용을 0.5초 지연 (`Park3DGameMode`)

**UDS 는 자기 `BeginPlay` 에서 태양을 자기 값으로 세팅한다.** 게임모드가 먼저 조명을 적용하면
그 뒤에 덮인다 — 로그에는 "태양 150.0 lux 적용"이 남는데 `light.get` 은 `5 lux` 를 돌려주는 상태가 됐다.

덮어쓰기는 **초기 1회뿐**임을 실측했다(적용 후 2·8·20·40초 모두 150 lux 유지). 따라서 짧은 지연이면 충분하다.
적용부를 `ApplyStartupLighting()` 으로 분리하고 `FTimerHandle StartupLightTimer` 로 0.5초 뒤 호출한다.

### 3.4.1 (참고) 시작 조명 지연은 통합 하늘 시스템 레벨에서는 무의미해졌다

3.4 의 0.5초 지연은 "우리가 마지막에 값을 넣는다"는 전제였는데, 3.3 의 결론에 따라 이 레벨에서는
값을 넣지 않는다. 지연 자체는 유지한다 — 통합 하늘 시스템이 없는 레벨(빈 부트 맵 등)에서는
여전히 필요하고, 있는 레벨에서는 가드가 먼저 걸려 아무 일도 하지 않는다.

### 3.5 조명 기본값을 한낮으로

기존 기본값(`Sangmyung.json`)은 태양 5.0 lux·노출 −1.02 로 사실상 달빛이었다. 레벨 환경에서
참조 이미지에 맞는 값을 실측으로 찾아 `LightSettings.json` 으로 저장했다.

```json
{"ExposureEV100": 3.5, "SunIntensity": 150, "SunAltitudeDeg": 75, "SunAzimuthDeg": 150, "SkyIntensity": 20}
```

`SkyIntensity` 는 요청값 60·100 이 모두 20 으로 잘렸다 — `ClampSettings` 의 상한이 20 이다.
그늘을 더 열려면 그 상한을 손봐야 하며, 이번에는 건드리지 않았다.

**함정:** `light.setDefault` 는 `_default.txt` 에 **절대 경로**를 기록한다(기존 값은 파일명만).
패키지는 `Save/` 가 ProjectDir 밖이라 그 경로가 깨진다 → 파일명만 남기도록 되돌렸다.
`setDefault` 가 절대 경로를 쓰는 것 자체는 이번 범위 밖으로 두었다.

## 4. 검증

`UnrealEditor.exe -game -RpcPort=13530` 으로 띄워 RPC·스트림으로 확인했다.
(기존 인스턴스가 13510·13601~13602 를 쓰고 있어 포트를 분리했다.)

| 항목 | 결과 |
|---|---|
| 환경 렌더 | 건물·유리창·가로수·화강암 연석·보도블록 정상. 체커보드/검정 없음 |
| 좌표 정합 | **손댈 필요 없었다** — 주차면 프리셋 5종과 차량이 레벨 주차장 위에 그대로 얹힌다 |
| 단색 바닥 | `map_floor=false` 로 생성 안 함(로그 확인) |
| 이중 조명 | 태양·하늘·하늘빛 "생성했습니다" 로그 없음 = UDS 것 재사용. 노출 볼륨만 신규(UDS 에 없음) |
| 시작 조명 | 재기동 후 `sun=150 alt=75 azi=150 sky=20 exp=3.5` 유지 |
| 유닛 테스트 | 95 성공 / 2 실패 |

실패 2건은 이번 변경과 접점이 없다.

- `Park3D.Rpc.CamModule` — 테스트가 `cam.savePreset` 을 "미구현이라 실패해야 한다"고 기대하는데 실제로는
  구현되어 성공한다. 2026-08-11 결선 때 테스트를 갱신하지 않은 잔재다.
- `Park3D.CarPlacement.PlateNumber` — `CarActorTest.cpp:205` "실차 메시 로드" 실패. NullRHI 헤드리스 실행 탓으로 보인다.

**사전 실패인지는 확인하지 않았다.**

## 4.1 패키지

쿡 2,124/2,124, `.ucas` 2.7GB, 산출물 3.5GB. `Save/`(config·조명)도 정상 스테이징됐다.
**패키지 실행본으로 밝은 한낮 화면을 확인했다.**

첫 시도는 `Error_UnknownCookFailure` 로 실패했다. 쿡은 전량 성공했는데 컴파일 에러 35건이
빌드를 중단시켰고, **전부 `BP_PlayerController` 하나**에서 나왔다.

```
LV_Park_01 (부팅맵)
  └─ BP_Camera (레벨에 배치된 감시카메라 폴)
       └─ /Game/Core, /Game/Widgets   ← 이전 버전 BP UI 세트(WBP_RenderPanel 포함)
            └─ BP_PlayerController
                 └─ Open/Save File Dialog, Get User Directory  ← 플러그인이 이 머신에 없음
```

현재 코드가 쓰는 위젯은 `Content/UI/` 9개뿐이고(`/Game/UI/WBP_CameraViewer`,
`/Game/UI/WBP_MainMenu`), `Content/Widgets/` 123개와 `Content/Core/` 20개는 소스·ini 참조가 0이다.
그런데 레벨이 쓰는 `BP_Camera` 가 이들을 물고 있어 단순히 빼낼 수 없고, 파일 다이얼로그 노드를
주던 플러그인은 프로젝트 `Plugins/` 폴더 자체가 없어 복구가 불가능하다.

→ `BuildPackage.bat` 에 `-IgnoreCookErrors` 를 넣었다. **에러를 고친 것이 아니라 통과시킨 것**이며,
근거는 그 에셋이 실행에 쓰이지 않는다는 점이다. 플러그인이 복구되거나 레거시 세트를 정리하면 빼야 한다.

## 5. 남은 것 / 알려진 한계
- **레벨 에셋을 수정했다.** `LV_Park_01` 의 `Ultra_Dynamic_Sky` 를 `Animate Time of Day=false`,
  `Time of Day=1300`(오후 1시)으로 고정하고 저장했다. `Content/` 는 git 밖이므로 이 변경은
  커밋에 없다 — 다른 작업본에서는 레벨을 다시 손봐야 한다.
- **PTZ 카메라 2대가 주차장이 아니라 건물을 본다.** 위치(`CamPos_Seosin.json`)는 그대로 두었다 —
  레벨이 바뀌었으니 pan/tilt 가 맞지 않는 것이 당연하고, 카메라 배치는 사용자 데이터라 임의로 바꾸지 않았다.
- **참조 이미지의 UI(`WBP_RenderPanel`)는 복원하지 않았다.** 그 화면은 현재 빌드가 쓰지 않는 이전 버전 위젯이며,
  사용자가 "환경만, UI 는 현재 유지"로 결정했다.
- 미사용 콘텐츠 분리의 이점(패키지 축소)은 이번 복원으로 되돌아갔다. 다시 줄이려면 BFS 루트를
  새 부팅맵(`LV_Park_01`)으로 두고 판정을 다시 해야 한다 — 그때도 **비-ASCII FName 은 UTF-16LE 로
  저장된다**는 2026-08-16 의 함정이 그대로 적용된다.
