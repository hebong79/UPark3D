## 2. 표준 작업 흐름

Terra QA가 Automation/PIE 중심의 기능 검증을 끝낸 뒤, Luna doc-writer가 변경과 맞닿은 인접 동작을 독립적으로 점검한다. 확인 대상은 변경 성격에 따라 인접 호출, UI/입력, JSON·저장/로드, 렌더·액터 상태에서 선택한다.

Luna는 기존 테스트 결과, PIE 결과, 로그, 스크린샷, 코드·에셋 참조를 교차해 `_workspace/{phase}_luna_behavior_impact_report.md`에 통과/실패/미검증과 근거를 기록한다. 실패 또는 고위험이면 Terra QA/구현으로 되돌려 수정·재검증한다. Luna는 이 단계에서 기능 코드를 직접 수정하지 않는다.

## 3. Goal/Loop 규칙

Goal/Loop는 기존 요청대로 Terra가 설계·영향도·구현·검증·사후 판단을 모두 단독 수행한다. Luna의 주변 동작 사후점검은 별도로 수행하지 않으며, Luna는 검증 자료를 받아 최종 한글 문서만 작성한다.
