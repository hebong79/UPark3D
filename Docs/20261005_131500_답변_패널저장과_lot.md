# 답변 — "게임 안 PresetMaker 패널의 저장 버튼은 lot 을 모른다"는 뜻

## 질문

#1185 보고에 "게임 안 PresetMaker 패널의 저장 버튼은 lot 을 모릅니다"라고 적었다. 이게 무슨 뜻인가.

## 답

### 프리셋 파일을 쓰는 길은 두 가지다

| 경로 | 누가 쓰나 | 코드 | lot 처리 |
|---|---|---|---|
| ① RPC `preset.save` | 웹 SettingManager 의 💾 버튼 | `PresetRpcModule.cpp` → `SavePresetsToJson(Path, Presets, Lot)` | 이번에 고쳤다. 받은 `lot` 을 파일에 쓴다. |
| ② 게임 화면 PresetMaker 패널의 "저장" 버튼 | 시뮬레이터 창에서 사람이 직접 누름 | `UPresetMakerWidget::SaveToJsonFile` → `SavePresetsToJson(FilePath, Presets)` | 손대지 않았다. `lot` 을 넘기지 않는다. |

### 저장은 파일 전체를 새로 쓴다

②는 "기존 파일에 프리셋만 덮는" 방식이 아니다.
`{isUnreal, datas}` 로 **파일 전체를 다시 쓴다**.
그래서 그 파일에 원래 `lot` 이 있었더라도, ②로 저장하는 순간 `lot` 키가 사라진다.

### 실제로 문제가 되는 순서

1. 웹에서 💾 → `001_Preset_Seo_1.json` 에 `datas` 와 `lot`(주차장 영역)이 함께 저장된다.
2. 누군가 시뮬레이터 창에서 PresetMaker 패널로 같은 파일을 열고, 면 하나를 고친 뒤 "저장"을 누른다.
3. 파일이 `{isUnreal, datas}` 로 다시 써져 **`lot` 이 사라진다**. 오류나 경고는 없다.
4. 다음에 웹에서 📂 로 열면 영역이 없으므로 아무것도 그리지 않는다. 지시대로 "없으면 무시"가 동작한 것이다.
   그래서 영역이 사라진 사실을 아무도 눈치채지 못한다.

패널의 "열기"는 `lot` 을 읽어도 그리지 않는다. 다만 그리기는 웹이 맡으므로 이것은 문제가 아니다.
**문제는 패널 저장이 lot 을 지우는 것 하나뿐이다.**

### 왜 안 고쳤나

#1185 요청은 RPC(`preset.save`/`preset.load`)만 다뤘다. 패널 동작을 바꾸는 것은 요청 범위 밖이라 보고만 했다.

### 고치려면 (선택지)

- **A. 패널 저장 시 기존 lot 보존(권장).** 같은 경로에 이미 파일이 있으면 그 파일의 `lot` 을 읽어 그대로 다시 쓴다.
  - 고칠 곳은 `SaveToJsonFile` 한 곳이다.
  - 다른 이름으로 저장하면 영역이 따라가지 않는다. 그 파일에는 원래 영역이 없었으니 맞는 동작이다.
- **B. 그대로 둔다.** 패널로 다시 저장하는 일이 드물다면 운영 규칙으로 막는다. 예: "lot 이 든 파일은 웹에서만 저장".
