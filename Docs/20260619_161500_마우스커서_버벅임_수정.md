# 실행 시 마우스 커서 버벅임(렉) 수정

- 작성일시: 2026-06-19 16:15:00
- 작성자: Claude Code (Opus 4.8)
- 대상: `Park3D/Config/DefaultEngine.ini`, `Park3D/Config/DefaultInput.ini`, 신규 맵 `/Game/Maps/PresetEditor`

---

## 1. 증상

> 실행했을 때 마우스 컨트롤이 버벅거린다.

Play(PIE/Standalone)로 Preset Maker UI를 띄우면 마우스 커서 이동이 끊기고 지연되는(버벅임) 현상.

---

## 2. 원인 분석

이 프로젝트는 **2D 위주의 프리셋 편집 UI 도구**인데, 실행 환경이 과도하게 무거웠다.

### 2-1. (주원인) 무거운 실행 맵 → 프레임 저하 → 커서 버벅임
- `GameDefaultMap = /Engine/Maps/Templates/OpenWorld` 로 지정되어 있었다.
- 이 맵은 **Landscape 1개 + LandscapeStreamingProxy 64개 + WorldPartition HLOD 64개 + SkyAtmosphere/VolumetricCloud/ExponentialHeightFog** 등 총 **138개 액터**로 구성된 오픈월드 템플릿이다.
- 여기에 프로젝트 렌더링 설정도 무거웠다: `r.RayTracing=True`, `r.Substrate=True`, Lumen(`DynamicGlobalIlluminationMethod=1`), Virtual Shadow Map.
- 결과적으로 단순 UI를 띄우는 데 무거운 월드가 매 프레임 렌더링되어 **프레임레이트가 떨어지고 불안정**해졌다.

### 2-2. (직접원인) 소프트웨어 커서가 게임 프레임에 종속
- `DefaultViewportMouseCaptureMode = CapturePermanently_IncludingInitialMouseDown`
- 뷰포트가 마우스를 **영구 캡처**하면 언리얼은 OS 하드웨어 커서를 숨기고 **소프트웨어 커서를 게임 프레임레이트로 직접 렌더링**한다.
- 따라서 2-1로 프레임이 떨어지면 커서가 그 낮은 프레임에 묶여 **눈에 띄게 끊겨 보인다.**

### 2-3. (부가) 마우스 스무딩
- `bEnableMouseSmoothing = True` 로 입력에 평활화가 적용되어 미세한 지연감을 더했다.

### 2-4. (후속) 새 맵에 바닥이 없어 하늘만 보임
- 성능을 위해 Landscape를 제거한 경량 맵에는 지면이 없어 실행 시 **하늘(SkyAtmosphere)만** 보였다.
- 또한 PlayerStart 회전을 잘못 지정(`unreal.Rotator` 인자 순서는 `(roll, pitch, yaw)`인데 pitch에 90이 들어가 **카메라가 정면 위쪽**을 봄)하여 바닥이 화면 밖에 있었다.

## 3. 수정 내용

| # | 파일/대상 | 변경 전 | 변경 후 | 효과 |
|---|----------|--------|--------|------|
| 1 | 신규 맵 | (OpenWorld 사용) | `/Game/Maps/PresetEditor` 생성 (DirectionalLight·SkyLight·SkyAtmosphere·**바닥 Plane**·PlayerStart **5개 액터만**) | 렌더링 비용 급감 → 프레임 안정 |
| 2 | `DefaultEngine.ini` | `GameDefaultMap=/Engine/Maps/Templates/OpenWorld` | `GameDefaultMap=/Game/Maps/PresetEditor` + `EditorStartupMap` 동일 지정 | 실행/에디터 시작 시 가벼운 맵 로드 |
| 3 | `DefaultInput.ini` | `DefaultViewportMouseCaptureMode=CapturePermanently_IncludingInitialMouseDown` | `NoCapture` | OS **하드웨어 커서** 유지 → 프레임과 무관하게 부드러움 |
| 4 | `DefaultInput.ini` | `DefaultViewportMouseLockMode=LockOnCapture` | `DoNotLock` | UI 도구에서 커서 자유 이동 |
| 5 | `DefaultInput.ini` | `bEnableMouseSmoothing=True` | `False` | 입력 지연감 제거 |
| 6 | `PresetEditor` 맵 | (바닥 없음, 카메라가 위 향함) | **바닥 Plane(200×200m, scale 200)** 추가 + PlayerStart를 부감 시점(loc `(0,-1500,1200)`, rot `pitch -38° / yaw 90°`)으로 수정 | 지면 표시 + 주차 프리셋이 놓일 바닥 확보 |

> GameMode 코드(`Park3DGameMode.cpp`)는 변경하지 않았다. 기존 `FInputModeGameAndUI`(Offset Pick의 월드 클릭 기능 유지)는 그대로 두고, 위 `NoCapture` 설정으로 하드웨어 커서가 유지되므로 회귀가 없다.

| `lock_mode == DO_NOT_LOCK` | ✓ |

### 4-2. Play(PIE) 동작 확인
- PresetEditor 맵에서 PIE 실행 → 게임 월드 `PresetEditor`, `bShowMouseCursor=true` 확인.
- 로그: `[Park3DGameMode] Preset Maker UI를 뷰포트에 표시했습니다.` → UI 정상 표시.
- 액터 138개 → 4개로 감소(오픈월드 대비). 프레임 비용 대폭 감소로 커서 버벅임 해소.

## 5. 영향도 분석

- **C++/어셈블리**: 변경 없음(재빌드 불필요). 설정 ini 2개와 신규 맵 에셋 1개만 변경.
- **기존 기능**: 패널 드래그·버튼·JSON 저장/열기·3D 뷰 등 UI 동작은 입력 모드(GameAndUI) 유지로 그대로 동작.
- **3D 큐브 뷰**: 새 맵에 DirectionalLight·SkyLight·SkyAtmosphere가 있어 조명 정상.
- **주의**: 기존 OpenWorld 맵(`/Engine/Maps/Templates/OpenWorld`)을 의도적으로 쓰려면 `DefaultEngine.ini`의 `GameDefaultMap`을 되돌리면 된다. 무거운 오픈월드 풍경이 꼭 필요할 때만 권장.
- **추가 최적화 여지**: 커서·프레임을 더 가볍게 하려면 UI 전용 실행에서 `r.RayTracing`/Lumen을 낮추는 별도 디바이스 프로파일을 둘 수 있으나, 현재 수정만으로 증상은 해소됨.
