## 2. 만든 파일

| 경로 | 역할 |
|---|---|
| `Tools/usd_export/run_export.py` | 호스트 래퍼. job JSON 생성 → `UnrealEditor-Cmd` commandlet 기동 → report/파일 실물로 판정 → 차량별 wrapper 작성 → pxr 로 실측 → `_summary.json` |
| `Tools/usd_export/export_cars.py` | commandlet 안에서 도는 쪽. `StaticMeshExporterUSDOptions` + `AssetExportTask` 로 1대씩 export, 한 대마다 `_report.json` 갱신 |
| `Park3D/Saved/USDExport/Cars/<slug>/<slug>.usdc` | 원본 export (metersPerUnit 0.01, upAxis Z, LOD 0~5 variantSet) |
| `Park3D/Saved/USDExport/Cars/<slug>/<재질명>.usdc` | 베이킹된 재질 사이드카(대당 10~20개), 메시가 상대 참조 |
| `Park3D/Saved/USDExport/Cars/<slug>/Textures/tire_Normal.png` | 유일하게 텍스처로 남은 채널(타이어 노멀). 나머지는 상수값으로 축약됨 |
| `Park3D/Saved/USDExport/Cars/<slug>/<slug>_omniverse.usda` | **Omniverse 에서 여는 파일.** `metersPerUnit=1`, 0.01 스케일 + 노멀 override |
| `Park3D/Saved/USDExport/Cars/_job.json`, `_report.json`, `_summary.json`, `_ue.log` | 실행 기록 |

실행:

```powershell
# pxr(usd-core)이 있는 파이썬으로 돌리면 실측까지 한 번에. 없으면 export/wrapper 만 하고 측정은 건너뛴다.
python Tools\usd_export\run_export.py                          # 23대, usdc, 512² 베이킹
python Tools\usd_export\run_export.py --cars 현대_쏘나타 --format usda --out D:\...\Test1
python Tools\usd_export\run_export.py --skip-export            # wrapper·측정만 다시
```

## 3. 설계 결정

- **디스크 이름은 전부 ASCII slug**(`run_export.py` 의 `SLUGS` 표). USD prim 식별자는 ASCII 만 허용되고 Ubuntu/DGX 로 넘길 때 한글 경로가 깨질 수 있다. 원본 prim 이름은 UE 가 `현대_쏘나타` 그대로 쓰지만 wrapper 의 defaultPrim 은 slug 이므로 소비자는 wrapper 만 보면 된다. 카탈로그 `prefabId` 는 `_summary.json` 에 같이 적어 두었다.
- **한글 이름은 job JSON(ensure_ascii) 으로 건넨다.** #124 의 "commandlet python 에서 한글이 깨진다 → chr() 조립" 과 같은 효과를, 소스·커맨드라인에 한글을 한 글자도 두지 않는 방식으로 얻었다. `export_cars.py` 는 주석 외 ASCII 만 쓴다.
- **판정은 파일 실물.** `run_asset_export_task` 반환값·종료코드는 기록만 하고, `ok` 는 `os.path.isfile(출력)` 이다.
- **베이킹 채널 6종**(가이드 6장 권장값). 기본 12종에서 Specular/Anisotropy/Tangent/Subsurface/AO/OpacityMask 를 뺐다. `PropertyEntry.Property` 는 `set_editor_property("Property", …)` 로 넣었고 23대 모두 `bake_properties_applied: true`.
- **wrapper 는 원본을 건드리지 않는다.** 스케일과 재질 override 는 wrapper 레이어의 `over` 로만 들어간다. 다시 export 해도 wrapper 는 `--skip-export` 로 재생성된다.

## 4. 밟은 함정 / 새로 안 것

1. **UE 5.8 베이커의 상수 노멀 결함이 여기서도 그대로 나온다.** 노멀 텍스처가 없는 재질마다 `inputs:normal = (0.498, -0.498, 1)` — 표면에서 35° 기운 셰이딩 노멀(#272 가 흑백 미로 무늬로 실측). wrapper 에서 `(0, 0, 1)` 로 덮었다(대당 9~19개). 단, override 경로가 `LOD0/SectionN/…` 이라 **LOD variant 를 LOD1~5 로 바꾸면 그 변형의 재질에는 안 먹는다**.
2. **유리 재질은 베이킹 결과가 전부 0 이다** — `clearglass/darkglass/lightglass/matteglass/orangeglass/redglass/windowglass` 의 diffuse·opacity·roughness·metallic 이 0, ior 1. #272 의 말대로 "값이 없다"는 뜻이고, 이대로면 Omniverse 에서 유리 서브셋이 **보이지 않는다**(대당 3~7개). 원인과 복구는 **6장** — 같은 날 후속으로 wrapper override 로 고쳤고 `materials_zero_opacity` 는 23대 전부 빈 목록이 됐다(1장 표의 "유리(값 없음)" 열은 복구 전 개수).
3. **첫 1대 119초, 이후 대당 3~7초.** 베이킹 셰이더가 DDC 에 채워지면 export 가 사실상 I/O 시간만 남는다. 23대 배치 전체가 commandlet 기동 포함 126초. #153 의 "512² 베이킹 18분" 은 808개 재질을 처음 굽는 값이었다.
4. **UE 가 내장한 pxr 은 단독 파이썬에서 못 쓴다.** `Engine/Plugins/Runtime/USDCore/Content/Python/Lib/Win64/X64/site-packages` 를 UE 파이썬 3.11 에 물리면 `import pxr` 은 되지만 `Plug.Registry` 가 비어 stage 를 못 열고, `PXR_PLUGINPATH_NAME` 을 `Resources/UsdResources/Win64/X64/plugins` 로 주면 **프로세스가 멈춘다**(2분 타임아웃, 출력 없음 — hdStorm/hgiGL 같은 렌더 플러그인까지 로드하는 것으로 추정, 미확인). 측정은 시스템 파이썬 venv 에 `pip install usd-core`(26.8, 3.13 휠 있음)로 했다.
5. **`Bash run_in_background` 는 timeout(최대 10분)에 걸린다** — 첫 배치를 그 방식으로 띄웠다가 PowerShell `Start-Process` 로 분리해 다시 띄웠다. 그 사이 죽은 첫 배치가 10대를 이미 뽑아 두었고(대당 5초라) 두 번째 배치가 `replace_identical` 로 덮어써 결과에는 영향이 없다.
6. **#204 의 "LOD 전혀 없음" 은 원본이 아니라 그 팩의 성질이다.** UE 메시는 6 LOD 를 갖고 있고 이번 export 는 `variantSet "LOD"` 로 LOD0~5 를 다 담았다(기본 선택 LOD0). 실시간 배치 비용을 줄이려면 소비자가 variant 를 바꾸면 된다 — 새로 export 할 필요가 없다.
7. **삼각형 수가 UE `get_num_triangles(0)` 과 USD LOD0 면 수가 두 대에서 다르다** — 레이 +34, SM7 +14,616(1.1%). USD 는 소스 메시 디스크립션(`bExportStaticMeshSourceData`)에서 나오고 UE 렌더 데이터는 빌드 때 퇴화 삼각형을 제거하므로 그 차이로 추정(미확인). 나머지 21대는 정확히 일치.
8. `assetInfo:identifier` 에 이 PC 의 절대 경로가 박힌다 — #272 도 같은 관찰. 합성에는 안 쓰이는 출처 메타데이터라 그대로 두었다. 텍스처 경로는 전부 상대(`Textures/tire_Normal.png`)이고 누락 0.

## 5. 검증된 것 / 안 된 것

**검증(수치·파일):** 23대 출력 파일 실물, wrapper bbox(전장 3.6~5.3 m, 바닥 z≈0), LOD variant 6개, 재질 바인딩 15/15 해석(쏘나타 GeomSubset 전부 bound), 텍스처 상대경로·존재, 삼각형 평균이 #204 와 일치.

**미검증:** Omniverse/Isaac 에서의 실제 렌더(이 PC 에 없음) — 따라서 **앞뒤 방향, 노멀 override 의 시각 효과, 유리 표현, 텍스처 색**은 화면으로 확인하지 못했다. 가이드 10장의 검증표 중 크기·Up Axis·계층·텍스처 존재만 수치로 닫혔다. #272 팩(다른 PC 산출)과의 파일 단위 대조는 하지 않았다(팩을 내려받지 않음).

## 6. 유리 서브셋 복구 (같은 날 후속, 사용자 승인)

4장 2번의 "유리가 전부 0" 을 고쳤다. **경로 B — wrapper 레이어 override** 를 택했다(#272 팩의 `_build/` 스크립트를 가져오는 A 안은 그 팩이 MDL/vMaterials 기반이라 우리 UsdPreviewSurface export 에 그대로 맞지 않고, 217 MB 다운로드와 MDL 의존이 생긴다. 노멀 override 가 이미 wrapper 에 있으니 같은 자리가 일관된다). 구현은 `Tools/usd_export/glass_fix.py`, `run_export.py` 가 wrapper 작성 직후 부른다. **원본 `<slug>.usdc` 는 무수정**(23개 전부 mtime 11:36 그대로).

### 6.1 왜 0 이었나 — 원인 확정
commandlet 으로 재질 인스턴스를 덤프해 보니 유리 7종은 전부 glTF 임포트의 `/InterchangeAssets/gltf/M_Transmission`(Blend Translucent, **Thin Translucent**, `TransmissionFactor 1`) 인스턴스다. UE 5.8 베이커는 이 조합에서 채널 값을 하나도 못 뽑는다 → UsdPreviewSurface 에 0 이 박힌다. 즉 "검정"이 아니라 "값 없음"(#272 의 관찰과 일치).

### 6.2 쓴 값과 근거
UsdPreviewSurface 에는 transmission 이 없어 `opacity` 로 근사했다. **색·IOR·거칠기는 UE 인스턴스 값 그대로**, 어둡기(opacity 와 창유리 틴트 배율)는 **#272 댓글 3건의 최종 분류를 따른 선택값**이다.

| 서브셋 | UE 인스턴스 값 (BaseColorFactor / IOR / Roughness) | wrapper 에 쓴 값 (diffuse / opacity / roughness / ior) | 역할(#272 분류) |
|---|---|---|---|
| clearglass(앞) | (0.80,0.80,0.80) / 1.45 / 0 | (0.80,0.80,0.80) / **0.30** / 0 / 1.45 | 헤드램프 렌즈 — 원본 색, 맑게 |
| windowglass | (0.750,0.824,0.803) / 1.45 / 0 | UE 색 × 0.15 = (0.11,0.12,0.12) / **0.85** / 0.05 / 1.45 | 창유리 — 짙은 선팅 |
| darkglass | (0.30,0.30,0.30) / 1.45 / 0 | UE 색 × 0.35 = (0.10,0.10,0.10) / **0.85** / 0.05 / 1.45 | 선루프·짙은 글레이징 |
| **smokedglass**(신설) | — | (0.32,0.32,0.32) / **0.60** / 0 / 1.45 | 후면 램프바·테일게이트 커버 — #272 `Glass_Smoke` "medium 0.32 smoke" |
| **Glass_Dark**(신설, darkglass 없는 차) | — | darkglass 와 동일 | 후면 clearglass 를 옮겨 담는 곳 |
| redglass | (0.988,0.096,0.058) / 1.45 / 0 | 색 그대로 / 0.70 / 0 / 1.45 | 테일램프 렌즈 — 손대지 않음(색) |
| orangeglass | (0.787,0.241,0, **a=0.6**) / 1.52 / 0 | 색 그대로 / 0.60(=UE alpha) / 0 / 1.52 | 방향지시등 렌즈 |
| lightglass | (1,1,1, a=0.6) / 1.45 / 0 | (1,1,1) / 0.60(=UE alpha) / 0 / 1.45 | K5·쏘렌토만 |
| matteglass | (1,1,1, a=0.6) / 1.45 / **0.5** | (1,1,1) / 0.60 / 0.5(=UE) / 1.45 | K5·쏘렌토·ZR-V |

굵은 숫자가 "선택값"이다 — 0.30/0.85/0.60/0.70 과 ×0.15/×0.35 는 UE 에서 온 값이 아니다. 이 PC 에 Omniverse 가 없어 화면으로 조정하지 못했다.

### 6.3 서브셋 분류 — #272 의 기하 기준 그대로
- **A.** `clearglass` 는 헤드램프 렌즈(앞)와 리어 램프바 커버·테일게이트 유리(뒤)가 한 서브셋에 섞인 잡탕이라 재질을 통째로 어둡게 하면 헤드램프가 죽는다 → 연결 성분 단위로 **뒤쪽(yn > 0.6)** 만 darkglass 로 옮긴다.
- **B.** darkglass 성분 중 **뒤쪽(yn > 0.6) 이면서 윗변이 그린하우스보다 낮은(zn < 0.75)** 것 → `smokedglass` + `Glass_Smoke`. 테일게이트 윈도우(윗변이 높다)·선루프는 darkglass 에 남는다.
- yn = 차량 bbox 로 정규화한 성분 중심 Y, zn = 성분 최고점 Z. 연결 성분은 정점을 0.01 cm 격자로 용접한 뒤 union-find.
- **앞/뒤 축은 두 경로로 확정**: ① `CarActor.cpp:496` 이 앞 번호판을 `Origin.Y − MountY` 에 단다(−Y = 앞, 번호판 캡처로 검증된 코드) ② 사이드미러 서브셋 중심이 yn 0.37~0.44(쏘나타·K5·머스탱·ZR-V), 포터는 실내 0.23·브레이크디스크 0.73 — 앞이 낮은 yn 이다.

### 6.5 미검증
- **화면.** opacity 근사가 Omniverse RTX 에서 어떻게 보이는지(UsdPreviewSurface 의 opacity 는 굴절 없는 투명도다), 선팅 어둡기·스모크 0.32 의 시각 결과, 헤드램프가 살아 있는지 — 전부 렌더 없이 값만 넣은 상태다.
- **렌더러 함정(#272 댓글):** RealTimePathTracing 은 투과 광선이 실내 지오메트리를 건너뛰어 차가 통째로 투명해 보인다. PathTracing 에서는 대시보드·시트가 정상이다. 이 증상은 재질 결함이 아니므로 값을 더 만지기 전에 렌더 모드부터 볼 것. 이 wrapper 는 렌더 모드를 pin 하지 않는다.
- LOD1~5 variant 로 바꾸면 이 override(서브셋 재분류·재질 값·노멀)는 LOD0 경로에만 있어 적용되지 않는다.
