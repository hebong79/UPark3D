# BUILD / COOK / STAGE / ARCHIVE 는 각각 무엇을 하는가

- 날짜: 2026-08-19
- 질문: `BuildPackage.bat` 실행 중 화면에 뜨는 `[BUILD] [COOK] [STAGE] [ARCHIVE]` 4단계 설명
- 관련 파일: `BuildPackage.bat`, `BuildProgress.ps1`

---

## 0. 한 줄 요약

**코드 만들고(BUILD) → 에셋 손질하고(COOK) → 상자에 담고(STAGE) → 배송지에 놓는다(ARCHIVE).**

이 4단계는 `BuildPackage.bat` 이 부르는 UAT 명령 하나가 순서대로 실행하는 것이다.

```
RunUAT.bat BuildCookRun -project=Park3D.uproject
    -noP4 -platform=Win64 -clientconfig=Development
    -cook -build -stage -pak -IgnoreCookErrors
    -archive -archivedirectory=<repo>\Package
```

`-build -cook -stage -archive` 플래그가 곧 화면의 네 단계다.

---

## 1. BUILD — C++ 소스를 실행 파일로 컴파일

`Park3D/Source/` 의 `.cpp` 를 컴파일·링크해 실행 파일을 만든다.

- 산출물: `Park3D/Binaries/Win64/Park3D.exe`
- 에셋(`Content/`)은 전혀 건드리지 않는다.
- 개발 중 C++ 만 고쳤을 때 따로 돌리는 아래 명령이 정확히 이 단계만 하는 것이다.

```
"C:\Program Files\Epic Games\UE_5.8\Engine\Build\BatchFiles\Build.bat" ^
    Park3D Win64 Development -Project=<...>\Park3D.uproject -WaitMutex
```

> 참고: `Build.bat` 을 `Park3DEditor` 타깃으로 돌리면 exe 가 아니라
> `UnrealEditor-Park3D.dll`(에디터 모듈)이 나온다. 단독 실행 exe 는
> `Park3D` 타깃이어야 한다 — `BuildPackage.bat` 헤더에 적힌 그 이유다.

## 2. COOK — 에셋을 그 플랫폼이 바로 먹을 수 있는 형태로 변환

에디터용 `.uasset` 을 런타임 포맷으로 "굽는다".

- 셰이더를 대상 RHI(D3D12/SM6)용으로 컴파일
- 텍스처를 GPU 압축 포맷(BC1/BC5/BC7 등)으로 변환
- 스태틱 메시를 GPU 버텍스/인덱스 버퍼 형태로 빌드
- 에디터 전용 데이터(소스 아트, 편집 메타)를 떼어냄
- 산출물: `Park3D/Saved/Cooked/Windows/`

**4단계 중 제일 오래 걸리고 제일 잘 터지는 단계다.** 이 프로젝트에서 실제로 겪은 것:

- 쿡이 83/579 에서 멈춘 것처럼 보인 사건(2026-08-16). 행이 아니라 차량 메시 34개
  동시 빌드로 커밋 차지가 98% 까지 차서 배치를 기다리는 중이었다.
  → `DefaultEngine.ini [ConsoleVariables]` 로 비동기 컴파일 동시성을 4로 제한해 해결.
- `-IgnoreCookErrors`: 레거시 BP UI 세트(`/Game/Core`, `/Game/Widgets`)가 설치되지
  않은 파일 다이얼로그 플러그인을 참조해 35건 컴파일 에러를 낸다. 실행에는 쓰이지
  않으므로 이 플래그로 넘긴다.
- **DDC(파생 데이터 캐시)가 비어 있으면 수십 분, 차 있으면 1~2분.** 같은 프로젝트라도
  쿡 시간이 크게 달라지는 이유가 이것이다(실측: 최초 58분 → 캐시 후 1분 13초).

## 3. STAGE — 실행에 필요한 것만 골라 배포 레이아웃으로 모음

구운 에셋 + exe + 엔진 런타임 DLL 을 실제 배포 폴더 구조로 복사한다.

- 산출물: `Park3D/Saved/StagedBuilds/Windows/`
- `-pak` 이 있어 구운 에셋은 낱개 파일이 아니라 `.pak` / `.ucas` / `.utoc`
  컨테이너로 묶인다.

> `BuildPackage.bat` 이 시작 전에 "Park3D.exe 실행 중이면 중단" 하는 이유가 이 단계다.
> 실행 중인 패키지가 파일을 잡고 있으면 스테이징이 실패하거나 낡은 exe 가 그대로 남는다.

## 4. ARCHIVE — 완성된 상자를 최종 납품 위치로 복사

`-archivedirectory` 가 가리키는 곳으로 스테이징 결과를 통째로 옮긴다.

- 산출물: `Package/Windows/` — 우리가 실제로 실행하는 `Package/Windows/Park3D.exe`
- 순수 복사라 제일 빠르다(실측 2초).

## 5. UAT 가 끝난 뒤 배치가 따로 하는 일

`Save/`(차량 카탈로그·주차 프리셋·카메라 위치 등 JSON 참조 데이터)는 **쿡 대상이 아니다.**
런타임에 그냥 읽는 텍스트 파일이라 UAT 4단계가 건드리지 않는다. 그래서 배치가 마지막에
직접 복사한다.

```
robocopy <repo>\Park3D\Save  <repo>\Package\Windows\Save  /MIR /XD Sim
```

`Park3DDataPaths::GetSaveRootDir` 가 `ProjectDir()\Save` 가 없으면
`<Stage>\Save` 를 보기 때문에 exe 옆에 둔다. 이게 빠지면 패키지는 뜨지만 차량 카탈로그·
프리셋·카메라가 전부 없다.

## 6. 화면의 숫자 읽는 법

```
[BUILD]   done  100%    elapsed 01:33
[COOK]    done  100%    elapsed 02:46
[STAGE]   done  100%    elapsed 03:38
[ARCHIVE] done  100%    elapsed 03:40
```

**elapsed 는 단계별 소요시간이 아니라 시작부터의 누적 시간이다.**
`BuildProgress.ps1` 의 `Format-Elapsed` 가 스크립트 시작 시각(`$started`) 기준으로
찍기 때문이다. 실제 단계 소요는 빼서 봐야 한다.

| 단계 | 누적 | 실제 소요 |
|---|---|---|
| BUILD | 01:33 | 1분 33초 |
| COOK | 02:46 | 1분 13초 |
| STAGE | 03:38 | 52초 |
| ARCHIVE | 03:40 | 2초 |

퍼센트의 근거가 되는 로그 라인:

- BUILD: `[3/8] Compile [x64] Park3DAppConfig.cpp` → `n/m`
- COOK: `LogCook: Display: Cooked packages 400 Packages Remain 260 Total 660` → `N/Total`

**쿡 중 퍼센트가 한 번씩 뒤로 가는 것은 정상이다** — 의존 에셋이 발견되면서 `Total` 이
진행 중에 늘어난다(500 → 576 → 660). 정지가 아니다.

## 7. 성공 판정

`RunUAT` 래퍼는 실패해도 0을 돌려주는 경우가 있어 **종료코드를 믿지 않는다.**
배치는 두 가지로 판정한다.

1. 로그에 `AutomationTool exiting with ExitCode=0` 마커가 있는가
2. `Package\Windows\Park3D.exe` 산출물이 실제로 있는가

## 8. 이 프로젝트에서 반복적으로 사고가 난 지점

**"패키지 복제 후 exe 만 교체" 방식은 BUILD 산출물만 갈아끼우는 것이다.**
개발 중 검증에 상용으로 쓰는 절차인데(`Package/Work135xx` 로 `robocopy /MIR` 복제 후
`Park3D\Binaries\Win64\Park3D.exe` 만 덮어쓰기), 여기서 반영되는 것은 C++ 변경뿐이다.

- 반영됨: C++ 소스 변경 (BUILD)
- 반영 안 됨: Content 에셋 변경 (COOK 필요), `Save/` JSON 변경 (robocopy 필요)

2026-08-18 "설정을 넣었는데 나무가 안 없어진다" 신고가 정확히 이 상태였다 —
exe 는 최신인데 배포본의 `Save/config_pmaker.json` 은 전날 것이었다.
**"넣었는데 안 먹는다" 는 실행본이 읽는 파일의 `LastWriteTime` 을 먼저 본다.**
