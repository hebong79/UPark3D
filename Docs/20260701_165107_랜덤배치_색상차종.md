# 랜덤 배치(색상 + 차량 종류) 구현

- 날짜: 2026-07-01 16:51:07
- 대상: `ParkingCarTypes.h`(FCarPos), `CarActor.cpp`(InitFromPos), `CarPlacementWidget.h/.cpp`(AddCarAtWorld)
- 유형: 기능 구현 (+ JSON 스키마 확장)
- 요청: "랜덤배치가 체크되면 마우스 클릭으로 차량 배치할 때마다 색상과 차량의 종류가 바뀌게."

## 1. 요구사항 / 결정

- 배치 모드에서 **Ctrl+좌클릭(바닥)** 으로 차량을 추가하는 경로(`AddCarAtWorld`)에서, `Check_Random` 체크 시 **차량 종류(프리팹/타입)와 도색을 무작위**로 지정.
- 미체크 시: 기존대로 콤보(Combo_Prefab/Combo_Type) 선택값 사용, 도색 없음(원본색).
- **색상 유지 방식(사용자 결정)**: JSON에 저장. → `FCarPos`에 `color` 필드 추가.

### 색상이 데이터에 필요했던 이유
차량 배치 시마다 `AddCarAtWorld` → `RefreshView()` → `Mgr->RebuildAll()`이 **모든 액터를 파괴·재생성**한다. 색을 액터에만 칠하면 다음 배치 때 초기화되므로, 색상은 `FCarPos`(데이터)에 저장해 재생성·저장/로드에서 유지되도록 했다.

## 2. 변경 내용

### (1) `ParkingCarTypes.h` — FCarPos에 color 추가
```cpp
UPROPERTY(...) int32 color = -1; // JSON key "color". -1=미도색(원본), 0~=ECarColor 정수
```
- **하위 호환**: Unity/기존 파일에 `color` 키가 없으면 로드 시 기본값 -1 유지 → 기존 차량은 원본색 그대로. 자동생성/일반 배치 차량도 -1(미도색).
- JSON에는 이제 `"color"` 키가 추가로 직렬화됨(사용자 승인 사항). Unity 원본 8필드 계약에서 1필드 확장.

### (2) `CarActor.cpp` — InitFromPos 도색 적용
```cpp
ApplyTransformFromData(MetersToUU);
if (ColorComp && CarData.color >= 0)
{
    ColorComp->SetColorByEnum((ECarColor)CarData.color);
}
```
- color가 -1이면 도색 안 함(원본). 0 이상이면 `ECarColor` 프리셋으로 carpaint 슬롯 도색.
- 메시 세팅 직후 호출 → 동적 머티리얼 생성/적용 가능.

### (3) `CarPlacementWidget.h` — 체크박스 바인딩
```cpp
UPROPERTY(meta = (BindWidgetOptional)) UCheckBox* Check_Random = nullptr; // 랜덤배치(색상+차량종류)
```
- **BindWidgetOptional**: WBP에 없어도 크래시 없음. 단, 기능 동작하려면 **WBP_CarPlacement의 체크박스 이름을 정확히 `Check_Random`으로** 지정해야 함.

### (4) `CarPlacementWidget.cpp` — AddCarAtWorld 랜덤 로직
```cpp
const bool bRandom = (Check_Random && Check_Random->IsChecked());
int32 ColorVal = -1;
if (bRandom && Catalog.Num() > 0)
{
    const int32 Pick = FMath::RandRange(0, Catalog.Num() - 1);
    PrefabId = Catalog[Pick].Idx;   // 무작위 차량 프리팹
    Type     = Catalog[Pick].Type;  // 해당 프리팹의 타입
    ColorVal = FMath::RandRange((int32)ECarColor::White, (int32)ECarColor::Purple); // 무작위 도색(0~9)
}
else { /* 기존: 콤보 선택값 */ }
...
P.color = ColorVal;
```
- 종류는 **카탈로그 항목을 무작위 선택**(프리팹 id + 타입 동시 결정). 색은 `ECarColor` 10종(White~Purple) 중 무작위.

## 3. 영향도 분석

- **JSON 스키마**: `color` 키 1개 추가(9필드). 기존 파일 로드는 하위 호환(-1 기본). 저장 파일은 Unity로 되돌릴 때 `color` 키가 포함됨 — Unity 로더가 알 수 없는 키를 무시하면 무방, 엄격 파싱이면 주의(사용자 승인).
- **기존 동작 회귀**: 랜덤 미체크 시 배치 경로·값 동일. 자동생성(AutoCreate)·이동/회전·저장/열기 무변경. color 기본 -1이라 기존 차량 외형 불변.
- **의존성**: 신규 include 없음(ECarColor는 ParkingCarTypes.h, CheckBox 헤더 기존 포함). `UCarColorComponent::SetColorByEnum` 기존 API 사용.
- **적용 지점**: 랜덤은 `AddCarAtWorld`(마우스 클릭 배치)만. 버튼 `자동생성`은 대상 아님(요청 문구 "마우스 클릭").

## 4. 검증

- **유닛테스트**: 배치/도색은 UWorld·액터·머티리얼·입력 의존이라 자동 유닛테스트 대상 밖. (색 매핑 `ColorForEnum`은 기존 순수 함수.)
- **동작 확인(사용자, Ctrl+Alt+F11 컴파일 후)**:
  1. WBP_CarPlacement의 랜덤배치 체크박스 이름이 **`Check_Random`** 인지 확인(아니면 바인딩 안 됨).
  2. `배치 시작` → **랜덤배치 체크** → 바닥 Ctrl+좌클릭 반복: 매번 **차량 종류와 색상이 무작위**로 배치되는지.
  3. 저장 → 열기: 색상/종류가 유지되는지(JSON `color` 저장 확인).
  4. **랜덤 해제**: 콤보 선택 차량 + 원본색으로 배치(기존 동작)인지.

## 5. 후속 참고

- WBP에 `Check_Random` 체크박스가 아직 없다면 UMG에서 추가 필요(요청 스크린샷상 존재). 이름만 맞추면 동작.
- 색 팔레트는 `ECarColor` 10종 고정. 특정 색만 랜덤 풀로 제한하려면 RandRange 범위를 조정.
