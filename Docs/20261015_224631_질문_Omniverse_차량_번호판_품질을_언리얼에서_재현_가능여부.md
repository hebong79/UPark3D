# 질문: Omniverse 의 차량·차량 번호판 품질을 언리얼에서 같은 수준으로 끌어올릴 수 있나?

## 결론

**가능하다.** 두 항목의 사정은 다르다.

- **차량:** 차이는 재질에 있다. 메시는 언리얼에서 내보낸 것과 같다. 도색(클리어코트 + 출고색)과 크롬·림·타이어 값을 옮기면 된다. 상세는 같은 날 문서 `20261015_192340_질문_Omniverse_품질에_맞춘_언리얼_차량건물_업그레이드_가능여부.md` 에 있다.
- **번호판:** 이미 거의 같은 수준이다. 2026-09-21 에 Omniverse 의 `plategen.py` 를 그대로 가져와 바탕을 구웠다. 텍스처 해상도는 언리얼이 더 높다. 남은 차이는 홀더 메시, 필름식 판의 클리어코트, 판 테두리 모서리 정도로 작다.

미검증: 문서와 코드를 조사한 결과다. 두 렌더러의 캡처를 나란히 놓고 비교하지는 않았다.

## 번호판 비교

## 차량 비교 요약

같은 날 문서의 결론을 요약한다.

| 순위 | 항목 | 방법 |
|---|---|---|
| 1 | 도색 | 클리어코트 마스터 재질 + Omniverse 출고색 표(펄 화이트·메탈릭·솔리드 3분류, clearcoat 1.0 / 0.03). **`car.setColor` 가 쓰는 `BaseColorFactor` 파라미터 이름을 유지한다** |
| 2 | 크롬·림·타이어 | 슬롯별 값 교정(크롬 0.80/1/0.08, 림 0.70/1/0.28, 타이어 0.025/0/0.78) |
| 3 | 유리 | 언리얼은 이미 투과한다. 나란히 캡처해 보고 IOR·틴트를 맞춘다 |
| — | 형상 | 할 일 없음. Omniverse 는 VRAM 때문에 LOD2 를 쓰고, 언리얼은 LOD0 까지 쓴다 |

화면에 보이는 차이는 렌더러에서도 생긴다. Omniverse 는 패스 트레이싱(16 spp)에 HDRI 를 쓰고, 언리얼은 실시간 Lumen 을 쓴다. 재질을 맞춰도 반사와 그늘의 질감은 완전히 같아지지 않는다. 같은 수준을 정지 캡처에만 요구한다면 언리얼 Path Tracer 를 검토할 수 있다. 다만 SceneCapture 에서 Path Tracer 가 동작하는지는 확인하지 않았다.

## 제약

- `Content/` 는 git 밖에 있다. 재질은 `Tools/` 의 커맨드릿 파이썬으로 만들어야 재현된다(`Tools/plate_kinds/run_build_assets.py` 선례).
- 재질 에셋을 바꾸면 **재쿡**해야 한다. exe 만 교체해서는 정본에 반영되지 않는다.
- 이번 세션은 언리얼 에디터 MCP 연결에 실패했다(ECONNREFUSED).
- 도색을 바꾸면 색 마스크 기반 `scenario.*` 가림률의 기준선이 움직일 수 있다. 깊이 기반 `withTruth` 는 영향을 받지 않는다.

**결론이 바뀐다.** "Omniverse 가 차량·번호판 품질에서 앞선다" 는 전제는 이 비교에서 성립하지 않았다. 남은 차이는 셋이다.

1. **그늘이 파랗고 어둡다**(조명). 기본맵은 `LightSettings_Base.json` 으로 조절할 수 있다. 서신·객리단은 UDS 가 조명을 쥐고 있어 따로 봐야 한다.
2. **도색에 하늘 반사가 약하다**(클리어코트 없음). 체감 차이는 작다.
3. **햇빛 받는 흰색이 날아간다**(노출). 이것도 조명 문제다.

한계: Omniverse 기준 이미지는 9월 렌더라 조명과 구도가 완전히 같지는 않다. 두 렌더러를 같은 시각, 같은 조건으로 찍은 비교가 아니다.

## 2단계: 조명 — 하늘빛 색 `skyColor` 신설과 기본맵 조정 (2026-10-16)

마스터 지시는 "권장대로 진행"(1번 안, 조명부터)이었다.

### 원인 좁히기

- **그늘 채움광으로는 안 된다.** `shadowFillIntensity` 를 0→3 으로 올려도 그늘 판 B/R 은 2.10→2.01 에 그쳤다. 채움광은 피치 −60° 의 고정 방향 빛이라 수직인 번호판 앞면에 거의 닿지 않는다(`light_sweep_shadowfill.json`).
- **UDS 레벨은 문제가 없다.** 서신·객리단에 서 있는 차 앞판을 정면에서 찍었더니 B/R 이 0.97~1.09 로 중립이었다(`uds_seosin_plate.jpg`, `uds_gaek_plate.jpg`). 판 바탕 밝기는 246~247 로 포화 직전이지만 250 이상 픽셀은 없었다. 객리단 5대 중 4대는 카메라가 차체에 묻혀 판이 안 보였다(측정 대상 제외, 스크립트의 자리 계산 문제).
- 따라서 파란 그늘은 **기본맵 하늘빛(SkyLight)의 색**에서 온다. 기본맵 SkyLight 는 대기를 실시간 캡처하는데, 그 빛이 진한 파랑이다.

### 영향과 한계

- **기본맵에만 영향이 있다.** 서신·객리단(UDS)은 이 키를 적용하지 않는다(그쪽은 이미 중립).
- 기본맵의 하늘빛이 강해지고 따뜻해져서, 기본맵에서 잰 `scenario.*` 가림률 기준선이 움직일 수 있다. 시나리오는 자기 `lightFile` 을 적용하므로, 그 파일에 SkyColor 키가 없으면 흰색으로 되돌아간다.
- 하늘빛은 반사에도 쓰인다. 그래서 차체·유리에 비치는 하늘도 덜 파래진다. 3/4 화면에서 눈에 띄는 차이는 없었다.
- 판정은 흰 쏘나타 1대, 한 시각(태양 고도 44.5°), Omniverse 9월 렌더 2장을 기준으로 했다.

## 권장 순서(최초 안)

1. 같은 차, 같은 구도, 같은 번호판 종류로 Omniverse 와 언리얼 캡처를 나란히 찍어 차이를 확정한다.
2. 차량 도색 클리어코트를 먼저 적용한다. 체감 차이가 가장 크다.
3. 번호판은 클리어코트(필름식)와 홀더만 추가한다. 둘 다 작은 작업이다.
