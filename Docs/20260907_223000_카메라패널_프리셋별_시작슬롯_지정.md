## 1. 승인된 결정 넷

시안 두 장(배치안·조작안)을 실제 화면 위에 그려 보여 주고 받은 답이다.

| 항목 | 결정 | 이유 |
|---|---|---|
| 동작 | **기록만** — 프리셋에 값을 저장하고 바닥 번호는 그대로 둔다 | 화면의 숫자가 임의로 바뀌지 않는다. 재부여는 하지 않는다 |
| 클릭 대상 | **레벨 면 + 프리셋 면 모두** | 지금 바닥에 번호가 그려지는 대상과 같다 |
| 버튼 | **없음** — LShift+클릭만, 자리에는 안내 문구 | 수정키를 누르는 것 자체가 지정 의사다. 모드를 켜 두고 잊는 사고가 없고, Ctrl 피킹과 수정키가 갈려 간섭도 없다 |
| 배치 | **B안** — 프리셋 줄 아래 새 줄 | 라벨·안내 문구를 온전히 쓰고 나중에 버튼을 더 둘 자리가 남는다 |

## 2. 저장되는 값

`FCamDir.start_slot`(0=미지정). JSON 직렬화는 `FJsonObjectConverter` 가 구조체를 그대로 돌리므로 키가 자동으로 `start_slot` 이 된다.

```json
{ "idx": 2, "sname": "Preset 2", "cam_id": 1, "preset_id": 2,
  "pan": 149.23, "tilt": 18.0, "zoom": 1.5,
  "start_slot": 12 }
```

Unity 파서는 모르는 키를 무시하므로 파일 호환이 유지되고, 이 키가 없는 옛 파일은 0(미지정)으로 읽힌다(테스트 `Park3D.CameraControl.JsonFixture` 가 이 값을 못 박는다).

## 3. 점 → 번호 판정

`AParkingPresetManager::FindSlotNumberAtWorld` 를 새로 뒀다. **바닥에 번호를 그릴 때 쓰는 바로 그 목록**(`CollectSlotNumbers`) 위에서 판정하므로 화면 숫자와 어긋날 수 없다.

- 판정은 면 축으로 옮겨 반쪽 크기와 비교하는 OBB 검사다. 이를 위해 슬롯 정보에 긴 변(`LengthCm`)을 추가했다(그전에는 글자 크기 상한용 짧은 변만 있었다).
- 겹치면 먼저 만난 면(프리셋 면 → 레벨 면 순)을 준다.
- 클릭 Z 는 무시한다 — 클릭은 바닥을 맞히고 면은 두께가 0 이다.

## 4. 조작

`UCameraControlWidget::TickStartSlotPick` 이 매 틱 돈다.

1. 좌클릭 상승 에지를 만든다(`Park3DPickInput::FLeftClickEdge`). `WasInputKeyJustPressed` 는 Slate 가 입력을 가져가면 영영 false 라 쓸 수 없다.
2. Shift 는 **PlayerController 와 Slate 양쪽**을 본다. 패널이 떠 있으면 PlayerController 만으로는 못 본다(Ctrl 피킹이 겪은 것과 같은 사정).
3. 패널 위 클릭은 무시한다. 에지는 조건과 무관하게 매 틱 소비해야 한다 — 안 그러면 패널에서 누른 클릭이 밖으로 나온 뒤 "방금 눌림"으로 되살아난다.
4. 바닥 트레이스 → 번호 조회 → 칸에 표시 + 알림.

찍은 값은 **칸에만** 들어간다. 프리셋 반영은 기존 필드와 같이 "수정"(또는 "추가")이 하고, 파일에 남는 건 "저장"이다. 실수로 찍어도 되돌릴 여지가 두 단계 있다.

## 5. RPC

- `cam.applyPreset`/`savePreset`/`loadPreset` 응답에 `startSlot` 이 실린다. 기록 전용 값이라 외부에서 읽을 길이 없으면 넣은 의미가 없다.
- `cam.savePreset` 에 `startSlot` 을 주면 그 값으로 덮는다. 카메라 상태에서 읽어 낼 수 없는 값(사람이 정한다)이라 **준 경우에만** 덮고, 아니면 기존 값을 지킨다.

## 7. 함정 기록

- **합성 키 입력이 UE 에 안 들어간다.** `keybd_event(VK_LSHIFT, scan=0, flags=0)` 은 클릭은 잡히는데 Shift 가 `pc=0 slate=0` 이었다. `KEYEVENTF_SCANCODE` 로 스캔코드(0x2A)를 실어 보내니 `pc=1 slate=1` 이 됐다. `SendInput` 은 이 하네스에서 아예 전달되지 않았다(클릭 에지조차 안 생김).
- **"안 먹는다"의 절반은 클릭 지점이었다.** 중간에 뷰가 바뀐 줄 모르고 옛 좌표를 계속 찍어 "그 자리에 주차면이 없습니다"만 반복했다. 판정은 그때그때 캡처한 화면에서 좌표를 다시 읽어야 한다.
- **테스트에서 합성 프리셋은 레벨 면과 겹칠 수 있다.** 에디터 월드(LV_Park_01)의 실제 주차면과 원점 부근에서 겹쳐 "면 밖" 판정이 참이 되지 않았다 → 프리셋 오프셋을 (500,500)m 로 멀리 뒀다. 또 조회 API 는 매니저 목록(`ResolvePresets`)을 보므로 테스트도 `StoredPresets` 에 담아야 실제 경로와 같아진다.

## 8. 남은 것

- 번호를 **다시 매기는** 기능은 이번 결정에서 제외했다(기록만). 필요해지면 `start_slot` 을 기준으로 `RebuildSlotNumbers` 의 시작값을 바꾸는 쪽으로 열면 된다.
- 파일 저장 왕복은 자동화 테스트로만 확인했다. 패널의 "저장"은 파일 대화상자를 띄워 자동 클릭으로 검증하지 않았다.
