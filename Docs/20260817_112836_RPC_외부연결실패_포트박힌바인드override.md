# RPC 외부 연결 실패 — 포트에 박힌 바인드 override 가 포트 변경으로 빗나갔다

- 작성: 2026-08-17 11:28
- 증상 신고: SettingAgent 장비 설정에서 `연결 실패 · 5000ms · Park3D RPC 통신 실패
  (http://192.168.0.10:13520/rpc cam.getPTZ): The operation was aborted due to timeout`
- 대상: `Park3D/Config/DefaultEngine.ini`, `Park3D/Config/DefaultGame.ini`, `.mcp.json`,
  `Park3D/Save/Config/config_pmaker.json`

## 1. 무엇이 원인이었나

**RPC 만 루프백에 바인드돼 있었다.** 방화벽·인증·앱 미기동 어느 것도 아니다.

| 대상 | 결과 |
|------|------|
| `http://127.0.0.1:13520/rpc` | 200 |
| `http://192.168.0.10:13520/rpc` | 연결 거부 |

listen 상태가 갈라져 있었다 — RPC 는 `127.0.0.1:13520`, 영상은 `0.0.0.0:13600/13611/13612`.
**영상 URL 은 되는데 제어 URL 만 안 되는** 모습이 여기서 나온다(영상은 자체 소켓이라 엔진 HTTP 서버 설정과 무관).

기동 로그 한 줄에 답이 있었다.

```
[RPC] 리슨 포트 결정: 13520
[RPC] JSON-RPC 서버 시작: http://localhost:13520/rpc (bind=localhost, auth=ANONYMOUS(우회), method 116개)
```

`bind=localhost` 인 이유: 외부 바인드 지정이 **포트에 박혀 있었다.**

```ini
[HTTPServer.Listeners]
+ListenerOverrides=(Port=13510,BindAddress=any)
```

그런데 `Save/Config/config_pmaker.json` 의 `rpc_port` 가 **13520** 으로 바뀌면서 이 목록이 빗나갔고,
엔진 기본값(`localhost`)으로 **조용히** 폴백했다. 실패를 알리는 로그도, 에러도 없다.

같은 파일의 주석이 이미 이 사고를 예고하고 있었다 — *"포트와 결합된다: -RpcPort= 로 다른 포트를 쓰면
이 override 가 매칭되지 않아 조용히 localhost 로 폴백한다"*. 경고가 있었어도 포트를 바꾼 쪽
(`config_pmaker.json`)과 바인드를 여는 쪽(`DefaultEngine.ini`)이 **다른 파일**이라 함께 움직이지 않았다.

## 2. 포트 결정 순서(참고)

`RpcServerSubsystem` 기준, 뒤로 갈수록 우선:

1. `DefaultGame.ini [RpcServer] Port`
2. `Save/Config/config_pmaker.json` 의 `rpc_port`
3. 커맨드라인 `-RpcPort=`(`0` 이면 서버 미기동)

즉 **ini 를 고쳐도 `config_pmaker.json` 이 있으면 그쪽이 이긴다.** 이번 사고도 여기서 시작됐다.

## 3. 조치 (13520 을 정본으로)

| 파일 | 변경 |
|------|------|
| `Park3D/Config/DefaultEngine.ini` | `+ListenerOverrides=(Port=13520,BindAddress=any)` 추가(13510 도 유지) + 사고 경위 주석 |
| `Park3D/Config/DefaultGame.ini` | `[RpcServer] Port` 13510 → 13520 (폴백까지 일치) |
| `.mcp.json` | `PARK3D_RPC_URL` 13510 → 13520 |
| `Park3D/Save/Config/config_pmaker.json` | `rpc_port` 13520 (이미 바뀌어 있던 값을 이제 저장소에 반영) |

전역 `DefaultBindAddress=any` 는 쓰지 않는다 — 이 프로세스의 **모든** HTTP 리스너(현재·미래)가 상속으로
외부에 열리고, 그런 리스너에는 우리 인증 게이트가 없다. 포트별 override 를 유지한다.

## 4. 검증(실측)

```
[RPC] JSON-RPC 서버 시작: http://0.0.0.0:13520/rpc (bind=any, auth=ANONYMOUS(우회), method 116개)
LocalAddress 0.0.0.0  LocalPort 13520
```

신고와 같은 메서드로 확인:

| 대상 | 결과 |
|------|------|
| `POST http://127.0.0.1:13520/rpc cam.getPTZ` | 200 (`pan 19.80 / tilt 8.70`) |
| `POST http://192.168.0.10:13520/rpc cam.getPTZ` | **200** (동일) |

## 5. 다음에 포트를 바꿀 때

포트를 바꾸는 곳은 세 군데인데(위 §2), **바인드를 여는 곳은 `DefaultEngine.ini` 하나다.**
포트를 바꾸면 그 목록에 새 포트를 넣고, 기동 로그의 `bind=` 값으로 실효 적용을 확인할 것.
`bind=localhost` 면 외부에서는 어떤 방화벽 설정으로도 붙지 않는다.

## 6. 별건으로 남기는 관찰

신고 화면의 영상 URL 이 `http://192.168.0.10:13611/stream` 인데, 같은 화면의 안내가
"camId 1 의 영상 포트는 13601 입니다 — 지금 13611 는 다른 카메라를 봅니다" 라고 말한다
(영상 포트 = 13600 + camId). 이번 연결 실패의 원인은 아니지만, 그대로 두면 **다른 카메라 화면**을 보게 된다.
