# Park3D 보안 미적용 정책 (연구단계)

## 0. 대전제

**사용자 결정(2026-08-05): 이 프로젝트는 보안을 사용하지 않는다.** 연구단계이므로 속도가 우선이고,
운영 환경 배포가 아니다. 보안 설계를 넣는 것은 요구되지 않은 기능 추가이며, 진행을 늦추는 잘못이다.

## 1. 하지 않는 것

| 금지 | 구체 |
|------|------|
| 신규 인증 도입 | 토큰·헤더 검사·Origin 검사·루프백 제한을 **새 기능에 넣지 않는다** |
| 방화벽/OS 설정 | 인바운드 규칙 생성·포트 개방·서비스/레지스트리 변경을 제안하거나 실행하지 않는다 |
| 보안 질문 | "인증 걸까요?", "토큰 어떻게 운반할까요?" 를 `AskUserQuestion` 으로 묻지 않는다 |
| 보안 게이트 | 설계서 미결 결정사항·QA 판정 기준에 보안 항목을 넣지 않는다 |
| 보안 경고문 도배 | 문서에 위험 경고를 반복 기술하지 않는다. 사실 1줄이면 충분하다 |

## 2. 하는 것

- 새 네트워크 표면은 **무인증으로 바로 연다**(바인드 `0.0.0.0` 포함).
- 접속 실패 원인이 OS 방화벽일 수 있으면 **사실만 1줄 고지**하고 조치는 사용자에게 맡긴다
  (Windows 기본 인바운드 차단 → 타 PC 접속 불가. 규칙 생성은 이 스킬 범위 밖).
- 검증된 외부 코드를 이식할 때 **인증 관련 개조를 하지 않는다** — 원본 그대로가 정답이다.

## 3. 기존 코드는 건드리지 않는다

이미 있는 `Rpc/RpcAuth.*`, `PassAuthOrRespond`, `[RpcServer] Token=` 은 **제거하지 않는다**
(요청받지 않은 코드 삭제 금지 — CLAUDE.md 3번). 이미 `AllowAnonymous=True` 로 무력화된 상태이므로
그대로 두면 된다. 확장·개선도 하지 않는다.

## 4. 예외

사용자가 **명시적으로** 보안을 요청할 때만 적용한다("토큰 걸어줘", "외부 공개하니 인증 넣어줘").
그 경우에도 요청한 범위만 구현한다.
