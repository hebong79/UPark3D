# 프리셋 파일에 주차장 영역(`lot`) 저장·열기 — 보드 #1185

## 1. 요청

SettingManager(보드 #1185, 2026-10-05)의 요청이다. 마스터 지시는 다음과 같다.

> 프리셋메이커에서 파일을 저장할 때 주차면 영역도 json 파일에 저장해 줘. 열기 부분도 수정해 줘.
> 주차면 영역이 있으면 그려 주고, 없으면 무시한다.

프리셋 파일은 시뮬레이터가 쓰고, `file.write` 같은 RPC는 없다. 그래서 웹은 파일에 영역을 직접 넣을 수 없었다.
변경 전에는 `preset.save {lot}`를 보내면 `warnings:[{kind:unknownParam,key:lot}]`만 돌아오고 `lot`은 버려졌다.

#1168의 `lot.set`과는 다른 기능이다. `lot.set`은 **레벨마다** `Save/3D/Lot/Lot_<레벨>.json`에 영역을 하나씩 둔다.
이번 요청은 **프리셋 파일마다** 영역을 담는 것이다(예: `001_Preset_Seo_1.json`이 자기 영역을 가진다).

## 2. 계약(추가형)

| 메서드 | 변경 |
|---|---|
| `preset.save {…, lot?}` | `lot = {points:[{x,y}], source?}`를 파일 **루트 `lot` 키**에 **그대로** 쓴다(해석하지 않는다). 생략하거나 `null`이면 키를 쓰지 않는다. 옛 파일의 `lot`도 이어받지 않는다. 응답에 `lot:bool`(이번에 썼는지)을 추가했다. |
| `preset.load` | `lot` 키가 있는 파일도 전과 똑같이 읽는다. 파일에 `lot`이 있으면 응답 `{ok, count, lot}`에 그대로 실어 준다. **바닥에 그리지는 않는다.** 그리기는 SettingManager가 `preview.show`(id `drawing-lot`)로 한다. |
| `file.read {kind:preset}` | 변경 없음. 파일 내용을 그대로 돌려주므로 `content.lot`이 보인다. |

`lot`은 모양만 검사한다. 객체여야 하고, `points`는 3..2000개 배열, 각 점은 숫자 `x`·`y`를 가진 객체여야 한다.
어기면 `-32602`(`bad_params`)를 돌려주고 **파일을 쓰지 않는다**. 이유는 파일에 쓰레기가 남는 것을 막기 위해서다.
점 상한 2000은 `preview.show`·`lot.set`과 같다.
좌표는 SettingManager가 정한다. 월드 미터이고 `preset.numbers`·`lot.set`과 같은 좌표계다.

파일 형태:

```json
{ "isUnreal": true, "datas": [ … ], "lot": { "points": [{"x":0,"y":0}, …], "source": "boundary" } }
```

## 3. 변경 파일

- `PresetMakerWidget.h/.cpp`
  - `SavePresetsToJson(Path, Presets, Lot = nullptr)`: DTO를 `FJsonObject`로 바꾼 뒤 `lot`을 얹어 직렬화한다. 출력은 전과 같은 pretty 형식이다.
  - `LoadPresetsFromJson(Path, Out, OutLot = nullptr)`: 한 번 파싱한 루트에서 DTO와 `lot`을 함께 꺼낸다.
  - 두 함수 모두 기본 인자를 쓰므로 기존 호출부(패널·`bay.*`·`scenario`·매니저 config 로딩)는 고치지 않았다.
- `Rpc/Modules/PresetRpcModule.cpp`: `ReadPresetFileLot`(검사)를 추가하고 `preset.save`·`preset.load`에 연결했다.
- `Rpc/RpcHelpTable.cpp`: `preset.save`(`lot` 파라미터·반환)와 `preset.load`(`lot?`) 설명을 고쳤다.
- `Tests/PresetMakerJsonTest.cpp`: `Park3D.PresetMaker.FileLot` 테스트를 새로 넣었다. 검사 항목은 다음과 같다.
  - `lot`과 함께 저장한 뒤 다시 읽으면 프리셋과 `lot`이 같다.
  - 옛 함수 형태로도 읽힌다.
  - `lot` 없이 다시 저장하면 키가 사라진다.

## 5. 추가 — 패널 저장이 lot을 지우지 않게 (마스터 선택 A, 같은 날)

### 문제

게임 화면 PresetMaker 패널의 "저장"은 파일 전체를 `{isUnreal, datas}`로 다시 쓴다.
그래서 웹이 넣어 둔 `lot`이 경고 없이 사라졌다.
자세한 설명은 `Docs/20261005_131500_답변_패널저장과_lot.md`에 있다.

### 수정

- `UPresetMakerWidget::SavePresetsToJsonKeepingLot(Path, Presets)`를 새로 만들었다.
  - 같은 경로에 파일이 이미 있으면, 그 파일의 `lot`을 읽어 그대로 다시 쓴다.
  - 새 파일이면 `lot` 없이 쓴다.
- 패널 저장 함수 `SaveToJsonFile`이 이 함수를 쓰도록 바꿨다.
  패널에서 저장하는 길은 `HandleSave` → `SaveToJsonFile` 하나뿐이다(grep으로 확인).
- RPC `preset.save`는 그대로다. `lot`을 생략하면 키를 쓰지 않는다(계약 그대로).
  `bay.toPresets`·`preset.importFile`도 손대지 않았다. 둘 다 새 내용을 만드는 경로다.

### 검증

- 빌드 2종 Succeeded. Automation **160/160**.
- `FileLot` 테스트에 두 경우를 추가했다.
  - 2b: 패널 저장으로 프리셋을 바꿔 덮어써도 `lot`이 남는다(faceCount 4→6 반영).
  - 2c: 새 파일로 저장하면 `lot`이 없다.
- **실제 패널 버튼 클릭은 하지 않았다.**
  버튼이 Windows 저장 대화상자를 거치는데, 합성 입력이 사용자 창으로 새어 들어간 전례(09-08)가 있어서다.
  버튼 뒤의 함수(`SaveToJsonFile`)는 자동화 테스트가 직접 검증한다.
