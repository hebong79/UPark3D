## 2. 원인 진단

### 2-1. 증상

메인 뷰포트 스크린샷 실측:

| 영역 | 루마 | 채도 | 표준편차 |
|------|------|------|---------|
| 메인 뷰포트 지면 | **171.7** | 10.4% | **2.9** |
| 카메라 캡처 지면 | 110.4 | - | - |

지면 표준편차 2.9 = **질감이 완전히 소실**된 상태. 차량도 전부 흰색으로 떠 색 구분이 되지 않았다.

### 2-2. 원인 — 노출이 달빛 기준으로 고정돼 있었다

`PP_FixedExposure` 의 `AutoExposureMin/MaxBrightness = 0.0`, 즉 **EV100 0 고정**이다. `ExtendDefaultLuminanceRange=True` 에서 EV100 0 은 약 0.1 cd/m²(달빛 수준)에 맞춘 노출값이라, 한낮 조명(EV100 12~15가 정상)을 받으면 하얗게 탄다.

직전 작업에서 조명을 어둡게 유지했을 때는 이 과다 노출이 우연히 상쇄돼 문제가 드러나지 않았고, 조명을 한낮으로 올리자 표면화됐다.

> **직전 작업의 판단을 정정한다.** 당시 "`PP_FixedExposure` 는 CCTV 밝기 일관성을 위한 의도된 설계이므로 보존"이라고 판단했다. 고정 자체(Min==Max)는 옳았지만, **고정값 0 이 부적절**하다는 점을 놓쳤다. 이번 구현은 고정 구조는 유지하고 그 값만 조절 가능하게 만든다.

## 3. 구현 내용

### 3-1. 신규 모듈

| 파일 | 역할 |
|------|------|
| `Light/LightControlTypes.h` | `FLightSettings` — 6항목 |
| `Light/LightControlLibrary.h/.cpp` | 순수 함수: JSON 직렬화/역직렬화, 클램프, 파일 입출력, 기본값 포인터, 고도↔pitch 변환 |
| `Light/LightControlManager.h/.cpp` | `AActor`. 레벨의 `DirectionalLight`/`SkyLight`/unbound `PostProcessVolume` 을 찾아 적용·캡처 |
| `Light/LightControlWidget.h/.cpp` | 패널 UI + 적용/저장/열기 |
| `Tests/LightControlLibraryTest.cpp`, `Tests/LightControlManagerTest.cpp` | 유닛테스트 6건 |

수정: `MainMenuWidget`(버튼 추가), `Park3DGameMode`(시작 적용). `Build.cs` 변경 없음.

### 3-2. 각도 규약

태양 방향은 UI 에서 **고도(지평선 위 0~90)** 로 다룬다. `DirectionalLight` 의 pitch 는 음수가 하향이라 직관과 반대이므로(카메라 tilt 와 같은 함정), 부호 변환은 라이브러리가 전담한다: `pitch = -고도`.

방위는 잘라내지 않고 0~360 으로 **감는다**(370 → 10, −30 → 330). 359°에서 계속 돌려도 자연스럽게 이어진다.

### 3-3. 기본값 포인터 방식

```
Save/3D/Light/Daylight.json   조명 설정
Save/3D/Light/_default.txt    마지막으로 저장·열기한 파일명 한 줄
```

- **저장**: 파일 다이얼로그로 이름 지정 저장 → 포인터 갱신
- **열기**: 다이얼로그로 불러와 즉시 적용 → 포인터 갱신
- **시작**: 포인터 읽기 → 파일 로드 → 적용. 어느 단계든 실패하면 **내장 기본값** 폴백

포인터는 **상대 파일명**으로 기록한다. 에디터의 `Park3D/Save/` 와 패키지의 `Package/Windows/Save/` 로 Save 루트가 달라도 각자 자기 `Light/` 폴더에서 해석된다(양쪽 실행 확인).

### 3-4. 패널 UI 를 C++ 로 구성한 이유 (관례 예외)

이 프로젝트의 관례는 "C++ 베이스 + WBP 디자이너"지만, 이번 패널은 C++ 에서 위젯 트리를 직접 만든다.

에디터와 Unreal MCP(8000)가 모두 미기동이라 GUI 로 WBP 를 만들 수 없었고, **헤드리스 파이썬으로 WBP 를 만들 수 있는지 프로브한 결과 실패**했다 — UE5.8 파이썬에 `WidgetBlueprint.WidgetTree` 가 노출되지 않는다(`Failed to find property 'widget_tree'`). 자산 생성 자체는 되지만 내부 위젯을 구성할 수 없다.

- 기능 제약은 없다. 나중에 이 클래스를 부모로 하는 WBP 를 만들면 디자이너에서 재배치할 수 있다.
- Main Menu 버튼도 같은 이유로 WBP 를 수정할 수 없어, `VBox_Menu` 를 이름으로 찾아 **런타임 삽입**한다. 스타일·폰트·패딩은 기존 버튼(`Btn_MapSize`)에서 복사하고, 기존 WBP 자산은 건드리지 않는다.

## 4. 구현 중 실제로 걸린 함정 3건

| # | 증상 | 원인 | 조치 |
|---|------|------|------|
| 1 | 매니저 테스트가 값이 전부 기본값이라며 실패 | 테스트가 라이트를 **따로 스폰**했는데, 매니저는 "월드의 첫 DirectionalLight"를 찾는다. 에디터 월드에는 이미 `EditorStartupMap=PresetMaker1` 의 라이트가 로드돼 있어 그쪽이 대상이 됐다 | 월드의 실제 조명을 대상으로 삼고, 원래 값을 스냅샷 → 검증 → **복원**하도록 테스트 재작성 |
| 2 | 방위 200 을 넣었는데 액터가 −160 을 반환 | `FRotator` 가 yaw 를 [−180,180] 으로 정규화(같은 방향) | 단언을 0~360 환산 비교로 수정 |
| 3 | 메뉴 버튼이 Exit **아래**에 붙음 | `ShiftChild` 는 UMG 슬롯 배열만 바꾸고 **이미 만들어진 Slate 트리는 재배치하지 않는다**. `NativeConstruct` 는 Slate 빌드 이후 시점 | 버튼 삽입을 `NativeOnInitialized`(Slate 빌드 전)로 이동 |

추가로 `Btn_Exit` 가 `VBox_Menu` 의 직계 자식이 아니어서 `GetChildIndex` 가 INDEX_NONE 을 반환 → 부모를 거슬러 올라가 직계 자식을 찾도록 보완. UMG 기본 폰트 24 라 라벨이 슬라이더를 덮어 → 폰트 14 + 고정폭 열(라벨 150 / 수치 84)로 수정.

## 6. 확인된 트레이드오프 (해소 방안 포함)

**하나의 노출값으로 원경과 근경을 동시에 맞출 수 없다.**

- 원인: `ExponentialHeightFog` 밀도 **0.0436**(UE 기본 0.02의 2배 이상) + `SkyAtmosphere.height_fog_contribution=1.0` 의 원거리 인스캐터로 원경 지면이 근경보다 밝게 뜬다.
- 결과: EV 2.5 에서 **카메라 캡처(CCTV) 지면 뭉갬이 5.8% → 70.5%** 로 악화. 차량 식별은 유지되나 노면은 어둡다.
- 참고: EV 0 에서 메인 뷰포트가 192 였던 것은 **톤매퍼 상단에서 포화**된 상태였기 때문이며, 카메라 경로는 EV 에 정확히 선형으로 반응한다(110 → 38.8 = 1.5스톱).

**해소 방안**: 안개 농도를 7번째 패널 항목으로 추가하면 원경/근경 격차 자체가 줄어 하나의 노출로 양쪽을 맞출 수 있다. 소규모 변경이며 사용자 판단 대기 중이다.

즉시 대응은 패널의 노출 슬라이더다 — 1.5 로 내리면 카메라 뭉갬 28.3%, 0 으로 내리면 5.8% 로 돌아간다.

## 7. 영향도

- `.umap`·레벨 에셋 **변경 0건**. 조명은 시작 시 파일에서 적용된다.
- **동작 변화 1건**: 레벨에 저장된 조명 값이 실행 시 파일 값으로 덮인다(요구사항 R4 의 의도된 결과이나 명시가 필요).
- Main Menu 항목 1개 증가. 스타일은 기존 버튼에서 복사해 외형 일관.
- RPC 79개 메서드 시그니처·동작 변경 없음(조명 RPC 는 요청 범위 밖이라 추가하지 않음).
