## 2. 역할 및 처리 로직

표준 작업은 다음 순서로 고정됐다.

```text
Sol 설계·사전 영향도
  → Terra 개발·빌드
  → 별도 Terra Automation/PIE QA
  → Sol 사후 영향도
  → Luna 주변 동작 사후점검
  → Luna 최종 한글 Docs
```

Goal/Loop는 다음 상태와 역할을 사용한다.

```text
Sol DESIGN/IMPACT
  → Terra EDIT/PRECHECK/COMPILE_GATE/RUN
  → 별도 Terra VERIFY
  → Sol POST-IMPACT
  → 실패 시 Sol 재설계, 동일 원인 3회 중단
  → Luna 최종 Docs
```

Goal/Loop에서는 별도 Luna 주변 동작 보고서를 만들지 않으며, Luna는 통과한 설계·영향도·구현·반복·QA 근거를 최종 문서로 종합한다. 구현 역할은 QA의 최종 승인 권한을 갖지 않고, QA는 기능 코드를 직접 수정하지 않는다.

## 4. 권한 및 MCP

- MCP 불변값은 서버명 `unreal`, URL `http://localhost:8000/mcp`다.
- 작업 전 `list_toolsets`와 필요한 `describe_toolset`으로 capability를 확인하고, 확인된 gateway `call_tool` 또는 직접 도구에 매핑한다.
- Claude 공유 권한은 UE 5.8 읽기, Unreal MCP discovery/gateway, 현재 Park3D Editor 빌드로 최소화됐다. 과거 프로젝트 경로, 세션성 경로, 삭제·강제 종료·패키지 설치·광범위 읽기 허용은 제거됐다.
- Codex에는 Claude allow-list를 복제하지 않고 런타임 샌드박스·승인 계층을 사용한다.

## 5. 영향도 및 주변 동작 판정

Luna 사후점검 보고서와 impact §11을 교차한 결과는 다음과 같다.

| 영향 면 | 결과 | 근거/제약 |
|---|---|---|
| 인접 라우팅·산출물 | 통과 | 표준 및 Goal/Loop 역할·게이트·실패 복귀·phase 산출물 경로 정렬 |
| Goal/Loop 역할 분리 | 통과 | Sol 설계/영향도, Terra 구현/실행, 독립 Terra QA, Luna 문서화가 활성 지침에 명시됨 |
| 권한 승인 사용성 | 정적 통과, 중간 위험 | 최소 권한으로 보안·재현성은 개선됐으나 timestamp/진단 명령에 승인 프롬프트 가능 |
| MCP discovery | 통과, Claude 런타임 미검증 | 현재 Codex 세션의 toolset discovery/설명 스키마 실호출 통과 |

| 기존 산출물 보존 | 통과 | `_workspace_prev` 이동·삭제 규칙 제거, 충돌 없는 phase 및 기존 자료 보존 |

중간 잔여 위험은 Goal/Loop에서 구현자와 QA의 테스트 파일 소유권이 겹칠 수 있는 점, Goal 재설계 시 전용 설계 경로 인계가 실제 dry-run에서 확인되지 않은 점, 문서에 표기된 일부 UMG 직접 도구명을 gateway 스키마에 매핑하는 실제 작업이 미검증인 점이다. 높은 위험이나 실패는 확인되지 않았다.
