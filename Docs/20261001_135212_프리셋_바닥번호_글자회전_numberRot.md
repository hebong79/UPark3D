# 프리셋 바닥 번호 글자 회전 `numberRot` (보드 #1086)

## 1. 요청
보드 #1086(SettingManager 채팅 세션): 프리셋 면의 바닥 번호 글자를 돌릴 RPC 가 없다.
`preset.rotate deltaFaceRot:180`·`deltaGroupRot:180`·`preset.setDirType 1`·`preset.update camIdx` 모두 글자 방향을 못 바꾸고,
`preset.setView` 에 방향 키가 없으며 `preset.numbers` 의 `rotY` 는 면 축일 뿐이다. 사용자가 채팅에 「숫자가 뒤집어졌어」 라고 해도 고칠 수 없다.

## 2. 원인
글자 방향은 `AParkingPresetManager::PlaceNumber` 의 자동 규칙이 정한다.
① 면의 길이·폭 두 축 중 열 방향(가장 가까운 이웃 면 쪽)에 수직인 축을 고르고
② 부호를 **가장 가까운 카메라 쪽**으로 접는다(카메라 화면에서 바로 읽히게, 09-07 결정).
faceRot 180 은 축 부호만 뒤집는데 ②가 다시 접어 버리므로 결과가 같다. groupRot·dirType 도 마찬가지다.
즉 "글자 방향" 을 바꿀 입력이 애초에 없었다.

### RPC 계약 (추가만, 기존 키 불변)
```
preset.rotate {idx, deltaNumberRot}      → 글자만 상대 회전(면 기하 불변)
preset.update {idx, numberRot}           → 절대값
preset.create {..., numberRot?}          → 기본 0(자동)
preset.numbers → numbers[].textRotY, numbers[].numberRot(preset 면)
```
「숫자가 뒤집어졌어」 → `preset.rotate {idx, deltaNumberRot:180}`.

## 4. 결정·한계
- **"faceRot 을 따르게" 는 하지 않았다.** 자동 규칙(가까운 카메라 쪽)을 바꾸면 서신·객리단 레벨 면과 기존 프리셋 화면이 전부 달라진다. 자동 위에 보정값을 더하는 방식이라 기본값 0 이면 기존 화면과 같다.
- 보정은 **프리셋 단위로 모든 면에 똑같이** 더해진다. 자동 규칙이 면마다 가까운 카메라를 보므로 한 프리셋 안에서도 면끼리 방향이 다를 수 있고(실측: 2번 프리셋 5·6 vs 7·8), 그 차이는 그대로 남는다.
- 레벨 면(`BP_ParkingSlot`)에는 적용되지 않는다(프리셋이 아님, 요청 범위 밖).
- `textRotY` 는 반올림하면 360 으로 보일 수 있다(359.99…).
