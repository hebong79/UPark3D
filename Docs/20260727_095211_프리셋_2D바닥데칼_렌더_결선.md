# 프리셋 주차면을 2D 바닥 데칼로 출력 — RPC 렌더 경로 결선

- 작성일시: 2026-07-27 09:52
- phase: `preset_decal_rpc`
- 요청: "주차면 6개는 2D로 바닥면에 만들어주고 데칼로 출력하도록 수정해줘"
- 결과: **완료** (유닛 12/12 통과, 실동작 캡처 확인, 회귀 없음)

## 1. 배경 — 왜 코드 수정이 필요했나

선행 작업에서 `preset.create` RPC 하나로 주차면 6개(2.5 m × 5 m) 프리셋을 만들었으나, 화면에는 **파란 디버그 라인 + 3D 큐브**로 그려졌다.

원인은 데칼 렌더 로직의 **결선 누락**이었다. `AParkingPresetManager::RebuildDecals()`는 이미 완성되어 있었고(바닥 4변 라인 데칼 + 선택 fill 데칼, 압출 없는 2D 전용) 문제는 그것을 부르는 진입점이었다.

| 경로 | 진입점 | `RebuildDecals` 호출 |
|------|--------|---------------------|
| 위젯(PresetMaker 대화상자) | `PresetMakerWidget.cpp:789` | **O** — `Check_UseDecal` 토글로 디버그 라인과 배타 처리 |
| RPC / 데이터 권위 | `ParkingPresetManager.cpp:279 RefreshView()` | **X** — `RebuildAll`(디버그 라인)만 |

`preset.rebuildAll`이 노출하던 토글은 `showQubeBox`(3D 큐브) 하나뿐이었고, 임의 UFUNCTION을 호출하는 RPC도 없다. 즉 **MCP 명령만으로는 데칼을 켤 수단이 존재하지 않았다.**

대안으로 "`preset.save`로 JSON 저장 → 대화상자에서 수동으로 열기"(위젯의 `Check_UseDecal`이 기본 켜져 있으므로 데칼로 렌더)가 있었으나, 사람 손이 필요하고 이후 RPC 조작 시 데칼이 갱신되지 않아 채택하지 않았다.

## 3. 변경 내역

### 3-1. `ParkingPresetManager.h`

`bShow3DView` 바로 아래에 토글 1개 추가. 두께는 **기존 필드 `DecalLineThicknessCm`(기본 10 cm)을 재사용**해 신규 필드를 만들지 않았다.

```cpp
/**
 * 데칼 렌더 사용 토글(RefreshView 반영). true=2D 바닥 데칼만, false=디버그 라인만(배타).
 * 위젯의 Check_UseDecal 기본 체크와 동일하게 true 로 둔다. 데칼 모드에서는 bShow3DView 를 무시한다.
 */
UPROPERTY(Transient, BlueprintReadWrite, Category = "Parking|Data")
bool bUseDecalView = true;
```

`Transient`이므로 JSON·`.uasset` 어디에도 직렬화되지 않는다 → 기존 프리셋 파일 호환 유지.

### 3-2. `ParkingPresetManager.cpp` — `RefreshView()`

```cpp
void AParkingPresetManager::RefreshView()
{
    // 데칼과 디버그 라인은 상호 배타(위젯 RefreshView 와 동일 규칙) — 같은 기하를 쓰므로 겹치면 이중 라인이 된다.
    if (bUseDecalView)
    {
        ClearAll(); // 디버그 라인/반투명 메시 제거
        RebuildDecals(StoredPresets, SelectedPresetIndex, DecalLineThicknessCm, true);
    }
    else
    {
        RebuildAll(StoredPresets, SelectedPresetIndex, bShow3DView);
        RebuildDecals(StoredPresets, SelectedPresetIndex, DecalLineThicknessCm, false); // 데칼 전부 숨김
    }
}
```

**2D가 보장되는 이유:** `RebuildDecals`는 `Bottom[4]`만 사용하고 `QubeHeight` 압출·`Top[4]`를 만들지 않는다. 따라서 `bShow3DView`가 true로 남아 있어도 데칼 모드에서는 큐브가 그려지지 않는다.

### 3-3. `Rpc/Modules/PresetRpcModule.cpp` — `preset.rebuildAll`

```cpp
// useDecal 은 전달됐을 때만 대입(생략 호출이 데칼 모드를 끄지 않도록).
if (RpcParam::Has(P, TEXT("useDecal")))       Mgr->bUseDecalView = ...;
if (RpcParam::Has(P, TEXT("decalThickness"))) Mgr->DecalLineThicknessCm = ...;
```

응답에 `useDecal` / `show3D` / `decalThickness`를 추가해 현재 모드를 확인할 수 있게 했다.

| 키 | 타입 | 생략 시 | 의미 |
|----|------|---------|------|
| `useDecal` | bool | **현 상태 유지** | true=2D 데칼, false=디버그 라인 |
| `decalThickness` | float | **현 상태 유지** | 데칼 라인 폭(cm) |
| `showQubeBox` | bool | false로 리셋(기존 동작) | 라인 모드에서만 유효 |

`useDecal`을 "있을 때만 대입"으로 둔 것은 의도적이다. 무관한 호출이 데칼 모드를 꺼버리는 것을 막는다.

### 3-4. `Tests/ParkingDecalTest.cpp`

신규 자동화 테스트 `Park3D.ParkingDecal.RefreshViewMode` 추가(기존 파일에 추가 → `Build.cs` 영향 없음).

| TP-2 | 라인 모드 → 가시 데칼 0 | 통과 |

기존 `ComputeSlotCorners`·`Rebuild`·`Park3D.Rpc.*` 9개 전부 통과(회귀 없음).

신규 테스트가 조용히 스킵되지 않았음을 확인했다 — 해당 테스트의 `BeginEvents`/`EndEvents` 구간이 비어 있어 스킵 경고가 없었다.

### 4-2. 실동작 — 패키지 앱(실RHI) + RPC

```
preset.clear                                        → {ok:true}
preset.create {faceCount:6, xSize:2.5, zSize:5, ...} → {idx:1, faceCount:6, xSize:2.5, zSize:5}
preset.rebuildAll {useDecal:true}                    → {ok:true, count:1, useDecal:true,
                                                        show3D:false, decalThickness:10}
```

신규 응답 필드가 돌아온 것 자체가 새 코드 경로의 런타임 증거다.

임시 카메라(높이 22 m, tilt 90 = 수직 하향)로 캡처한 결과:

| 캡처 | 조건 | 관찰 |
|------|------|------|
| `_workspace/preset_decal_rpc_pie_01_decal6.jpg` | `useDecal:true` | **흰색 라인 데칼로 6면**이 바닥에 평면 표시, 큐브 없음. 각 칸 세로:가로 ≈ 2:1 (5 m × 2.5 m 일치) |
| `_workspace/preset_decal_rpc_pie_02_linemode_cube.jpg` | `useDecal:false, showQubeBox:true` | **파란 디버그 라인 + 3D 큐브**, 흰 데칼 전부 사라짐 |

두 캡처의 대조로 세 가지가 동시에 실증된다.
1. 흰 선은 디버그 라인이 아니라 **데칼**이다 (디버그 라인은 파란색 `LineColor(0,90,255)`, 데칼은 `MI_Decal_Line_Road_White_02` 흰색).
2. 두 경로가 **상호 배타**로 동작한다.
3. 데칼 모드는 `showQubeBox`와 무관하게 **2D**다.

### 4-3. 빌드 반영 실증

본 세션의 `Build.bat` 호출은 `Target is up to date / 0 action(s)`를 반환했다. 실제 컴파일·패키징은 **다른 세션에서 수행**되었다(사용자 확인). 따라서 로그가 아니라 바이너리 문자열 테이블로 반영 여부를 판정했다.

`useDecal` / `decalThickness` / `bUseDecalView` 세 마커가 에디터 DLL과 패키지 EXE 양쪽에 모두 존재함을 확인했다.

> 주의: `TEXT()` 리터럴은 UTF-16이라 ASCII grep으로는 잡히지 않는다. UTF-16으로 디코딩한 뒤 검색해야 한다.

## 5. 영향도

상세: `_workspace/preset_decal_rpc_impact_report.md`(사전), `_workspace/preset_decal_rpc_impact_post.md`(사후)

### 변화

- **RPC 경로 13곳**(`preset.create/update/delete/move/rotate/groupMove/groupRotate/setSize/setDirType/select/load/rebuildAll` + `ClearPresets`)의 렌더 결과가 디버그 라인 → 2D 데칼로 바뀐다. 요청된 변경이며 데이터·응답 페이로드는 불변이다.
- `preset.rebuildAll {showQubeBox:true}`만으로는 이제 큐브가 보이지 않는다. `{useDecal:false, showQubeBox:true}`로 기존 동작을 재현할 수 있다.

### 영향 없음

- 빌드 모듈(`Build.cs` 무변경 — `UDecalComponent`는 이미 사용 중인 `Engine` 모듈)
- JSON 스키마 / DTO / 저장·열기 호환성
- PresetMaker 위젯 (매니저 `RefreshView()`를 경유하지 않고 자체 로직 사용)
- 차량 배치(`car.*`, `random.*`), 카메라(`cam.*`), 측정(`measure.*`)

### 새로 생긴 특성

RPC 경로가 처음으로 데칼 머티리얼에 의존하게 됐다. `LineDecalMaterial`(`MI_Decal_Line_Road_White_02`) 로드 실패 시 데칼 모드에서 **화면에 아무것도 표시되지 않는다**(디버그 라인은 `ClearAll`로 이미 지워진 상태). 로그 `[ParkingManager] LineDecalMaterial 이 null`로 진단 가능하며, 위젯 경로가 이미 갖고 있던 특성이 확장된 것이다.

## 7. 미검증 항목

1. **PresetMaker 대화상자 실동작** — 검증은 패키지 앱 + RPC로만 했고 위젯 UI를 열어보지 않았다. 코드상 영향이 없어야 하지만 실측하지 않았다.
2. **선택 상태의 fill 데칼** — 이번 시나리오는 선택 없음(`INDEX_NONE`)이라 fill 경로가 실행되지 않았다.
3. **위젯과 RPC 동시 사용** — 마지막 `RefreshView` 호출자가 렌더를 덮는 기존 제약(`ParkingPresetManager.h:34` 주석) 그대로. 이번에 재확인하지 않음.

## 8. 정리하지 못한 것

검증용 임시 카메라 `Camera-1`(pos 0.5, 6.25, 높이 22 m, tilt 90)이 씬에 남아 있다. `cam.delete {camId:1}`을 호출했으나 `{ok:false}`였고, 원인은 `ACameraControlManager::RemoveCameraAt`의 기존 규칙이다.

```cpp
if (Cameras.Num() <= 1) return false;   // 최소 1개 유지(설계 §4.2)
```

본 변경과 무관한 기존 동작이다. 앱을 재시작하면 사라진다.

## 9. 사용법

```jsonc
// 2D 바닥 데칼 (기본값)
preset.rebuildAll { "useDecal": true }

// 데칼 라인 두께 조정 (cm)
preset.rebuildAll { "useDecal": true, "decalThickness": 15 }

// 기존 디버그 라인 + 3D 큐브로 되돌리기
preset.rebuildAll { "useDecal": false, "showQubeBox": true }
```

`preset.create` 등 다른 프리셋 RPC는 `useDecal`을 건드리지 않으므로, 한 번 데칼 모드로 두면 이후 조작에서도 계속 데칼로 렌더된다.
