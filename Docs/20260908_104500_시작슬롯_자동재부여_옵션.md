# 시작 슬롯 — 뒤쪽 면 자동 재부여를 옵션으로 (기본: 수동)

작성 2026-09-08 / 대상 커밋 브랜치 `feat/slot-auto-option`

## 1. 요청

> 현재. 슬롯 번호를 수정하면 뒷쪽 슬롯번호들이 자동으로 수정된다. 자동으로 수정 되지 않게 수정해줘.
> ( 옵션을 넣어서 자동수정 여부를 체크박스로 만들어줘. (기본은 수동 작업으로) )

09-08 오전에 넣은 기준점 재부여는 **기준 면 뒤의 면을 항상 +1 씩 이어 매겼다**. 그것을 끄고,
끌지 말지를 사용자가 고르게 한다. 기본은 **끈 상태(수동)** — 기준 면 한 장만 바뀐다.

## 2. 결정

| 항목 | 결정 | 이유 |
|------|------|------|
| 기본값 | **수동**(자동 꺼짐) | 사용자 지시. 값이 없는 옛 파일도 `false` 로 읽혀 같은 동작이 된다 |
| 저장 위치 | `FCamDir.auto_renumber` (프리셋마다 따로) | 시작 슬롯·갯수와 같은 자리. 프리셋 A 는 자동, B 는 수동이 가능하다 |
| 갯수 칸 | 자동일 때만 유효 → 꺼지면 **칸을 잠근다** | "넣었는데 안 먹는다"를 없앤다. 값 자체는 지운다(잠글 뿐) |
| 적용 시점 | 체크만으로는 안 바뀐다. **'수정'** 이 반영한다 | 시작 슬롯·갯수와 같은 규약(되돌릴 여지 2단계) |
| 배치 | 갯수 칸 오른쪽 `☐ 자동`, **안내 문구는 아랫줄로 내림** | 아래 4절 |

## 3. 동작 규칙

기준점 하나에 대해 `ApplyNumberAnchors` 가 바꾸는 면의 개수:

| 자동 | 갯수 | 바뀌는 면 |
|------|------|-----------|
| 꺼짐(기본) | (무시) | **기준 면 1장** |
| 켜짐 | 0 | 기준 면부터 묶음 끝까지 |
| 켜짐 | N | 기준 면 포함 N 장 |

묶음 경계(프리셋 면 → 레벨 면)에서 이어 매기기가 끊기는 규칙, 같은 면에 기준점이 둘이면 뒤가
이기는 규칙, 번호 중복을 막지 않는 규칙은 그대로다.

예) 면 1..6 에 `기준 면 3 → 10`

- 수동: `1, 2, 10, 4, 5, 6`
- 자동 + 갯수 0: `1, 2, 10, 11, 12, 13`
- 자동 + 갯수 2: `1, 2, 10, 11, 5, 6`

## 4. 함정 — 칸 줄에 안내 문구가 들어갈 폭이 없다

체크박스와 라벨(`자동`)이 들어가면 한 줄이 `시작 슬롯 · 칸 · 갯수 · 칸 · ☐ · 자동` 으로 차서
오른쪽 끝의 안내 문구(`LShift+클릭으로 기준 면 지정`, 약 136px)가 들어갈 자리가 없다.
패널 폭은 **넓히지 않는다**(2026-08-18 사용자 결정 — 그때 폭을 늘렸다가 되돌렸다).

→ 안내 문구를 **아랫줄(전용 HorizontalBox)** 로 내리고 오른쪽 정렬했다. 패널 높이는
`FitPanelToContent` 가 매 틱 재보정하므로 줄이 하나 늘어도 잘리지 않는다.

문구를 줄여 한 줄에 욱여넣는 안은 버렸다 — 가장 긴 문구가 나오는 상태가 하필
**기준 면을 아직 안 찍은 첫 화면**이라 첫 사용자가 잘린 글자를 본다.

## 6. 파일 형식 (`CamPos_*.json`)

`FJsonObjectConverter` 가 `FCamDir` 의 모든 UPROPERTY 를 쓰므로 키가 자동으로 늘어난다.

```json
{ "idx": 1, "sname": "Preset 1", "…": "…",
  "start_slot": 1, "start_face": "level:BP_ParkingSlot_C_5#0", "start_count": 6,
  "auto_renumber": false }
```

- Unity 파서는 모르는 키를 무시한다 → 형식 호환 유지.
- `auto_renumber` 가 **없는 옛 파일은 false = 수동**으로 읽힌다. 즉 09-08 오전에 저장해 둔
  파일(`start_count` 가 들어 있는 것 포함)도 다시 열면 **기준 면 한 장만** 바뀐다.

## 7. RPC

```jsonc
// 자동으로 켜기
{"method":"cam.savePreset","params":{"camId":1,"presetId":1,
  "startFace":"level:BP_ParkingSlot_C_5#0","startSlot":1,"startCount":6,"autoRenumber":true}}

// 응답/조회(cam.presets, cam.loadPreset …)
{"startSlot":1,"startFace":"level:…#0","startCount":6,"autoRenumber":true}
```

`autoRenumber` 를 안 주면 기존 값을 지킨다(`startSlot`·`startCount` 와 같은 규약).

## 8. 검증

- 자동화 테스트 **104/104 성공**(실패 0). TN-8 수동 `1,2,10,4,5,6` / 자동 `1,2,10,11,12,13`,
  TN-9 수동은 갯수 3 을 줘도 `1,10,3,4,5,6`.
- `Park3DEditor`·`Park3D` 두 타깃 빌드 성공.

실기는 패키지 복제(`Package/Work13520`, exe 만 교체, RPC 13520 / 스트림 13700·13711~13750)에서
서신지구대(레벨 면 23개)로 확인했다. 판정은 `preset.numbers` 의 번호 배열 + 창 캡처 둘 다.

**RPC 경로**

| 호출 | 바닥 번호 |
|------|-----------|
| 기준점 없음 | `1,2,…,23` |
| `startFace=…C_1#0, startSlot=100, startCount=6` (autoRenumber 생략=기본) | `1,2,3,4,**100**,6,7,…` — 갯수 6 을 줘도 한 장만 |
| `autoRenumber:true` (갯수 6 유지) | `1,2,3,4,100,101,…,105,11,12,…` |
| `startCount:0` (자동 유지) | `1,2,3,4,100,101,…,118` (끝까지) |
| `autoRenumber:false` | `1,2,3,4,100,6,7,…` (원상) |

**패널 경로** — `car.hideAll` 로 차량을 숨겨 바닥 번호를 보이게 한 뒤

1. LShift+클릭(11번 면) → 칸에 `11`, 문구 `기준 면 #11 → '수정'`
2. 시작 슬롯 `50` / 갯수 `3` 타이핑(**편집 중에도 검은 글자로 보인다** — 09-08 오전 수정이 유효)
3. `자동` 체크 후 '수정' → `…,10,**50,51,52**,14,…`
4. `자동` 해제 후 '수정' → `…,10,**50**,12,13,14,…` (12·13 이 원래 번호로 복귀)

체크박스를 켜고 끄는 즉시 갯수 칸이 흰색/회색으로 바뀌는 것(사용 가능/잠금)도 캡처로 확인했다.
