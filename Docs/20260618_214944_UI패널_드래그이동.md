---

## 1. 요청

> UI 위를 마우스로 좌측 버튼을 누른 상태에서 이동하면 UI가 따라 움직이게 만들어줘.

---

## 2. 구현

`UPresetMakerWidget`에 마우스 이벤트 3종을 오버라이드하여 **패널(RootBorder)을 RenderTranslation으로 따라 이동**시킨다.

| 오버라이드 | 동작 |
|-----------|------|
| `NativeOnMouseButtonDown` | 좌클릭 시 드래그 시작 — 시작 로컬좌표/누적이동량 저장 + `CaptureMouse(TakeWidget())` |
| `NativeOnMouseMove` | 드래그 중이면 로컬좌표 델타를 `RootBorder->SetRenderTranslation()` 으로 적용 |
| `NativeOnMouseButtonUp` | 좌클릭 해제 시 드래그 종료 + `ReleaseMouseCapture()` |

### 2.1 버튼/입력칸과 공존하는 원리
- 버튼·체크박스·입력칸·리스트는 **해당 위젯이 마우스-다운을 소비**하므로 위젯 루트의 `NativeOnMouseButtonDown` 까지 버블링되지 않는다 → 조작은 그대로 동작.
- **패널 배경(RootBorder, Visible)·타이틀·여백**은 클릭을 소비하지 않아 루트로 버블링 → 드래그 시작.
- 즉 "버튼이 아닌 패널 영역을 잡고 끌면" 패널이 이동하고, 버튼/입력은 정상 클릭된다.

### 2.2 좌표/DPI 처리
- 스크린 픽셀 대신 **루트 지오메트리 로컬 좌표**(`InGeometry.AbsoluteToLocal`) 델타를 사용 → DPI 스케일이 자동 반영되고, RenderTranslation 단위와 일치(별도 DPI 라이브러리 불필요).
- 루트 지오메트리는 RootBorder의 RenderTranslation 영향을 받지 않으므로 드래그 중 피드백 없이 안정적.
- `RootBorder` 는 `BindWidgetOptional` 로 WBP의 동일 이름 보더에 바인딩.

## 4. 사용법
- 패널의 **타이틀/배경/여백을 좌클릭한 채 드래그** → 패널이 마우스를 따라 이동.
- 버튼·입력칸·리스트·콤보를 클릭하면 드래그가 아니라 해당 조작이 동작(의도된 동작).

## 5. 영향도
- `PresetMakerWidget.h/.cpp` 만 변경(마우스 오버라이드 3종 + RootBorder 바인딩 + 드래그 상태 4필드). 추가 모듈/에셋 변경 없음. 재빌드 1회.
- 이동은 RenderTransform(시각 변환)이라 앵커/레이아웃(화면 60% 사이징)은 그대로 유지. 위젯을 다시 열면 위치는 초기화(중앙).
- 클릭 통과 차단(이전 작업)과 독립적으로 공존.
