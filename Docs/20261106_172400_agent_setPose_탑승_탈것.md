# `agent.setPose` — 탑승 중인 탈것 옮기기

- 요청: pm-ff. 마스터 원문 「사람표현 수정해줘.(자전거 흰색도 변경)」(pm-68 전달, 상황복구 PM 요청). 탑승자 쪽 설계는 `StateRestoreActor-rider\docs\20261106_170500_탑승자_표현_설계.md`
- 브랜치: `fix/agent-setpose-rider`(main `f2401ff` 에서), worktree `D:\Work2\Unreal2\UPark3D_setpose`
- 승인: 작업본 재빌드·RPC 시험은 PM 승인, 예약 c5805. 머지·push·정본 교체는 하지 않았다.

## 1. 왜

`agent.setPose` 는 탑승 관계가 있는 대상이 하나라도 있으면 호출 전체를 거절했다. 상황복구 렌더러가 탄 사람을 `rider:true` 로 그리면 자전거 한 대 때문에 그 시각의 모든 대상이 멈춘다.

## 2. 계약

| 입력 | 동작 |
|---|---|
| 탑승 중인 탈것 id | 받는다. 탄 사람이 함께 간다 |
| 탄 사람 id | 지금처럼 호출 전체 `-32000 bad_params`, 아무것도 안 옮긴다 |
| 탄 사람 없는 탈것, 걷는 사람 | 바뀌지 않음 |

- **`agent.list`:** 호출이 끝난 시점에 탄 사람의 `pos`·`directionDeg`·`speedMps`·`state`·`motionType` 이 탈것 값과 같다. `activityType` 은 `riding`, `ridingWith` 는 그대로다.
- **`applied`·`changed`:** 항목 수를 센다. 탄 사람은 세지 않는다(탈것 1 항목 = 1).
- **`speedMps`:** 탈것에 준 값이 탄 사람에게 그대로 나온다. 탑승 자세는 고정이다. **페달·바퀴가 도는 애니메이션은 없다.** `agent.move` 로 달릴 때도 없다. 있어야 한다면 별도 작업이다.
- **`agent.stop`:** 탄 사람 id 를 주면 탈것의 표시 속도까지 끝난다(이전과 같은 경로).
- **`agent.delete`:** 바꾸지 않았다. 탈것만 지우면 사람이 오른쪽 0.8 m 에 내려 선다. 탈것과 탄 사람을 한 호출로 지우면 둘 다 없어지고 관계가 닫힌다.
- **`state.snapshot/restore`, atomic `system.batch`:** 탈것 자리·표시 속도·관계가 돌아오고 탄 사람은 탈것에 맞는다. `paused:true` 는 둘 다 세운다.

`system.help agent.setPose`(`Rpc/RpcHelpTable.cpp`)와 메서드 메타(`Rpc/Modules/AgentRpcModule.cpp`)를 함께 고쳤다.

### 넣지 않은 것

호별 `results`(한 항목 실패가 나머지를 막지 않게): 넣지 않았다. 지금의 「틀린 항목이 있으면 아무것도 안 옮긴다」 계약을 뒤집고 호출처 처리도 바뀌어야 한다. 렌더러가 탈것 id 만 보내면 필요가 줄어든다.

## 3. 코드

`Sim/ParkAgentManager.cpp` `SetPoses`, 두 곳.

1. 거절 조건을 「탑승 관계」에서 「탄 사람」(`Kind == Pedestrian && RidingWith`)으로 좁혔다.
2. 옮긴 뒤 `Advance(0.f)` 로 탄 사람 값을 맞춘다. `agent.stop` 과 같은 방식이다.

`SyncActor` 는 탄 사람을 건너뛴다. 탄 사람 액터는 좌석에 붙어(`AttachRider`) 탈것을 따라가므로 액터는 이것으로 맞고, 건너뛰던 것은 `FParkAgent` 의 값이다. 틱을 기다리지 않게 호출 안에서 맞춘다.

- Automation(worktree 에디터 `-nullrhi`): `Park3D.Agent.SetPose`·`Life`·`Nav`, `Park3D.Rpc.Help.TableMatchesRegistry` 통과.
