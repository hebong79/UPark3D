# 운영 단계는 Sonnet 5.5 가 맡는다

마스터 지시(2026-10-05): 아래 다섯 가지는 **항상 Sonnet 5.5 가 담당**한다.

- 커밋
- 머지
- 푸시
- 재빌드(게임 `Park3D` / 에디터 `Park3DEditor` 타깃)
- exe 교체·정본 교체·재기동

메인 세션(어떤 모델이든)은 이 명령들을 Bash/PowerShell 로 **직접 실행하지 않는다**. 위임하고, 결과를 전달할 뿐이다.

## 메인 세션이 하는 일

1. **승인 확인** — `git-flow` 규칙을 따른다.
   - 머지·푸시·재쿡은 **이번 대화에서 마스터가 명시적으로 승인했거나, PM 이 마스터 승인을 받아 대상과 원문을 적어 명령한 것만** 넘긴다(마스터 지시 2026-11-05).
   - 재빌드·exe 교체(PROCEDURE 5절)·정본 교체(6절)·재기동은 **담당 PM 이 대상을 적어 명령했을 때만** 넘긴다. 마스터 원문을 요구하지 않는다. 끝나면 한 줄 보고한다(마스터 결정 2026-11-06).
   - "커밋해줘" 는 머지·푸시 승인이 아니다.
   - `Package\Windows` 의 교체·재기동은 `.10` 배포다(이 PC = 192.168.0.10). 담당 PM 명령 없이 하지 않는다.
   - `.125`·`.8` 에 넣는 exe 는 머지된 main 으로만 만든다. 브랜치 빌드 시험은 `.10` 에서 한다.
2. **위임 호출** — Agent 도구로 아래처럼 부른다.
   - `subagent_type: "general-purpose"`, `model: "sonnet"`, `run_in_background: false`
   - `description`: 예) "Park3D 커밋·빌드"
   - `prompt`: 아래 틀을 채운다. 서브에이전트는 이 대화를 모르므로 **필요한 사실을 전부** 적는다.
3. **결과 전달** — 서브에이전트의 보고(커밋 해시, 빌드 결과, 재기동 확인값, 실패 출력)를 마스터에게 사실대로 전한다.
   - Docs 문서·변경 이력(`park3d-history`)은 작업 맥락을 아는 메인 세션이 쓴다.
   - 그 문서 커밋도 다시 위임한다.
   - 배포 뒤 기록(`Docs/*.md`·`CLAUDE.md`·`park3d-history` 만)은 PROCEDURE 1절 예외에 따라 main 에 직접 커밋·push 한다.
     prompt 의 할 일에 "배포 기록 커밋" 이라고 적는다.
4. **실패 처리**
   - 서브에이전트가 실패하거나 막히면 **메인 세션이 대신 실행하지 않는다**.
   - 실패 내용을 보고하고 다음 행동을 마스터에게 묻는다.
   - 빌드 오류가 코드 문제라면 코드 수정은 메인 세션이 한다. 그다음 빌드는 다시 위임한다.

할 일(순서대로): <예: 커밋 → 게임·에디터 빌드 → main 머지 → push → exe 교체·재기동>
브랜치: <feat/...>
