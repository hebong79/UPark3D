# 차량 배치 UI / Main Menu — Unity CarObject → Unreal 변환 설계서

- 작성일: 2026-06-23 21:51
- 작성자: architect (설계 전담)
- 대상 규칙: CLAUDE.md 0번(설계 필수) 수행 — 본 문서는 **설계서**이며 구현 코드는 포함하지 않는다.
- 범위: Unity `unity/CarObject/` 모듈(차량 배치 대화상자 + 차량 오브젝트 리스트 + 우측 Main Menu + 차량 액터/풀/색상/하이라이트/JSON 저장) → Unreal 5(Park3D) 포팅.
- 기준 패턴: 기존 `Park3D/Source/Park3D/PresetMakerWidget.*`, `ParkingPresetManager.*`, `ParkingPresetTypes.h`, `ParkingGeometryLibrary.*`, `Park3DGameMode.*`, `Park3D.Build.cs`.

## 0. 한눈에 보는 결론(요약)

- **신규 C++ 클래스 7종**을 추가한다.
  1. `ParkingCarTypes.h` — 데이터 구조체/열거형 (`FCarPos`, `FCarPosDatas`, `FCarPresetEntry`, `ECarType`, `ECarColor`, `ECarMoveMode`). `ParkingPresetTypes.h` 스타일.
  2. `UCarPlacementWidget` (`UUserWidget`) — 차량 배치 대화상자. `UPresetMakerWidget` 패턴 모방.
  3. `ACarPlacementManager` (`AActor`) — 차량 액터 스폰/풀/리스트 관리(매니저). `AParkingPresetManager` 패턴 모방.
  4. `ACarActor` (`AActor`) — 개별 차량 액터(메시 + 번호판 + 색상 + 하이라이트). Unity `CObjCar` 대응.
  5. `UCarColorComponent` (`UActorComponent`) — 차량 도색 색상 제어. Unity `CVehicleColorController` 대응.
  6. `UCarPlacementLibrary` (`UBlueprintFunctionLibrary`) — **순수 계산 함수**(좌표 변환, 자동배치 위치 산출, ID 생성). 유닛테스트 1순위 타깃. `UParkingGeometryLibrary` 패턴.
  7. `UMainMenuWidget` (`UUserWidget`) — 우측 Main Menu(프리셋/차량/카메라/맵/거리체크/VLA/Exit 버튼 허브). Unity `CPMakerMenuDlg` 대응.
- **선택/하이라이트는 별도 컴포넌트 없이** `ACarActor` 내부 상태 + 머티리얼 동적 인스턴스로 처리(대안 비교 §8 참조 — Unity의 `CCarSelectHighlight` 외곽선 메쉬 복제 방식은 1차 범위에서 제외, 단색/Overlay로 대체).
- **JSON 입출력은 Unity `CarPos_SNum.json` 스키마와 100% 호환**(§7, 샘플로 **확정**). Unity `pos`의 `SVector3{x,y,z}`(Y-up, m)를 `FCarVec3`(소문자 키)로 그대로 직렬화하여 상호 호환을 유지하고, 좌표 변환은 로딩/저장 경계에서만 수행한다.
- **풀링은 1차에서 도입하지 않는다**(YAGNI — CLAUDE.md 2번 단순함 우선). 차량 수백 대 이상에서 성능 이슈가 확인되면 2차에 `ACarPlacementManager` 내부에 풀을 추가(인터페이스를 미리 매니저 메서드로 캡슐화하여 교체 가능하게 설계).

## 2. Unity 원본 클래스 역설계 요약 + 대응 매핑

### 2.1 `CCarPlacementDlg` (1238줄) — 핵심 대화상자

- **상태 필드**: 현재 프리팹 id(`m_iCurPrefabId`), 키타입(`EKeyType{None,Move,Rot}`), 다중 선택 리스트(`m_MultiSelectedCars/Items`), Shift 범위선택 앵커(`m_AnchorIdx`), 자동배치 기준점(`m_vOffsetAutoCarPos`), 파일명(`m_DefaultFileName`).
- **초기화**: 드롭다운 2종 채우기(`InitDropdown_CarType` = ECarType 이름, `InitDropdown_CarPrefabs` = 프리팹 이름 목록), 리스트 UI 초기화.
- **선택 모델**: 단일 클릭=교체선택, Ctrl=토글, Shift=앵커~현재 범위. primary(`m_SelectdCarObject`)는 마지막 추가 항목. 스크롤 아이템 ↔ 월드 차량 ↔ `SCarPos` 3자를 id(`m_NameId`)로 동기화.
- **편집 흐름**: 리스트/월드 선택 → `FromSaveData`(폼 채움) → 사용자 편집 → `m_btnRepair`→`ToSaveData`(데이터 반영) + 월드 액터 회전/타입 갱신. 다중 선택 시 RotY/Front만 일괄 적용.
- **이동/회전**: `Update_CarMoveRotate`(WASD 카메라기준 평면 이동, 회전은 xDelta×10), 휠 회전(`m_inRotateTerm` 기본 5°), `OnClicked_AddRotate`(+90°). 프리셋그룹 토글 시 같은 presetId 일괄.
- **자동배치**: `OnClicked_AutoCreate` — 개수/간격/세로여부 입력 → `CreateRandomCarsInLine`(기준차량 right벡터·회전각 상속) → 각 차량에 presetId/slotId 부여 + 리스트 추가.
- **배치(픽)**: `CheckPickingPositionByMouse` — Ctrl+좌클릭 & "Floor" 태그 → `AddCarObject(hit)`; 그냥 좌클릭 & "Car" 레이어 → 선택(Shift 토글).
- **저장/열기**: 표준 파일 대화상자 → `CDataMgr.SaveCarPosFile/LoadCarPosFileFromDataMgr` → 리스트/월드 재생성.

### 2.2 `CCarObjListUI` (901줄) — 차량 인스턴스 관리

- 프리팹 리스트(`m_PrefabList`)·차량 인스턴스 리스트(`m_ObjCarList`) 보유. 차량 생성(`CreateCarObject`, `CreateCarObjectByCarPos`, `CreateRandomCarObjectByCarPos`), 일렬 자동생성(`CreateRandomCarsInLine`), 리셋(`Reset_CreateCarObjectList`), 제거(`RemoveCarObject/RemoveAll`), 색상 무작위(`SetRandomColorOfCarList`).
- VLA 학습용 보조: `HideRandomCars`, `HideRandomNoiseCars`, `GetNoiseShowCount`(0대50%/1대45%/2대5%). → **1차 범위 제외**(차량배치 UI 핵심 아님). 매니저에 향후 추가 가능하도록 메서드 자리만 표시.
- **대응**: 이 클래스 역할은 `ACarPlacementManager` 가 흡수(인스턴스 리스트 = `TArray<ACarActor*>`, 프리팹 목록 = `TArray<UStaticMesh*>` 또는 `TArray<FCarPresetEntry>` 데이터테이블).

### 2.4 `CVehicleColorController` → `UCarColorComponent`

- Unity: 머티리얼 키워드(`carpaint/Body/Paint...`)로 타깃 렌더러 선별, `MaterialPropertyBlock`로 `_BaseColor`/메탈릭/스무스니스 설정, 번호판(`licplate`) 제외, HSV 랜덤색.
- Unreal: 차량 메시의 머티리얼 슬롯 중 이름 키워드 매칭 슬롯에 `UMaterialInstanceDynamic` 생성 후 `SetVectorParameterValue("BaseColor"/"Color")`, `SetScalarParameterValue("Metallic"/"Roughness")`. 번호판 슬롯 제외. 랜덤은 `FLinearColor::MakeFromHSV8`/HSV→RGB.
- **확인 필요**: Park3D 차량 머티리얼이 어떤 파라미터 이름을 노출하는지(에셋 임포트 후 `get_material_info`로 확인). 임포트 차량이 GLB→UE 머티리얼인지, 별도 마스터 머티리얼인지에 따라 파라미터명이 달라짐. → **가정**: 색 변경 가능한 마스터 머티리얼 파라미터 `BaseColor`(Vector), `Metallic`/`Roughness`(Scalar)를 두고 차량 메시에 인스턴스로 적용.

### 2.5 `CCarSelectHighlight` → `ACarActor::SetSelected`

- Unity: 단색(차체 색 교체) 또는 외곽선(메시 복제 + Front cull + scale 1.05). 
- Unreal 1차: **단색 오버레이**만 채택(외곽선 메시 복제는 복잡도↑, 5.x는 Custom Depth + PostProcess Outline이 정석이나 별도 머티리얼/포스트프로세스 셋업 필요). `ACarActor::SetSelected(true)` → `UCarColorComponent`로 선택색(시안) 적용 or `SetRenderCustomDepth(true)`. → §8 대안 비교.

### 2.6 `CCarObjectPool` → (1차 미적용)

- 매니저가 `SpawnCar`/`DespawnCar` 메서드를 제공. 1차는 `SpawnActor`/`Destroy`. 풀 도입 시 이 두 메서드 내부만 교체.

### 2.7 `CGlbLoader` → 임포트 에셋 사용

- Unity는 런타임 GLB 로딩(glTFast). Unreal은 **에디터에서 미리 임포트한 `UStaticMesh`/`USkeletalMesh`** 를 데이터테이블로 참조하는 것이 정석(런타임 glTF 런타임 로딩 플러그인 도입은 과도). → **결정**: 차량 메시는 사전 임포트 에셋. 런타임 GLB 로딩은 범위 제외(확인 필요: 차량 종류가 런타임에 추가되어야 하면 재검토).

### 2.8 `CPMakerMenuDlg` → `UMainMenuWidget`

- Unity 버튼: 프리셋메이커/차량배치/카메라컨트롤/맵크기/(폴대)/VLA이미지메이커(씬로드)/VLA시뮬(씬로드)/Exit. 각 버튼은 해당 Dlg `IsShow ? CloseUI : OpenUI` + 형제 Dlg 닫기(배타적).
- 스크린샷 기준 버튼: 프리셋 메이커 / 차량 배치 / 카메라 컨트롤 / 맵 크기 변경 / 거리.피쳐 체크 / VLA 학습 데이터 / VLA 시뮬레이터 / Exit.
- Unreal: 각 위젯을 `CreateWidget` 후 `AddToViewport`/`RemoveFromParent` 토글. 배타 표시 관리. VLA 항목은 레벨 오픈(`UGameplayStatics::OpenLevel`) 또는 미구현 알림.

### 2.9 `CDataMgr`/`CSaveCarPosData` → 위젯 보유 + JSON 라이브러리

- 차량 데이터 컨테이너(`FCarPosDatas`)를 `UCarPlacementWidget` 이 직접 보유(`UPresetMakerWidget::Presets` 패턴). 매니저는 표시(액터)만 담당. `AddCarPosData`(id 생성 `"{idx}-{HH.MM.SS}"`)는 `UCarPlacementLibrary::MakeCarId` 순수함수로.

## 3. 언리얼 클래스 / 데이터 구조 설계

### 3.1 `ParkingCarTypes.h` (신규, `ParkingPresetTypes.h` 스타일)

```text
UENUM(BlueprintType) ECarType : uint8
{ None=0, Small, Medium, Large, Suv, Bongo, Truck };   // Unity ECarType (None=0, Small=1..Truck=6)

UENUM(BlueprintType) ECarColor : uint8
{ White=0, Black, Silver, Gray, Red, Blue, Green, Yellow, Orange, Purple };

UENUM(BlueprintType) ECarMoveMode : uint8 { None=0, Move, Rotate };   // Unity EKeyType

USTRUCT(BlueprintType) FCarVec3                 // === Unity SVector3 (JSON pos) — 소문자 키 강제 ===
{                                               //  FVector 직접 사용 시 UE가 X/Y/Z(대문자)로 직렬화 → Unity 비호환
  float x = 0;  float y = 0;  float z = 0;      //  (샘플 CarPos_23Num_서신.json 으로 소문자 확정)
};

USTRUCT(BlueprintType) FCarPos                 // === Unity SObjectPos (CarPos JSON 1개 항목, 8필드) ===
{
  FString id;            // "idx-HH.mm.ss"
  int32   type     = 0;  // = ECarType 정수 직접 매핑 (0=None=미설정)
  int32   presetId = 1;  // 프리셋 그룹 id (1부터)
  int32   slotId   = 1;  // 주차면 슬롯 (1부터, -1=슬롯 외)
  int32   prefabId = 1;  // 차량 메시 id (1부터)
  FCarVec3 pos;          // ★ Unity 좌표(Y-up, m) 그대로 직렬화 — 키 소문자 x/y/z (JSON 호환)
  float   rotY     = 0;  // Y축(Unity) 회전 deg
  bool    isFront  = true;
};

USTRUCT(BlueprintType) FCarPosDatas { TArray<FCarPos> datas; };   // === Unity SObjectPosDatas (JSON 루트) ===

USTRUCT(BlueprintType) FCarPresetEntry         // === Unity CScoCarData.SCarData (메시 카탈로그) ===
{
  int32      Idx = 1;                 // 1부터
  ECarType   Type = ECarType::Medium;
  FString    PrefabName;              // 표시/매칭용 이름
  TSoftObjectPtr<UStaticMesh> Mesh;   // 임포트된 차량 메시
};

## 6. 좌표 · 단위 규약

| 항목 | Unity | Unreal | 변환식 |
|------|-------|--------|--------|
| 좌표계 | 왼손, **Y-up**, X right, Z forward | 왼손, **Z-up**, X forward, Y right | 아래 |
| 단위 | meter | cm | ×100 (MetersToUU) |
| 평면 | XZ 평면(지면) | XY 평면(지면) | Unity(x,z) ↔ UE(x,y) |
| 높이 | Y | Z | |
| 회전(차량) | `rotY`(Y축, deg) | Yaw(Z축, deg) | 부호 보정 확인 필요 |

- **권장 변환(기존 PresetMaker가 Offset에 적용한 규약과 정합)**: PresetMaker는 `P.Offset.X = Hit.Location.X/U`, `Offset.Y = Hit.Location.Y/U`로 **UE의 (X,Y)를 그대로 m로 나눠** 프리셋 평면 좌표로 썼다(축 스왑/부호반전 없이). 차량도 동일 규약을 1차 채택한다:
  - `UnityPosToUE(u)` = `FVector(u.X * U, u.Z * U, u.Y * U)` — Unity의 z(전방)→UE y, Unity의 y(상)→UE z.
  - `UEToUnityPos(e)` = `FVector(e.X / U, e.Z / U, e.Y / U)`.
- **회전 부호**: Unity Y축 회전(시계, 위에서 볼 때)과 UE Yaw(반시계 기준)의 방향이 반대일 수 있음. 1차 가정 `UEYaw = UnityRotY`(동일), 실제 차량 메시 정면 방향과 함께 **동작 확인 단계에서 검증**(필요 시 `Yaw = -UnityRotY` 또는 `+180°` 오프셋). → §10 테스트 포인트.
- **JSON 좌표 보존**: 위 변환은 **메모리(액터 배치) 경계에서만** 수행하고, 디스크 JSON `pos`는 Unity 값을 그대로 저장하여 `CarPos_SNum.json` 상호호환을 유지한다(§7 NFR-01).

> 확인 필요: PresetMaker가 축 스왑 없이 (X,Y) 직접 사용했다면, 그 프로젝트의 Unity 데이터가 실제로 (x,y)=(가로,세로)였을 가능성. 차량 JSON의 `pos`가 Unity 어느 축 조합인지(특히 z 사용 여부)를 실제 `CarPos_SNum.json` 샘플로 확정해야 한다(현재 샘플 파일 미확보).

  └ CSavePolePosData : CSaveObjectPosData     // 기둥용 (차량용 CSaveCarPosData도 동일 베이스 추정)
```
`SaveToJson`은 `m_Data`(=`SObjectPosDatas`)를 **Newtonsoft `JsonConvert.SerializeObject`** 로 직렬화 → 루트 `{"datas":[...]}`.

**`SObjectPos` 권위 필드 (8개, 모두 소문자 키):**

| 키 | 타입 | 의미 (주석 원문) | 샘플 값 |
|----|------|-----------------|--------|
| `id` | string | 차량 obj id (시간 기반 구분용, `{idx}-{HH.mm.ss}`) | `"0-16.25.24"` |
| `type` | int | **`ECarType` 정수값 그대로**(직접 매핑). 샘플이 전부 `0`인 것은 타입 데이터가 아직 적용 안 된 상태(미설정=0)일 뿐 정상 | `0` |
| `presetId` | int | 프리셋 id (1부터) | `1` |
| `slotId` | int | 주차면 id (1부터, **-1 = 슬롯 외 영역**) | `1` |
| `prefabId` | int | 오브젝트(프리팹) id (1부터) | `1`,`2` |
| `pos` | SVector3 | 위치값 **(키 소문자 `x/y/z` 확정)** | `{"x":12.68,"y":-0.05,"z":21.16}` |
| `rotY` | float | y축 회전값(도) | `180.0`, `271.13` |
| `isFront` | bool | 주차면 기준 차량 전/후 (true=전면) | `true` |

```json
{"datas":[
  {"id":"0-16.25.24","type":0,"presetId":1,"slotId":1,"prefabId":1,
   "pos":{"x":12.6805592,"y":-0.0504936576,"z":21.1645584},"rotY":180.0,"isFront":true}
]}
```

**확정 사항(설계 반영):**
- ✅ **`pos` 키는 소문자 `x/y/z`** — 따라서 §8.5 **A안(`FCarVec3{float x,y,z}` 전용 USTRUCT) 채택 확정**. `FVector` 직접 사용 시 UE 직렬화가 대문자 `X/Y/Z`가 되어 좌표가 조용히 (0,0,0)으로 손실되므로 **금지**. (`FCarPos.pos` 타입을 `FVector` → `FCarVec3`로 변경 — §3.1·§4 시그니처도 동일 적용.)
- ✅ **루트 키는 `datas`**, 항목 8필드는 위 표대로. 필드 키 그대로(`id/type/presetId/slotId/prefabId/pos/rotY/isFront`)로 `FCarPos` 멤버명을 소문자 시작으로 둔다.
- ✅ **파일명 규칙**: `CarPos_{N}Num_{태그}.json` — `{N}`은 항목 수(샘플 `23Num` = 23대, id 0~22와 일치). UI 타이틀의 `CarPos_SNum`은 일반화 표기.
- ✅ **`pos.y`는 높이(Unity Y-up)** — 샘플의 y가 모두 0 근방(−0.05~0.002, 지면 높이). 지면 평면은 `x`,`z`. 이는 §6 좌표 변환 가정(Y-up, 지면 XZ)과 일치.
- ✅ **`type` = `ECarType` 직접 매핑(확정)**: JSON `type` 정수는 `ECarType` enum 값과 1:1. 샘플이 전부 `0`인 것은 타입 데이터가 아직 적용되지 않은 상태(미설정=`0`=`None`)일 뿐이며 스키마/매핑상 문제 없음. → `FCarPos.type`을 직접 `(ECarType)type`으로 해석. 단, 로드 시 `type==0`은 "미설정"으로 간주하고 UI 기본 타입으로 폴백할지 여부만 구현 시 결정.
- 💡 **공통화 기회**: `SObjectPos`는 차량·기둥 공용 스키마이고 `CSaveObjectPosData`가 범용 베이스다. 언리얼에서도 `FCarPos`를 차량 전용으로 좁히지 말고 **범용 `FObjectPos` + 차량 별칭**으로 두면 향후 기둥(Pole) 배치 기능과 저장 로직(`UCarPlacementLibrary`의 JSON I/O)을 재사용 가능 → §9 연동 지점에 반영 권고.
- jsonl(슬롯 점유 `CSaveSlotOccupyData`)은 별개 기능 — 본 설계 범위 외.

## 8. 대안 비교

### 8.1 위젯 구현: C++ UMG (BindWidget) vs 순수 Blueprint
- **A. C++ 베이스 + WBP 리페어런트(채택)**: 기존 `UPresetMakerWidget`와 동일 패턴. 로직 버전관리·유닛테스트·일관성 우수. 디자이너는 WBP에서 레이아웃만.
- B. 순수 BP: 빠른 프로토타이핑이나 로직 비대 시 유지보수/테스트 난이. → 기각.

### 8.2 차량 메시 로딩: 사전 임포트 에셋 vs 런타임 GLB
- **A. 에디터 사전 임포트 `UStaticMesh` + 데이터테이블(채택)**: 안정·빠름·머티리얼 파라미터 제어 용이. Unity glTFast 런타임 로딩을 대체.
- B. 런타임 glTF 플러그인(glTFRuntime): 차종이 런타임 추가돼야 할 때만 가치. 현재 요구에 과도(YAGNI). → 보류(요구 확인 시 재검토).

### 8.3 풀링 전략
- **A. 1차 미적용, 매니저 메서드로 캡슐화(채택)**: `SpawnCar/DespawnCar` 내부만 나중에 풀로 교체. 단순함 우선.
- B. 즉시 풀 구현(Unity `CCarObjectPool` 포팅): 검증/미아복구 로직까지 포팅은 과도. → 2차.

### 8.4 선택 하이라이트
- **A. 단색 오버레이(1차 채택)**: `UCarColorComponent`로 선택색 적용/복원. 가장 단순, Unity SolidColor 모드와 동일.
- B. Custom Depth + PostProcess Outline: UE 정석 외곽선이나 포스트프로세스 볼륨/머티리얼 셋업 필요. → 2차 옵션(Unity Outline 모드 대응).
- C. 메시 복제+Front cull(Unity 방식 직역): UE에서 비권장(비효율). → 기각.

### 8.5 JSON pos 키 보장: `FVector` 직접 vs 전용 `FCarVec3`
- **A. `FCarVec3{float x,y,z}` 전용 구조체 — ✅ 확정 채택**: Unity `SVector3`와 키(`x/y/z`) 정확 일치 보장, UE 버전 직렬화 차이 회피. 샘플 `CarPos_23Num_서신.json`에서 소문자 `x/y/z` 확인됨.
- B. `FVector` 직접: UE가 `X/Y/Z`(대문자)로 직렬화 → Unity 비호환, 좌표 (0,0,0) 손실. **기각.**

### 8.6 데이터 보유 위치: 위젯 vs 매니저 vs 싱글톤
- **A. 위젯이 `FCarPosDatas` 보유(채택)**: PresetMaker가 `Presets`를 위젯에 둔 것과 정합. 매니저는 표시 전용.
- B. 매니저/싱글톤(`CDataMgr` 직역): 전역 상태 → UE에서 테스트/수명관리 불리. → 기각.

## 9. 기존 PresetMaker와의 연동 / 공통화 지점

1. **입력 헬퍼 공통화**: `PresetMakerWidget.cpp`의 익명 `ToInt/ToFloat/SetText/F3`를 공유 헤더(`ParkUIHelpers.h` inline) 또는 공통 베이스로 추출 가능. 1차는 복붙 최소 중복 허용(외과적 변경 원칙), 2차에 공통화 검토.
2. **파일 대화상자**: `PromptOpenFilePath/PromptSaveFilePath` + `PARK3D_USE_FILE_DIALOG` 패턴 동일 재사용. 기본 경로만 `Saved/3D/CarPos/CarPos_SNum.json`로.
3. **매니저 탐색/생성**: `GetCarManager()`는 `GetViewManager()`와 동일 구조(`GetAllActorsOfClass` → 없으면 `SpawnActor`).
4. **GameMode/Pawn**: `APark3DGameMode`가 현재 PresetMaker만 자동 표시. **변경 제안**: 시작 위젯을 `UMainMenuWidget`(WBP_MainMenu)로 바꾸고, 메뉴에서 각 Dlg를 토글하도록. 이는 PresetMaker 자동표시 동작에 영향 → §영향도(별도 impact-analyst 검토 필요).
5. **PresetId 연계**: 차량의 `presetId`는 PresetMaker의 `FParkingPreset.PresetIdx`와 의미상 동일 그룹키. 향후 "프리셋 그룹 단위 일괄 이동/회전"(FR-12)이 PresetMaker 프리셋과 시각적으로 일치하도록 두 모듈이 같은 presetId 공간을 공유함을 문서화.
6. **Build.cs**: 현 의존성(`UMG/Slate/Json/JsonUtilities/DesktopPlatform`)으로 충분. 신규 모듈 추가 없음(차량 메시는 기본 Engine). 런타임 GLB 채택 시에만 플러그인 추가.

- **TP-1 좌표 라운드트립**: `UEToUnityPos(UnityPosToUE(u)) ≈ u` (오차 1e-3), 임의 벡터 다수.

- **TP-7 Unity 호환**: 손으로 만든 `CarPos_SNum.json`(§7 샘플) 로드 시 datas 1개, 필드 정확.

- **TP-10 매니저 일관성**: RebuildAll(N개) → `Cars.Num()==N`, 중복 NameId 없음.
- **TP-11 선택 모델**: 단일/Ctrl토글/Shift범위 선택 인덱스 집합 검증(순수 헬퍼로 분리 권장 → 테스트 용이).

- **TP-13 삭제**: 선택 삭제 후 데이터/액터/리스트 동기 감소.
- **TP-14 회전 부호(동작확인)**: 차량 메시 정면이 의도대로(전면주차 isFront=true) 보이는지 Edit/Play Mode 육안 + 스크린샷.
