## 2. 조치

### 2-1. 조명을 코드가 보장한다 (검은 화면 재발 방지)

`ALightControlManager::EnsureLightingActors()` 를 신설하고 `ApplySettings()` 진입부에서
호출한다. **레벨에 없는 것만** 스폰하므로, 조명을 이미 갖고 있는 레벨(예: 새 콘텐츠의
`LV_Park_*`)에서는 아무것도 만들지 않고 기존 액터를 그대로 쓴다.

- `ADirectionalLight` — `SetMobility(Movable)` 필수. 기본 Stationary 로 두면 런타임 회전이 먹지 않는다.
- `ASkyAtmosphere` — 화면의 배경. 없으면 하늘이 검게 남는다.
- `ASkyLight` — `bRealTimeCapture = true`. **`ASkyLight` 는 `AInfo` 파생이라 `ALight::SetMobility` 가
  없다** → 컴포넌트(`USkyLightComponent`)에 직접 `SetMobility` 를 건다. (첫 빌드에서 C2039 로 드러남)
- `APostProcessVolume` — `bUnbound = true`. `FindExposureVolume()` 이 전역 볼륨을 우선 집는 형태에 맞춘다.

기존 매니저 관례(`AMapFloorActor::GetOrSpawn` / `ACarPlacementManager`)와 같은 "없으면 만든다" 방식이다.

### 2-2. 차량 카탈로그를 JSON 폴백으로 (DataTable 의존 제거)

`Content/` 는 `.gitignore` 로 제외돼 있어(SVN 이 authoritative) `DT_CarCatalog` 를 다시 만들어도
다음 콘텐츠 교체 때 또 사라진다. 그래서 **git 으로 추적되는 `Save/Config/car_catalog.json` 이
메시까지 결정**하게 했다.

- `car_catalog.json` 에 `"meshDir": "/Game/Actors/Car/Meshs"` 추가
- `UCarCatalogConfigLibrary::BuildCatalogFromConfig()` 신설 — `<meshDir>/<이름>.<이름>` 규칙으로 조립
- `ACarPlacementManager::CatalogFromTable()` 이 **단일 관문**이므로 여기서 폴백한다
  (DT 가 null 이거나 비면 JSON 으로 구성). UI·RPC·시뮬 세 경로가 모두 이 함수를 거치므로
  한 곳만 고치면 세 경로가 같은 카탈로그를 본다.
- `RpcServerSubsystem` / `AParkingSimManager::EnsureCatalog` 의 "DT 로드 실패 시 포기" 분기를
  "nullptr 을 그대로 넘김"으로 바꿔 폴백이 타도록 했다.
- `기아_소울` → `기아_쏘울` (실제 에셋 파일명에 맞춤). 저장된 `CarPos_*.json` 중
  이 이름을 참조하는 파일은 없어 안전하다(전수 확인).

**한계**: `FCarPresetEntry::Type`(소형/중형/SUV…) 은 JSON 이 갖고 있지 않아 전부 기본값
`Medium` 이 된다. 이 값은 차량 배치 패널의 차종 필터 콤보 표시와 `car.catalog` 의 `type`
필드에만 쓰이고 기하·렌더에는 영향이 없다.

## 3. 함정 (다음 세션이 같은 시간을 쓰지 않도록)

### 3-1. `StopPIE` 는 UE 의 HTTP 리스너를 **전부** 내린다

PIE 를 중지하면 `HttpServerModule` 이 공유 리스너를 통째로 정리한다:

```
LogHttpServerModule: Stopping all listeners...
LogHttpListener: HttpListener stopping listening on Port 8000    ← Unreal MCP
LogHttpListener: HttpListener stopping listening on Port 13510   ← Park3D RPC
```

에디터 소유인 MCP(8000)까지 함께 죽어서 그 뒤로 에디터를 조작할 수 없게 된다.
**PIE 중지 전에 MCP 로 할 일을 끝내 두거나, 중지 후에는 에디터 재기동을 전제로 잡을 것.**

### 3-2. `ConstructorHelpers::FObjectFinder` 는 프로세스 수명 동안 캐시된다

CDO 생성자 안의 `static ConstructorHelpers::FObjectFinder` 는 **에디터 기동 시점에 한 번**만
조회하고 결과(실패 포함)를 static 으로 붙든다. 에디터가 뜬 **뒤에** 만든 에셋은
그 세션에서 절대 물리지 않는다.

실제로 이번에 에디터 11:37 기동 → 머티리얼 11:39 생성 → PIE 를 아무리 돌려도
`[MapFloor] 아스팔트 머티리얼을 찾지 못했습니다` 가 계속 떴다. **에디터 재기동으로 해결.**
에셋을 새로 만들고 코드가 그것을 CDO 에서 잡아야 하면 재기동이 필수다.

### 3-3. 콘텐츠 교체 시 World Partition 맵은 `__ExternalActors__` 를 반드시 같이 옮길 것

맵 파일(`.umap`)만 옮기면 액터가 0개인 빈 월드가 된다. 화면은 검게 나오지만
에러 로그는 `LoadErrors` 한 줄뿐이라 원인이 잘 안 보인다.
