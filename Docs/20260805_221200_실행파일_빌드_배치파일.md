# 실행파일 빌드 배치 파일 (BuildPackage.bat)

- 작성일: 2026-08-05 22:12
- 대상: `BuildPackage.bat` (저장소 루트, 신규)
- 목적: Park3D 독립 실행 exe(`Package\Windows\Park3D.exe`) 생성을 한 번의 실행으로 처리

## 1. 왜 UBT Build.bat 이 아니라 UAT 인가

`Build.bat Park3DEditor` 는 `UnrealEditor-Park3D.dll`(모듈)만 만든다. 실행은 엔진 공용
`UnrealEditor.exe` 가 이 DLL 을 로드하는 구조라서 **에디터 없이 도는 exe 는 나오지 않는다.**
독립 exe 는 쿠킹(cook) + 스테이징(stage) 이 필요하므로 UAT `BuildCookRun` 을 쓴다.

## 2. 실행 방법

```
BuildPackage.bat
```

인자는 없다. 항상 `Development / Win64` 전체 패키징(`-cook -build -stage -pak -archive`)을 돈다.
저장소의 기존 패키징 기록이 전부 이 조합이고, RPC·MCP 등 개발 도구가 Development 전제라 기본값으로 고정했다.

| 항목 | 값 |
|------|-----|
| 엔진 | `C:\Program Files\Epic Games\UE_5.8` (파일 상단 `UE_ROOT`) |
| 프로젝트 | `Park3D\Park3D.uproject` |
| 산출물 | `Package\Windows\Park3D.exe` |
| 로그 | `_workspace\package_build.log` |

진행 상황은 콘솔에 흐르지 않고 로그로 간다. 실시간으로 보려면 다른 창에서:

```
powershell -NoProfile -Command "Get-Content -Wait '_workspace\package_build.log'"
```

## 3. 스크립트가 막아주는 것

### 3.1 RunUAT 종료코드 착시

RunUAT 래퍼는 내부가 실패해도 `0` 을 반환하는 경우가 있다(쿠킹 에러 등). 종료코드를 믿으면
실패한 빌드를 성공으로 보고하게 된다. 그래서 **로그의 성공 표식**과 **산출물 존재**를 함께 본다.

```
findstr /C:"AutomationTool exiting with ExitCode=0" "%LOG%"
if not exist "%ARCHIVE%\Windows\Park3D.exe" ...
```

실패 시 로그에서 `BUILD FAILED` / `ERROR:` / `Error_` / `error(s)` 줄을 뽑아 콘솔에 보여준다.

### 3.2 실행 중인 패키지

`Park3D.exe` 가 떠 있으면 스테이징이 산출물을 덮어쓰지 못해 **낡은 exe 가 그대로 남는다**
(빌드는 성공처럼 보인다). `tasklist` 로 먼저 확인하고 실행 중이면 중단한다.

### 3.3 엔진 경로

`RunUAT.bat` 이 없으면 즉시 중단하고 `UE_ROOT` 를 고치라고 안내한다.

## 4. 배치 파일이 ASCII 전용인 이유 (중요)

**`.bat` 안에 한글을 넣지 말 것.** 처음 작성분은 한글 주석·메시지를 넣었다가 두 번 깨졌다.

- `.bat` 은 자신이 어떤 코드페이지에서 실행될지 제어할 수 없다. 이 환경의 `cmd` 기본값은 **65001** 이었다.
- CP949 한글의 트레일 바이트에는 `|`, `&`, `>`, `^` 가 포함된다. 코드페이지가 어긋나면 이 바이트들이
  **셸 연산자로 해석되어 주석이 명령으로 실행된다.** 실제로 그 파편 중 하나가 패키지된
  `Park3D.exe` 를 실행시켰다.
- 파일 안에 `chcp 65001` 을 넣는 우회도 안 된다. cmd 가 배치 파일을 읽는 도중 코드페이지가 바뀌면
  파일 읽기 위치가 어긋나 **그 뒤 줄 전체가 깨진다.**

따라서 `BuildPackage.bat` 은 주석·메시지까지 전부 ASCII 로 유지한다(비ASCII 바이트 0개). 한글 설명은 이 문서에 둔다.

## 5. 검증 결과

| 항목 | 결과 |
|------|------|
| 배치 파싱 | 정상 (비ASCII 바이트 0개 확인) |
| UAT 결과 | `BUILD SUCCESSFUL`, `AutomationTool exiting with ExitCode=0`, 1분 21초 |
| 산출물 | `Package\Windows\Park3D.exe` (2026-08-05 22:09 갱신) |
| 실제 게임 바이너리 | `Package\Windows\Park3D\Binaries\Win64\Park3D.exe` 345MB, 동일 시각 갱신 |
| 배치 종료코드 | 0 |

`Package\Windows\Park3D.exe` 는 부트스트랩이고 실제 게임 프로세스·창 핸들은
`Package\Windows\Park3D\Binaries\Win64\Park3D.exe` 에 있다(창 검증 시 주의).

## 6. 영향도

- **신규 파일 1개**(`BuildPackage.bat`)만 추가했고 기존 소스·설정은 건드리지 않았다. 빌드 산출물 경로,
  UAT 인자 모두 기존 기록과 동일하므로 기존 패키징 절차와 충돌하지 않는다.
- `Package/` 는 `.gitignore` 에 이미 등록되어 있어 수 GB 산출물이 커밋되지 않는다.
- `_workspace\package_build.log` 는 매 실행마다 덮어쓴다.
- 이 실행으로 만들어진 패키지에는 같은 날 커밋한 조명 패널 글자색 수정(`61a8674`)이 포함된다.
