# 차량 메시 메모리 풀(캐시) 로딩 최적화

- 날짜: 2026-07-01 17:45:41
- 대상: `CarPlacementManager.h/.cpp`(메시 캐시), `CarPlacementWidget.cpp`(NativeConstruct 프리로드)
- 유형: 성능 최적화 (버그성 지연 해소)
- 요청: "랜덤배치 시 차량이 뜨는 데 3~5초 걸린다. 일반배치는 즉시(처음 한 번만 느림). 메모리 풀 등으로 더 빠르게 로딩되게."

## 1. 원인 분석

- 스폰 경로 `ACarPlacementManager::SpawnCarFromPos` 가 매번 `E->Mesh.LoadSynchronous()` 로 **디스크에서 동기 로드**했다.
- 차량 배치 시마다 위젯이 `RefreshView()` → `RebuildAll()` 로 **모든 액터를 파괴·재생성**한다. 액터가 파괴되면 그 메시에 대한 하드 참조가 사라져 **GC 언로드** 대상이 되고, 다음 배치에서 다시 동기 로드된다.
- **일반배치**: 콤보로 고른 동일 메시만 반복 → 대개 상주 상태라 첫 로드 이후 즉시.
- **랜덤배치**: 매번 다른 prefab을 뽑음 → 새 메시의 최초 동기 로드가 반복 발생 + 재생성마다 여러 메시 재로드 → 3~5초 스톨.

## 2. 설계 (메모리 풀)

`ACarPlacementManager` 에 **prefabId → 로드된 메시** 캐시를 두어 하드 참조로 상주시킨다(GC 언로드 방지). 다이얼로그 오픈 시 카탈로그 전체를 1회 프리로드하면, 이후 스폰/재생성은 디스크 로드 없이 즉시 처리된다.

- 매니저는 레벨에 상주(ClearAll 은 차량 액터만 제거, 매니저·캐시는 유지) → 캐시는 세션 동안 지속. 다이얼로그를 다시 열어도 캐시 히트로 프리로드가 즉시 끝난다.
- "처음 한 번은 느림"(다이얼로그 오픈 시 1회 프리로드)은 사용자가 수용한 조건과 일치.

## 3. 변경 내용

### `CarPlacementManager.h`
```cpp
UFUNCTION(...) void PreloadCatalogMeshes(const TArray<FCarPresetEntry>& Catalog); // 전체 프리로드
private:
UStaticMesh* ResolveMesh(const TArray<FCarPresetEntry>& Catalog, int32 PrefabId); // 캐시 우선 해석
UPROPERTY(Transient) TMap<int32, TObjectPtr<UStaticMesh>> MeshCache;              // 메모리 풀(하드 참조)
```

### `CarPlacementManager.cpp`
- `SpawnCarFromPos`: `E->Mesh.LoadSynchronous()` 인라인 로드 → `ResolveMesh(Catalog, Pos.prefabId)` 로 교체.
- `ResolveMesh`: 캐시 히트 시 즉시 반환, 미스 시 `FindEntryByPrefabId` 로 해석·`LoadSynchronous` 후 캐시에 추가(하드 참조).
- `PreloadCatalogMeshes`: 카탈로그 각 항목 메시를 1회 로드해 캐시에 상주(이미 있으면 스킵) + 로그.

### `CarPlacementWidget.cpp`
- `NativeConstruct` 말미에 `GetCarManager()->PreloadCatalogMeshes(GetCatalog())` 호출(다이얼로그 오픈 시 1회).

## 4. 영향도 분석

- **동작 동일성**: 메시 해석 결과는 기존 `FindEntryByPrefabId` + `LoadSynchronous` 와 동일(폴백 규칙 포함). 캐시는 "언제 로드하느냐"만 바꿈.
- **메모리**: 카탈로그 전 메시가 상주 → 메모리 사용 증가(카탈로그 크기만큼). 주차장 카탈로그 규모(수~수십 종)에서는 허용 범위. 필요 시 `MeshCache` 를 LRU/부분 상주로 축소 가능(후속).
- **의존성**: 신규 include 없음(`UStaticMesh` 는 기존 사용). API 시그니처 변경 없음(신규 함수 추가). JSON/데이터 스키마 무관.
- **회귀 위험 낮음**: 일반배치·자동생성·저장/열기·이동/회전 경로 모두 스폰 로직만 공유하며 결과 동일.

## 5. 검증

- **유닛테스트**: 에셋 동기 로드/월드 스폰 의존이라 자동 유닛테스트 대상 밖.
- **동작 확인(사용자, Ctrl+Alt+F11 컴파일 후)**:
  1. 차량배치 다이얼로그 오픈 시 로그 `[CarPlacement] 메시 프리로드: N개(...)` 확인(최초 1회 소요).
  2. 랜덤배치 체크 후 연속 Ctrl+좌클릭: **즉시** 차량이 뜨는지(3~5초 스톨 사라짐).
  3. 다이얼로그를 닫았다 다시 열면 프리로드가 즉시 끝나는지(캐시 유지).
  4. 일반배치·자동생성·저장/열기 정상 여부.

## 6. 후속 참고

- 프리로드 시점은 다이얼로그 오픈(NativeConstruct). 오픈 순간의 1회 프리징이 부담되면 비동기 스트리밍(`FStreamableManager::RequestAsyncLoad`)으로 백그라운드 로드 후 완료 콜백에 상주시키는 방식으로 개선 가능(단, 로드 완료 전 스폰은 폴백 메시 필요).
