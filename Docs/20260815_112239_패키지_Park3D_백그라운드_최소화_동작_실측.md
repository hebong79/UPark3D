# 패키지 Park3D — 창 최소화(백그라운드) 시 동작 여부 실측

- 일시: 2026-08-15 11:05~11:22
- 대상: 작업본 패키지 `Package/Work13520/Park3D.exe` (RPC 13520, cam 스트림 13611~)
- 사용자 실행창(13510, PID 7340)은 **건드리지 않음**

## 질문
> 빌드해서 실행되는 Park3D는 화면이 최소화될 때도 백그라운드로 동작하나?

## 결론
**동작한다. 최소화해도 멈추지 않는다.** 게임 틱이 약 22% 느려지고 CPU가 약 27% 줄 뿐,
RPC·씬 캡처·MJPEG 스트림은 전부 정상이다.

단, **최소화는 괜찮지만 창을 닫으면(X 버튼) 즉시 프로세스가 종료된다** — 이번 실측 중
실제로 그 종료 로그를 확인했다(아래 5항).

## 측정 결과

같은 프로세스(PID 26988)를 전경 → 최소화 순으로 각각 15초(스트림은 12초) 측정.

| 지표 | 전경 | 최소화 | 비율 |
|---|---|---|---|
| 게임 틱 fps (`cam.streamStatus.main.tickFps`) | 16.03 (15.12~16.59) | 12.51 (11.70~13.20) | **78%** |
| CPU 사용(코어 합) | 393% | 285% | **73%** |
| RPC 왕복(`cam.streamStatus`) | 2,203ms | 2,148ms | 동일 |

| MJPEG 스트림 cam1 (SOI 마커 직접 계수) | 4.97 fps | 4.76 fps | **96%** |

보조 측정(재기동 전 인스턴스 PID 25296에서도 동일 경향): 전경 CPU 542% → 최소화 284%,
ping 30회 실패 0, 캡처 정상.

### 해석
- **게임 스레드는 계속 돈다.** 틱이 16→12.5fps로 낮아지는 건 창이 보이지 않아 메인 뷰포트
  렌더 비용이 빠진 결과이고, 정지·프리즈가 아니다. 타이머·시뮬 로직은 계속 진행된다.
- **씬 캡처는 최소화의 영향을 거의 안 받는다.** 카메라 스트림은 목표 5fps 대비 4.76fps로
  전경(4.97fps)과 4% 차이. 백그라운드로 두고 카메라 영상을 뽑아 쓰는 사용이 가능하다.
- **RPC는 영향 없음.** 왕복 시간이 전경/최소화 동일하고 실패 0.

## 부수 발견 (최소화와 무관, 별개 이슈)
**RPC 왕복이 상시 약 2.2초다.** `system.ping` 같은 무부하 메서드도 2,050~2,850ms가 걸린다.
전경/최소화가 같은 값이므로 백그라운드 스로틀이 아니라 서버 구조(UE `IHttpRouter` 기반,
게임 스레드 틱에 종속)에서 오는 지연으로 보인다. 틱이 16fps(프레임당 62ms)인데 왕복이
2.2초면 요청 하나에 수십 프레임이 소요되는 셈 — 원인 규명은 이번 범위 밖으로 남긴다.

## 실측 중 발생한 사건 (사실 보고)
11:10:28에 작업본 인스턴스(PID 25296)가 **종료**됐다. 크래시가 아니라 창 파괴 요청에 의한
정상 종료다:

```
LogSlate: Request Window 'Park3D (64-bit Development PCD3D_SM6) ' being destroyed
LogEngine: All Windows Closed
LogWindows: FPlatformMisc::RequestExit(0, UGameEngine::Tick.ViewportClosed)
```

시각이 `sim.start` 호출 시점과 겹치지만 **인과는 확정하지 못했다** — 로그에 sim 관련 항목이
전혀 남지 않았고(RPC 호출은 로그를 남기지 않음), 사용자가 직접 닫았을 가능성도 배제할 수
없다. 이 종료로 확인된 사실은 하나: **창이 닫히면 패키지 Park3D는 그 자리에서 종료된다.**
백그라운드 상주는 최소화로 해야 하며 닫기는 안 된다.

이후 같은 exe를 재기동(PID 26988)해 위 비교 측정을 완료했다. 재기동 시 커맨드라인 인자는
비어 있었고(포트는 config 지정) `Start-Process`만으로 13520이 정상 리슨했다.

## 측정 방법
- 창 상태 조작: `user32!ShowWindow(hwnd, 6=SW_MINIMIZE / 9=SW_RESTORE)`, `IsIconic`으로 확인
- 틱 fps: `cam.streamStatus` 응답의 `main.tickFps`
- CPU: `Process.TotalProcessorTime` 델타 ÷ 실경과시간
- 스트림 fps: 13611에 HTTP 접속해 수신 바이트에서 JPEG SOI(`FF D8`) 마커를 직접 계수
- 스크립트는 스크래치패드에만 작성(저장소 파일 변경 없음)

## 범위 밖 / 미검증
- 화면 잠금·절전·RDP 세션 분리 상태는 측정하지 않았다(최소화와 다른 조건).
- 장시간(수십 분 이상) 백그라운드 유지 시 누수·드리프트는 보지 않았다.
- 시뮬 주행(`sim.start`)의 백그라운드 진행 속도는 위 종료 사건으로 측정하지 못했다.
