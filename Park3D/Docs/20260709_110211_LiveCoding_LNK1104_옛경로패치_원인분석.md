# Live Coding `LNK1104` (옛 경로 patch_0.exe) 원인 분석 및 해결

- 작성일: 2026-07-09 11:02
- 대상: Park3D (UE 5.8) Live Coding 핫컴파일
- 증상: 컴파일은 성공(`Result: Succeeded`)했으나, Live Coding **패치 링크** 단계에서 실패

```
LINK : fatal error LNK1104: 'D:\Work\Unreal\Project\Parking\Park3D\Binaries\Win64\UnrealEditor-Park3D.patch_0.exe'
Error exit code: 1104
Failed to link patch
```

## 1. 결론 (원인) — 정정본

> ⚠️ 최초 진단("실행 중 에디터의 메모리 상태 문제 → 재시작하면 해결")은 **오진**이었다.
> 에디터를 완전히 재시작한 뒤 다시 컴파일해도 동일 오류가 재현되어 재조사한 결과, 진짜 원인은 아래와 같다.

프로젝트 작업 폴더를 **`D:\Work\Unreal\Project\Parking` → `D:\Work\UnrealWork\Parking`** 로 이동했다.
그런데 **베이스 모듈 `UnrealEditor-Park3D.dll` 이 폴더 이동 전(07/06 18:22)에 마지막으로 풀 링크된 상태 그대로**이고,
이동 이후 모든 컴파일이 **Live Coding**(`-LiveCoding`)이었다.
Live Coding은 `patch_N.exe` 델타만 만들 뿐 **베이스 DLL을 재링크하지 않는다.**
그 결과 DLL 안에는 **옛 경로만** 박혀 있고, Live Coding이 패치 출력 경로를 이 **베이스 DLL의 원본 경로 정보**에서 도출하기 때문에
**이미 사라진 옛 폴더**에 `UnrealEditor-Park3D.patch_0.exe`를 쓰려다 `LNK1104(파일을 열 수 없음)`으로 실패한다.

즉 **문제는 에디터 프로세스 메모리가 아니라, 낡은 상태로 굳어 있는 DLL 파일 자체**다.
그래서 에디터를 재시작해도(같은 DLL을 다시 로드하므로) 해결되지 않는다.

### 결정적 증거
- `UnrealEditor-Park3D.dll` LastWriteTime = **2026-07-06 18:22** (이동 전 마지막 풀 링크).
- DLL 바이너리 내 문자열: `D:\Work\Unreal\Project\Parking\...\Source\Park3D\*.cpp` 다수 → **옛 경로만 존재**.
- DLL 내 **신규 경로(`UnrealWork\Parking`) 문자열은 0개**.
- `.dll.rsp`(라이브)·`.target`·`LiveCoding.json`·`LiveCodingModules.json` 은 전부 신규 경로로 정상 → 매니페스트는 무관, 베이스 DLL이 범인.
- 에디터 완전 재기동(PID 18096, 11:05, 신규 경로) 후에도 `LNK1104` 재현.

| 확인 항목 | 결과 | 판정 |
|-----------|------|------|

| `LiveCodingModules.json` (에디터가 보고한 로드 모듈) | `...\UnrealWork\Parking\...\UnrealEditor-Park3D.dll` | **신규 경로 ✓** |

**핵심:** 디스크상의 모든 빌드 산출물(`.rsp`, `.target`, `LiveCodingModules.json`)은 신규 경로로 깨끗하다.
오직 **실행 중 에디터 프로세스의 Live Coding 내부 등록만 옛 경로**다.
(현재 세션 PID 1428은 옛 경로 세션 PID 1412로부터 Live Coding "Restart & Reload" 체인으로 승계되어 옛 상태가 남았다.)

## 3. 해결 방법 — 베이스 DLL을 일반 빌드로 1회 재링크

핵심은 **Live Coding이 아니라 일반 빌드로 `UnrealEditor-Park3D.dll` 을 새 경로에서 다시 링크**하는 것이다. 한 번만 하면 이후 Live Coding이 정상 동작한다.

1. **작업 저장 후 에디터 완전 종료** (File → Exit).
   - DLL이 로드 중이면 파일이 잠겨 재링크가 불가하다. 작업 관리자에서 `UnrealEditor.exe`가 없는지 확인.
2. 낡은 산출물 삭제(재링크 강제 + 잔여 패치 정리):
   - `Park3D\Binaries\Win64\UnrealEditor-Park3D.dll`
   - `Park3D\Binaries\Win64\UnrealEditor-Park3D.pdb`
   - `Park3D\Binaries\Win64\UnrealEditor-Park3D.patch_*.*`
3. **일반 빌드**(Ctrl+Alt+F11 아님) 로 재링크:
   - Visual Studio/Rider: `Development Editor`+`Win64` → Park3D 프로젝트 **Rebuild**, 또는
   - UBT 직접 실행:
     ```
     & "C:\Program Files\Epic Games\UE_5.8\Engine\Build\BatchFiles\Build.bat" `
       Park3DEditor Win64 Development `
       -Project="D:\Work\UnrealWork\Parking\Park3D\Park3D.uproject" -WaitMutex
     ```
4. `D:\Work\UnrealWork\Parking\Park3D\Park3D.uproject` 실행 → 이후 Ctrl+Alt+F11(Live Coding) 정상.

### 확실히 하려면 (완전 초기화)
- 위로도 안 되면 에디터 종료 상태에서 `Park3D\Binaries`, `Park3D\Intermediate` 삭제 → `.uproject` 우클릭 **Generate Visual Studio project files** → 일반 Build 풀 빌드.

### 선택(정리)
- 옛 경로 MRU 기록은 방치해도 무해하며 최근 목록에서 자연히 사라진다.
- 옛 폴더(`D:\Work\Unreal\Project\Parking`)는 예정대로 삭제해도 무방하다 (이미 없음/삭제 예정).

### 재발 방지 (중요)
- **폴더/경로 이동 후에는 반드시 "일반 빌드"로 1회 풀 링크**하여 베이스 DLL을 새 경로로 갱신한 뒤 Live Coding을 사용한다.
- Live Coding만 반복하면 베이스 DLL이 옛 경로로 굳은 채 계속 남아 같은 문제가 재발한다.

## 4. 영향도

- **소스 코드 / 모듈 빌드:** 영향 없음 (컴파일 성공, 산출물 정상).
- **다른 모듈·의존성:** 영향 없음 (옛 경로 참조는 실행 중 에디터 런타임 상태에 국한).
- **재발 방지:** 폴더를 이동할 때는 에디터를 먼저 완전히 종료한 뒤 이동하고, 이동 후에는 새 경로에서 처음부터 기동하면 이 문제가 발생하지 않는다.
