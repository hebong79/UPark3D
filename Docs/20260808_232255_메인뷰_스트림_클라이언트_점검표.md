## 1. 접속 정보

| 항목 | 값 |
|------|-----|
| 메인 뷰 스트림 | `http://192.168.0.125:13600/` |
| 카메라 1번 스트림 | `http://192.168.0.125:13601/` (camId 2 = 13602 …) |
| RPC(상태 조회) | `http://192.168.0.125:13510/rpc` |
| 형식 | `multipart/x-mixed-replace; boundary=park3dframe` (MJPEG) |
| 인증 | **없음** — `AllowAnonymous=True` (폐쇄망 개발 설정) |
| 해상도 | 960×540 고정 (창 크기와 무관) |
| 목표 fps | 10 |

브라우저 주소창에 URL을 그대로 넣거나, HTML 에서 `<img src="http://192.168.0.125:13600/">` 로 붙이면 된다.
쿼리 파라미터는 없다.

> 서버 IP `192.168.0.125` 는 2026-08-08 기준 Wi-Fi 주소다. 바뀌었으면 서버에서
> `Get-NetIPAddress -AddressFamily IPv4` 로 다시 확인할 것.

## 2. 접속이 안 될 때 — 먼저 볼 것

### 2-1. ⚠ 방화벽 (원격 접속 실패의 1순위)

**현재 13600·13601 을 여는 인바운드 방화벽 규칙이 없다.** 13510(RPC)만 규칙이 있다.

```
Park3D RPC 13510   Allow      ← 있음
13600 / 13601      (규칙 없음) ← 없음
```

포트는 `0.0.0.0` 으로 리슨 중이라 **서버 본체는 정상**이다. 그러나 규칙이 없으면 패킷이
커널에서 버려지므로 **앱 로그에는 아무것도 남지 않는다.** 접속만 조용히 실패한다.

- 같은 PC(`127.0.0.1:13600`)에서는 보이는데 다른 PC에서는 안 보인다 → 거의 확실히 이것이다.
- 조치는 호스트 방화벽 변경이므로 이 문서 범위 밖이다. 서버 관리자에게 13600(및 사용 중인
  카메라 포트 대역)의 인바운드 허용을 요청할 것.

### 2-2. 앱이 떠 있는지

서버에서:

```powershell
Get-NetTCPConnection -State Listen -LocalPort 13600 | Select-Object LocalAddress, OwningProcess
```

`0.0.0.0 / <PID>` 가 나오면 리슨 중이다. 아무것도 안 나오면 앱이 꺼졌거나 메인 뷰 채널이 정지 상태다.

### 2-3. 화면이 검거나 안 나올 때

**보는 클라이언트가 0명이면 캡처 자체를 하지 않는다**(유휴 비용 0 설계). 접속하면 그때부터
프레임이 생성되므로, 처음 1~2초 지연은 정상이다.

## 3. 눈으로 확인할 것 — 미검증 항목

아래 3가지는 코드상 대응은 되어 있으나 **실기 확인이 안 된 항목**이다. 클라이언트에서 처음 볼 때
반드시 확인해 주기 바란다.

| # | 증상 | 어떻게 보이나 | 원인이라면 |
|---|------|---------------|-----------|
| 1 | **영상이 비스듬함** | 화면이 사선으로 밀려 계단처럼 어긋난다 | GPU row pitch(행 정렬) 처리 실패 |
| 2 | **색이 뒤집힘** | 파란 것이 빨갛게, 빨간 것이 파랗게 (BGR↔RGB) | 렌더타깃 픽셀 포맷 불일치 |
| 3 | **상하 반전** | 영상이 위아래로 뒤집혀 나온다 | 스테이징 복사 방향 |

1·2 는 실패 시 스트림을 끊고 로그를 남기는 가드가 들어가 있으나, 가드를 빠져나가는 경우가
없다고 단정할 수 없다. 3 은 소스로 추론만 했고 가드가 없다.

**하나라도 보이면 캡처(스크린샷)를 남기고 알려 주기 바란다.**

### 3-1. UI가 안 나오는 것은 정상이다

스트림에는 **Preset Maker / Main Menu 등 UMG UI가 나오지 않는다. 3D 씬만 나간다.**
이는 버그가 아니라 설계다 — 스트림은 화면을 복사해 UI를 지우는 방식이 아니라, UI가 개입하지
않는 전용 씬 캡처로 별도 렌더한 결과다. 시점(위치·화각)은 화면과 같다.

## 4. 숫자로 확인 — 상태 조회

### 4-1. 호출 방법

**PowerShell**

```powershell
$body = @{jsonrpc='2.0'; id=1; method='cam.streamStatus'; params=@{}} | ConvertTo-Json -Compress
(Invoke-RestMethod -Uri 'http://192.168.0.125:13510/rpc' -Method Post -Body $body -ContentType 'application/json').result.main
```

**curl**

```bash
curl -s -X POST http://192.168.0.125:13510/rpc \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"cam.streamStatus","params":{}}'
```

### 4-2. 판정 기준

| 키 | 의미 | 정상 범위 | 벗어나면 |
|----|------|-----------|----------|
| `clients` | 현재 시청자 수 | 1 이상 | 0 이면 캡처를 하지 않는다(정상 동작) |
| `fps` | 실측 fps | 9.5 ~ 10.5 | 낮으면 아래 단계별 값으로 원인 구분 |
| `targetFps` | 목표 fps | 10 | — |
| `captureAvgMs` | 게임 스레드 총 비용 | 5 ~ 7ms | 10ms 초과면 이상 |
| `captureSceneAvgMs` | 씬 캡처 호출 | 0.2 ~ 0.5ms | — |
| `readbackAvgMs` | 리드백(게임 스레드 몫) | 0.01ms 미만 | 1ms 이상이면 비동기가 안 먹는 상태 |
| `encodeAvgMs` | JPEG 인코딩 | 5 ~ 6ms | 현재 비용의 95%가 여기다 |
| `inFlight` | 진행 중 리드백 수 | 0 ~ 2 | 항상 `readbackSlots` 와 같으면 병목 |
| `skippedNoSlot` | 슬롯 부족으로 건너뛴 누적 | 0 | 계속 증가하면 슬롯 부족 |
| `readbackSlots` | 리드백 슬롯 수 | 6 | — |
| `tickFps` | 앱 전체 틱 레이트 | 40 이상 | 크게 낮으면 스트림 외 요인도 의심 |

`captureAvgMs` 는 `captureScene + readback + encode` 세 값의 합이다.

## 6. 증상 → 원인 분류

| 클라이언트에서 보이는 것 | 먼저 볼 값 | 유력한 원인 |
|--------------------------|-----------|-------------|
| 아예 접속이 안 됨 | 서버에서 리슨 여부 | §2-1 방화벽 (원격만 실패하면 거의 확정) |
| 접속은 되는데 화면이 안 옴 | `clients`, `fps` | `clients`가 0이면 접속이 실제로 안 붙은 것 |
| 영상이 뚝뚝 끊김 | `fps`, `skippedNoSlot` | fps가 낮으면 앱 부하, `skippedNoSlot` 증가면 슬롯 부족 |
| 영상이 느리게 따라옴(지연) | `inFlight` | 설계상 1~2프레임 지연은 정상(감시 스트림) |
| 화면은 도는데 스트림만 멈춤 | `fps`가 0으로 굳음 | 리드백이 완료되지 않는 경우. **워치독이 없어 자동 복구되지 않는다** — 앱 재기동 필요 |
| 영상이 비스듬/색 반전/상하 반전 | — | §3 미검증 항목. 캡처를 남기고 보고 |

## 7. 알려진 한계

| 항목 | 내용 |
|------|------|
| 워치독 없음 | GPU 리드백이 영영 끝나지 않으면 스트림이 멈춘 채 자동 복구되지 않는다 |
| 스킵 원인 구분 | `skippedNoSlot` 은 슬롯 부족만 센다. 페이싱으로 건너뛴 것과는 구분되지 않는다 |
| PTZ 카메라 채널 | 13601~ 은 **아직 동기 리드백**이다. 이번 개선은 메인 뷰(13600)에만 적용됐다 |
| 해상도 고정 | 960×540. 스트림 도중 바꾸면 클라이언트가 깨지므로 고정값이다 |
| 인증 없음 | `AllowAnonymous=True`. 폐쇄망 전제이며 외부망 노출 환경에서는 재검토가 필요하다 |
| GPU 몫 미측정 | 위 수치는 전부 **게임 스레드** 비용이다. 두 번째 씬 렌더의 GPU/렌더 스레드 부하는 아직 측정되지 않았다 |
